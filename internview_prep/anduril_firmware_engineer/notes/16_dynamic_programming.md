# 16. 동적 계획법 (Dynamic Programming) — Q1~Q9 📐

> DP는 "큰 문제를 작은 겹치는 부분문제로 쪼개, 답을 표(table)에 저장해 재사용"하는 기법이다.
> 펌웨어 엔지니어에게 DP는 **자원/전력/대역폭의 최적 배분**(knapsack), **명령 퍼지 매칭**
> (edit distance), **델타 업데이트 diff**(LCS)로 직결된다. 오랜만이면 아래 **4단계 프레임워크**만
> 몸에 익히면 대부분의 문제가 풀린다.

---

## DP 접근 4단계 (매 문제 이 순서로 생각하라)

1. **상태 정의 (State)** — `dp[i]` 또는 `dp[i][j]` 가 *정확히 무엇의 답*인지 한 문장으로 적는다.
   - "dp[i] = i번째 원소로 끝나는 ...의 최대 길이" 처럼 *끝나는/이하/까지* 를 명확히.
   - 상태를 잘못 잡으면 점화식이 안 나온다. 여기서 90%가 갈린다.
2. **전이 정의 (Transition)** — `dp[i]` 를 *더 작은* `dp[...]` 로 표현하는 **점화식**을 세운다.
   - "마지막 선택(마지막 걸음/마지막 동전/마지막 문자)"이 무엇이었나를 기준으로 경우를 나눈다.
3. **기저 정의 (Base case)** — 가장 작은 입력을 *직접* 채운다. `n=0`, `n=1`, 빈 문자열, `dp[0]=0/1`.
   - 엣지 케이스(빈 배열, 용량 0)는 거의 항상 기저에서 처리된다.
4. **순서 정의 (Order)** — 점화식이 참조하는 값이 *먼저* 계산되도록 루프 방향을 정한다.
   - 0/1 knapsack이 용량을 **내림차순**으로 도는 이유가 바로 이 단계다.

> 보너스: 표를 다 채운 뒤 **답의 위치**(마지막 칸? 전체 최댓값?)를 확인하고,
> 가능하면 **롤링(rolling)** 으로 메모리를 O(n)→O(1)/O(W)로 줄인다.

---

## 왜 Anduril 펌웨어 인터뷰에 DP가 나오나

- **자원 최적화**: 제한된 전력/대역폭/연산 예산 안에서 가치를 최대화 → 0/1 knapsack 그 자체.
  (예: 링크 예산 안에서 어떤 텔레메트리 스트림을 보낼지 선택)
- **퍼지 매칭**: 잡음 섞인 명령/식별자 문자열을 사전과 대조 → edit distance(Levenshtein).
- **델타/OTA 업데이트**: 두 펌웨어 이미지의 공통부분 → LCS/diff 로 전송량 최소화.
- **bottom-up의 결정성**: 재귀 메모이제이션은 스택 깊이가 입력에 따라 변한다. bottom-up +
  고정 크기 테이블은 **최악 지연/메모리가 컴파일 타임에 확정** → 안전필수(safety-critical) 코드에 적합.

## 핵심 개념 치트시트

| 문제 | 상태 dp | 점화식 | 복잡도 |
|------|---------|--------|--------|
| 계단 오르기 | i계단 방법 수 | `dp[i]=dp[i-1]+dp[i-2]` | O(n)/O(1) |
| 도둑질 | 0..i 최대 금액 | `dp[i]=max(dp[i-1], dp[i-2]+a[i])` | O(n)/O(1) |
| 동전 최소 | 금액 a 최소 동전 | `dp[a]=min(dp[a-c]+1)` | O(amt·nc)/O(amt) |
| LIS | i로 끝나는 최장 | `dp[i]=1+max(dp[j] : a[j]<a[i])` | O(n²)/O(n) |
| 0/1 배낭 | 용량 c 최대 가치 | `dp[c]=max(dp[c], dp[c-w]+v)` | O(n·W)/O(W) |
| 편집 거리 | a[..i]→b[..j] | `일치:dp[i-1][j-1] / 아니면 1+min(3방향)` | O(mn)/O(mn) |
| LCS | a[..i],b[..j] 공통 | `일치:dp[i-1][j-1]+1 / 아니면 max(2방향)` | O(mn)/O(mn) |
| 격자 경로 | (i,j)까지 경로 수 | `dp[i][j]=dp[i-1][j]+dp[i][j-1]` | O(mn)/O(n) |
| 최대 곱 | i로 끝나는 max/min | `max(x, maxp·x, minp·x)` | O(n)/O(1) |

## 1D DP: 롤링으로 O(1) 공간

### 계단 오르기 / 도둑질 = 피보나치 계열

```c
// 계단: dp[i] = dp[i-1] + dp[i-2]
int prev2 = 1, prev1 = 1;               // dp[0], dp[1]
for (int i = 2; i <= n; ++i) {
    int cur = prev1 + prev2;
    prev2 = prev1; prev1 = cur;
}
return prev1;
```

- **핵심 통찰**: dp[i]가 바로 앞 두 값에만 의존하면 배열 전체가 필요 없다 → 변수 2개.
- 도둑질도 구조가 같다. "i집을 털까 말까"의 두 선택을 max로 합칠 뿐:
  `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`.

### 동전 최소 개수 = 무한대 초기화 + min

```c
dp[0] = 0;                               // 기저
for (int a = 1; a <= amount; ++a) {
    dp[a] = INF;
    for (int c = 0; c < nc; ++c)
        if (a - coins[c] >= 0 && dp[a-coins[c]] + 1 < dp[a])
            dp[a] = dp[a-coins[c]] + 1;
}
// dp[amount] == INF 이면 -1 (만들 수 없음)
```

- **함정**: `INT_MAX` 를 그대로 쓰고 `+1` 하면 오버플로. `INT_MAX-1` 같은 여유 INF 사용.
- 그리디(큰 동전부터)는 일반적으로 **틀린다**(예: coins=[1,3,4], amount=6 → 그리디 4+1+1=3, DP 3+3=2).

## 2D DP: 문자열/격자

### 편집 거리 vs LCS = 쌍둥이 표

두 문제 모두 `dp[i][j]` = "a의 앞 i글자와 b의 앞 j글자"에 대한 답. 대각선 일치가 핵심.

```c
// 편집 거리(최소화)
if (a[i-1]==b[j-1]) dp[i][j] = dp[i-1][j-1];            // 공짜
else dp[i][j] = 1 + min3(dp[i-1][j],    // 삭제
                         dp[i][j-1],    // 삽입
                         dp[i-1][j-1]); // 치환

// LCS(최대화)
if (a[i-1]==b[j-1]) dp[i][j] = dp[i-1][j-1] + 1;        // 공통 +1
else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
```

- **기저**: 편집거리는 `dp[i][0]=i, dp[0][j]=j`(전부 삭제/삽입). LCS는 `dp[*][0]=dp[0][*]=0`.
- C에는 2D 가변 배열이 없으니 **1차원으로 flatten**: `dp[i*W + j]`, `W = lb+1`. malloc 후 free.

### 격자 경로 = 위 + 왼쪽, 1D 롤링

```c
for (int j = 0; j < n; ++j) row[j] = 1;   // 첫 행/열 = 1
for (int i = 1; i < m; ++i)
    for (int j = 1; j < n; ++j)
        row[j] += row[j-1];               // 새 row[j] = 위(옛 row[j]) + 왼쪽(row[j-1])
```

- 2D 표에서 각 칸이 "위 + 왼쪽"에만 의존 → 한 행만 유지하며 제자리 갱신하면 O(n) 공간.

## 0/1 배낭: 루프 방향이 정답을 바꾼다

```c
int *dp = calloc(cap+1, sizeof *dp);      // dp[c] = 용량 c 최대 가치
for (int i = 0; i < n; ++i)
    for (int c = cap; c >= w[i]; --c)     // ★ 내림차순 ★
        dp[c] = max(dp[c], dp[c-w[i]] + v[i]);
```

- **왜 내림차순?** `dp[c-w[i]]` 가 *이번 아이템을 아직 안 쓴* 값이어야 각 아이템을 최대 1번 쓴다.
  오름차순으로 돌면 방금 갱신된(=이미 이 아이템을 쓴) 값을 또 참조해 **무제한 배낭**(unbounded)이 된다.
- 이 한 줄이 "0/1 vs 무제한"을 가르는, DP 4단계 중 **순서(order)** 의 대표 예시.

## 최대 곱 부분배열: 최솟값도 같이 들고 다녀라

```c
int maxp = nums[0], minp = nums[0], ans = nums[0];
for (int i = 1; i < n; ++i) {
    int x = nums[i], a = maxp*x, b = minp*x;
    maxp = max3(x, a, b);                  // 음수 곱으로 뒤집힐 수 있으니
    minp = min3(x, a, b);                  // 최소도 후보로 유지
    ans = max(ans, maxp);
}
```

- **핵심 통찰**: 음수 × 음수 = 양수. 지금까지의 *최솟(가장 음수)* 곱이 다음 음수를 만나면
  가장 큰 값이 될 수 있다. 그래서 max와 min을 **쌍으로** 추적한다. (합 문제 Kadane의 곱셈판)

## 인터뷰 팔로업 & 함정

- **Q. 메모이제이션(top-down) vs 타뷸레이션(bottom-up)?** → 결과 같음. 임베디드는 스택
  안전/결정성 때문에 bottom-up 선호. top-down은 재귀 깊이 = 상태 수 → 스택 오버플로 위험.
- **Q. LIS를 O(n log n)으로?** → `tails[k]` = 길이 k+1 증가수열의 *가능한 최소 꼬리값*.
  각 원소를 이진탐색으로 tails에 삽입/교체. 길이 = tails 크기.
- **함정: 동전 그리디** → 일반 동전계에서 틀림. 반드시 DP.
- **함정: INF + 1 오버플로** → coin change에서 `INT_MAX` 대신 여유 INF.
- **함정: knapsack 루프 방향** → 내림차순 잊으면 무제한 배낭이 됨.
- **함정: 2D 인덱스 off-by-one** → `dp` 는 `(la+1)×(lb+1)`. 문자 접근은 `a[i-1]`, `b[j-1]`.
- **함정: 최대 곱에서 0** → 0을 만나면 max/min이 0으로 리셋되는 게 자연스럽게 처리됨(후보에 x 포함).
- **함정: 빈 입력** → n=0 이면 대부분 0 반환. 기저에서 먼저 걸러라.
