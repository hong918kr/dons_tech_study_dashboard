# 간결한 갭 분석과 우선순위 로드맵 (SSD FW/Embedded SWE 면접 대비)

## 현재 세트 커버 수준

- **강점:**  
  비트/버퍼/직렬화, 경량 자료구조, 기본 동시성(SPSC), 고정소수점, 파서, 체크섬/CRC, TLV/프로토콜 기초

- **보통:**  
  FSM, 타임아웃/타이머, 로그, wear leveling 기초

- **미흡:**  
  멀티코어 메모리 모델, 고급 lock-free, 실제 RTOS 커널 오브젝트 심층, 전력/클럭 구조, 디버깅/트레이스 기법, 성능/지연 분석, 아키텍처 설계 트레이드오프 설명 능력

- **비포함:**  
  C++ 현대 문법/RAII/템플릿/atomic 메모리 순서, 도메인 특화(SSD용 FTL, NVMe, NAND 특성 등)

---

## SSD Firmware 면접에서 핵심 추가 요구 영역  
(**굵게 표시된 테마는 빈출**)

- **프로토콜:**  
  NVMe 명령 세트, Submission/Completion Queue, Doorbell, SQ/CQ depth 튜닝, Interrupt coalescing

- **데이터 경로:**  
  PRP/SGL, Scatter-Gather, DMA alignment, Cache line, 메타데이터 레이아웃

- **NAND 특성:**  
  Page/Block 구조, Program/Erase cycle, Read disturb, Retention, Bad block 관리, Read reclaim

- **FTL 설계:**  
  Page vs Block mapping, Hybrid, Log-structured write path, GC 정책(온도 분류, greedy vs cost-benefit)

- **Wear leveling:**  
  Static vs Dynamic, Hot/Cold 분리, 이동 비용 추적

- **신뢰성:**  
  ECC(BCH/LDPC) 파이프라인 개요, RAID-like parity across dies/channels, Metadata journaling, Power-loss protection (PLP) 순서(Flush ordering)

- **QoS/Latency:**  
  Tail latency 원인(Queue contention, GC interference), Backpressure, Host-visible throttling

- **Thermal/Power:**  
  Throttling 상태 머신, Power state transitions, Idle background ops 스케줄링

- **성능 모델링:**  
  채널/웨이 병렬성, Outstanding commands vs Utilization, Bandwidth 계산 근사

- **진단/모니터링:**  
  SMART 속성, Telemetry log, Lifetime 예측(P/E cycle consumption)

- **보안:**  
  Namespace secure erase, TCG Opal(개념 수준), Firmware signing chain

- **테스트 인프라:**  
  Fault injection (bit flip, timeout), Power cut simulation, Consistency 검증(메타데이터 replay)

- **코드 품질:**  
  Crash dump 최소 포맷, Assert vs graceful degrade, 심볼/로그 최소화 전략

## 다른 도메인 전환 시 공통 Core (Drone / Humanoid / EV 등)

- RTOS: Preemption latency, Priority inversion 해결(PI mutex, ceiling)
- 동기화: Multi-producer ring, RCU 개념, Lock-free vs Hazard pointers(개요 수준)
- 실시간: Hard vs Soft deadlines, Worst-case path 식별, Budget enforcement
- 하드웨어 경로: DMA descriptor life cycle, Cache invalidate/clean, Memory barrier 사용 이유
- 센서/모션: Sensor fusion(대략), Time synchronization (PTP/체계)
- Safety: Watchdog escalation, Fault containment region, Safe state fallback
- 업데이트: Secure boot chain, Anti-rollback, A/B rollback trigger
- 전력: DVFS 개념, Clock tree gating, Sleep residency 결정

## C++ 대비 추가 (타사 FW/Embedded C++ 요구 대비)

- RAII로 자원(락, 버퍼, 매핑 테이블) 보호 → C 버전 구현과 비교 설명
- move semantics, noexcept, explicit, delete default
- 템플릿: traits를 이용한 compile-time endian 변환 선택, constexpr lookup table 생성
- std::atomic memory_order (relaxed/acquire/release/acq_rel/seq_cst) 시나리오 설명
- Lock-free 구조: ring, freelist, ABA 회피(tagged ptr) 개요
- 임베디드 제약: new/delete 제한, 커스텀 allocator, placement new, 예외 사용 금지 방침(대안 에러 코드)
- 코루틴(선택): 비동기 NVMe Admin vs IO 구분 시 표현 가능성(개념 수준)

## 갭 우선순위(SSD 지향)

1. NVMe 큐/명령/PRP/SGL 데이터 경로 → 스케치로 설명 가능하도록
2. NAND 물리 특성 + FTL 매핑/GC/Wear leveling 전략 비교표 작성
3. ECC/RAID/Power-loss sequence(Flush ordering + journal commit) 설명 능력
4. Tail latency 원인 분석 & GC 간섭 완화 아이디어(Idle GC, credit 시스템)
5. Thermal/Power state machine 설계 연습
6. Fault injection & Consistency 검증 시나리오(Test plan 형태)
7. C++ 현대 문법 + atomic ordering 사례 3개 준비
8. Lock contention 줄이기: Shard, per-core queue, batching 전략

## 간단 자가 점검 체크리스트

- NVMe SQ/CQ depth 선택 이유 말할 수 있는가?
- GC 트리거 조건(유휴, 임계 비율) 2가지 이상 제시 가능한가?
- Power cut 중 메타데이터 무결성 보장 절차 단계별?
- LDPC vs BCH 선택 트레이드오프 요약 가능?
- Tail latency 99.9% 개선 방법 3가지?
- Wear leveling metric(erase count variance) 추적 구조?
- Host IO vs Background(GC/Refresh) 간 스케줄 정책 설명?
- memory_order_release/consume/acquire 차이 개념?
- FTL mapping 캐시 eviction 정책(LRU vs segmented LRU) 논리?

## 결론

- 기존 100 + 확장 50 문제 = “언어/저수준 구현 역량”은 높음.
- SSD FW 면접 합격 확률을 높이려면 도메인(FTL, NVMe, NAND 신뢰성) + 성능·신뢰성 아키텍처 + 현대 C++ 최소 블록을 반드시 보강.
- 위 우선순위 로드맵을 따라 도메인 아키텍처 설명 능력(화이트보드)에 집중하면 차별화 가능.
