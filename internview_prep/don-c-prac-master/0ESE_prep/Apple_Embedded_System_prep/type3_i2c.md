# I2C 센서 드라이버 문제 상세 설명

---

## 1. I2C란?

- **Inter-Integrated Circuit**의 약자.
- 마스터(예: MCU)와 슬레이브(예: 센서) 간에 **동기식 직렬 통신**을 하는 방식.
- 2개의 주요 신호선:
  - **SCL**: 클럭
  - **SDA**: 데이터 (양방향)

---

## 2. I2C의 Half-Duplex 특성

- 한 번에 한 방향으로만 데이터가 흐름 (읽기 또는 쓰기).
- 여러 슬레이브 장치를 주소(7비트 또는 10비트)로 구분.

---

## 3. I2C 통신의 기본 시퀀스

1. **Start 신호**: 통신 시작
2. **슬레이브 주소 전송**: 읽기/쓰기 비트 포함
3. **명령 바이트 전송**: 센서에게 원하는 동작 요청 (예: 온도 읽기)
4. **Repeated Start 신호**: 읽기 모드로 전환할 때 사용
5. **슬레이브 주소(읽기 모드) 전송**
6. **데이터 바이트 읽기**
   - 첫 번째 바이트(MSB)는 ACK(더 읽을 데이터가 있음을 알림)
   - 두 번째 바이트(LSB)는 NACK(마지막 바이트임을 알림)
7. **Stop 신호**: 통신 종료
8. **받은 두 바이트를 16비트 값으로 합침**

---

## 4. 코드 흐름 예시

```c
uint16_t read_temperature_i2c(void) {
    i2c_start();
    i2c_write(SENSOR_ADDR << 1 | 0); // 쓰기 모드 (LSB=0)
    i2c_write(TEMP_CMD);             // 명령 바이트

    i2c_start();
    i2c_write(SENSOR_ADDR << 1 | 1); // 읽기 모드 (LSB=1)

    uint8_t msb = i2c_read(1); // 첫 바이트, ACK
    uint8_t lsb = i2c_read(0); // 두 번째 바이트, NACK

    i2c_stop();

    return ((uint16_t)msb << 8) | lsb;
}


## 5. 인터뷰에서 설명할 포인트

Start/Stop 신호: 통신의 시작과 끝을 명확히 구분
슬레이브 주소와 읽기/쓰기 비트: 장치 선택 및 동작 방향 지정
명령 바이트: 센서에게 원하는 동작을 요청
Repeated Start: 쓰기 후 바로 읽기 모드로 전환할 때 사용
ACK/NACK: 여러 바이트를 읽을 때 마지막 바이트는 NACK로 신호
바이트 합치기: 센서가 2바이트로 값을 보내면, 보통 상위 바이트(MSB)와 하위 바이트(LSB)를 합쳐 16비트 값으로 만듦
엔디안(Endian): 센서 데이터시트에서 바이트 순서(MSB/LSB)를 반드시 확인


## 6. 실전에서 주의할 점

데이터시트 확인: 명령 바이트, 데이터 순서, ACK/NACK, 주소 등은 센서마다 다름
타이밍: 일부 센서는 명령 후 약간의 딜레이가 필요할 수 있음
에러 처리: 실제 구현에서는 I2C 통신 에러, 센서 응답 없음 등도 고려해야 함

## 7. I2C와 SPI의 차이

I2C: Half-Duplex, 느림, 2선(주소로 슬레이브 선택), ACK/NACK 신호
SPI: Full-Duplex, 빠름, 여러 슬레이브 지원(각각의 CS 필요)

Start/Stop 신호, 주소/명령 전송, ACK/NACK, 바이트 합치기 등
