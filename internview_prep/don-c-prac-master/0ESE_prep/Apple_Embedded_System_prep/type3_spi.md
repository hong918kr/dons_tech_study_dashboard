# SPI 센서 드라이버 문제 상세 설명

---

## 1. SPI란?

- **Serial Peripheral Interface**의 약자.
- 마스터(예: MCU)와 슬레이브(예: 센서) 간에 **동기식 직렬 통신**을 하는 방식.
- 4개의 주요 신호선:
  - **SCLK**: 클럭
  - **MOSI**: 마스터 → 슬레이브 데이터
  - **MISO**: 슬레이브 → 마스터 데이터
  - **CS (Chip Select)**: 슬레이브 선택 신호 (LOW면 활성화)

---

## 2. SPI의 Full-Duplex 특성

- 데이터를 보낼 때 동시에 데이터를 받음.
- 예를 들어, 마스터가 1바이트를 보내면 슬레이브도 1바이트를 동시에 보냄.
- 센서에서 데이터를 읽으려면, **더미 바이트(보통 0x00)**를 보내면서 데이터를 받음.

---

## 3. 센서에서 2바이트 데이터 읽는 일반적인 순서

1. **CS를 LOW로 내려 센서 활성화**
2. **명령 바이트(command byte) 전송**
   - 예: 온도 읽기 명령(센서마다 다름, 예를 들어 0x01)
3. **데이터 수신**
   - SPI는 데이터를 보내야만 데이터를 받을 수 있으므로,
     센서에서 데이터를 받으려면 "더미 바이트(예: 0x00)"를 전송하면서 데이터를 읽음.
   - 예:
     - 첫 번째 더미 바이트 전송 → 첫 번째 데이터 바이트 수신
     - 두 번째 더미 바이트 전송 → 두 번째 데이터 바이트 수신
4. **CS를 HIGH로 올려 센서 비활성화**
5. **받은 두 바이트를 16비트 값으로 합침**

---

## 4. 코드 흐름 예시

```c
uint16_t read_temperature(void) {
    cs_low(); // 센서 선택

    spi_transfer(0x01); // 온도 읽기 명령 전송 (센서마다 다름)

    uint8_t msb = spi_transfer(0x00); // 첫 번째 데이터 바이트 수신
    uint8_t lsb = spi_transfer(0x00); // 두 번째 데이터 바이트 수신

    cs_high(); // 센서 비활성화

    return ((uint16_t)msb << 8) | lsb; // 두 바이트를 16비트로 합침
}

---

## 5. 인터뷰에서 설명할 포인트

CS 제어: 여러 SPI 장치가 있을 때, 원하는 장치만 활성화
명령 바이트: 센서에게 "온도값을 보내라"는 신호
더미 바이트: SPI의 Full-Duplex 특성 때문에 데이터를 받으려면 아무 값(보통 0x00)을 보내면서 데이터를 받음
바이트 합치기: 센서가 2바이트로 값을 보내면, 보통 상위 바이트(MSB)와 하위 바이트(LSB)를 합쳐 16비트 값으로 만듦
엔디안(Endian): 센서 데이터시트에서 바이트 순서(MSB/LSB)를 반드시 확인


---

## 6. 실전에서 주의할 점
데이터시트 확인: 명령 바이트, 데이터 순서, CS 제어 방식 등은 센서마다 다름
타이밍: 일부 센서는 명령 후 약간의 딜레이가 필요할 수 있음
에러 처리: 실제 구현에서는 SPI 통신 에러, 센서 응답 없음 등도 고려해야 함

---

## 7. SPI와 I2C의 차이
SPI: Full-Duplex, 빠름, 여러 슬레이브 지원(각각의 CS 필요)
I2C: Half-Duplex, 느림, 2선(주소로 슬레이브 선택), ACK/NACK 신호
요약
이 문제는 센서의 데이터시트에 따라 SPI 통신 시퀀스를 코드로 옮기는 능력,
CS 제어, 명령 전송, 더미 바이트 활용, 바이트 합치기 등
임베디드 저수준 드라이버의 핵심을 묻는 문제입니다.
실제 구현 시 센서 데이터시트를 반드시 참고해야 하며,
각 통신 방식의 특성을 이해하고 있어야 합니다.
