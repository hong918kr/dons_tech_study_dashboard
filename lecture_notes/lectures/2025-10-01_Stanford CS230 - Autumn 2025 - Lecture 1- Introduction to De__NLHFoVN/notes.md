# Stanford CS230 | Autumn 2025 | Lecture 1: Introduction to Deep Learning

> Stanford · 2025-10-01 · 01:00:17 · 강사: Andrew Ng · [영상 링크](https://www.youtube.com/watch?v=_NLHFoVNlbg)

## 📌 한 줄 요약

CS230 1강. 본격 기술 내용보다는 **수업 운영 방식 · 딥러닝이 왜 중요한가 · 코스 전체 구성 · AI 시대의 커리어 전략**을 다루는 오리엔테이션 강의. Andrew Ng가 "딥러닝을 *실용적으로* 잘 쓰는 사람"을 길러내겠다는 목표를 제시하고, scaling이 딥러닝을 지배하게 된 이유와 AI 보조 코딩 시대의 일하는 법·취업 관점을 풀어낸다.

## 🎯 핵심 메시지

> **"코딩이 쉬워지면 코딩하는 사람은 줄지 않고 오히려 늘어난다."**
> AI가 코딩을 자동화하니 코딩을 배우지 말라는 조언은 *역사상 최악의 커리어 조언*이 될 것. 펀치카드→키보드, 어셈블리→고급언어로 갈 때마다 코더는 더 많아졌다.

**보조 메시지**
- 딥러닝과 neural network는 오늘날 사실상 같은 말 — "deep learning"이 그냥 브랜딩이 더 좋았을 뿐.
- LLM에 프롬프트만 넣어선 안 되는 일이 많다 → 한 단계 더 내려가 **딥러닝 레이어를 직접 만질 줄 알아야** 풀린다.
- **빠르게, 그리고 책임감 있게 (move fast *and* be responsible)** — 빠른 팀이 오히려 더 안전하다(문제를 빨리 발견·수정).
- CS·ML·DL **기초(fundamentals)** 를 알아야 AI에게 "정확히 무엇을 원하는지"를 그 언어로 지시할 수 있다.

## 🗺️ 딥러닝의 위치 — 추상화 스택

아래로 갈수록 기반(foundation), 위로 갈수록 응용. 위에서 안 풀리면 한 층 내려가 직접 손본다.

```
Generative AI (Transformer)   ← 최신, 대부분 텍스트 생성. 프롬프트로 시작
        ↑ 위에서 안 되면 내려간다
Deep Learning (neural network) ← 이 수업의 중심
        ↑
Machine Learning              ← 데이터로 학습하는 알고리즘
        ↑
CS Fundamentals               ← 컴퓨터가 어떻게 동작하는지
```

- **CS230의 커버 범위**: 딥러닝을 중심으로, 아래로 ML 개념(목적함수·파라미터 최적화)을 일부, 위로 Gen AI(transformer가 무엇인가)를 일부 건드린다.
- generative AI = 딥러닝의 한 응용. 주로 **transformer**로 구현되어 텍스트(가끔 이미지·오디오)를 생성 → ChatGPT, Claude, Gemini, Llama 등 LLM.

## 📈 딥러닝이 부상한 이유 — Scaling

- **데이터 양 vs 성능** 그래프: 전통적 ML(로지스틱 회귀, 결정트리 등)은 데이터를 아무리 더 줘도 성능이 **plateau(정체)**. "넘쳐나는 데이터를 어떻게 써야 할지 모르는" 상태.
- 반면 신경망은 **작은 모델 → 중간 → 거대 모델**로 키울수록 성능이 계속 좋아진다. 즉 **대규모 신경망을 학습시키는 레시피 + 대량 데이터** 조합이 예외적 성능을 냄.
- 약 15년 전 **Stanford에서 GPU·CUDA로 딥러닝을 스케일업**한 초기 연구가 도화선. (재미있는 일화: 신경망 학습용 첫 GPU 머신을 Stanford 학부생 Ian Goodfellow가 기숙사 방에서 만들었다.)
- 이후 연구들이 **scaling이 예측 가능**함을 보임 → "GPU·연산·데이터를 이만큼 넣으면 성능은 이 정도" 예측 가능. OpenAI의 **scaling laws** 논문이 이 아이디어를 대중화 → 데이터센터·초거대 모델 투자로 이어짐.

## 🏫 코스 포지셔닝 — CS129 vs CS229 vs CS230

|------|------|------|

| **CS229** | 수학·이론 중심 | 매우 빠르고 강도 높음. 행렬·벡터 미적분 등 ML 알고리즘의 이론·수식 유도. 더 넓은 ML 기법 survey(지도/비지도, 결정트리, boosting, k-means 등). |
| **CS230** (이 수업) | 실용·딥러닝 집중 | math-light, 매우 실전적. ML 기법 중 가장 유용한 **딥러닝 한 분야를 깊게**. |

- **선수과목**: ML이 필수는 아님. 단, ML을 전혀 모르면 처음 2~3주가 빠르게 느껴질 수 있음.
- **229와 230 동시 수강 가능** — 두 커리큘럼은 의도적으로 겹침을 최소화.
- 229는 *실시간 대면* 강의, 230은 *플립드 러닝*(고품질 온라인 영상 시청 + 교실은 토론).

## 📚 코스 구성 — 온라인 5개 모듈

1. **신경망·딥러닝 기초** — TensorFlow/PyTorch 없이 **raw Python으로 밑바닥부터** 구현해 원리를 이해.
2. **신경망 튜닝** — hyperparameter(파라미터를 제어하는 파라미터: learning rate, 망 크기 등) 튜닝의 실전 스킬. *"새벽 2시에 hyperparameter 튜닝하던 경험이 실력을 가른다."*
3. **ML 프로젝트 전략** — 복잡한 시스템(예: 얼굴인식 출입문)에서 무엇을 먼저 할지 **체계적으로 진단**하는 법.
4. **Convolutional Networks (CNN)** — 주로 컴퓨터 비전(이미지) 응용.
5. **Sequence Models** — 시계열·텍스트 등 시퀀스. **transformer**도 다룸(Gen AI 혁명의 동력).

## 🛠️ ML 프로젝트 전략 — "규율 있는 개발 프로세스"

- 복잡한 시스템은 컴포넌트가 많다(얼굴인식: 이미지 정제 → 얼굴 추출 → 등록 → 비교 → 위조 사진 판별 …). 무엇에 시간을 쓸지 결정이 핵심.
- **경험 적은 팀의 실수**: 논문 하나 읽고 "데이터 더 모으자" 식으로 *무작위로* 할 일을 고름 → 6개월 데이터 수집했는데 성능 안 오르는 경우 많음.
- **데이터를 더 모을지 / GPU를 더 살지** 등은 *애플리케이션에 따라* 진단으로 결정해야 함. 뉴스 hype("AI엔 데이터·GPU가 많이 필요")만 보고 큰돈 쓰는 실수 사례 다수.
- 규율 있는 진단 프로세스는 **10배의 속도 차이**를 낸다(몇 달 → 며칠). 강의 후반에 **시뮬레이션 실습**으로 의사결정 연습 예정.
- **데이터가 충분한지 판단법**: 정답 공식은 없음. 유사 프로젝트 경험·논문이 있으면 감을 잡음(예: 얼굴인식은 고유 얼굴 5만 장이면 괜찮은 편). 완전 신규(green field) 문제는 **일단 소량으로 학습시켜 보고** 결과로 필요량을 가늠. (100개로 충분할 때도, 1000억 개로도 부족할 때도 있음.)

## 🤖 AI 트렌드 — 보조 코딩과 프로토타이핑

- **AI 보조 코딩**(Claude Code, Cursor, Gemini CLI, Codex 등)으로 개인 생산성이 사상 최고. Ng는 "다신 손으로 코딩하던 시절로 안 돌아가고 싶다"고.
- 소프트웨어를 두 갈래로: ① **빠르고 거친(quick & dirty) 프로토타입**, ② **프로덕션급 견고한 소프트웨어**. AI 보조 코딩이 가장 큰 차이를 내는 건 ①. (프로덕션엔 더 신중히 — agent coder가 DB 마이그레이션 오류로 테스트 DB를 날린 실제 사례.)
- **샌드박스 환경**(내 노트북에서만 돌고 민감정보 없음)에서는 보안·확장성·신뢰성 요구를 낮춰 **더 빨리 의사결정** 가능.
- **ML은 결과를 미리 알 수 없다**: 출력은 코드(100% 통제) + **데이터(통제 못 함)** 에 동시에 의존. 세상이 주는 데이터는 "기묘하고 놀랍다"(억양·속도·배경소음 등). → 시스템을 만들어 봐야 데이터의 실체와 사용자의 진짜 니즈를 발견 → **빠른 피드백 루프**가 가치를 만든다.
- "move fast and break things"는 *break*가 문제였을 뿐, 빠르게 가는 것 자체가 잘못은 아니다. → **"move fast and be responsible."**

## 💼 커리어 · 취업 관점

- **생산성 4단계** (낮음 → 높음):
  1. 경험 없음 + AI 모름
  2. 10년 경력 + AI 모름
  3. **신입 + AI 능숙** ← 2번보다 위
  4. 10년 경력 + AI 능숙 (최상)
  → **AI 이해가 매우 중요**, 단 경험도 중요. 실제로 Ng는 "곧 졸업하는 신입(AI 능숙)"을 "AI 안 쓰는 10년 경력 풀스택"보다 채용한 적 있음.
- **CS 졸업생 실업률 상승**: 하지만 실리콘밸리는 GenAI·딥러닝·ML 인재를 못 구해서 난리. 갭의 원인은 *2002년식 스킬셋*(AI 미반영 커리큘럼). 수요는 AI 결합 스킬에 몰려 있다.
- 최고의 개발자 = **AI 보조 코딩에 능숙 + CS 기초를 깊이 이해**. (비유: 미술사를 아는 협업자는 미드저니에 "장르·팔레트"의 언어로 지시해 멋진 그림을 뽑지만, 모르면 "로봇 그림 예쁘게 그려줘"밖에 못 함 → AI도 *그 언어를 아는 사람*이 압도적 성능.)
- CS·ML·DL 기초는 매일 중요한 의사결정에 쓰인다. 다른 학과 친구들에게도 **"빌더가 되라"**고 권하라 — 진입장벽이 역사상 가장 낮은 시기.

## 🧰 Gen AI 실무 도구 모음 (버즈워드 — 지금 다 몰라도 됨)

채용 시 Ng가 보는 "GenAI 응용 스킬셋":

- **RAG** (Retrieval Augmented Generation), **vector database**
- **evals & error analysis** (평가·오류 분석)
- **guardrails** (가드레일)
- **knowledge / 외부 지식 연결**, **multimodal**, **fine-tuning**
- **agentic workflows**

> 비용 일화: 프로토타입 땐 LLM API가 저렴($/백만 토큰)하지만, 사용자가 몰리면 청구액이 **폭증**. 이때 **딥러닝으로 작은 모델을 fine-tune**해 비용 곡선을 다시 꺾는 게 결정적 스킬.
