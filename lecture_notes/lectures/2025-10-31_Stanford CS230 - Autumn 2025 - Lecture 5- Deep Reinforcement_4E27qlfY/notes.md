## 📌 한 줄 요약

심층 강화학습(deep reinforcement learning)은 강화학습(reinforcement learning)과 딥러닝(deep learning)을 결합해, 좋은 의사결정의 시퀀스(sequence of good decisions)를 자동으로 학습하는 방법이다. 강의 전반부는 Q러닝(Q-learning) → 심층 Q러닝(deep Q-learning, DQN)을 벨만 방정식(Bellman equation), 경험 재현(experience replay), 엡실론 탐욕(epsilon-greedy) 같은 학습 기법과 함께 다룬다. 후반부는 GPT-2를 ChatGPT로 도약시킨 핵심 기술인 인간 피드백 기반 강화학습(RLHF, reinforcement learning from human feedback)을 SFT, 보상 모델(reward model)과 함께 설명한다.

## 🎯 핵심 메시지

> 강화학습은 "예시로 가르치는(teach by example)" 지도학습과 달리 "경험으로 가르치는(teach by experience)" 방식이다. 핵심은 라벨이 지연되는(delayed labels) 환경에서 좋은 의사결정의 시퀀스를 만들어내는 것이며, 그 학습 신호의 뼈대가 벨만 방정식이다.

**보조 메시지**
- 바둑(Go)처럼 상태 공간이 방대하고 정답(ground truth)이 명확하지 않은 문제는 지도학습으로 풀기 어렵다 → 강화학습이 적합하다.
- Q 테이블(Q-table)은 상태·행동 공간이 커지면 다루기 불가능 → 신경망을 보편 함수 근사기(universal function approximator)로 써서 Q 함수를 근사한다(DQN).
- DQN은 라벨이 없으므로 신경망 자신이 만든 추정값(벨만 타깃)을 라벨처럼 써서 지도학습을 흉내 낸다.
- 안정적 학습을 위한 실전 기법: 전처리(pre-processing), 종료 상태(terminal state) 처리, 경험 재현, 엡실론 탐욕 탐색.
- RLHF는 게임의 강화학습 틀을 언어 모델에 그대로 적용해, 인간의 응답이 아니라 인간의 **선호(preference)** 에 정렬(align)시킨다.

## 🧭 강화학습이란 무엇인가

지도학습과 강화학습의 차이:

| 구분 | 지도학습(supervised learning) | 강화학습(reinforcement learning) |
|---|---|---|
| 학습 방식 | 예시로 가르침 (cat / non-cat) | 경험으로 가르침 (환경과 상호작용) |
| 라벨 | 즉시·명확 | 지연됨(delayed), 희소함(sparse) |
| 목표 | 입력→출력 매핑 | 좋은 의사결정의 시퀀스 |

**바둑을 지도학습으로 풀면 안 되는 이유 (강의 토론 정리)**
- 가능한 보드 상태가 너무 많아 모든 상태를 데이터로 못 본다 → 일반화 실패.
- 한 수가 좋은 수였는지조차 알 수 없고, 장기 전략(long-term strategy) 정보가 없는 일회성(one-off) 라벨만 본다.
- 정답(ground truth)이 잘 정의되지 않음 — 최고의 인간도 매번 최선의 수를 두지 않으므로, 최고 인간을 타깃으로 삼아도 그 이상으로 못 간다.

**강화학습 응용 예시:** 게임(Atari, 바둑, Dota/StarCraft), 자율주행(autonomous driving)의 동적 계획, 로봇 제어(robotic control), 그리고 (강사가 가장 큰 응용이라고 언급한) 광고·마케팅·실시간 입찰(real-time bidding) — 구매까지 이어지는 장기적 전략이 필요하기 때문.

## 🗣️ 핵심 용어와 기본 틀(framework)

에이전트(agent)가 환경(environment)과 상호작용한다.

- **행동(action) $a_t$**: 시간 $t$에 취하는 행동.
- **상태(state) $s_t$**: 행동에 따라 $s_t \to s_{t+1}$로 전이(transition).
- **관측(observation) $o_t$**: 에이전트가 실제로 보는 정보. 상태와 같을 수도 있다.
- **보상(reward) $r_t$**: 행동 후 받는 값. 목표는 보상의 최대화.

**상태 ≠ 관측인 이유:** 바둑/체스는 관측 = 상태(모든 정보가 보임)지만, League of Legends·StarCraft는 안개(fog)로 일부만 보이므로 관측 < 상태. 또한 오픈월드 게임처럼 계산상의 이유로 관심 영역만 관측하기도 한다.

**전이(transition):** 상태 $s_t$에서 행동 $a_t$를 취해 $o_t$, $r_t$를 관측하고 $s_{t+1}$로 넘어가는 전체 과정.

## ♻️ 토이 예제: "Recycling is good"

5개 상태의 간단한 환경으로 Q러닝의 직관을 잡는다.

- 상태: S2(초기, 갈색) / S1·S5(종료, 파랑) / S3·S4(일반)
- 보상: 쓰레기통(S1) **+2**, 초콜릿 포장 줍기(S4) **+1**, 재활용통(S5) **+10**
- 행동: 왼쪽 / 오른쪽
- 추가 규칙: 청소부가 3분 뒤 도착, 한 칸 이동에 1분 → S3↔S4를 무한히 왕복하며 보상을 긁어모으는 행동을 막는다.

**리턴(return)** 은 할인된 보상의 합으로 정의한다:

```
R = r_0 + γ·r_1 + γ²·r_2 + γ³·r_3 + ...
```

- **할인 계수(discount factor) γ ∈ [0, 1]**: 시간/돈의 가치, 로봇의 에너지 소모 같은 개념. 지금 받는 1달러가 10년 뒤 1달러보다 낫다.
- γ = 1 (시간 무관): 최적 전략은 오른쪽, 오른쪽, 오른쪽 → 총 보상 11 (1 + 10).
- γ = 0.9: 여전히 오른쪽 행 → 리턴 9.

**즉시 보상(immediate reward) $r_0$는 할인하지 않는다.**

## 📊 Q 테이블과 백트래킹(backtracking)

**Q 테이블**: 크기 = (상태 수 × 행동 수). 각 칸 $Q(s,a)$ = "상태 $s$에서 행동 $a$를 취하는 것이 얼마나 좋은가". 이 표만 완성하면 에이전트는 각 상태에서 가장 큰 Q값의 행동만 고르면 된다.

환경을 트리로 보고 즉시 보상을 매긴 뒤, **뒤에서부터 거꾸로 올라오며(backtracking)** 할인 리턴을 채운다 (γ = 0.9 예시):

```
S3에서 오른쪽으로 가면 → 즉시보상 1 + 0.9 × 10 = 10
S2에서 오른쪽으로 가면 → 즉시보상 0 + 0.9 × 10 = 9
S3에서 왼쪽으로 S2로 가면 → 0 + 0.9 × 9 = 8.1
```

### 벨만 최적 방정식(Bellman optimality equation)

강화학습에서 가장 중요한 식. 최적 Q 테이블은 모든 (상태, 행동) 쌍에서 이 식을 만족한다:

```
Q*(s, a) = r + γ · max_{a'} Q*(s', a')
```

직관: 완벽한 Q 함수를 가졌다면, 어떤 상태에서 행동 $a$를 하면 보상 $r$을 얻고 새 상태 $s'$로 가며, 거기서 또 최선의 행동을 반복한다 → 이것이 정확히 위에서 한 백트래킹이다. (즉시 보상 + 할인 × 다음 상태에서의 최선의 행동값)

### 정책(policy)

상태가 주어지면 무엇을 할지 알려주는 함수. Q러닝에서는:

```
π(s) = argmax_a Q*(s, a)
```

즉 "표에서 해당 상태를 보고, 가장 높은 Q값을 주는 행동을 고른다."

**Q 테이블의 한계:** 상태·행동 공간이 방대해지면(바둑처럼 돌을 어디에나 둘 수 있는 경우) 행렬이 감당 불가능하게 커진다 → 여기서 딥러닝이 등장한다.

## 🤖 심층 Q러닝(Deep Q-Learning, DQN)

Q 테이블 조회(lookup) 대신, 신경망 한 번의 순전파(forward pass)로 Q값을 얻는다.

- **입력**: 상태 $s$ (예: 원핫 벡터 `0 1 0 0 0` = state 2).
- **출력 층**: 행동 수만큼의 뉴런. 행동이 2개면 $Q(s, \text{left})$, $Q(s, \text{right})$ 두 값을 출력.

### 라벨이 없는데 어떻게 학습하나?

우리가 아는 두 가지: ① 보상 구조(reward structure), ② 최적 Q 함수는 벨만 방정식을 만족한다는 사실. 이 둘로 **타깃 Y를 스스로 만들어** 지도학습을 흉내 낸다.

L2 손실(quadratic loss)을 쓴다:

```
L = ( Y − Q(s, a) )²
```

타깃 Y는 벨만 방정식으로 정의한다 (현재 네트워크가 왼쪽이 더 낫다고 판단한 경우):

```
Y = r_left  +  γ · max_{a'} Q(s'_left, a')
     └즉시보상┘    └─ 두 번째 순전파로 추정 ─┘
```

- **순전파가 2번 일어난다**: ① 상태 $s$를 넣어 행동 선택, ② 다음 상태 $s'$를 넣어 최선의 Q값을 구해 타깃에 더함.
- **한 스텝만 앞을 본다(one step lookahead)** — 여러 스텝 보면 계산이 무거워진다.
- 타깃 Y는 처음엔 부정확하지만 "아무것도 없는 것보다는 낫다." Q가 좋아지면 타깃 Y도 같이 좋아져서 함께 수렴한다.
- **타깃 Y는 고정(fixed)으로 취급한다**: Y 안의 Q항도 파라미터에 의존하지만, 역전파 시 미분하지 않고 상수처럼 다룬다.
- **종료 상태(terminal state)** 에서는 벨만 항이 없고 Y = 즉시 보상뿐.

### 바닐라 Q러닝 의사코드(pseudo-code)

```
Q 네트워크 파라미터 무작위 초기화
for each episode:                          # 한 에피소드 = 시작~종료까지 한 판
    초기 상태 s에서 시작
    while not terminal:                     # 타임스텝 반복
        s를 Q에 순전파
        최대 Q값을 주는 행동 a 실행
        보상 r과 다음 상태 s' 관측
        s'를 Q에 순전파해 타깃 Y 계산 (벨만)
        손실 L = (Y − Q(s,a))² 로 경사하강(gradient descent) 업데이트
```

## 🎮 사례: Atari Breakout으로 본 실전 기법

벽돌깨기(Breakout)에 DQN을 적용하며 입출력과 전처리를 설계한다.

- **입력 상태**: 화면 픽셀.
- **출력**: 행동별 Q값 (왼쪽 / 오른쪽 / 정지 — 3개).

### 전처리(pre-processing) f(s)

차원을 줄여 계산을 빠르게:

| 처리 | 이유 |
|---|---|
| 점수(score) 잘라내기 | "항상 이기는 것"이 목표면 점수는 무관. 단, 축구처럼 점수에 따라 전략이 바뀌는 게임은 점수가 필요 — 설계자의 판단. |
| 그레이스케일(grayscale) 변환 | 색은 사용자 경험용일 뿐. (단, DeepMind가 Seaquest류 게임에서 채널 제거 시 물고기가 사라져 실패한 사례 있음) |
| 높이·너비 축소 | 차원 축소 |
| **프레임 히스토리(history) 4장** | 단일 화면으로는 공의 진행 방향을 알 수 없다 → 여러 프레임으로 속도/방향 파악 |

> 화면 픽셀을 그대로 쓰는 이유: 저차원 표현이 한 게임엔 더 좋을 수 있지만, **단일 알고리즘으로 50여 개 Atari 게임을 풀려면** 인간이 보는 화면을 그대로 주는 편이 더 잘 일반화된다.

**아키텍처**: 픽셀을 다루므로 합성곱 신경망(convolutional network) — conv + ReLU 블록들 뒤에 완전연결 층(fully connected layer)으로 Q값 출력.

### 경험 재현(experience replay)

**문제점:** ① 연속한 화면들이 강하게 상관(correlation)됨 — 공이 한 방향으로 이동하는 거의 같은 프레임에 반복 학습하면 비효율. (지도학습으로 치면 고양이 미니배치 → 개 미니배치 → 고양이… 식으로 수렴 안 됨) ② 한 경험을 한 번 쓰고 버려 재사용 안 함.

**해결:** 각 전이(transition) = (s, a, r, s')를 **재현 메모리(replay memory) D** 에 저장하고, 매 스텝 D에서 **무작위로 미니배치를 샘플링**해 학습한다.
- 상관 줄이고, 데이터 재사용으로 효율↑.
- 행동 자체는 게임 진행 방향대로 실제로 취하되, 파라미터 업데이트는 그 행동이 아니라 샘플된 경험으로 한다.
- 발전형: **우선순위 스위핑(prioritized sweeping)** — 경사(gradient)가 큰 통찰력 있는 경험(예: 체스의 큰 실수)에 가중치를 줘 더 자주 다시 학습.

### 탐험 vs 활용 & 엡실론 탐욕(epsilon-greedy)

**지역 최솟값(local minima) 문제:** 무작위 초기화된 네트워크가 보상 0짜리 행동을 먼저 시도해 0으로 학습하고, 그다음 보상 1짜리 행동에 정착하면, 보상 1000짜리 상태를 **영원히 방문하지 않는다.**

- **활용(exploitation)**: 아는 길을 반복하며 더 잘하게 됨 (매일 같은 자전거 경로).
- **탐험(exploration)**: 안 가본 길을 시도 (남쪽 경로가 더 빠를 수도).
- **엡실론 탐욕**: 확률 ε(예: 5%)로 무작위 행동을 취해 새 경로를 방문하게 한다. (체스에서 가끔 창의적 수를 두는 것과 같음)

> Q&A: 초기값을 무한대로 두면 안 되나? → 세 Q값이 모두 무한대면 선택 불가, 또 보상 대비 손실/경사가 폭발해 학습이 어렵다. 보상 구조를 예측할 수 없으므로 무작위 초기화 + 엡실론 탐욕이 여러 환경에 더 잘 확장된다.

### 모든 기법을 합친 최종 의사코드

```
Q 네트워크 파라미터 초기화, 재현 메모리 D 초기화
for each episode:
    초기 상태 s, terminal = false
    while not terminal:
        확률 ε로 무작위 행동, 아니면 argmax Q(f(s), a)
        행동 실행 → 보상 r, 다음 상태 s' 관측
        s' 전처리, 전이 (f(s), a, r, f(s'))를 D에 저장
        D에서 미니배치 무작위 샘플
        타깃 Y 계산 (종료면 r, 아니면 벨만), 손실로 경사하강
```

학습 결과 에이전트는 사람처럼 **공을 벽 뒤로 보내 터널을 뚫는** 전략을 스스로 발견한다. 동일 알고리즘(무수정)으로 Pong, Seaquest, Space Invaders 등 다수 게임을 풀 수 있다는 점이 인상적.

## 🧗 고급 주제

### Montezuma's Revenge — 희소·지연 보상

열쇠를 얻으려면 사다리·밧줄·적 회피 등 길고 정확한 행동 시퀀스가 필요한데, 무작위 네트워크가 이를 우연히 해낼 확률이 극히 낮다. 인간은 "사다리/밧줄/적"에 대한 **사전 지식(prior knowledge)·직관(intuition)** 으로 쉽게 푼다.
- **모방 학습(imitation learning)**: 무작위 초기화 대신, 사다리 같은 개념을 미리 알게 해 보상에 더 빨리 도달하도록 시작점을 개선.

### PPO와 정책 기반 방법

- 매우 인기 있는 알고리즘 **PPO(Proximal Policy Optimization)** (Schulman의 TRPO/PPO 논문). (더 최신으로 Stanford의 **DPO** 언급, 본 강의 범위 밖)
- Q러닝은 **가치 기반(value-based)** — Q값을 배우고 정책은 argmax. PPO는 **정책을 직접** 학습하는 더 확률적(probabilistic) 방법.
- **연속 공간(continuous spaces)** 에 강함 — 자율주행처럼 핸들을 "몇 도" 돌리는 연속 행동이면 Q러닝은 행동을 잘게 쪼개야 해 비효율. PPO는 **기대 이점(expected advantage)** 개념으로 "현 상태 대비 얼마나 더 나은가"를 다룬다.

### 보상 정의(체스/바둑 예) 와 자기 대국(self-play)

- 바둑: 이기면 1, 아니면 0 (마지막 수까지 모두 0). 체스: 말을 잡는 중간 보상(intermediate reward)을 주거나, 최종 보상만 주는 end-to-end 방식(더 어렵지만 더 최적일 수 있음).
- **경쟁적 자기 대국(competitive self-play)**: 같은 모델을 다르게 초기화해 서로 겨루게 하고, 더 나아진 모델을 나머지에 복사 후 반복. Sumo 같은 환경에서 발(feet) 공격, 무게중심 낮추기 같은 **창발적 행동(emergent behavior)** 이 나타남.
- AlphaGo의 "이상한 수"는 인간과 달리 에이전트가 **이기는 것 자체** 만 최대화하기 때문 — 큰 차이가 아니라 작은 차이로도 이기기만 하면 되므로 직관에 어긋나 보인다.

## 🧠 RLHF — 인간 피드백 기반 강화학습

GPT-2와 ChatGPT를 가른 핵심 기술. LLM을 인간의 **선호** 에 정렬한다.

### 사전학습(pre-training)의 문제

언어 모델의 학습 목표는 **다음 토큰 예측(next token prediction)**:

```
"deep learning" → "is" → "so" → "cool" ...
```

이렇게 학습된 사전학습 모델의 한계:
1. **온라인 데이터는 도움됨(helpfulness)을 반영하지 않음** — "deep learning is so cool"은 많지만 "what is deep learning"에 답하는 형태가 아니다. 모델은 질문에 답이 아니라 텍스트를 이어 쓰도록 학습됨.
2. **좋음/공손함/도움됨 개념이 없음** — "노트북이 안 켜져요, 어떻게 하죠?"에 사실 나열("노트북은 전원 문제로 안 켜지기도 합니다")만 하고 실제 해결 단계를 주지 않는다.

### 1단계: 지도 미세조정(SFT, Supervised Fine-Tuning)

인간이 작성한 **프롬프트-응답 쌍** 데이터셋으로 미세조정.

```
프롬프트: "Explain deep learning to a beginner"
+ 인간 작성 응답: "Deep learning is a type of machine learning that uses neural ___"
→ 모델이 "networks" 예측 (사전학습과 같은 손실)
```

- 한계: 데이터 수집 비용이 매우 큼(초기 InstructGPT는 약 **13,000쌍**으로도 좋은 성과). 지도학습이라 미관측 프롬프트로의 **일반화 보장 없음.**
- SFT는 좋은 행동의 **모방(imitation)** 일 뿐, **선호 최적화(preference optimization)** 가 아니다.

### 2단계: 보상 모델(Reward Model, RM)

인간의 응답이 아니라 **선호** 에 정렬하기 위해, 어떤 응답을 인간이 선호하는지 예측하는 별도 모델을 학습.

- 라벨러(labeler)에게 같은 프롬프트의 응답 2개 이상(SFT에서 온도 조절 등으로 샘플)을 보여주고 순위 매김 → **선호 데이터(preference data)**, 쌍별 비교(pairwise comparison).
- RM은 **SFT에서 초기화**하되, 마지막 소프트맥스(softmax) 층을 제거하고 **스칼라 값을 내는 선형 층(reward head)** 으로 교체.
- 손실 함수는 **선호된 응답에 더 높은 보상**을 주도록 학습 → 인간 선호의 프록시(proxy)인 비평가(critic)가 완성됨.

> 실제 인간 대신 모델을 쓰는 이유: 모든 입력에 폭넓게·확장성 있게 적용 가능. 또 "둘 중 무엇을 선호하나"를 묻는 게 직접 답을 쓰게 하는 것보다 훨씬 빠르다(ChatGPT가 응답 선호를 묻는 이유).

### 3단계: RLHF — 게임 강화학습 틀의 재사용

앞서 배운 강화학습 setup을 LLM에 그대로 매핑한다:

| 강화학습 요소 | RLHF에서의 의미 |
|---|---|
| 목표(objective) | 보상 모델이 주는 기대 보상 최대화 (인간 선호 정렬) |
| 에이전트(agent) | 미세조정 중인 언어 모델 |
| 환경(environment) | 가능한 프롬프트·연속(continuation)들의 공간 |
| 상태(state) | 프롬프트 + 지금까지 생성된 토큰들 |
| 다음 상태(next state) | 토큰 하나가 추가된 상태 |
| 행동(action) | 다음 토큰 선택 (정책이 결정) |
| 보상(reward) | 보상 모델이 추정 (인간 선호 대리) |
| 에피소드(episode) | 하나의 완전한 프롬프트(생성 완료까지) |

**핵심 특징 — 희소·에피소드형 보상(sparse, episodic reward):**
- 모델은 **매 토큰마다 보상을 받지 않는다.** 보상 모델이 프롬프트+응답 전체를 평가하므로, **생성이 끝나야** 보상이 나온다.
- 중간 보상은 보통 0 → 체스처럼 끝에서만 잘했는지 알 수 있는 희소 보상 문제. 그래서 "좋은 의사결정의 시퀀스"를 충분히 만들어 비평가가 선호하는 응답을 내야 한다.

흐름 요약: **사전학습 모델 → (SFT) → SFT 모델 → (RM + RLHF) → 정렬된 모델.**

> 강의 끝에 Andrej Karpathy의 영상을 언급 — 강화학습이 때때로 매우 비효율적이며 인간의 사고가 훨씬 효율적이라는 점, 즉 RL이 최선의 도구이긴 해도 여전히 한계가 있다는 관점을 소개.

## 🔑 핵심 용어

| 용어 | 설명 |
|---|---|
| 에이전트 / 환경(agent / environment) | 행동하는 주체와 그 주체가 상호작용하는 세계 |
| 상태 / 관측(state / observation) | 환경의 실제 상태 / 에이전트가 보는 정보(부분 관측 가능) |
| 보상 / 리턴(reward / return) | 단일 행동의 점수 / 할인된 보상의 누적합 |
| 할인 계수(discount factor) γ | [0,1] 사이 값. 미래 보상의 현재 가치를 낮춤 |
| Q 함수 / Q 테이블 | $Q(s,a)$ = 상태 $s$에서 행동 $a$의 가치 |
| 벨만 최적 방정식(Bellman optimality) | $Q^*(s,a)=r+\gamma\max_{a'}Q^*(s',a')$, 최적 Q가 만족하는 식 |
| 정책(policy) π | 상태→행동 함수. Q러닝에선 $\arg\max_a Q^*(s,a)$ |
| DQN(deep Q-network) | Q 테이블을 신경망으로 근사 |
| 경험 재현(experience replay) | 전이를 메모리에 저장 후 무작위 샘플로 학습, 상관 제거·재사용 |
| 엡실론 탐욕(epsilon-greedy) | 확률 ε로 무작위 행동 → 탐험 보장 |
| 탐험 vs 활용(exploration / exploitation) | 새 경로 시도 vs 아는 길 강화 |
| 종료/에피소드(terminal / episode) | 게임 끝 상태 / 시작~종료까지의 한 판 |
| 모방 학습(imitation learning) | 인간 사전지식으로 시작점 개선 |
| PPO | 정책을 직접 학습하는 확률적·연속공간 친화 알고리즘 |
| 자기 대국(self-play) | 모델끼리 겨루며 더 나은 모델을 복사·반복 |
| SFT(supervised fine-tuning) | 인간 작성 프롬프트-응답 쌍으로 미세조정(모방) |
| 보상 모델(reward model) | 인간 선호를 예측하는 스칼라 출력 모델(critic) |
| RLHF | 보상 모델을 평가자로 두고 LLM을 선호에 정렬하는 강화학습 |

## ✍️ 학습 메모

- **RL을 한 문장으로**: "좋은 의사결정의 시퀀스(sequences of good decisions)를 자동으로 만드는 것." 지도학습=예시로 가르침, RL=경험으로 가르침.
- **DQN의 핵심 트릭**: 라벨이 없으니 신경망 자신의 출력(벨만 타깃)을 라벨로 쓴다. 순전파 2번, 한 스텝만 앞을 봄, 타깃은 미분하지 않고 고정.
- **종료 상태에서는 벨만 항이 사라지고 타깃 = 즉시 보상** 임을 꼭 기억(흔한 실수 포인트).
- **세 가지 안정화 기법**(전처리 / 경험 재현 / 엡실론 탐욕)이 최근 RL이 잘 작동하는 큰 이유.
- **벨만 방정식은 평가 척도로도 쓰임**: 두 RL 모델 중 어느 쪽이 더 좋은지 헷갈릴 때, 손실(벨만 방정식이 잘 지켜지는지)을 모니터링하거나 자기 대국으로 비교.
- **RLHF는 새 알고리즘이 아니라 강화학습 틀의 재적용**: 게임의 (상태/행동/보상)을 (프롬프트+생성토큰 / 다음 토큰 / 보상모델 점수)로 바꾼 것. 보상이 끝에서만 나오는 희소·에피소드형 문제라는 점이 핵심.
- **SFT vs RLHF**: SFT는 인간 응답을 모방, RLHF는 인간 선호를 최적화. 선호 라벨링이 정답 작성보다 싸고 빠르며 일반화에 유리.
- 추천 자료: AlphaGo 다큐멘터리(Netflix) — RL 관점으로 보면 "이상한 수"의 의미를 이해할 수 있음.
