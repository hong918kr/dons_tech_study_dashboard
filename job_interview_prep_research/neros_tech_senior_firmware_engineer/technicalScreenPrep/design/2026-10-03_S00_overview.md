| 부품 | 역할 | 예시 장비 · 방법 [추정] | 쓰는 노트 |
|---|---|---|---|
| **Host runner** | 리그 하나를 맡는 PC/SBC, pytest 실행, CI runner | 미니 PC, Raspberry Pi 5, GitLab runner tag | 전부 |
| **Power control** | 전원 on/off, 전압 sweep, brown-out | 프로그래머블 PSU(SCPI), USB 릴레이, 전류 측정 | S01 · S05 · S06 · S08 |

| **Stimulus injection** | 입력을 스크립트로 | 센서 에뮬(SPI slave MCU), DAC, CRSF 주입, 패턴 생성기, 녹화 재생 | S01 · S03 · S04 · S06 |
| **Observation capture** | 출력을 타임스탬프와 함께 | 로직 애널라이저, DShot 디코더 MCU, 캡처 카드, 포토다이오드, 스펙트럼 분석기 | 전부 |
| **Link / environment** | 무선 · 환경 조건 | 차폐 박스, step attenuator, 채널 에뮬레이터, SDR, 열 챔버, shaker | S02 · S04 · S08 |
| **Time reference** | 독립된 시계 | GPIO 마커 + LA, PPS, µs 타이머 MCU | S01 · S04 · S06 · S08 |
| **DUT driver layer** | 테스트가 부르는 API | `DutCli`, `Flasher`, `Psu`, `RcInjector`, `MotorCapture` | [N04 문제 A](../notes/2026-10-02_N04_system_design_test_tooling.md), [문제 04](../python/problems/04_hil_conftest.md) |
| **Results pipeline** | 결과 · 측정값 · 아티팩트 저장과 판정 | JUnit + events.jsonl → DB, 아티팩트 → object storage, flaky 점수 | [N04 문제 C](../notes/2026-10-02_N04_system_design_test_tooling.md) |
| **Rig health** | 리그 자체가 정상인지 | 시작 전 self-test, golden unit, quarantine | [N04 문제 B](../notes/2026-10-02_N04_system_design_test_tooling.md), S07 |

- 핵심 원칙 셋: **(1) 독립 관측** — DUT가 스스로 보고하는 값(link quality, 타임스탬프)을 믿지 말고 바깥에서 잰다 **(2) 인프라 실패 분리** — 리그 고장을 펌웨어 회귀로 보고하지 않는다 **(3) 한 번 정의, 여러 곳에서 실행** — 같은 시나리오가 SITL · HITL · 비행 로그에 적용

## 4. "Design a test system for X" — 어느 직군이든 같은 6단계

| 단계 | 질문 | 예 (Flight) |
|---|---|---|
| 1. 무엇을 증명하나 | 이 펌웨어가 지켜야 할 약속 3개 | 루프 타이밍, failsafe, 모드 전환 |
| 2. 레벨 나누기 | unit은 개발자, 나머지는 어느 리그에서? | SITL = 로직 대량, HITL = 타이밍·드라이버 |
| 3. 리그 블록도 | 자극 → DUT → 관측, 시계, 전원 | 센서 주입 MCU → FC → DShot 캡처 |
| 4. 숫자 | 리그 수, 실행 시간, 판정 기준 | PR 10분 스모크, nightly 2시간, p99 지터 < 50µs [추정] |
| 5. 실패 모드 | 리그가 틀리면? flaky면? | self-test, quarantine, flip-rate |
| 6. 결과 흐름 | 누가 어떻게 보나 | MR 코멘트, 대시보드, 릴리즈 게이트 |

> 시작 대사: **"Let me start from what this firmware has to guarantee, then decide which of those each test level can actually prove, and only then draw the rig."**
