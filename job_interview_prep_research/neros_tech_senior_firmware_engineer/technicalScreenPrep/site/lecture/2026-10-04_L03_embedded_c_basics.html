이번 스크린 면접관은 Full Stack 엔지니어로 추정되니 [추정] 임베디드 C를 깊게 파고들기보다 "C 코드를 읽고, 흔한 버그를 알아보고, 테스트할 줄 아나" 정도를 볼 가능성이 크다. 그래서 이 강의는 짧은 코드 + 한 줄 답 위주다. 코드는 전부 lecture/code_c/l03_embedded_c.c 한 파일이고, -Wall -Wextra -Werror + ASan/UBSan으로 컴파일해서 모든 assert가 통과한 것이다 (make -C lecture/code_c test → L03: all examples PASS). 더 깊은 C/C++ 질문은 온사이트용 onsitePrep N04 C/C++ 기본기 · N07 임베디드 퀴즈에 있다.

0. 한 장 요약 — 나오면 이 한 줄로#

주제30초 답의 핵심
고정 폭 타입레지스터 · 프로토콜엔 uint8_t/uint32_t. int 크기는 플랫폼마다 다르다
signed / unsigned섞어서 비교하면 -1이 큰 unsigned가 된다. unsigned overflow는 wrap(정의됨), signed overflow는 UB
비트set |=, clear &= ~, toggle ^=, test >> n & 1. 필드 = shift + mask
포인터주소. p + 1은 한 원소 뒤. ->는 구조체 포인터 멤버
문자열'\0'로 끝나는 char 배열. 길이 + 1 바이트 필요. snprintf는 항상 끝을 막는다
memcpy vs memmove영역이 겹치면 memmove
엔디언little = 낮은 주소에 낮은 바이트. wire 데이터는 바이트 단위로 조립
volatile"매번 메모리에서 다시 읽어라" — ISR · 레지스터. 원자성 · 순서 보장은 아님
static함수 안: 값 유지 / 파일 범위: 이 파일 안에서만 보임
const읽기 전용 (보통 flash에 놓인다)
구조체 패딩정렬 때문에 빈 바이트가 생긴다 → sizeof ≠ 필드 합. wire 포맷에 struct를 그대로 쓰지 말 것
매크로인자마다 괄호, 전체에 괄호, 부작용 있는 인자 금지, 여러 문장은 do { } while (0)
ring buffer2의 거듭제곱 크기 + free-running index + 마스크 (L00)
timeout(uint32_t)(now - start) >= timeout — tick이 wrap 해도 맞다
ISR짧게, 블로킹 금지, 플래그 · 링에 넣고 main에서 처리

1. 고정 폭 타입과 정수 함정#

질문답
왜 int 대신 uint32_t?int는 16비트일 수도 32비트일 수도 있다. 레지스터 · 패킷은 크기가 정확해야 한다
uint8_t 255 + 1?0. unsigned는 wrap이 정의된 동작
int 최댓값 + 1?UB(정의되지 않은 동작). 컴파일러가 "안 일어난다"고 가정하고 최적화할 수 있다
-1 < 1u는?거짓. -1이 unsigned로 바뀌어 4294967295가 된다 → -Wsign-compare 경고를 켜 둔다
uint8_t a=200, b=100; a+b?300 — 계산은 int로 올라가서 한다(integer promotion). 다시 uint8_t에 넣으면 44

2. 비트 조작 — 가장 자주 나온다#

  • 말로 할 것: "set은 OR, clear는 AND NOT, toggle은 XOR, test는 shift 후 AND 1"
  • 레지스터 필드 쓰기 = read-modify-write: 읽고 → 그 필드만 지우고 → 새 값 OR → 쓰기. ISR도 같은 레지스터를 건드리면 그 사이에 끼어들 수 있다 → 인터럽트를 잠깐 끄거나, 하드웨어의 set/clear 전용 레지스터(예: STM32 BSRR)를 쓴다
  • v & (v - 1) = 가장 낮은 1비트 지우기 → popcount, 2의 거듭제곱 검사

3. 포인터#

선언뜻
const uint8_t *p가리키는 값을 못 바꿈 (읽기 전용 버퍼를 받을 때)
uint8_t *const p포인터 자체를 못 바꿈 (고정 주소)
volatile uint32_t *reg그 주소의 값을 매번 다시 읽음 (레지스터)
p[i]*(p + i)와 같다
  • 흔한 버그: NULL 역참조, 해제한 메모리 사용, 지역 변수의 주소를 반환, 배열 범위 밖 접근 → 테스트에서 ASan으로 잡는다

4. 문자열#

  • char buf[16]에 넣을 수 있는 글자는 15개 (마지막은 '\0')
  • strcpy · sprintf · gets는 길이를 모른다 → snprintf · strncpy(끝 처리 주의) · 직접 길이 검사
  • snprintf 반환값이 버퍼 크기 이상이면 잘린 것 — 테스트할 때 확인할 포인트

5. memcpy vs memmove#

  • memcpy는 영역이 겹치면 UB. 겹칠 수 있으면 memmove (뒤에서부터 복사해서 덮어쓰기를 피한다)
  • 면접 단골: "memcpy를 직접 짜 봐" → 바이트 루프 + "겹치면 memmove"까지 말하면 충분

6. 엔디언#

  • 네트워크 · 많은 센서 레지스터는 big-endian, MCU 메모리는 보통 little
  • 받은 바이트를 *(uint32_t *)buf로 읽으면 엔디언 + 정렬(alignment) 둘 다 문제 → 시프트로 조립 (위의 rd_le16, rd_be32)

7. volatile · static · const · extern#

키워드한 줄흔한 오해
volatile컴파일러가 읽기 · 쓰기를 생략하거나 레지스터에 캐시하지 못하게"volatile이면 스레드 · ISR에 안전하다" → 아니다. 원자성 · 메모리 순서는 보장 안 함
static (함수 안)호출 사이에 값 유지, 0으로 초기화 (.bss)스택이 아니라 전역 메모리에 있다
static (파일 범위)이 .c 파일 밖에서 안 보임 (내부 링크)이름 충돌 방지, 캡슐화
const읽기 전용. 전역 const는 보통 flash(.rodata)#define과 달리 타입이 있다
extern"정의는 다른 파일에 있다"는 선언헤더에 정의(=값)를 넣으면 다중 정의 에러
volatile const프로그램은 못 쓰지만 하드웨어가 바꾸는 값 (읽기 전용 상태 레지스터)모순 아님

8. 구조체 패딩#

  • 이 Mac(arm64)에서 실제 sizeof: padded_t = 12, 필드 순서만 바꾼 reordered_t = 8
  • __attribute__((packed))로 패딩을 없앨 수 있지만, 정렬 안 된 접근이 느리거나(일부 코어에선 fault) 이식성이 떨어진다 → wire 포맷은 바이트 직렬화가 정석
  • 테스트 포인트: _Static_assert(sizeof(hdr_t) == 4, "...")로 레이아웃을 컴파일 타임에 고정

9. 매크로 함정#

  • 규칙 4개: 인자마다 괄호 · 전체에 괄호 · 부작용 있는 인자(i++) 금지 · 여러 문장은 do { ... } while (0)
  • 가능하면 static inline 함수가 낫다 (타입 검사, 인자 한 번만 평가, 디버거에서 보임)

10. Ring buffer (C)#

  • 핵심 세 줄: 크기는 2의 거듭제곱, head/tail은 마스크 없이 계속 증가, head - tail이 개수 (unsigned wrap 덕분에 2^32를 넘어도 맞다)
  • ISR이 push, main이 pop이면 → head는 ISR만, tail은 main만 쓴다(단일 writer). 멀티코어 · 최적화까지 생각하면 C11 atomics의 acquire/release (onsitePrep N05)
  • Python 버전과 비교: L00 Part 1

11. 체크섬 · CRC#

  • 구현이 맞는지는 표준 check 값으로: CRC-8/SMBUS(poly 0x07)는 "123456789" → 0xF4
  • XOR 체크섬은 같은 비트가 두 번 틀리면 못 잡는다 → 링크에는 CRC

12. 시간 — tick wrap과 디바운스#

  • now >= start + timeout은 wrap 직전에 틀린다 (start + timeout이 넘쳐서 작은 수가 됨) → 항상 now - start 형태로
  • 디바운스: 버튼 · 리밋 스위치 · 노이즈 많은 입력. "N번 연속 같은 값일 때만 바뀐다"

13. 상태 머신#

  • 테스트 관점: 모든 (상태, 이벤트) 조합을 표로 돌린다 — 허용 안 되는 전이가 무시되는지가 버그의 단골 자리

14. 연결 리스트 뒤집기 (C 코딩 질문 단골)#

  • 말로: "prev, curr, next 세 포인터. 다음을 기억하고, 화살표를 뒤집고, 한 칸 전진." 빈 리스트 · 노드 1개 경계 확인

15. 메모리 맵 — 변수는 어디에 사나#

영역무엇예
.text (flash)코드함수
.rodata (flash)읽기 전용 상수const uint8_t table[] = {...}, 문자열 리터럴
.data (RAM, 초기값은 flash에서 복사)초기값 있는 전역 · staticint x = 5;
.bss (RAM, 0으로 초기화)초기값 없는 전역 · staticstatic int count;
stack (RAM)지역 변수, 함수 호출uint8_t buf[64]; (함수 안)
heap (RAM)malloc임베디드에선 잘 안 쓴다 — 단편화 · 실패 처리 · 시간 비결정성
  • 테스트 포인트: 스택 오버플로(큰 지역 배열, 깊은 재귀) — 스택 끝에 패턴(0xDEADBEEF)을 채우고 나중에 지워졌는지 확인하는 stack painting, map 파일로 RAM/flash 사용량 추적

16. ISR(인터럽트) 규칙#

규칙왜
짧게 — 플래그 세우기 · 링에 넣기만다른 인터럽트 · 메인 루프 지연
블로킹 금지 (printf, malloc, 대기 루프, mutex)ISR은 기다릴 수 없다
ISR과 공유하는 변수는 volatile + 원자적 접근컴파일러 캐시 방지, 찢어진 읽기 방지
main에서 여러 바이트 공유 데이터를 읽을 땐 짧게 인터럽트 끄기(critical section) 또는 단일 writer 구조읽는 도중 값이 바뀜
인터럽트 플래그를 지운다안 지우면 무한히 다시 들어온다

영어 한 줄: "Keep the ISR short: capture the data, push it into a ring buffer or set a flag, clear the interrupt, and do the real work in the main loop or a task."

할 것어떻게
경계값 표최솟값 −1, 최솟값, 최솟값 +1, 중간, 최댓값 −1, 최댓값, 최댓값 +1, 타입 극단값(INT_MIN)
