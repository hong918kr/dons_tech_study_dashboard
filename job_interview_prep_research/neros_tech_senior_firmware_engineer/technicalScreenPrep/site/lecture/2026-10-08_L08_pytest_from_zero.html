🐣 L08 · pytest 처음부터 — 무엇이 어떤 역할인지 아주 쉽게

pytest를 처음 보는 사람 기준으로, 단어 뜻(fixture · parametrize · @)부터 시작해서 6단계로 하나씩 쌓는다. 각 단계는 아주 작은 예제 파일 하나 + 그 파일을 실제로 돌렸을 때 화면에 나온 것 그대로다 (lecture/pytest101/, bash lecture/pytest101/run_examples.sh로 다시 돌릴 수 있다). 다 읽는 데 20분이면 된다.

0. 한 문장으로#

pytest = "test_로 시작하는 함수를 전부 찾아서 실행하고, 그 안의 assert가 참인지 확인해 결과를 알려 주는 프로그램"

비유하면:

실제 세계pytest
검사할 제품내가 만든 함수 · 클래스 (예: RingBuffer)
검사 항목 하나테스트 함수 하나 (def test_…():)
"이 값이어야 한다" 판정assert 결과 == 기대값
검사관pytest — 검사 항목을 알아서 찾아서 전부 돌리고 합격 · 불합격을 보고
검사 전에 지그(fixture)에 제품 올리기, 끝나면 내리기fixture — 준비와 정리
같은 검사를 여러 입력으로parametrize
진짜 장비 대신 쓰는 가짜 장비Mock

1.5 단어 뜻부터 — fixture · parametrize · @#

fixture = "고정 장치", 테스트가 올라가는 받침대#

  • 영어 fixture는 원래 "고정해 둔 장치 · 설비"라는 뜻이다. 공장 테스트에서 보드를 꽂아 고정하는 지그 · 픽스처(bed-of-nails, pogo-pin fixture)가 바로 그 말이다
  • 소프트웨어 테스트에서는 "테스트가 시작될 때 항상 똑같이 갖춰져 있어야 하는 상태"를 말한다 — 빈 버퍼, 열린 포트, 전원이 켜진 리그, 임시 폴더
  • 그래서 pytest의 fixture 함수가 하는 일은 공장의 지그와 같다:
공장 지그pytest fixture
보드를 지그에 꽂고 고정yield 앞: 준비 (버퍼 만들기, 포트 열기, 리그 전원 켜기)
검사 실행yield 자리에서 테스트 함수가 실행됨
검사 끝나면 보드 빼고 지그 원위치yield 뒤: 정리 (포트 닫기, 전원 끄기) — 테스트가 실패해도 실행
보드마다 같은 지그 상태에서 시작테스트마다 새로 준비 → 앞 테스트의 흔적이 안 남음

한 문장: fixture = 테스트가 올라가는 '항상 같은 출발 상태'를 만들어 주고, 끝나면 치워 주는 함수.

parametrize = "매개변수화", 값을 빈칸으로 바꾸기#

  • parameter = 매개변수 (함수의 입력 칸). parametrize = 고정된 값을 매개변수(빈칸)로 바꿔서 여러 값을 넣을 수 있게 한다는 뜻
  • 매개변수화하기 전 — 값이 박혀 있다:
  • 매개변수화한 뒤 — n, expected가 빈칸이 되고, 표의 줄마다 채워서 실행된다:

한 문장: parametrize = 같은 검사를 '입력 칸'으로 만들어 두고, 표의 줄마다 한 번씩 돌리는 것.

@ = 데코레이터, 함수 위에 붙이는 "꼬리표 / 포장지"#

  • @무엇 은 바로 아래 함수를 그 '무엇'에 한 번 통과시키라는 Python 문법이다. 아래 두 코드는 완전히 같다:
  • 데코레이터가 하는 일은 두 종류다: ① 함수를 감싸서 동작을 바꾸거나(위의 shout), ② 함수는 그대로 두고 꼬리표만 붙이거나 명단에 등록한다
  • pytest의 @는 ②번 — 꼬리표다:
붙인 것pytest에게 하는 말
@pytest.fixture"이 함수는 테스트가 아니라 준비물(fixture)이야. 누가 이 이름을 인자로 달라고 하면 실행해서 넣어 줘"
@pytest.mark.parametrize("n, expected", [...])"이 테스트에는 입력 표가 붙어 있어. 줄마다 한 번씩 돌려 줘"
@pytest.mark.skip(reason=...)"이건 건너뛰어"
  • pytest는 테스트를 모을 때 각 함수에 어떤 꼬리표가 붙었는지 읽고 그에 맞게 실행한다. 그래서 @를 안 붙이면 fixture가 그냥 평범한 함수가 되고, 테스트가 인자로 달라고 해도 pytest가 못 찾는다

직접 돌려서 확인한 것 (python decorator_demo.py):

  • 1) @shout 과 greet2 = shout(greet2) 결과가 같다 → @는 줄임말
  • 2) @register 는 함수를 바꾸지 않고 명단에만 적었다 → 꼬리표형 데코레이터
  • 3) @pytest.mark.parametrize 를 붙이자 test_is_even 에 parametrize 꼬리표와 입력 표가 붙었다. @pytest.fixture 를 붙인 rb 는 pytest가 관리하는 fixture 객체로 바뀌었다 → pytest가 이걸 보고 동작한다
헷갈리는 질문답
@는 pytest 전용 문법인가?아니다. Python 문법이다. @property, @dataclass, @staticmethod도 같은 것 (L01 9 · 10절)
@pytest.fixture 뒤에 괄호를 붙여도 되나?된다. @pytest.fixture / @pytest.fixture() 둘 다 OK. 옵션을 줄 땐 @pytest.fixture(scope="session")
@pytest.mark.parametrize에서 첫 인자가 문자열인 이유?테스트 함수의 인자 이름을 알려 주는 것. "n, expected" ↔ def test_is_even(n, expected) 이름이 같아야 한다
fixture와 parametrize를 같이 쓸 수 있나?된다. def test_wraparound(rb, laps): — rb는 fixture에서, laps는 표에서 (7절 예제)

3. 2단계 — "에러가 나야 맞는" 검사: pytest.raises#

  • with pytest.raises(IndexError): 블록 안에서 IndexError가 나면 통과, 안 나면 실패
  • 쓰는 곳: 빈 버퍼에서 pop, 잘못된 입력, 타임아웃 같은 에러 경로

4. 3단계 — 입력만 바꿔 여러 번: parametrize#

  • 위 표의 4줄이 테스트 4개가 된다: test_is_even[0-True], [1-False] …
  • for 문으로 돌리는 것과 차이: 하나가 실패해도 나머지는 계속 돌고, 어느 입력이 틀렸는지 이름으로 보인다

포인트설명
어떻게 연결되나테스트 함수 인자에 fixture 이름(port)을 쓰기만 하면 pytest가 그 fixture를 실행해서 결과를 넣어 준다. 직접 부르지 않는다
yieldyield 앞 = 준비, 뒤 = 정리. 테스트는 그 사이에 실행된다. 테스트가 실패해도 정리는 실행된다
테스트마다 새로기본은 테스트 하나마다 새 준비물 → 앞 테스트의 흔적이 다음 테스트에 안 남는다 (test_starts_open이 통과한 이유)
  • 실무 연결: 리그 열기 · DUT 리셋 · 끝나면 전원 끄기 = fixture. 비싼 준비(리그 연결)는 @pytest.fixture(scope="session")로 한 번만
  • Python의 with 문, C++의 RAII와 같은 생각: "정리는 반드시 일어난다"

6. 5단계 — 진짜 장치 대신 가짜: Mock#

줄뜻
fake = Mock()무엇이든 받아 주는 가짜 객체. fake.write(...), fake.readline() 다 된다
fake.readline.return_value = b"TEMP=23.5\n""readline이 불리면 이걸 돌려줘라" = 가짜 장치의 대답 정하기
fake.write.assert_called_once_with(b"TEMP?\n")"write가 딱 한 번, 정확히 이 바이트로 불렸나" = 보낸 것 검사
응답을 여러 개 차례로fake.readline.side_effect = [b"", b"TEMP=21\n"] — 첫 번째는 무응답, 두 번째는 정상 (재시도 테스트)
  • 왜 쓰나: 하드웨어 없이(CI에서도) 드라이버 로직을 검사하려고. 단, 진짜 장치에서 한 번은 확인해야 가짜가 현실과 어긋나지 않는다

8. 자주 하는 착각#

착각사실
테스트 함수를 내가 불러야 한다아니다. pytest가 test_로 시작하는 함수를 찾아서 부른다
fixture를 rb()로 불러야 한다아니다. 테스트 인자에 이름만 쓴다 (def test_fifo(rb):)
assert에 메시지를 꼭 써야 한다아니다. 실패하면 pytest가 실제 값 · 기대 값을 보여 준다
파일 이름은 아무거나pytest 만 치면 test_*.py (또는 *_test.py) 파일을 찾는다. 파일을 직접 지정하면 이름은 상관없다
unittest를 따로 배워야 한다pytest는 unittest로 쓴 테스트도 그대로 돌린다. 시작은 pytest 하나면 된다
pytest가 없으면 못 돌린다if __name__ == "__main__": test_fifo(...) 처럼 직접 불러도 된다 (단, fixture는 직접 만들어 넘겨야 함) — L05 형식

9. 면접에서 쓸 영어 (짧게)#

질문답
"Have you used pytest?""Yes — plain test functions with asserts, fixtures for setup and cleanup, parametrize for tables of inputs, and unittest.mock to fake hardware."
"What's a fixture?""A function that prepares something a test needs and cleans it up afterwards. The test just asks for it by name. Code after yield runs even if the test fails."
"Why parametrize instead of a loop?""Each input becomes its own test, so one failure doesn't hide the others, and the report shows exactly which input failed."
"Why mock?""To test driver logic without hardware — I script the device's replies and check exactly what we sent. Then one real-hardware test keeps the mock honest."
