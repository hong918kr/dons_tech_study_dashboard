0. 한 장 요약#

주제핵심 한 줄테스트와의 관계
C vs C++ (임베디드)C++의 "공짜" 기능(class, template, constexpr, RAII)은 쓰고, 비용 있는 것(예외, RTTI, heap, iostream)은 끈다빌드 플래그를 알아야 host 테스트 빌드와 타깃 빌드의 차이를 이해한다
참조 &NULL이 될 수 없는 별칭. 큰 객체는 const T&
enum class · constexpr · static_assert타입 안전한 enum, 컴파일 타임 계산 · 검증레이아웃 · 상수를 컴파일 타임 테스트로 고정
RAII생성자에서 잡고 소멸자에서 놓는다 — 모든 return 경로에서 정리critical section · 락 · 리그 자원 정리
class 기본초기화 리스트, explicit, const 멤버 함수, private
템플릿타입 · 크기를 컴파일 타임에 → RingBuffer<T, N>, heap 없음
std::array · std::optional고정 크기 배열 / 예외 없이 "값 없음"
인터페이스(가상 함수) + DIHAL을 인터페이스로 받으면 fake를 끼워 테스트가장 중요한 테스트 seam
템플릿 주입가상 호출 없이 같은 효과 (zero-cost)타깃 성능이 중요할 때의 seam
콜백함수 포인터 + void* ctx, 캡처 없는 람다, 템플릿 람다
레지스터volatile 구조체 + reinterpret_cast, static_assert(offsetof)레지스터 블록을 가짜 메모리로 바꿔 host에서 테스트
extern "C"C 코드와 링크GoogleTest로 C 펌웨어를 테스트할 때 필수
소유권복사 금지 · 이동, 실무는 unique_ptr / 정적 할당
함정slicing, 가상 소멸자, override, 정적 초기화 순서

1. 임베디드에서 C++의 무엇을 쓰고 무엇을 끄나#

쓴다 (비용 0에 가깝다)조심 / 끈다이유
class, 접근 제어, 참조, namespace예외 (-fno-exceptions)코드 크기, 실행 시간 비결정성, unwind 테이블
constexpr, static_assert, enum classRTTI (-fno-rtti): dynamic_cast, typeid코드 크기
템플릿 (RingBuffer<T, N>)heap: new, std::vector, std::string, std::function(할당 가능)단편화, 실패 처리, 시간
RAII, 람다(캡처 없거나 참조 캡처)iostream크기가 매우 크다
std::array, std::optional, <algorithm> 일부가상 함수 남용객체마다 vptr, 호출마다 간접 점프
  • 템플릿의 비용: 실행 비용은 없지만 타입마다 코드가 복제될 수 있다(code bloat) → map 파일로 크기 추적
  • 예외를 끄면 std::optional::value()처럼 예외를 던지는 API는 쓰지 않는다 → if (opt) / *opt

2. 참조#

  • 포인터 vs 참조: 참조는 NULL이 없고 다시 묶을 수 없다. "없을 수도 있다"면 포인터나 std::optional
  • 함정: 호출하는 쪽에서 scale(v, 4)만 보고는 v가 바뀐다는 걸 모른다 → 이름 · 문서로 드러낸다

3. enum class · constexpr · static_assert#

  • enum class Mode : uint8_t — 이름이 새어 나가지 않고, int로 몰래 바뀌지 않고, 크기를 정할 수 있다(wire 포맷)
  • constexpr 함수 · 표는 컴파일 타임에 계산 → 결과가 flash에 상수로
  • static_assert = 컴파일 타임 테스트. 크기 · 오프셋 · 상수 관계가 깨지면 빌드가 실패한다

4. RAII — C++이 테스트 코드와 펌웨어에 주는 가장 큰 선물#

  • RAII = Resource Acquisition Is Initialization: 자원의 수명 = 객체의 수명. 함수 중간에서 return해도, 에러 경로여도 소멸자가 정리한다
  • C에서 disable_irq(); ... if (err) { enable_irq(); return; } ... enable_irq();처럼 짝을 손으로 맞추던 것을 컴파일러가 보장
  • 같은 생각이 Python에선 with (context manager), pytest에선 yield fixture — "리그 전원은 테스트가 실패해도 반드시 끈다"
  • 복사를 = delete로 막는 이유: 복사되면 소멸자가 두 번 불려 "두 번 enable" 같은 버그

문법뜻

explicitLed led = 13; 같은 암시적 변환 금지

6. 템플릿 — 크기가 고정된 RingBuffer<T, N>#

  • N이 템플릿 인자라 배열이 객체 안에 정적으로 들어간다 (heap 없음). static_assert로 2의 거듭제곱을 컴파일 타임에 강제
  • std::optional<T>: 예외 없이 "꺼낼 게 없다"를 반환. C의 bool rb_pop(rb_t*, uint8_t *out)과 같은 정보
  • C 버전과 비교: L03 10절, Python 버전: L00 Part 1

7. 인터페이스 + 의존성 주입 — 테스트 가능한 C++의 핵심#

  • 피검 코드(TempSensor)가 구체 드라이버가 아니라 인터페이스(II2c&)를 받으므로, 테스트는 FakeI2c를 넘겨 재시도 · 에러 경로를 하드웨어 없이 검증한다
  • GoogleTest라면 FakeI2c 대신 gMock: MOCK_METHOD(bool, read, (uint8_t, uint8_t, uint8_t*, std::size_t), (override)); → L02 A5
  • 가상 소멸자: 부모 포인터로 객체를 지울 때 자식 소멸자가 불리게. 인터페이스엔 항상 virtual ~I() = default;
  • 비용: 객체마다 vptr 하나 + 호출마다 간접 점프. 대부분 무시할 수준이지만 μs 단위 ISR 경로라면 8절

테스트 seam어떻게 바꿔 끼우나비용언제

9. 콜백 — 함수 포인터, 람다#

  • ISR · C API에 넘길 땐 함수 포인터 + void* ctx (캡처 없는 람다는 함수 포인터로 바뀐다)
  • C++ 내부에선 템플릿 + 람다가 가장 싸다 (인라인됨). std::function은 편하지만 캡처가 크면 heap을 쓸 수 있다
  • 캡처: [&total] 참조, [total] 복사, [&] 전부 참조 — 콜백이 나중에 불리면 참조 캡처가 dangling이 될 수 있다

10. 메모리 맵 레지스터#

  • 레지스터 블록을 volatile 멤버를 가진 구조체로 표현하고, 타깃에선 reinterpret_cast<GpioRegs*>(주소)
  • static_assert(offsetof(...))로 레퍼런스 매뉴얼의 오프셋과 일치하는지 컴파일 타임에 검사
  • 테스트 트릭: 주소를 돌려주는 함수(gpio())만 바꾸면 host에서 가짜 메모리로 드라이버 로직을 테스트할 수 있다 (read-modify-write가 다른 핀을 안 건드리는지 등)

11. extern "C" — C 펌웨어를 C++ 테스트로#

  • C++은 오버로딩 때문에 함수 이름을 장식(mangling)한다 → C 컴파일러가 만든 심볼과 이름이 달라 링크 에러
  • 그래서 GoogleTest · CppUTest로 C 코드를 테스트할 때 extern "C" { #include "sensor.h" } (L02 A4 · A5가 실제로 그렇게 했다)
  • C 헤더를 C++에서도 쓰게 하려면 헤더 안에 #ifdef __cplusplus extern "C" { #endif

12. 소유권 — 복사 · 이동 · Rule of Zero#

  • 자원(메모리, 핸들, 포트)을 직접 소유하는 클래스는 복사 · 이동 · 소멸을 다 정해야 한다 (Rule of Three/Five)
  • 더 좋은 답은 Rule of Zero: 소유는 std::unique_ptr · std::array 같은 표준 타입에 맡기고, 내 클래스엔 특수 멤버 함수를 안 쓴다
  • 펌웨어에선 대개 heap 자체를 안 쓴다 → 정적 할당 · 고정 크기 풀

13. 함정 — 읽다가 알아봐야 하는 것#

함정증상예방
object slicing자식을 값으로 넘기면 부모 부분만 복사 → 가상 함수가 부모 것참조 · 포인터로
가상 소멸자 없음부모 포인터로 delete 하면 자식 소멸자 안 불림 (UB, 누수)인터페이스엔 virtual ~I() = default
override 안 씀시그니처가 살짝 달라 오버라이드가 아니라 새 함수가 됨항상 override
dangling 참조 · 람다 캡처사라진 지역 변수를 참조수명 확인, ASan
정적 초기화 순서다른 파일의 전역 객체가 아직 생성 전함수 안 static (Meyers singleton), 전역 객체 최소화
정수 함정C와 같다 (signed overflow UB, promotion)L03 1절

14. 테스트 엔지니어 관점 정리#

상황할 것
C++ 모듈을 테스트해야 한다의존성이 인터페이스 / 템플릿 인자 / 링크 seam 중 어디로 들어오는지 먼저 본다
seam이 없다개발자와 "HAL을 인터페이스로 빼자"를 제안 — 테스트 가능성은 설계 리뷰 항목
단위 테스트 프레임워크GoogleTest + gMock (C++ 표준), 작은 타깃이면 CppUTest (L02)
host 빌드 vs 타깃 빌드같은 소스를 두 번: host(ASan/UBSan, 예외 유무 동일하게) · 타깃(크로스 컴파일). 플래그 차이를 CI에 명시
컴파일 타임 테스트static_assert로 레이아웃 · 상수 · 템플릿 조건
정리 보장테스트 하네스의 리그 자원도 RAII 객체로 (C++ 하네스라면)
