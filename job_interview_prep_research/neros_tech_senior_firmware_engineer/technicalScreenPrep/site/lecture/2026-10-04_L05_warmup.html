Python 8#

01 · Two Sum — dict 로 '값 → 인덱스' 기억하기 (LeetCode 1)#

nums 와 target 이 주어질 때 합이 target 인 두 인덱스 [i, j] (없으면 []). O(n). 테스트 함수 하나 + main 까지 직접.

  • dict 기본 — d[k] = v 넣기 · k in d 있나(O(1)) · d[k] 꺼내기(없으면 KeyError) · d.get(k, 기본값) 안전하게 꺼내기
  • 순서가 중요: '확인 → 저장'. 저장부터 하면 같은 원소를 두 번 쓴다 ([3], 6 → [0, 0] 버그)
  • 복잡도: 시간 O(n), 메모리 O(n) (dict)
  • 빈 파일: python3 lecture/warmup/new.py py 1 · 정답 파일: 01_two_sum.py · 정답 실행: python3 lecture/warmup/py/01_two_sum.py

02 · Two Sum 변형 — dict 로 개수 세기 (합이 target 인 쌍의 수)#

nums 에서 i < j 이고 nums[i] + nums[j] == target 인 쌍의 개수를 O(n) 으로. dict.get 으로 빈도를 센다.

  • 01 은 dict 에 '인덱스'를, 이 문제는 '지금까지 본 횟수'를 넣는다 — dict 의 두 번째 단골 용도
  • count[x] = count.get(x, 0) + 1 이 세기의 기본형 (collections.Counter 도 같은 일)
  • 전부 짝을 비교하면 O(n²), dict 로 O(n)
  • 빈 파일: python3 lecture/warmup/new.py py 2 · 정답 파일: 02_two_sum_count_pairs.py · 정답 실행: python3 lecture/warmup/py/02_two_sum_count_pairs.py

03 · Two pointer — 정렬된 배열의 두 수의 합 (LeetCode 167)#

오름차순 nums 에서 합이 target 인 두 인덱스 [i, j] (없으면 []). 추가 메모리 O(1).

  • 같은 문제의 세 가지 풀이 — dict: O(n) 시간 · O(n) 메모리 / 투 포인터: O(n) 시간 · O(1) 메모리 / 원소마다 이진 탐색: O(n log n) · O(1)
  • 정렬돼 있다는 조건이 있으면 투 포인터가 가장 좋다 (메모리 0, 캐시 친화적)
  • 왜 맞나: 합이 작으면 왼쪽 값을 키울 수밖에 없고, 크면 오른쪽 값을 줄일 수밖에 없다 → 버리는 쌍 중에 답이 없다
  • 빈 파일: python3 lecture/warmup/new.py py 3 · 정답 파일: 03_two_pointer_sorted_pair.py · 정답 실행: python3 lecture/warmup/py/03_two_pointer_sorted_pair.py

04 · Two pointer (같은 방향) — 정렬된 배열의 중복 제거, 제자리 (LeetCode 26)#

정렬된 리스트 nums 를 제자리에서 중복 없이 앞쪽에 모으고, 고유 원소 개수 k 를 돌려준다. 추가 메모리 O(1).

  • 03 은 양 끝에서 좁혀 오는 투 포인터, 이건 slow(쓸 자리) · fast(읽는 자리)가 같은 방향으로 가는 투 포인터
  • list(set(nums)) 는 쉽지만 O(n) 메모리 + 순서 보장 안 됨 → 면접에선 제자리 O(1) 이 요구된다
  • 같은 패턴: 0 을 뒤로 밀기, 특정 값 제거, C 에서 버퍼 압축
  • 빈 파일: python3 lecture/warmup/new.py py 4 · 정답 파일: 04_two_pointer_dedup.py · 정답 실행: python3 lecture/warmup/py/04_two_pointer_dedup.py

05 · 이진 탐색 — left · right · mid (LeetCode 704)#

오름차순 nums 에서 target 의 인덱스, 없으면 -1. left/right/mid 로 O(log n).

  • 불변식: 답이 있다면 항상 nums[left..right] 안에 있다 → while left <= right
  • mid 는 (left + right) // 2 (Python 은 오버플로 없음, C 에선 left + (right - left) / 2)
  • 흔한 버그: left = mid / right = mid 로 두면 무한 루프 → 반드시 mid ± 1
  • 실무에선 bisect.bisect_left(nums, target) — 없을 때 '들어갈 자리'까지 준다
  • 빈 파일: python3 lecture/warmup/new.py py 5 · 정답 파일: 05_binary_search.py · 정답 실행: python3 lecture/warmup/py/05_binary_search.py

06 · BST — 삽입 · 검색 · 중위 순회#

Node(val) 로 이진 탐색 트리. insert(root, val) → root, contains(root, val) → bool, inorder(root) → 정렬된 리스트.

  • 05 이진 탐색과 같은 생각 — 작으면 왼쪽, 크면 오른쪽. 균형이면 O(log n), 한쪽으로 치우치면 O(n)
  • 중위 순회(왼쪽 → 나 → 오른쪽) 결과는 항상 정렬돼 있다 → 테스트에서 이걸로 트리 전체를 검증
  • 빈 파일: python3 lecture/warmup/new.py py 6 · 정답 파일: 06_bst.py · 정답 실행: python3 lecture/warmup/py/06_bst.py

07 · Ring buffer — head · tail · count#

RingBuffer(capacity): push(x) → bool (가득 차면 False), pop() → 가장 오래된 값 (비었으면 IndexError), peek(), len(), is_full().

  • head = 다음에 쓸 칸, tail = 다음에 읽을 칸, count = 들어 있는 개수. head == tail 이 '빈 것'인지 '가득 찬 것'인지 count 가 구분해 준다
  • 다른 방법 — count 없이 '한 칸 비우기' (용량 하나 손해), C 에서는 free-running index (C 문제 06)
  • 테스트 포인트 — 정확히 가득 찼을 때, 한 바퀴 돈 뒤(wrap)의 순서, 빈 상태에서 pop
  • 빈 파일: python3 lecture/warmup/new.py py 7 · 정답 파일: 07_ring_buffer.py · 정답 실행: python3 lecture/warmup/py/07_ring_buffer.py

08 · 괄호 검사 — 스택 (LeetCode 20)#

'()[]{}' 로만 된 문자열이 올바르게 닫혔는지 True/False.

  • 여는 괄호는 push, 닫는 괄호는 pop 해서 짝 확인. 끝나고 스택이 비어 있어야 한다
  • dict 로 '닫는 → 여는' 짝을 표로 두면 if 문이 없어진다
  • 빈 파일: python3 lecture/warmup/new.py py 8 · 정답 파일: 08_valid_parentheses.py · 정답 실행: python3 lecture/warmup/py/08_valid_parentheses.py

01 · 문자열 제자리 뒤집기#

void reverse_str(char *s) — 추가 메모리 없이 뒤집는다. NULL · 빈 문자열도 안전하게. 테스트 함수 + main 까지 직접.

02 · 연결 리스트 — push_front · length · reverse#

node_t {int val; next}. push_front(head, node) → 새 head, list_len(head), reverse(head) → 새 head. malloc 없이 노드를 받아서.

  • reverse = prev · curr · next 세 포인터: next 기억 → 화살표 뒤집기 → 한 칸 전진
  • 테스트 포인트 — 빈 리스트(NULL), 노드 1개, 뒤집은 뒤 마지막 노드의 next 가 NULL 인지

03 · strcpy 직접 구현 + 크기 제한 버전#

my_strcpy(dst, src) → dst. safe_copy(dst, cap, src) → 항상 '\0' 로 끝내고, 잘렸으면 false.

  • strcpy 는 dst 크기를 모른다 → 버퍼 오버플로의 단골. 실무는 크기를 받는 버전
  • 테스트 포인트 — 딱 맞는 길이(cap - 1 글자), 한 글자 넘침, cap == 0
  • 빈 파일: python3 lecture/warmup/new.py c 3 · 정답 파일: 03_strcpy.c · 정답 실행: make -C lecture/warmup c (playground: make c F=c/<파일>)

04 · atoi 직접 구현#

int my_atoi(const char *s) — 앞 공백 무시, + / - 부호, 숫자가 아닌 글자에서 멈춤, int 범위를 넘으면 INT_MAX / INT_MIN.

  • 순서: 공백 건너뛰기 → 부호 → 숫자 누적 (v * 10 + (c - '0'))

05 · Ring buffer — head · tail · count (아무 크기나 가능)#

rb_t {buf[RB_CAP], head, tail, count}. rb_push(rb, v) → bool (가득 차면 false), rb_pop(rb, &v) → bool (비었으면 false).

  • count 가 full / empty 를 구분하므로 용량을 전부 쓴다. 인덱스는 (i + 1) % RB_CAP 로 감는다 → 크기가 2의 거듭제곱일 필요 없음
  • 단점: push 와 pop 이 둘 다 count 를 고친다 → ISR 생산자 + main 소비자면 count 가 공유 변수가 되어 보호가 필요 (06 은 이 문제가 없다)
  • 테스트 포인트 — 정확히 가득, 한 칸 넘침, 한 바퀴 돈 뒤의 순서
  • 빈 파일: python3 lecture/warmup/new.py c 5 · 정답 파일: 05_ring_buffer_count.c · 정답 실행: make -C lecture/warmup c (playground: make c F=c/<파일>)

06 · Ring buffer — free-running head/tail (2의 거듭제곱, count 없음)#

rb_t {buf[8], head, tail}. head/tail 은 마스크 없이 계속 증가, 접근할 때만 & (SIZE - 1). 개수 = head - tail.

  • 05 와 비교: count 가 없어서 push 는 head 만, pop 은 tail 만 쓴다 → ISR 생산자 / main 소비자(SPSC)에서 lock 없이 쓸 수 있는 구조
  • unsigned 뺄셈이라 head 가 2^32 를 넘어 0 으로 돌아도 head - tail 이 맞다 → 테스트는 UINT32_MAX 근처에서 시작
  • % 대신 & 마스크 → 나눗셈 없음. 대신 크기가 반드시 2의 거듭제곱
  • 빈 파일: python3 lecture/warmup/new.py c 6 · 정답 파일: 06_ring_buffer_free_running.c · 정답 실행: make -C lecture/warmup c (playground: make c F=c/<파일>)

말하면서 풀기 — 공통 대사#

  • 시작: "Let me restate it and check the edge cases — empty input, one element, no answer."
  • 복잡도 먼저: "Hash map: O(n) time, O(n) space." / "Two pointers: O(n) time, O(1) space."
  • 테스트: "I'll add one normal case and the riskiest edge — here, the element pairing with itself."
  • 끝: "Let me run it." → PASS → "If I had more time I'd add a randomized test against a brute-force version."
