2. 공통 전략 — 어느 시나리오든#

시점할 것대사
0–2분문제를 다시 말하고 질문 3개: 입력 형태 · 경계 · 정책"Before I code — what should happen when it's full? Single-threaded to start? Python is fine?"
2–3분계획을 한 줄로"Data structure first, then the operations, then tests."
구현작은 단위로, 자주 실행"Let me run what I have so far."
직후묻기 전에 테스트"Before we move on, I'd like to add a few tests — normal case, exactly full, wraparound."
확장다시 질문 → 기존 테스트가 깨지지 않는지 실행"I'll keep the old tests green while I add this."
막힘생각을 말로, 예시로 손 시뮬레이션"Let me trace capacity 3 by hand."
끝 5분안 한 것 · 다음에 할 것"Next I'd add a randomized test against deque, and run this on the rig in CI."

  • 언어: 기본 Python. C를 원하면 바로 C (L05 C 05/06). 판단 기준은 P00 "10-06 저녁 판단"

시나리오 B · 로그 · 텔레메트리 처리 + 테스트 (~20%)#

면접관이 할 말 (예상): "Here's a telemetry log from a drone — one frame per line. Parse it, tell me if any frames were dropped, the longest gap between frames, and the lowest battery voltage. Malformed lines shouldn't crash it. Then test it."

  • 왜 나올 수 있나: Full Stack 엔지니어가 매일 하는 일(데이터 파싱 · 요약 · 에러 처리)이면서, 드론 · 테스트 맥락이 있다 [추정]
  • 질문 3개: "Is seq strictly increasing, or can it wrap or arrive out of order?" · "Should malformed lines be skipped and counted?" · "Is the whole log in memory, or streaming?"

모의 B 테스트#

설계 결정이유 (말할 것)
파싱(parse_line)과 집계(check)를 분리"Each piece is testable on its own — parser edge cases don't need a whole log."
형식 오류는 세고 넘어감"One bad line from a noisy link shouldn't hide the rest of the flight."
결과를 dataclass로"A structured report is easy to assert on and to send to a dashboard."
리스트 대신 이터러블을 받음"It works on a file object or a serial stream, line by line, constant memory."
꼬리 질문답의 핵심
"seq wraps at 65535."차이를 (cur - prev) % 65536으로, 1이면 정상 · 0이면 중복 · 큰 값이면 누락
"Frames can arrive out of order."작은 재정렬 창(ring buffer!)에 모았다가 순서대로 방출, 창보다 늦으면 '늦게 도착' 카운트
"It's a 2 GB log."지금 구조 그대로 스트리밍 (for line in open(...)), missing은 범위 (start, end)로 저장해 메모리 절약
"Test the malformed handling better."parametrize로 빈 줄 · 키 누락 · 숫자 아님 · = 없음 (위 테스트)
"How would CI use this?"비행 로그 업로드 → 이 검사 → 기준(누락률, 최대 간격) 넘으면 실패 · 대시보드 (N04 문제 C)

4. 면접관이 Full Stack이라서 생기는 것 — 대응 [추정]#

가능성대응
임베디드 용어(ISR, DMA)가 안 통할 수 있다한 문장 번역: "an interrupt handler is like a callback that can fire between any two instructions"
코드 스타일 · 이름 · 구조를 꼼꼼히 본다함수 작게, 이름이 스펙 문장처럼, 매직 넘버 상수화, docstring 한 줄
클래스 설계 질문 ("how would you extend this?")정책을 생성자 인자로, 테스트 가능한 경계(주입)
웹식 테스트 감각 (fixture, mock, CI)그대로 통한다 — pytest는 공통 언어
"왜 FW Test로 왔나" 같은 짧은 대화30초: "I build test infrastructure around real hardware, and I write the firmware too, so I can read the code under test."
