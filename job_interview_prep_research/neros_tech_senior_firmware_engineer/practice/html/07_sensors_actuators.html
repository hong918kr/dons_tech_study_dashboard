1. 전체 그림 — 한 프레임(1~8 kHz)에 일어나는 일#

 [센서]                      [전처리]                  [제어]        [출력]
 gyro/accel --SPI burst--> decode(BE int16)  --> bias 제거 --> PID --> 믹서 --> DShot --> ESC
 (Q1)                       (Q2)                 (Q3)                 (Q6)     (Q6)
                                                  |
                                              필터 (Q4)
                                        mavg / median / LPF / notch

 [RC 링크]
 ELRS/CRSF --22B packed--> 16ch x 11bit 언팩 --> throttle/stick (Q5)
                                  |
                          링크 나이 > timeout ?  --> FAILSAFE (Q5)

핵심 한 줄: 이 전체 경로에 float 이 한 개도 없어도 된다. 전부 정수/고정소수점이면 실행 시간이 결정적(deterministic)이고, FPU 없는 MCU 로도 포팅된다.

2. 개념 정리#

2.1 센서 역할 분담 ⭐#

센서측정대역 / 레이트강점약점
Gyro각속도 (dps)1~32 kHz빠르고 진동·가속에 강함적분하면 드리프트 (bias)
Accel비력(specific force)1~4 kHz장기적으로 중력 방향 = 절대 기준프롭 진동·기동 가속에 오염

센서 융합의 본질: 서로의 약점을 시간 스케일로 상쇄한다. 자이로는 단기에 정확하고 장기에 틀리고, accel/mag/GPS 는 장기에 정확하고 단기에 시끄럽다. → 고역통과(자이로) + 저역통과(accel) = 상보필터.

2.2 I2C vs SPI — 무엇을 보고 고르나 ⭐#

I2CSPI
핀2 (SCL/SDA) — 공유 버스4 + CS 1개/디바이스
속도100k / 400k / 1M Hz흔히 1~50 MHz (IMU 는 보통 8~20)
주소7비트 주소 → 같은 칩 2개면 충돌CS 라인으로 구분 → 충돌 없음
신뢰성open-drain + 풀업 → 노이즈에 약함, 버스 락업(SDA 물림) 있음push-pull, 락업 없음
ACK/에러NACK 로 에러 감지 가능프로토콜 차원의 에러 감지 없음(그래서 WHO_AM_I 로 확인)
적합baro, mag, EEPROM (느리고 핀 아까울 때)gyro/accel (고레이트), flash, 고속 ADC

드론 실무 기준선: 8 kHz 자이로는 SPI 말고는 답이 없다. 6바이트 × 8000/s = 48 kB/s 인데, I2C 400 kHz 의 실효 처리량은 오버헤드 포함 ~35 kB/s 정도로 이미 한계다. 게다가 I2C 락업 한 번이면 자이로가 통째로 사라진다. baro/mag 는 100 Hz 면 충분하므로 I2C 로 밀어도 된다.

  • SPI 읽기 비트: 첫 바이트 = [R/W(1) | reg(7)]. 읽기는 reg | 0x80. → 레지스터 주소는 7비트뿐.
  • I2C 레지스터 포인터: START [addr|W] reg 로 디바이스 내부 포인터를 세팅하고, REPEATED START [addr|R] 로 읽는다. 포인터는 읽을 때마다 자동 증가 → burst 가 공짜. (STOP 을 끼우면 다른 마스터가 포인터를 바꿔버릴 수 있다 → repeated start 를 써야 원자적)

2.3 burst read 가 왜 중요한가 ⭐⭐#

  1. 원자성 (torn sample): X 를 읽고 Y 를 읽는 사이에 디바이스가 새 샘플을 쓰면, X 는 옛 샘플 / Y 는 새 샘플이 된다. 자세 추정기가 존재하지 않는 회전을 본다. 좋은 IMU 는 burst 중에 출력 레지스터를 shadow/latch 해준다 — burst 로 읽어야만 그 보장을 받는다.
  2. 버스 시간: 트랜잭션마다 주소·오버헤드가 붙는다. 6번 나눠 읽으면 오버헤드도 6배.
  3. DMA: burst 는 DMA 한 번으로 끝난다 → CPU 사이클 0. 단일 읽기 6번은 ISR 6번.
  4. 지터: 트랜잭션이 하나면 샘플 시각이 하나로 정의된다. 6개면 샘플마다 시각이 다르다.

2.4 샘플레이트와 aliasing ⭐#

  • Nyquist: 샘플레이트 fs 로 샘플링하면 fs/2 위의 성분은 사라지는 게 아니라 낮은 주파수로 접혀 들어온다(aliasing). 한번 접히면 어떤 디지털 필터로도 못 뺀다.
  • 프롭 진동은 300~800 Hz. 1 kHz 로 샘플링하면 600 Hz 진동이 400 Hz 로 둔갑해 나타난다.
  • 그래서 IMU 칩 안에 아날로그 anti-alias 필터(DLPF) 가 있고, 그걸 켠 뒤 다운샘플해야 한다. CONFIG 레지스터의 DLPF_CFG 가 그것. (Q1 의 RMW 예제가 바로 이 필드다)
  • 정리: "디지털 필터는 aliasing 을 못 고친다. 고치는 건 샘플링 전 아날로그 필터뿐."
  • 오버샘플링(8 kHz 로 읽고 소프트에서 평균)도 정답 중 하나 — 대역을 먼저 확보하고 줄인다.

2.5 진동, 노치 필터, RPM 필터 ⭐⭐#

  • 프롭 1개가 초당 300~600회전(18k~36k RPM) → 300~600 Hz 대역의 강한 정현파. 날개 개수를 곱한 blade passing frequency 성분도 같이 뜬다.
  • 이게 D 항에 들어가면: D 가 진동을 증폭 → 모터가 같은 주파수로 떨림 → 발열 / ESC 디싱크 / 번아웃.
  • LPF 로 지우려면: 컷오프를 100 Hz 이하로 내려야 하는데, 그러면 위상 지연이 커져 PID 의 위상 여유가 사라지고 저주파 wobble 이 생긴다. 노이즈를 지우는 대가가 지연이다.
  • 노치 필터(notch): 문제의 한 주파수만 파낸다. 같은 노이즈 제거량에 대해 지연이 훨씬 싸다.
  • RPM 필터: ESC 에서 양방향 DShot 으로 실제 RPM 을 받아, 모터 4개 × 하모닉 3개 = 노치 12개를 RPM 을 따라 실시간으로 이동시킨다. 현대 FPV 성능의 절반이 여기서 나온다.
  • 하드웨어가 먼저: 소프트 필터는 마지막 수단이다. 프롭 밸런싱, 소프트 마운트, 자이로 위치(무게중심 근처), 프레임 강성이 훨씬 효과적이다. 면접에서 이 말이 나오면 가산점.

2.6 상보필터 vs EKF — 한 줄 비교#

상보필터 (complementary)EKF (확장 칼만)
아이디어자이로는 고역통과, accel/mag 는 저역통과. 고정 게인 하나.상태 공분산을 들고 다니며 게인을 매 스텝 최적으로 계산
비용곱셈 몇 번, 수십 사이클행렬 연산, 수천~수만 사이클 + 튜닝 지옥
상태자세(attitude)만자세 + 속도 + 위치 + 센서 bias 까지 추정
쓰는 곳레이트 루프 / 소형 FC (Betaflight 는 사실상 이것)위치 제어, GPS 융합 (ArduPilot/PX4 EKF2/3)

한 줄 답: "상보필터는 게인이 고정, EKF 는 게인이 불확실성에 따라 적응한다. 자세만 필요하고 CPU 가 빡빡하면 상보, GPS·속도·bias 까지 엮으면 EKF."

2.7 CRSF / ELRS 링크와 failsafe 정책 ⭐⭐#

  • CRSF(TBS Crossfire) 는 ExpressLRS 도 쓰는 시리얼 프로토콜. 프레임: [sync 0xC8][len][type][payload...][crc8 poly 0xD5]
  • RC_CHANNELS_PACKED (type 0x16) = 16채널 × 11비트 = 176비트 = 정확히 22바이트. 비트 순서는 LSB-first 비트스트림 — 바이트 0 의 LSB 가 채널 0 의 비트 0. 채널이 바이트 경계를 아무렇게나 걸친다(11 과 8 은 서로소).
  • 값 범위 172 ~ 1811, 중앙 992 → 1000~2000 µs 에 대응. (왜 172? CRSF 는 실제로 ±100% 밖의 여유 구간까지 11비트에 담는다)
  • failsafe 판정은 "값"이 아니라 "시간"으로 한다. 재밍/거리이탈은 조용한 침묵으로 온다 — 쓰레기 값이 아니라 프레임이 안 온다.
  age = now_ms - last_valid_frame_ms;   // 부호없는 뺄셈 = 랩 안전
  failsafe = (age > timeout_ms);
  • 정책 계층: 보통 2단계.
    1. 짧은 끊김(~수백 ms): 마지막 스틱 값을 홀드 — 순간 드롭아웃으로 떨어지지 않게.
    2. 지속 끊김: 정해진 동작 — 호버/자동 착륙/모터 정지/RTH. 기체 종류와 운용 규정이 정한다.
  • CRC 를 통과한 프레임만 타임스탬프를 갱신해야 한다. 아니면 깨진 프레임이 failsafe 를 막는다.

2.8 DShot vs PWM vs OneShot ⭐#

표준 PWMOneShot125 / MultishotDShot
신호1000~2000 µs 펄스, 50~490 Hz125~250 µs (8배 압축)디지털 비트스트림 (150/300/600/1200 kbps)
분해능타이머 틱에 의존 (사실상 ~1000단계)같음2048단계 고정
캘리브레이션필요 (ESC 마다 min/max 학습)필요불필요 — 값이 숫자로 전달됨
에러 검출없음 (노이즈 = 조용한 오출력)없음4비트 CRC → 깨진 프레임은 ESC 가 버린다
드리프트온도/전압에 따라 펄스폭 해석이 흔들림흔들림없음
부가 기능없음없음커맨드(비프/회전방향/3D모드), 양방향 RPM

DShot 프레임 (16비트, MSB first 전송):

[ throttle 11bit ][ telemetry 1bit ][ CRC 4bit ]
value = (throttle << 1) | telem
crc   = (value ^ (value >> 4) ^ (value >> 8)) & 0x0F     // 세 니블의 XOR
frame = (value << 4) | crc

throttle 값 의미: 0 = 정지/disarm, 1~47 = 특수 커맨드(비프, 회전방향, 설정저장, 3D), 48~2047 = 실제 출력 2000단계.

2.9 양방향 DShot (bidirectional / DShot telemetry) ⭐#

  • 같은 한 가닥 신호선을 반이중(half-duplex) 으로 쓴다. FC 가 프레임을 보내고 나면 라인을 입력으로 뒤집고, ESC 가 eRPM 을 GCR 인코딩으로 돌려준다.
  • 값은 eRPM(전기적 RPM). 기계적 RPM = eRPM / (극쌍수). 보통 모터 극수 14 → 극쌍 7.
  • 왜 중요한가: RPM 필터(2.5절)의 입력이 여기서 나온다. 또 모터 고장/디싱크를 RPM 이 명령과 어긋나는 것으로 즉시 감지할 수 있다.
  • 대가: CRC 가 반대 방향으로는 역전된 형태이고, 타이밍이 빡빡해서 DMA + 정확한 타이머 캡처가 필요하다. 프로토콜 오버헤드 때문에 루프레이트 상한도 낮아진다.

2.10 quad-X 믹서와 saturation / airmode ⭐⭐⭐#

배치 (위에서 본 모습, 이 파일의 인덱스는 시계방향):

   FL(3)   FR(0)          대각 쌍 (FR,RL) 과 (FL,RR) 이 반대 방향으로 회전
      \   /               -> yaw 는 "대각 쌍의 차이"로만 만들어진다
       \ /                   (반작용 토크 = 회전 방향의 반대)
       / \
      /   \
   RL(2)   RR(1)
mix[FR] = -roll - pitch + yaw;
mix[RR] = -roll + pitch - yaw;
mix[RL] = +roll + pitch + yaw;
mix[FL] = +roll - pitch - yaw;
out[i]  = throttle + mix[i];

포화(saturation) 가 이 문제의 전부다. 스로틀이 90% 인데 roll 명령이 들어오면 throttle + mix 가 범위를 넘는다. 여기서 순진하게 모터별로 clamp 하면 안 된다:

throttle=2000, roll=200, 범위 0..2047
  순진한 clamp : FL = min(2200, 2047) = 2047, FR = 1800  ->  차이 247  (명령은 400!)
                 -> 요청한 롤의 62% 만 나온다. 풀스로틀에서 기체가 제어를 잃는 전형적 원인.
  올바른 처리  : 스로틀을 양보시킨다. t = 2047 - 200 = 1847
                 FL = 2047, FR = 1647  ->  차이 400 그대로  (자세 권한 100% 보존)

정석 알고리즘 (이 문제의 mixer_quad_x, Betaflight 의 mix-range/airmode 와 같은 아이디어):

  1. throttle 빼고 자세 성분만 mix[4] 로 계산.
  2. span = max(mix) - min(mix) 가 출력 범위보다 크면 전체를 같은 비율로 스케일다운 (개별 clamp 와 달리 모터 간 비율이 보존된다).
  3. 이제 span ≤ range 이므로, throttle 을 통째로 밀어 넣어 전부 범위 안에 들어가게 한다.

우선순위는 자세 > 스로틀이다. 고도는 좀 틀려도 되지만 자세를 잃으면 기체가 뒤집힌다.

  • airmode: 스로틀 0 에서도 위 처리를 유지해 모터를 최소값 위로 띄워두는 모드. 프리스타일/곡예에서 스로틀을 끊어도 자세 제어가 살아있다. 대가는 "착지해도 모터가 안 멈춤" → arm/disarm 로직과 반드시 함께 설계해야 한다.
  • yaw 우선순위 낮추기: 포화가 심하면 yaw 권한을 먼저 깎는 구현이 많다. roll/pitch 를 잃으면 추락하지만, yaw 는 잠깐 어긋나도 살아남는다.

3. 각 Q 핵심 한 줄#

Q함수한 줄
Q1imu_write_reg / imu_read_reg / imu_modify_reg / imu_burst_readRMW 는 마스크 밖 비트를 절대 안 건드린다. 자이로 6바이트는 1 트랜잭션 — 원자적 샘플 + 버스 시간 + DMA
Q2imu_decode_xyz / gyro_to_mdps센서는 big-endian, MCU 는 little-endian → 바이트 단위 수동 조립. 스케일은 곱하기 전에 넓히고 half-away-from-zero 반올림
Q3gyro_bias_* / apply_bias_sat정지 N 샘플 평균 = zero-rate offset. 빼기는 int32 로 넓혀 계산 → clamp (int16 랩 = 부호 뒤집힌 자이로 = 추락)
Q4moving_avg_update / median3 / lpf1_update2의 거듭제곱 창 → 나눗셈이 시프트. median 은 단발 스파이크 제거. IIR 은 Q15 y += (x-y)*α>>15. 모든 필터의 대가는 지연
Q5rc_unpack_channels / rc_to_us / rc_link_ok11비트 × 16 = 22바이트 LSB-first 비트 누산기. failsafe 는 값이 아니라 시간으로, now - last 부호없는 뺄셈
Q6dshot_frame / pwm_us_to_ticks / mixer_quad_xDShot = 11+1+4비트 XOR CRC. 믹서는 clamp 가 아니라 스로틀을 양보시켜 자세 권한을 지킨다

4. 흔한 함정 (체크리스트)#

5. 면접 꼬리질문 (답 요지 포함)#

Q. "자이로를 I2C 로 붙이면 왜 안 되나? 숫자로 말해봐." → 8 kHz 루프면 125 µs 예산이다. I2C 400 kHz 에서 6바이트 burst 는 주소·ACK 포함 대략 ~90 µs — 예산의 70%를 버스가 먹는다. 단일 읽기 6번이면 300 µs 로 예산 초과. SPI 10 MHz 면 같은 6바이트가 ~7 µs, DMA 로 넘기면 CPU 는 0 사이클. 게다가 I2C 는 open-drain 이라 노이즈에 약하고 SDA 락업이 있다 — 자이로가 통째로 사라지면 추락이다. 그래서 gyro/accel 은 SPI, baro/mag(100 Hz 면 충분)는 I2C 로 분리하는 게 표준 배치다.

Q. "프롭 진동 때문에 자이로가 시끄럽다. 어떻게 접근하겠나?" → 순서가 중요하다. (1) 먼저 측정 — 블랙박스로 자이로 스펙트럼을 떠서 몇 Hz 인지 본다. (2) 하드웨어 — 프롭 밸런싱, 소프트 마운트, 자이로를 무게중심 근처로. 가장 효과가 크다. (3) anti-alias — IMU 의 DLPF 를 켜서 fs/2 위 성분을 샘플링 전에 잘라낸다. (4) 노치 — 문제 주파수만 파낸다. LPF 로 같은 양을 지우는 것보다 지연이 훨씬 싸다. (5) RPM 필터 — 양방향 DShot 으로 실제 RPM 을 받아 노치를 RPM 따라 움직인다. 핵심 문장: "노이즈를 얼마나 지울지가 아니라, 몇 ms 의 지연을 지불할지를 고르는 문제다."

Q. "링크가 끊겼다. 정확히 무슨 일이 일어나야 하나?" → 판정은 시간 기반이다. 재밍은 이상한 값이 아니라 침묵으로 온다. age = now - last_valid_frame 을 부호없는 뺄셈으로 재고, CRC 통과 프레임만 시각을 갱신한다. 동작은 2단계: 짧은 드롭아웃(~수백 ms)은 마지막 값 홀드(순간 끊김으로 떨어지지 않게), 지속되면 정책 동작(호버 / 자동 착륙 / 모터 정지 / RTH). 부팅 기본값은 failsafe 여야 하고, failsafe 중에는 arm 이 불가능해야 한다. 그리고 failsafe 진입/이탈은 반드시 로그로 남긴다 — 추락 후에 "링크였나 배터리였나"를 가르는 유일한 증거다.

Q. "DShot 이 PWM 보다 나은 이유를 3가지만." → (1) 에러 검출: 4비트 CRC 가 있어 깨진 프레임은 ESC 가 버린다. PWM 은 노이즈가 그대로 조용한 오출력이 된다 — 모터가 멋대로 튄다. (2) 캘리브레이션 불필요: 값이 숫자로 전달되므로 ESC 마다 min/max 를 학습시킬 필요가 없고, 온도/전압 드리프트도 없다. (3) 양방향 텔레메트리: 실제 RPM 이 돌아와 RPM 노치 필터와 모터 고장 감지가 가능해진다. 덤으로 2048단계 고정 분해능과 특수 커맨드(회전방향/비프)도 같은 선으로 나간다.

Q. "풀스로틀에서 롤 명령이 들어왔다. 모터 하나는 이미 최대다. 어떻게 하나?" → 자세가 스로틀보다 우선이다. 모터별 clamp 를 하면 포화한 쪽의 자세 명령이 잘려 요청 대비 60% 만 나오고, 기체가 그 방향으로 제어를 잃는다(풀스로틀 뒤집힘의 전형). 올바른 처리는 (1) 자세 성분만 따로 계산해 span = max-min 을 구하고, span 이 출력 범위보다 크면 전체를 같은 비율로 스케일다운해 모터 간 비율을 보존한 뒤, (2) throttle 을 양보시켜(위/아래로 밀어) 전부 범위 안에 들어가게 한다. 결과적으로 고도는 조금 흔들려도 모터 간 차이 = 자세 권한은 100% 유지된다. Betaflight 의 airmode / mix-range 가 정확히 이 처리이고, 심한 포화에서는 yaw 권한을 먼저 깎는 게 관례다.
