면접에서 쓸 문장: "센서→액추에이터 end-to-end 지연을 예산으로 관리한다. 8 kHz 루프에서 125 µs 안에 자이로 읽기(SPI 버스트) + 필터 + PID + DShot 송출이 끝나야 하고, 로깅이나 텔레메트리가 그 예산을 침범하면 비행 품질이 먼저 무너진다." ← JD의 *"drive resource trade-offs when subsystems compete for the same budget"*에 정확히 대응.

3. 서브시스템 해부#

3.1 Flight Controller (MCU)#

역할: 위 파이프라인 전부를 실시간으로 돌리는 심장. 핵심 부품/스펙: STM32F4/F7/H7 또는 최신 Cortex-M33급. 클럭 100~500 MHz, SRAM 수백 KB, 플래시 1~2 MB, DMA 채널, 하드웨어 타이머, FPU 유무. 펌웨어가 하는 일: 부트 → 클럭/전원 설정 → 페리페럴 초기화 → 센서 bring-up → 스케줄러 → 루프. 파라미터 저장, OSD, failsafe.

면접 질문: "이 MCU에 자이로 8 kHz, 로깅, 텔레메트리, GPS를 다 올려야 한다. 어디서 예산이 깨지고 무엇을 먼저 자르나?"

3.2 IMU — 자이로/가속도계#

역할: 자세 제어의 1차 입력. 드론 펌웨어에서 가장 타이밍이 민감한 센서. 핵심 부품: ICM-42688-P, BMI270, MPU6000 계열. SPI 10~24 MHz 연결, FIFO 내장, DRDY 인터럽트 핀. 펌웨어가 하는 일: WHO_AM_I 확인 → ODR/FS 설정 → DRDY 인터럽트에서 버스트 리드 → 스케일 변환 → 필터 → PID.

면접 질문: "자이로 노이즈가 갑자기 늘어 모터가 뜨겁다. 어떻게 좁혀 들어가나?" (→ 진동/필터/모터 이슈의 고전적 디버깅 트리)

3.3 기압계 · 자력계 · GNSS · 광류/ToF#

역할: 고도·방위·위치 보조. 재밍 환경에서는 GPS를 못 믿는다는 게 Neros 맥락의 핵심.

면접 질문: "GPS가 죽었다. Position Hold를 어떻게 유지하나?" ← Archer AI 기능과 직결

3.4 ESC와 모터 (추진계)#

역할: 펌웨어 명령을 추력으로 바꾸는 구간. FC 펌웨어 바깥에 또 하나의 펌웨어(ESC) 가 있다. 핵심 부품: BLDC 아웃러너(KV 값), 4-in-1 ESC (BLHeli_32 / AM32), MOSFET, 션트 저항.

면접 질문: "모터 하나가 비행 중 디싱크 났다. FC 펌웨어는 이걸 어떻게 감지하고 무엇을 해야 하나?"

3.5 전원계#

역할: 모든 실패의 절반이 여기서 온다. Don의 "safety margin sign-off" 경험이 가장 잘 붙는 곳.

면접 질문: "필드에서만 가끔 리셋된다. 벤치에서는 재현이 안 된다." ← 컨텍스트 파일 4.3의 디버깅 시나리오와 동일

3.6 RC 링크 / C2 라디오#

역할: 조종 명령과 텔레메트리의 통로. 방산에서는 적이 적극적으로 방해하는 채널. 핵심 부품: ELRS 계열 송수신기(SX1280 LoRa), 다이버시티 안테나, 또는 Neros 자체 설계 모듈.

면접 질문: "링크 품질이 떨어질 때 텔레메트리·영상·제어 중 무엇을 먼저 버리나?" ← 04_ipc_budget Q6과 같은 문제

3.7 영상 계통 (카메라 · VTX · 고글)#

역할: FPV의 본질. 조종자가 "보는" 지연이 곧 조작 성능.

Neros에 CODEC Video Compression Engineer 공고가 따로 있다 — 영상 링크를 직접 만든다는 뜻.

3.8 컴패니언 컴퓨트 / Autonomy#

역할: Archer AI의 "종말 유도"와 GPS-denied 기능이 도는 곳. MCU가 아니라 embedded Linux + 가속기.

Neros의 Autonomy Platform & Runtime Lead 공고가 이 영역을 그대로 기술한다: 모듈 인터페이스 계약, 실시간 스케줄링,
지연 회계, 온보드 로깅·시간 동기, 기체 배포 경로. 지원 포지션(Platform)과 바로 옆에서 맞물리는 팀이다.
