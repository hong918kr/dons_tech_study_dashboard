# 00. 드론 펌웨어 아키텍처 — 컨셉 리서치 맵

> FPV 드론 한 대가 **어떤 부품으로 구성되고, 펌웨어가 각 부품에서 무엇을 하는지**를 서브시스템별로 해부한 지도.
> 코드 문제(`01`~`07`)가 "손"이라면 이 문서는 "머리"다. 온사이트의 시스템 설계·디버깅 라운드는 여기서 나온다.
>
> 각 섹션은 **① 역할 → ② 핵심 부품/스펙 → ③ 펌웨어가 하는 일 → ④ 리서치 항목 `- [ ]` → ⑤ 예상 면접 질문** 구조다.
> `- [ ]` 항목은 "검색해서 30분 안에 한 문단으로 요약할 수 있는 단위"로 쪼갰다. 전부 할 필요 없다 — §9의 Top 15부터.

---

## 0. 이 문서 쓰는 법

1. **먼저 §1~§2**를 읽고 전체 블록도와 타이밍 예산을 외운다. 이 둘만 알아도 "드론 잘 모르는 사람"에서 벗어난다.
2. §3의 서브시스템 중 **Don의 경험과 붙는 것부터** 판다 (버스·전원·센서 인터페이스 = Apple/SSD 경험과 직결).
3. 모르는 게 나오면 §10의 1차 소스(실제 코드)를 본다. 블로그보다 **Betaflight/PX4/ELRS 소스 트리 구조**를 훑는 게 빠르다.
4. 면접에서는 **"모른다 + 구조적으로 추론"** 이 "아는 척"보다 훨씬 좋다. 이 문서의 목적은 추론할 골격을 만드는 것.

**Neros 특이점** (공고·공개자료 기준): 라디오(C2·영상 링크)를 **자체 설계**하고, flight computer·센서도 자체 통합한다.
즉 위 블록 중 상당수가 "사서 붙이는 모듈"이 아니라 **사내 펌웨어 팀의 코드**다. Platform 팀은 그 위에 공통 런타임을 깐다.

## 2. 제어 루프 파이프라인과 타이밍 예산

```
gyro 샘플(8kHz) ─▶ 노치/저역 필터 ─▶ 자이로 rate
                                        │
RC 입력(250~1000Hz) ─▶ 스무딩 ─▶ setpoint
                                        ▼
                             ┌──────────────────┐
     자세각(accel/mag 융합) ─▶│ PID 캐스케이드    │─▶ roll/pitch/yaw/throttle 요구량
     (angle mode일 때만)      │ (outer 각도 →     │
                             │  inner rate)     │
                             └──────────────────┘
                                        ▼
                                  믹서(quad-X) ─▶ 모터 4개 요구값 ─▶ 포화/airmode 처리
                                        ▼
                                  DShot 프레임(600/1200) ─▶ ESC ─▶ 전류 정류 ─▶ 회전
                                        ▲
                       양방향 DShot RPM 텔레메트리 ──┘ (→ RPM 필터로 되먹임)
```

| 루프 | 전형적 주기 | 무엇이 여기서 결정되나 |
|---|---|---|
| 자이로 읽기 + 필터 + PID (inner) | **1~8 kHz** (125 µs ~ 1 ms) | 비행 감각(feel), 지터, 프로펠러 진동 대응 |
| 자세/각도 루프 (outer) | 250~1000 Hz | angle/horizon 모드 안정성 |
| RC 링크 수신 | 150~1000 Hz (ELRS 패킷 레이트) | 조종 지연, 링크 끊김 감지 |
| 텔레메트리 다운링크 | 5~50 Hz | 대역폭 경쟁의 주범 |
| GPS | 5~25 Hz | 위치 유지, GPS-denied 시 제외 |
| 기압계 | 25~100 Hz | 고도 유지 |
| 로깅(blackbox) | 500 Hz ~ 2 kHz | 사후 디버깅 vs 플래시/대역폭 |
| 컴패니언 비전/autonomy | 30~120 Hz | 종말 유도, 표적 추적 |

**면접에서 쓸 문장**: "센서→액추에이터 end-to-end 지연을 예산으로 관리한다. 8 kHz 루프에서 125 µs 안에
자이로 읽기(SPI 버스트) + 필터 + PID + DShot 송출이 끝나야 하고, 로깅이나 텔레메트리가 그 예산을 침범하면
비행 품질이 먼저 무너진다." ← JD의 *"drive resource trade-offs when subsystems compete for the same budget"*에 정확히 대응.

- [ ] 8 kHz 루프에서 125 µs 예산을 항목별로 쪼개보기 (SPI 전송 시간 계산 포함: 14바이트 @ 10 MHz)
- [ ] 지연(latency)과 지터(jitter)의 차이, 제어 안정성에 어느 쪽이 더 치명적인지
- [ ] Betaflight의 `scheduler.c`가 태스크 우선순위와 예산 초과를 다루는 방식

## 3. 서브시스템 해부

### 3.1 Flight Controller (MCU)
**역할**: 위 파이프라인 전부를 실시간으로 돌리는 심장.
**핵심 부품/스펙**: STM32F4/F7/H7 또는 최신 Cortex-M33급. 클럭 100~500 MHz, SRAM 수백 KB, 플래시 1~2 MB, DMA 채널, 하드웨어 타이머, FPU 유무.
**펌웨어가 하는 일**: 부트 → 클럭/전원 설정 → 페리페럴 초기화 → 센서 bring-up → 스케줄러 → 루프. 파라미터 저장, OSD, failsafe.

- [ ] Cortex-M4 vs M7 차이 (캐시·파이프라인·더블 이슈)와 캐시가 DMA와 만나면 생기는 문제 (cache coherency, `SCB_CleanDCache`)
- [ ] FPU가 있어도 인터럽트에서 float 쓰면 생기는 비용 (lazy stacking)
- [ ] DMA + 더블 버퍼로 SPI 센서 읽기를 CPU 없이 돌리는 구조
- [ ] 링커 스크립트: `.bss`/`.data`/`.noinit`, 스택 위치, 플래시/RAM 예산을 `.map`으로 추적하는 법
- [ ] HardFault 핸들러에서 스택 프레임 디코드해 PC/LR 복구하기 (crash dump)
- [ ] 워치독(IWDG) 주기와 "살아있는데 멈춘" 태스크 감지 설계

**면접 질문**: "이 MCU에 자이로 8 kHz, 로깅, 텔레메트리, GPS를 다 올려야 한다. 어디서 예산이 깨지고 무엇을 먼저 자르나?"

### 3.2 IMU — 자이로/가속도계
**역할**: 자세 제어의 1차 입력. 드론 펌웨어에서 가장 타이밍이 민감한 센서.
**핵심 부품**: ICM-42688-P, BMI270, MPU6000 계열. SPI 10~24 MHz 연결, FIFO 내장, DRDY 인터럽트 핀.
**펌웨어가 하는 일**: WHO_AM_I 확인 → ODR/FS 설정 → DRDY 인터럽트에서 버스트 리드 → 스케일 변환 → 필터 → PID.

- [ ] 자이로와 가속도계의 역할 분담 (단기 정확 vs 장기 기준), 드리프트와 노이즈 특성
- [ ] ODR·대역폭·aliasing: 8 kHz 루프에 32 kHz 자이로를 쓰는 이유
- [ ] 프로펠러 진동이 만드는 스펙트럼과 대응: 정적 노치 → 동적 노치 → **RPM 필터**(양방향 DShot 필요)
- [ ] 자이로 캘리브레이션(bias)과 부팅 시 기체가 흔들리면 생기는 문제, 온도 드리프트
- [ ] FIFO vs DRDY 폴링 vs 인터럽트: 각각의 지터 특성
- [ ] 센서 축 정렬(board orientation)과 마운트 진동 절연(soft-mount)

**면접 질문**: "자이로 노이즈가 갑자기 늘어 모터가 뜨겁다. 어떻게 좁혀 들어가나?" (→ 진동/필터/모터 이슈의 고전적 디버깅 트리)

### 3.3 기압계 · 자력계 · GNSS · 광류/ToF
**역할**: 고도·방위·위치 보조. **재밍 환경에서는 GPS를 못 믿는다**는 게 Neros 맥락의 핵심.

- [ ] 기압계 원리와 한계 (프로펠러 와류·기체 내 압력 변화 → 폼 커버)
- [ ] 자력계가 전류(모터·배선)에 오염되는 문제와 캘리브레이션(hard/soft iron)
- [ ] GNSS 기본: TTFF, 위성 수와 HDOP, UBX 프로토콜, RTK가 필요한 경우
- [ ] **GPS 재밍 vs 스푸핑** 차이와 탐지 방법 (신호세기 급변, 해답 불일치)
- [ ] GPS-denied 항법 수단: 광류(optical flow) + ToF 고도, VIO, 관성 추측항법의 드리프트
- [ ] 센서 융합에서 "신뢰할 수 없는 센서"를 빼는 로직 (innovation gate, fault detection)

**면접 질문**: "GPS가 죽었다. Position Hold를 어떻게 유지하나?" ← Archer AI 기능과 직결

### 3.4 ESC와 모터 (추진계)
**역할**: 펌웨어 명령을 추력으로 바꾸는 구간. FC 펌웨어 바깥에 **또 하나의 펌웨어(ESC)** 가 있다.
**핵심 부품**: BLDC 아웃러너(KV 값), 4-in-1 ESC (BLHeli_32 / AM32), MOSFET, 션트 저항.

- [ ] BLDC 정류 방식: 사다리꼴(trapezoidal, BEMF 감지) vs **FOC** — 효율·소음·저속 토크 차이
- [ ] 디지털 프로토콜 계보: PWM → OneShot → **DShot 300/600/1200**, 프레임 구조(11비트 + 텔레 + CRC4)
- [ ] **양방향 DShot**: ESC가 RPM을 되돌려주고 FC가 RPM 노치 필터에 쓰는 루프
- [ ] 모터 타임 상수, 스로틀 응답 지연이 PID 튜닝에 주는 영향
- [ ] 데스크톱 테스트 위험: 프롭 없이 돌릴 때와 부하가 걸릴 때 전류 차이
- [ ] ESC 보호 로직: 과전류, 디싱크(desync), 온도 폴백

**면접 질문**: "모터 하나가 비행 중 디싱크 났다. FC 펌웨어는 이걸 어떻게 감지하고 무엇을 해야 하나?"

### 3.5 전원계
**역할**: 모든 실패의 절반이 여기서 온다. Don의 "safety margin sign-off" 경험이 가장 잘 붙는 곳.

- [ ] LiPo 셀 전압/내부저항, sag(부하 시 전압 강하), 저전압 컷오프 전략
- [ ] 전류 센싱(션트 vs 홀)과 mAh 적산 오차, 배터리 잔량 추정의 어려움
- [ ] 브라운아웃: 급가속 시 전압 강하 → MCU 리셋 → **공중 재부팅**. 대응(벌크 커패시터, BOR 설정, 리셋 원인 기록)
- [ ] 전원 시퀀싱과 인러시 전류, 스파크 방지 XT60 커넥터
- [ ] 노이즈: 스위칭 레귤레이터가 자력계·ADC·라디오에 주는 영향 (Don의 SI 경험과 연결)

**면접 질문**: "필드에서만 가끔 리셋된다. 벤치에서는 재현이 안 된다." ← 컨텍스트 파일 4.3의 디버깅 시나리오와 동일

### 3.6 RC 링크 / C2 라디오
**역할**: 조종 명령과 텔레메트리의 통로. 방산에서는 **적이 적극적으로 방해하는 채널**.
**핵심 부품**: ELRS 계열 송수신기(SX1280 LoRa), 다이버시티 안테나, 또는 Neros 자체 설계 모듈.

- [ ] LoRa 확산 스펙트럼(SF·대역폭)과 수신 감도 vs 데이터율 트레이드오프
- [ ] FHSS(주파수 도약)와 동기화, 패킷 레이트(150/500/1000 Hz)가 지연·사거리에 주는 영향
- [ ] **링크 버짓 계산**: 송신 출력 + 안테나 이득 − 경로손실 − 수신 감도 = 마진 (20km를 어떻게 만드나)
- [ ] CRSF 프로토콜 구조(UART 420 kbaud, 프레임·CRC8), 채널 패킹 11비트 × 16
- [ ] LQ(Link Quality)와 RSSI의 차이, failsafe 판단 기준
- [ ] 재밍의 종류(광대역 barrage, 스윕, 반응형)와 펌웨어 측 대응(주파수 회피, 출력 제어, 저속 모드 폴백)
- [ ] 암호화·인증(리플레이 공격 방지)이 방산 링크에서 필요한 이유

**면접 질문**: "링크 품질이 떨어질 때 텔레메트리·영상·제어 중 무엇을 먼저 버리나?" ← `04_ipc_budget` Q6과 같은 문제

### 3.7 영상 계통 (카메라 · VTX · 고글)
**역할**: FPV의 본질. 조종자가 "보는" 지연이 곧 조작 성능.

- [ ] 아날로그 FPV(CVBS)의 장점: 지연 ~20 ms, 우아한 열화(노이즈로 점점 나빠짐)
- [ ] 디지털 HD 링크: 해상도↑ 지연↑, **절벽형 열화**(cliff effect), 코덱 지연 예산
- [ ] H.264/H.265 인코딩 지연 구성요소, I-frame 주기와 패킷 손실 복원
- [ ] 영상과 C2가 같은 대역을 나눠 쓸 때의 우선순위 정책
- [ ] 카메라 센서 노출/WDR이 종말 유도 비전 인식에 주는 영향

> Neros에 **CODEC Video Compression Engineer** 공고가 따로 있다 — 영상 링크를 직접 만든다는 뜻.

### 3.8 컴패니언 컴퓨트 / Autonomy
**역할**: Archer AI의 "종말 유도"와 GPS-denied 기능이 도는 곳. MCU가 아니라 **embedded Linux + 가속기**.

- [ ] MCU(FC)와 Linux(컴패니언)의 역할 분담, 둘 사이 IPC(UART/SPI/Ethernet/공유메모리)와 시간 동기
- [ ] 비전 기반 표적 추적의 파이프라인 (검출 → 추적 → 유도 명령), 실패 시 폴백
- [ ] 임베디드 가속기에서 모델 양자화(INT8)와 지연·정확도 트레이드오프
- [ ] 결정론적 제어 루프(MCU)와 비결정론적 추론(Linux)을 안전하게 결합하는 인터페이스 설계
- [ ] PREEMPT_RT, CPU 격리(isolcpus), 스케줄링 지연 측정
- [ ] 실패 안전: 컴패니언이 죽어도 기체가 계속 날아야 한다 (watchdog + 권한 회수)

> Neros의 **Autonomy Platform & Runtime Lead** 공고가 이 영역을 그대로 기술한다: 모듈 인터페이스 계약, 실시간 스케줄링,
> 지연 회계, 온보드 로깅·시간 동기, 기체 배포 경로. 지원 포지션(Platform)과 **바로 옆에서 맞물리는 팀**이다.

### 3.9 지상국 (GCS) · 핸드셋
- [ ] MAVLink 개념: 메시지 ID, 시그니처, 텔레메트리 레이트 설정
- [ ] MSP(Betaflight 설정 프로토콜)와 설정 파라미터 전달 구조
- [ ] 다중 기체 운용, 주파수 계획, 전술적 EW 저항 GCS(Flatbow/Crossbow)가 푸는 문제
- [ ] 펌웨어 업데이트·설정을 현장에서 어떻게 배포하나 (USB, 무선 OTA, SD 카드)

### 3.10 페이로드 · 안전 인터페이스 (방산 특수)
- [ ] arming 체인과 안전 요구: 물리적 안전핀, 소프트웨어 arming 조건, 이중 확인
- [ ] "attritable(소모형)" 설계 철학: 회수하지 않는 기체에 어디까지 투자하나

### Betaflight vs PX4 — 면접에서 한 문장으로 구분하기
| | **Betaflight** | **PX4** |
|---|---|---|
| 태생 | FPV 레이싱/프리스타일, 조종감 최우선 | 연구·상용 자율비행 플랫폼 |
| 실행 모델 | 슈퍼루프 + 우선순위 스케줄러(`scheduler.c`), 단일 MCU | NuttX(POSIX) 다중 태스크, 모듈 프로세스 |

| 설정 | **Parameter Groups(PG)** + MSP + CLI | 파라미터 시스템 + MAVLink/QGC |
| 로깅 | **blackbox** (고속 비행 로그) | ulog |
| 추정 | 상보 필터 계열, 간결 | **EKF2** (다센서 융합) |
| 빌드 | make/CMake | CMake + 보드 컨피그 |
| Neros 관련성 | 채용공고에 Betaflight·ExpressLRS 반복 언급 → **FPV 계열 스택 기반** 추정 | 우대사항에 PX4 명시 |

- [ ] Betaflight 소스 트리 훑기: `src/main/` 아래 `scheduler/`, `pg/`, `blackbox/`, `rx/crsf.c`, `flight/pid.c`, `flight/mixer.c`
- [ ] Parameter Group이 "설정 구조체의 버전 호환"을 어떻게 푸는지 (→ `03_config_store` 문제와 직접 비교)
- [ ] uORB의 pub/sub이 MCU 단일 코어에서 어떻게 구현되는지, 복사 vs 제로카피
- [ ] blackbox의 기록 포맷과 대역폭 절약 기법 (델타 인코딩, 프레임 종류 I/P)
- [ ] 부트로더: DFU 진입, 이미지 서명 검증, A/B 슬롯과 롤백 (→ `03_config_store` Q5/Q6과 같은 패턴)

## 5. 제어·추정 핵심 개념 (수학은 최소로)

- [ ] **PID 캐스케이드**: 바깥 각도 루프 → 안쪽 각속도 루프. rate 모드와 angle 모드의 차이
- [ ] P/I/D 각 항이 실제 비행에서 만드는 증상 (진동, 처짐, 노이즈 증폭), D항과 노이즈의 관계
- [ ] 적분 포화(integral windup)와 anti-windup, 모터 포화 시 처리
- [ ] **믹서와 포화**: 한 모터가 상한에 걸렸을 때 자세 권한을 유지하는 법 (airmode, 스로틀 스케일링) → `07` Q6
- [ ] 피드포워드(setpoint 기반)가 조종 반응성에 주는 효과
- [ ] **상보 필터 vs EKF**: 계산량·튜닝·센서 고장 대응의 차이를 각각 두 문장으로
- [ ] 필터 체인이 만드는 위상 지연(phase lag)과 제어 안정성의 정면 충돌
- [ ] 좌표계: body frame vs earth frame, 쿼터니언을 쓰는 이유(짐벌락)

**면접 질문**: "필터를 더 걸면 노이즈는 줄지만 왜 기체가 불안정해지나?" (→ 위상 지연)

## 6. 안전 · failsafe · 진단

- [ ] failsafe 단계 설계: RC 끊김 → 호버/자동 착륙/자폭 등 정책, 복구 조건(re-acquire)
- [ ] arming 조건 체크리스트 (자이로 캘리브레이션, 각도, 배터리, 링크, GPS)
- [ ] 워치독 계층: 하드웨어 IWDG + 소프트웨어 태스크 감시 + 컴패니언 감시
- [ ] 리셋 원인 레지스터 기록과 부팅 시 보고 (brownout인지 워치독인지 HardFault인지)
- [ ] 크래시 덤프를 `.noinit` RAM에 남기고 재부팅 후 전송하는 패턴
- [ ] blackbox 로그로 사후 분석하는 루틴 (모터 출력 포화, 자이로 스파이크, 링크 LQ 급락 상관분석)
- [ ] **필드에서만 나는 버그**를 잡는 전략: 상시 로깅 + 트리거 덤프 + 재현 리그(HIL)

## 7. 양산·플랫폼 관점 — Don의 강점이 붙는 자리

> JD의 "platform code that other engineers depended on"과 Don의 Apple/SSD 경험이 만나는 지점. **이 섹션이 차별화 포인트다.**

- [ ] **HW 변종 관리**: 같은 기능, 다른 부품(Board A/B)을 하나의 코드베이스로 지원하는 법 — 빌드 타임 변종 vs 런타임 감지, HAL 경계, 보드 ID를 EEPROM/저항 스트랩으로 읽기
- [ ] **캘리브레이션·프로비저닝**: 공장에서 기체별 고유값(자이로 bias, 자력계, 시리얼, 키)을 어떻게 써넣고 검증하나
- [ ] **시리얼라이제이션/genealogy**: 어떤 기체에 어떤 보드·펌웨어·부품 로트가 들어갔는지 추적 (Neros에 Manufacturing Systems 공고가 따로 있음)
- [ ] **공장 테스트**: 기능 테스트(FCT) 항목 설계, 커버리지, 테스트 시간이 곧 원가인 대량 생산 환경
- [ ] **OTA/펌웨어 업데이트**: 안전한 롤백, 부분 실패 복구, 야전에서의 업데이트 배포
- [ ] **secure boot / 키 관리**: 노획된 기체에서 펌웨어·키가 유출되는 시나리오
- [ ] **빌드 재현성**: 어떤 커밋이 어떤 기체에 실렸는지 증명하는 것 = 방산에서의 추적성 요구 (→ JD의 hermetic build)
- [ ] 부품 단종(EOL)과 second source 대응이 펌웨어 일정에 주는 충격

**면접에서 쓸 문장**: "저는 새 실리콘이 전체 시스템을 만날 때 깨지는 지점을 잡고, 그걸 MP 전에 잡아내는 공장 테스트 노드를
설계해 왔습니다. 드론은 도메인이 다르지만, 주당 1,200대를 만드는 조직에서 **변종·캘리브레이션·추적성**이 만드는 문제는 같습니다."
