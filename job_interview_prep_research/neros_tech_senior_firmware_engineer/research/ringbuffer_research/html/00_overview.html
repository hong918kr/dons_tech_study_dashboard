🎯 링버퍼 개관 — 무엇이고, 왜 펌웨어의 1번 자료구조인가

링버퍼가 무엇이고 왜 펌웨어의 1번 자료구조인가. 용어 정리와 레벨 0→5 로드맵.

개관약 3분체크 0 / 8
임베디드 면접에서 "자료구조 하나만 완벽하게 물어본다면?" 의 답은 거의 항상 링버퍼다.
이유는 단순하다. 링버퍼는 동적 할당 없이, 고정된 시간 안에, 생산자와 소비자의 속도 차이를 흡수하는
유일한 기본 부품이기 때문이다. UART·SPI·I2C·CAN·USB·로깅·텔레메트리·오디오·DMA — 전부 이걸로 만든다.

1. 문제 정의: 속도가 다른 두 주체#

   빠르고 불규칙한 생산자            느리고 규칙적인 소비자
   ─────────────────────            ────────────────────
   UART RX 인터럽트                  메인 루프의 파서
   IMU DRDY 인터럽트                 1kHz 제어 루프
   LOG_INFO() 호출                   UART 로 뱉는 flush 태스크
   ADC DMA 완료                      필터 계산
        │                                   │
        └──────────►  [   ? ? ?   ]  ◄──────┘

가운데 ? 에 뭘 놓을 것인가.

후보왜 안 되는가
malloc 으로 만든 연결 리스트 큐힙 단편화, 할당 시간이 비결정적(non-deterministic), ISR 에서 malloc 호출 금지, 메모리 고갈 시 대응 불가
그냥 배열 + memmove 로 앞당기기pop 마다 O(n) 복사. 1KB 버퍼에서 인터럽트가 죽는다
전역 변수 하나 (latest_sample)소비자가 늦으면 조용히 유실. 몇 개 놓쳤는지도 모른다
링버퍼고정 메모리, O(1) push/pop, 유실을 숫자로 셀 수 있음 ✅
한 줄 요약: 링버퍼 = 끝과 처음이 이어진 고정 크기 배열 + 읽기 위치 + 쓰기 위치.

2. 용어 — 이 문서 전체에서 이렇게 쓴다#

용어의미주의
head다음에 쓸 위치 (생산자가 움직인다)책마다 반대로 쓰는 경우가 있다. 면접에서는 정의를 먼저 말하고 시작하라
tail다음에 읽을 위치 (소비자가 움직인다)
size / cap버퍼 슬롯 개수레벨 2부터는 2의 거듭제곱 강제
used현재 들어있는 개수head - tail (레벨 2 기준)
free더 넣을 수 있는 개수size - used
empty비어 있음head == tail
full가득 참레벨마다 다르다 — 이것이 레벨을 가르는 핵심

링버퍼의 근본 문제 한 문장#

head == tail 은 비었다는 뜻인가, 가득 찼다는 뜻인가?

배열을 한 바퀴 돌면 두 상황 모두 head == tail 이 된다. 이걸 어떻게 구분하느냐가 레벨 0~2 전체의 주제다.

size = 8, 한 바퀴 돌았을 때

  비었음:  tail ──┐             가득:   tail ──┐
                  ▼                             ▼
           [ ][ ][ ][ ][ ][ ][ ][ ]      [A][B][C][D][E][F][G][H]
                  ▲                             ▲
          head ───┘                     head ───┘

          head == tail                  head == tail      ← 구분 불가!

해법은 셋뿐이다. 한 칸을 버리거나(L0), 개수를 세거나(L1), 인덱스를 안 감싸거나(L2).

3. 레벨 사다리 — 각 레벨은 바로 앞 레벨의 약점을 하나씩 없앤다#

레벨무엇없애는 약점새로 생기는 대가연습
0고정 크기 + % + 한 칸 희생— (출발점)슬롯 1개 낭비, 나눗셈 비용make prob N=L0_modulo
1count 필드 추가낭비되는 한 칸양쪽이 count 를 갱신 → 나중에 무락을 막는다make prob N=L1_count
22의 거듭제곱 + & mask + free-running 인덱스나눗셈 비용 + count 경합 + 낭비 전부size 가 2의 거듭제곱으로 제한make prob N=L2_mask
3void* + elem_size / 매크로 생성int 전용이라는 제약memcpy 오버헤드, 정렬(alignment) 책임make prob N=L3_generic
4stdatomic + acquire/release크리티컬 섹션(인터럽트 지연)메모리 모델을 정확히 알아야 함make prob N=L4_spsc
5a덮어쓰기(overwrite) 모드"가득 차면 새 데이터 유실"생산자도 tail 을 옮긴다 → 무락 논증이 깨진다make prob N=L5a_overwrite
5bacquire/commit zero-copymemcpy 자체랩 지점 분할, DMA 캐시 일관성make prob N=L5b_zerocopy
—함정 총정리 + MPMC——07 노트
레벨 2가 진짜 분기점이다. 실무 펌웨어 링버퍼의 90%는 레벨 2 구조에
(필요하면) 레벨 3/4/5의 성질을 덧댄 것이다. 레벨 0, 1은 왜 레벨 2가 그 모양인지를
이해하기 위한 계단이다.

4. 이 폴더 사용법#

cd research/ringbuffer_research

make list                    # 레벨 목록
make prob N=L0_modulo        # 연습 stub — // TODO 를 채우고 FAIL 이 PASS 로
make sol  N=L0_modulo        # 정답 실행 (전부 PASS 확인)
make diff N=L0_modulo        # 내 답과 정답의 차이
make test                    # 전체 회귀
make notes                   # 이 노트들 HTML 재생성 + 대시보드 열기

하루 한 레벨, 이 루프로#

  1. 노트를 읽는다 (10~20분).
  2. 노트를 덮고 problems/LN_*.c 의 // TODO 를 맨손으로 채운다. 컴파일 에러부터 맞서라.
  3. make prob N=... → FAIL 이 하나라도 남으면 왜 FAIL 인지 먼저 추측하고 나서 고친다.
  4. 전부 PASS 하면 make diff N=... 로 정답과 비교. 다르면 어느 쪽이 나은지 근거를 대 본다.
  5. 다음 날 다시 맨손으로. 두 번째에 30분 안에 못 짜면 아직 내 것이 아니다.
면접에서 요구되는 수준은 "화이트보드에서 20분 안에 레벨 2를 짜고, 랩어라운드와
full/empty 판별을 말로 설명하면서, 레벨 4로 확장하면 뭐가 달라지는지 답하는 것"이다.
