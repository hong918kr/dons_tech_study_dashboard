# 🎯 링버퍼 개관 — 무엇이고, 왜 펌웨어의 1번 자료구조인가

> 임베디드 면접에서 "자료구조 하나만 완벽하게 물어본다면?" 의 답은 거의 항상 **링버퍼**다.
> 이유는 단순하다. 링버퍼는 **동적 할당 없이**, **고정된 시간 안에**, **생산자와 소비자의 속도 차이를 흡수**하는
> 유일한 기본 부품이기 때문이다. UART·SPI·I2C·CAN·USB·로깅·텔레메트리·오디오·DMA — 전부 이걸로 만든다.

---

## 1. 문제 정의: 속도가 다른 두 주체

```
   빠르고 불규칙한 생산자            느리고 규칙적인 소비자
   ─────────────────────            ────────────────────
   UART RX 인터럽트                  메인 루프의 파서
   IMU DRDY 인터럽트                 1kHz 제어 루프
   LOG_INFO() 호출                   UART 로 뱉는 flush 태스크
   ADC DMA 완료                      필터 계산
        │                                   │
        └──────────►  [   ? ? ?   ]  ◄──────┘
```

가운데 `?` 에 뭘 놓을 것인가.

| 후보 | 왜 안 되는가 |
|---|---|
| `malloc` 으로 만든 연결 리스트 큐 | 힙 단편화, 할당 시간이 비결정적(non-deterministic), ISR 에서 `malloc` 호출 금지, 메모리 고갈 시 대응 불가 |
| 그냥 배열 + `memmove` 로 앞당기기 | pop 마다 O(n) 복사. 1KB 버퍼에서 인터럽트가 죽는다 |
| 전역 변수 하나 (`latest_sample`) | 소비자가 늦으면 **조용히 유실**. 몇 개 놓쳤는지도 모른다 |
| **링버퍼** | 고정 메모리, O(1) push/pop, 유실을 **숫자로** 셀 수 있음 ✅ |

> **한 줄 요약**: 링버퍼 = 끝과 처음이 이어진 고정 크기 배열 + 읽기 위치 + 쓰기 위치.

## 2. 용어 — 이 문서 전체에서 이렇게 쓴다

| 용어 | 의미 | 주의 |
|---|---|---|
| `head` | **다음에 쓸** 위치 (생산자가 움직인다) | 책마다 반대로 쓰는 경우가 있다. 면접에서는 **정의를 먼저 말하고** 시작하라 |
| `tail` | **다음에 읽을** 위치 (소비자가 움직인다) | |
| `size` / `cap` | 버퍼 슬롯 개수 | 레벨 2부터는 **2의 거듭제곱** 강제 |
| `used` | 현재 들어있는 개수 | `head - tail` (레벨 2 기준) |
| `free` | 더 넣을 수 있는 개수 | `size - used` |
| empty | 비어 있음 | `head == tail` |
| full | 가득 참 | 레벨마다 다르다 — **이것이 레벨을 가르는 핵심** |

### 링버퍼의 근본 문제 한 문장

> `head == tail` 은 **비었다**는 뜻인가, **가득 찼다**는 뜻인가?

배열을 한 바퀴 돌면 두 상황 모두 `head == tail` 이 된다. 이걸 어떻게 구분하느냐가 레벨 0~2 전체의 주제다.

```
size = 8, 한 바퀴 돌았을 때

  비었음:  tail ──┐             가득:   tail ──┐
                  ▼                             ▼
           [ ][ ][ ][ ][ ][ ][ ][ ]      [A][B][C][D][E][F][G][H]
                  ▲                             ▲
          head ───┘                     head ───┘

          head == tail                  head == tail      ← 구분 불가!
```

해법은 셋뿐이다. **한 칸을 버리거나(L0), 개수를 세거나(L1), 인덱스를 안 감싸거나(L2).**

## 3. 레벨 사다리 — 각 레벨은 바로 앞 레벨의 약점을 하나씩 없앤다

| 레벨 | 무엇 | 없애는 약점 | 새로 생기는 대가 | 연습 |
|---|---|---|---|---|
| **0** | 고정 크기 + `%` + 한 칸 희생 | — (출발점) | 슬롯 1개 낭비, 나눗셈 비용 | `make prob N=L0_modulo` |
| **1** | `count` 필드 추가 | 낭비되는 한 칸 | **양쪽이 count 를 갱신** → 나중에 무락을 막는다 | `make prob N=L1_count` |
| **2** | 2의 거듭제곱 + `& mask` + free-running 인덱스 | 나눗셈 비용 + count 경합 + 낭비 **전부** | `size` 가 2의 거듭제곱으로 제한 | `make prob N=L2_mask` |
| **3** | `void*` + `elem_size` / 매크로 생성 | `int` 전용이라는 제약 | `memcpy` 오버헤드, **정렬(alignment)** 책임 | `make prob N=L3_generic` |
| **4** | `stdatomic` + acquire/release | 크리티컬 섹션(인터럽트 지연) | 메모리 모델을 정확히 알아야 함 | `make prob N=L4_spsc` |
| **5a** | 덮어쓰기(overwrite) 모드 | "가득 차면 새 데이터 유실" | **생산자도 tail 을 옮긴다** → 무락 논증이 깨진다 | `make prob N=L5a_overwrite` |
| **5b** | acquire/commit zero-copy | `memcpy` 자체 | 랩 지점 분할, DMA 캐시 일관성 | `make prob N=L5b_zerocopy` |
| **—** | 함정 총정리 + MPMC | — | — | [07 노트](07_pitfalls_mpmc.html) |

> **레벨 2가 진짜 분기점이다.** 실무 펌웨어 링버퍼의 90%는 레벨 2 구조에
> (필요하면) 레벨 3/4/5의 성질을 덧댄 것이다. 레벨 0, 1은 **왜 레벨 2가 그 모양인지**를
> 이해하기 위한 계단이다.

## 4. 이 폴더 사용법

```sh
cd research/ringbuffer_research

make list                    # 레벨 목록
make prob N=L0_modulo        # 연습 stub — // TODO 를 채우고 FAIL 이 PASS 로
make sol  N=L0_modulo        # 정답 실행 (전부 PASS 확인)
make diff N=L0_modulo        # 내 답과 정답의 차이
make test                    # 전체 회귀
make notes                   # 이 노트들 HTML 재생성 + 대시보드 열기
```

### 하루 한 레벨, 이 루프로

1. 노트를 **읽는다** (10~20분).
2. 노트를 **덮고** `problems/LN_*.c` 의 `// TODO` 를 맨손으로 채운다. 컴파일 에러부터 맞서라.
3. `make prob N=...` → FAIL 이 하나라도 남으면 **왜 FAIL 인지 먼저 추측**하고 나서 고친다.
4. 전부 PASS 하면 `make diff N=...` 로 정답과 비교. 다르면 **어느 쪽이 나은지 근거를 대 본다.**
5. **다음 날 다시 맨손으로.** 두 번째에 30분 안에 못 짜면 아직 내 것이 아니다.

> 면접에서 요구되는 수준은 "화이트보드에서 20분 안에 레벨 2를 짜고, 랩어라운드와
> full/empty 판별을 **말로 설명**하면서, 레벨 4로 확장하면 뭐가 달라지는지 답하는 것"이다.

## 5. 면접에서 반드시 나오는 질문 8개

이 노트 전체를 다 읽고 나면 아래에 전부 답할 수 있어야 한다. 지금은 못 해도 된다 — **체크리스트로 쓰라.**

- [ ] `head == tail` 이 empty 인지 full 인지 어떻게 구분하나? 방법 3가지와 각각의 대가는?
- [ ] 왜 버퍼 크기를 2의 거듭제곱으로 잡나? 1000바이트가 필요하면 어떻게 하나?
- [ ] 인덱스를 마스킹해서 저장하지 않고 계속 증가시키면 오버플로가 나지 않나? (`uint32_t` 가 랩할 때)
- [ ] ISR 에서 `printf` 를 쓰면 왜 안 되나? **4가지** 이유를 대라.
- [ ] `volatile` 만으로 ISR ↔ 메인 공유가 안전한가? 아니라면 무엇이 더 필요한가?
- [ ] `count` 필드를 쓰면 왜 lock-free SPSC 가 깨지나?
- [ ] 버퍼가 가득 찼을 때 새 데이터를 버릴 것인가, 오래된 데이터를 버릴 것인가? 판단 기준은?
- [ ] 생산자가 둘 이상(MPMC)이면 무엇이 달라지나? CAS 하나로 되나?

## 6. 실무에서 이 코드가 어디에 있나 (참고용 레퍼런스)

| 곳 | 무엇 | 어느 레벨 |
|---|---|---|
| Linux `kfifo` (`include/linux/kfifo.h`) | 커널 표준 링버퍼 | 레벨 2 + 레벨 3 (매크로 방식) + SPSC |
| Linux `circ_buf` (`Documentation/core-api/circular-buffers.rst`) | 배리어 설명이 교과서 | 레벨 4 |
| FreeRTOS `StreamBuffer` / `MessageBuffer` | ISR-safe 바이트/메시지 스트림 | 레벨 2 + 4 |
| Zephyr `ring_buf` | `ring_buf_put_claim` / `put_finish` | 레벨 5b (zero-copy) |
| ST HAL `HAL_UART_Receive_DMA` (circular) | HT/TC 인터럽트로 반쪽씩 소비 | 레벨 5b |
| Betaflight / PX4 의 `ringbuffer` | 드론 FC 의 IMU·로그 경로 | 레벨 2 + 5a |
| `boost::lockfree::spsc_queue` | 참고할 만한 C++ 구현 | 레벨 4 |
