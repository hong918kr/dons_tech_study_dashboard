# 코딩 연습 세트 작성 스펙 (`coding/`)

Hark 1차 tech session 대비. [마스터 플랜 §4](../plan/P01_tech_session_master_plan.md)의 우선순위 5문제를 **문제 / 모범답안 / 해설 노트** 세 갈래로 만든다.

## 문제 목록
| N | stem | 주제 | 왜 이 문제인가 |
|---|---|---|---|
| 01 | `01_spsc_ring_isr` | ISR-safe SPSC 링버퍼 | 임베디드 면접 단골 1위. UART·오디오·로그 전부 |
| 02 | `02_i2s_pingpong` | I2S DMA 핑퐁 버퍼 핸드오프 | Hark가 오디오 기기 |
| 03 | `03_reg_bitfield` | 레지스터 비트필드 매크로와 RMW | 워밍업 단골 |
| 04 | `04_mem_pool` | 고정 크기 memory pool | "malloc 없이" 요구가 따라붙음 |
| 05 | `05_uart_parser` | UART 패킷 파서 FSM + 체크섬 | 통신 + 상태기계 + 복구 |

## 파일 구조
```
coding/
  problems/NN_stem.md     ← 문제만. 답·힌트 코드 없음
  starters/NN_stem.c      ← 컴파일되는 뼈대 + 테스트 main (TODO 자리)
  solutions/NN_stem.c     ← 모범답안 + 테스트 main
  notes/NN_stem.md        ← 아주 자세한 해설 (그림 중심)
  Makefile                ← make run N=01 / make sol N=01 / make all
```

## 공통 규칙
1. 노트·문제 문서는 **한국어**, 기술 용어는 영어 그대로. 설명체(~다).
2. **마크다운은 다음만**: `#`~`###`, 문단, `-`/`1.` 목록(중첩 금지), 표, `> ` 인용, 코드펜스, `---`, `- [ ]`, 인라인 `` ` ``/`**굵게**`/`[링크](url)`. raw HTML 금지. 코드 블록 밖에서 별표(`*`) 쓰지 말 것(포인터는 인라인 코드로).
3. 코드는 `cc -std=c11 -Wall -Wextra -O2`에서 **경고 0개**로 컴파일되어야 한다. C11 표준 라이브러리만 쓴다(하드웨어·RTOS 헤더 금지, 필요하면 가짜 정의를 만들고 주석으로 밝힌다).
4. 각 `solutions/NN_*.c`와 `starters/NN_*.c`는 `main()`에 **assert 기반 테스트**를 포함한다. 실행하면 통과 항목을 한 줄씩 출력하고 마지막에 `ALL TESTS PASSED`를 찍는다.
5. `starters/NN_*.c`는 **테스트는 그대로 두고 구현부만 `TODO`**로 비운다. 그 상태로도 컴파일은 되어야 한다(테스트는 실패해도 됨).
6. 기존 [S01 코딩 드릴](../study/S01_c_coding_drills.md)에 같은 주제가 있다. **API 이름과 동작을 S01과 일치**시키고, 해설은 거기보다 훨씬 자세히 쓴다(중복 요약이 아니라 확장).

## `problems/NN_stem.md` 구조 (80~150줄)
```markdown

> **주제**: … · **난이도**: 기초/중급/심화 · **목표 시간**: N분
> **해설은 보지 말 것**: 먼저 `starters/NN_stem.c`를 채워 `make run N=NN`으로 통과시킨다.

## 면접관의 문장
<영어로, 면접관이 실제로 말할 법한 문제 제시 3~6문장>

## 요구사항
<번호 목록으로 정확한 명세. 경계 동작까지 못박기>

## 인터페이스
```c
<헤더에 해당하는 타입과 함수 시그니처만>
```

## 제약
<금지 사항(동적 할당 등), 실행 환경 가정(ISR/스레드), 성능 요구>

## 예시 동작
<입출력 시퀀스 또는 타임라인>

## 스스로 점검할 질문
<풀고 나서 답할 수 있어야 하는 질문 5~8개. 답은 쓰지 않는다>

## follow-up (면접관이 이어서 물을 것)
<3~5개. 답 없이 질문만>
```

## 금지
- 지어낸 API·레지스터 이름. 가상의 것은 주석으로 "예시"라고 밝힌다.
- Don의 경험을 지어내는 것. 이 세트는 기술 문서이므로 개인 경험 언급은 넣지 않는다.
- `solutions/`와 `notes/`의 코드가 서로 다른 것.
