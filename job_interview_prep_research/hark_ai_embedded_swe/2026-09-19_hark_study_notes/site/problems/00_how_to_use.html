1. 폴더 구조#

2. 명령#

터미널에서 coding/ 안으로 들어간 뒤 쓴다.

명령하는 일
make list문제 목록
make run N=01내가 채운 starters/01_*.c 빌드·실행
make sol N=01모범답안 실행 (전부 통과하는 걸 확인)
make all모범답안 5개 전부 실행
make clean빌드 산출물 삭제

구현 전에 make run을 하면 첫 assert에서 멈춘다. 정상이다. 안내 문구가 같이 나온다.

3. 한 문제를 푸는 순서#

  1. problems/NN_*.md를 읽는다. 요구사항과 경계 조건을 종이에 적는다.
  2. 먼저 손으로 자료구조를 그린다. 인덱스가 어디를 가리키는지, 가득 찬 상태와 빈 상태를 어떻게 구분하는지.
  3. starters/NN_*.c의 TODO를 채운다. 테스트는 건드리지 않는다.
  4. make run N=NN — 통과할 때까지.
  5. 통과하면 make sol N=NN으로 모범답안과 비교한다. 다르면 왜 다른지 본다.
  6. notes/NN_*.md를 읽는다. 내가 놓친 관점(ISR 경합, 메모리 순서, 정렬)이 여기 있다.
  7. 문제 파일 맨 아래 "스스로 점검할 질문"에 소리 내어 답한다. 이게 면접에서 나오는 부분이다.

4. 5문제와 우선순위#

N문제왜 중요한가목표
01ISR-safe SPSC 링버퍼임베디드 면접 최빈출. UART·오디오·로그 전부25분 안에 백지에서
02I2S DMA 핑퐁 버퍼Hark가 오디오 기기라 확률 높음30분
03레지스터 비트필드와 RMW워밍업 단골. 못 풀면 치명적15분
04고정 크기 memory pool"malloc 없이"가 따라붙음30분
05UART 패킷 파서 FSM통신 + 상태기계 + 복구를 한 번에35분

하루 한 문제면 5일, 시간이 없으면 01 → 03 → 02 순서로 세 개만.

5. 면접에서의 규칙#

  • 짜기 전에 설계를 한 문장으로 말한다. "인덱스를 free-running으로 두고 마스킹으로 접근하겠습니다."
  • 경계 조건을 먼저 말한다. 가득 참, 빔, wrap, 동시 접근. 이것만으로 점수가 된다.
  • 막히면 침묵하지 말고 불변식을 소리 내어 다시 말한다.
  • 다 짜고 나면 직접 테스트 케이스를 말한다. "제가 확인할 건 세 가지입니다."
