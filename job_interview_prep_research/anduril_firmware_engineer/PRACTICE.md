# 🎯 연습 행동 순서 (How to Practice)

이 폴더로 **실전 연습하는 정확한 순서**. 핵심은 **읽기(대시보드) → 직접 타이핑(에디터) → 컴파일/채점(make) → 막히면 힌트→정답 → 다시 맨손으로.**

---

## 0. 화면 배치 (1회 세팅)

한 화면에 셋을 나란히 두면 흐름이 끊기지 않는다:

| 왼쪽 | 가운데 | 오른쪽 |
|------|--------|--------|
| **대시보드** (읽기) `index.html` 브라우저 | **에디터** `problems/NN.c` (직접 구현) | **터미널** (`make` 실행) |

```sh
cd /Users/donh/workspace/dons_tech_study_dashboard/internview_prep/anduril_firmware_engineer
open index.html          # 대시보드 (오프라인, 새로고침 OK)
code .                   # VS Code로 폴더 열기 (또는 원하는 에디터)
make list                # 토픽(=파일 이름 N) 목록 확인
```

> 대시보드는 **읽기 전용 참고서**, 실제 코딩은 항상 `problems/NN.c` **에디터에서 손으로** 친다. 이게 면접장(빈 화면에 직접 타이핑)과 같은 조건.

---

## 1. 한 문제 연습 루프 ⭐ (제일 중요)

하나의 토픽(예: `05_circular_buffer`)을 잡았다면:

1. **개념 5분** — 대시보드에서 그 토픽 열기 → **Concept cheatsheet + Study note** 훑기 (왜 나오는지 / 패턴 / 함정).
2. **문제 읽기** — 대시보드에서 문제 카드 펼쳐 **Problem·Signature·Examples** 확인. **정답(Solution)은 아직 열지 않는다.**
3. **에디터에서 구현** — `problems/05_circular_buffer.c` 의 해당 함수 `// TODO` 를 직접 채운다.
4. **컴파일 + 실행 (채점)**:
   ```sh
   make prob N=05_circular_buffer
   ```
   → 테스트 하네스가 `[PASS]/[FAIL]` 를 찍는다. 목표는 **내가 짠 함수의 FAIL → PASS.**
5. **막히면 힌트** — 3분 이상 막히면 대시보드 카드에서 **hint 1 → 2 → 3** 순서로만 연다 (한 번에 다 열지 말 것).
6. **그래도 막히면 정답** — 카드의 **"정답 코드 보기"** 로 확인 → **해설(Explanation)·함정(Pitfalls)** 까지 읽고 **왜** 그런지 이해.
7. **맨손 재구현** — 방금 본 정답을 **지우고** `problems/NN.c` 를 **다시 처음부터** 직접 친다. (핵심: 눈으로 이해 ≠ 손이 기억. 이 단계가 진짜 연습.)
8. **solved 체크** — 다 풀면 대시보드 카드의 **체크박스**로 표시 → 진행률이 저장된다(localStorage).

> 참고 파일: `solutions/NN.c` = 정답 원본, `notes/NN.md` = 노트(대시보드 Study note와 동일 내용). 에디터에서 바로 보고 싶을 때 사용.

## 2. 하루 루틴 (예: 60~90분)

1. **복습 10분** — 대시보드 **미해결만(unsolved)** 필터로, 어제 푼 토픽에서 1~2개 **맨손 재구현**(1번 루프 7단계).
2. **신규 40~60분** — 오늘 토픽 1개를 1번 루프로 진행 (보통 문제 3~6개).
3. **모의고사 1세트(45분)** — 아래 3번. (시간 여유 있을 때 / 주 2~3회)
4. 끝나고 대시보드 상단 **진행률(%)** 확인.

## 3. 45분 모의고사 루틴 (면접 시뮬레이션)

네 지난 탈락 지점이 "3번을 시간 내 못 넘김"이었으니 **이게 제일 중요한 훈련**이다.

1. 대시보드 → **⏱️ 45분 모의고사** 탭 → 세트 하나 고른다.
2. **▶ 시작** 누르고 타이머 켠다. **정답 절대 안 보기.**
3. 3문제(easy→medium→hard)를 에디터에서 `make prob N=…` 로 **순차 완주** 시도.
4. 45:00 지나면(또는 3개 끝나면) 멈추고 **못 푼 문제만 정답 확인 → 맨손 재구현.**
5. 목표: **45분 안에 3번까지 PASS.** 처음엔 2개도 OK, 매주 속도를 올린다.

## 5. 명령어 치트시트

```sh
make list                       # 토픽(N 값) 목록
make prob N=05_circular_buffer  # 내 연습 파일 컴파일+실행 (FAIL→PASS 확인)  ← 평소 이거
make sol  N=05_circular_buffer  # 정답 컴파일+실행 (전부 PASS 확인용)
make test                       # 전 토픽 정답 회귀 (환경 점검용, 173문제 801체크)
make clean                      # 빌드 산출물 삭제
```

- `N` = `problems/` 파일 이름에서 `.c` 뺀 것 (예: `11_arrays_hashing`).
- 컴파일 경고도 버그다 — `make` 는 `-Wall -Wextra` 로 돈다. 경고 0 + 전 PASS 가 목표.

---

## 6. 막힐 때 규칙 (자기통제)

- **3분 룰**: 3분 막히면 hint 1개. 또 3분이면 hint 2. 정답은 **최후에만.**
- 정답 본 문제는 **반드시 그 자리에서 맨손 재구현**(안 하면 안 배운 것).
- "이해했다"는 착각 금지 — **빈 파일에서 다시 칠 수 있어야** 아는 것.
- 하루 끝: 오늘 푼 것 중 1개를 내일 복습 큐(unsolved 해제 안 하고 재도전)로.
