## 2. 임베디드 C 기본 — 거의 확실 (각 30초 답변)

| 질문 | 답의 핵심 |
|---|---|
| `volatile`은 언제 쓰나? | 컴파일러가 접근을 캐시·제거하지 못하게. **MMIO 레지스터**, ISR과 공유하는 플래그(`sig_atomic_t`), 하드웨어가 바꾸는 메모리. **스레드 동기화에는 부족** — 원자성도 순서도 없음 |
| `static` 세 가지 의미 | 파일 스코프 링키지 제한 / 함수 내 지역의 수명 연장 / 구조체 밖 전역의 심볼 은닉. 임베디드에선 정적 버퍼 확보에도 |
| `const volatile`이 말이 되나? | 된다. "내가 쓰지는 않지만 하드웨어가 바꾸는" 읽기 전용 상태 레지스터 |
| 구조체 패딩·정렬 | 멤버는 자기 크기 배수 주소에 정렬, 구조체 끝에도 패딩. **레지스터 맵이나 패킷에 struct를 그대로 쓰면 위험** → `packed` 또는 바이트 단위 직렬화 |
| 엔디안 | 바이트 순서. 네트워크/프로토콜은 대개 big-endian → 바이트 단위로 조립·분해하면 호스트 무관 |
| 비트 조작 | set `x |= (1u<<n)` / clear `x &= ~(1u<<n)` / toggle `x ^= (1u<<n)` / test `(x>>n)&1u`. **RMW는 원자적이 아니다** — 레지스터는 ISR·다른 코어와 경쟁 |
| 스택 vs 힙, malloc 금지 이유 | 단편화로 장시간 구동 후 실패, 할당 시간이 비결정적. 정적 풀·부팅 시 1회 할당. 스택 사용량은 최악값으로 계산 |
| 함수 포인터 | 드라이버 인터페이스(ops 구조체), 상태머신 테이블. 테스트에서 fake 주입 |
| 고정소수점 | float 없는 MCU에서 Q포맷. 곱셈 후 시프트, 오버플로 주의 |

## 3. 인터럽트 · 동시성 — 이 면접관이 좋아할 영역

| 질문 | 답의 핵심 |
|---|---|
| ISR에서 하면 안 되는 것 | 블로킹(mutex/malloc/printf), 긴 작업. 플래그 세우거나 **lock-free 링버퍼**에 넣고 즉시 나온다. RTOS는 `...FromISR` 변형만 |
| ISR ↔ main 데이터 공유 | SPSC 링버퍼 + `_Atomic` 인덱스, release/acquire. 가득 차면 **버리고 카운트**(ISR은 기다릴 수 없다) |
| Linux에서 인터럽트 처리 구조 | top half(빠르게 확인·ack) / bottom half(workqueue, threaded IRQ)로 분리. 하드 IRQ 컨텍스트에선 잠들 수 없어 **spinlock**, 프로세스 컨텍스트에선 mutex |
| spinlock vs mutex (커널) | spinlock은 안 잠들고 도는 것 — 인터럽트 컨텍스트·아주 짧은 구간. mutex는 잠듦 — 프로세스 컨텍스트. 싱글코어 선점 커널에서 spinlock은 선점 비활성화 |
| 우선순위 역전 | 낮은 우선순위가 락을 쥔 채 중간에 선점 → 높은 우선순위 무한 대기. **우선순위 상속 mutex**(FreeRTOS `xSemaphoreCreateMutex`, 바이너리 세마포어는 불가), 또는 자원을 한 태스크가 소유 |
| 원자성 vs 배리어 | atomic은 연산이 안 쪼개지는 것, 배리어는 **보이는 순서**. ARM에서 release≈저장 전 DMB, acquire≈로드 후 DMB. Cortex-R 멀티코어에서 공유 디스크립터에 배리어 넣던 경험 |
| watchdog | 정해진 시간 내 kick 못 하면 리셋. **작업 스레드의 진행을 확인한 뒤** kick해야 의미 있음(그냥 타이머로 kick하면 무용지물) |

## 4. 버스 · 프로토콜 — 제품이 I2C/SPI/UART라 반드시

| 질문 | 답의 핵심 |
|---|---|
| I2C 기본 | 2선(SCL/SDA), 오픈드레인 + 풀업, 주소 7비트, ACK/NACK, 멀티마스터 조정 |
| I2C 버스가 hang되면? | 슬레이브가 SDA를 잡고 있음 → **SCL을 9클럭 토글**해 트랜잭션 강제 종료 후 STOP, 그래도 안 되면 전원 리셋. 원인: 마스터가 중간에 리셋됨 |
| clock stretching | 슬레이브가 SCL을 low로 잡아 마스터를 기다리게 함. 마스터 구현이 이걸 지원해야 함 |
| 풀업 저항 선택 | 너무 크면 rise time 초과(파형 둥글어짐), 너무 작으면 low 레벨 못 만듦. 버스 용량과 속도로 계산 — **스코프로 파형 확인**이 답 |
| SPI | 4선, CPOL/CPHA 4모드, CS 타이밍, 풀듀플렉스. 데이지체인 |
| UART | 비동기, baud 오차 2% 이내, 프레이밍/오버런 에러, 흐름제어 |
| CRC/체크섬 | 전송 오류 검출. CRC 다항식, 검증 시 0이 되는 성질. **틀리면 출력에 값을 쓰지 않는다** |
| 프레이밍 | 길이 접두 vs 구분자(SLIP 스터핑) vs 고정 길이. **부분 수신**을 전제로 상태 있는 파서 |

## 5. Linux 쪽 (면접관 전문 영역 — 정직하게, 아는 만큼 정확히)

| 질문 | 답의 핵심 |
|---|---|
| kernel space vs user space | 드라이버는 커널, 데몬은 유저. `/dev`, `/sys`, `ioctl`, `mmap`로 연결. 크래시 파급·권한·성능이 다름 |
| 디바이스 드라이버가 하는 일 | 하드웨어 레지스터 접근을 추상화해 char/block/net 인터페이스로 노출. probe에서 리소스 확보, 인터럽트 등록, file_operations 제공 |
| device tree | 어떤 하드웨어가 어디에 붙었는지 커널에 알려주는 데이터. 드라이버 코드 변경 없이 보드 차이 흡수 |
| 유저 공간에서 I2C | `/dev/i2c-N` + `ioctl(I2C_SLAVE)` + read/write. 커널 드라이버가 필요한 경우는 인터럽트·전력관리·다른 서브시스템 연동이 필요할 때 |
| DMA와 캐시 | DMA가 쓴 버퍼는 읽기 전 **invalidate**, CPU가 쓴 버퍼는 보내기 전 **clean**. 캐시 라인 정렬. Linux는 `dma_alloc_coherent` 또는 streaming API |
| 부팅 순서 | ROM → SPL → U-Boot → kernel → rootfs → init(systemd). 어디서 멈췄는지로 문제 범위를 좁힌다 |
| poll/epoll | 한 스레드가 여러 fd 대기. 게이트웨이 데몬의 기본 구조. EINTR·부분 read 처리 |
| A/B OTA | 비활성 슬롯에 쓰고 서명 검증 후 부트 설정 전환, 헬스체크 통과 전엔 커밋 보류, 실패 시 롤백 |

> **갭을 다루는 문장**: "커널 드라이버를 프로덕션에 올려본 적은 없습니다. 제가 한 건 베어메탈에서 그 아래층 — 부트 ROM부터 DRAM·PCIe 컨트롤러 브링업, 레지스터 레벨 드라이버, DMA·인터럽트 —이라서, Linux가 무엇을 추상화하는지는 정확히 압니다. 지금 그 위쪽을 배우는 중이고, 예를 들어 [최근 공부한 것 하나]를 해봤습니다."
> 절대 아는 척하지 말 것. 이 면접관은 바로 안다.

## 6. 디버깅 시나리오 — 가장 배점이 큰 부분

**질문 예**: "게이트웨이가 며칠에 한 번씩 오프라인이 됩니다. 어떻게 접근하시겠어요?" / "센서가 가끔 이상한 값을 줍니다." / "보드가 부팅이 안 됩니다."

**말할 방법론 (순서를 그대로)**

1. **증상 정의**: 재현율, 조건(온도·시간·특정 유닛), 언제부터, 무엇이 바뀌었나
2. **범위 좁히기**: 전원 → 클럭 → 리셋 → 버스 신호 → 펌웨어 로직 → 상위 소프트웨어. **계층을 반으로 자른다**
3. **관측 확보**: 로그·카운터를 먼저 심는다(재현이 느릴수록 중요). 스코프/로직 분석기로 **실제 파형**, 프로토콜 분석기로 트랜잭션
4. **가설 하나씩 검증**: 한 번에 한 변수만 바꾼다
5. **재현 조건 자동화**: 스트레스·온도 챔버·전원 사이클로 재현율을 올린다
6. **근본 원인 확인 후 재발 방지**: 테스트 추가, 카운터 노출

**여기서 꺼낼 내 사례 3개 (미리 정리)**
- Apple: 간헐적 인터페이스 장애를 스코프·프로토콜 분석기로 root cause까지 — 신호 마진 문제였는지, 타이밍이었는지 구체적으로
- Solidigm: FPGA 브링업에서 RTL freeze 전 I2C/SPI/DMA 버그 발견
- SK hynix: NVMe telemetry로 **현장에서 재현 안 되는 문제**를 데이터로 추적 → 200만 대 fleet과 바로 연결되는 이야기

## 7. 실시간·설계 (어제 준비한 것 그대로)

- 생산자를 막지 않는 버퍼링: 링버퍼 / **더블·트리플 버퍼**(소유권 3상태) / 최신값
