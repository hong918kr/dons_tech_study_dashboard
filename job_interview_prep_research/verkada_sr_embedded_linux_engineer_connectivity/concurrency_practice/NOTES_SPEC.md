# concurrency_practice 기초 노트 — 작성 스펙

## 목적

`concurrency_practice/solutions/NN_*.c` 의 10문제는 **면접 시뮬레이션용 통짜 문제**다.
여기에 붙일 노트는 성격이 다르다: **동시성을 처음부터 다시 배우는 사람이 읽는 글**이다.

독자는 Don — 임베디드 펌웨어 7년 경력(SSD 컨트롤러, 베어메탈 C, DMA/ISR)이지만
**POSIX 스레드·condvar·C11 atomics·Linux 사용자 공간은 거의 처음**이다. 그래서:

- 베어메탈에서 이미 아는 것(인터럽트, DMA 완료, 링버퍼, 레지스터)과 **연결해서** 설명한다.
- `pthread_mutex_lock` 같은 API는 **처음 보는 사람 기준으로** 한 번은 풀어서 설명한다.
- 수식이나 형식적 정의보다 **왜 그렇게 되는지 그림과 시나리오**로 설명한다.
- 한 줄씩 코드를 따라가며 "이 줄이 없으면 무슨 일이 생기나"를 보여준다.

이미 있는 `verkada_prep/notes/*.md` 는 **면접 직전 복습용 요약**이다. 이 노트는 그 앞 단계,
**처음 이해하는 단계**를 담당한다. 내용이 겹쳐도 좋지만 톤과 깊이가 달라야 한다.

## 파일


## 공통 규칙

1. **한국어 기본**, 기술 용어는 영어 그대로(mutex, condition variable, memory order…).
   설명체(~다). 존댓말 금지.
2. 코드 블록은 ```` ```c ````, 터미널은 ```` ```sh ````, 다이어그램은 ```` ``` ````.
3. **마크다운 문법은 다음만 사용**: `#`~`###` 제목, 문단, `-`/`1.` 목록(중첩 금지),
   표, `> ` 인용, ```` ``` ```` 코드펜스, `---` 구분선, `- [ ]` 체크박스,
   인라인 `` ` `` `**굵게**` `[링크](url)`. **raw HTML 금지**(HTML 렌더러가 따로 있다).
4. 길이: 문제별 노트 150~300줄, `00_start_here.md` 250~400줄.
5. 코드 조각은 반드시 `solutions/NN_*.c` 의 **실제 코드와 일치**해야 한다. 지어내지 말 것.
   (먼저 해당 .c 파일을 읽고, 인용할 부분을 그대로 가져온다. 설명을 위해 줄여 인용하는 것은
   괜찮지만 동작이 달라지게 바꾸면 안 된다.)
6. 각 노트 맨 위 `> **연습**:` 줄의 명령은 실제로 동작하는 것만 쓴다
   (`make run N=01`, `make sol N=01`, `make tsan N=01`).
7. 파일은 지정된 것만 만든다. `solutions/`, `starters/`, `Makefile` 등 기존 파일은 **수정 금지**.
