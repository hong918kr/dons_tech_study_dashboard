0. 문제 한국어 소개 (먼저 읽기)

영어 문제(§1)를 읽기 전에 무엇을 만들라는 건지 먼저 잡기 위한 요약입니다. 실제 풀이와 테스트는 §1 영어 문제 기준입니다.

  • 한 줄 요약: 바퀴 두 개짜리 로봇의 encoder 값으로 위치(x, y, θ)를 추적하고(A·B), 그 위치로 waypoint들을 차례로 찾아가는 시뮬레이션을 돌린다(C).
  • 상황: differential-drive 로봇(구동 바퀴 2개 + 보조 바퀴 1개). 바퀴마다 quadrature encoder가 있고 16-bit 하드웨어 카운터로 읽는다. 앞으로 굴면 증가, 뒤로 굴면 감소, 양방향으로 wrap(65535 + 1 → 0, 0 − 1 → 65535).
  • 배경 개념
    • encoder tick: 바퀴가 조금 돌 때마다 1씩 세는 단위. 여기선 1바퀴 = 2048 tick(x4 decode 후). 1바퀴에 가는 거리는 2π · 바퀴 반지름이라 tick당 거리 = 2π · wheel_radius_m / ticks_per_rev.
    • track width: 왼쪽·오른쪽 바퀴 사이 거리. 두 바퀴가 간 거리가 다르면 그 차이 ÷ track width만큼 로봇이 돈다: dθ = (dr − dl) / track_width_m. 로봇 중심이 간 거리는 평균 d = (dl + dr) / 2.
    • dead reckoning / odometry: 바깥 센서 없이 바퀴가 간 거리만 누적해서 현재 pose(x, y, θ)를 추정하는 것.
    • midpoint integration: 한 스텝 동안 방향이 바뀌니까 시작 방향 θ 대신 중간 방향 θ + dθ/2로 이동시키는 방식. 그냥 cos(θ)(Euler)는 테스트 정밀도를 못 맞춘다.
  • 입력: Part A는 이전/현재 16-bit 카운터 값. Part B는 pose, 양쪽 바퀴 tick 변화량, Robot(ticks_per_rev, wheel_radius_m, track_width_m, max_omega_rad_s). Part C는 시작 pose, waypoint 배열 wps[n], 속도 v, 조향 gain k_heading, dt, reach_tol, t_max.
  • 출력: A는 부호 있는 tick 수. B는 *p 갱신. C는 모든 waypoint 도착이면 true + *t_done, 시간 초과면 false.
  • 규칙
    • Part A: wrap을 넘어도 정확해야 함. 읽는 사이 이동은 32768 tick 미만이라고 가정.
    • Part B: wrap_angle()은 각도를 (−π, π] 로. odom_update() 후 θ도 이 범위 유지. midpoint 또는 exact arc 사용.
    • Part C: 매 스텝 t = k · dt. ① 현재 waypoint까지 거리 <= reach_tol이면 다음 것으로(여러 개 연속 가능) ② 다 도착하면 *t_done = t, true ③ t >= t_max면 false(*t_done 안 씀) ④ ω = k_heading · wrap(waypoint 방향 − θ), ±max_omega 로 clamp ⑤ 거리 v·dt, 회전 ω·dt만큼 이동(Part B integrator 재사용).
    • n == 0이면 바로 true, *t_done = 0. malloc 금지.
  • 예제 풀어 읽기: 1바퀴 = 2π·0.1 = 0.628319 m. enc_delta(65530, 4) = +10, enc_delta(3, 65533) = -6. 양쪽 2048 tick → (0.628319, 0, 0) 직진. (−1024, 1024) → 제자리 회전, θ = 1.256637. (1, 3) tick을 1280번 → 반지름 0.5 m 사분원, (0.5, 0.5, π/2). θ = 3.0에서 1.256637 더 돌면 −2.026548로 wrap. 정사각형 (2,0) (2,2) (0,2) (0,0) 따라가기 → 16.09 s.
  • 놓치기 쉬운 것: +32767은 그대로, +32769는 −32767로 해석됨; wrap_angle(-π)는 π(경계가 (−π, π]); 65000 → 1512는 +2048; waypoint 0개면 pose 그대로; 시작부터 reach_tol 안이면 t = 0; 시간 초과 시 *t_done 건드리지 않기; 170°에서 −168.7° 방향 목표는 왼쪽으로 21.3° 도는 게 최단(heading 오차를 wrap 안 하면 오른쪽으로 길게 돎).
  • 구현할 함수
    • Part A: enc_delta(prev, now)
    • Part B: wrap_angle(a), odom_update(p, dl_ticks, dr_ticks, r)
    • Part C: follow_waypoints(p, wps, n, r, v, k_heading, dt, reach_tol, t_max, t_done)

1. Problem

A small differential-drive ground robot (two driven wheels, one caster) has a quadrature encoder on each wheel. Each encoder is read from a 16-bit hardware counter that counts up when the wheel rolls forward and down when it rolls backward, and wraps in both directions (65535 + 1 → 0, 0 − 1 → 65535). Build the dead-reckoning layer and a tiny path follower.

Part A — encoder delta

  • enc_delta(prev, now) returns the signed number of ticks moved between two counter reads.
  • It must be correct across the wrap. You may assume the wheel moved fewer than 32768 ticks between reads.

Part B — odometry

  • wrap_angle(a) maps any angle (radians) to the range (−π, π].
  • odom_update(p, dl_ticks, dr_ticks, r) updates the pose from the two wheel deltas:
    • meters per tick = 2π · wheel_radius_m / ticks_per_rev
    • d = (dl + dr) / 2 (distance of the robot center), dθ = (dr − dl) / track_width_m
    • Use midpoint integration (x += d·cos(θ + dθ/2), same for y with sin) or the exact arc. Plain Euler (cos(θ)) is not accurate enough for the tests.
    • Keep θ in (−π, π].

Part C — waypoint following (simulation)

follow_waypoints() runs a fixed-step simulation of a unicycle model (constant forward speed v, turn rate ω). At step k the time is t = k · dt. Every step:

  1. While the current waypoint is within reach_tol (distance <=), advance to the next one.
  2. If all waypoints are reached, write t to *t_done and return true.
  3. If t >= t_max, return false (do not write *t_done).
  4. Steer: ω = k_heading · wrap(bearing_to_waypoint − θ), clamped to ±r->max_omega_rad_s.
  5. Move one step: distance v·dt, turn ω·dt (reuse your Part B integrator).

n == 0 means there is nothing to do: return true with *t_done = 0.

Constraints

  • double for the pose, integer ticks for the encoders. <math.h> is available.
  • No malloc. follow_waypoints runs at most t_max / dt steps of O(1) work.
  • dt > 0. wps may be NULL only when n == 0.

Clarifying questions to ask (first 3 minutes)

  1. How often are the encoders read, and what is the top wheel speed? (Is |delta| < 32768 guaranteed?)
  2. Is θ = 0 along +x, counter-clockwise positive? Which wheel is "left"?
  3. Should θ be wrapped to (−π, π] or [0, 2π)?
  4. Midpoint or exact-arc integration? Do you want me to compare with Euler?
  5. In the follower: is "reached" <= or < reach_tol? Is speed constant, or should it slow down near the waypoint?
  6. What should happen when there are zero waypoints, or the robot already sits on one?

    const Robot rb = { 2048, 0.10, 0.50, 2.0 };     /* 1 rev = 2*pi*0.1 = 0.628319 m */
    Pose p;
    double t;

    /* 1. enc_delta, no wrap */

    CHECK(enc_delta(150, 100) == -50);

    /* 2. enc_delta across the wrap, both directions */
    CHECK(enc_delta(65530, 4) == 10);
    CHECK(enc_delta(3, 65533) == -6);

    /* 3. half-range limit: +32767 is fine, +32769 aliases to -32767 */
    CHECK(enc_delta(0, 32767) == 32767);
    CHECK(enc_delta(0, 32769) == -32767);

    /* 4. straight line: both wheels one revolution */

    odom_update(&p, 2048, 2048, &rb);
    CHECK(NEAR(p.x, 0.628319, 1e-6) && NEAR(p.y, 0.0, 1e-12) && NEAR(p.theta, 0.0, 1e-12));

    /* 5. spin in place: x, y unchanged, theta = 2 * 0.314159 / 0.5 = 1.256637 */
    p = (Pose){ 1, 2, 0 };
    odom_update(&p, -1024, 1024, &rb);
    CHECK(NEAR(p.x, 1.0, 1e-12) && NEAR(p.y, 2.0, 1e-12) && NEAR(p.theta, 1.256637, 1e-6));

    /* 6. quarter circle, radius 0.5 m: 1280 small steps of (1, 3) ticks -> (0.5, 0.5, pi/2) */
    p = (Pose){ 0, 0, 0 };
    for (int s = 0; s < 1280; s++) odom_update(&p, 1, 3, &rb);
    CHECK(NEAR(p.x, 0.5, 1e-6) && NEAR(p.y, 0.5, 1e-6) && NEAR(p.theta, PI / 2, 1e-9));

    /* 7. heading wrap: 3.0 + 1.256637 = 4.256637 -> -2.026548 */
    p = (Pose){ 0, 0, 3.0 };
    odom_update(&p, -1024, 1024, &rb);
    CHECK(NEAR(p.theta, -2.026548, 1e-6));

    /* 8. wrap_angle range is (-pi, pi] */
    CHECK(NEAR(wrap_angle(PI), PI, 1e-12) && NEAR(wrap_angle(-PI), PI, 1e-12));
    CHECK(NEAR(wrap_angle(1.5 * PI), -0.5 * PI, 1e-12) && NEAR(wrap_angle(-7.0), -7.0 + 2 * PI, 1e-12));
    CHECK(NEAR(wrap_angle(0.25), 0.25, 1e-15));

    /* 9. encoder wrap feeding odometry: 65000 -> 1512 is +2048 ticks on both wheels */
    p = (Pose){ 0, 0, 0 };
    odom_update(&p, enc_delta(65000, 1512), enc_delta(65000, 1512), &rb);
    CHECK(NEAR(p.x, 0.628319, 1e-6) && NEAR(p.y, 0.0, 1e-12));

    /* 10. square path: 4 waypoints, v = 0.5 m/s, k = 3, dt = 10 ms, tol = 0.1 m -> 16.09 s */
    const Point sq[] = { {2, 0}, {2, 2}, {0, 2}, {0, 0} };
    p = (Pose){ 0, 0, 0 }; t = -1;
    CHECK(follow_waypoints(&p, sq, 4, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(NEAR(t, 16.09, 0.05) && hypot(p.x, p.y) <= 0.1);

    /* 11. zero waypoints: done immediately, pose untouched */
    p = (Pose){ 1, 1, 0.5 }; t = -1;
    CHECK(follow_waypoints(&p, NULL, 0, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(t == 0.0 && p.x == 1.0 && p.y == 1.0 && p.theta == 0.5);

    /* 12. already inside reach_tol of the only waypoint */
    const Point here[] = { {0.05, 0} };
    p = (Pose){ 0, 0, 0 }; t = -1;
    CHECK(follow_waypoints(&p, here, 1, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(t == 0.0 && p.x == 0.0);

    /* 13. timeout: the square needs ~16 s, t_max = 5 s -> false, t_done untouched */
    p = (Pose){ 0, 0, 0 }; t = -1;
    CHECK(!follow_waypoints(&p, sq, 4, &rb, 0.5, 3.0, 0.01, 0.1, 5.0, &t));
    CHECK(t == -1);

    /* 14. heading error crosses +-pi: facing 170 deg, target at bearing -168.7 deg.
     *     Shortest turn is +21.3 deg (left). Turning right the long way takes 5.00 s. */
    const Point behind[] = { {-1.0, -0.2} };
    const double th0 = 170.0 * PI / 180.0;
    p = (Pose){ 0, 0, th0 }; t = -1;
    CHECK(!follow_waypoints(&p, behind, 1, &rb, 0.5, 3.0, 0.01, 0.1, 0.01, &t));  /* one step */
    CHECK(p.theta > th0);                                                       /* turned left */
    p = (Pose){ 0, 0, th0 }; t = -1;
    CHECK(follow_waypoints(&p, behind, 1, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(NEAR(t, 1.86, 0.05));

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

3. 힌트 (막힐 때 하나씩)

Hint 1 — Part A는 타이머 랩어라운드와 똑같다

now - prev를 16비트 unsigned로 먼저 자르고((uint16_t)), 그 결과를 int16_t로 다시 해석하면 됩니다. 0x8000 미만이면 앞으로, 이상이면 뒤로 간 것입니다. uint16_t끼리 빼면 int로 승격되므로 캐스트 없이 return now - prev;라고 쓰면 4 - 65530 = -65526이 그대로 나옵니다.

Hint 2 — Part B: 이동과 회전을 한 함수로

static void advance(Pose *p, double d, double dth) 하나를 만들고 Part B와 Part C가 같이 쓰게 하세요. 안에서는 이동 방향을 θ + dth/2(구간 중간 헤딩)로 잡고, 마지막에 θ = wrap_angle(θ + dth). wrap_angle은 fmod(a, 2π) 후 > π면 −2π, <= −π면 +2π.

Hint 3 — Part C: 각도 오차는 반드시 wrap

bearing - θ를 그대로 쓰면 170°에서 −169°를 볼 때 오차가 −339°가 되어 반대 방향으로 거의 한 바퀴 돕니다. wrap_angle(bearing - θ)면 +21°. 루프 순서는 "도달 검사 → 끝났나 → 시간 초과 → 조향 → 한 스텝 이동"이고, 시간은 t += dt 누적 대신 t = k * dt로 계산하면 오차가 쌓이지 않습니다.

4. 풀이

4.1 핵심 아이디어 — 엔코더 랩어라운드

16비트 카운터는 원형입니다. "두 읽기 사이의 차이"를 모듈로 2¹⁶으로 계산한 뒤, 가까운 쪽(±32767 안)으로 해석하면 방향까지 맞게 나옵니다. HAL 타이머 tick 비교((int32_t)(now - deadline) >= 0)와 같은 원리입니다.

조건은 두 읽기 사이 실제 이동이 32768 tick 미만이라는 것뿐입니다. 이 로봇(2048 tick/rev)이라면 한 번 읽는 사이에 바퀴가 16바퀴 미만 돌면 되므로, 100 Hz로 읽으면 1600 rev/s까지 안전합니다. 테스트 3번이 이 한계를 보여 줍니다: enc_delta(0, 32769)는 실제로 +32769였더라도 −32767로 보입니다.

4.2 차동 구동 기하 — 왜 d와 dθ가 그렇게 나오나

4.5 정답 코드

💡 정답 코드 펼치기 (35분 풀어 본 다음에)
solution.c
/*
 * R2  Wheel Odometry and Waypoint Following (differential drive)
 *
 * A two-wheeled ground robot has one quadrature encoder per wheel. Each encoder is a
 * 16-bit hardware counter that wraps in both directions.
 *
 * Part A  enc_delta(prev, now): signed tick change between two counter reads.
 *         Must be correct across the 65535 <-> 0 wrap. Assume |real motion| < 32768
 *         ticks between reads.
 * Part B  wrap_angle(a): map any angle to (-pi, pi].
 *         odom_update(p, dl_ticks, dr_ticks, r): dead-reckon the pose from the two wheel
 *         deltas. ticks -> meters, d = (dl + dr) / 2, dtheta = (dr - dl) / track.
 *         Use midpoint (or exact-arc) integration, not Euler. Keep theta in (-pi, pi].
 * Part C  follow_waypoints(...): fixed-step simulation (unicycle model, constant v).
 *         Each step: if within reach_tol of the current waypoint, advance to the next
 *         (repeat); when all are reached return true and write the time to *t_done.
 *         Otherwise steer with omega = k_heading * wrap(bearing_to_wp - theta),
 *         clamp |omega| <= r->max_omega_rad_s, and move one step of dt.
 *         Time is k * dt (step k). Return false (t_done untouched) once t >= t_max.
 *         n == 0 -> true, t_done = 0.
 *
 * Reference solution.  Build & run:  ./run.sh R2 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <math.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)
#define NEAR(a, b, tol) (fabs((a) - (b)) <= (tol))

#define PI 3.14159265358979323846

typedef struct { double x, y, theta; } Pose;      /* meters, meters, radians (-pi, pi] */
typedef struct { double x, y; } Point;
typedef struct {
    uint32_t ticks_per_rev;      /* encoder ticks per wheel revolution (after x4 decode) */
    double   wheel_radius_m;
    double   track_width_m;      /* distance between the two wheel contact points */
    double   max_omega_rad_s;    /* turn-rate limit used by follow_waypoints */
} Robot;

/* ---- Part A ---- */
int32_t enc_delta(uint16_t prev, uint16_t now)
{
    /* modulo-2^16 difference, then reinterpret as signed: same trick as wrap-safe timers */
    return (int16_t)(uint16_t)(now - prev);
}

/* ---- Part B ---- */
double wrap_angle(double a)
{
    a = fmod(a, 2.0 * PI);                 /* (-2pi, 2pi) */
    if (a > PI)        a -= 2.0 * PI;
    else if (a <= -PI) a += 2.0 * PI;
    return a;                              /* (-pi, pi] */
}

/* Move along a constant-curvature arc of length d that turns by dth.
 * The chord points along the midpoint heading; its length is d * sin(h)/h, h = dth/2.
 * (Plain midpoint uses length d: error O(d*dth^2) per step. This is exact.) */
static void advance(Pose *p, double d, double dth)
{
    double h = 0.5 * dth;
    double chord = (fabs(h) < 1e-9) ? d : d * sin(h) / h;
    p->x += chord * cos(p->theta + h);
    p->y += chord * sin(p->theta + h);
    p->theta = wrap_angle(p->theta + dth);
}

void odom_update(Pose *p, int32_t dl_ticks, int32_t dr_ticks, const Robot *r)
{
    double m_per_tick = 2.0 * PI * r->wheel_radius_m / (double)r->ticks_per_rev;
    double dl = dl_ticks * m_per_tick;
    double dr = dr_ticks * m_per_tick;
    advance(p, 0.5 * (dl + dr), (dr - dl) / r->track_width_m);
}

/* ---- Part C ---- */
bool follow_waypoints(Pose *p, const Point *wps, size_t n, const Robot *r,
                      double v, double k_heading, double dt, double reach_tol,
                      double t_max, double *t_done)
{
    if (dt <= 0.0 || (n > 0 && wps == NULL)) return false;
    size_t i = 0;
    for (uint32_t k = 0;; k++) {
        double t = k * dt;                          /* no float accumulation drift */
        while (i < n && hypot(wps[i].x - p->x, wps[i].y - p->y) <= reach_tol)
            i++;                                    /* may skip several at once */
        if (i == n) { *t_done = t; return true; }
        if (t >= t_max) return false;

        double bearing = atan2(wps[i].y - p->y, wps[i].x - p->x);
        double w = k_heading * wrap_angle(bearing - p->theta);   /* shortest way round */
        if (w >  r->max_omega_rad_s) w =  r->max_omega_rad_s;
        if (w < -r->max_omega_rad_s) w = -r->max_omega_rad_s;
        advance(p, v * dt, w * dt);
    }
}

int main(void)
{
    const Robot rb = { 2048, 0.10, 0.50, 2.0 };     /* 1 rev = 2*pi*0.1 = 0.628319 m */
    Pose p;
    double t;

    /* 1. enc_delta, no wrap */
    CHECK(enc_delta(100, 150) == 50);
    CHECK(enc_delta(150, 100) == -50);

    /* 2. enc_delta across the wrap, both directions */
    CHECK(enc_delta(65530, 4) == 10);
    CHECK(enc_delta(3, 65533) == -6);

    /* 3. half-range limit: +32767 is fine, +32769 aliases to -32767 */
    CHECK(enc_delta(0, 32767) == 32767);
    CHECK(enc_delta(0, 32769) == -32767);

    /* 4. straight line: both wheels one revolution */
    p = (Pose){ 0, 0, 0 };
    odom_update(&p, 2048, 2048, &rb);
    CHECK(NEAR(p.x, 0.628319, 1e-6) && NEAR(p.y, 0.0, 1e-12) && NEAR(p.theta, 0.0, 1e-12));

    /* 5. spin in place: x, y unchanged, theta = 2 * 0.314159 / 0.5 = 1.256637 */
    p = (Pose){ 1, 2, 0 };
    odom_update(&p, -1024, 1024, &rb);
    CHECK(NEAR(p.x, 1.0, 1e-12) && NEAR(p.y, 2.0, 1e-12) && NEAR(p.theta, 1.256637, 1e-6));

    /* 6. quarter circle, radius 0.5 m: 1280 small steps of (1, 3) ticks -> (0.5, 0.5, pi/2) */
    p = (Pose){ 0, 0, 0 };
    for (int s = 0; s < 1280; s++) odom_update(&p, 1, 3, &rb);
    CHECK(NEAR(p.x, 0.5, 1e-6) && NEAR(p.y, 0.5, 1e-6) && NEAR(p.theta, PI / 2, 1e-9));

    /* 7. heading wrap: 3.0 + 1.256637 = 4.256637 -> -2.026548 */
    p = (Pose){ 0, 0, 3.0 };
    odom_update(&p, -1024, 1024, &rb);
    CHECK(NEAR(p.theta, -2.026548, 1e-6));

    /* 8. wrap_angle range is (-pi, pi] */
    CHECK(NEAR(wrap_angle(PI), PI, 1e-12) && NEAR(wrap_angle(-PI), PI, 1e-12));
    CHECK(NEAR(wrap_angle(1.5 * PI), -0.5 * PI, 1e-12) && NEAR(wrap_angle(-7.0), -7.0 + 2 * PI, 1e-12));
    CHECK(NEAR(wrap_angle(0.25), 0.25, 1e-15));

    /* 9. encoder wrap feeding odometry: 65000 -> 1512 is +2048 ticks on both wheels */
    p = (Pose){ 0, 0, 0 };
    odom_update(&p, enc_delta(65000, 1512), enc_delta(65000, 1512), &rb);
    CHECK(NEAR(p.x, 0.628319, 1e-6) && NEAR(p.y, 0.0, 1e-12));

    /* 10. square path: 4 waypoints, v = 0.5 m/s, k = 3, dt = 10 ms, tol = 0.1 m -> 16.09 s */
    const Point sq[] = { {2, 0}, {2, 2}, {0, 2}, {0, 0} };
    p = (Pose){ 0, 0, 0 }; t = -1;
    CHECK(follow_waypoints(&p, sq, 4, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(NEAR(t, 16.09, 0.05) && hypot(p.x, p.y) <= 0.1);

    /* 11. zero waypoints: done immediately, pose untouched */
    p = (Pose){ 1, 1, 0.5 }; t = -1;
    CHECK(follow_waypoints(&p, NULL, 0, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(t == 0.0 && p.x == 1.0 && p.y == 1.0 && p.theta == 0.5);

    /* 12. already inside reach_tol of the only waypoint */
    const Point here[] = { {0.05, 0} };
    p = (Pose){ 0, 0, 0 }; t = -1;
    CHECK(follow_waypoints(&p, here, 1, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(t == 0.0 && p.x == 0.0);

    /* 13. timeout: the square needs ~16 s, t_max = 5 s -> false, t_done untouched */
    p = (Pose){ 0, 0, 0 }; t = -1;
    CHECK(!follow_waypoints(&p, sq, 4, &rb, 0.5, 3.0, 0.01, 0.1, 5.0, &t));
    CHECK(t == -1);

    /* 14. heading error crosses +-pi: facing 170 deg, target at bearing -168.7 deg.
     *     Shortest turn is +21.3 deg (left). Turning right the long way takes 5.00 s. */
    const Point behind[] = { {-1.0, -0.2} };
    const double th0 = 170.0 * PI / 180.0;
    p = (Pose){ 0, 0, th0 }; t = -1;
    CHECK(!follow_waypoints(&p, behind, 1, &rb, 0.5, 3.0, 0.01, 0.1, 0.01, &t));  /* one step */
    CHECK(p.theta > th0);                                                       /* turned left */
    p = (Pose){ 0, 0, th0 }; t = -1;
    CHECK(follow_waypoints(&p, behind, 1, &rb, 0.5, 3.0, 0.01, 0.1, 60.0, &t));
    CHECK(NEAR(t, 1.86, 0.05));

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

코드 읽는 포인트

  • (int16_t)(uint16_t)(now - prev): 승격된 int 뺄셈 결과를 16비트로 자르고 부호 있게 해석합니다. uint16_t → int16_t 변환은 범위를 넘으면 C 표준상 implementation-defined지만 모든 2의 보수 컴파일러(gcc/clang/armcc)에서 기대대로 동작합니다. 완전히 이식성 있게 쓰려면 uint16_t u = now - prev; return u < 0x8000u ? (int32_t)u : (int32_t)u - 65536;.
  • advance() 하나를 Part B(엔코더)와 Part C(시뮬레이션)가 공유합니다. 면접에서 "같은 기구학 모델을 센서 쪽과 시뮬레이션 쪽에서 둘 다 쓴다"고 말하면 설계가 깔끔해 보입니다.
  • wrap_angle의 경계: fmod 결과는 (−2π, 2π)이고, > π와 <= −π 비교로 (−π, π]가 됩니다. wrap_angle(-PI) == PI가 테스트 8번입니다.
  • 도달 검사는 while입니다. 웨이포인트 두 개가 겹쳐 있거나 시작 위치가 이미 첫 웨이포인트 위면 한 스텝에 여러 개를 넘깁니다(테스트 12).
  • 시간은 t = k * dt. t += dt를 수천 번 하면 오차가 쌓여서 t >= t_max 판정이 한 스텝 어긋날 수 있습니다.

4.6 복잡도

  • enc_delta, wrap_angle, odom_update: O(1), 메모리 O(1).
  • follow_waypoints: 스텝 수 O(t_max / dt), 스텝마다 O(1)(while의 총 반복은 n 이하). 추가 메모리 O(1).

5. 임베디드 관점으로 말할 것

  • 어디서 읽나 — ISR vs task: 엔코더 카운터는 하드웨어(타이머의 encoder mode, 예: STM32 TIMx)가 세므로 CPU는 일정 주기로 카운터만 읽으면 됩니다. 1 kHz 타이머 ISR에서 두 카운터를 같은 순간에 읽어 delta를 큐에 넣고, 삼각함수가 들어간 odom_update는 task에서 돌리는 구성이 일반적입니다. 두 바퀴를 서로 다른 시각에 읽으면 회전 중 가짜 dθ가 생깁니다.
  • 랩어라운드는 타이머와 같은 규칙: "unsigned로 빼고 signed로 해석". 대신 읽기 주기 × 최고 속도 < 32768 tick을 보장해야 합니다. 이걸 숫자로 말할 수 있으면 좋습니다(4.1).
  • FPU 없는 MCU: pose를 고정소수점(예: x, y는 0.1 mm 단위 int32_t, θ는 2¹⁶ = 한 바퀴인 uint16_t binary angle)으로 두면 각도 wrap이 정수 오버플로로 공짜가 됩니다. sin/cos는 256~1024 엔트리 룩업 테이블. Cortex-M4F 이상이면 float(double 아님)로 충분합니다.
  • 오도메트리의 한계 — 바퀴 미끄러짐: 휠 오도메트리는 위치 오차가 거리에 비례해 쌓이고, 특히 헤딩 오차가 이후 위치 오차를 키웁니다. 오프로드 UGV(Scout의 ATV)는 미끄러짐이 커서 IMU yaw rate(자이로)를 헤딩에 퓨전(complementary filter 또는 EKF)하고, GNSS/비주얼 오도메트리로 위치를 보정합니다. "dθ는 자이로, d는 엔코더"라는 간단한 조합만 말해도 충분히 실무적입니다.
  • Jason 연결점: 면접관 Jason MacDonald는 Charles Machine Works에서 굴착 장비의 semi-autonomous path following을 했습니다. waypoint 추종, 헤딩 오차 wrap, 최소 회전 반경 때문에 생기는 오버슈트(chart2의 0.18 m), 미끄러짐 보정은 그가 직접 겪은 주제일 가능성이 큽니다. 실제 스크린 문제(R1)의 원 운동 업데이트와 이 문제의 exact arc가 같은 식이라는 점도 연결해서 말하면 좋습니다.

6. Follow-up 질문과 답

Follow-up (English)답
The robot drives on gravel and the wheels slip. What do you do?엔코더는 "바퀴가 돈 양"이지 "몸체가 간 양"이 아닙니다. 헤딩은 자이로 yaw rate 적분을 주로 쓰고 엔코더 dθ는 보조로, complementary filter(θ = α(θ + ω_gyro·dt) + (1−α)·θ_odom) 또는 EKF로 합칩니다. 두 바퀴 차이 vs 자이로의 불일치가 크면 slip 감지 플래그를 올리고 그동안 엔코더 가중치를 낮춥니다. 절대 위치는 GNSS/비주얼 오도메트리로 보정합니다.
Euler vs midpoint vs exact arc — how big is the difference?4.2 표 그대로: 반지름 0.5 m 사분원을 1280 스텝으로 나누면 Euler 4.3e-4 m, midpoint 4.4e-8 m, exact 9.3e-15 m. Euler는 스텝당 O(d·dθ), midpoint는 O(d·dθ²). 한 스텝에 큰 회전이 들어오면(루프가 늦게 돈 경우) Euler 0.576 m vs midpoint 0.078 m vs exact 0이라 exact arc가 dt 지터에 가장 강합니다.
Why not pure pursuit instead of a heading P-controller?Pure pursuit는 경로 위 lookahead 점을 향하는 원호의 곡률 κ = 2·sin(α)/L_d을 바로 ω = v·κ로 씁니다. 웨이포인트 사이 선분을 따라가므로 모서리 컷이 부드럽고 경로 이탈이 작습니다. 헤딩 P 제어는 점만 보므로 옆바람/미끄러짐에 cross-track 오차가 남습니다. 실차에서는 pure pursuit나 Stanley(cross-track + heading)가 표준이고, 이 문제의 P 제어는 30분 면접용 최소 버전입니다.
Why must the heading error be wrapped?각도는 원 위의 값이라 170°와 −169°는 21° 차이인데 단순 뺄셈은 −339°를 줍니다. wrap 없이 쓰면 먼 쪽으로 돌아서(테스트 14: 1.86 s → 5.00 s), 좁은 공간에서는 장애물에 부딪힐 수도 있습니다. 오차가 정확히 ±π일 때 좌/우가 매번 바뀌며 떨지 않도록 범위를 (−π, π]처럼 한쪽만 닫는 것도 의미가 있습니다.
The control loop period jitters (9–14 ms). Does your code care?고정 dt를 가정하면 안 됩니다. 매 주기 하드웨어 타이머로 측정한 dt(wrap-safe uint32_t 뺄셈)를 쓰고, 엔코더는 이미 "그 사이 이동량"이라 dt와 무관하게 맞습니다. 다만 속도(d/dt)를 계산하거나 ω를 적용할 때 실제 dt를 써야 하고, 비정상적으로 큰 dt(멈춤, 디버거)는 클램프하거나 그 주기를 버립니다. exact arc는 큰 dt에서도 정확해서 유리합니다.
How would you test this on real hardware?(1) 직선 10 m를 줄자로 재서 m_per_tick(바퀴 반지름) 보정, (2) 제자리 10바퀴를 돌려 track_width 보정, (3) UMBmark처럼 정사각형을 시계/반시계 방향으로 각각 몇 번 돌고 출발점 대비 closing error를 재서 체계 오차(바퀴 지름 차이, 유효 트랙 폭)를 분리합니다. 같은 로그를 이 시뮬레이터에 재생(replay)해서 HIL 회귀 테스트로 씁니다.
What if the counter is 32-bit, or the read can be torn?32비트도 같은 식((int32_t)(now - prev))입니다. 8비트 MCU에서 16비트 카운터를 두 번에 나눠 읽으면 상·하위 바이트 사이에 캐리가 생길 수 있으므로 하드웨어 latch를 쓰거나 "상위 읽기 → 하위 읽기 → 상위 재확인" 루프로 읽습니다.

7. 자주 하는 실수

  • now - prev를 int로 계산하고 16비트로 자르지 않음 → 65530 → 4가 −65526 (테스트 2)
  • 엔코더 delta를 uint16_t/uint32_t로 저장 → 후진이 거대한 양수가 됨
  • Euler(cos(θ)) 적분 → 사분원 테스트(6번)에서 4.3e-4 m 오차로 실패
  • θ를 wrap하지 않음, 또는 [0, 2π)로 wrap → 테스트 7·8번 실패. wrap_angle(-π)를 −π로 둠
  • 헤딩 오차를 wrap하지 않음 → 먼 쪽으로 돌아 감 (테스트 14). 이 문제에서 면접관이 가장 보고 싶어 하는 버그입니다
  • d와 dθ 계산에서 track_width / 2로 나눔 → 회전량이 2배
  • 도달 검사를 if로 한 번만 함 → 이미 웨이포인트 위에 있는 경우나 겹친 웨이포인트에서 한 스텝씩 늦어짐
  • n == 0일 때 wps[0]에 접근 → NULL 역참조 (테스트 11)
  • t += dt 누적으로 시간 비교 → 타임아웃 경계가 한 스텝 어긋남
