T1-3 · Moving Average and Rise-Rate Overheat

IDT1-3
PriorityP0
Patternring buffer + running sum + integer rounding
Time30 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh T1-3 / ./run.sh T1-3 sol

1. Problem

A temperature sensor is noisy, so the firmware smooths it with a moving average of the last WIN samples before deciding anything. Temperatures are int16_t in tenths of a degree Celsius.

  1. Maintain the moving average in O(1) per sample (no re-summing the window). Use the struct below.
  2. While the window is still filling, average over the samples you have (count), not over WIN.
  3. Return the average as an integer, rounded half away from zero (7.5 → 8, -7.5 → -8).
  4. Write ma_overheat(): overheat if the average >= avg_thresh or the rise across the window (newest sample − oldest sample still in the window) >= rise_thresh. An empty window is never overheated.
  5. No malloc, no floating point.
#define WIN 4      /* 8 in production; 4 keeps tests small */
typedef struct { int16_t buf[WIN]; uint8_t idx, count; int32_t sum; } MovAvg;

void    ma_init(MovAvg *m);
int16_t ma_avg(const MovAvg *m);                 /* 0 if empty */
int16_t ma_push(MovAvg *m, int16_t x);           /* returns the new average */
bool    ma_overheat(const MovAvg *m, int16_t avg_thresh, int16_t rise_thresh);

Example

WIN = 4
push:    10   20   30   40   50
returns: 10   15   20   25   35      (last window = 20, 30, 40, 50)

after the 5th push: avg = 35, rise = 50 - 20 = 30
ma_overheat(m, 36, 30) -> true   (rise)
ma_overheat(m, 36, 31) -> false

rounding: push -10, -5  ->  -15/2 = -7.5  ->  -8   (plain C division gives -7)

Constraints

  • WIN <= 255 (fits uint8_t); samples are any int16_t value, including INT16_MIN / INT16_MAX.
  • ma_push must be O(1); memory is the struct only.

Clarifying questions to ask (first 3 minutes)

  1. Before the window is full, do we average over count or over WIN? Do we report anything at all?
  2. How should the average be rounded — truncate, floor, or round to nearest? What about negative temperatures?
  3. Is "rise" newest − oldest in the window, or a slope per second?
  4. What range can samples take? (Decides the type of sum.)
  5. Should the overheat decision wait until the window is full?

3. 힌트 (막힐 때 하나씩)

Hint 1 — O(1)의 비결은 누적합

매번 WIN개를 다시 더하지 말고 sum을 들고 다닙니다. 새 값이 들어오면 나갈 값(가장 오래된 값)을 먼저 빼고, 새 값을 더한 뒤 그 칸에 덮어씁니다. 윈도우가 덜 찼으면 빼지 않고 count++만 합니다.

Hint 2 — idx 하나로 newest와 oldest를 둘 다 찾기

idx는 "다음에 쓸 칸"입니다. 그래서 newest = buf[(idx + WIN - 1) % WIN], oldest = buf[(idx + WIN - count) % WIN]. 꽉 찼으면 oldest는 buf[idx]와 같고, 덜 찼으면 buf[0]입니다. 이 한 식으로 두 경우가 다 됩니다.

Hint 3 — 음수 반올림

C의 /는 0 쪽으로 자릅니다(-15/2 == -7). (sum + cnt/2) / cnt는 양수에서만 맞습니다. 부호로 나눠서 음수는 절댓값으로 반올림한 뒤 부호를 다시 붙이세요: -((-sum + cnt/2) / cnt).

4. 풀이

4.1 핵심 아이디어 — 그림으로 보기

링버퍼 칸 4개, 다음에 쓸 위치 idx, 지금 들어 있는 개수 count, 합 sum 네 가지만 보면 됩니다. 다섯 번째 push에서 처음으로 빼기(evict)가 일어납니다.

4.2 반올림 규칙

평균은 int16_t로 돌려줘야 하니 정수 나눗셈의 반올림 규칙을 정해야 합니다. 여기서는 round half away from zero로 정했습니다. 양수와 음수가 대칭이라 영하 온도에서 평균이 한쪽으로 치우치지 않습니다.

solution.c
/*
 * T1-3  Moving Average + Rise-Rate Overheat
 *
 * Keep the average of the last WIN samples in O(1) per sample, then flag overheat when
 * the average is at or above avg_thresh OR the rise across the window is at or above rise_thresh.
 *
 * Definitions (agreed with the interviewer):
 *   - Ring buffer of WIN int16_t samples + running sum in int32_t (WIN * INT16 range fits easily).
 *   - While the window is still filling, divide by count (number of samples so far), not WIN.
 *   - Average is ROUNDED HALF AWAY FROM ZERO:  15/2 -> 8,  -15/2 -> -8,  5/3 -> 2,  -5/3 -> -2.
 *     (Plain C division truncates toward zero: -15/2 == -7. That is NOT what we want.)
 *   - rise = newest - oldest sample currently in the window (0 with one sample).
 *   - ma_overheat() on an empty window returns false.
 *   - No malloc, no floating point.
 *
 * Reference solution.  Build & run:  ./run.sh T1-3 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

#define WIN 4   /* 8 in the original spec; 4 keeps the tests short */

typedef struct {
    int16_t buf[WIN];
    uint8_t idx;     /* next slot to write (= oldest slot once full) */
    uint8_t count;   /* samples in the window, 0..WIN */
    int32_t sum;     /* sum of the samples in the window */
} MovAvg;

/* round-half-away-from-zero division, den > 0 */
static int32_t div_round(int32_t num, int32_t den)
{
    return num >= 0 ? (num + den / 2) / den
                    : -((-num + den / 2) / den);
}

void ma_init(MovAvg *m)
{
    memset(m, 0, sizeof *m);
}

int16_t ma_avg(const MovAvg *m)
{
    if (m->count == 0) return 0;
    return (int16_t)div_round(m->sum, m->count);   /* rounded mean of int16 values fits int16 */
}

int16_t ma_push(MovAvg *m, int16_t x)
{
    if (m->count == WIN) m->sum -= m->buf[m->idx];   /* evict the oldest */
    else                 m->count++;
    m->buf[m->idx] = x;
    m->sum += x;
    m->idx = (uint8_t)((m->idx + 1) % WIN);
    return ma_avg(m);
}

bool ma_overheat(const MovAvg *m, int16_t avg_thresh, int16_t rise_thresh)
{
    if (m->count == 0) return false;
    int16_t newest = m->buf[(m->idx + WIN - 1) % WIN];
    int16_t oldest = m->buf[(m->idx + WIN - m->count) % WIN];
    int32_t rise = (int32_t)newest - oldest;      /* int32: 32767 - (-32768) overflows int16 */
    return ma_avg(m) >= avg_thresh || rise >= rise_thresh;
}

int main(void)
{
    MovAvg m;
    memset(&m, 0, sizeof m);

    /* 1. basic: filling then sliding (window becomes 20,30,40,50) */
    ma_init(&m);
    CHECK(ma_push(&m, 10) == 10);
    CHECK(ma_push(&m, 20) == 15);
    CHECK(ma_push(&m, 30) == 20);
    CHECK(ma_push(&m, 40) == 25);
    CHECK(ma_push(&m, 50) == 35);
    CHECK(m.sum == 140 && m.count == WIN && m.idx == 1);

    /* 2. positive rounding: half rounds up, below half rounds down */
    ma_init(&m);
    ma_push(&m, 1);
    CHECK(ma_push(&m, 2) == 2);          /* 3/2 = 1.5  -> 2 */
    CHECK(ma_push(&m, 2) == 2);          /* 5/3 = 1.67 -> 2 */
    CHECK(ma_push(&m, 0) == 1);          /* 5/4 = 1.25 -> 1 */

    /* 3. negative rounding is symmetric (C truncation would give -7 and -1) */
    ma_init(&m);
    ma_push(&m, -10);
    CHECK(ma_push(&m, -5) == -8);        /* -15/2 = -7.5  -> -8 */
    ma_init(&m);
    ma_push(&m, -1); ma_push(&m, -2);
    CHECK(ma_push(&m, -2) == -2);        /* -5/3 = -1.67 -> -2 */

    /* 4. int16 extremes: the sum must not overflow */
    ma_init(&m);
    for (int i = 0; i < WIN; i++) ma_push(&m, INT16_MAX);
    CHECK(ma_avg(&m) == INT16_MAX);
    CHECK(ma_push(&m, INT16_MIN) == 16383);   /* (3*32767 - 32768)/4 = 16383.25 */
    for (int i = 0; i < WIN - 1; i++) ma_push(&m, INT16_MIN);
    CHECK(ma_avg(&m) == INT16_MIN);

    /* 5. overheat by average or by rise (window 20,30,40,50: avg 35, rise 30) */
    ma_init(&m);
    CHECK(!ma_overheat(&m, 0, 0));            /* empty window never alarms */
    for (int16_t v = 10; v <= 50; v += 10) ma_push(&m, v);
    CHECK(ma_overheat(&m, 35, 100));          /* avg 35 >= 35 */
    CHECK(!ma_overheat(&m, 36, 31));          /* avg 35 < 36, rise 30 < 31 */
    CHECK(ma_overheat(&m, 36, 30));           /* rise 30 >= 30 */

    /* 6. rise while filling uses the real oldest; a falling window has negative rise */
    ma_init(&m);
    ma_push(&m, 100); ma_push(&m, 130);
    CHECK(ma_overheat(&m, 999, 30) && !ma_overheat(&m, 999, 31));
    ma_init(&m);
    ma_push(&m, 500); ma_push(&m, 400); ma_push(&m, 300);
    CHECK(!ma_overheat(&m, 999, 0));          /* rise = -200 */
    ma_init(&m);
    ma_push(&m, INT16_MIN); ma_push(&m, INT16_MAX);
    CHECK(ma_overheat(&m, INT16_MAX, 30000)); /* rise 65535 needs int32 */

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

코드 읽는 포인트

  • if (count == WIN) sum -= buf[idx]; else count++; — 덮어쓰기 전에 빼야 합니다. 순서를 바꾸면 방금 넣은 값을 뺍니다.
  • sum이 int32_t인 이유: int16_t 8개의 합은 최대 ±262,144라서 int16_t로는 넘칩니다. int32_t면 WIN이 65,536까지 안전합니다.
  • rise도 int32_t로 계산합니다. 32767 - (-32768) = 65535는 int16_t 범위를 넘습니다(테스트 6번 마지막 줄).
  • 반올림된 평균은 항상 윈도우의 최솟값과 최댓값 사이 정수라서 int16_t로 캐스팅해도 안전합니다.
  • % WIN은 WIN이 상수라 컴파일러가 최적화합니다. 2의 거듭제곱이면 & (WIN - 1)과 같습니다.

4.5 복잡도

  • ma_push, ma_avg, ma_overheat 모두 O(1) 시간.
  • 메모리 O(WIN) — WIN=8이면 buf 16바이트 + idx·count 2바이트 + sum 4바이트(패딩 포함 약 24바이트).

5. 임베디드 관점으로 말할 것

  • FPU 없이 정수만: 평균·반올림·상승률 모두 정수 연산입니다. Cortex-M0에는 하드웨어 나눗셈도 없으니, WIN을 2의 거듭제곱으로 잡아 꽉 찬 뒤에는 시프트로 나누는 방법도 말할 수 있습니다(음수 시프트는 floor라 반올림을 따로 처리).
  • 오버플로 범위를 말로 계산하기: "int16 최대 32767 × 8 = 262,136, int32로 충분"이라고 숫자로 말하면 신뢰가 갑니다.
  • 필터 지연: 이동 평균은 WIN/2 샘플 정도 늦게 반응합니다. 그래서 평균은 노이즈에 강한 느린 판정, rise는 급상승을 빨리 잡는 판정으로 둘을 OR로 묶습니다. 이 트레이드오프를 설명하면 좋습니다.
  • 덜 찬 윈도우의 정책: 부팅 직후 샘플 1개로 평균 판정을 할지, count == WIN까지 기다릴지는 안전 요구사항으로 정할 일입니다. 여기서는 바로 판정합니다(과열은 빨리 잡는 쪽이 안전).
  • 스트리밍 감지기와 결합하면 "평균이 N회 연속 임계 이상" 같은 판정이 됩니다 → T1-2. 링버퍼 자체는 T2-1.

6. Follow-up 질문과 답

Follow-up (English)답
WIN is a power of two. Replace the division with a shift.꽉 찬 뒤에는 sum >> 3(WIN=8)이 가능하지만, 음수에서 >>는 floor(−7.5 → −8, −7.25 → −8)이고 구현 정의 동작입니다. 반올림까지 하려면 (sum + 4) >> 3은 양수에서만 맞으니 부호 처리를 똑같이 해야 합니다. 덜 찬 동안은 여전히 count로 나눕니다.
Compare with an exponential moving average.EMA: avg += (x - avg) >> k. 메모리 1워드, 버퍼 없음, 나눗셈 없음. 대신 오래된 값이 완전히 사라지지 않고, 정밀도를 위해 avg를 고정소수점(<< k 스케일)으로 들고 있어야 합니다. 정확한 "최근 N개 평균"이나 "최근 N개 중 가장 오래된 값"이 필요하면 링버퍼가 맞습니다.
Make the rise a rate in 0.1 °C per second.샘플마다 타임스탬프도 링버퍼에 넣고 rise * 1000 / (t_newest - t_oldest)를 계산합니다. 곱셈은 int32_t로, 시간차는 uint32_t 뺄셈(랩 안전), 0으로 나누기 검사. 실제로는 나눗셈 대신 rise * 1000 >= R * dt로 비교하면 더 빠르고 안전합니다.
What if ma_push runs in an ISR and ma_avg in the main loop?sum(32비트)과 count를 따로 읽으면 중간에 끊긴 값을 볼 수 있습니다. 짧게 인터럽트를 막고 복사하거나, ISR이 계산된 평균 하나만 volatile int16_t로 내보내게 합니다.
Running max or median instead of mean?이동 최댓값은 단조 deque로 O(1) 분할상환 → T2-4. 중앙값은 작은 WIN이면 정렬된 배열 삽입, 크면 힙 두 개 → T2-8.

  • 덜 찬 윈도우에서 WIN으로 나눔 → 첫 출력이 10이 아니라 3(10/4 = 2.5 → 반올림), 테스트 1번 실패
