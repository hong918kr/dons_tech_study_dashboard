T1-2 · Streaming Overheat Detector

IDT1-2
PriorityP0
Patternstate machine + hysteresis + consecutive-N counter
Time30 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh T1-2 / ./run.sh T1-2 sol

1. Problem

Temperature samples from one sensor arrive one at a time (for example, from a timer interrupt every 100 ms). Temperatures are in tenths of a degree Celsius (850 means 85.0 °C).

Write a detector with O(1) state that reports events, not levels:

  • While NORMAL: after n_confirm consecutive samples with temp >= high, switch to OVERHEATED and return EV_OVERHEAT on that sample.
  • While OVERHEATED: after n_confirm consecutive samples with temp <= low, switch back to NORMAL and return EV_RECOVERED on that sample.
  • Every other sample returns EV_NONE. A sample that breaks the streak resets the counter. Never report EV_OVERHEAT twice in a row.
  • TEMP_INVALID (INT16_MIN) is a sensor error code: return EV_NONE and reset the counter.
  • det_init must reject low >= high and n_confirm == 0 by returning false; an uninitialized detector never fires.
  • No malloc.
#define TEMP_INVALID INT16_MIN
typedef enum { EV_NONE, EV_OVERHEAT, EV_RECOVERED } Event;
typedef struct { /* you design it */ } Detector;

bool  det_init(Detector *d, int16_t high, int16_t low, uint8_t n_confirm);
Event det_update(Detector *d, int16_t temp_c10);

Example

high = 850, low = 800, n_confirm = 3

index : 0    1    2    3    4    5    6    7    8
temp  : 840  860  870  880  860  820  790  780  770
event : -    -    -    OVH  -    -    -    -    REC

EV_OVERHEAT at index 3 (860, 870, 880 are three in a row >= 850)
EV_RECOVERED at index 8 (790, 780, 770 are three in a row <= 800)

Spikes: 900 700 900 700  ->  no events (the streak never reaches 3)

Constraints

  • 1 <= n_confirm <= 255, low < high.
  • det_update is called from one context only (no locking needed in this version).

Clarifying questions to ask (first 3 minutes)

  1. Is "hot" >= high or > high? Is "recovered" <= low or < low?
  2. Does a sample between low and high while overheated reset the recovery streak, or just not count?
  3. What should a sensor error value do — be skipped, or break the streak?
  4. Should I return an event (edge) or the current state (level)? Can the caller ask for the state too?
  5. Should det_init validate low < high? What happens if it is called with bad values?

3. 힌트 (막힐 때 하나씩)

Hint 1 — 상태에 무엇이 필요한가?

설정값 3개(high, low, n_confirm) + 런타임 상태 2개면 충분합니다: 현재 상태(bool overheated)와 연속 카운터(uint8_t streak). 카운터를 두 개(hot용, cool용) 둘 필요는 없습니다. 지금 상태에서 "반대편으로 가는 조건"만 세면 됩니다.

Hint 2 — 한 줄로 조건 고르기

bool toward = overheated ? (t <= low) : (t >= high); 이 조건이 거짓이면 streak = 0, 참이면 streak++. streak == n_confirm이 되는 순간 상태를 뒤집고 이벤트를 반환하면서 streak = 0으로 되돌립니다.

Hint 3 — 중복 이벤트는 구조상 생기지 않는다

과열 상태에서는 >= high를 아예 세지 않습니다. 그래서 900이 계속 들어와도 toward가 거짓 → EV_NONE만 나옵니다. 상태 머신으로 짜면 "이벤트 중복 금지" 플래그가 따로 필요 없습니다.

4. 풀이

4.1 핵심 아이디어 — 그림으로 보기

임계값이 하나면 85.0 °C 근처에서 값이 흔들릴 때 OVERHEAT/RECOVERED가 계속 번갈아 나옵니다(chattering). 해결책은 두 가지를 겹쳐 쓰는 것입니다.

  • 히스테리시스: 들어갈 때는 high, 나올 때는 low. 그 사이(노란 띠)에서는 상태가 바뀌지 않습니다.
  • 연속 N회 확인: 한 번 튄 값(spike)으로는 상태를 바꾸지 않습니다.

solution.c
/*
 * T1-2  Streaming Overheat Detector (hysteresis + N-sample confirmation)
 *
 * Samples arrive one at a time. Report an event only on the sample that causes it.
 *
 * Definitions (agreed with the interviewer):
 *   - NORMAL -> OVERHEATED after n_confirm CONSECUTIVE samples with temp_c10 >= high.
 *     That sample returns EV_OVERHEAT.
 *   - OVERHEATED -> NORMAL after n_confirm CONSECUTIVE samples with temp_c10 <= low.
 *     That sample returns EV_RECOVERED.
 *   - Any sample that breaks the streak resets the counter. Every other sample returns EV_NONE
 *     (no duplicate EV_OVERHEAT while already overheated).
 *   - TEMP_INVALID (INT16_MIN) is a sensor error: it returns EV_NONE and resets the counter.
 *   - det_init returns false (and leaves the detector unusable) if low >= high or n_confirm == 0.
 *   - O(1) state, no malloc.
 *
 * Reference solution.  Build & run:  ./run.sh T1-2 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

#define TEMP_INVALID INT16_MIN   /* sensor error code */

typedef enum { EV_NONE, EV_OVERHEAT, EV_RECOVERED } Event;

typedef struct {
    int16_t high, low;      /* enter / exit thresholds, low < high */
    uint8_t n_confirm;      /* consecutive samples needed for a transition */
    uint8_t streak;         /* consecutive samples toward the NEXT transition */
    bool    overheated;     /* current state */
    bool    valid;          /* init succeeded */
} Detector;

bool det_init(Detector *d, int16_t high, int16_t low, uint8_t n_confirm)
{
    memset(d, 0, sizeof *d);
    if (low >= high || n_confirm == 0) return false;   /* valid stays false */
    d->high = high;
    d->low = low;
    d->n_confirm = n_confirm;
    d->valid = true;
    return true;
}

Event det_update(Detector *d, int16_t temp_c10)
{
    if (!d->valid) return EV_NONE;
    if (temp_c10 == TEMP_INVALID) { d->streak = 0; return EV_NONE; }

    /* the condition that moves us toward the other state */
    bool toward = d->overheated ? (temp_c10 <= d->low) : (temp_c10 >= d->high);
    if (!toward) { d->streak = 0; return EV_NONE; }

    if (++d->streak < d->n_confirm) return EV_NONE;

    d->streak = 0;                         /* transition: start counting fresh */
    d->overheated = !d->overheated;
    return d->overheated ? EV_OVERHEAT : EV_RECOVERED;
}

/* test helper: feed n samples, record every event */
static void feed(Detector *d, const int16_t *x, size_t n, Event *ev)
{
    for (size_t i = 0; i < n; i++) ev[i] = det_update(d, x[i]);
}

int main(void)
{
    Detector d;
    Event ev[16];

    /* 1. basic: overheat confirmed at index 3, recovery confirmed at index 8 */
    const int16_t a[] = { 840, 860, 870, 880, 860, 820, 790, 780, 770 };
    CHECK(det_init(&d, 850, 800, 3));
    feed(&d, a, 9, ev);
    for (size_t i = 0; i < 9; i++)
        CHECK(ev[i] == (i == 3 ? EV_OVERHEAT : i == 8 ? EV_RECOVERED : EV_NONE));

    /* 2. spikes never reach 3 in a row -> no events */
    const int16_t b[] = { 900, 700, 900, 700 };
    det_init(&d, 850, 800, 3);
    feed(&d, b, 4, ev);
    CHECK(ev[0] == EV_NONE && ev[1] == EV_NONE && ev[2] == EV_NONE && ev[3] == EV_NONE);

    /* 3. stays hot: exactly one EV_OVERHEAT, no duplicates */
    const int16_t c[] = { 900, 900, 900, 900, 900, 900, 900 };
    det_init(&d, 850, 800, 3);
    feed(&d, c, 7, ev);
    int n_over = 0;
    for (size_t i = 0; i < 7; i++) n_over += (ev[i] == EV_OVERHEAT);
    CHECK(n_over == 1 && ev[2] == EV_OVERHEAT);

    /* 4. hysteresis band: 820 (between low and high) resets the recovery streak */
    const int16_t e[] = { 900, 900, 900, 790, 790, 820, 790, 790, 790 };
    det_init(&d, 850, 800, 3);
    feed(&d, e, 9, ev);

    det_init(&d, 850, 800, 3);

코드 읽는 포인트

  • toward 한 줄이 상태별 분기를 대신합니다. 상태가 3개 이상(경고/위험/셧다운)으로 늘면 switch (state)로 바꾸면 됩니다.
  • ++d->streak < d->n_confirm: streak은 n_confirm에 닿는 순간 0으로 돌아가므로 uint8_t가 넘칠 일이 없습니다(최대 255).
  • valid 플래그: det_init이 실패한 감지기는 아무 이벤트도 내지 않습니다. "잘못된 설정으로 조용히 오동작"보다 안전합니다. memset으로 먼저 0을 채워서 실패해도 상태가 정의됩니다.
  • 원래 문제 시그니처는 void det_init이었는데, 검증 결과를 알리려고 bool로 바꿨습니다. 면접에서도 "init이 bool을 돌려줘도 될까요?"라고 물어보면 좋습니다.

4.5 복잡도

  • det_update 한 번에 O(1) 시간.
  • 상태 O(1) — 구조체 8바이트(int16_t 2개 + uint8_t 2개 + bool 2개). 센서가 16개면 128바이트 → T1-4.

5. 임베디드 관점으로 말할 것

  • ISR에서 부를 수 있는 크기: 분기 몇 개와 증가 하나뿐이고 블로킹·나눗셈·malloc이 없습니다. 다만 이벤트 처리(로그, 팬 제어, 셧다운)는 ISR 밖에서 하도록 플래그나 큐로 넘깁니다.
  • Edge vs level: 이벤트(edge)를 돌려주면 호출자는 "켜기/끄기"를 한 번만 하면 됩니다. 현재 상태(level)가 필요하면 det_is_overheated() 접근자를 따로 둡니다.
  • 히스테리시스 + 디바운스는 펌웨어 기본기: 버튼 디바운스, 배터리 저전압 컷오프, 팬 on/off 모두 같은 패턴입니다 → T2-7.
  • 센서 에러를 0 °C로 취급하지 않기: INT16_MIN 같은 sentinel을 정해서 걸러야 합니다. 그렇지 않으면 I2C가 끊긴 순간 "급격히 냉각"으로 보여 RECOVERED가 잘못 나갈 수 있습니다. 여기서는 streak을 리셋해서 "확인되지 않은 연속"을 끊었습니다.
  • 실패하면 안전한 쪽으로: 에러가 오래 지속되면 과열로 간주할지(fail-safe) 따로 정책이 필요합니다 → T1-6.

6. Follow-up 질문과 답

Follow-up (English)답
Use time instead of a sample count: overheat after 3 s above high.streak 대신 uint32_t since_ms를 저장합니다. 조건이 처음 참이 될 때 시각을 기록하고, (uint32_t)(now - since_ms) >= hold_ms로 판정합니다. 뺄셈 비교라 tick 랩어라운드에도 안전합니다. 샘플 간격이 들쭉날쭉해도 맞습니다.
Add warning / critical / shutdown levels.enum Level과 레벨별 {enter, exit} 임계값 테이블을 두고, 한 단계씩 올라가고 내려가는 상태 머신으로 만듭니다. 각 전이는 같은 streak 로직을 씁니다. 셧다운은 보통 래치(자동 복귀 없음)로 합니다.
Call a callback instead of returning an event.det_init에 void (*cb)(void *ctx, Event e)와 ctx를 받습니다. ISR 문맥이면 콜백 안에서 무거운 일을 하지 말라고 문서화합니다.
What if det_update is called from an ISR and det_is_overheated() from the main loop?overheated는 bool 한 바이트라 읽기 자체는 원자적이지만, 컴파일러 캐싱을 막으려면 volatile 또는 C11 atomic_bool이 필요합니다. 여러 필드를 함께 읽으면 인터럽트를 잠깐 막습니다.
What happens with n_confirm = 255 at 1 kHz?255 ms 지연입니다. 확인 횟수는 "반응 속도 vs 오탐"의 트레이드오프라서 샘플링 주기와 함께 정해야 합니다.

7. 자주 하는 실수

  • 전이할 때 streak = 0을 안 함 → 과열 직후 회복 카운트가 이전 값에서 시작해서 너무 빨리 RECOVERED
  • 과열 상태에서도 >= high를 세서 EV_OVERHEAT를 반복 반환 → 테스트 3번 실패
  • 띠 안의 값(820)이 회복 streak을 리셋하지 않음 → 테스트 4번에서 index 6에 일찍 회복
