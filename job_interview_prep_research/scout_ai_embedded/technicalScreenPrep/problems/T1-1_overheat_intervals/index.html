T1-1 · Overheat Intervals

IDT1-1
PriorityP0
Patternsingle pass + open/close interval
Time30 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh T1-1 / ./run.sh T1-1 sol

1. Problem

You are given temperature samples from one sensor, sorted by time. Each sample has a timestamp in milliseconds and a temperature in tenths of a degree Celsius (815 means 81.5 °C).

Return every overheat interval: a maximal run of consecutive samples whose temperature is at or above thresh, lasting at least min_ms.

  • An interval starts at the first hot sample of a run and ends at the last hot sample of that run.
  • Duration is end_ms - start_ms. Keep the interval only if duration >= min_ms.
  • Write at most out_cap intervals into out, but always return the total number found, so the caller can detect truncation. out may be NULL when out_cap == 0.
  • Do not use malloc. Target O(n) time and O(1) extra memory.
typedef struct { uint32_t t_ms; int16_t temp_c10; } Sample;   /* temp in 0.1 degC */
typedef struct { uint32_t start_ms, end_ms; } Interval;

size_t find_overheat(const Sample *s, size_t n, int16_t thresh, uint32_t min_ms,
                     Interval *out, size_t out_cap);

Example

thresh = 800, min_ms = 1000
samples = (0,750) (500,810) (1000,820) (1500,830) (2000,790) (2500,850) (3000,700)

output  = 1 interval: {500, 1500}
          (the run at 2500 lasts 0 ms, so it is dropped)

Constraints

  • 0 <= n <= 100000, timestamps strictly increasing, no wraparound (for this version).
  • temp_c10 is any int16_t value.

Clarifying questions to ask (first 3 minutes)

  1. Is "hot" >= thresh or > thresh?
  2. Where does an interval end — at the last hot sample, or at the first cool sample after it?
  3. Should a single hot sample count when min_ms == 0?
  4. What should happen if more intervals are found than fit in out?
  5. Could timestamps go backwards or wrap around?

3. 힌트 (막힐 때 하나씩)

Hint 1 — 무엇을 기억해야 하나?

배열 전체를 다시 볼 필요가 없습니다. 한 번 순회하면서 "지금 구간이 열려 있는가(in_hot)", 구간 시작 시각(start), 마지막 과열 샘플 시각(last_hot) 세 개만 들고 다니면 됩니다.

Hint 2 — 구간이 닫히는 순간은 두 번
  1. 과열 중에 정상 샘플을 만났을 때
  2. 배열이 끝났는데 아직 과열 중일 때 ← 가장 많이 빠뜨리는 케이스
Hint 3 — out_cap 처리

if (cnt < out_cap) out[cnt] = …; cnt++; 이 두 줄 패턴이면 버퍼가 작아도 넘치지 않고, 반환값은 항상 전체 개수입니다. out == NULL && out_cap == 0도 자동으로 안전합니다.

4. 풀이

4.1 핵심 아이디어 — 그림으로 보기

예제 입력을 그래프로 그리면 이렇습니다. 빨간 점(≥ 800)이 연속으로 이어진 묶음이 "후보 구간"이고, 그중 길이가 min_ms 이상인 것만 남깁니다.

정의가 답을 바꾼다는 게 이 문제의 함정입니다. 끝을 "첫 정상 샘플"로 정의하면 같은 입력에서 {500, 2000}(1500 ms)과 {2500, 3000}(500 ms → 탈락)이 나옵니다. 그래서 질문 2번을 꼭 먼저 해야 합니다. 면접관은 이 질문을 하는지를 봅니다.

4.2 상태 머신

코드는 두 상태(COOL, HOT)를 오가는 작은 상태 머신입니다. 상태를 bool in_hot 하나로 표현합니다.

4.4 정답 코드

💡 정답 코드 펼치기 (30분 풀어 본 다음에)
solution.c
/*
 * T1-1  Overheat Intervals
 *
 * You are given temperature samples sorted by time. Return every interval in which
 * the temperature stayed at or above `thresh` for at least `min_ms`.
 *
 * Definitions (agreed with the interviewer):
 *   - A sample is HOT when temp_c10 >= thresh.
 *   - An interval starts at the first HOT sample of a run and ends at the LAST HOT
 *     sample of that run (not at the first cool sample).
 *   - Duration = end_ms - start_ms. Keep the interval only if duration >= min_ms.
 *   - Write at most out_cap intervals into out, but ALWAYS return the total number found
 *     (so the caller can detect truncation). out may be NULL when out_cap == 0.
 *   - No malloc. O(n) time, O(1) extra memory.
 *
 * Reference solution.  Build & run:  ./run.sh T1-1 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

typedef struct { uint32_t t_ms; int16_t temp_c10; } Sample;   /* temp in 0.1 degC */
typedef struct { uint32_t start_ms, end_ms; } Interval;

size_t find_overheat(const Sample *s, size_t n, int16_t thresh, uint32_t min_ms,
                     Interval *out, size_t out_cap)
{
    size_t cnt = 0;
    bool in_hot = false;              /* is an interval currently open? */
    uint32_t start = 0, last_hot = 0;

    for (size_t i = 0; i < n; i++) {
        bool hot = s[i].temp_c10 >= thresh;
        if (hot) {
            if (!in_hot) { in_hot = true; start = s[i].t_ms; }   /* open */
            last_hot = s[i].t_ms;                               /* extend */
        } else if (in_hot) {                                    /* close */
            in_hot = false;
            if (last_hot - start >= min_ms) {
                if (cnt < out_cap) out[cnt] = (Interval){ start, last_hot };
                cnt++;
            }
        }
    }
    if (in_hot && last_hot - start >= min_ms) {   /* still hot at the end */
        if (cnt < out_cap) out[cnt] = (Interval){ start, last_hot };
        cnt++;
    }
    return cnt;
}

int main(void)
{
    Interval out[8];

    /* 1. basic: one long run kept, one zero-length run dropped */
    const Sample a[] = { {0,750}, {500,810}, {1000,820}, {1500,830}, {2000,790}, {2500,850}, {3000,700} };
    size_t k = find_overheat(a, 7, 800, 1000, out, 8);
    CHECK(k == 1);
    CHECK(k >= 1 && out[0].start_ms == 500 && out[0].end_ms == 1500);

    /* 2. empty input */
    CHECK(find_overheat(NULL, 0, 800, 0, out, 8) == 0);

    /* 3. hot until the end -> the open interval must be closed */
    const Sample b[] = { {0,900}, {400,900}, {800,900}, {1200,900} };
    k = find_overheat(b, 4, 800, 1000, out, 8);
    CHECK(k == 1 && out[0].start_ms == 0 && out[0].end_ms == 1200);

    /* 4. exactly at the threshold counts as hot */
    const Sample c[] = { {0,800}, {1000,800}, {2000,799} };
    k = find_overheat(c, 3, 800, 1000, out, 8);
    CHECK(k == 1 && out[0].start_ms == 0 && out[0].end_ms == 1000);

    /* 5. min_ms == 0 keeps a single hot sample */
    const Sample d[] = { {0,700}, {10,900}, {20,700}, {30,900} };
    k = find_overheat(d, 4, 800, 0, out, 8);
    CHECK(k == 2 && out[0].start_ms == 10 && out[1].start_ms == 30 && out[1].end_ms == 30);

    /* 6. out_cap smaller than the result: count is still exact, nothing written past cap */
    Interval one[1] = { {0xDEAD, 0xBEEF} };
    k = find_overheat(d, 4, 800, 0, one, 1);
    CHECK(k == 2 && one[0].start_ms == 10);
    CHECK(find_overheat(d, 4, 800, 0, NULL, 0) == 2);

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

코드 읽는 포인트

  • last_hot - start는 uint32_t 뺄셈입니다. 타임스탬프가 증가한다는 전제에서는 항상 0 이상이고, 나중에 랩어라운드를 허용해도 이 형태 그대로 안전합니다(§6 Follow-up).
  • "닫고 내보내기" 코드가 루프 안과 루프 뒤에 두 번 나옵니다. 면접에서는 static void emit(...) 헬퍼로 빼도 되고, 그대로 두되 "루프 뒤에 열린 구간 처리"라고 말로 짚으면 됩니다.
  • (Interval){ start, last_hot }는 C99 compound literal입니다. 낯설면 out[cnt].start_ms = start; out[cnt].end_ms = last_hot;로 써도 됩니다.

4.5 복잡도

  • 시간 O(n) — 각 샘플을 한 번만 봅니다.
  • 추가 메모리 O(1) — 변수 4개(cnt, in_hot, start, last_hot). 출력 버퍼는 호출자가 줍니다.

5. 임베디드 관점으로 말할 것

  • 호출자 버퍼 + 전체 개수 반환: MCU에서는 malloc을 쓰지 않습니다. 결과 크기를 모르면 "쓸 수 있는 만큼 쓰고, 필요한 개수를 돌려준다"가 표준 패턴입니다(snprintf와 같은 규칙).
  • 정수 온도: 0.1 °C 단위 int16_t라 FPU가 없어도 비교만으로 끝납니다. 범위는 ±3276.7 °C로 충분합니다.
  • 스트리밍으로 바꾸기 쉬움: 상태가 4개 변수뿐이라, 같은 로직을 update(sample) 함수로 바꾸면 ISR이 채운 링버퍼에서 샘플을 하나씩 꺼내 처리할 수 있습니다 → T1-2로 이어집니다.

6. Follow-up 질문과 답

Follow-up (English)답
What if timestamps are uint32_t ticks that can wrap around?비교를 last_hot - start >= min_ms처럼 뺄셈 결과로만 하면 랩어라운드에도 맞습니다. end > start + min_ms 같은 덧셈 비교는 틀립니다.
What if two samples are far apart (a dropout)?max_gap_ms를 받아서, 이전 샘플과 간격이 그보다 크면 열린 구간을 강제로 닫습니다. 센서가 죽은 동안을 과열로 쳐 주면 안 되기 때문입니다.
Make it streaming.상태 4개를 구조체에 넣고 update()로 샘플 하나씩 처리, 구간이 닫힐 때 이벤트를 반환 → T1-2.
Readings flicker around the threshold.높은 임계값으로 시작, 낮은 임계값으로 회복하는 히스테리시스, 또는 연속 N회 확인 → T1-2.
What is the complexity? Can it be better?O(n)/O(1). 모든 샘플을 한 번은 봐야 하므로 이보다 나을 수 없습니다.

7. 자주 하는 실수

  • 루프가 끝난 뒤 열린 구간을 닫지 않음 → "끝까지 과열" 테스트(3번) 실패
  • >와 >= 혼동 → 테스트 4번 실패
  • out_cap을 넘어서 씀(버퍼 오버런) 또는 out_cap에서 멈추고 개수도 멈춤 → 테스트 6번 실패
  • 구간 길이를 샘플 개수로 셈 → 샘플 간격이 일정하지 않으면 틀림
