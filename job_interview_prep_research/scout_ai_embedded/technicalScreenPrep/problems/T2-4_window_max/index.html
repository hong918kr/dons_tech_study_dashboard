T2-4 · Peak Temperature over the Last W Samples

IDT2-4
PriorityP1
Patternmonotonic deque in a fixed array (LeetCode 239)
Time25 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh T2-4 / ./run.sh T2-4 sol

1. Problem

The motor-driver thermal monitor gets one temperature sample per tick and must report the peak of the last w samples after every sample (the fan controller reacts to the peak, not the average). Rescanning w samples on every tick is too slow at high rates; make each push amortized O(1).

  • wm_init(m, w) with 1 <= w <= W_MAX (16).
  • wm_push(m, temp) adds one sample and returns the max of the last w samples, or of all samples so far if fewer than w have arrived.
  • Temperatures are int16_t in 0.1 °C and may be negative.
  • Fixed memory: the deque lives in a W_MAX-entry array inside the struct. No malloc.
#define W_MAX   16u                       /* power of two */
#define DQ_MASK (W_MAX - 1u)

typedef struct { uint32_t seq; int16_t temp; } Entry;
typedef struct {
    uint32_t w;                           /* window length in samples           */
    uint32_t seq;                         /* sequence number of the NEXT sample */
    uint32_t front, back;                 /* free-running deque indices         */
    Entry dq[W_MAX];
} WinMax;

void    wm_init(WinMax *m, uint32_t w);
int16_t wm_push(WinMax *m, int16_t temp);

Example

w = 3
push:   810  790  830  820  800  780  850
return: 810  810  830  830  830  820  850

Constraints

  • Up to millions of pushes: seq will wrap past UINT32_MAX.
  • 1 <= w <= W_MAX.

Clarifying questions to ask (first 3 minutes)

  1. Is the window "last w samples" or "last W milliseconds"? (Time-based windows need timestamps in the deque.)
  2. What should the first w - 1 calls return — the max so far, or nothing?
  3. Is w fixed at init, and what is its upper bound (so I can size a static array)?
  4. Ties: does it matter which equal sample is kept?
  5. Is O(w) per sample actually too slow here? (If w = 8 at 10 Hz, brute force is fine — say so.)

static int16_t brute_max(const int16_t *x, size_t i, uint32_t w)
{
    size_t lo = (i + 1 >= w) ? i + 1 - w : 0;
    int16_t m = x[lo];
    for (size_t j = lo + 1; j <= i; j++) if (x[j] > m) m = x[j];

{
    WinMax m = {0};

    /* 1. basic: w = 3 */

    CHECK(ok);

    wm_init(&m, 2);

    CHECK(wm_push(&m, -350) == -200);
    CHECK(wm_push(&m, -400) == -350);

    for (int i = 0; i < 2000; i++) { r = r * 1103515245u + 12345u; x[i] = (int16_t)((r >> 16) % 600) - 100; }
    for (uint32_t w = 1; w <= W_MAX; w += 5) {
        wm_init(&m, w);
        ok = 1;
        for (size_t i = 0; i < 2000; i++) ok &= wm_push(&m, x[i]) == brute_max(x, i, w);
        CHECK(ok);
    }

    /* 6. sequence counter wraps past UINT32_MAX */
    wm_init(&m, 3);
    m.seq = UINT32_MAX - 1u;
    ok = 1;
    for (int i = 0; i < 7; i++) ok &= wm_push(&m, a[i]) == want[i];

3. 힌트 (막힐 때 하나씩)

Hint 1 — 다시는 최대가 될 수 없는 샘플

새 샘플 x가 들어왔을 때, 그보다 먼저 들어왔고 값이 x 이하인 샘플은 앞으로 영원히 최대가 될 수 없습니다(x보다 먼저 창을 떠나니까). 그런 샘플은 지금 버려도 됩니다.

Hint 2 — 무엇을 저장하나

남은 샘플들은 앞(front)에서 뒤(back)로 값이 엄격하게 감소합니다. 그래서 최대는 항상 front입니다. 값과 함께 순번(seq)을 저장해야 front가 창 밖으로 나갔는지 판단할 수 있습니다.

Hint 3 — 순서: 만료 → 뒤에서 pop → push

push 전에 front를 먼저 만료시키면 deque 크기가 항상 w 이하라서 W_MAX 배열이 넘치지 않습니다. 만료 조건은 wrap-safe 뺄셈 seq - front.seq >= w.

4. 풀이

4.1 핵심 아이디어 — deque 변화 보기

예제(w = 3)를 한 단계씩 따라가면 deque에는 "앞으로 최대가 될 가능성이 있는 샘플"만 남습니다. 빨간 상자(front)가 답입니다.

4.2 신호로 보기

같은 데이터를 시간축에 그리면, 출력(빨간 점선)은 창 안의 가장 높은 점을 따라가는 계단입니다.

4.3 손으로 따라가기 (trace)

front, back은 free-running 인덱스입니다(size = back - front). 표의 값은 wm_push 직후입니다.

/*
 * T2-4  Peak Temperature over the Last W Samples   (LeetCode 239, streaming)
 *
 * The motor-driver thermal monitor gets one temperature sample per tick and must report
 * the PEAK of the last W samples after every sample (the fan controller reacts to the
 * peak, not the average). Brute force rescans W samples per tick; do better.
 *
 * Definitions (agreed with the interviewer):
 *   - wm_init(m, w) with 1 <= w <= W_MAX.
 *   - wm_push(m, temp) adds one sample and returns the max of the last w samples
 *     (or of all samples so far, if fewer than w have arrived).
 *   - Temperatures are int16_t in 0.1 degC (may be negative).
 *   - Fixed memory: the deque lives in a W_MAX-entry array inside the struct. No malloc.
 *   - Amortized O(1) per push.
 *
 * Reference solution.  Build & run:  ./run.sh T2-4 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

#define W_MAX  16u                        /* power of two: deque index uses a mask */
#define DQ_MASK (W_MAX - 1u)

typedef struct { uint32_t seq; int16_t temp; } Entry;

typedef struct {
    uint32_t w;                           /* window length in samples         */
    uint32_t seq;                         /* sequence number of the NEXT sample */
    uint32_t front, back;                 /* free-running deque indices; size = back - front */
    Entry dq[W_MAX];                      /* temps strictly decreasing front -> back */
} WinMax;

void wm_init(WinMax *m, uint32_t w)
{
    memset(m, 0, sizeof *m);
    m->w = w;
}

int16_t wm_push(WinMax *m, int16_t temp)
{
    /* 1) expire the front if it is about to slide out (seq - front.seq >= w) */
    if (m->back != m->front && m->seq - m->dq[m->front & DQ_MASK].seq >= m->w)
        m->front++;

    /* 2) drop smaller-or-equal samples from the back: they can never be the max again */
    while (m->back != m->front && m->dq[(m->back - 1u) & DQ_MASK].temp <= temp)
        m->back--;
    m->dq[m->back++ & DQ_MASK] = (Entry){ m->seq, temp };   /* size <= w <= W_MAX */
    m->seq++;

    return m->dq[m->front & DQ_MASK].temp;   /* 3) front is the max */
}

/* ---- test helper: brute force over the same window ---- */
static int16_t brute_max(const int16_t *x, size_t i, uint32_t w)
{
    size_t lo = (i + 1 >= w) ? i + 1 - w : 0;
    int16_t m = x[lo];
    for (size_t j = lo + 1; j <= i; j++) if (x[j] > m) m = x[j];
    return m;
}

int main(void)

    CHECK(ok);

    /* 2. w = 1: the max is just the current sample */

코드 읽는 포인트

  • <=로 pop하므로 같은 값이면 새 샘플이 남습니다. 새 샘플이 더 오래 창에 있으니 deque가 더 작아집니다(테스트 4번의 −200 두 개).
  • 만료는 한 번의 if로 충분합니다. 매 push마다 seq가 1씩 늘어서, 한 번에 창을 벗어나는 샘플은 많아야 하나이기 때문입니다.
  • 만료를 push 뒤에 하면 순간적으로 deque에 w + 1개가 들어가서, w == W_MAX일 때 front 슬롯을 덮어씁니다. 테스트 3번(w = 16, 계속 감소하는 입력이라 deque가 꽉 참)이 이 버그를 잡습니다. 무작위 입력(테스트 5번)으로는 16개 연속 감소가 거의 안 나와서 못 잡습니다.
  • 테스트 6번은 seq를 UINT32_MAX - 1에서 시작합니다. seq - front.seq 뺄셈이라 랩어라운드에도 맞습니다.

4.5 복잡도

  • 시간: 각 샘플은 deque에 한 번 들어가고 많아야 한 번 나오므로 amortized O(1). 단, 한 번의 push가 최악 O(w)일 수 있습니다(i = 6처럼).
  • 메모리: W_MAX × 8 B + 16 B. 원본 샘플은 저장하지 않습니다.

5. 임베디드 관점으로 말할 것

  • worst-case vs amortized: 하드 실시간 루프에서는 "평균 O(1)"보다 "최악 몇 사이클"이 중요합니다. 이 구조의 최악은 pop w번이고 w <= 16이라 상한이 명확하다고 말합니다.
  • 작은 w면 brute force: w = 8이면 8개 비교가 deque 관리보다 빠르고 코드도 짧습니다. 면접관에게 "w가 크거나 샘플 속도가 높을 때 이 구조가 이득"이라고 트레이드오프를 말하면 좋습니다.
  • 고정 배열 + 마스크: T2-1 링버퍼와 같은 free-running 인덱스 기법입니다. 이 deque는 양쪽 끝에서 빠지므로 back--도 씁니다.
  • ISR 안에서 호출: 샘플 ISR에서 바로 wm_push를 부르면, 최대값을 읽는 task와 경쟁하지 않도록 반환값만 volatile int16_t peak에 저장합니다(16비트 store는 원자적).

6. Follow-up 질문과 답

Follow-up (English)답
Window is the last W_ms milliseconds, not w samples.Entry에 t_ms를 저장하고 만료 조건을 now - front.t_ms >= W_ms로 바꿉니다. 이때 한 번에 여러 개가 만료될 수 있으니 if를 while로 바꾸고, 샘플 속도 상한으로 배열 크기를 정합니다.
Also report the minimum.오름차순 deque를 하나 더 둡니다(pop 조건 >=). 메모리 2배, 로직 동일.
Report the average instead.합계 하나와 링버퍼로 O(1): 새 값 더하고 나가는 값 빼기. int32_t 합계(T1-3).
Why not a max-heap?힙은 O(log w)이고, 창을 떠난 원소를 지우려면 lazy deletion이 필요합니다. deque가 더 단순하고 빠릅니다.
Batch version: given an array, output all window maxima.같은 구조로 i >= w - 1부터 출력하면 LeetCode 239 그대로, 출력 n - w + 1개.

7. 자주 하는 실수

  • 값만 저장하고 인덱스(seq)를 안 저장 → 만료 판단 불가
  • 만료를 push 뒤에 처리 → w == W_MAX에서 front 슬롯을 덮어씀(테스트 3번)
  • pop 조건을 <로 써서 같은 값이 쌓임 → 결과는 맞지만 deque가 커지고 최악 시간이 늘어남. <=를 쓰는 이유를 말할 것
  • 처음 w - 1개 샘플에서 아무것도 반환하지 않음 → 테스트 1번 실패. 정의를 물어볼 것
  • front/back을 uint8_t로 두고 마스크 없이 인덱싱 → 범위 밖 접근
