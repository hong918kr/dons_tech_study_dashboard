T2-2 · UART Temperature Packet Parser

IDT2-2
PriorityP0
Patternbyte-wise state machine + resync
Time30 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh T2-2 / ./run.sh T2-2 sol

1. Problem

A temperature board streams packets to the robot's main MCU over UART. The UART RX interrupt hands you one byte at a time. Write a parser that emits every complete, valid packet and silently resynchronizes after line noise or a corrupted packet.

Frame format:

[0xAA SYNC] [LEN] [PAYLOAD: LEN bytes] [CHK]
  • 1 <= LEN <= MAX_PAYLOAD (16). Any other LEN is a bad frame.
  • CHK = XOR of LEN and every payload byte (SYNC is not included).
  • A temperature payload is sensor_id followed by int16 temperatures (0.1 °C, little-endian). The parser does not interpret it; it emits the raw payload.
  • On a bad LEN or bad CHK: increment bad_frames and go back to hunting for SYNC. If the bad LEN byte is itself 0xAA, treat it as a new SYNC.
  • 0xAA may legally appear inside the payload or as the CHK byte (framing is length-based).
  • parser_feed returns true exactly when the byte completes a valid packet, and only then writes *out.
#define SYNC_BYTE   0xAAu
#define MAX_PAYLOAD 16u

typedef enum { ST_SYNC, ST_LEN, ST_PAYLOAD, ST_CHK } ParseState;
typedef struct { uint8_t len; uint8_t data[MAX_PAYLOAD]; } Packet;
typedef struct {
    ParseState st;
    uint8_t len, idx, chk;
    uint8_t data[MAX_PAYLOAD];
    uint32_t bad_frames;
} Parser;

void parser_init(Parser *p);
bool parser_feed(Parser *p, uint8_t b, Packet *out);

Example

bytes:  00 13 | AA 03 01 2C 03 2D | AA 03 01 2C 03 00 | AA 05 02 2C 03 38 03 13
          noise   good: id 1, 812     CHK 00 (want 2D)    good: id 2, 812, 824

output: 2 packets  {len 3: 01 2C 03}  {len 5: 02 2C 03 38 03}
        bad_frames = 1

Constraints

  • Bytes arrive one at a time and a packet may be split across any number of calls.
  • No malloc. Parser state must fit in a small struct.
  • O(1) work per byte.

Clarifying questions to ask (first 3 minutes)

  1. Which checksum — XOR, 8-bit sum, or CRC-8/16? Does it cover LEN? SYNC?
  2. What is the maximum payload length? Is LEN = 0 valid?
  3. Can 0xAA appear inside the payload? (If yes, length-based framing; no byte stuffing?)
  4. After a bad checksum, resume from the next byte or rescan the bytes of the bad frame?
  5. Is there an inter-byte timeout that should reset the parser?

static size_t feed_all(Parser *p, const uint8_t *s, size_t n, Packet *out, size_t cap)
{
    size_t got = 0;
    for (size_t i = 0; i < n; i++) {
        Packet pk;
        if (parser_feed(p, s[i], &pk)) { if (got < cap) out[got] = pk; got++; }
    }
    return got;
}
static int16_t temp_at(const Packet *pk, size_t k)     /* k-th temp after sensor_id */
{
    return (int16_t)(pk->data[1 + 2 * k] | (pk->data[2 + 2 * k] << 8));
}

int main(void)
{
    Parser p = {0};
    Packet out[4];
    size_t k;

    /* 1. basic: noise, good packet, bad-CHK packet, good packet with two temps */
    const uint8_t s1[] = { 0x00, 0x13,
                           0xAA, 0x03, 0x01, 0x2C, 0x03, 0x2D,               /* id 1: 812      */
                           0xAA, 0x03, 0x01, 0x2C, 0x03, 0x00,               /* bad CHK        */
                           0xAA, 0x05, 0x02, 0x2C, 0x03, 0x38, 0x03, 0x13 }; /* id 2: 812, 824 */
    parser_init(&p);
    k = feed_all(&p, s1, sizeof s1, out, 4);
    CHECK(k == 2 && p.bad_frames == 1);
    CHECK(k >= 1 && out[0].len == 3 && out[0].data[0] == 1 && temp_at(&out[0], 0) == 812);
    CHECK(k >= 2 && out[1].len == 5 && out[1].data[0] == 2 && temp_at(&out[1], 1) == 824);

    /* 2. packet split across two UART chunks: state survives between calls */
    parser_init(&p);
    k  = feed_all(&p, s1 + 2, 3, out, 4);           /* AA 03 01          */
    CHECK(k == 0);
    k += feed_all(&p, s1 + 5, 3, out, 4);           /* 2C 03 2D          */
    CHECK(k == 1 && temp_at(&out[0], 0) == 812);

    /* 3. bad LEN (0 and 17) then double SYNC: AA AA must still lock on */
    const uint8_t s3[] = { 0xAA, 0x00, 0xAA, 0x11, 0xAA, 0xAA, 0x03, 0x01, 0x2C, 0x03, 0x2D };
    parser_init(&p);
    k = feed_all(&p, s3, sizeof s3, out, 4);
    CHECK(k == 1 && p.bad_frames == 3 && temp_at(&out[0], 0) == 812);

    /* 4. 0xAA inside the payload and as CHK is data, not a SYNC */
    const uint8_t s4[] = { 0xAA, 0x03, 0xAA, 0x01, 0x02, 0xAA };   /* CHK = 03^AA^01^02 = AA */
    parser_init(&p);
    k = feed_all(&p, s4, sizeof s4, out, 4);
    CHECK(k == 1 && out[0].data[0] == 0xAA && temp_at(&out[0], 0) == 513);

    /* 5. maximum length (16) is accepted */
    uint8_t s5[2 + 16 + 1] = { 0xAA, 16 };
    uint8_t chk = 16;
    for (int i = 0; i < 16; i++) { s5[2 + i] = (uint8_t)(i * 7); chk ^= s5[2 + i]; }
    s5[18] = chk;
    parser_init(&p);
    k = feed_all(&p, s5, sizeof s5, out, 4);
    CHECK(k == 1 && out[0].len == 16 && out[0].data[15] == 105 && p.bad_frames == 0);

    /* 6. no output and no state change on pure noise or empty input */
    const uint8_t s6[] = { 0x00, 0x55, 0xFF, 0x13 };
    parser_init(&p);
    CHECK(feed_all(&p, s6, sizeof s6, out, 4) == 0 && p.bad_frames == 0 && p.st == ST_SYNC);
    CHECK(feed_all(&p, NULL, 0, out, 4) == 0);

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

3. 힌트 (막힐 때 하나씩)

Hint 1 — 상태 4개

"지금 무엇을 기다리는가"가 곧 상태입니다: SYNC 바이트 → LEN 바이트 → payload 바이트들 → CHK 바이트. enum + switch 하나로 끝납니다. 버퍼 전체를 다시 훑는 코드는 필요 없습니다.

Hint 2 — 체크섬은 받으면서 누적

LEN을 받을 때 chk = LEN, payload 바이트마다 chk ^= b. CHK 바이트가 오면 비교만 하면 됩니다. 나중에 다시 계산하지 않습니다.

Hint 3 — 실패하면 어디로?

나쁜 LEN, 나쁜 CHK 모두 bad_frames++ 후 SYNC 상태로 돌아갑니다. 예외 하나: LEN 자리에 온 바이트가 0xAA면 그게 진짜 SYNC일 수 있으니 LEN 상태에 머뭅니다(테스트 3번).

4. 풀이

4.1 핵심 아이디어 — 상태 머신

ISR이 주는 바이트 하나마다 switch가 한 번 돌고, 각 상태는 그 바이트를 어떻게 쓸지와 다음 상태만 정합니다.

4.2 바이트 스트림에 상태를 겹쳐 보기

§1 예제(테스트 1번)의 22바이트를 상태와 함께 그리면 이렇습니다. 13번 바이트 00은 CHK 자리에서 기대값 2D와 달라 프레임 전체가 버려지고, 14번 AA부터 다시 잡습니다.

4.3 손으로 따라가기 (trace)

 * T2-2  UART Temperature Packet Parser
 *
 * A temperature board streams packets to the robot's main MCU over UART. The UART RX
 * interrupt hands you ONE byte at a time. Write a parser that emits each complete,
 * valid packet and silently resynchronizes after noise or corrupted packets.
 *
 * Frame format (agreed with the interviewer):
 *   [0xAA SYNC] [LEN] [PAYLOAD: LEN bytes] [CHK]
 *   - 1 <= LEN <= MAX_PAYLOAD. Any other LEN is a bad frame.
 *   - CHK = XOR of LEN and every payload byte (SYNC is not included).
 *   - Payload of a temperature packet: sensor_id, then int16 temps (0.1 degC) little-endian.
 *     The parser itself does not care: it emits the raw payload.
 *   - Bad LEN or bad CHK: count it in bad_frames and go back to hunting for SYNC.
 *     If the bad LEN byte is itself 0xAA, treat it as a new SYNC.
 *   - 0xAA may appear inside the payload or as the CHK byte (length-based framing).
 *   - parser_feed returns true exactly when the byte completes a valid packet,
 *     and only then writes *out. No malloc.
 *
 * Reference solution.  Build & run:  ./run.sh T2-2 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

#define SYNC_BYTE   0xAAu
#define MAX_PAYLOAD 16u

typedef enum { ST_SYNC, ST_LEN, ST_PAYLOAD, ST_CHK } ParseState;

typedef struct { uint8_t len; uint8_t data[MAX_PAYLOAD]; } Packet;

typedef struct {
    ParseState st;
    uint8_t len, idx, chk;               /* expected length, bytes received, running XOR */
    uint8_t data[MAX_PAYLOAD];
    uint32_t bad_frames;                 /* diagnostics: bad LEN or bad CHK */
} Parser;

void parser_init(Parser *p)
{
    memset(p, 0, sizeof *p);             /* ST_SYNC == 0 */
}

bool parser_feed(Parser *p, uint8_t b, Packet *out)
{
    switch (p->st) {
    case ST_SYNC:
        if (b == SYNC_BYTE) p->st = ST_LEN;
        break;                                       /* anything else: noise, skip */
    case ST_LEN:
        if (b == 0 || b > MAX_PAYLOAD) {
            p->bad_frames++;
            p->st = (b == SYNC_BYTE) ? ST_LEN : ST_SYNC;   /* 0xAA may be the real SYNC */
            break;
        }
        p->len = b; p->idx = 0; p->chk = b;
        p->st = ST_PAYLOAD;
        break;
    case ST_PAYLOAD:
        p->data[p->idx++] = b;                       /* idx < len <= MAX_PAYLOAD */
        p->chk ^= b;
        if (p->idx == p->len) p->st = ST_CHK;
        break;
    case ST_CHK:
        p->st = ST_SYNC;                             /* either way, hunt for the next frame */
        if (b != p->chk) { p->bad_frames++; break; }
        out->len = p->len;
        memcpy(out->data, p->data, p->len);
        return true;
    }
    return false;
}

코드 읽는 포인트

  • ST_PAYLOAD에서 p->data[p->idx++]가 안전한 이유: LEN 상태에서 len <= MAX_PAYLOAD를 이미 검사했고, idx == len이 되는 순간 CHK로 넘어갑니다. 범위 검사를 입구에서 한 번 하는 구조입니다.
  • ST_CHK에서 먼저 p->st = ST_SYNC로 바꾸고 비교합니다. 성공이든 실패든 다음 상태가 같기 때문에 분기가 줄어듭니다.
  • 파서는 out을 성공할 때만 씁니다. 그래서 호출자는 반환값만 보고 out을 믿을 수 있습니다.
  • 테스트 4번: payload 첫 바이트와 CHK가 모두 0xAA여도 길이 기반이라 정상 처리됩니다. "0xAA를 보면 무조건 새 프레임"으로 짜면 여기서 깨집니다.

4.5 복잡도

  • 바이트당 O(1), 분기 몇 개. ISR 안에서 직접 돌려도 됩니다.
  • 메모리: Parser 28 B(64비트 macOS 기준) + 출력 Packet 17 B. 동적 할당 없음.

5. 임베디드 관점으로 말할 것

  • ISR과 분리: 보통 UART RX ISR은 바이트를 T2-1 링버퍼에 넣기만 하고, task가 꺼내서 parser_feed를 돌립니다. 파서가 O(1)이라 ISR 안에서 직접 돌려도 되지만, 완성 패킷 처리는 task에서 합니다.
  • XOR의 약점: XOR은 같은 비트가 두 번 뒤집히는 오류나 바이트 순서 바뀜을 못 잡습니다. 실제 제품이면 CRC-8(예: 0x07)이나 CRC-16-CCITT를 쓰자고 말합니다. 구조는 같고 chk ^= b 한 줄만 바뀝니다.
  • inter-byte timeout: 패킷 중간에 선이 끊기면 파서가 PAYLOAD에 머물러 다음 패킷 앞부분을 먹습니다. 마지막 바이트 시각을 기억해 두고, 예를 들어 5 ms 넘게 조용하면 SYNC로 리셋합니다(wrap-safe now - last >= timeout).
  • 진단 카운터: bad_frames, overrun 같은 카운터는 현장에서 "케이블 노이즈인가, 속도 불일치인가"를 가르는 첫 단서입니다.

6. Follow-up 질문과 답

Follow-up (English)답
After a bad checksum you drop the whole frame. Could a real packet be hidden inside it?그렇습니다. 깨진 프레임 안에 진짜 AA가 있었다면 놓칩니다. 받은 바이트를 작은 버퍼에 두고, 실패 시 SYNC 다음 바이트부터 다시 스캔하면 됩니다. 대신 최악의 경우 바이트당 O(MAX_PAYLOAD).
How would you avoid 0xAA ambiguity entirely?바이트 스터핑(SLIP, COBS, HDLC 방식)으로 payload 안의 SYNC 값을 이스케이프하면, SYNC를 보면 무조건 프레임 시작이라 재동기화가 즉시 됩니다.
Replace XOR with CRC-8.crc = table[crc ^ b] 테이블 방식(256 B) 또는 비트 루프 8회. 초기값과 다항식을 프로토콜 문서에서 확인합니다.
The payload has a 16-bit little-endian temperature. How do you decode it portably?하위·상위 바이트를 시프트와 OR로 조립합니다(테스트의 temp_at 참고). 구조체 포인터 캐스팅은 정렬·엔디안·strict aliasing 문제가 있습니다.
What if packets arrive faster than the task consumes them?완성 패킷을 별도 큐에 넣고, 꽉 차면 버린 개수를 셉니다. 원인은 baud rate 대비 task 주기 계산으로 설명합니다.

7. 자주 하는 실수

  • ST_LEN에서 LEN == 0 또는 LEN > MAX_PAYLOAD 검사를 빠뜨림 → data[] 오버런(테스트 3번, ASan이 잡음)
  • 체크섬에 LEN을 포함하지 않음 → 테스트 1번부터 실패. 프로토콜 정의를 먼저 물어볼 것
  • payload 중간의 0xAA를 SYNC로 처리 → 테스트 4번 실패
  • 패킷을 함수 하나에 배열로 받아 파싱 → "바이트 단위로 들어온다"는 요구를 놓침(테스트 2번: 쪼개진 패킷)
  • 실패 후 idx, chk를 리셋하지 않음 → LEN 상태에서 리셋하면 자연히 해결됩니다
