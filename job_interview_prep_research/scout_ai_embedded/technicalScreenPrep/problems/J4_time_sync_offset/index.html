J4 · Clock Offset from Request/Response Timestamps (NTP-style)

IDJ4
PriorityP1
Pattern4-timestamp math + min-delay filter + slew-limited correction
Time20 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh J4 / ./run.sh J4 sol

1. Problem

A robot MCU stamps its sensor samples with its own free-running clock (microseconds, int64_t). The fusion code on the host needs those stamps on the host clock. To learn the mapping, the MCU pings the host and records four timestamps:

eventclock
t[0] = t1MCU sends requestMCU
t[1] = t2host receives requesthost
t[2] = t3host sends replyhost
t[3] = t4MCU receives replyMCU
offset = ((t2 - t1) + (t3 - t4)) / 2     /* host_time = mcu_time + offset */
delay  = (t4 - t1) - (t3 - t2)           /* round trip minus host hold time */
  • The / 2 rounds toward negative infinity (floor): 1999 / 2 -> 999, -2001 / 2 -> -1001. (Plain C / truncates toward zero; agree on this first.)
  • Part A — sync_sample(): compute offset and delay of one sample. Return false and leave the outputs untouched if t4 < t1, t3 < t2, or delay < 0.
  • Part B — sync_best(): among n samples, use the valid sample with the smallest delay. Ties go to the earliest index. Return false if no sample is valid.
  • Part C — clock_apply(): update the applied offset with a new measurement.
    • If not synced yet, or |measured - applied| > STEP_THRESHOLD_US (128000), step: applied = measured.
    • Otherwise slew: move toward measured by at most MAX_SLEW_PPM (500) × elapsed_local_us / 1e6 µs (integer floor; no movement if elapsed_local_us <= 0).
    • Return the applied offset. to_host_time() returns local_us + applied offset.
  • No malloc, integer math only.
#define STEP_THRESHOLD_US 128000
#define MAX_SLEW_PPM      500

typedef struct { int64_t offset_us; bool synced; } ClockSync;

bool    sync_sample(const int64_t t[4], int64_t *offset_us, int64_t *delay_us);
bool    sync_best(const int64_t (*samples)[4], size_t n, int64_t *offset_us, int64_t *delay_us);
int64_t clock_apply(ClockSync *cs, int64_t measured_offset_us, int64_t elapsed_local_us);
int64_t to_host_time(const ClockSync *cs, int64_t local_us);

Example

true offset = +5000 us (host is ahead), 200 us each way, host holds 100 us
t = {10000, 15200, 15300, 10500}
offset = ((15200-10000) + (15300-10500)) / 2 = (5200 + 4800) / 2 = 5000
delay  = (10500-10000) - (15300-15200)      = 500 - 100          = 400

asymmetric: up 300, down 100, same true offset
t = {20000, 25300, 25400, 20500}  ->  offset 5100, delay 400   (error 100 <= delay/2)

ClockSync starts {0, false}:
apply(5000, 0)       -> 5000    first sync: step
apply(7000, 1000000) -> 5500    slew, +500 us per second
apply(7000, 1000000) -> 6000 -> 6500 -> 7000 -> 7000

Constraints

  • Timestamps are int64_t µs; differences fit easily (no wraparound in this version).
  • samples may be NULL when n == 0. cs is never NULL.

Clarifying questions to ask (first 3 minutes)

  1. Which sign convention: host - MCU or MCU - host?
  2. How should the / 2 round for negative or odd sums?
  3. What makes a sample invalid — and should I write outputs when it is?
  4. With several samples, average them or pick the min-delay one? Tie-break?
  5. Step or slew? What threshold and max slew rate? Is the first sync always a step?

    /* 2. asymmetric path: up 300, down 100, true offset 5000 -> measured 5100 (error 100 <= delay/2) */
    const int64_t b[4] = { 20000, 25300, 25400, 20500 };
    CHECK(sync_sample(b, &off, &del));
    CHECK(off == 5100 && del == 400);

    /* 3. negative offset: MCU is 2000 us AHEAD of the host */
    const int64_t c[4] = { 100000, 98150, 98200, 100350 };
    CHECK(sync_sample(c, &off, &del));
    CHECK(off == -2000 && del == 300);

    /* 4. rounding of odd sums: floor, not truncation */
    const int64_t r1[4] = { 0, 1000, 1000, 1 };      /* sum  1999 ->  999 */
    const int64_t r2[4] = { 1000, 0, 0, 1001 };      /* sum -2001 -> -1001 */
    CHECK(sync_sample(r1, &off, &del) && off == 999 && del == 1);
    CHECK(sync_sample(r2, &off, &del) && off == -1001 && del == 1);

    /* 5. invalid samples are rejected and outputs are left untouched */
    const int64_t bad_rtt[4]   = { 100, 200, 300, 50 };    /* t4 < t1 */
    const int64_t bad_proc[4]  = { 0, 500, 400, 1000 };    /* t3 < t2 */
    const int64_t bad_delay[4] = { 0, 100, 600, 300 };     /* delay = 300 - 500 < 0 */
    off = 777; del = 777;
    CHECK(!sync_sample(bad_rtt, &off, &del));
    CHECK(!sync_sample(bad_proc, &off, &del));
    CHECK(!sync_sample(bad_delay, &off, &del));
    CHECK(off == 777 && del == 777);

    /* 6. best-of-N: minimum delay wins, invalid skipped, tie -> earliest */
    const int64_t s[5][4] = {
        { 10000, 15200, 15300, 10500 },   /* off 5000, delay  400 */
        { 20000, 25900, 26000, 21300 },   /* off 5300, delay 1200 (queued) */
        { 30000, 35080, 35100, 30180 },   /* off 5000, delay  160 <- best */
        { 40000, 45000, 44000, 41000 },   /* invalid: t3 < t2 */
        { 50000, 55100, 55120, 50180 },   /* off 5020, delay  160 (tie, later) */
    };
    CHECK(sync_best(s, 5, &off, &del));
    CHECK(off == 5000 && del == 160);
    CHECK(!sync_best(s + 3, 1, &off, &del));   /* only the invalid one */
    CHECK(!sync_best(NULL, 0, &off, &del));

    /* 7. slew: first call steps, then at most 500 us per second of local time */
    ClockSync cs = { 0, false };
    CHECK(clock_apply(&cs, 5000, 0) == 5000);          /* first sync -> step */
    CHECK(clock_apply(&cs, 7000, 1000000) == 5500);
    CHECK(clock_apply(&cs, 7000, 1000000) == 6000);
    CHECK(clock_apply(&cs, 7000, 1000000) == 6500);
    CHECK(clock_apply(&cs, 7000, 1000000) == 7000);
    CHECK(clock_apply(&cs, 7000, 1000000) == 7000);    /* converged: no overshoot */
    CHECK(clock_apply(&cs, 9000, 0) == 7000);          /* no elapsed time -> no move */
    CHECK(to_host_time(&cs, 1000000) == 1007000);

    /* 8. step on a large jump, then slew down; threshold is strict '>' */
    CHECK(clock_apply(&cs, 300000, 1000000) == 300000);   /* |293000| > 128000 -> step */
    CHECK(clock_apply(&cs, 299000, 400000) == 299800);    /* -1000 clamped to -200 */
    CHECK(clock_apply(&cs, 427800, 1000000) == 300300);   /* diff == 128000 -> slew +500 */
    CHECK(clock_apply(&cs, 428301, 1000000) == 428301);   /* diff == 128001 -> step */
    CHECK(to_host_time(&cs, -428301) == 0);

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

3. 힌트 (막힐 때 하나씩)

Hint 1 — 공식을 외우지 말고 유도하기

진짜 offset을 θ, 올라가는 지연을 u, 내려오는 지연을 d라고 하면 t2 − t1 = θ + u, t3 − t4 = θ − d입니다. 더해서 2로 나누면 θ + (u − d)/2 → 지연이 대칭(u = d)이면 정확히 θ. 빼면 u + d = delay입니다. 면접에서 이 두 줄을 화이트보드에 쓰면 공식을 몰라도 됩니다.

Hint 2 — floor 나눗셈

C의 /는 0 쪽으로 자릅니다(-3/2 == -1). floor가 필요하면 q = x / 2; if (x < 0 && x % 2) q--;. 음수에 >> 1은 C23 전까지 implementation-defined라 피하는 것이 안전합니다.

Hint 3 — slew 클램프

err = measured − applied, max = elapsed * 500 / 1000000. |err| > 128000이면 그냥 대입(step). 아니면 err를 [-max, +max]로 자른 뒤 더합니다. 이렇게 하면 목표를 지나치는 일(overshoot)이 자동으로 없습니다.

4. 풀이

4.1 핵심 아이디어 — 그림으로 보기

같은 메시지 왕복을 두 개의 시계로 잰다고 생각하면 됩니다. x축은 "진짜 시간"이고, t1·t4는 MCU 시계로, t2·t3는 host 시계로 찍힌 값입니다.

  • t2 − t1에는 offset + 올라가는 지연, t3 − t4에는 offset − 내려오는 지연이 들어 있습니다. 평균을 내면 지연이 상쇄됩니다.
  • 상쇄는 대칭일 때만 정확합니다. 비대칭이면 오차는 (u − d)/2이고, 그 크기는 최대 delay/2입니다(예제 2: up 300/down 100 → 5100, 오차 100 ≤ 200).
  • 그래서 여러 번 재고 delay가 가장 작은 샘플을 고릅니다. delay가 작다는 것은 큐잉(버스 경합, OS 스케줄링)이 적었다는 뜻이고, 오차 상한 delay/2도 가장 작습니다. 평균을 내면 큐잉에 오염된 샘플이 결과를 끌고 갑니다.

4.2 step vs slew

측정한 offset을 바로 대입하면 to_host_time()이 거꾸로 가거나 갑자기 뛸 수 있습니다. 작은 오차는 천천히 따라가고(slew), 큰 오차만 즉시 맞춥니다(step). chrony/ntpd의 동작과 같습니다.

/*
 * J4  Clock Offset from Request/Response Timestamps (NTP-style)  --  Reference solution
 *
 * An MCU (local clock, microseconds) pings the host (host clock, microseconds):
 *   t[0] = t1  MCU send      (MCU clock)
 *   t[1] = t2  host receive  (host clock)
 *   t[2] = t3  host send     (host clock)
 *   t[3] = t4  MCU receive   (MCU clock)
 *
 *   offset = ((t2 - t1) + (t3 - t4)) / 2      host_time = mcu_time + offset
 *   delay  = (t4 - t1) - (t3 - t2)            round trip minus host processing
 *
 * Rounding (agreed with the interviewer): the /2 rounds toward NEGATIVE infinity
 * (floor), so +1.5 -> 1 and -1.5 -> -2. Plain C `/` truncates toward zero instead.
 *
 * Part A  sync_sample(): one sample -> offset/delay. Return false (outputs untouched)
 *         if t4 < t1, t3 < t2, or delay < 0.
 * Part B  sync_best(): among n samples pick the VALID one with the smallest delay
 *         (least queuing noise). Ties -> the earliest index. false if none is valid.
 * Part C  clock_apply(): move the applied offset toward a new measurement.
 *         - not synced yet, or |measured - applied| > STEP_THRESHOLD_US -> STEP (jump).
 *         - otherwise SLEW by at most MAX_SLEW_PPM * elapsed_local_us / 1e6
 *           (integer floor; elapsed <= 0 allows no movement).
 *         Returns the applied offset. to_host_time() = local_us + applied offset.
 *
 * No malloc, int64_t microseconds, integer math only.
 * Build & run:  ./run.sh J4 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

#define STEP_THRESHOLD_US 128000   /* 128 ms: bigger error -> jump instead of slew */
#define MAX_SLEW_PPM      500      /* at most 500 us of correction per second    */

typedef struct {
    int64_t offset_us;   /* applied offset: host = local + offset_us */
    bool    synced;      /* false until the first clock_apply()      */
} ClockSync;

/* floor(x / 2) without relying on >> of a negative number (impl-defined before C23) */
static int64_t floor_div2(int64_t x)
{
    int64_t q = x / 2;               /* truncates toward zero          */
    if (x < 0 && (x % 2) != 0) q--;  /* negative odd: one more step down */
    return q;
}

bool sync_sample(const int64_t t[4], int64_t *offset_us, int64_t *delay_us)
{
    int64_t rtt  = t[3] - t[0];      /* t4 - t1, MCU clock  */
    int64_t proc = t[2] - t[1];      /* t3 - t2, host clock */
    if (rtt < 0 || proc < 0) return false;
    int64_t delay = rtt - proc;
    if (delay < 0) return false;     /* host held it longer than the round trip: bad stamps */

    *offset_us = floor_div2((t[1] - t[0]) + (t[2] - t[3]));
    *delay_us  = delay;
    return true;
}

bool sync_best(const int64_t (*samples)[4], size_t n, int64_t *offset_us, int64_t *delay_us)
{
    bool found = false;
    int64_t best_off = 0, best_del = 0;
    for (size_t i = 0; i < n; i++) {
        int64_t off, del;
        if (!sync_sample(samples[i], &off, &del)) continue;
        if (!found || del < best_del) {          /* strict '<' keeps the earliest on ties */
            found = true; best_off = off; best_del = del;
        }
    }
    if (found) { *offset_us = best_off; *delay_us = best_del; }
    return found;
}

int64_t clock_apply(ClockSync *cs, int64_t measured_offset_us, int64_t elapsed_local_us)
{
    int64_t err = measured_offset_us - cs->offset_us;
    int64_t mag = err < 0 ? -err : err;

    if (!cs->synced || mag > STEP_THRESHOLD_US) {          /* STEP */
        cs->offset_us = measured_offset_us;
        cs->synced = true;
        return cs->offset_us;
    }
    int64_t max_slew = elapsed_local_us > 0
                     ? elapsed_local_us * MAX_SLEW_PPM / 1000000 : 0;
    if (err >  max_slew) err =  max_slew;                  /* SLEW, clamped */
    if (err < -max_slew) err = -max_slew;
    cs->offset_us += err;
    return cs->offset_us;
}

int64_t to_host_time(const ClockSync *cs, int64_t local_us)
{
    return local_us + cs->offset_us;
}

        { 50000, 55100, 55120, 50180 },   /* off 5020, delay  160 (tie, later) */
    };
    CHECK(sync_best(s, 5, &off, &del));
    CHECK(off == 5000 && del == 160);
    CHECK(!sync_best(s + 3, 1, &off, &del));   /* only the invalid one */
    CHECK(!sync_best(NULL, 0, &off, &del));

    /* 7. slew: first call steps, then at most 500 us per second of local time */
    ClockSync cs = { 0, false };
    CHECK(clock_apply(&cs, 5000, 0) == 5000);          /* first sync -> step */
    CHECK(clock_apply(&cs, 7000, 1000000) == 5500);
    CHECK(clock_apply(&cs, 7000, 1000000) == 6000);
    CHECK(clock_apply(&cs, 7000, 1000000) == 6500);
    CHECK(clock_apply(&cs, 7000, 1000000) == 7000);
    CHECK(clock_apply(&cs, 7000, 1000000) == 7000);    /* converged: no overshoot */
    CHECK(clock_apply(&cs, 9000, 0) == 7000);          /* no elapsed time -> no move */
    CHECK(to_host_time(&cs, 1000000) == 1007000);

    /* 8. step on a large jump, then slew down; threshold is strict '>' */
    CHECK(clock_apply(&cs, 300000, 1000000) == 300000);   /* |293000| > 128000 -> step */
    CHECK(clock_apply(&cs, 299000, 400000) == 299800);    /* -1000 clamped to -200 */
    CHECK(clock_apply(&cs, 427800, 1000000) == 300300);   /* diff == 128000 -> slew +500 */
    CHECK(clock_apply(&cs, 428301, 1000000) == 428301);   /* diff == 128001 -> step */
    CHECK(to_host_time(&cs, -428301) == 0);

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

코드 읽는 포인트

  • sync_sample()은 검사를 모두 통과한 다음에만 출력 포인터에 씁니다. 실패 시 호출자의 이전 값이 보존됩니다(테스트 5).
  • sync_best()는 sync_sample()을 재사용하고, 비교를 <로 해서 동점이면 앞의 샘플을 유지합니다. <=로 쓰면 테스트 6이 5020으로 실패합니다.
  • clock_apply()의 elapsed * 500 / 1000000은 곱셈 먼저, 나눗셈 나중입니다. 순서를 바꾸면 1초 미만 elapsed에서 0이 됩니다(400000 µs → 200 µs가 나와야 함).
  • step 판정은 mag > STEP_THRESHOLD_US(엄격한 >)입니다. 경계값 128000은 slew 쪽입니다.

4.5 복잡도

  • sync_sample, clock_apply, to_host_time: O(1).
  • sync_best: 시간 O(n), 추가 메모리 O(1) — 최선값 두 개만 들고 다닙니다.

5. 임베디드 관점으로 말할 것

  • 왜 이 문제인가: 면접관 Jason은 자율주행(Latitude AI)과 Charles Machine Works에서 공용 라이브러리에 NTP time synchronization을 넣었던 경력이 있습니다. 로봇 센서 퓨전은 MCU의 IMU/엔코더 타임스탬프를 host(Jetson 등) 시계 위로 옮겨야 카메라·LiDAR와 정렬됩니다. "타임스탬프가 틀리면 퓨전이 틀린다"는 한 줄로 시작하면 좋습니다.
  • 타임스탬프는 가능한 한 하드웨어 가까이: t1은 UART/CAN 송신 직전이 아니라 송신 완료 인터럽트에서, t4는 수신 ISR에서 찍어야 소프트웨어 지연이 delay에 섞이지 않습니다. 센서 샘플도 DRDY 인터럽트(ISR)에서 free-running 타이머를 읽어 찍고, 처리는 task에서 합니다 → E3.
  • int64 µs: 32비트 µs 카운터는 71분이면 랩어라운드합니다. 하드웨어 타이머가 32비트라면 overflow 인터럽트로 상위 32비트를 확장해 64비트로 씁니다.
  • slew 중에도 단조 증가: 500 ppm slew는 시계를 최대 0.05% 빠르게/느리게 할 뿐이라 시간이 거꾸로 가지 않습니다. step은 로그를 남기고, 퓨전 버퍼처럼 시간 순서에 의존하는 소비자에게 알려야 합니다.
  • min-delay 필터: 실제로는 8–16개 샘플을 링버퍼에 두고 그중 최소 delay를 쓰는 방식이 흔합니다(NTP clock filter와 같은 생각) → T2-1.

6. Follow-up 질문과 답

Follow-up (English)답
Why does an asymmetric link bias the offset? How big can the error be?공식이 θ + (u − d)/2를 계산하기 때문입니다. u, d ≥ 0이고 u + d = delay이므로 오차 |u − d|/2 ≤ delay/2. 측정만으로는 비대칭을 알 수 없어서, delay가 작은 샘플을 써서 상한을 줄이는 것이 최선입니다.
How does PTP (IEEE 1588) do better than NTP?같은 4-타임스탬프 수식이지만, 타임스탬프를 PHY/MAC 하드웨어가 패킷이 선을 지나는 순간 찍습니다. OS·드라이버·큐 지연이 빠져서 sub-µs 정확도가 나옵니다. 스위치가 체류 시간을 보정하는 transparent clock도 있습니다.
The offset keeps drifting between syncs. How do you handle frequency error?크리스털은 수십 ppm 틀립니다. (local time, offset) 쌍들을 모아 선형 회귀하면 기울기 = 주파수 오차(drift), 절편 = offset입니다. host = local + offset + drift × (local − t_ref)로 sync 사이를 보간하고, slew rate에도 drift 보정을 더합니다.
On Linux, which clock should the host use?간격 측정과 타임아웃은 CLOCK_MONOTONIC(뒤로 안 감, NTP slew만 반영). 로그·다른 장비와 맞추는 절대 시각은 CLOCK_REALTIME(step 가능). 센서 퓨전은 보통 monotonic 기반. chrony가 slew/step 정책(makestep)을 관리합니다. 원시 하드웨어 속도는 CLOCK_MONOTONIC_RAW.
Where do you timestamp a sensor sample — ISR or task?ISR(DRDY 인터럽트)에서 타이머를 읽어 샘플과 같이 큐에 넣습니다. task에서 찍으면 스케줄링 지연(수백 µs~ms)이 가변 오차로 들어갑니다. DMA라면 버퍼 완료 시각에서 샘플 간격으로 역산합니다.
What if the robot has GPS?GPS PPS 신호는 매 초 정각에 ±수십 ns 정확도의 엣지를 줍니다. 타이머 input capture로 엣지 시각을 잡으면 MCU 시계의 offset과 drift를 직접 구할 수 있고, host도 같은 PPS로 맞추면(chrony + PPS) 모든 장비가 같은 시간축을 씁니다.
Why not just average all samples?큐잉 지연은 항상 양수 방향으로만 늘고 분포가 한쪽으로 긴 꼬리를 가집니다. 평균은 그 꼬리에 끌려가지만, 최소 delay 샘플은 거의 "순수 전송 시간"에 가깝습니다.

  • / 2를 그대로 써서 음수 홀수 합이 0 쪽으로 잘림 → 테스트 4의 -1001이 -1000이 됨
