T1-8 · Blocking API Wrapper

IDT1-8
PriorityP2
Patterndedicated sampler thread + mutex-protected cache + ring buffer window
Time40 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh T1-8 / ./run.sh T1-8 sol

1. Problem

The vendor driver gives you a single function:

int16_t read_temp(void);   /* temp in 0.1 degC, or TEMP_ERR (INT16_MIN) on a bus error */

It blocks for up to 1 second (one I2C conversion) and is not thread-safe — two threads inside it at the same time corrupt the bus. Many application threads need the temperature. Build a small service on top of it:

int  sampler_start(void);              /* start ONE background sampler thread; 0 ok, -1 if running */
void sampler_stop(void);               /* stop and join; safe to call twice */
bool get_latest_temp(int16_t *out);    /* NEVER waits for the sensor; false if no reading yet */
bool is_overheating(int16_t thresh);   /* max of readings with now - t <= 5000 ms is > thresh */
  • Only the sampler thread may call read_temp(). Never hold a lock across read_temp().
  • Drop TEMP_ERR readings and keep the last good value.
  • Keep history in a fixed-size ring buffer of (t_ms, temp) — no malloc. Use now_ms() for time.
  • is_overheating returns false when there is no reading inside the window.
  • start/stop are called from one control thread.

The file provides a fake sensor and a fake clock so the test runs in about 1 second: read_temp() polls with nanosleep until the test feeds a value, or returns TEMP_ERR after 200 ms (a scaled-down "1 s"). now_ms() only moves when the test sets it.

Example

now=1000  sensor -> 250   get_latest_temp -> 250   is_overheating(800) -> false
now=2000  sensor -> 900   get_latest_temp -> 900   is_overheating(800) -> true
now=3000  sensor -> 300   get_latest_temp -> 300   is_overheating(800) -> true  (900 is 1 s old)
now=7000  (no reading)                             is_overheating(800) -> true  (7000-2000 = 5000)
now=7001  (no reading)                             is_overheating(800) -> false (900 expired)

Constraints

  • One read takes about 1 s, so the 5 s window holds about 5–6 readings. Ring capacity HIST_CAP = 16.
  • get_latest_temp / is_overheating may be called from any number of threads at any rate.

Clarifying questions to ask (first 3 minutes)

  1. Should reads be continuous (a background thread), or on demand when someone asks? How fresh must "latest" be?
  2. What should get_latest_temp return before the first reading, or when the sensor has been failing for a long time?
  3. "Last 5 s" — measured by the time the reading finished? Inclusive at exactly 5000 ms?
  4. Is > or >= the overheat rule? And with no readings in the window — false, or "unknown" (fail-safe)?
  5. How quickly must stop() return? (It cannot interrupt a read that is already in progress.)

/*
 * T1-8  Blocking API Wrapper
 *
 * The vendor driver gives you one function:
 *
 *     int16_t read_temp(void);   // temp in 0.1 degC, or TEMP_ERR on a bus error
 *
 * It BLOCKS for up to 1 s (one I2C conversion) and is NOT thread-safe: two threads

 * temperature. Build a small service on top of it:
 *
 *   int  sampler_start(void);           start ONE background sampler thread.

 *                                       reading exists yet, else *out = latest reading.
 *   bool is_overheating(int16_t thresh); true if the MAX of the readings taken within
 *                                       the last 5000 ms (now - t <= 5000) is > thresh.
 *                                       false if there is no reading in that window.
 *
 * Rules: pthreads; read_temp() is called only by the sampler thread; never hold a lock
 * across read_temp(); TEMP_ERR readings are dropped (keep the last good value); keep a

#define READ_TIMEOUT_MS 200            /* real part: up to 1000 ms */

static atomic_uint     g_now_ms;                              /* fake monotonic clock */
static uint32_t now_ms(void) { return (uint32_t)atomic_load(&g_now_ms); }

static pthread_mutex_t g_dev_mx = PTHREAD_MUTEX_INITIALIZER;  /* harness only */
static bool            g_dev_has;
static int16_t         g_dev_val;
static atomic_int      g_dev_inside;
static atomic_bool     g_dev_overlap;                         /* concurrent entry seen */

static void sleep_ms(long ms)
{
    struct timespec ts = { ms / 1000, (ms % 1000) * 1000000L };
    nanosleep(&ts, NULL);
}

static uint64_t real_ms(void)           /* real monotonic time, harness + tests only */
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (uint64_t)ts.tv_sec * 1000u + (uint64_t)ts.tv_nsec / 1000000u;
}

int16_t read_temp(void)                 /* blocking, NOT thread-safe */
{
    if (atomic_fetch_add(&g_dev_inside, 1) != 0) atomic_store(&g_dev_overlap, true);
    int16_t v = TEMP_ERR;
    uint64_t start = real_ms();
    while (real_ms() - start < READ_TIMEOUT_MS) {
        sleep_ms(5);                                          /* "conversion time" */
        pthread_mutex_lock(&g_dev_mx);
        bool got = g_dev_has;
        if (got) { v = g_dev_val; g_dev_has = false; }
        pthread_mutex_unlock(&g_dev_mx);
        if (got) break;
    }
    atomic_fetch_sub(&g_dev_inside, 1);
    return v;                                                 /* TEMP_ERR = timeout/NACK */
}

{

    g_dev_val = v; g_dev_has = true;

}

{
    int16_t v = 0;

    /* 1. before start: no data, not overheating; start once only */
    CHECK(get_latest_temp(&v) == false);
    CHECK(is_overheating(800) == false);
    CHECK(sampler_start() == 0);
    CHECK(sampler_start() == -1);

    /* 2. never blocks: the sampler is parked inside read_temp() right now */
    uint64_t t0 = real_ms();
    CHECK(get_latest_temp(&v) == false);
    CHECK(real_ms() - t0 < 50);

    /* 3. readings flow through; window max is strictly greater than thresh */
    atomic_store(&g_now_ms, 1000); sensor_feed(250);
    CHECK(wait_latest(250, 300));
    CHECK(is_overheating(800) == false);
    atomic_store(&g_now_ms, 2000); sensor_feed(900);
    CHECK(wait_latest(900, 300));
    CHECK(is_overheating(800) == true);
    CHECK(is_overheating(900) == false);          /* 900 > 900 is false */

    /* 4. a cool latest value does not hide a hot reading still inside the 5 s window */
    atomic_store(&g_now_ms, 3000); sensor_feed(300);
    CHECK(wait_latest(300, 300));
    CHECK(is_overheating(800) == true);
    atomic_store(&g_now_ms, 7000);                /* 7000 - 2000 = 5000: still inside */
    CHECK(is_overheating(800) == true);
    atomic_store(&g_now_ms, 7001);                /* 5001: the 900 reading expired */
    CHECK(is_overheating(800) == false);

    /* 5. a bus error (read timeout) keeps the last good value */
    sleep_ms(READ_TIMEOUT_MS + 50);
    CHECK(get_latest_temp(&v) && v == 300);

    /* 6. ring buffer wraps (20 readings > HIST_CAP 16); window still correct */
    bool flowed = true;
    for (int16_t k = 0; k < 20 && flowed; k++) {
        atomic_store(&g_now_ms, 10000u + 100u * (uint32_t)k);
        sensor_feed((int16_t)(400 + k));
        flowed = wait_latest((int16_t)(400 + k), 300);
    }
    CHECK(flowed);
    CHECK(is_overheating(418) == true);           /* max in window = 419 */
    CHECK(is_overheating(419) == false);

    /* 7. stop is bounded by one read, idempotent; the sensor never saw two callers */
    t0 = real_ms();
    sampler_stop();
    CHECK(real_ms() - t0 < READ_TIMEOUT_MS + 150);
    sampler_stop();
    CHECK(get_latest_temp(&v) && v == 419);
    CHECK(atomic_load(&g_dev_overlap) == false);

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

3. 힌트 (막힐 때 하나씩)

Hint 1 — 누가 센서를 만지는가

센서를 부르는 스레드를 딱 하나(sampler)로 정하면 "thread-safe가 아님" 문제는 설계로 사라집니다. 나머지 스레드는 센서가 아니라 sampler가 남긴 복사본만 읽습니다. 그래서 get_latest_temp는 절대 1초를 기다리지 않습니다.

Hint 2 — 락은 어디까지? 
v = read_temp();          // 락 밖 (최대 1 s)
t = now_ms();
lock;  latest = v; ring_push(t, v);  unlock;   // 락 안 (µs)

read_temp()를 락 안에 넣으면 그동안 모든 호출자가 락에서 최대 1초 막힙니다. 요구사항 "never blocks" 위반입니다.

Hint 3 — 5초 윈도우 max

링버퍼를 최신 → 과거 순으로 돌면서 (uint32_t)(now - t) > 5000이 나오면 멈춥니다(그보다 오래된 건 더 오래됨). 그 전까지의 max를 구해 > thresh. 링 인덱스는 (head + CAP - 1 - k) % CAP.

4. 풀이

4.1 핵심 아이디어 — 스레드 타임라인

구조는 세 덩어리입니다.

  1. sampler 스레드: while (running) { v = read_temp(); if (err) continue; lock; 저장; unlock; }
  2. 공유 상태 (g_mx 하나로 보호): latest, have, 링버퍼 hist[16], head, count
  3. 읽기 API: 락 잡고 복사/스캔하고 놓기. 센서는 절대 안 건드림

running은 atomic_bool입니다. 루프 조건으로만 쓰이고 다른 데이터와 묶여 있지 않으므로 락 없이 atomic 하나면 충분합니다.

 *                                       reading exists yet, else *out = latest reading.

#define WINDOW_MS 5000u
#define HIST_CAP  16u        /* >= readings in 5 s: one read takes ~1 s, plus margin */

typedef struct { uint32_t t_ms; int16_t temp; } Rec;

static pthread_mutex_t g_mx = PTHREAD_MUTEX_INITIALIZER;  /* guards everything below */
static int16_t  g_latest;
static bool     g_have;
static Rec      g_hist[HIST_CAP];
static uint32_t g_head, g_count;                          /* next write slot, fill level */

static atomic_bool g_running;
static pthread_t   g_thr;
static bool        g_started;                             /* control thread only */

static void *sampler_main(void *arg)
{
    (void)arg;
    while (atomic_load(&g_running)) {
        int16_t v = read_temp();               /* slow part: NO lock held */
        if (v == TEMP_ERR) continue;           /* keep the last good value */
        uint32_t t = now_ms();

        pthread_mutex_lock(&g_mx);             /* short critical section */
        g_latest = v;
        g_have = true;
        g_hist[g_head] = (Rec){ t, v };
        g_head = (g_head + 1) % HIST_CAP;
        if (g_count < HIST_CAP) g_count++;
        pthread_mutex_unlock(&g_mx);
    }
    return NULL;
}

int sampler_start(void)
{
    if (g_started) return -1;
    pthread_mutex_lock(&g_mx);
    g_have = false; g_head = 0; g_count = 0;
    pthread_mutex_unlock(&g_mx);

    atomic_store(&g_running, true);
    if (pthread_create(&g_thr, NULL, sampler_main, NULL) != 0) {
        atomic_store(&g_running, false);
        return -1;
    }
    g_started = true;
    return 0;
}

void sampler_stop(void)
{
    if (!g_started) return;
    atomic_store(&g_running, false);
    pthread_join(g_thr, NULL);                 /* waits for at most one read_temp() */
    g_started = false;
}

bool get_latest_temp(int16_t *out)
{
    pthread_mutex_lock(&g_mx);                 /* held for a copy, never for I/O */
    bool ok = g_have;
    if (ok) *out = g_latest;
    pthread_mutex_unlock(&g_mx);
    return ok;
}

bool is_overheating(int16_t thresh)
{
    bool found = false;
    int16_t mx = INT16_MIN;

    pthread_mutex_lock(&g_mx);
    uint32_t now = now_ms();
    for (uint32_t k = 0; k < g_count; k++) {               /* newest -> oldest */
        const Rec *r = &g_hist[(g_head + HIST_CAP - 1 - k) % HIST_CAP];
        if ((uint32_t)(now - r->t_ms) > WINDOW_MS) break;  /* wrap-safe; rest are older */
        if (!found || r->temp > mx) mx = r->temp;
        found = true;
    }
    pthread_mutex_unlock(&g_mx);
    return found && mx > thresh;
}

    sleep_ms(READ_TIMEOUT_MS + 50);
    CHECK(get_latest_temp(&v) && v == 300);

    /* 6. ring buffer wraps (20 readings > HIST_CAP 16); window still correct */
    bool flowed = true;
    for (int16_t k = 0; k < 20 && flowed; k++) {
        atomic_store(&g_now_ms, 10000u + 100u * (uint32_t)k);
        sensor_feed((int16_t)(400 + k));
        flowed = wait_latest((int16_t)(400 + k), 300);
    }
    CHECK(flowed);
    CHECK(is_overheating(418) == true);           /* max in window = 419 */
    CHECK(is_overheating(419) == false);

    /* 7. stop is bounded by one read, idempotent; the sensor never saw two callers */
    t0 = real_ms();
    sampler_stop();
    CHECK(real_ms() - t0 < READ_TIMEOUT_MS + 150);
    sampler_stop();
    CHECK(get_latest_temp(&v) && v == 419);
    CHECK(atomic_load(&g_dev_overlap) == false);

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);
    return g_fail != 0;
}

코드 읽는 포인트

  • sampler_main에서 now_ms()는 read_temp()가 끝난 뒤 찍습니다. 1초짜리 읽기의 "측정 시각"을 시작으로 볼지 끝으로 볼지는 정의 문제지만, 끝을 쓰면 윈도우가 데이터를 너무 일찍 버리지 않습니다.
  • is_overheating은 락 안에서 now_ms()를 읽습니다. 락 밖에서 읽으면 그 사이 sampler가 "미래" 타임스탬프를 넣어 now - t가 음수(→ uint32_t로 아주 큰 수)가 되는 경합이 생길 수 있습니다.
  • sampler_stop: running = false 후 pthread_join. sampler가 read_temp() 안에 있으면 그 읽기가 끝날 때까지(최대 1 s, 여기선 200 ms) 기다립니다. 테스트 7번이 이 상한을 확인합니다.
  • get_latest_temp의 반환을 bool + out 파라미터로 둔 이유: int16_t 하나로는 "아직 값 없음"을 표현할 값이 없습니다(모든 값이 유효한 온도).
  • 하네스의 g_dev_overlap은 read_temp() 동시 진입을 감지합니다. 테스트 7번에서 false여야 합니다.

4.5 복잡도

  • get_latest_temp: O(1), 락 보유 시간은 복사 몇 번.
  • is_overheating: O(W), W = 윈도우 안 샘플 수(≈ 5). 최대 HIST_CAP = 16.
  • 메모리: 링버퍼 16 × 8바이트 + 스레드 1개. malloc 없음.

5. 임베디드 관점으로 말할 것

  • "센서 소유자는 하나": 버스·주변장치는 담당 스레드(또는 RTOS 태스크) 하나가 소유하고, 나머지는 메시지/공유 캐시로만 접근하는 게 임베디드의 표준 패턴입니다. 락으로 직렬화하는 것보다 단순하고 우선순위 역전도 없습니다.
  • 락 밖 I/O: 블로킹 I/O를 락 안에서 하면 모든 읽기 스레드가 I/O 시간만큼 막히고, RTOS에서는 높은 우선순위 태스크가 낮은 우선순위 태스크의 I2C를 기다리는 우선순위 역전이 생깁니다.
  • fail-safe 정책: 센서가 계속 TEMP_ERR이면 윈도우가 비어 is_overheating이 false가 됩니다. 안전 관점에서는 "모름"을 과열 쪽으로 처리해야 할 수 있습니다. 실무 API라면 enum { OK, HOT, STALE } 3상태로 돌려줍니다 → T1-6.
  • RTOS 버전: pthread 대신 태스크 1개 + 뮤텍스(또는 크리티컬 섹션). latest가 32비트 이하면 atomic store/load 한 번으로 락 없이도 됩니다(Cortex-M에서 정렬된 32비트 접근은 원자적).

6. Follow-up 질문과 답

Follow-up (English)답
Can get_latest_temp be lock-free?(valid << 16) | (uint16_t)temp를 _Atomic uint32_t 하나에 담아 store/load. 값과 유효 플래그가 한 워드라 찢어지지 않습니다. 링버퍼까지 락 없이 하려면 seqlock이 필요합니다.
Reads might be much faster than 1 s. Is the ring still enough?아닙니다. 16칸이 5초보다 빨리 차면 윈도우 안 샘플을 잃어 max가 틀립니다. 샘플러를 고정 주기로 페이싱하거나, 초 단위 버킷 max(6칸)로 바꾸면 샘플 속도와 무관하게 O(1) 메모리입니다 → T2-4의 단조 덱도 대안.
stop() must return within 10 ms.진행 중인 read_temp()는 끊을 수 없으므로 pthread_join을 기다리지 않는 detach + "종료 중" 플래그, 또는 드라이버에 타임아웃/취소 API가 필요합니다. 읽기 사이에 쉬는 구간이 있다면 pthread_cond_timedwait로 즉시 깨웁니다.
Readers want fresh data on demand instead of a background thread.요청 결합(single-flight): 첫 요청자만 읽고 나머지는 condvar로 그 결과를 기다림. Verkada 원본 유형 → 04_temp_single_flight.
What if the clock is wall time and NTP steps it backwards?CLOCK_MONOTONIC을 씁니다. 벽시계가 뒤로 가면 now - t가 랩되어 거대한 값 → 윈도우가 통째로 비어 보입니다.

7. 자주 하는 실수

  • read_temp()를 락 안에서 호출 → get_latest_temp()가 진행 중인 읽기만큼(여기선 최대 200 ms, 실제는 1 s) 막힘 (테스트 2번 실패)
  • get_latest_temp가 직접 read_temp()를 부름 → 블로킹 + 동시 진입 (g_dev_overlap true, 테스트 7번 실패)
  • 윈도우를 "최신 5개"로 구현 → 시간 기반이 아님 (테스트 4번의 7001 케이스 실패)
  • 스캔 중단 조건을 now - t >= 5000으로 → 정확히 5000 ms인 샘플을 버려 7000에서 false (테스트 4번 실패)
  • TEMP_ERR를 그대로 publish → latest가 −3276.8 °C (테스트 5번 실패)
  • stop()을 두 번 부르면 pthread_join을 두 번 → 미정의 동작. g_started 플래그로 막음
