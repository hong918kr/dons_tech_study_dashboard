0. 문제 한국어로 먼저 보기

영어 원문(§1)을 읽기 전에 무슨 상황이고 뭘 만들어야 하는지만 빠르게 잡는 요약입니다. 풀이 힌트는 없습니다.

한 줄 요약: first silicon bring-up/validation 코드 조각 10개(D1–D10)에 각각 버그가 정확히 하나씩 있습니다. 1–2분 안에 찾아 말하고 고칩니다.

상황

  • 면접관이 짧은 bring-up/validation 코드를 보여 주고 묻습니다: "FPGA에서는 되는데 first silicon에서는 안 돼요(또는 가끔만 안 돼요). 뭐가 문제죠?" 조각 하나에 1–2분.
  • 함수 10개가 전부 buggy.c에 있고, 각각 옆에 작은 mock HW model이 붙어 있습니다.
    • MMIO read 횟수 counter, W1C 레지스터(1을 쓰면 그 비트가 지워짐), separate copy array로 흉내 낸 D-cache, descriptor를 snoop하는 DMA engine, fake timer, canary word(영역 바깥을 건드렸는지 보는 표식 값)가 들어 있는 fake RAM
  • 테스트 main()은 crash나 hang 없이 버그 10개를 모두 드러냅니다. 목표는 ALL PASS 출력.

드릴마다 내가 내놓을 것

  1. 의도한 동작과 실제 HW에서의 증상을 읽음 (buggy.c의 Intended 주석).
  2. 버그를 한 문장으로 말하고, 어떤 입력이나 타이밍에서 터지는지 말함.
  3. 고친 줄을 씀.
  4. 어떻게 미리 잡을 수 있었는지 말함 (compiler warning, sanitizer, static analysis, review checklist, directed test 중).

D8 field_get()reg의 bits [lsb + width - 1 : lsb]를 오른쪽 정렬해서 반환. 1 <= width <= 32, lsb + width <= 32 (width 32 = 레지스터 전체)일반 필드는 정상. field_get(0xABCD1234, 0, 32)는 0xABCD1234여야 함. §2에 따르면 이 드릴은 UBSan runtime error가 먼저 찍힘

지켜야 할 조건

  • 함수 body만 바꿈 (D7은 struct 선언도 바꿔도 됨).
  • mock HW helper(dma_status_read, intc_read/intc_write, cpu_rd/cpu_wr/dcache_*, dma_copy, hw_snoop, DESC_WR, timer_now, pll_status_read)와 TEST GUARD 표시 줄은 그대로 둠. 실제 HW 대신 bus/cache/DMA engine이 본 것을 테스트가 확인하려고 있는 코드임.
  • 고친 파일은 -Wall -Wextra -Werror -fsanitize=address,undefined로 통과해야 함.

1. Problem

The interviewer shares a short piece of bring-up / validation code and asks: "This works on the FPGA but fails on first silicon (or only sometimes). What is wrong?" You get one to two minutes per snippet.

For each of the ten drills below:

  1. Read the intended behavior and the symptom on real hardware.
  2. Name the bug in one sentence, and say which input or timing triggers it.
  3. Write the fixed line.
  4. Say how you would have caught it (compiler warning, sanitizer, static analysis, review checklist, a directed test).

All ten functions live in buggy.c, each next to a tiny mock HW model (MMIO read counter, W1C register, D-cache modelled as a separate copy array, a DMA engine that snoops descriptors, a fake timer, fake RAM with canary words). The test main() exposes every bug without crashing or hanging. Your job is to make it print ALL PASS.

Constraints

  • Change only the function bodies (and, for D7, the struct declaration).
  • Keep the mock HW helpers (dma_status_read, intc_read/intc_write, cpu_rd/cpu_wr/dcache_*, dma_copy, hw_snoop, DESC_WR, timer_now, pll_status_read) and the line marked TEST GUARD as they are. They stand in for hardware and only exist so the test can see what the bus, the cache and the DMA engine saw.
  • The fixed file must pass with -Wall -Wextra -Werror -fsanitize=address,undefined.

Clarifying questions to ask

  1. What are the register access semantics? (RW, RO, W1C, write-only, read-to-clear)
  2. Is the DMA cache-coherent with the CPU on this SoC (ACE/CHI port), or do I manage cache maintenance by hand?
  3. What is the width and frequency of the timer / cycle counter, i.e. how often does it wrap?
  4. What endianness is the device or the dump format? Is the CPU running little-endian?
  5. Is this code running from a cached region, with the MMU on, or on a bare-metal flat map?

buggy.c
/*
 * D  Debug Drills (D1-D10) — silicon validation / bring-up flavor
 *
 * Ten short bare-metal functions of the kind a silicon-validation engineer writes
 * on first silicon: poll a status bit, ack an interrupt, run a DMA loopback, hand a
 * descriptor to hardware, wait for a PLL lock, decode a register dump, map a register
 * block, extract a bit field, report bandwidth, run a memory test.
 * Each one compiles and "looks right", but each has exactly ONE realistic bug.
 * For every drill:
 *   1. read the "Intended" comment,
 *   2. say the bug out loud in under a minute (and which input triggers it),
 *   3. fix it with a one-line (or few-line) change.
 *
 * There is no real hardware here. Each drill has a tiny mock HW model
 * (a counter of MMIO reads, a W1C status register, a D-cache modelled as a separate
 * copy array, a DMA engine that snoops descriptors, a fake timer, a fake RAM with
 * canary words). The test main() exposes every bug WITHOUT crashing or hanging.
 *
 * Buggy version.  Build & run:  ./run.sh D buggy     (copy to my.c, fix, ./run.sh D my)
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

/* ------------------------------------------------------------------------------------
 * D1  Poll a DMA status register until DONE.
 * Intended: poll DMA_STATUS until bit DONE is 1. Return the number of polls that saw
 *           DONE == 0 (0 if it was already done), or -1 after max_polls polls.
 *           Every poll must be a real bus read of the register.
 *
 * Source as written on the bench:
 *     #define DMA_STATUS (*(uint32_t *)0x40001004u)        // no volatile
 *     while (!(DMA_STATUS & DMA_DONE)) { ... }
 * At -O2 the compiler may load DMA_STATUS once and spin on the register copy.
 * The body below is that compiled behavior, written out in C so the host test can see it.
 * Mock HW: dma_status_read() is one bus read; DONE reads 1 from the Nth read on.
 * ---------------------------------------------------------------------------------- */
#define DMA_DONE (1u << 0)
static uint32_t g_d1_reads, g_d1_done_on_read;

static uint32_t dma_status_read(void)          /* models one MMIO load */
{
    g_d1_reads++;
    return g_d1_reads >= g_d1_done_on_read ? DMA_DONE : 0u;
}

int wait_dma_done(uint32_t max_polls)
{
    uint32_t st = dma_status_read();
    for (uint32_t i = 0; i < max_polls; i++) {
        if (st & DMA_DONE) return (int)i;
    }
    return -1;
}

/* ------------------------------------------------------------------------------------
 * D2  Acknowledge one interrupt source.
 * Intended: INT_STATUS is write-1-to-clear (W1C): writing 1 to a bit clears it,
 *           writing 0 leaves it alone. irq_ack(bit) must clear ONLY that bit and
 *           leave every other pending source pending.
 * Mock HW: intc_read()/intc_write() are the bus accessors of a W1C register.
 * ---------------------------------------------------------------------------------- */
#define IRQ_TX_DONE (1u << 0)
#define IRQ_RX_DONE (1u << 1)
#define IRQ_ERR     (1u << 4)
static uint32_t g_int_status;                     /* hardware latch */

static uint32_t intc_read(void)        { return g_int_status; }
static void     intc_write(uint32_t v) { g_int_status &= ~v; }   /* W1C semantics */

void irq_ack(uint32_t bit)
{
    intc_write(intc_read() | bit);
}

/* ------------------------------------------------------------------------------------
 * D3  DMA memory-to-memory loopback test with a write-back D-cache.
 * Intended: CPU writes a pattern into src, DMA copies src -> dst, CPU checks dst.
 *           Return the number of mismatching words (0 = pass). Must pass on every
 *           run, not only the first one.
 * Mock HW: ddr[] is DRAM (what DMA sees). dc_*[] is the CPU D-cache: one word per
 *          "line", write-back. The DMA engine reads/writes ddr[] only (not coherent).
 * ---------------------------------------------------------------------------------- */
#define RAM_WORDS 64
static uint32_t ddr[RAM_WORDS];
static uint32_t dc_data[RAM_WORDS];
static bool     dc_valid[RAM_WORDS], dc_dirty[RAM_WORDS];

static uint32_t cpu_rd(uint32_t a)
{
    if (!dc_valid[a]) { dc_data[a] = ddr[a]; dc_valid[a] = true; }   /* line fill */
    return dc_data[a];
}
static void cpu_wr(uint32_t a, uint32_t v) { dc_data[a] = v; dc_valid[a] = dc_dirty[a] = true; }
static void dcache_clean(uint32_t a, uint32_t n)          /* write dirty lines back to DRAM */
{
    for (uint32_t i = a; i < a + n; i++)
        if (dc_valid[i] && dc_dirty[i]) { ddr[i] = dc_data[i]; dc_dirty[i] = false; }
}
static void dcache_invalidate(uint32_t a, uint32_t n)     /* drop lines; next read refills */
{
    for (uint32_t i = a; i < a + n; i++) dc_valid[i] = dc_dirty[i] = false;
}
static void dma_copy(uint32_t src, uint32_t dst, uint32_t n)   /* start + wait for DONE */
{
    for (uint32_t i = 0; i < n; i++) ddr[dst + i] = ddr[src + i];
}

uint32_t dma_loopback_test(uint32_t src, uint32_t dst, uint32_t n, uint32_t seed)
{
    for (uint32_t i = 0; i < n; i++) cpu_wr(src + i, seed + i * 0x01010101u);
    dcache_clean(src, n);                       /* make the pattern visible to DMA */
    dma_copy(src, dst, n);
    uint32_t bad = 0;
    for (uint32_t i = 0; i < n; i++)
        if (cpu_rd(dst + i) != seed + i * 0x01010101u) bad++;
    return bad;
}

/* ------------------------------------------------------------------------------------
 * D4  Hand a TX descriptor to the DMA engine.
 * Intended: fill buf_addr and length, then give the descriptor to HW by setting OWN.
 *           The engine may fetch the descriptor at ANY moment once OWN = 1, so it
 *           must see the new buf_addr and length together with OWN.
 * Layout:   ctrl[31] = OWN (1 = owned by HW), ctrl[30] = IOC (irq on complete),
 *           ctrl[15:0] = length in bytes.
 * Mock HW:  DESC_WR() is one store to descriptor memory; after every store the engine
 *           snoops the descriptor and, the first time it sees OWN = 1, latches a copy.
 * ---------------------------------------------------------------------------------- */
#define DESC_OWN (1u << 31)
#define DESC_IOC (1u << 30)
typedef struct { uint32_t buf_addr; uint32_t ctrl; } DmaDesc;
static DmaDesc g_hw_seen;                       /* what the engine fetched */
static bool    g_hw_took;

static void hw_snoop(const DmaDesc *d)
{
    if (!g_hw_took && (d->ctrl & DESC_OWN)) { g_hw_seen = *d; g_hw_took = true; }
}
#define DESC_WR(d, field, v) do { (d)->field = (v); hw_snoop(d); } while (0)
static inline void dma_wmb(void) { /* real HW: __DSB() / wmb(); no-op in the model */ }

void desc_submit(DmaDesc *d, uint32_t buf, uint16_t len)
{
    DESC_WR(d, ctrl, DESC_OWN | DESC_IOC | len);
    dma_wmb();
    DESC_WR(d, buf_addr, buf);
}

/* ------------------------------------------------------------------------------------
 * D5  Wait for PLL lock with a timeout on a free-running 32-bit timer.
 * Intended: poll PLL_STATUS.LOCK. Return the number of polls that saw LOCK == 0, or
 *           -1 once at least `timeout` ticks have elapsed since the start.
 *           The timer wraps from 0xFFFFFFFF to 0, and that must not matter.
 *           d5_elapsed records the ticks elapsed when the timeout fired.
 * Mock HW:  timer_now() advances 1000 ticks per call. LOCK reads 1 from the Nth read on
 *           (N = 0 means the PLL never locks: fault injection).
 * ---------------------------------------------------------------------------------- */
#define PLL_LOCK (1u << 0)
static uint32_t g_tick, g_pll_reads, g_pll_lock_on_read, d5_elapsed;

static uint32_t timer_now(void) { uint32_t t = g_tick; g_tick += 1000u; return t; }
static uint32_t pll_status_read(void)
{
    g_pll_reads++;
    return (g_pll_lock_on_read && g_pll_reads >= g_pll_lock_on_read) ? PLL_LOCK : 0u;
}

int wait_pll_lock(uint32_t timeout)
{
    uint32_t start = timer_now();
    int polls = 0;
    while (!(pll_status_read() & PLL_LOCK)) {
        uint32_t now = timer_now();
        if (now > start + timeout) { d5_elapsed = now - start; return -1; }
        polls++;
        if (polls > 100000) return -2;        /* TEST GUARD (not part of the drill) */
    }
    return polls;
}

/* ------------------------------------------------------------------------------------
 * D6  Decode a 32-bit register value from a debug-UART dump.
 * Intended: the on-chip debug monitor dumps each 32-bit register as 4 bytes,
 *           LITTLE-endian on the wire: b[0] = bits 7..0, ..., b[3] = bits 31..24.
 *           Return the register value.
 * ---------------------------------------------------------------------------------- */
uint32_t reg_from_dump(const uint8_t b[4])
{
    return ((uint32_t)b[0] << 24) | ((uint32_t)b[1] << 16) |
           ((uint32_t)b[2] << 8)  |  (uint32_t)b[3];
}

/* ------------------------------------------------------------------------------------
 * D7  Register map of a UART block (datasheet):
 *       0x00 CTRL   0x04 STATUS   0x08-0x0F reserved   0x10 INT_EN   0x14 DATA
 *     All registers are 32-bit. Block size 0x18.
 * Intended: uart_enable_rx_irq() sets INT_EN.RX (bit 0) at offset 0x10.
 * Mock HW:  uart_block[] is the register block; the fake UART decodes it by offset.
 * ---------------------------------------------------------------------------------- */
#define UART_INT_RX (1u << 0)
typedef struct {
    uint32_t CTRL;          /* 0x00 */
    uint32_t STATUS;        /* 0x04 */
    uint16_t RESERVED[2];   /* 0x08 - 0x0F */
    uint32_t INT_EN;        /* 0x10 */
    uint32_t DATA;          /* 0x14 */
} UartRegs;
static uint32_t uart_block[8];

void uart_enable_rx_irq(volatile UartRegs *u)
{
    u->INT_EN |= UART_INT_RX;
}

/* ------------------------------------------------------------------------------------
 * D8  Extract a bit field from a register value.
 * Intended: return bits [lsb + width - 1 : lsb] of reg, right-aligned.
 *           Valid for 1 <= width <= 32 and lsb + width <= 32 (width 32 = whole register).
 * ---------------------------------------------------------------------------------- */
uint32_t field_get(uint32_t reg, unsigned lsb, unsigned width)
{
    uint32_t mask = (1u << width) - 1u;
    return (reg >> lsb) & mask;
}

/* ------------------------------------------------------------------------------------
 * D9  Report DMA bandwidth from a cycle-counter measurement.
 * Intended: `bytes` were moved in `cycles` cycles of a `clk_mhz` MHz counter.
 *           Return MB/s (10^6 bytes per second), truncated:
 *             MB/s = bytes / (cycles / clk_mhz [us]) = bytes * clk_mhz / cycles.
 *           Must be exact for bytes up to 4 GiB - 1 and clk_mhz up to 2000.
 * ---------------------------------------------------------------------------------- */
uint32_t bw_mbps(uint32_t bytes, uint32_t cycles, uint32_t clk_mhz)
{
    uint64_t bw = bytes * clk_mhz / cycles;
    return (uint32_t)bw;
}

/* ------------------------------------------------------------------------------------
 * D10 Write/read-back memory test over a region given in BYTES.
 * Intended: for every 32-bit word in [base, base + len_bytes) write a pattern, then
 *           read all words back. Return the number of mismatching words.
 *           Must not touch a single byte outside the region.
 * Mock HW:  fake_ram[0..15] is the region under test (64 bytes); the words after it
 *           are canaries standing in for "whatever lives next to the region".
 * ---------------------------------------------------------------------------------- */
#define D10_REGION_WORDS 16
#define D10_RAM_WORDS    (D10_REGION_WORDS * 4 + 16)   /* big enough that a 4x overrun stays in-bounds */
#define CANARY(i)        (0xC0FFEE00u | (uint32_t)(i))
static uint32_t fake_ram[D10_RAM_WORDS];

uint32_t mem_test(uint32_t *base, size_t len_bytes)
{
    uint32_t *end = base + len_bytes;
    for (uint32_t *p = base; p < end; p++) *p = 0xA5A50000u ^ (uint32_t)(p - base);
    uint32_t bad = 0;
    for (uint32_t *p = base; p < end; p++)
        if (*p != (0xA5A50000u ^ (uint32_t)(p - base))) bad++;
    return bad;
}

/* ================================== tests ======================================== */
static int g_sec_fail;
static void begin(void) { g_sec_fail = g_fail; }
static void end(const char *name) { printf("%-30s %s\n", name, g_fail == g_sec_fail ? "ok" : "<-- BUG"); }

int main(void)
{
    /* D1 */
    begin();
    g_d1_reads = 0; g_d1_done_on_read = 1;
    CHECK(wait_dma_done(100) == 0);                        /* already done */
    g_d1_reads = 0; g_d1_done_on_read = 4;                 /* DONE appears on the 4th read */
    CHECK(wait_dma_done(100) == 3);
    CHECK(g_d1_reads == 4);                                /* one bus read per poll */
    g_d1_reads = 0; g_d1_done_on_read = 1000;              /* never within budget */
    CHECK(wait_dma_done(10) == -1);
    CHECK(g_d1_reads == 10);
    end("D1 poll without volatile");

    /* D2 */
    begin();
    g_int_status = IRQ_TX_DONE;
    irq_ack(IRQ_TX_DONE);
    CHECK(intc_read() == 0);                              /* normal: one source */
    g_int_status = IRQ_TX_DONE | IRQ_RX_DONE | IRQ_ERR;    /* three sources pending */
    irq_ack(IRQ_TX_DONE);
    CHECK(intc_read() == (IRQ_RX_DONE | IRQ_ERR));        /* RX and ERR must survive */
    end("D2 W1C read-modify-write");

    /* D3 */
    begin();
    memset(ddr, 0, sizeof ddr); dcache_invalidate(0, RAM_WORDS);          /* cold start */
    CHECK(dma_loopback_test(0, 32, 16, 0x11110000u) == 0); /* run 1: dst not in cache yet */
    CHECK(dma_loopback_test(0, 32, 16, 0x22220000u) == 0); /* run 2: dst lines cached by run 1 */
    CHECK(ddr[32 + 5] == 0x22220000u + 5u * 0x01010101u);  /* DMA itself did write DRAM */
    end("D3 DMA cache coherency");

    /* D4 */
    begin();
    DmaDesc d = { 0xDEAD0000u, 0 };                        /* stale buf_addr from the last use */
    g_hw_took = false;
    desc_submit(&d, 0x80001000u, 256);
    CHECK(g_hw_took);
    CHECK(g_hw_seen.buf_addr == 0x80001000u);              /* engine must fetch the NEW buffer */
    CHECK((g_hw_seen.ctrl & 0xFFFFu) == 256u);
    CHECK(d.buf_addr == 0x80001000u && (d.ctrl & DESC_OWN));
    end("D4 descriptor OWN ordering");

    /* D5 */
    begin();

    CHECK(d5_elapsed >= 50000 && d5_elapsed <= 51000);
    g_tick = 0xFFFFF000u; g_pll_reads = 0; d5_elapsed = 0; /* start 4096 ticks before wrap */
    CHECK(wait_pll_lock(50000) == -1);
    CHECK(d5_elapsed >= 50000 && d5_elapsed <= 51000);     /* must not give up early */
    end("D5 timeout across wrap");

    begin();
    const uint8_t id[4]  = { 0x78, 0x56, 0x34, 0x12 };    /* CHIP_ID = 0x12345678 */
    const uint8_t one[4] = { 0x01, 0x00, 0x00, 0x00 };

    begin();

3. 힌트 (막힐 때 하나씩)

Hint 1 — 어디부터 의심하나

실리콘 bring-up 코드 버그는 대부분 다섯 종류입니다. (1) 컴파일러가 HW 접근을 바꿈(volatile 없음), (2) 레지스터 의미(W1C, RO, read-to-clear), (3) 메모리 순서·캐시(DMA coherency, OWN 비트 순서, barrier), (4) 정수 폭(overflow, shift, wrap), (5) 레이아웃·단위(struct offset, endianness, byte vs word). 스니펫을 보면 "HW는 이 순간 무엇을 보나?"와 "타입이 몇 비트지?"를 먼저 묻습니다.

Hint 2 — 숫자를 하나 넣어 보기
  • D2: pending이 0x13이고 TX(bit 0)만 지우려 할 때, 실제로 쓰는 값은?
  • D5: start = 0xFFFFF000, timeout = 50000이면 start + timeout은?
  • D8: width = 32면 1u << 32는?
  • D9: 16777216 * 1000은 2^32보다 큰가?
  • D10: uint32_t *base에 + 64를 하면 몇 바이트 뒤인가?
Hint 3 — 도구가 알려 주는 것

./run.sh는 ASan/UBSan을 켭니다. 도구가 잡는 것은 D8 하나(UBSan shift exponent 32)뿐입니다. D7은 _Static_assert(offsetof(...))를 넣었다면 컴파일이 막혔을 것입니다. D10은 실제 보드라면 ASan 대신 canary/MPU가 잡습니다(여기서는 fake RAM이 4배 크기라 ASan도 조용함). 나머지 D1–D6, D9는 HW 모델 + 방향성 테스트로만 드러납니다. 그래서 validation 엔지니어는 "도구 + 경계값 테스트 + 리뷰 체크리스트"를 같이 씁니다.

4. 풀이

4.1 핵심 아이디어

각 드릴에서 말할 순서는 항상 같습니다: ① 버그 한 문장 → ② 터지는 입력/타이밍 → ③ 고친 한 줄 → ④ 어떻게 찾았을지. HW 면접관에게는 여기에 ⑤ 첫 실리콘에서 어떻게 보였을지(scope, 로그, JTAG)를 한 줄 붙이면 좋습니다. 아래는 드릴별 문제(English)와 힌트·답(펼치기)입니다.

D1 · Poll a status register

Intended behavior: poll DMA_STATUS until bit DONE is 1. Return the number of polls that saw DONE == 0, or -1 after max_polls polls. Every poll must be a real bus read.

Source as written on the bench:

#define DMA_STATUS (*(uint32_t *)0x40001004u)      /* no volatile */
int wait_dma_done(uint32_t max_polls) {
    for (uint32_t i = 0; i < max_polls; i++)
        if (DMA_STATUS & DMA_DONE) return (int)i;
    return -1;
}

buggy.c writes out what -O2 is allowed to make of this: one load before the loop, then a loop over the register copy.

Symptom on first silicon: works with -O0 and under the debugger; the -O2 release build always reports "DMA timeout". A logic analyzer / AXI monitor shows exactly one read of 0x40001004, then nothing.

D1 힌트

컴파일러 입장에서 *(uint32_t *)0x40001004는 그냥 메모리입니다. 루프 안에서 아무도 그 메모리에 쓰지 않는데, 매번 다시 읽어야 할 이유가 있을까요?

💡 D1 답 펼치기

버그: 레지스터 포인터에 volatile이 없어서 컴파일러가 읽기를 루프 밖으로 끌어냅니다(loop-invariant hoisting). 첫 읽기에서 DONE이 0이면 이후 max_polls번 같은 값을 보고 -1을 돌려줍니다. 테스트: DONE이 4번째 읽기에 1이 되도록 하면 정답은 3, 버그 버전은 -1이고 버스 읽기 횟수는 4가 아니라 1입니다.

고친 코드

#define DMA_STATUS (*(volatile uint32_t *)0x40001004u)
for (uint32_t i = 0; i < max_polls; i++)
    if (DMA_STATUS & DMA_DONE) return (int)i;   /* 매 반복 새 버스 읽기 */

fixed.c에서는 dma_status_read()를 루프 안에서 매번 부르는 것으로 같은 의미를 표현합니다. 실제 코드는 readl() / REG32() 같은 volatile 접근자를 쓰고, 레지스터 포인터를 직접 역참조하지 않는 것을 규칙으로 둡니다.

어떻게 찾나

  • 컴파일러·sanitizer는 못 잡습니다(최적화로서 합법).
  • 리뷰 체크리스트: "MMIO 접근은 모두 volatile 접근자를 거치는가?" grep으로 (uint32_t *)0x 같은 생 캐스트를 찾습니다.
  • 디스어셈블: 루프에 ldr이 없으면 바로 보입니다. "-O0에서 되고 -O2에서 안 된다"는 증상은 거의 항상 volatile 아니면 UB입니다.
  • volatile은 컴파일러만 막습니다. CPU 쪽 순서(Device memory 속성, barrier)는 D4에서 따로 다룹니다.

D2 · Acknowledge one interrupt source (W1C)

Intended behavior: INT_STATUS is write-1-to-clear: writing 1 to a bit clears it, writing 0 leaves it alone. irq_ack(bit) must clear only that bit and leave every other pending source pending.

void irq_ack(uint32_t bit) {
    intc_write(intc_read() | bit);       /* i.e. INT_STATUS |= bit; */
}

Symptom on first silicon: under load, RX completions and error interrupts are "sometimes lost". The interrupt line drops after the TX handler runs even though RX data is in the FIFO; the error counter in the log stays at 0 while the PHY reports CRC errors.

D2 힌트

|=는 "읽고, OR하고, 쓰기"입니다. 읽은 값에는 지금 pending인 모든 비트가 1로 들어 있습니다. W1C 레지스터에 그 값을 그대로 다시 쓰면?

💡 D2 답 펼치기

버그: W1C 레지스터에 read-modify-write를 했습니다. pending이 0x13(TX, RX, ERR)이면 쓰는 값도 0x13이 되어 세 비트가 모두 지워집니다. 결과 0x00, 기대값 0x12. RX와 ERR 이벤트가 처리되기 전에 사라집니다.

고친 한 줄

intc_write(bit);                         /* INT_STATUS = bit; */

어떻게 찾나

  • 도구는 못 잡습니다. 레지스터 맵의 access type(RW/RO/W1C/RC)을 헤더에 같이 생성하고, W1C 필드에 |=를 쓰지 못하게 하는 접근자(reg_w1c(addr, mask))를 두는 것이 근본 해결입니다.
  • 방향성 테스트: 소스 2개 이상을 동시에 pending시키고 하나만 ack한 뒤 나머지가 남아 있는지 확인합니다(validation에서 "interrupt aggregation" 테스트).
  • 같은 함정: 같은 레지스터에 RW 필드와 W1C 필드가 섞여 있으면 RW 필드를 바꾸려는 RMW가 W1C 비트를 지웁니다. 이때는 W1C 비트 위치를 0으로 마스킹하고 씁니다: reg = (reg & ~W1C_MASK) | new_rw_bits;. 자세한 버전은 V2.

D3 · DMA loopback with a write-back D-cache

Intended behavior: CPU writes a pattern into src, DMA copies src → dst, CPU checks dst. Return the number of mismatching words. Must pass on every run, not only the first one. The DMA engine is not cache-coherent.

for (i = 0; i < n; i++) cpu_wr(src + i, seed + i * 0x01010101u);
dcache_clean(src, n);                    /* make the pattern visible to DMA */
dma_copy(src, dst, n);                   /* start + wait for DONE */
for (i = 0; i < n; i++)
    if (cpu_rd(dst + i) != seed + i * 0x01010101u) bad++;

Symptom on first silicon: the DMA loopback test passes right after reset, then fails on the second and later iterations with every word wrong. The "wrong" data is exactly the previous iteration's pattern. Dumping dst over JTAG (which reads DRAM, not the cache) shows correct data.

D3 힌트

첫 번째 실행의 검증 루프가 dst를 읽으면서 그 라인들은 캐시에 들어왔습니다. 두 번째 실행에서 DMA가 DRAM에 새 데이터를 쓰면, CPU의 캐시는 그 사실을 알까요?

💡 D3 답 펼치기

버그: DMA가 끝난 뒤 dst의 캐시 라인을 invalidate하지 않았습니다. 1회차 검증에서 dst 라인이 캐시에 올라왔고, 2회차에 DMA가 DRAM에 0x27270505(word 5)를 써도 CPU는 캐시 hit로 1회차 값 0x16160505를 읽습니다. 16개 word 모두 mismatch → bad = 16. DRAM 자체(ddr[37])는 맞습니다.

고친 한 줄

dma_copy(src, dst, n);
dcache_invalidate(dst, n);               /* device wrote it -> drop CPU copies */

규칙은 두 개입니다. 장치가 메모리를 읽기 전에 clean(src), CPU가 장치가 쓴 메모리를 읽기 전에 invalidate(dst). 실제 Cortex-A에서는 추측성 prefetch가 DMA 도중 dst 라인을 다시 채울 수 있어서, DMA 시작 전에 clean+invalidate 하고 끝난 후에 다시 invalidate하는 것이 안전합니다(Linux dma_unmap_single(DMA_FROM_DEVICE)가 하는 일). 버퍼는 캐시 라인(64 B) 정렬·크기여야 invalidate가 이웃 데이터를 버리지 않습니다.

어떻게 찾나

  • 도구는 못 잡습니다. 같은 테스트를 2회 이상, 다른 seed로 돌리는 것이 핵심입니다(이 드릴에서도 1회차는 통과).
  • 진단 요령: JTAG로 DRAM을 직접 읽으면 맞고 CPU가 읽으면 틀리면 coherency 문제. 캐시를 끄거나(SCTLR.C=0) 버퍼를 non-cacheable로 매핑해서 증상이 사라지면 확정입니다.
  • SoC 질문: "이 DMA 마스터는 ACE-Lite/CHI로 coherent interconnect에 붙어 있나?" coherent면 maintenance가 필요 없지만, 실리콘 초기에는 coherency를 끄고 테스트하는 경우가 많습니다. 자세한 링 버퍼 버전은 V3.

D4 · Hand a descriptor to the DMA engine (OWN bit)

Intended behavior: fill buf_addr and length, then give the descriptor to hardware by setting OWN. The engine may fetch the descriptor at any moment once OWN = 1, so it must see the new buf_addr and length together with OWN. Layout: ctrl[31] = OWN, ctrl[30] = IOC, ctrl[15:0] = length.

void desc_submit(DmaDesc *d, uint32_t buf, uint16_t len) {
    d->ctrl = DESC_OWN | DESC_IOC | len;
    dma_wmb();
    d->buf_addr = buf;
}

Symptom on first silicon: rare, load-dependent data corruption: occasionally a packet is transmitted from the previous buffer, or the engine raises a bus error on a stale address (here 0xDEAD0000). It never happens on the FPGA (slow engine, fetches late) and gets worse at higher DMA clock.

D4 힌트

OWN을 쓰는 순간부터 descriptor는 HW 것입니다. 그 순간 buf_addr에는 어떤 값이 들어 있나요? barrier는 어느 두 store 사이에 있어야 할까요?

💡 D4 답 펼치기

버그: OWN을 먼저 쓰고 나머지 필드를 나중에 씁니다. 엔진이 OWN=1을 본 순간 가져간 descriptor는 buf_addr = 0xDEAD0000(지난번 값), ctrl = 0xC0000100입니다. barrier가 있긴 하지만 엉뚱한 위치(OWN 뒤)에 있습니다.

고친 코드

d->buf_addr = buf;                       /* 1. payload fields */
dma_wmb();                               /* 2. make them visible first */
d->ctrl = DESC_OWN | DESC_IOC | len;     /* 3. OWN last = hand-off */
/* 4. (if the engine is idle) write the doorbell / tail pointer register */

반대 방향도 같습니다. 완료 처리할 때는 OWN==0을 먼저 읽고, dma_rmb() 후에 status/length를 읽습니다. 순서가 바뀌면 HW가 아직 쓰기 전의 length를 읽습니다.

어떻게 찾나

  • 도구는 못 잡습니다. 리뷰 체크리스트: "ownership 비트는 마지막에 쓰고, 그 앞에 write barrier가 있는가?"
  • C 컴파일러도 일반 store 순서를 바꿀 수 있고(descriptor가 volatile이 아니면), Arm의 Normal memory는 CPU도 store 순서를 바꿉니다. 그래서 volatile만으로는 부족하고 dmb oshst/dsb 같은 barrier가 필요합니다.
  • 실리콘에서 재현: DMA 클럭을 올리고 descriptor를 연속 제출하는 스트레스 테스트, 또는 엔진 쪽 AXI 트레이스에서 descriptor fetch 시점과 CPU store 시점을 비교합니다. FPGA는 엔진이 느려서 순서 버그가 숨는 대표적인 경우입니다.

D5 · PLL lock timeout on a wrapping timer

Intended behavior: poll PLL_STATUS.LOCK. Return the number of polls that saw LOCK == 0, or -1 once at least timeout ticks have elapsed since the start. The 32-bit timer wraps from 0xFFFFFFFF to 0, and that must not matter.

uint32_t start = timer_now();
while (!(pll_status_read() & PLL_LOCK)) {
    uint32_t now = timer_now();
    if (now > start + timeout) return -1;
    ...
}

Symptom on first silicon: about once every 43 s of uptime (a 100 MHz 32-bit counter wraps every 42.9 s), PLL lock "fails" after almost no time and the boot falls back to the bypass clock. Power-cycle and it is fine. In PVT runs this looks like a random lock-failure rate, which is the worst kind of false failure.

D5 힌트

start가 랩 직전(0xFFFFF000)이면 start + timeout은 작은 수가 됩니다. 첫 번째 now(0xFFFFF3E8)는 그 작은 수보다 큰가요?

💡 D5 답 펼치기

버그: 덧셈 비교 now > start + timeout은 start + timeout이 랩되면 깨집니다. 0xFFFFF000 + 50000 = 0x0000B350(45904)이고, 첫 poll의 now = 0xFFFFF3E8은 그보다 크므로 1000 tick 만에 타임아웃(d5_elapsed = 1000, 기대 50000). 반대로 start + timeout은 랩되지 않았는데 now가 먼저 랩하면 다음 한 바퀴 동안 타임아웃이 안 납니다(hang). 덤으로 >라 정확히 timeout인 순간을 한 poll 놓칩니다.

고친 한 줄

if ((uint32_t)(now - start) >= timeout) return -1;

부호 없는 뺄셈은 mod 2^32로 정의되어 있어서 경과 시간이 2^32보다 작기만 하면 랩과 무관하게 맞습니다. (uint32_t) 캐스트는 16-bit 카운터처럼 int로 승격되는 타입에서 꼭 필요하므로 습관으로 붙입니다.

어떻게 찾나

  • 컴파일러·sanitizer 모두 조용합니다(unsigned 랩은 정의된 동작).
  • 테스트: 타이머 초기값을 랩 직전으로 두는 시뮬레이션, 실리콘에서는 타이머를 0xFFFF0000 근처로 preload할 수 있으면 몇 ms 안에 재현됩니다.
  • 리뷰 체크리스트: "시간 비교는 항상 now - start로". V12의 timestamp 비교도 같은 원리입니다.

D6 · Rebuild a register value from a byte dump

Intended behavior: the on-chip debug monitor dumps each 32-bit register as 4 bytes, little-endian on the wire: b[0] = bits 7..0, …, b[3] = bits 31..24. Return the register value.

uint32_t reg_from_dump(const uint8_t b[4]) {
    return ((uint32_t)b[0] << 24) | ((uint32_t)b[1] << 16) |
           ((uint32_t)b[2] << 8)  |  (uint32_t)b[3];
}

Symptom on first silicon: the bring-up script prints CHIP_ID = 0x78563412 instead of the expected 0x12345678 and declares "wrong die". A status register with only bit 0 set reads 0x01000000, so the script decodes bit 24 instead of bit 0.

D6 힌트

{0x78, 0x56, 0x34, 0x12}를 받아서 0x12345678을 만들어야 합니다. b[0]은 몇 번 비트 자리로 가야 하나요?

💡 D6 답 펼치기

버그: 와이어 포맷은 little-endian인데 big-endian(MSB first)으로 조립합니다. {78 56 34 12} → 0x78563412, {01 00 00 00} → 0x01000000, {00 00 00 80} → 0x00000080. 바이트 순서가 뒤집힌 값이 나옵니다.

고친 코드

return  (uint32_t)b[0]        | ((uint32_t)b[1] << 8) |
       ((uint32_t)b[2] << 16) | ((uint32_t)b[3] << 24);

시프트로 조립하면 호스트 endianness와 무관합니다. memcpy(&v, b, 4)는 호스트가 LE일 때만 맞으므로(PC에서는 되고 BE 호스트에서는 틀림) 이식성 있는 코드에서는 피합니다. 각 바이트를 (uint32_t)로 캐스트하는 것도 중요합니다. 안 하면 b[3] << 24가 int로 계산되어 b[3] >= 0x80일 때 UB(D8과 같은 종류)입니다.

어떻게 찾나

  • 도구는 못 잡습니다. 비대칭 테스트 값(0x12345678, 0x00000001, 0x80000000)을 쓰는 것이 답입니다. 0x00000000, 0xFFFFFFFF, 0xA5A5A5A5처럼 바이트가 대칭인 값은 endianness 버그를 숨깁니다.
  • 실리콘 첫날 습관: CHIP_ID/버전 레지스터처럼 알려진 값을 먼저 읽어 버스·endianness·주소 디코드를 한 번에 확인합니다. 센서 쪽(I2C/SPI, 보통 MSB first)은 반대 방향이라는 것도 같이 말합니다.

D7 · Register-map struct layout

Intended behavior: datasheet map of a UART block, all registers 32-bit: 0x00 CTRL, 0x04 STATUS, 0x08–0x0F reserved, 0x10 INT_EN, 0x14 DATA. uart_enable_rx_irq() sets INT_EN.RX (bit 0) at offset 0x10.

typedef struct {
    uint32_t CTRL;          /* 0x00 */
    uint32_t STATUS;        /* 0x04 */
    uint16_t RESERVED[2];   /* 0x08 - 0x0F */
    uint32_t INT_EN;        /* 0x10 */
    uint32_t DATA;          /* 0x14 */
} UartRegs;
void uart_enable_rx_irq(volatile UartRegs *u) { u->INT_EN |= UART_INT_RX; }

Symptom on first silicon: RX interrupts never fire. Writes to DATA produce no TX activity on the scope. A bus trace shows the driver writing 0x0C and 0x10 instead of 0x10 and 0x14. The comments in the struct are correct; the struct is not.

D7 힌트

uint16_t RESERVED[2]는 몇 바이트인가요? 0x08부터 0x0F까지는 몇 바이트인가요? 주석의 오프셋은 컴파일러가 확인하지 않습니다.

💡 D7 답 펼치기

버그: reserved 영역을 uint16_t[2](4바이트)로 선언했는데 실제로는 8바이트(32-bit 2개)입니다. 그 뒤 필드가 모두 4바이트씩 당겨져서 offsetof(INT_EN) = 0x0C, offsetof(DATA) = 0x10, sizeof = 0x14(기대 0x10, 0x14, 0x18). 드라이버는 reserved 레지스터(0x0C)에 쓰고, DATA에 쓴다는 것이 실제로는 INT_EN에 씁니다.

고친 코드

uint32_t RESERVED[2];   /* 0x08 - 0x0F */
_Static_assert(offsetof(UartRegs, INT_EN) == 0x10, "UART INT_EN offset");
_Static_assert(offsetof(UartRegs, DATA)   == 0x14, "UART DATA offset");
_Static_assert(sizeof(UartRegs)           == 0x18, "UART block size");

_Static_assert가 진짜 수정입니다. 다음 사람이 필드를 잘못 바꿔도 빌드가 실패합니다.

어떻게 찾나

  • _Static_assert(offsetof(...)) 또는 pahole로 레이아웃 확인. 가장 좋은 방법은 레지스터 헤더를 손으로 쓰지 않고 IP-XACT/SystemRDL에서 생성하는 것입니다(실리콘 팀이 이미 RTL용으로 갖고 있음).
  • validation 테스트: register reset-value / walking-ones 테스트를 생성된 맵 기준으로 돌리면 오프셋이 틀린 레지스터에서 바로 실패합니다. 이 테스트가 bring-up 첫날 하는 일입니다.
  • 같은 종류: uint16_t로 선언한 32-bit 레지스터(접근 폭이 틀려 버스 에러 또는 상위 비트 유실), packed struct로 인한 unaligned 접근.

D8 · Bit-field mask generation

Intended behavior: return bits [lsb + width − 1 : lsb] of reg, right-aligned. Valid for 1 <= width <= 32 and lsb + width <= 32 (width 32 = whole register).

uint32_t field_get(uint32_t reg, unsigned lsb, unsigned width) {
    uint32_t mask = (1u << width) - 1u;
    return (reg >> lsb) & mask;
}

Symptom on first silicon: every field decodes correctly except full-width ones: field_get(PERF_CNT, 0, 32) returns 0 on the Cortex-A/R target, so the throughput report shows 0 cycles. Built for a different core or with another compiler/optimization level, it returns something else.

D8 힌트

C에서 shift 양이 피연산자의 비트 폭 이상이면 무엇이 정의되어 있나요? ./run.sh D buggy의 첫 줄을 보세요.

💡 D8 답 펼치기

버그: width == 32일 때 1u << 32는 정의되지 않은 동작(UB)입니다. Arm과 x86은 shift 양을 mod 32로 처리해서 1u << 32 == 1, mask가 0이 되고 결과는 0(기대 0xABCD1234). 다른 컴파일러나 최적화 수준에서는 다른 값이 나올 수 있습니다.

고친 한 줄

uint32_t mask = (width >= 32) ? 0xFFFFFFFFu : ((1u << width) - 1u);
/* or, for 1 <= width <= 32:  uint32_t mask = 0xFFFFFFFFu >> (32u - width); */

어떻게 찾나

  • UBSan이 바로 알려 줍니다: buggy.c:228:25: runtime error: shift exponent 32 is too large for 32-bit type 'unsigned int'. 호스트에서 sanitizer로 단위 테스트를 돌리는 이유입니다.
  • 형제 버그: 1 << 31(부호 있는 int에서 부호 비트로 shift, C11에서 UB) → #define BIT(n) (1u << (n))처럼 항상 unsigned 리터럴. uint8_t 바이트를 << 24하면 int로 승격된 뒤 같은 UB가 됩니다(D6).
  • 테스트 경계값: width 1, 31, 32와 lsb 0, 31.

D9 · Bandwidth from a cycle count

Intended behavior: bytes were moved in cycles cycles of a clk_mhz MHz counter. Return MB/s (10^6 bytes per second), truncated: MB/s = bytes * clk_mhz / cycles. Must be exact for bytes up to 4 GiB − 1 and clk_mhz up to 2000.

uint32_t bw_mbps(uint32_t bytes, uint32_t cycles, uint32_t clk_mhz) {
    uint64_t bw = bytes * clk_mhz / cycles;
    return (uint32_t)bw;
}

Symptom on first silicon: small transfers report sensible numbers (4 KiB → 4096 MB/s), but the 16 MiB benchmark reports 928 MB/s for a DDR path the scope/perf counters say runs at 4 GB/s. The team starts debugging the DDR controller when the bug is in the report.

D9 힌트

bw가 uint64_t라는 것이 곱셈에 영향을 주나요? bytes * clk_mhz는 어떤 타입으로 계산되나요? 16777216 * 1000을 2^32와 비교해 보세요.

💡 D9 답 펼치기

버그: 결과를 uint64_t에 담아도 곱셈은 uint32_t로 계산됩니다(두 피연산자 모두 32-bit). 16777216 × 1000 = 16,777,216,000은 2^32를 넘어서 mod 2^32 = 3,892,314,112가 되고, / 4194304 = 928(기대 4000). bytes = 0xFFFFFFFF, clk = 2000이면 결과는 0(기대 2000).

고친 한 줄

uint64_t bw = (uint64_t)bytes * clk_mhz / cycles;   /* widen BEFORE multiply */

캐스트는 첫 피연산자에 붙여야 합니다. (uint64_t)(bytes * clk_mhz)는 이미 넘친 값을 넓힐 뿐입니다. 최대값 검산: (2^32 − 1) × 2000 < 2^43이라 64-bit로 충분합니다. 순서를 bytes / cycles * clk로 바꾸면 overflow는 피하지만 정밀도를 잃습니다(곱하고 나누기).

어떻게 찾나

  • unsigned overflow는 정의된 동작이라 UBSan 기본 설정은 조용합니다. clang -fsanitize=unsigned-integer-overflow(UB가 아니지만 검사 가능)나 -Wconversion 계열, 정적 분석(Coverity, clang-tidy bugprone-implicit-widening-of-multiplication-result)이 잡습니다.
  • 테스트: 큰 값 + 독립 측정과 교차 검증(perf counter, scope로 본 버스 활동, 이론 최대 대역폭과 비교). 벤치마크 숫자가 이론치의 23%면 "HW가 느리다"보다 "계산이 틀렸다"를 먼저 의심합니다. 자세한 버전은 V4.

D10 · Memory test over a region given in bytes

Intended behavior: for every 32-bit word in [base, base + len_bytes) write a pattern, then read all words back. Return the number of mismatching words. Must not touch a single byte outside the region.

uint32_t mem_test(uint32_t *base, size_t len_bytes) {
    uint32_t *end = base + len_bytes;
    for (uint32_t *p = base; p < end; p++) *p = 0xA5A50000u ^ (uint32_t)(p - base);
    ...                                  /* read back the same range */
}

Symptom on first silicon: the memory test passes, and right after it the board crashes or the stack/heap/log buffer that sits after the test region is corrupted. Testing a 64 KiB SRAM window trashes the next 192 KiB.

D10 힌트

uint32_t * 포인터에 정수 n을 더하면 주소는 몇 바이트 움직이나요? len_bytes = 64면 end는 base에서 몇 바이트 뒤인가요?

💡 D10 답 펼치기

버그: 포인터 산술은 원소 단위입니다. base + len_bytes는 len_bytes × 4바이트 뒤라서 테스트 범위가 4배가 됩니다. 64바이트(16 word) 영역을 테스트하면 64 word를 쓰고, 뒤의 canary 48개가 덮어써집니다. 그런데 쓴 범위를 그대로 다시 읽으므로 결과는 bad = 0, 테스트 통과입니다. 이게 가장 위험한 점입니다.

고친 한 줄

uint32_t *end = base + len_bytes / sizeof *base;

len_bytes가 4의 배수인지(그리고 base가 4바이트 정렬인지)도 assert하는 것이 좋습니다. API를 아예 size_t n_words로 받으면 이 종류의 실수가 사라집니다.

어떻게 찾나

  • 호스트에서는 ASan이 global-buffer-overflow로 잡습니다(이 드릴은 fake RAM을 4배 크게 잡아서 ASan 대신 canary로 보이게 함).
  • 타깃에서는 guard/canary 영역을 두고 테스트 후 검사, MPU로 테스트 영역 밖을 no-access로 막기, 또는 JTAG data watchpoint를 base + len_bytes에 겁니다.
  • "메모리 테스트 자체를 검증"하는 습관: fault injection(테스트 중 한 word를 일부러 뒤집기)으로 테스트가 실패할 수 있는지 확인합니다. March 알고리즘 버전은 V1.

fixed.c
/*
 * D  Debug Drills (D1-D10) — silicon validation / bring-up flavor
 *
 * Ten short bare-metal functions of the kind a silicon-validation engineer writes
 * on first silicon: poll a status bit, ack an interrupt, run a DMA loopback, hand a
 * descriptor to hardware, wait for a PLL lock, decode a register dump, map a register
 * block, extract a bit field, report bandwidth, run a memory test.
 * Each one compiles and "looks right", but each has exactly ONE realistic bug.
 * For every drill:
 *   1. read the "Intended" comment,
 *   2. say the bug out loud in under a minute (and which input triggers it),
 *   3. fix it with a one-line (or few-line) change.
 *
 * There is no real hardware here. Each drill has a tiny mock HW model
 * (a counter of MMIO reads, a W1C status register, a D-cache modelled as a separate
 * copy array, a DMA engine that snoops descriptors, a fake timer, a fake RAM with
 * canary words). The test main() exposes every bug WITHOUT crashing or hanging.
 *
 * Fixed version (reference).  Build & run:  ./run.sh D fixed   -> ALL PASS
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

/* ------------------------------------------------------------------------------------
 * D1  Poll a DMA status register until DONE.
 * Intended: poll DMA_STATUS until bit DONE is 1. Return the number of polls that saw
 *           DONE == 0 (0 if it was already done), or -1 after max_polls polls.
 *           Every poll must be a real bus read of the register.
 *
 * Source as written on the bench:
 *     #define DMA_STATUS (*(uint32_t *)0x40001004u)        // no volatile
 *     while (!(DMA_STATUS & DMA_DONE)) { ... }
 * At -O2 the compiler may load DMA_STATUS once and spin on the register copy.
 * The body below is that compiled behavior, written out in C so the host test can see it.
 * Mock HW: dma_status_read() is one bus read; DONE reads 1 from the Nth read on.
 * ---------------------------------------------------------------------------------- */
#define DMA_DONE (1u << 0)
static uint32_t g_d1_reads, g_d1_done_on_read;

static uint32_t dma_status_read(void)          /* models one MMIO load */
{
    g_d1_reads++;
    return g_d1_reads >= g_d1_done_on_read ? DMA_DONE : 0u;
}

int wait_dma_done(uint32_t max_polls)
{
    for (uint32_t i = 0; i < max_polls; i++) {
        if (dma_status_read() & DMA_DONE) return (int)i;   /* FIX: volatile -> a fresh bus read every poll */
    }
    return -1;
}

/* ------------------------------------------------------------------------------------
 * D2  Acknowledge one interrupt source.
 * Intended: INT_STATUS is write-1-to-clear (W1C): writing 1 to a bit clears it,
 *           writing 0 leaves it alone. irq_ack(bit) must clear ONLY that bit and
 *           leave every other pending source pending.
 * Mock HW: intc_read()/intc_write() are the bus accessors of a W1C register.
 * ---------------------------------------------------------------------------------- */
#define IRQ_TX_DONE (1u << 0)
#define IRQ_RX_DONE (1u << 1)
#define IRQ_ERR     (1u << 4)
static uint32_t g_int_status;                     /* hardware latch */

static uint32_t intc_read(void)        { return g_int_status; }
static void     intc_write(uint32_t v) { g_int_status &= ~v; }   /* W1C semantics */

void irq_ack(uint32_t bit)
{
    intc_write(bit);                            /* FIX: W1C - write only the bit to clear, no RMW */
}

/* ------------------------------------------------------------------------------------
 * D3  DMA memory-to-memory loopback test with a write-back D-cache.
 * Intended: CPU writes a pattern into src, DMA copies src -> dst, CPU checks dst.
 *           Return the number of mismatching words (0 = pass). Must pass on every
 *           run, not only the first one.
 * Mock HW: ddr[] is DRAM (what DMA sees). dc_*[] is the CPU D-cache: one word per
 *          "line", write-back. The DMA engine reads/writes ddr[] only (not coherent).
 * ---------------------------------------------------------------------------------- */
#define RAM_WORDS 64
static uint32_t ddr[RAM_WORDS];
static uint32_t dc_data[RAM_WORDS];
static bool     dc_valid[RAM_WORDS], dc_dirty[RAM_WORDS];

static uint32_t cpu_rd(uint32_t a)
{
    if (!dc_valid[a]) { dc_data[a] = ddr[a]; dc_valid[a] = true; }   /* line fill */
    return dc_data[a];
}
static void cpu_wr(uint32_t a, uint32_t v) { dc_data[a] = v; dc_valid[a] = dc_dirty[a] = true; }
static void dcache_clean(uint32_t a, uint32_t n)          /* write dirty lines back to DRAM */
{
    for (uint32_t i = a; i < a + n; i++)
        if (dc_valid[i] && dc_dirty[i]) { ddr[i] = dc_data[i]; dc_dirty[i] = false; }
}
static void dcache_invalidate(uint32_t a, uint32_t n)     /* drop lines; next read refills */
{
    for (uint32_t i = a; i < a + n; i++) dc_valid[i] = dc_dirty[i] = false;
}
static void dma_copy(uint32_t src, uint32_t dst, uint32_t n)   /* start + wait for DONE */
{
    for (uint32_t i = 0; i < n; i++) ddr[dst + i] = ddr[src + i];
}

uint32_t dma_loopback_test(uint32_t src, uint32_t dst, uint32_t n, uint32_t seed)
{
    for (uint32_t i = 0; i < n; i++) cpu_wr(src + i, seed + i * 0x01010101u);
    dcache_clean(src, n);                       /* make the pattern visible to DMA */
    dma_copy(src, dst, n);
    dcache_invalidate(dst, n);                  /* FIX: drop stale dst lines before the CPU reads */
    uint32_t bad = 0;
    for (uint32_t i = 0; i < n; i++)
        if (cpu_rd(dst + i) != seed + i * 0x01010101u) bad++;
    return bad;
}

/* ------------------------------------------------------------------------------------
 * D4  Hand a TX descriptor to the DMA engine.
 * Intended: fill buf_addr and length, then give the descriptor to HW by setting OWN.
 *           The engine may fetch the descriptor at ANY moment once OWN = 1, so it
 *           must see the new buf_addr and length together with OWN.
 * Layout:   ctrl[31] = OWN (1 = owned by HW), ctrl[30] = IOC (irq on complete),
 *           ctrl[15:0] = length in bytes.
 * Mock HW:  DESC_WR() is one store to descriptor memory; after every store the engine
 *           snoops the descriptor and, the first time it sees OWN = 1, latches a copy.
 * ---------------------------------------------------------------------------------- */
#define DESC_OWN (1u << 31)
#define DESC_IOC (1u << 30)
typedef struct { uint32_t buf_addr; uint32_t ctrl; } DmaDesc;
static DmaDesc g_hw_seen;                       /* what the engine fetched */
static bool    g_hw_took;

static void hw_snoop(const DmaDesc *d)
{
    if (!g_hw_took && (d->ctrl & DESC_OWN)) { g_hw_seen = *d; g_hw_took = true; }
}
#define DESC_WR(d, field, v) do { (d)->field = (v); hw_snoop(d); } while (0)
static inline void dma_wmb(void) { /* real HW: __DSB() / wmb(); no-op in the model */ }

void desc_submit(DmaDesc *d, uint32_t buf, uint16_t len)
{
    DESC_WR(d, buf_addr, buf);                  /* FIX: payload fields first */
    dma_wmb();                                  /* ...visible before OWN */
    DESC_WR(d, ctrl, DESC_OWN | DESC_IOC | len); /* OWN last: hand-off point */
}

/* ------------------------------------------------------------------------------------
 * D5  Wait for PLL lock with a timeout on a free-running 32-bit timer.
 * Intended: poll PLL_STATUS.LOCK. Return the number of polls that saw LOCK == 0, or
 *           -1 once at least `timeout` ticks have elapsed since the start.
 *           The timer wraps from 0xFFFFFFFF to 0, and that must not matter.
 *           d5_elapsed records the ticks elapsed when the timeout fired.
 * Mock HW:  timer_now() advances 1000 ticks per call. LOCK reads 1 from the Nth read on
 *           (N = 0 means the PLL never locks: fault injection).
 * ---------------------------------------------------------------------------------- */
#define PLL_LOCK (1u << 0)
static uint32_t g_tick, g_pll_reads, g_pll_lock_on_read, d5_elapsed;

static uint32_t timer_now(void) { uint32_t t = g_tick; g_tick += 1000u; return t; }
static uint32_t pll_status_read(void)
{
    g_pll_reads++;
    return (g_pll_lock_on_read && g_pll_reads >= g_pll_lock_on_read) ? PLL_LOCK : 0u;
}

int wait_pll_lock(uint32_t timeout)
{
    uint32_t start = timer_now();
    int polls = 0;
    while (!(pll_status_read() & PLL_LOCK)) {
        uint32_t now = timer_now();
        if ((uint32_t)(now - start) >= timeout) { d5_elapsed = now - start; return -1; }  /* FIX: modular elapsed */
        polls++;
        if (polls > 100000) return -2;        /* TEST GUARD (not part of the drill) */
    }
    return polls;
}

/* ------------------------------------------------------------------------------------
 * D6  Decode a 32-bit register value from a debug-UART dump.
 * Intended: the on-chip debug monitor dumps each 32-bit register as 4 bytes,
 *           LITTLE-endian on the wire: b[0] = bits 7..0, ..., b[3] = bits 31..24.
 *           Return the register value.
 * ---------------------------------------------------------------------------------- */
uint32_t reg_from_dump(const uint8_t b[4])
{
    return  (uint32_t)b[0]        | ((uint32_t)b[1] << 8) |     /* FIX: b[0] is the LSB */
           ((uint32_t)b[2] << 16) | ((uint32_t)b[3] << 24);
}

/* ------------------------------------------------------------------------------------
 * D7  Register map of a UART block (datasheet):
 *       0x00 CTRL   0x04 STATUS   0x08-0x0F reserved   0x10 INT_EN   0x14 DATA
 *     All registers are 32-bit. Block size 0x18.
 * Intended: uart_enable_rx_irq() sets INT_EN.RX (bit 0) at offset 0x10.
 * Mock HW:  uart_block[] is the register block; the fake UART decodes it by offset.
 * ---------------------------------------------------------------------------------- */
#define UART_INT_RX (1u << 0)
typedef struct {
    uint32_t CTRL;          /* 0x00 */
    uint32_t STATUS;        /* 0x04 */
    uint32_t RESERVED[2];   /* 0x08 - 0x0F */   /* FIX: two 32-bit words = 8 bytes */
    uint32_t INT_EN;        /* 0x10 */
    uint32_t DATA;          /* 0x14 */
} UartRegs;
_Static_assert(offsetof(UartRegs, INT_EN) == 0x10, "UART INT_EN offset");   /* FIX: lock the map */
_Static_assert(offsetof(UartRegs, DATA)   == 0x14, "UART DATA offset");
_Static_assert(sizeof(UartRegs)           == 0x18, "UART block size");
static uint32_t uart_block[8];

void uart_enable_rx_irq(volatile UartRegs *u)
{
    u->INT_EN |= UART_INT_RX;
}

/* ------------------------------------------------------------------------------------
 * D8  Extract a bit field from a register value.
 * Intended: return bits [lsb + width - 1 : lsb] of reg, right-aligned.
 *           Valid for 1 <= width <= 32 and lsb + width <= 32 (width 32 = whole register).
 * ---------------------------------------------------------------------------------- */
uint32_t field_get(uint32_t reg, unsigned lsb, unsigned width)
{
    uint32_t mask = (width >= 32) ? 0xFFFFFFFFu : ((1u << width) - 1u);   /* FIX: shift by 32 is UB */
    return (reg >> lsb) & mask;
}

/* ------------------------------------------------------------------------------------
 * D9  Report DMA bandwidth from a cycle-counter measurement.
 * Intended: `bytes` were moved in `cycles` cycles of a `clk_mhz` MHz counter.
 *           Return MB/s (10^6 bytes per second), truncated:
 *             MB/s = bytes / (cycles / clk_mhz [us]) = bytes * clk_mhz / cycles.
 *           Must be exact for bytes up to 4 GiB - 1 and clk_mhz up to 2000.
 * ---------------------------------------------------------------------------------- */
uint32_t bw_mbps(uint32_t bytes, uint32_t cycles, uint32_t clk_mhz)
{
    uint64_t bw = (uint64_t)bytes * clk_mhz / cycles;   /* FIX: widen BEFORE the multiply */
    return (uint32_t)bw;
}

/* ------------------------------------------------------------------------------------
 * D10 Write/read-back memory test over a region given in BYTES.
 * Intended: for every 32-bit word in [base, base + len_bytes) write a pattern, then
 *           read all words back. Return the number of mismatching words.
 *           Must not touch a single byte outside the region.
 * Mock HW:  fake_ram[0..15] is the region under test (64 bytes); the words after it
 *           are canaries standing in for "whatever lives next to the region".
 * ---------------------------------------------------------------------------------- */
#define D10_REGION_WORDS 16
#define D10_RAM_WORDS    (D10_REGION_WORDS * 4 + 16)   /* big enough that a 4x overrun stays in-bounds */
#define CANARY(i)        (0xC0FFEE00u | (uint32_t)(i))
static uint32_t fake_ram[D10_RAM_WORDS];

uint32_t mem_test(uint32_t *base, size_t len_bytes)
{
    uint32_t *end = base + len_bytes / sizeof *base;   /* FIX: pointer + n counts ELEMENTS, not bytes */
    for (uint32_t *p = base; p < end; p++) *p = 0xA5A50000u ^ (uint32_t)(p - base);
    uint32_t bad = 0;
    for (uint32_t *p = base; p < end; p++)
        if (*p != (0xA5A50000u ^ (uint32_t)(p - base))) bad++;
    return bad;
}

static int g_sec_fail;

int main(void)
{

    CHECK(intc_read() == (IRQ_RX_DONE | IRQ_ERR));        /* RX and ERR must survive */
    end("D2 W1C read-modify-write");

    end("D3 DMA cache coherency");

    CHECK(d5_elapsed >= 50000 && d5_elapsed <= 51000);     /* must not give up early */
    end("D5 timeout across wrap");

    begin();
    const uint8_t id[4]  = { 0x78, 0x56, 0x34, 0x12 };    /* CHIP_ID = 0x12345678 */

    CHECK(field_get(0xABCD1234u, 0, 1) == 0u);
    CHECK(field_get(0xABCD1234u, 0, 32) == 0xABCD1234u);   /* whole register */
    end("D8 mask shift UB");

    begin();
    CHECK(bw_mbps(4096, 1000, 1000) == 4096u);             /* normal: 4 KiB in 1 us */
    CHECK(bw_mbps(16777216u, 4194304u, 1000) == 4000u);    /* 16 MiB at 4 GB/s */
    CHECK(bw_mbps(0xFFFFFFFFu, 0xFFFFFFFFu, 2000) == 2000u);
    end("D9 bandwidth overflow");

    begin();
    for (uint32_t i = 0; i < D10_RAM_WORDS; i++) fake_ram[i] = CANARY(i);
    CHECK(mem_test(fake_ram, D10_REGION_WORDS * sizeof(uint32_t)) == 0);

    CHECK(fake_ram[D10_REGION_WORDS - 1] == (0xA5A50000u ^ 15u));   /* last word was tested */

    return g_fail != 0;

코드 읽는 포인트

  • 모든 수정에 /* FIX: ... */ 주석이 붙어 있습니다. diff buggy.c fixed.c로 보면 드릴마다 1–4줄만 다릅니다.
  • D1의 dma_status_read()는 "버스 읽기 1회"를 세는 hook입니다. 실제 volatile 버그는 최적화기가 만드는 것이라 호스트 테스트로 재현하기 어려워서, buggy.c는 -O2가 만든 결과를 C로 풀어 썼습니다.
  • D3의 캐시 모델은 word 하나가 라인 하나인 단순화입니다. 실제 라인은 64 B라서 정렬·크기 문제가 추가됩니다.
  • D4의 DESC_WR()는 store 한 번마다 DMA 엔진이 descriptor를 훔쳐보는(snoop) 최악의 타이밍을 모델링합니다.
  • D10의 fake RAM은 일부러 4배 + 16 word로 잡았습니다. 버그 버전이 범위를 넘어도 ASan이 멈추지 않고 canary 48개 파괴로 보이게 하기 위해서입니다.

4.4 복잡도

드릴 자체는 복잡도 문제가 아닙니다. 고친 코드는 모두 원래와 같은 O(n) 또는 O(1)이고 추가 메모리가 없습니다. 비용이 드는 수정은 D3(라인 수만큼 cache maintenance 명령)과 D4(barrier 1개)뿐이며, 둘 다 DMA 전송 시간에 비하면 무시할 수준입니다.

5. 임베디드 관점으로 말할 것

  • HW가 보는 것 vs 코드가 보는 것: D1(컴파일러), D3(캐시), D4(store 순서)는 모두 "CPU 코드가 생각하는 메모리 상태와 버스/디바이스가 실제로 보는 상태가 다르다"는 같은 문제입니다. 이 한 문장으로 세 드릴을 묶어서 말하면 시니어로 보입니다.
  • 레지스터 의미는 헤더에 넣는다: D2(W1C), D7(offset)은 레지스터 맵을 IP-XACT/SystemRDL에서 생성하고 access type·offset을 _Static_assert로 고정하면 사라집니다. 손으로 쓴 헤더는 첫 실리콘 버그의 단골 원인입니다.
  • 도구 + 방향성 테스트: -Wall -Wextra -Werror, 호스트 ASan/UBSan(D8, D10), 정적 분석(D9)으로 잡을 수 있는 것은 먼저 잡고, 나머지(D2, D3, D5, D6)는 다중 pending, 반복 실행, 랩 직전 preload, 비대칭 값 같은 경계 조건 테스트로 잡습니다.
  • FPGA에서 통과 ≠ 실리콘에서 통과: FPGA/HAPS는 클럭이 10–50배 느리고 캐시·coherency 구성이 다를 수 있습니다. D3, D4 같은 타이밍·coherency 버그는 실리콘에서 처음 보이는 경우가 많습니다.
  • 테스트를 테스트한다: D10처럼 "통과하는데 틀린" 테스트가 제일 위험합니다. fault injection으로 테스트가 실제로 실패할 수 있는지 확인하는 것이 validation 코드의 기본입니다.

5.1 면접관(HW 출신 Sr Manager)이 파고들 포인트

  • "How would you tell a silicon bug from a software bug here?" → 같은 동작을 다른 경로로 관찰합니다. D3이면 JTAG로 DRAM 직접 읽기 vs CPU 읽기, D4면 AXI 트레이스로 descriptor fetch 시점 확인, 캐시를 끄거나 non-cacheable로 매핑해서 증상이 사라지는지 봅니다. "I change one variable at a time — cache off, lower DMA clock, JTAG read of DRAM — and see which observation disagrees; that tells me whether the bug is in my code, the coherency setup, or the RTL."
  • "Why didn't this show up on the FPGA?" → FPGA는 엔진이 느리고(D4 순서 버그가 숨음), 캐시·coherency 설정이 다를 수 있고, 타이머가 느려 랩까지 오래 걸립니다(D5). "The FPGA runs ten to fifty times slower, so ordering and wrap bugs that need a tight window often only appear at silicon speed — that's why I add stress and preload tests before first silicon."
  • "How do you know your validation test itself is correct?" → fault injection(D10 canary, 일부러 flip한 bit), 비대칭 패턴(D6), 반복 실행(D3)으로 테스트가 실패할 수 있음을 먼저 보입니다. "Every test I write has a negative case: I inject a fault and prove the test catches it, otherwise a passing result means nothing."
  • "How do you stop these from coming back across the RAP1 family?" → 레지스터 헤더 생성 + _Static_assert, volatile/W1C 접근자 라이브러리, CI에서 호스트 sanitizer 빌드, 리뷰 체크리스트. "I'd put the fixes in the infrastructure — generated register headers with access types, one accessor layer, sanitizer builds in CI — so the next chip variant inherits them."
  • "What would a false failure like D5 cost in PVT or SLT?" → 랜덤해 보이는 실패율이 PVT 코너 데이터에 섞여 실제 마진 문제와 구분이 안 되고, SLT에서는 good die를 버립니다. "A timing bug in the test looks like a random yield loss, so it pollutes the PVT data and can scrap good parts in SLT — test-code bugs are expensive."
