IDV12
PriorityP1
Patternwrap-safe counter delta + two-pointer nearest match
Time30 min

파일: stub.c(여기서 풀기) · solution.c(정답) · 실행: ./run.sh V12 / ./run.sh V12 sol

0. 문제 한국어로 먼저 보기

영어 원문(§1)을 읽기 전에 무슨 상황이고 뭘 만들어야 하는지만 빠르게 잡는 요약입니다. 풀이 힌트는 없습니다.

한 줄 요약: 여러 카메라의 frame 기록(16-bit frame counter + ns timestamp)을 보고, 카메라 하나하나의 stream 상태(drop/중복/순서 뒤바뀜/주기 jitter)와 카메라끼리의 sync(skew) 를 판정하는 checker를 짭니다.

상황

  • autonomy SoC가 MIPI CSI-2로 여러 카메라의 frame을 받습니다. capture path는 frame마다 record 하나를 남깁니다.
    • 카메라의 16-bit HW frame counter: 65535 다음 0으로 wrap
    • PTP로 맞춘 clock의 64-bit timestamp(ns): start-of-frame 시점에 찍음
  • 기준 속도는 30 fps, 주기 P = 33,333,333 ns.
  • 핵심 용어
    • dropped: counter가 건너뛴 만큼 빠진 frame 수
    • duplicate: 같은 counter가 또 들어온 frame
    • out-of-order: counter가 거꾸로 갔거나 timestamp가 앞 frame보다 늦지 않은 frame
    • timing pair: counter가 정확히 +1인 연속 두 frame. 이 쌍에서만 dt(timestamp 차이)를 잼
    • jitter: |dt - P|
    • skew: 같은 순간의 frame들 사이 timestamp 차이 (max − min)
  • 테스트의 make_cam()이 30 fps timestamp(1e9 × k / 30, 정수)를 만들어 줍니다.

구현할 것

함수하는 일규칙
stream_stats(f, n, period_ns, st)카메라 한 대의 stream 통계를 StreamStats에 채움one pass, 정수 연산. frames, dropped, duplicates, out_of_order, pairs, dt_min_ns, dt_max_ns, dt_mean_ns(floor), max_jitter_ns. 성공 시 0 (stub 테스트 기준), period_ns == 0 같은 잘못된 인자 → -EINVAL (stub 주석)
sync_check(cam, n, ncam, period_ns, limit_ns, ss, flagged, flagged_cap)camera 0 기준으로 frame마다 skew 계산, SyncStats 채움skew가 limit_ns를 넘은 reference frame index를 flagged에 최대 flagged_cap개 쓰고, flag된 총 개수를 반환. 잘못된 인자(NULL, ncam == 0 또는 > MAX_CAM, period == 0) → -EINVAL

stream_stats가 frame마다 하는 판정 (d = (uint16_t)(cur.counter − prev.counter), prev = 현재 baseline)

  1. d == 0 → duplicate. baseline 그대로.
  2. d >= 0x8000 → counter가 거꾸로 감 → out-of-order. baseline 그대로.
  3. 그 밖 → dropped += d − 1. 그다음
    • cur.ts <= prev.ts면 out-of-order
    • 아니고 d == 1이면 timing pair, dt = cur.ts − prev.ts
    • 그리고 baseline = cur.
  • timing pair들에 대해 dt_min, dt_max, dt_mean(floor), max_jitter = max |dt − P|. pair가 하나도 없으면 모두 0.

sync_check가 하는 일

  1. camera 0이 reference. reference frame i마다 다른 카메라 각각에서 timestamp가 가장 가까운 frame을 찾음.
  2. 그 차이가 |diff| <= P / 2일 때만 match로 인정.
  3. skew(i) = reference frame과 match된 frame들의 timestamp 중 max − min.
  4. 모든 카메라가 match되면 complete, 하나라도 빠지면 incomplete.
  5. 최대 skew와 그 index 기록 (같은 값이면 먼저 나온 index).
  6. skew(i) > limit_ns이면 i를 flag.

예시를 말로 풀면

  • P = 33,333,333 ns, limit = 1,000,000 ns, frame 6개, timestamp는 5 s 기준 상대값.
    • cam0(reference): 정확한 30 fps.
    • cam1: cam0보다 항상 50,000 ns 늦고, frame 4가 빠짐 (counter 7 8 9 10 _ 12).
    • cam2: frame index마다 400,000 ns씩 더 밀림 (PTP lock이 안 된 free-running 카메라).
  • frame별 skew는 50,000 / 400,000 / 800,000 / 1,200,000 / 1,600,000 / 2,000,000.
    • 1,000,000을 넘는 frame 3, 4, 5가 flag → 반환 3, flagged = {3, 4, 5}.
    • frame 4는 cam1에 짝이 없으니 incomplete. 그래서 ref_frames 6, complete 5, incomplete 1, max_skew 2,000,000(frame 5).
  • stream_stats(cam1): frame 5개, counter 10 → 12에서 1개 drop, timing pair는 7→8, 8→9, 9→10의 3개.
  • stream_stats(cam2): 주기가 400,000 ns씩 길어져 dt_min 33,733,333, dt_max 33,733,334, max_jitter 400,001.

지켜야 할 조건

  • 각 stream은 도착 순서대로 정렬돼 있음. sync_check에 들어오는 stream의 timestamp는 non-decreasing.
  • 카메라는 최대 MAX_CAM = 8대.
  • malloc 금지, floating point 금지. sync_check는 전체 frame 수에 대해 O(total frames).
  • stream이 비어 있을 수 있음 (n == 0, 포인터가 NULL일 수도 있음).

1. Problem

An autonomy SoC receives frames from several cameras over MIPI CSI-2. For every frame the capture path logs a record: the camera's 16-bit hardware frame counter (wraps 65535 → 0) and a 64-bit timestamp in ns from a PTP-synced clock, taken at start-of-frame. Nominal rate is 30 fps (period P = 33,333,333 ns). Write the checker a validation run uses to decide whether the capture path and the camera sync are healthy.

typedef struct { uint16_t frame_counter; uint64_t ts_ns; } FrameRec;

typedef struct {
    uint32_t frames, dropped, duplicates, out_of_order;
    uint32_t pairs;                          /* consecutive (+1) pairs used for timing */
    uint64_t dt_min_ns, dt_max_ns, dt_mean_ns, max_jitter_ns;   /* jitter = |dt - P| */
} StreamStats;

typedef struct {
    uint32_t ref_frames, complete, incomplete;
    uint64_t max_skew_ns;
    uint32_t max_skew_idx;
} SyncStats;

int stream_stats(const FrameRec *f, size_t n, uint64_t period_ns, StreamStats *st);
int sync_check(const FrameRec *const cam[], const size_t n[], size_t ncam,
               uint64_t period_ns, uint64_t limit_ns,
               SyncStats *ss, uint32_t *flagged, size_t flagged_cap);   /* # flagged or -EINVAL */

stream_stats (one pass, integer math). With d = (uint16_t)(cur.counter − prev.counter):

  • d == 0 → duplicate (baseline unchanged)
  • d >= 0x8000 → counter went backwards → out-of-order (baseline unchanged)
  • otherwise → dropped += d − 1; if cur.ts <= prev.ts it is out-of-order; else if d == 1 it is a timing pair with dt = cur.ts − prev.ts. Baseline becomes cur.
  • Over timing pairs: dt_min, dt_max, dt_mean (floor), max_jitter = max |dt − P|. All 0 when there are no pairs.

sync_check. Camera 0 is the reference. For each reference frame i, find in every other camera the frame with the nearest timestamp; it matches only if |diff| <= P / 2. skew(i) = max − min timestamp over the reference frame and its matches. Count complete (every camera matched) and incomplete. Track the max skew (first index wins on ties). Flag i when skew(i) > limit_ns: write up to flagged_cap indices and return the total. Bad arguments → -EINVAL.

Example

P = 33,333,333 ns, limit = 1,000,000 ns, 6 frames, timestamps relative to 5 s
cam0 (ref): 0, 33,333,333, 66,666,666, 100,000,000, 133,333,333, 166,666,666
cam1      : same + 50,000 ns, frame 4 dropped (counters 7 8 9 10 _ 12)
cam2      : same + 400,000 ns x frame index (free-running, not PTP-locked)

sync_check -> 3, flagged = {3, 4, 5}
  skew per frame = 50,000 / 400,000 / 800,000 / 1,200,000 / 1,600,000 / 2,000,000
  ref_frames 6, complete 5, incomplete 1 (frame 4), max_skew 2,000,000 at frame 5
stream_stats(cam1) -> frames 5, dropped 1, pairs 3
stream_stats(cam2) -> dt_min 33,733,333, dt_max 33,733,334, max_jitter 400,001

Constraints

  • Each stream is sorted by arrival; for sync_check its timestamps are non-decreasing. Up to MAX_CAM = 8 cameras.
  • No malloc, no floating point. O(total frames) for sync_check.
  • Streams may be empty (n == 0, pointer may be NULL).

Clarifying questions to ask (first 3 minutes)

  1. Where is the timestamp taken — CSI-2 frame-start packet at the receiver, end-of-frame, or in the driver?
  2. Are the cameras hardware-triggered from one source, or free-running and only timestamped by PTP?
  3. How wide is the HW frame counter, and can it reset (camera re-init) as opposed to wrap?
  4. What is the skew limit, and is it measured against a reference camera or as max − min across all?
  5. A frame missing in one camera: skip it, or report the frame as incomplete?
  6. Is jitter judged against the nominal period, or against the stream's own mean period (to separate jitter from clock drift)?

/* =====================================================================
 * Test harness (do not edit)
 * ===================================================================== */
#define BASE_NS 5000000000ull                                     /* 5 s after PTP epoch */
static uint64_t gen(uint32_t k) { return BASE_NS + 1000000000ull * k / 30u; }  /* exact 30 fps */

/* camera with frames 0..cnt-1, counter starting at c0, timestamp = gen(k) + off + drift*k */
static size_t make_cam(FrameRec *out, uint32_t cnt, uint16_t c0, int64_t off, int64_t drift, int skip)
{
    size_t m = 0;
    for (uint32_t k = 0; k < cnt; k++) {
        if ((int)k == skip) continue;
        out[m].frame_counter = (uint16_t)(c0 + k);
        out[m].ts_ns = (uint64_t)((int64_t)gen(k) + off + drift * (int64_t)k);
        m++;
    }
    return m;
}

{

    CHECK(st.dt_mean_ns == 33333333 && st.max_jitter_ns == 1);

    CHECK(stream_stats(c0, n0, PERIOD_NS, &st) == 0);
    CHECK(st.dropped == 0 && st.out_of_order == 0 && st.pairs == 5);

    CHECK(stream_stats(c0, n0, PERIOD_NS, &st) == 0);
    CHECK(n0 == 6 && st.dropped == 1 && st.pairs == 4 && st.out_of_order == 0);

    CHECK(st.pairs == 2 && st.dt_min_ns == 33333333 && st.dt_max_ns == 33333333);

    ns[2] = n2;
    CHECK(sync_check(cams, ns, 3, PERIOD_NS, 1000000, &ss, NULL, 0) == 0);

    /* 7. example: cam1 drops frame 4, cam2 drifts +0.4 ms per frame (not PTP-locked) */
    n0 = make_cam(c0, 6, 100, 0, 0, -1);
    n1 = make_cam(c1, 6, 7, 50000, 0, 4);
    n2 = make_cam(c2, 6, 60000, 0, 400000, -1);
    ns[0] = n0; ns[1] = n1; ns[2] = n2;
    CHECK(sync_check(cams, ns, 3, PERIOD_NS, 1000000, &ss, fl, 8) == 3);
    CHECK(fl[0] == 3 && fl[1] == 4 && fl[2] == 5);
    CHECK(ss.ref_frames == 6 && ss.complete == 5 && ss.incomplete == 1);
    CHECK(ss.max_skew_ns == 2000000 && ss.max_skew_idx == 5);
    CHECK(stream_stats(c2, n2, PERIOD_NS, &st) == 0);
    CHECK(st.dt_min_ns == 33733333 && st.dt_max_ns == 33733334 && st.max_jitter_ns == 400001);
    CHECK(stream_stats(c1, n1, PERIOD_NS, &st) == 0);
    CHECK(st.frames == 5 && st.dropped == 1 && st.pairs == 3);

    /* 8. empty streams and bad arguments */
    st.frames = 99;
    CHECK(stream_stats(NULL, 0, PERIOD_NS, &st) == 0);
    CHECK(st.frames == 0 && st.pairs == 0 && st.dt_min_ns == 0 && st.dt_mean_ns == 0);
    ns[1] = 0;                                                    /* camera 1 delivered nothing */
    CHECK(sync_check(cams, ns, 3, PERIOD_NS, 1000000, &ss, fl, 8) == 3);
    CHECK(ss.ref_frames == 6 && ss.incomplete == 6 && ss.complete == 0);
    ns[0] = 0;                                                    /* reference empty */
    CHECK(sync_check(cams, ns, 3, PERIOD_NS, 1000000, &ss, fl, 8) == 0 && ss.ref_frames == 0);
    CHECK(sync_check(cams, ns, 0, PERIOD_NS, 1000000, &ss, fl, 8) == -EINVAL);
    CHECK(stream_stats(c0, n0, 0, &st) == -EINVAL);

    printf(g_fail ? "%d FAILED\n" : "ALL PASS\n", g_fail);

3. 힌트 (막힐 때 하나씩)

Hint 1 — 16비트 랩은 뺄셈 한 번

(uint16_t)(cur - prev)는 65535 → 0에서 1이 나옵니다. 결과가 0x8000 이상이면 "뒤로 간 것"으로 봅니다(TCP sequence 비교와 같은 규칙). 비교 연산자(cur > prev)로는 랩을 못 다룹니다.

Hint 2 — 지터는 연속(+1) 쌍에서만

프레임이 빠지면 간격이 2P가 됩니다. 이걸 지터에 넣으면 min/max가 망가집니다. drop은 drop대로 세고, 타이밍 통계는 d == 1인 쌍만 씁니다.

Hint 3 — 가장 가까운 프레임은 two-pointer로

카메라마다 커서 pos[c]를 둡니다. 기준 시각 t 이하인 마지막 프레임까지 커서를 밀고, 후보는 k와 k+1 두 개뿐입니다. 기준 프레임이 시간순이라 커서는 뒤로 가지 않으므로 전체 O(Σn)입니다. 차이가 P/2보다 크면 "그 카메라는 이 프레임을 놓쳤다".

4. 풀이

4.1 핵심 아이디어 — 프레임 정렬과 skew

두 함수는 서로 다른 질문에 답합니다.

  • stream_stats: 한 카메라 안에서 캡처 경로가 프레임을 잃거나, 두 번 내거나, 순서를 바꾸는가? 간격은 안정적인가?
  • sync_check: 카메라 사이에서 같은 순간을 찍었는가? 프레임 인덱스로 맞추면 안 됩니다. 카메라마다 drop이 다르면 인덱스가 어긋나기 때문에 타임스탬프로 정렬합니다.

cam2처럼 offset이 계속 커지는 건 "고정 offset"이 아니라 클럭 드리프트입니다. 0.4 ms / 33.3 ms = 12,000 ppm라 과장된 값이지만, 실제로 PTP lock이 풀린 카메라는 수십 ppm로 천천히 벌어집니다. 장시간 테스트에서 skew가 시간에 비례해 커지면 드리프트, 한 번 튀면 지터나 트리거 문제입니다.

4.2 카운터 랩과 gap

늦게 온 프레임에 기준을 옮기면(baseline = 2) 다음 프레임 4에서 d = 2가 나와 없는 drop을 하나 더 셉니다. 그래서 OOO일 때는 baseline을 안 바꿉니다.

solution.c
/*
 * V12  Multi-Camera Frame Timestamp & Sync Checker
 * Reference solution.
 *
 * Each camera delivers frame records {frame_counter, timestamp_ns}. The counter is a 16-bit
 * hardware counter that wraps 65535 -> 0. The timestamp comes from a PTP-synced 64-bit clock
 * (ns), taken at start-of-frame. Nominal period: 33,333,333 ns (30 fps).
 *
 * Implement:
 *   stream_stats  per-stream health (one pass, integer math, no malloc):
 *     d = (uint16_t)(cur.counter - prev.counter)        (wrap-safe)
 *       d == 0        -> duplicates++                    (baseline unchanged)
 *       d >= 0x8000   -> out_of_order++ (counter went back; baseline unchanged)
 *       otherwise     -> dropped += d - 1; if cur.ts <= prev.ts -> out_of_order++;
 *                        else if d == 1 -> timing pair: dt = cur.ts - prev.ts;
 *                        baseline = cur
 *     Over timing pairs: pairs, dt_min, dt_max, dt_mean (floor), max_jitter = max |dt - period|.
 *     All dt fields are 0 when pairs == 0.
 *   sync_check    camera 0 is the reference. For each reference frame i, find in every other
 *     camera the frame with the nearest timestamp; it matches only if |diff| <= period / 2.
 *     skew(i) = max - min timestamp over the reference + matched frames.
 *     complete / incomplete = all cameras matched or not. Track max skew (first index wins).
 *     Flag i if skew(i) > limit_ns: write up to flagged_cap indices, return the total flagged.
 *     Each stream's timestamps are non-decreasing (O(total frames) two-pointer walk).
 *   Bad args (NULL, ncam == 0 or > MAX_CAM, period == 0) -> -EINVAL.
 *
 * Build & run:  ./run.sh V12 sol
 */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>
#include <errno.h>

static int g_fail;
#define CHECK(c) do { if (!(c)) { printf("FAIL line %d: %s\n", __LINE__, #c); g_fail++; } } while (0)

#define MAX_CAM   8
#define PERIOD_NS 33333333ull          /* 30 fps */

typedef struct { uint16_t frame_counter; uint64_t ts_ns; } FrameRec;

typedef struct {
    uint32_t frames, dropped, duplicates, out_of_order;
    uint32_t pairs;                    /* consecutive (+1) pairs used for timing */
    uint64_t dt_min_ns, dt_max_ns, dt_mean_ns;
    uint64_t max_jitter_ns;            /* max |dt - period| */
} StreamStats;

typedef struct {
    uint32_t ref_frames, complete, incomplete;
    uint64_t max_skew_ns;
    uint32_t max_skew_idx;             /* reference frame index of the max skew */
} SyncStats;

int stream_stats(const FrameRec *f, size_t n, uint64_t period_ns, StreamStats *st);
int sync_check(const FrameRec *const cam[], const size_t n[], size_t ncam,
               uint64_t period_ns, uint64_t limit_ns,
               SyncStats *ss, uint32_t *flagged, size_t flagged_cap);

/* ---------------- your code ---------------- */
static uint64_t absdiff(uint64_t a, uint64_t b) { return a > b ? a - b : b - a; }

int stream_stats(const FrameRec *f, size_t n, uint64_t period_ns, StreamStats *st)
{
    if (st == NULL || (f == NULL && n != 0) || period_ns == 0) return -EINVAL;
    memset(st, 0, sizeof *st);
    st->frames = (uint32_t)n;
    if (n == 0) return 0;

    uint16_t prev_c = f[0].frame_counter;
    uint64_t prev_t = f[0].ts_ns, sum = 0;
    for (size_t i = 1; i < n; i++) {
        uint16_t d = (uint16_t)(f[i].frame_counter - prev_c);   /* wrap-safe */
        if (d == 0)       { st->duplicates++;   continue; }
        if (d >= 0x8000u) { st->out_of_order++; continue; }     /* late frame: keep baseline */

        st->dropped += d - 1u;
        if (f[i].ts_ns <= prev_t) {
            st->out_of_order++;                                  /* time went backwards */
        } else if (d == 1) {
            uint64_t dt = f[i].ts_ns - prev_t;
            if (st->pairs == 0 || dt < st->dt_min_ns) st->dt_min_ns = dt;
            if (dt > st->dt_max_ns) st->dt_max_ns = dt;
            uint64_t j = absdiff(dt, period_ns);
            if (j > st->max_jitter_ns) st->max_jitter_ns = j;
            sum += dt;
            st->pairs++;
        }
        prev_c = f[i].frame_counter;
        prev_t = f[i].ts_ns;
    }
    if (st->pairs) st->dt_mean_ns = sum / st->pairs;
    return 0;
}

int sync_check(const FrameRec *const cam[], const size_t n[], size_t ncam,
               uint64_t period_ns, uint64_t limit_ns,
               SyncStats *ss, uint32_t *flagged, size_t flagged_cap)
{
    if (cam == NULL || n == NULL || ss == NULL || ncam == 0 || ncam > MAX_CAM || period_ns == 0)
        return -EINVAL;
    for (size_t c = 0; c < ncam; c++)
        if (cam[c] == NULL && n[c] != 0) return -EINVAL;
    memset(ss, 0, sizeof *ss);

    size_t pos[MAX_CAM] = { 0 };        /* two-pointer cursor per camera */
    uint64_t half = period_ns / 2;
    uint32_t nflag = 0;

    for (size_t i = 0; i < n[0]; i++) {
        uint64_t t = cam[0][i].ts_ns, lo = t, hi = t;
        bool all = true;
        for (size_t c = 1; c < ncam; c++) {
            const FrameRec *s = cam[c];
            if (n[c] == 0) { all = false; continue; }
            size_t k = pos[c];
            while (k + 1 < n[c] && s[k + 1].ts_ns <= t) k++;    /* last frame at or before t */
            pos[c] = k;
            size_t best = k;
            uint64_t diff = absdiff(s[k].ts_ns, t);
            if (k + 1 < n[c] && absdiff(s[k + 1].ts_ns, t) < diff) {
                best = k + 1;
                diff = absdiff(s[k + 1].ts_ns, t);
            }
            if (diff > half) { all = false; continue; }          /* this camera missed frame i */
            uint64_t tc = s[best].ts_ns;
            if (tc < lo) lo = tc;
            if (tc > hi) hi = tc;
        }
        uint64_t skew = hi - lo;
        ss->ref_frames++;
        if (all) ss->complete++; else ss->incomplete++;
        if (skew > ss->max_skew_ns) { ss->max_skew_ns = skew; ss->max_skew_idx = (uint32_t)i; }
        if (skew > limit_ns) {
            if (flagged != NULL && nflag < flagged_cap) flagged[nflag] = (uint32_t)i;
            nflag++;
        }
    }
    return (int)nflag;
}

/* =====================================================================
 * Test harness (do not edit)
 * ===================================================================== */
#define BASE_NS 5000000000ull                                     /* 5 s after PTP epoch */
static uint64_t gen(uint32_t k) { return BASE_NS + 1000000000ull * k / 30u; }  /* exact 30 fps */

/* camera with frames 0..cnt-1, counter starting at c0, timestamp = gen(k) + off + drift*k */
static size_t make_cam(FrameRec *out, uint32_t cnt, uint16_t c0, int64_t off, int64_t drift, int skip)
{
    size_t m = 0;
    for (uint32_t k = 0; k < cnt; k++) {
        if ((int)k == skip) continue;
        out[m].frame_counter = (uint16_t)(c0 + k);
        out[m].ts_ns = (uint64_t)((int64_t)gen(k) + off + drift * (int64_t)k);
        m++;
    }
    return m;
}

코드 읽는 포인트

  • absdiff(): uint64_t 두 개를 빼서 절댓값을 구할 때 a - b를 먼저 하면 음수가 큰 양수로 바뀝니다. 크기 비교 후 큰 쪽에서 뺍니다.
  • dt_min은 0으로 초기화되어 있으니 pairs == 0일 때 첫 값으로 설정합니다(UINT64_MAX로 초기화하면 pair가 없을 때 결과에 남음).
  • 합계 sum은 uint64_t라 30 fps로 수천 년치까지 안 넘칩니다. dt_mean은 floor 나눗셈입니다.
  • sync_check의 while (k + 1 < n[c] && s[k+1].ts <= t)가 커서를 앞으로만 밀기 때문에 기준 프레임 전체에 대해 각 카메라 배열을 한 번만 훑습니다.
  • flagged는 cap까지만 쓰고 개수는 끝까지 셉니다(snprintf 규칙).

4.5 복잡도

  • stream_stats: 시간 O(n), 메모리 O(1).
  • sync_check: 시간 O(Σ n[c]) (two-pointer), 메모리 O(MAX_CAM) 커서. 이진 탐색으로 하면 O(n₀ · ncam · log n)이라 더 느립니다.

5. 임베디드 관점으로 말할 것

  • 타임스탬프를 어디서 찍나가 정확도를 정합니다: CSI-2 수신기가 Frame Start short packet을 받는 순간 HW로 PTP 시간을 래치하는 게 가장 정확합니다(수 µs 이하). 드라이버의 IRQ 핸들러에서 찍으면 인터럽트 지연(수십 µs~ms)이 지터로 섞입니다. 같은 checker로 두 방식을 비교하면 지터 차이가 바로 보입니다.
  • 카메라 노출 시점 ≠ SOF 시점: rolling shutter는 줄마다 노출 시각이 다르고, SOF와 노출 중심 사이에 고정 지연이 있습니다. 모델이 다른 카메라를 섞으면 이 고정 지연이 skew offset으로 보이므로 보정 테이블이 필요합니다.
  • HW trigger vs free-running: 모든 카메라를 같은 트리거 신호(FSIN/XVS)로 찍으면 skew는 트리거 배선 + 센서 내부 지연 수준입니다. free-running이면 PTP만으로는 "시계는 같아도 찍는 순간이 다름" → 위 예제 cam2처럼 드리프트가 생깁니다.
  • 결과는 숫자로 남긴다: drop/dup/OOO/jitter/skew를 카메라별 카운터로 남기면 장시간 soak, 온도 corner, DDR 대역폭 스트레스(V3 DMA 동시 실행) 아래에서 회귀를 비교할 수 있습니다. CSI-2 패킷 레벨 검사는 V9.

5.1 면접관(HW 출신 Sr Manager)이 파고들 포인트

  • "How do you validate sync on real silicon, not just trust the timestamps?" → 타임스탬프 자체가 틀릴 수 있으니 외부 기준이 필요합니다: 모든 카메라 시야에 LED를 두고 알려진 시각(PTP PPS에 묶인 GPIO)에 깜빡여 각 프레임에서 LED가 켜진 줄/프레임을 찾습니다. 트리거 라인은 스코프로 직접 잽니다. "I close the loop with an external reference: a PPS-locked LED strobe in every camera's view, and a scope on the trigger lines."
  • "How do you know your checker is correct?" → 합성 스트림에 drop, wrap, dup, late frame, 고정 offset, 드리프트를 정확한 개수만큼 넣고 결과 숫자가 맞는지 봅니다(이 테스트들이 그것). 경계값(정확히 1 ms → flag 안 됨)도 고정합니다. "Every fault class has a synthetic stream with a known answer, including the exact-threshold boundary."
  • "64-bit timestamp from a 32-bit bus — what can go wrong?" → 하위 32비트를 읽은 뒤 상위를 읽는 사이에 carry가 넘어가면 4.29 s 튀는 값이 나옵니다(torn read). HW가 LO 읽기 때 HI를 래치하게 하거나, hi1 → lo → hi2 읽고 hi1 != hi2면 다시 읽습니다. 이 checker에서는 dt가 ±2^32 ns 근처로 튀는 프레임으로 나타납니다. "A torn hi/lo read shows up as a ±4.29 s jump in dt; the fix is a HW latch or the hi-lo-hi retry loop."
  • "What about clock domain crossing in the timestamp unit?" → 카메라 픽셀 클럭 도메인의 SOF 이벤트를 PTP 시계 도메인으로 넘길 때 동기화기 2~3 사이클 지연과 그 ±1 사이클 불확실성이 생깁니다. 고정 지연은 보정, ±1 사이클은 지터 바닥으로 문서화합니다. "The CDC adds a fixed latency we calibrate out plus one-cycle uncertainty, which sets the jitter floor."
  • "How long do you run it?" → drop률 1e-6을 말하려면 백만 프레임 이상(30 fps로 약 9시간)이 필요합니다. 그래서 짧은 SLT 버전(수천 프레임, 큰 오류만)과 긴 soak/PVT 버전을 나눕니다. "Short run for gross failures in SLT; hours-long soak across temperature for rate claims."

6. Follow-up 질문과 답

Follow-up (English)답
Explain PTP / gPTP (802.1AS) briefly.grandmaster 시계를 기준으로 Sync/Follow_Up(시각), Pdelay_Req/Resp(링크 지연) 메시지를 HW 타임스탬프로 주고받아 각 노드가 offset과 rate를 맞춥니다. 802.1AS(gPTP)는 차량/AVB용 프로파일로 모든 노드가 time-aware(경로 지연을 홉마다 측정)라 sub-µs 정확도가 나옵니다.
Hardware trigger vs free-running cameras?trigger: 한 신호로 노출 시작 → skew는 µs 수준, 대신 배선과 센서 trigger 모드 지원 필요. free-running: 배선 없음, 카메라 내부 클럭이 각자라 드리프트 → PTP로 타임스탬프는 맞아도 촬영 시각은 다름. 센서 퓨전에는 trigger가 유리합니다.
Where should the timestamp be taken?CSI-2 수신기에서 Frame Start packet 도착 시 HW 래치가 최선. 드라이버/ISR은 지연과 지터가 큼. 노출 시각을 원하면 SOF 기준에 센서별 고정 지연(노출 시간/2 등)을 보정합니다.
How would you read a 64-bit timer safely on a 32-bit bus?HW 래치(LO 읽을 때 HI 스냅샷)가 있으면 LO→HI 순서를 지킵니다. 없으면 do { h1 = HI; l = LO; h2 = HI; } while (h1 != h2);. 64-bit 단일 접근(AXI 64-bit)이 되면 그게 제일 간단합니다.
The skew limit is violated only sometimes. How do you debug?시간축으로 skew를 그립니다. 선형 증가 → 드리프트(PTP lock 상태 확인). 주기적 튐 → 다른 트래픽과 간섭(인터럽트/DDR). 랜덤 단발 → 타임스탬프 경로(torn read, CDC). 같은 순간 다른 카메라도 튀는지로 공통 원인 여부를 나눕니다.
A late frame is counted both as a gap and as out-of-order. Fix it?작은 재정렬 창(예: 최근 8개 counter 비트맵)을 두고, 창 안에서 늦게 온 counter는 drop에서 빼고 reordered로 셉니다. 네트워크 패킷 재정렬 검출과 같은 방식입니다.
Separate jitter from drift?dt의 평균이 P와 다르면 rate 오차(드리프트), 평균 주변의 흩어짐이 지터입니다. max |dt − mean|을 따로 계산하거나, 타임스탬프에 직선 회귀를 해서 기울기(ppm)와 잔차(지터)로 나눕니다.

7. 자주 하는 실수

  • cur > prev로 counter 비교 → 65535 → 0에서 가짜 OOO + 가짜 drop (테스트 3번)
