0. 문제 한국어로 먼저 보기

영어 원문(§1)을 읽기 전에 무슨 상황이고 뭘 만들어야 하는지만 빠르게 잡는 요약입니다. 풀이 힌트는 없습니다.

한 줄 요약: enumeration이 끝난 뒤 PCIe switch 뒤의 endpoint를 하나씩 검사하는 bring-up / system-validation 도구(pass/fail을 내는 lspci -vvv)의 핵심 함수들을 짭니다.

상황

  • 장치마다 4 KiB config space가 있고, cfg_rd32(rid, off) / cfg_wr32(rid, off, val)로만 접근합니다. 4바이트 정렬된 32-bit 접근만 됩니다. 8/16-bit 필드는 dword를 읽어서 꺼내야 합니다.
  • rid(Requester ID) = bus << 8 | dev << 3 | fn. 없는 장치는 all-ones(0xFFFFFFFF) 를 돌려줍니다.
  • 파일 아래쪽 fake가 장치 6개(+ 비어 있는 주소 1개)를 흉내 냅니다. 쓰기 가능 비트 mask, RW1C(1을 쓰면 지워지는) Status 에러 비트, 크기 mask를 돌려주는 BAR까지 모델링합니다.
    • 00:01.0 switch downstream port (Type 1 header)
    • 01:00.0 정상 NVMe SSD (Gen4 x4)
    • 02:00.0 같은 SSD인데 link가 낮게 잡힘, AER correctable 에러 기록됨
    • 03:00.0 capability list가 깨진 NIC (pointer 하위 비트 쓰레기, 순환)
    • 04:00.0 SR-IOV PF 가속기 (Gen5 x8, 8 GiB BAR)
    • 05:00.0 multi-function 가속기 (BAR 3종, Status에 에러 비트 기록됨)
    • 06:00.0 없음

예시를 말로 풀면

  • 01:00.0 정상 SSD: 0x34 → 0x40(Power Mgmt) → 0x50(MSI-X) → 0x70(PCI Express). PCIe cap은 0x70. extended는 0x100(AER) → 0x148(Serial No.) → 0x158(Secondary PCIe). Link Capabilities 0x00400C44, Link Status 0x1044 → 둘 다 Gen4(16000 MT/s) x4 → flag 0.
  • 02:00.0: 능력은 Gen4 x4인데 Link Status가 0x1022 = Gen2 x2 → speed와 width 둘 다 down(flag 3). AER Correctable Status 0x41(Receiver Error + Bad TLP) → 1.
  • 03:00.0: 0x40의 next가 0x53(하위 2비트 쓰레기) → mask하면 0x50(MSI). 0x50의 next가 다시 0x40 → PCIe cap을 찾으면 끝없이 돎 → -ELOOP.
  • 04:00.0 SR-IOV PF: NumVFs 8, offset 0x80, stride 2 → VF RID 0x0480, 0x0482, …, 0x048E = 04:10.0, 04:10.2, … 04:11.6. offset이 0xF8이면 뒤쪽 VF가 bus 5로 넘어감 → bridge가 bus 4까지만 덮으면 -ERANGE.
  • 05:00.0 BAR: 64-bit prefetchable 16 MiB, 32-bit 4 KiB, I/O 256 B → 3개. 재고 나서 Command 0x0007과 Status의 에러 비트가 그대로 남아 있어야 함.

1. Problem

Your validation tool runs after PCIe enumeration and checks every endpoint behind a switch: is it there, are its capability lists sane, did its link train to full speed and width, how are its SR-IOV VFs laid out, are AER errors logged, and how big are its BARs. Think of it as an lspci -vvv that returns pass/fail and can run before Linux exists.

Config space is reached only through two accessors. Each function has a 4 KiB little-endian config space; only aligned 32-bit accesses exist, so 8/16-bit fields are extracted from dwords. A missing function reads all-ones. The functions are a fake at the bottom of stub.c that models writable-bit masks, RW1C Status error bits, and BARs that read back their size mask.

Requirements:

  • pci_probe: Vendor ID 0xFFFF → -ENODEV. Header Type [6:0] (byte 0x0E, bit 7 is the multi-function flag) not 0 → -ENOTSUP. Else 0.
  • pci_find_cap: only if Status bit 4 (Capabilities List) is set, else -ENOENT. Start at the byte at 0x34; mask the low 2 bits of every pointer; a pointer below 0x40 → -EINVAL; more than 48 hops → -ELOOP; next = 0 → -ENOENT. Cap header: ID [7:0], next [15:8].
  • pci_find_ext_cap: start at 0x100. Header: ID [15:0], version [19:16], next [31:20]. A header of 0 or 0xFFFFFFFF at 0x100 → -ENOENT (no extended caps); later in the list → -EINVAL. next = 0 → -ENOENT; 0 < next < 0x100 → -EINVAL; more than 480 hops → -ELOOP.
  • pci_link_check: in the PCI Express capability (ID 0x10) read Link Capabilities (+0x0C: max speed [3:0], max width [9:4]) and Link Status (+0x12, 16-bit: current speed [3:0], negotiated width [9:4]). Fill LinkInfo; return LINK_SPEED_DOWN | LINK_WIDTH_DOWN as applicable (0 = full speed and width); current speed or width 0 → -ENOLINK; propagate the pci_find_cap error.
  • pcie_speed_mts: codes 1..6 → 2500, 5000, 8000, 16000, 32000, 64000 MT/s; anything else → 0.
  • pci_sriov_vfs: SR-IOV ext cap (ID 0x0010): TotalVFs +0x0E, NumVFs +0x10, First VF Offset +0x14, VF Stride +0x16. VF n (1-based) has RID = PF RID + offset + (n−1)·stride. Fill si (also on -EINVAL/-ERANGE; first_rid = last_rid = 0 when NumVFs is 0). NumVFs > TotalVFs → -EINVAL. Any VF bus number > sub_bus (the subordinate bus of the bridge above, so also > 255) → -ERANGE. Otherwise return NumVFs and write the first min(NumVFs, max) RIDs to vf_rid.
  • pci_aer_status: AER ext cap (ID 0x0001): Uncorrectable Error Status +0x04, Correctable Error Status +0x10. Return 1 if either is non-zero, 0 if both are clean, -ENOENT without AER.
  • pci_size_bars: for BAR0..5 (0x10..0x24): save, write 0xFFFFFFFF, read back, restore. Memory BAR: type [2:1] (10b = 64-bit, the next BAR is its upper half), prefetchable [3]; I/O BAR: bit 0 = 1, address from bit 2. Turn memory and I/O decode off (Command bits 1:0) while sizing and restore Command afterwards. Fill bar[6] (unimplemented BAR → all zero; upper half of a 64-bit BAR → flags = BAR_UPPER, size 0). Return the number of implemented BARs (a 64-bit pair counts once), -EINVAL if BAR5 claims to be 64-bit. Config space must be bit-for-bit unchanged afterwards.

Constraints

  • C11, no malloc. Config access only through cfg_rd32/cfg_wr32, aligned dwords only.
  • Functions other than pci_probe may assume the device passed pci_probe.
  • No input may cause an infinite loop.

Clarifying questions to ask (first 3 minutes)

  1. Is config access through ECAM (4 KiB per function) or legacy CF8/CFC (256 B, no extended caps)? Are byte/word accesses allowed?
  2. Does the tool only report, or may it retrain a downtrained link / clear AER status?
  3. Do we compare against the device's own Link Capabilities, or against a golden topology table (expected speed/width per slot)?
  4. Is anything else using the device while we size BARs (DMA in flight, a driver bound)? Decode off is not safe on a live device.
  5. Has firmware already set NumVFs and VF Enable, or should the tool enable SR-IOV itself?
  6. Can devices be hot-removed or surprise-down during the check?

/* =====================================================================
 * Test harness: fake PCIe functions behind a switch (do not edit)
 * ===================================================================== */
typedef struct {
    uint16_t rid;
    uint32_t dw[CFG_SPACE_SIZE / 4];    /* config space, dword view (little-endian) */
    uint32_t wm[CFG_SPACE_SIZE / 4];    /* RW bits */
    uint32_t w1c[CFG_SPACE_SIZE / 4];   /* RW1C bits */
} FakeFn;

#define NFN 8
static struct {
    FakeFn fn[NFN];
    int nfn;
    uint32_t bad_access;        /* unaligned or out-of-range config accesses */
    uint32_t decode_on_sizing;  /* all-ones written to a BAR while IO/MEM decode was on */
} F;

static FakeFn *fake_find(uint16_t rid)
{
    for (int i = 0; i < F.nfn; i++) if (F.fn[i].rid == rid) return &F.fn[i];
    return NULL;
}

uint32_t cfg_rd32(uint16_t rid, uint16_t off)
{
    if ((off & 3u) || off >= CFG_SPACE_SIZE) { F.bad_access++; return 0xFFFFFFFFu; }
    FakeFn *d = fake_find(rid);
    return d ? d->dw[off >> 2] : 0xFFFFFFFFu;           /* no device: UR -> all-ones */
}

void cfg_wr32(uint16_t rid, uint16_t off, uint32_t val)
{
    if ((off & 3u) || off >= CFG_SPACE_SIZE) { F.bad_access++; return; }
    FakeFn *d = fake_find(rid);
    if (!d) return;
    uint32_t i = off >> 2u;
    if (off >= PCI_BAR0 && off <= PCI_BAR0 + 20 && val == 0xFFFFFFFFu && (d->dw[1] & (CMD_IO | CMD_MEM)))
        F.decode_on_sizing++;
    d->dw[i] = (d->dw[i] & ~d->wm[i] & ~(val & d->w1c[i])) | (val & d->wm[i]);
}

/* ---- builders ---- */
static void fk_set(FakeFn *d, uint16_t off, uint32_t val, uint32_t wm)
{
    d->dw[off >> 2] = val; d->wm[off >> 2] = wm;
}

static FakeFn *fk_new(uint16_t rid, uint32_t id, uint32_t class_rev, uint8_t htype, uint32_t cmdsts)
{
    FakeFn *d = &F.fn[F.nfn++];
    memset(d, 0, sizeof *d);
    d->rid = rid;
    fk_set(d, 0x00, id, 0);
    fk_set(d, 0x04, cmdsts, 0x00000547u);               /* IO MEM BME PERR SERR INTxDis */
    d->w1c[1] = 0xF9000000u;                            /* Status error bits: RW1C */
    fk_set(d, 0x08, class_rev, 0);
    fk_set(d, 0x0C, (uint32_t)htype << 16, 0);
    return d;
}

static void fk_cap(FakeFn *d, uint8_t off, uint8_t id, uint8_t next, uint16_t rest)
{
    fk_set(d, off, (uint32_t)id | (uint32_t)next << 8 | (uint32_t)rest << 16, 0);
}

static void fk_pcie(FakeFn *d, uint8_t off, uint8_t next, uint32_t lnkcap, uint16_t lnksta)
{

static void fk_ext(FakeFn *d, uint16_t off, uint16_t id, uint8_t ver, uint16_t next)

static void fk_aer(FakeFn *d, uint16_t off, uint16_t next, uint32_t uncor, uint32_t cor)

3. 힌트 (막힐 때 하나씩)

Hint 1 — 8/16-bit 필드는 dword를 읽고 shift

cfg_rd16(rid, off) = cfg_rd32(rid, off & ~3) >> (8 * (off & 2)), cfg_rd8은 (off & 3)로 같은 방식입니다. Status는 0x04 dword의 위 16비트, Cap Ptr는 0x34 dword의 byte 0, Link Status(+0x12)는 cap + 0x10 dword의 위 16비트입니다. 이 helper 두 개를 먼저 만들면 나머지가 다 짧아집니다.

Hint 2 — 연결 리스트는 hop 수로 막는다

순환 검출에 visited 비트맵이나 Floyd 알고리즘까지 필요 없습니다. standard 영역에 들어갈 수 있는 cap은 최대 (256 − 64) / 4 = 48개, extended는 (4096 − 256) / 8 = 480개입니다. 그보다 많이 돌았다면 순환입니다(Linux PCI_FIND_CAP_TTL과 같은 방식). 각 hop에서 pointer 하위 2비트 mask → 범위 검사 → 읽기 순서를 지킵니다.

Hint 3 — BAR 크기는 "가장 낮은 쓰기 가능 비트"

all-ones를 쓰고 읽은 값에서 type 비트(메모리 [3:0], I/O [1:0])를 지운 mask m에 대해 size = m & (~m + 1)입니다. 64-bit BAR는 위 dword mask를 붙인 64-bit 값으로 계산합니다(4 GiB 이상이면 아래 dword mask는 0). Command는 16-bit 값만 써서 decode를 끄세요. dword 전체를 다시 쓰면 위 16비트 Status의 RW1C 에러 비트가 지워집니다.

4. 풀이

4.1 핵심 아이디어 — config space는 두 개의 연결 리스트

config space는 앞 64 B 고정 header 뒤에 연결 리스트 두 개가 있습니다. standard 리스트는 0x34에서 시작하는 8-bit pointer 체인(0x40–0xFF), extended 리스트는 0x100에서 시작하는 12-bit pointer 체인입니다. 기능(PCIe, MSI-X, AER, SR-IOV …)은 이 리스트를 따라가서 ID로 찾습니다. 고정 offset을 가정하면 장치마다 깨집니다.

검사 도구는 HW가 틀렸을 수 있다는 전제로 짭니다. 그래서 리스트 walk에도 세 가지 방어가 들어갑니다.

  • mask: pointer 하위 2비트는 reserved. 장치가 쓰레기를 넣어도 SW가 지웁니다(0x53 → 0x50).
  • 범위: standard pointer가 header 안(< 0x40)을 가리키거나 extended next가 0x100 아래면 깨진 리스트입니다.
  • hop 상한: 순환을 무조건 끝냅니다.

4.2 BAR sizing — write ones, read back, restore

BAR에서 주소 비트 중 장치가 쓰기를 허용하는 비트만 1로 읽힙니다. 크기가 2^k이면 bit k 아래 주소 비트는 0으로 고정되어 있으므로, 쓰기 가능한 가장 낮은 비트가 곧 크기입니다.

  • decode off: all-ones를 쓰는 순간 BAR가 잠깐 0xFFFFF000 같은 엉뚱한 주소를 decode합니다. 그 사이 다른 master의 접근이 이 장치로 잘못 갈 수 있어서 Command의 IO/MEM을 먼저 끕니다(Linux __pci_read_base도 같은 일을 합니다).
  • 16-bit Command 쓰기: 0x04 dword의 위 절반은 Status이고 에러 비트가 RW1C입니다. 읽은 dword를 그대로 다시 쓰면 05:00.0의 Received Master Abort 기록(0x2000)이 사라집니다. 검사 도구가 증거를 지우는 셈입니다. → V2의 W1C RMW 함정과 같은 이야기입니다.

/*
 * L2  PCIe Config Space Check - capability walk, link status, SR-IOV, AER, BAR sizing
 * Reference solution.
 *
 * After enumeration, a bring-up / system-validation tool checks every endpoint behind a
 * PCIe switch (an "lspci -vvv" that returns pass/fail). Config space is reached only through
 *   uint32_t cfg_rd32(uint16_t rid, uint16_t off);   off must be 4-byte aligned, < 4096
 *   void     cfg_wr32(uint16_t rid, uint16_t off, uint32_t val);
 * rid = bus << 8 | dev << 3 | fn. A missing device reads all-ones. The devices are a FAKE at
 * the bottom of this file (little-endian 4 KiB config space per function; writable-bit masks,
 * RW1C Status bits, BARs that read back their size mask).
 *
 * Implement:
 *   pci_probe        Vendor ID 0xFFFF -> -ENODEV. Header Type [6:0] != 0 -> -ENOTSUP. Else 0.
 *   pci_find_cap     standard list: only if Status bit 4 (Capabilities List) is set; start at the
 *                    byte at 0x34; mask pointer low 2 bits; pointer < 0x40 -> -EINVAL; more than
 *                    48 hops -> -ELOOP; end of list -> -ENOENT. Returns the cap offset.
 *   pci_find_ext_cap extended list from 0x100: header ID[15:0] ver[19:16] next[31:20].
 *                    Header 0 or 0xFFFFFFFF at 0x100 -> -ENOENT (no ext caps); later -> -EINVAL.
 *                    next 0 -> end (-ENOENT); 0 < next < 0x100 -> -EINVAL; > 480 hops -> -ELOOP.
 *   pci_link_check   PCI Express cap (ID 0x10): Link Capabilities (+0x0C) max speed [3:0], max
 *                    width [9:4]; Link Status (+0x12, 16-bit) current speed [3:0], width [9:4].
 *                    Fill LinkInfo; return LINK_SPEED_DOWN | LINK_WIDTH_DOWN flags (0 = full),
 *                    -ENOLINK if current speed or width is 0, or the find_cap error.
 *   pcie_speed_mts   speed code 1..6 -> 2500, 5000, 8000, 16000, 32000, 64000 MT/s; else 0.
 *   pci_sriov_vfs    SR-IOV ext cap (ID 0x0010): TotalVFs +0x0E, NumVFs +0x10, First VF Offset
 *                    +0x14, VF Stride +0x16. VF n (1-based) RID = PF RID + offset + (n-1)*stride.
 *                    NumVFs > TotalVFs -> -EINVAL. Any VF bus > sub_bus (the bridge's
 *                    subordinate bus, so also > 255) -> -ERANGE. Else return NumVFs and fill
 *                    vf_rid[0 .. min(NumVFs, max)-1]. SriovInfo is filled in every non-ENOENT case.
 *   pci_aer_status   AER ext cap (ID 0x0001): Uncorrectable Status +0x04, Correctable Status
 *                    +0x10. Return 1 if either is non-zero, 0 if clean, -ENOENT if no AER.
 *   pci_size_bars    BAR0..5: save, write 0xFFFFFFFF, read back, restore. 64-bit BARs use a pair.
 *                    Memory and I/O decode (Command bits 1:0) OFF while sizing, restored after.
 *                    Fill bar[6]; returns the number of implemented BARs (a 64-bit pair = 1),
 *                    -EINVAL if BAR5 claims to be 64-bit. Config space must be unchanged after.
 *
 * Only aligned 32-bit config accesses exist: 8/16-bit fields are extracted from a dword.
 * Every function except pci_probe may assume the device passed pci_probe.
 *
 * Build & run:  ./run.sh L2 sol

/* Sub-dword reads: read the aligned dword, shift the wanted bytes down. */
static uint16_t cfg_rd16(uint16_t rid, uint16_t off)
{
    return (uint16_t)(cfg_rd32(rid, (uint16_t)(off & ~3u)) >> (8u * (off & 2u)));
}

static uint8_t cfg_rd8(uint16_t rid, uint16_t off)
{
    return (uint8_t)(cfg_rd32(rid, (uint16_t)(off & ~3u)) >> (8u * (off & 3u)));
}

int pci_probe(uint16_t rid)
{
    if (cfg_rd16(rid, PCI_VENDOR_ID) == 0xFFFF) return -ENODEV;     /* UR -> all-ones */
    if ((cfg_rd8(rid, PCI_HEADER_TYPE) & 0x7F) != 0) return -ENOTSUP; /* ignore MF bit 7 */
    return 0;
}

int pci_find_cap(uint16_t rid, uint8_t id)
{
    if (!(cfg_rd16(rid, PCI_COMMAND + 2) & STATUS_CAP_LIST)) return -ENOENT;
    uint8_t pos = cfg_rd8(rid, PCI_CAP_PTR) & 0xFC;
    for (int hops = 0; pos != 0; hops++) {
        if (hops >= CAP_MAX_HOPS) return -ELOOP;
        if (pos < 0x40) return -EINVAL;                 /* points into the header */
        uint32_t h = cfg_rd32(rid, pos);                /* [7:0] ID, [15:8] next */
        if ((h & 0xFF) == id) return pos;
        pos = (uint8_t)(h >> 8) & 0xFC;
    }
    return -ENOENT;
}

int pci_find_ext_cap(uint16_t rid, uint16_t id)
{
    uint16_t pos = EXT_CAP_START;
    for (int hops = 0; ; hops++) {
        if (hops >= EXT_CAP_MAX_HOPS) return -ELOOP;
        uint32_t h = cfg_rd32(rid, pos);
        if (h == 0 || h == 0xFFFFFFFFu)                 /* empty list / no ECAM / broken */
            return pos == EXT_CAP_START ? -ENOENT : -EINVAL;
        if ((h & 0xFFFF) == id) return pos;
        uint16_t next = (uint16_t)(h >> 20) & 0xFFC;
        if (next == 0) return -ENOENT;
        if (next < EXT_CAP_START) return -EINVAL;
        pos = next;
    }
}

int pci_link_check(uint16_t rid, LinkInfo *li)
{
    int cap = pci_find_cap(rid, CAP_ID_PCIE);
    if (cap < 0) return cap;
    uint32_t lcap = cfg_rd32(rid, (uint16_t)(cap + PCIE_LNKCAP));
    uint16_t lsta = cfg_rd16(rid, (uint16_t)(cap + PCIE_LNKSTA));
    li->max_speed = lcap & 0xF;  li->max_width = (lcap >> 4) & 0x3F;
    li->cur_speed = lsta & 0xF;  li->cur_width = (lsta >> 4) & 0x3F;
    if (li->cur_speed == 0 || li->cur_width == 0) return -ENOLINK;
    int flags = 0;
    if (li->cur_speed < li->max_speed) flags |= LINK_SPEED_DOWN;
    if (li->cur_width < li->max_width) flags |= LINK_WIDTH_DOWN;
    return flags;
}

uint32_t pcie_speed_mts(uint8_t code)
{
    static const uint32_t mts[] = { 0, 2500, 5000, 8000, 16000, 32000, 64000 };
    return code < sizeof mts / sizeof mts[0] ? mts[code] : 0;
}

int pci_sriov_vfs(uint16_t pf, uint8_t sub_bus, SriovInfo *si, uint16_t *vf_rid, int max)
{
    int cap = pci_find_ext_cap(pf, EXT_ID_SRIOV);
    if (cap < 0) return cap;
    uint16_t c = (uint16_t)cap;
    si->total_vfs = cfg_rd16(pf, (uint16_t)(c + SRIOV_TOTAL_VFS));
    si->num_vfs   = cfg_rd16(pf, (uint16_t)(c + SRIOV_NUM_VFS));
    si->first_off = cfg_rd16(pf, (uint16_t)(c + SRIOV_VF_OFFSET));
    si->stride    = cfg_rd16(pf, (uint16_t)(c + SRIOV_VF_STRIDE));
    si->first_rid = si->last_rid = 0;
    if (si->num_vfs > si->total_vfs) return -EINVAL;
    if (si->num_vfs == 0) return 0;
    /* 32-bit math: pf + offset can pass 0xFFFF; uint16_t would silently wrap */
    si->first_rid = (uint32_t)pf + si->first_off;
    si->last_rid  = si->first_rid + (uint32_t)(si->num_vfs - 1) * si->stride;
    if ((si->last_rid >> 8) > sub_bus) return -ERANGE;   /* RIDs only grow: last is the max */
    for (int n = 0; n < si->num_vfs && n < max; n++)
        vf_rid[n] = (uint16_t)(si->first_rid + (uint32_t)n * si->stride);
    return si->num_vfs;
}

int pci_aer_status(uint16_t rid, uint32_t *uncor, uint32_t *cor)
{
    int cap = pci_find_ext_cap(rid, EXT_ID_AER);
    if (cap < 0) return cap;
    *uncor = cfg_rd32(rid, (uint16_t)(cap + AER_UNCOR_STATUS));
    *cor   = cfg_rd32(rid, (uint16_t)(cap + AER_COR_STATUS));
    return (*uncor | *cor) != 0;
}

/* Write all-ones, read the mask back, restore. */
static uint32_t bar_probe(uint16_t rid, uint16_t off, uint32_t *orig)
{
    *orig = cfg_rd32(rid, off);
    cfg_wr32(rid, off, 0xFFFFFFFFu);
    uint32_t m = cfg_rd32(rid, off);
    cfg_wr32(rid, off, *orig);
    return m;
}

int pci_size_bars(uint16_t rid, PciBar bar[6])
{
    /* Write only the Command half: writing Status back would clear its RW1C error bits. */
    uint16_t cmd = cfg_rd16(rid, PCI_COMMAND);
    cfg_wr32(rid, PCI_COMMAND, cmd & ~(CMD_IO | CMD_MEM));
    memset(bar, 0, 6 * sizeof bar[0]);
    int n = 0, rc = 0;
    for (int i = 0; i < 6; i++) {
        uint16_t off = (uint16_t)(PCI_BAR0 + 4 * i);
        uint32_t lo, m = bar_probe(rid, off, &lo);
        uint64_t base, mask;
        uint32_t flags;
        if (lo & 1u) {                                  /* I/O BAR: [1:0] are type bits */
            flags = BAR_IO;
            base = lo & ~3u;
            mask = m & ~3u;                             /* upper 16 bits may be hardwired 0 */
        } else {
            flags = (lo & 0x8u) ? BAR_PREF : 0;
            base = lo & ~0xFu;
            mask = m & ~0xFu;
            if (((lo >> 1) & 3u) == 2u) {               /* 64-bit: next BAR is the upper half */
                if (i == 5) { rc = -EINVAL; break; }
                uint32_t hi, mh = bar_probe(rid, (uint16_t)(off + 4), &hi);
                flags |= BAR_MEM64;
                base |= (uint64_t)hi << 32;
                mask |= (uint64_t)mh << 32;             /* >= 4 GiB: low half of mask is 0 */
                bar[i + 1].flags = BAR_UPPER;
            }
        }
        if (mask != 0) {                                /* size = lowest writable address bit */
            bar[i].base = base;
            bar[i].size = mask & (~mask + 1);
            bar[i].flags = flags;
            n++;
        }
        if (flags & BAR_MEM64) i++;
    }
    cfg_wr32(rid, PCI_COMMAND, cmd);                    /* decode back on, Status untouched */
    return rc ? rc : n;
}

코드 읽는 포인트

  • cfg_rd16/cfg_rd8 helper 두 개로 모든 sub-dword 필드를 처리합니다. 실제 HW에서도 일부 root complex는 byte/word config 접근을 지원하지 않아서 이 패턴이 그대로 쓰입니다.
  • pci_find_cap의 루프 순서: hop 상한 → 범위 검사 → 읽기. 범위 검사를 읽기 뒤에 두면 0x3C 같은 header 안 주소를 이미 읽은 뒤입니다(읽기에 부작용이 있는 레지스터면 사고).
  • pci_find_ext_cap에서 0x100의 0 / all-ones는 "없음"(conventional PCI, CF8/CFC 접근, 없는 장치), 중간의 all-ones는 "깨짐 또는 장치가 사라짐"으로 구분합니다.
  • SR-IOV RID는 uint32_t로 계산합니다. RID는 stride ≥ 0이라 단조 증가하므로 마지막 VF만 bus 범위를 보면 됩니다.
  • pci_size_bars는 BAR를 하나도 안 건너뛰고 6개 모두 4회씩 접근 + Command 3회 = config 접근 27회입니다(01:00.0, 05:00.0 모두). 64-bit BAR의 위 절반은 쌍으로 처리하고 i++로 넘어갑니다.

4.5 복잡도

  • pci_find_cap ≤ 48 hop, pci_find_ext_cap ≤ 480 hop, hop당 config read 1회. pci_link_check는 정상 장치에서 config read 7회.
  • pci_size_bars: 27회 고정. 실제 HW에서 config read는 non-posted TLP라 수 µs 걸리므로, 장치당 전체 검사는 수백 µs 수준입니다. 추가 메모리 O(1).

5. 임베디드 관점으로 말할 것

  • Enumeration(DFS bus numbering): root port에서 시작해 깊이 우선으로 bus 번호를 매깁니다. 각 bridge에 primary / secondary / subordinate bus를 쓰고, 아래를 다 돌고 나서 subordinate를 확정합니다. switch = upstream port 1개 + 내부 virtual bus + downstream port N개이고, port마다 Type 1 header(virtual PCI-PCI bridge)입니다. 그래서 switch 하나가 bus 번호를 최소 2개 먹고, SR-IOV VF가 다른 bus로 넘어가면 그 bus까지 subordinate 범위에 들어가야 합니다(이 문제의 sub_bus 검사).
  • ECAM 주소: base + (bus << 20 | dev << 15 | fn << 12 | off). 장치가 없으면 root complex가 UR로 끝내고 all-ones를 돌려줍니다. 그래서 0xFFFF = absent입니다. 리셋 직후에는 Vendor ID 0x0001(CRS/RRS)이 올 수 있고, 그동안 재시도합니다.
  • LTSSM과 downtrain: Detect → Polling → Configuration → L0, 속도 올리기는 Recovery를 거칩니다. Gen3부터는 equalization(Phase 0–3, preset/coefficient 협상)이 있습니다. 속도가 떨어지는 원인은 signal integrity(insertion loss, crosstalk, connector/via), refclk(SSC, jitter, common vs SRIS), equalization 실패, retimer 설정입니다. 폭이 떨어지면 특정 lane이 detect나 deskew에서 탈락한 것이고, 보통 물리 문제(lane short/open, 패키지·보드)입니다. 그래서 Link Status를 읽는 한 줄이 HW 문제를 잡는 첫 검사가 됩니다.
  • AER과 surprise down: correctable(Receiver Error, Bad TLP, Replay Timer Timeout)은 link가 재전송으로 버티고 있다는 뜻이고, downtrain과 같이 나오는 경우가 많습니다(02:00.0). uncorrectable(Completion Timeout, Poisoned TLP, Surprise Down)은 데이터나 장치가 날아간 것입니다. surprise down은 downstream port 쪽 AER과 DPC(Downstream Port Containment)가 처리하고, endpoint를 읽으면 all-ones가 옵니다. 검사 도구는 이때 멈추지 않고 "장치 사라짐"으로 기록해야 합니다.
  • SR-IOV / multi-host / NTB: SR-IOV는 PF 하나가 VF를 여러 개 만들고, VF마다 RID가 있어 VM이나 container에 직접 붙입니다(IOMMU가 RID로 격리). 장치를 여러 host가 나눠 쓰려면 MR-IOV 대신 PCIe fabric switch가 host마다 partition을 나누고 VF를 다른 host 쪽 도메인에 매핑합니다. host 사이는 NTB(Non-Transparent Bridge)가 주소와 RID를 변환해 잇습니다. failover는 standby 경로로 다시 routing하는 일이라, 그 순간 config space가 all-ones였다가 돌아오는 동작을 견디는 검사가 필요합니다.
  • production / system-validation gate로 만들기: 기대값 표(golden topology: 슬롯별 BDF, VID/DID, 기대 speed/width, 필수 cap, BAR 크기, VF 수)를 두고 매 부팅·매 SLT 단계에서 비교합니다. 결과는 장치별 pass/fail + 원시 레지스터 값으로 남깁니다. AER은 "0이어야 함"보다 soak 시간당 correctable 개수 기준이 현실적이고, 기록 후 RW1C로 지웁니다. Ethernet 쪽 상대는 L3, 결과 집계는 V5입니다.
  • FPGA vs 첫 실리콘: FPGA(HAPS/Zynq)에서는 PCIe hard IP가 Gen3/Gen4 정도에 config space 대부분을 IP가 만들어 주므로, 리스트 구조와 SW 흐름 검증이 목적입니다. 첫 실리콘에서는 같은 코드로 실제 PHY를 봅니다. link가 목표 speed/width에 붙는지, equalization 결과, Lane Margining(Gen4+ ext cap 0x0027)으로 eye margin을 잽니다. 그 margin을 전압·온도 코너에서 shmoo로 그리는 것이 V7입니다.

5.1 면접관 Iris Lee(SW·시스템 출신 Principal)가 파고들 포인트

  • "One endpoint behind the switch trained x2 instead of x4. Walk me through the debug." → link 양쪽(downstream port와 endpoint)의 LnkCap/LnkSta를 비교하고, LnkCtl2 Target Link Speed, AER correctable 개수, retrain(LnkCtl bit 5) 후 재현 여부를 봅니다. 그다음 vendor LTSSM 로그로 어떤 lane이 Detect·Polling에서 빠졌는지 확인하고, 슬롯·케이블을 바꿔 보드 문제인지 장치 문제인지 가릅니다. "I compare both ends of the link first, retrain to see if it's stable, then use the LTSSM trace to find which lane dropped — width loss is almost always physical."
  • "How does SR-IOV relate to sharing one device across multiple hosts?" → SR-IOV는 single-root 안에서 VF를 나누는 기능이고, multi-host 공유는 fabric switch가 host별 partition을 만들고 VF를 각 host 도메인에 매핑하거나, NTB로 host 사이 주소를 변환해서 합니다. 어느 쪽이든 VF RID가 bridge bus 범위 안에 있어야 하고 IOMMU가 RID로 격리합니다. "SR-IOV splits the device; the fabric switch or an NTB decides which host sees which VF, and the RID math has to fit every bridge's bus range."
  • "A device goes surprise-down in the middle of your check. What does your tool do?" → config read가 all-ones로 돌아오고, hop 상한 덕분에 리스트 walk가 멈추지 않습니다. 도구는 Vendor ID를 다시 읽어 "removed"로 기록하고, downstream port의 AER Surprise Down과 DPC 상태를 같이 남깁니다. fabric failover라면 경로가 복구된 뒤 다시 검사합니다. "All-ones is data, not a crash: every loop is bounded, and I re-read Vendor ID to classify it as removal, then log the downstream port's AER and DPC status."
  • "How does this become a production gate, not a debug script?" → golden topology 표와 비교해 장치별 pass/fail, 실패 시 원시 레지스터 덤프를 남기고, 같은 코드를 bootloader(bare-metal), Linux 진단, SLT에서 돌립니다. 기준은 버전 관리하고, AER은 soak 동안의 개수 기준으로 판정합니다. "One check library, a versioned golden topology, and the same pass/fail criteria from FPGA bring-up to the factory line."
  • "Why size BARs yourself instead of trusting lspci?" → bring-up 초기에는 Linux가 없고, 있어도 커널이 이미 주소를 배정한 뒤라 "장치가 요청한 크기"와 "배정된 창"이 섞입니다. 직접 재면 RTL의 BAR mask가 스펙과 맞는지 확인할 수 있습니다. 반대로 live 장치에서는 decode를 끄는 게 위험하니 그때는 lspci/sysfs 값을 씁니다. "Before Linux, sizing the BAR is how I verify the RTL's BAR mask; on a live system I read sysfs instead, because toggling decode under a driver is unsafe."

6. Follow-up 질문과 답

Follow-up (English)답
How is the ECAM address formed, and what does legacy CF8/CFC lose?base + bus<<20 | dev<<15 | fn<<12 | off, 함수당 4 KiB. CF8/CFC는 I/O port 방식이라 offset 8비트(256 B)만 되어서 extended cap(AER, SR-IOV)을 못 봅니다. 그 경우 0x100이 all-ones/0 → -ENOENT가 맞는 동작입니다.
Vendor ID reads 0x0001 right after reset. Why?CRS(Gen6부터 RRS) SW Visibility입니다. 장치가 아직 초기화 중이라 root port가 Vendor ID 자리에 0x0001을 돌려줍니다. 재시도해야 하고, 스펙상 리셋 후 100 ms 기다린 뒤 접근하며 장치는 최대 1초 안에 준비돼야 합니다. bring-up 중 이 상태가 계속되면 장치 FW가 멈춘 것입니다.
The endpoint says Gen5 but the switch port only does Gen4. Is Gen4 a failure?아닙니다. 기대값은 두 끝 LnkCap(실제로는 LnkCap2 Supported Link Speeds Vector)의 최소값, 그리고 LnkCtl2 Target Link Speed입니다. 실무 도구는 상대편 port의 cap까지 읽거나 golden 표의 기대 speed와 비교합니다.
How do you size VF BARs?SR-IOV cap +0x24..+0x38의 VF BAR0–5를 같은 write-ones 방식으로 잽니다. 결과는 VF 하나의 크기이고 전체 창은 그 × NumVFs입니다. System Page Size(+0x20)에 따라 크기가 달라지니 그걸 먼저 설정합니다.
How do you clear AER status, and when?RW1C라서 읽은 값을 그대로 다시 쓰면 그 비트만 지워집니다. 반드시 기록 먼저, 지우기 나중. uncorrectable이면 Header Log(+0x1C..)와 First Error Pointer도 같이 남깁니다. mask된 에러도 status 비트는 서지만 보고(ERR_* 메시지)는 안 됩니다.
Why must decode be off while sizing? What does Linux do?all-ones를 쓴 순간 BAR가 잘못된 주소 범위를 decode합니다. 다른 master(CPU, P2P DMA)의 접근이 그 범위에 걸리면 이 장치로 갑니다. Linux __pci_read_base는 Command의 decode를 끄고 재고, host bridge처럼 끌 수 없는 장치는 mmio_always_on으로 예외 처리합니다.
An accelerator needs a 32 GiB window. What changes?64-bit prefetchable BAR + Resizable BAR(ext cap 0x0015)로 지원 크기 목록을 받고, bridge의 prefetchable window(64-bit)도 그만큼 열어야 합니다. 4 GiB 이상이라 아래 dword mask가 0인 경우(04:00.0)를 반드시 처리해야 합니다.
Link is Gen4 x4 but measured throughput is half of expected. Where do you look?Device Control의 MPS/MRRS(작으면 TLP overhead 증가), ASPM L1 진입·탈출 지연, flow-control credit 부족, Relaxed Ordering, IOMMU translation 비용, 그리고 AER Replay 증가(link는 붙었지만 재전송 중). 측정은 V4 방식으로 min/median/p99.
What is different with ARI?ARI(ext cap 0x000E)가 켜지면 device 번호 5비트가 없어지고 function이 8비트(0–255)가 됩니다. 그래서 VF RID 0x0480은 "dev 16 fn 0"이 아니라 "function 128"로 읽습니다. RID 계산식은 같고 해석만 다릅니다. VF가 많은 SR-IOV 장치는 사실상 ARI가 필요합니다.

7. 자주 하는 실수

  • 16-bit 필드를 cfg_rd32(rid, cap + 0x12)처럼 비정렬로 읽음 → 이 fake와 많은 root complex에서 all-ones (테스트 6의 bad_access == 0)
  • pointer 하위 2비트를 mask 안 함 → 0x53에서 비정렬 읽기, 03:00.0에서 MSI를 못 찾음 (테스트 3)
  • hop 상한 없이 while (pos) → 순환 리스트에서 테스트가 영원히 멈춤. 없는 장치(all-ones)도 0xFC → 0xFC 순환을 만듭니다
  • Status bit 4를 안 보고 0x34부터 읽음 → cap list가 없는 장치에서 쓰레기를 따라감 (테스트 3 마지막)
  • Link Status를 mask 없이 비교 → Slot Clock Configuration(bit 12) 때문에 항상 "다름"
  • VF RID를 uint16_t로 더함 → 0xFC80 경우가 bus 0으로 감겨 통과 (테스트 4)
  • BAR 크기를 ~mask + 1로 계산 → I/O BAR가 0xFFFF0100(테스트 5), 64-bit BAR에서 아래 dword mask만 보면 8 GiB BAR가 "미구현"
  • 64-bit BAR의 위 절반을 다음 BAR로 또 재서 BAR 개수가 하나 더 나옴
  • Command를 dword로 다시 씀 → Status의 RW1C 에러 비트가 지워져 증거 손실 (테스트 5의 memcmp)
  • decode를 끄지 않고 sizing, 또는 끈 decode를 복원 안 함 → decode_on_sizing, Command 비교에서 걸림
