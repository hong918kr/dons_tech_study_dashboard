# Ch.27 스레드 API — pthread 로 만들고, 기다리고, 잠그고, 신호하기

> 📖 원문: [27. Interlude: Thread API](../book-md/C27_interlude_thread_api.md) · [PDF p.299](../Operating%20Systems%20-%20Three%20Easy%20Pieces.pdf#page=299) · ⏱️ 읽기 약 30분 · 🔗 선행: [Ch.26](2026-09-30_C26_concurrency_intro.md), [Ch.05](2026-09-30_C05_process_api.md)

## 0. 한눈에 보기

- POSIX 스레드(pthread)의 뼈대는 네 묶음이다: **생성**(`pthread_create`), **완료 대기**(`pthread_join`), **락**(`pthread_mutex_*`), **조건 변수**(`pthread_cond_*`).
- `void *` 인자 하나, `void *` 반환값 하나로 "아무 타입이나" 주고받는다. 함정: **스레드 스택 위의 변수 주소를 넘기거나 돌려주면 안 된다.**
- 락과 CV는 **반드시 초기화**하고, **리턴 코드를 반드시 확인**한다. CV 대기는 **항상 `while` 루프**로.
- 이 장은 레퍼런스다. 개념은 [Ch.28](2026-09-30_C28_locks.md)(락), [Ch.30](2026-09-30_C30_condition_variables.md)(CV)에서 깊게 다룬다.

> **CRUX: HOW TO CREATE AND CONTROL THREADS** — "What interfaces should the OS present for thread creation and control? How should these interfaces be designed to enable ease of use as well as utility?"
>
> → OS는 스레드 생성·제어를 위해 어떤 인터페이스를 제공해야 하나? 쓰기 쉬우면서도 쓸모 있게 하려면 어떻게 설계해야 하나?

## 1. 5분 복습표

| 용어 | 한 줄 뜻 | 예시 / 비유 |
|---|---|---|
| `pthread_create` | 새 스레드를 만들어 start_routine(arg) 실행 | `pthread_create(&t, NULL, f, &args)` |
| `pthread_t` | 스레드 핸들 (join 등에 씀) | 파일 디스크립터 같은 손잡이 |
| `pthread_attr_t` | 스택 크기·스케줄링 등 속성 | `pthread_attr_setstacksize` |
| 함수 포인터 | `void *(*start_routine)(void *)` | 콜백 등록 |
| `pthread_join` | 그 스레드가 끝날 때까지 기다리고 반환값 받기 | 프로세스의 `wait()` |
| `pthread_mutex_lock/unlock` | 임계 구역 진입/퇴장 | 화장실 열쇠 |
| `PTHREAD_MUTEX_INITIALIZER` | 정적 초기화 매크로 | 전역 락 |
| `pthread_mutex_init` | 동적(런타임) 초기화, 짝은 `_destroy` | 구조체 안의 락 |
| `pthread_mutex_trylock` | 잡혀 있으면 기다리지 않고 `EBUSY` | 데드락 회피 |
| `pthread_cond_wait` | 락을 풀고 잠들었다가, 깨면 락을 다시 잡고 리턴 | 대기실 |
| `pthread_cond_signal` | 그 CV에서 자는 스레드 하나 깨우기 | 호출벨 |
| spurious wakeup | 신호 없이 깨는 일 — 그래서 `while` 로 재확인 | "깼다 = 힌트" |
| 래퍼 함수 | 리턴 코드 검사 후 실패 시 종료 | `Pthread_create()` (대문자 P) |
| ThreadSanitizer | 데이터 레이스 탐지기 (clang `-fsanitize=thread`) | Linux의 helgrind 대체 |

## 2. 스레드 생성 (27.1)

```c
#include <pthread.h>
int pthread_create(pthread_t *thread,
                   const pthread_attr_t *attr,
                   void *(*start_routine)(void *),
                   void *arg);
```

인자 네 개:

1. **thread**: `pthread_t` 의 주소. 생성 함수가 채워 준다. 이후 이 스레드를 가리킬 때 쓴다.
2. **attr**: 속성. 스택 크기, 스케줄링 우선순위 등. `pthread_attr_init()` 으로 따로 만든다. 대부분 `NULL`(기본값)이면 충분.
3. **start_routine**: 새 스레드가 시작할 함수. 타입을 읽으면 "`void *` 하나를 받고 `void *` 를 돌려주는 함수의 포인터"다.
4. **arg**: start_routine에 넘길 인자.

왜 하필 `void *` 인가? **아무 타입이나** 넘기고 돌려받기 위해서다. 인자가 여러 개면 구조체로 묶어 그 주소를 넘기고, 받는 쪽에서 캐스팅해서 푼다 (Figure 27.1).

```c
typedef struct { int a; int b; } myarg_t;

void *mythread(void *arg) {
    myarg_t *m = (myarg_t *) arg;   // 받은 쪽에서 원래 타입으로 캐스팅
    printf("%d %d\n", m->a, m->b);
    return NULL;
}
...
myarg_t args = { 10, 20 };
pthread_create(&p, NULL, mythread, &args);
```

생성하는 순간, **자기 콜 스택을 가진 또 하나의 실행 주체**가 같은 주소 공간에서 돌기 시작한다.

## 3. 스레드 완료 기다리기 (27.2)

```c
int pthread_join(pthread_t thread, void **value_ptr);
```

- 첫 인자: 누구를 기다릴지.
- 둘째 인자: 반환값을 받을 곳. 반환값이 `void *` 이고 join이 그걸 **써 넣어야** 하므로, `void *` 변수의 **주소**(`void **`)를 넘긴다.

Figure 27.2처럼 결과를 구조체로 돌려주려면 **힙에 할당**해야 한다:

```c
void *mythread(void *arg) {
    myret_t *r = malloc(sizeof(myret_t));   // 힙: 스레드가 끝나도 살아 있음
    r->x = 1; r->y = 2;
    return (void *) r;
}
```

**절대 하면 안 되는 것** — 스택 변수의 주소를 돌려주기:

```c
void *mythread(void *arg) {
    myret_t r;          // 스레드 스택 위! 
    r.x = 1; r.y = 2;
    return (void *) &r; // 리턴하는 순간 r 은 사라진다 → dangling pointer
}
```

이 코드는 Apple clang에서 `-Wreturn-stack-address` 경고가 나온다 (그래서 이 노트의 실행 코드에는 넣지 않았다 — 경고 0 규칙). 컴파일러 경고를 무시하지 말아야 하는 이유다.

정수 하나만 주고받을 땐 구조체 없이 **포인터 자리에 정수를 끼워** 보낼 수 있다 (Figure 27.3). 다만 책의 `(int) arg` 캐스팅은 64비트에서 크기가 안 맞아 경고가 난다. 올바른 방법은 `intptr_t` 를 거치는 것이다: `(void *)(intptr_t)100` ↔ `(intptr_t)arg`.

마지막으로, `pthread_create` 직후 바로 `pthread_join` 하는 건 이상한 패턴이다 — 그건 그냥 **함수 호출**이다. 실제로는 여러 스레드를 만들어 병렬로 일을 시킨 뒤 join한다. 반대로 웹 서버의 워커 풀처럼 **영원히 도는 스레드는 join하지 않을 수도** 있다 (이때는 `pthread_detach` 로 자원 회수를 맡긴다).

## 4. 락 (27.3)

```c
int pthread_mutex_lock(pthread_mutex_t *mutex);
int pthread_mutex_unlock(pthread_mutex_t *mutex);
```

```c
pthread_mutex_t lock;
pthread_mutex_lock(&lock);
x = x + 1;            // 임계 구역
pthread_mutex_unlock(&lock);
```

의미: 아무도 락을 안 갖고 있으면 잡고 들어간다. 누가 갖고 있으면 **그 사람이 unlock할 때까지 lock()에서 리턴하지 않는다.** 여러 스레드가 lock() 안에서 기다릴 수 있지만, unlock은 락을 가진 스레드만 해야 한다.

위 코드는 **두 군데가 틀렸다.**

### 4.1 문제 1: 초기화 안 함

두 가지 방법:

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;   // 정적
```

```c
int rc = pthread_mutex_init(&lock, NULL);            // 동적
assert(rc == 0);   // 항상 성공 여부 확인!
...
pthread_mutex_destroy(&lock);                        // 다 쓰면
```

구조체 안에 락이 있거나 속성(타입)을 바꾸려면 동적 방식을 쓴다.

### 4.2 문제 2: 리턴 코드 확인 안 함

lock/unlock도 실패할 수 있다. 확인하지 않으면 **조용히 실패해서 여러 스레드가 임계 구역에 들어갈 수 있다.** 최소한 래퍼로 감싼다 (Figure 27.4):

```c
void Pthread_mutex_lock(pthread_mutex_t *mutex) {
    int rc = pthread_mutex_lock(mutex);
    assert(rc == 0);
}
```

실제로 어떤 에러가 오는지는 직접 해보기(§8.1의 [4])에서 확인한다: 이미 잡힌 락에 trylock → `EBUSY`(16), ERRORCHECK 타입에서 주인이 또 lock → `EDEADLK`(11), 주인 아닌 스레드가 unlock → `EPERM`(1). 기본(NORMAL) 타입은 이런 실수를 **검사하지 않는다** — 디버그 빌드에서는 ERRORCHECK 타입을 쓰는 게 좋다.

> 주의: `assert` 는 `-DNDEBUG` 릴리스 빌드에서 사라진다. 그래서 위 래퍼는 `rc` 를 쓴 뒤 `(void)rc;` 로 경고를 막아 두거나, 실제 제품 코드에선 `if (rc) abort();` 처럼 남는 검사로 만든다.

### 4.3 trylock 과 timedlock

```c
int pthread_mutex_trylock(pthread_mutex_t *mutex);
int pthread_mutex_timedlock(pthread_mutex_t *mutex, struct timespec *abs_timeout);
```

- trylock: 잡혀 있으면 즉시 실패(`EBUSY`).
- timedlock: 타임아웃까지 기다리다 실패. 타임아웃 0이면 trylock과 같다.
- 둘 다 **보통은 피하라.** 하지만 데드락 회피(→ [Ch.32](2026-09-30_C32_concurrency_bugs.md))처럼 "무한히 갇히지 않기"가 중요할 땐 쓸모 있다.
- **macOS 주의**: `pthread_mutex_timedlock` 이 **없다** (SDK 헤더에 선언이 없음, 직접 확인). 이식성 있는 코드라면 trylock + 짧은 sleep 루프나 CV의 `pthread_cond_timedwait` 로 대신한다.

## 5. 조건 변수 (27.4)

한 스레드가 **다른 스레드가 뭔가 해 주기를 기다려야** 할 때 쓴다.

```c
int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);
int pthread_cond_signal(pthread_cond_t *cond);
```

기다리는 쪽:

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t  cond = PTHREAD_COND_INITIALIZER;

Pthread_mutex_lock(&lock);
while (ready == 0)
    Pthread_cond_wait(&cond, &lock);
Pthread_mutex_unlock(&lock);
```

깨우는 쪽:

```c
Pthread_mutex_lock(&lock);
ready = 1;
Pthread_cond_signal(&cond);
Pthread_mutex_unlock(&lock);
```

세 가지 포인트:

1. **signal과 상태 변경(`ready = 1`)도 락을 잡고** 한다 → 경쟁 조건 방지.
2. wait만 락을 인자로 받는 이유: wait는 **잠들면서 락을 풀어야** 한다. 안 풀면 깨워 줄 스레드가 락을 못 잡아 영원히 못 깨운다. 그리고 **깨어나서 리턴하기 전에 락을 다시 잡는다.** 그래서 wait 이전과 이후 모두 "락을 잡고 있는" 상태가 유지된다.
3. **`if` 가 아니라 `while`**: 일부 구현은 신호 없이도 깨울 수 있다(**spurious wakeup**). 깨어났다는 건 "뭔가 바뀌었을지도"라는 **힌트**일 뿐이니 조건을 다시 확인한다.

### 5.1 플래그로 대충 하면 안 되나?

```c
while (ready == 0) ;   // spin
...
ready = 1;
```

**하지 마라.** 이유 두 가지:

- 성능: 오래 기다리면 CPU를 그냥 태운다.
- 정확성: 연구([X+10] "Ad Hoc Synchronization Considered Harmful")에 따르면 이런 임시 동기화의 **약 절반이 버그**였다. 실제로 이 노트의 TSan 실험(§8.2)에서 OSTEP의 `main-signal.c`(바로 이 패턴)가 **데이터 레이스로 잡힌다.** C 메모리 모델에서는 `volatile` 없는 `while (done == 0);` 를 컴파일러가 무한 루프로 바꿔도 합법이다.

## 6. 컴파일과 실행 (27.5)

```text
prompt> gcc -o main main.c -Wall -pthread
```

`pthread.h` 를 include하고, 링크 때 `-pthread` 를 준다. macOS에선 pthread가 libSystem에 들어 있어 `-pthread` 없이도 링크되지만, 이식성을 위해 붙이는 습관을 들이자.

## 7. 요약과 가이드라인 (27.6, ASIDE: THREAD API GUIDELINES)

API는 쉽다. 어려운 건 **동시성 프로그램의 논리**다. 책의 체크리스트:

- **단순하게.** 락·시그널 코드는 최대한 단순하게. 꼼수는 버그가 된다.
- **스레드 간 상호작용 최소화.** 상호작용 하나하나를 검증된 패턴으로.
- **락과 CV 초기화.** 안 하면 "가끔 되고 가끔 이상한" 코드가 된다.
- **리턴 코드 확인.**
- **인자 전달·반환에 주의.** 스택 변수 참조를 넘기면 대개 잘못하고 있는 것이다.
- **스레드마다 스택이 따로.** 공유하려면 힙이나 전역에.
- **스레드 간 신호는 항상 CV로.** 플래그 금지.
- **man 페이지를 읽어라.**

## 8. 직접 해보기

### 8.1 API 전부 한 번씩 — C27_thread_api.c

`code/C27_thread_api.c`: 구조체 인자/반환, intptr_t 정수 전달, 스레드 스택 크기, mutex 에러 코드, CV 대기를 한 번에 확인한다.

```c
// C27_thread_api.c — OSTEP Ch.27 Thread API 를 한 파일에서 전부 써 본다.
//  1) 구조체로 인자 넘기고, malloc 한 구조체로 결과 돌려받기 (Fig 27.2)
//  2) 정수 하나는 intptr_t 캐스팅으로 넘기기 (Fig 27.3 의 안전한 버전)
//  3) 스레드 속성(attr): 스택 크기 확인/변경
//  4) mutex: 초기화 · trylock(EBUSY) · ERRORCHECK 타입으로 "남의 락 unlock" 잡기(EPERM)
//  5) condition variable: ready 플래그를 while 로 기다리기
// build: cc -Wall -Wextra -O0 -pthread code/C27_thread_api.c -o .work/bin/C27_thread_api
#include <assert.h>
#include <errno.h>
#include <pthread.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

// ---------- 에러 체크 래퍼 (Fig 27.4 스타일) ----------
static void Pthread_create(pthread_t *t, const pthread_attr_t *a, void *(*f)(void *), void *arg) {
    int rc = pthread_create(t, a, f, arg);
    if (rc != 0) { fprintf(stderr, "pthread_create: %s\n", strerror(rc)); exit(1); }
}
static void Pthread_join(pthread_t t, void **ret) {
    int rc = pthread_join(t, ret);
    if (rc != 0) { fprintf(stderr, "pthread_join: %s\n", strerror(rc)); exit(1); }
}
static void Pthread_mutex_lock(pthread_mutex_t *m)   { int rc = pthread_mutex_lock(m);   assert(rc == 0); (void)rc; }
static void Pthread_mutex_unlock(pthread_mutex_t *m) { int rc = pthread_mutex_unlock(m); assert(rc == 0); (void)rc; }

// ---------- 1) 구조체 인자 / 구조체 반환 ----------
typedef struct { int a; int b; } myarg_t;
typedef struct { int x; int y; } myret_t;

static void *sum_thread(void *arg) {
    myarg_t *m = (myarg_t *)arg;
    myret_t *r = malloc(sizeof(*r));          // 힙에! 스택 변수 주소를 돌려주면 안 된다
    assert(r != NULL);
    r->x = m->a + m->b;
    r->y = m->a * m->b;
    return r;
}

// ---------- 2) 정수 하나 넘기기 ----------
static void *plus_one(void *arg) {
    intptr_t v = (intptr_t)arg;               // 포인터 크기 정수로 왕복 캐스팅
    return (void *)(v + 1);
}

// ---------- 3) 스택 크기 ----------
static void *stack_probe(void *arg) {
    (void)arg;
    size_t sz = pthread_get_stacksize_np(pthread_self());   // macOS 전용 확장
    return (void *)(uintptr_t)sz;
}

// ---------- 4) mutex 동작 ----------
static pthread_mutex_t m_err;                  // ERRORCHECK 타입 (동적 초기화)
static void *unlock_someone_elses(void *arg) {
    (void)arg;
    int rc = pthread_mutex_unlock(&m_err);     // main 이 잡고 있는 락을 남이 풀려 하면?
    return (void *)(intptr_t)rc;
}

// ---------- 5) condition variable ----------
static pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
static int ready = 0;

static void *waiter(void *arg) {
    (void)arg;
    int wakeups = 0;
    Pthread_mutex_lock(&lock);
    while (ready == 0) {                        // if 가 아니라 while!
        pthread_cond_wait(&cond, &lock);        // 잠들면서 lock 을 놓고, 깨면 다시 잡는다
        wakeups++;
    }
    Pthread_mutex_unlock(&lock);
    return (void *)(intptr_t)wakeups;
}

int main(void) {
    pthread_t p;

    // 1)
    myarg_t args = { 10, 20 };
    myret_t *res;
    Pthread_create(&p, NULL, sum_thread, &args);
    Pthread_join(p, (void **)&res);
    printf("[1] struct arg  -> returned x=%d y=%d\n", res->x, res->y);
    free(res);

    // 2)
    void *rv;
    Pthread_create(&p, NULL, plus_one, (void *)(intptr_t)100);
    Pthread_join(p, &rv);
    printf("[2] int arg 100 -> returned %ld\n", (long)(intptr_t)rv);

    // 3)
    printf("[3] main thread stack       = %zu KB\n", pthread_get_stacksize_np(pthread_self()) / 1024);
    Pthread_create(&p, NULL, stack_probe, NULL);
    Pthread_join(p, &rv);
    printf("    default new-thread stack = %zu KB\n", (size_t)(uintptr_t)rv / 1024);
    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setstacksize(&attr, 4 * 1024 * 1024);
    Pthread_create(&p, &attr, stack_probe, NULL);
    Pthread_join(p, &rv);
    pthread_attr_destroy(&attr);
    printf("    with attr setstacksize   = %zu KB\n", (size_t)(uintptr_t)rv / 1024);

    // 4)
    pthread_mutexattr_t ma;
    pthread_mutexattr_init(&ma);
    pthread_mutexattr_settype(&ma, PTHREAD_MUTEX_ERRORCHECK);
    int rc = pthread_mutex_init(&m_err, &ma);
    assert(rc == 0);
    pthread_mutexattr_destroy(&ma);
    Pthread_mutex_lock(&m_err);
    rc = pthread_mutex_trylock(&m_err);
    printf("[4] trylock on held lock      -> %d (%s)\n", rc, strerror(rc));
    rc = pthread_mutex_lock(&m_err);
    printf("    relock by owner (ERRCHECK) -> %d (%s)\n", rc, strerror(rc));
    Pthread_create(&p, NULL, unlock_someone_elses, NULL);
    Pthread_join(p, &rv);
    rc = (int)(intptr_t)rv;
    printf("    unlock by non-owner        -> %d (%s)\n", rc, strerror(rc));
    Pthread_mutex_unlock(&m_err);
    pthread_mutex_destroy(&m_err);

    // 5)
    Pthread_create(&p, NULL, waiter, NULL);
    usleep(100 * 1000);                         // waiter 가 먼저 잠들도록 잠깐 기다림
    Pthread_mutex_lock(&lock);
    ready = 1;
    pthread_cond_signal(&cond);
    Pthread_mutex_unlock(&lock);
    Pthread_join(p, &rv);
    printf("[5] cond: waiter woke up after %ld wakeup(s), ready=%d\n", (long)(intptr_t)rv, ready);
    return 0;
}
```

```text
$ cc -Wall -Wextra -O0 -pthread code/C27_thread_api.c -o .work/bin/C27_thread_api && .work/bin/C27_thread_api
[1] struct arg  -> returned x=30 y=200
[2] int arg 100 -> returned 101
[3] main thread stack       = 8176 KB
    default new-thread stack = 524 KB
    with attr setstacksize   = 4108 KB
[4] trylock on held lock      -> 16 (Resource busy)
    relock by owner (ERRCHECK) -> 11 (Resource deadlock avoided)
    unlock by non-owner        -> 1 (Operation not permitted)
[5] cond: waiter woke up after 1 wakeup(s), ready=1
```

관찰:

- [3] macOS의 새 스레드 기본 스택은 **약 512KB**(보고값 524KB는 가드 페이지 등 포함으로 보임), 메인 스레드는 약 8MB. 리눅스 glibc는 보통 새 스레드도 8MB(`ulimit -s`). macOS에서 큰 지역 배열을 쓰는 스레드는 attr로 키워야 한다.
- [4] ERRORCHECK 타입은 "주인이 또 잠그기"를 데드락 대신 `EDEADLK` 로, "남이 풀기"를 `EPERM` 으로 알려 준다. 기본 타입이었다면 앞의 것은 **영원히 멈추고**, 뒤의 것은 정의되지 않은 동작이다.
- [5] waiter가 먼저 잠든 뒤 signal 1번에 깨어났다. 만약 signal이 먼저 왔어도 `ready` 상태 변수 덕분에 while 조건이 거짓이라 잠들지 않고 바로 통과한다 — **CV 자체는 기억이 없고, 상태 변수가 기억을 담당한다** ([Ch.30](2026-09-30_C30_condition_variables.md)).

## 9. 펌웨어 엔지니어의 눈으로

- **RTOS API와 1:1 대응**: `pthread_create` ↔ `xTaskCreate`(스택 크기·우선순위가 attr 역할), `pthread_join` ↔ (RTOS엔 보통 없음 — 태스크가 무한 루프) 이벤트 그룹/세마포어로 완료 통지, `pthread_mutex` ↔ `xSemaphoreCreateMutex`(우선순위 상속 포함), `pthread_cond` ↔ 태스크 노티피케이션/이벤트 플래그.
- **void * 인자 패턴**은 펌웨어 콜백 API(DMA 완료 콜백의 `void *ctx`, NVMe 커맨드 완료 핸들러의 컨텍스트 포인터)와 같다. 그리고 같은 함정이 있다: **완료 콜백이 불릴 때 ctx가 가리키는 스택 프레임이 이미 사라졌을 수 있다** — 비동기 I/O 요청 구조체는 반드시 정적 풀/힙에 둔다.
- **스택 크기 감각**: macOS 새 스레드 512KB, 리눅스 8MB, FreeRTOS 태스크 수 KB. 펌웨어에서 쓰던 "스택 워터마크(uxTaskGetStackHighWaterMark) 측정" 습관은 사용자 공간 스레드에서도 가치가 있다.
- **ERRORCHECK 뮤텍스 = 디버그 빌드의 assert**. SSD FW에서 "락 주인 ID를 락 구조체에 기록해 두고 unlock 때 비교"하던 디버그 코드가 바로 이것이다. 출하 빌드에선 끄고, 랩 빌드에선 켠다.
- **TSan 같은 동적 검사기가 없는 베어메탈**에서는 같은 아이디어를 수동으로: 공유 변수 접근 함수에 "현재 컨텍스트(ISR/태스크 ID)"와 "락 보유 여부"를 assert. 시뮬레이터/QEMU 위에서 펌웨어를 돌릴 수 있으면 호스트 TSan을 그대로 쓸 수도 있다.

## 10. 면접 질문

### Q1. pthread_create 의 start_routine 이 왜 `void *(*)(void *)` 타입인가? 인자 여러 개를 넘기려면?
<details>
<summary>답 보기</summary>

- C에는 제네릭이 없으므로 **`void *` 가 "아무 포인터나"를 뜻하는 범용 타입**이다. 인자 하나·반환값 하나로 모든 경우를 덮는다.
- 인자 여러 개 → **구조체로 묶어 주소를 넘기고** 스레드에서 캐스팅해 푼다.
- 정수 하나 → `(void *)(intptr_t)v` 로 포인터 자리에 끼워 보낸다 (int 직접 캐스팅은 64비트에서 크기 불일치).
- 주의: 넘긴 구조체가 **스레드가 읽기 전에 사라지지 않게**(main의 루프 지역 변수 재사용, 함수 리턴) 수명을 보장해야 한다.

</details>

### Q2. 스레드 함수에서 지역 변수의 주소를 return 하면 무슨 일이 생기나?
<details>
<summary>답 보기</summary>

- 지역 변수는 **그 스레드의 스택**에 있고, 함수가 리턴하면(스레드 종료 시엔 스택 자체가 해제될 수도 있음) 그 메모리는 무효가 된다 → **dangling pointer**.
- join한 쪽이 그 주소를 역참조하면 쓰레기 값, 다른 데이터, 또는 segfault — **정의되지 않은 동작**이라 "가끔 맞는 값"이 나오는 게 더 위험하다.
- 해결: **malloc 해서 돌려주고 받는 쪽이 free**, 혹은 호출자가 결과 버퍼를 인자로 넘겨준다. clang은 `-Wreturn-stack-address` 로 경고한다.

</details>

### Q3. `pthread_cond_wait` 가 mutex 를 인자로 받는 이유는? 왜 while 로 감싸나?
<details>
<summary>답 보기</summary>

- wait는 **"락을 풀고 잠들기"를 원자적으로** 해야 한다. 따로 하면 "락 풀고 → (그 사이 signal이 와서 사라짐) → 잠듦" 의 **lost wakeup** 이 생긴다. 그래서 락을 넘겨받아 커널/라이브러리가 원자적으로 처리하고, 깨어나면 **락을 다시 잡은 뒤** 리턴한다.
- **while**: (1) **spurious wakeup** 허용, (2) Mesa 의미론 — 깨어나서 실제로 돌 때까지 다른 스레드가 먼저 조건을 바꿔 놓을 수 있음, (3) broadcast 로 여럿이 깨는 경우. 깨어남은 "다시 확인하라"는 힌트일 뿐이다.

</details>

### Q4. 그냥 `volatile int done` 플래그로 spin 하면 왜 안 되나? 실무적으로 언제는 괜찮나?
<details>
<summary>답 보기</summary>

- 성능: 기다리는 동안 **코어 하나를 100% 태운다.** 단일 코어면 신호를 줄 스레드가 돌 기회까지 뺏는다.
- 정확성: C11 메모리 모델에서 `volatile` 은 **원자성도 순서도 보장하지 않는다**. `done=1` 이 보이기 전에 그 앞에서 쓴 데이터가 안 보일 수 있다(ARM 같은 약한 메모리 모델). TSan은 이를 **데이터 레이스**로 보고한다(§8.2 실측).
- 괜찮은 경우: `_Atomic` + acquire/release 순서를 갖춘 플래그로, **대기가 매우 짧을 것이 확실**하고 코어가 남는 경우(예: 커널 스핀락, 폴링 모드 드라이버 — DPDK/SPDK 처럼 지연이 최우선인 곳). 그때도 보통 일정 횟수 spin 후 잠드는 **2단계 대기**로 만든다 ([Ch.28](2026-09-30_C28_locks.md)).

</details>

### Q5. mutex 리턴 코드는 실제로 어떤 경우에 실패하나?
<details>
<summary>답 보기</summary>

- `EINVAL`: 초기화 안 된/파괴된 락, 잘못된 속성.
- `EDEADLK`: ERRORCHECK 타입에서 주인이 다시 lock (기본 타입은 그냥 **영원히 멈춤**).
- `EPERM`: ERRORCHECK/RECURSIVE 타입에서 주인 아닌 스레드가 unlock.
- `EBUSY`: trylock 실패, 또는 잡힌 락을 destroy.
- `EOWNERDEAD`: robust mutex(리눅스)에서 주인이 락을 잡은 채 죽음 — 프로세스 간 공유 락에서 중요.
- 이 Mac에서 실측: trylock → 16(EBUSY), relock → 11(EDEADLK), 남의 unlock → 1(EPERM).

</details>

## 11. 자가 점검 & 숙제

### 퀴즈

Q1. 다음 코드의 버그는? `for (int i = 0; i < 4; i++) pthread_create(&t[i], NULL, worker, &i);`

<details>
<summary>정답</summary>

모든 스레드가 **같은 변수 `i` 의 주소**를 받는다. 스레드가 실제로 `*arg` 를 읽을 때는 `i` 가 이미 증가했거나 루프가 끝나(4, 혹은 스코프 종료로 무효) 있을 수 있다. 해결: `(void *)(intptr_t)i` 로 값을 넘기거나, 스레드별 인자 배열 `args[i]` 의 주소를 넘긴다.

</details>

Q2. `pthread_join(p, (void **)&m)` 에서 왜 `&m` 을 넘기나?

<details>
<summary>정답</summary>

join이 스레드의 반환값(`void *`)을 호출자 변수에 **써 넣어야** 하기 때문이다. C는 값 전달이므로 쓰려면 그 변수의 주소(`void **`)가 필요하다.

</details>

Q3. 정적 초기화(`PTHREAD_MUTEX_INITIALIZER`)를 쓸 수 없는 경우는?

<details>
<summary>정답</summary>

락이 **런타임에 만들어지는 구조체 안**(malloc한 노드, 배열의 원소)에 있거나, **속성(ERRORCHECK, RECURSIVE, 프로세스 공유 등)** 을 지정해야 할 때. 이때는 `pthread_mutex_init(&m, &attr)` 와 짝이 되는 `pthread_mutex_destroy` 를 쓴다.

</details>

Q4. 이 Mac에서 새 스레드 안에 `char buf[1 << 20];`(1MB) 지역 배열을 만들면?

<details>
<summary>정답</summary>

기본 스택이 약 512KB이므로 **가드 페이지를 넘어 죽는다**. 이 Mac에서 실제로 1MB 배열을 memset 하는 스레드를 돌려 보니 `Bus error`(SIGBUS, 종료 코드 138)로 죽었다 — macOS에선 스택 가드 페이지 접근이 SIGSEGV가 아니라 SIGBUS로 오는 경우가 많다. `pthread_attr_setstacksize` 로 키우거나 힙에 할당해야 한다. 메인 스레드(8MB)에선 멀쩡해서 "스레드로 옮기니 죽는다"는 형태로 나타나기 쉽다.

</details>
