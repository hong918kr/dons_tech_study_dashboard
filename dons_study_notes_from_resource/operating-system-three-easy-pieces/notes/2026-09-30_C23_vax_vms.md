## 0. 한눈에 보기

> **THE CRUX: How to avoid the curse of generality** — how can an OS be built so as to run effectively on a wide range of systems?
> (범용성의 저주를 어떻게 피할까 — 싸구려 기계부터 고성능 기계까지 하나의 OS가 어떻게 잘 돌 수 있을까?)

- VAX-11(DEC, 1970년대 말)과 그 OS **VMS**(설계자 Dave Cutler — 훗날 Windows NT 리더)는 지금까지 배운 VM 개념들을 **한 시스템에 깔끔하게 조합한 교과서 사례**다.
- HW 약점: 페이지가 **512 B**로 너무 작음 → 페이지 테이블이 거대해짐, **reference bit 없음**. VMS는 SW로 이 약점을 덮었다.
- 페이지 테이블 줄이기: **세그먼트(P0/P1/S)별 페이지 테이블** + **유저 페이지 테이블을 커널 가상 메모리에** 둬서 스왑 가능하게.
- 교체: **segmented FIFO** (프로세스별 RSS 한도 + 전역 clean/dirty second-chance 리스트), **page clustering** 으로 큰 디스크 쓰기.
- 지금도 모든 OS가 쓰는 "게으른" 기법 두 개: **demand zeroing**, **copy-on-write**. 둘 다 이 노트에서 macOS로 직접 관찰한다.

| page clustering | dirty 페이지를 모아 한 번에 큰 쓰기 | 묶음 배송 |

## 2. 배경 (23.1)

VAX-11 아키텍처는 VAX-11/780(고급)부터 11/750(저가)까지 여러 구현이 있었다. VMS는 이 넓은 범위에서 **모두 잘 동작하는** 메커니즘과 정책이 필요했다 — 그게 "범용성의 저주".

또 하나의 교훈: **HW가 늘 완벽하지는 않다.** VAX에는 설계상 약점이 몇 있었고, VMS는 SW 혁신으로 이를 숨겼다. 펌웨어 엔지니어에겐 익숙한 상황이다(실리콘 errata를 FW로 우회하기).

## 3. 메모리 관리 하드웨어 (23.2)

```text
VAX 가상 주소 (32비트), 페이지 512 B = 2^9

 31 30 29                          9 8          0
+-----+-----------------------------+------------+
| seg |        VPN 나머지 21비트      |  offset 9  |
+-----+-----------------------------+------------+
 \___________ VPN 23비트 ___________/
 seg = 00: P0 (유저 코드+힙)   01: P1 (유저 스택)   10: S (커널)   11: 사용 안 함
```

### 왜 페이지 테이블이 문제인가 — 계산

```text
선형 페이지 테이블 하나로 32비트 전체를 덮으면:
  엔트리 수 = 2^32 / 2^9 = 2^23 ≈ 838만 개
  PTE 4 B   → 2^23 × 4 B = 32 MB  (프로세스당!)
1970년대 말 VAX-11/780의 메모리는 수 MB 수준 → 말이 안 된다.
```

VMS의 두 가지 해법:

1. **세그먼트별 페이지 테이블.** P0, P1 각각에 base/bounds 레지스터가 있다. 힙과 스택 사이의 **빈 공간에는 PTE가 필요 없다**. ([Ch.20](2026-09-30_C20_smaller_page_tables.md)의 하이브리드 방식 그대로)
2. **유저 페이지 테이블을 커널 가상 메모리(S)에 둔다.** 그러면 메모리가 부족할 때 **페이지 테이블의 페이지도 디스크로 스왑**할 수 있다.

### 새 예제: 작은 프로세스의 페이지 테이블 크기

코드+힙 1 MB, 스택 64 KB인 프로세스.

```text
P0: 1 MB / 512 B = 2048 페이지 → PTE 2048 × 4 B = 8 KB
P1: 64 KB / 512 B =  128 페이지 → PTE  128 × 4 B = 512 B
합계 ≈ 8.5 KB   vs   선형 32 MB  → 약 3,800배 절약
```

### 대가: 주소 변환이 두 단계가 된다

유저 PTE가 커널 **가상** 주소에 있으므로, TLB miss 때 HW는:

```text
1) PTE 주소 = P0BR + VPN × 4        ← 이건 S 공간의 "가상" 주소
2) 그 가상 주소를 시스템 페이지 테이블(SBR, 물리 메모리에 있음)로 변환
   → PTE가 들어 있는 물리 페이지를 알아냄
3) PTE를 읽어 PFN을 얻음
4) PFN + offset → 원하는 데이터의 물리 주소
```

다행히 VAX는 **HW-managed TLB**가 있어 대부분 이 긴 과정을 건너뛴다.

지금까지는 "코드, 힙, 스택"만 있는 장난감 주소 공간을 썼다. 실제는 더 복잡하다.

- **페이지 0은 무효.** NULL 포인터 역참조를 잡기 위해서다.

> **ASIDE — 왜 NULL 접근이 segfault가 되나**
> `int *p = NULL; *p = 10;` → VA 0 → VPN 0 → TLB miss → 페이지 테이블에서 VPN 0이 **invalid** → OS로 trap → UNIX라면 시그널(SIGSEGV), 안 잡으면 프로세스 종료.

- **커널이 모든 유저 주소 공간에 매핑된다.** 문맥 교환 때 P0/P1 레지스터만 바꾸고 S 레지스터는 그대로 둔다. 그래서 같은 커널 구조체가 모든 프로세스 주소 공간에 보인다.
  - 장점: `write()`처럼 유저 포인터를 받으면 커널이 **그냥 그 주소로 복사**하면 된다. 커널이 물리 메모리에만 있었다면 페이지 테이블 스왑이 어렵고, 별도 주소 공간이었다면 유저↔커널 데이터 이동이 번거롭다. 커널이 "보호된 라이브러리"처럼 보인다.
- **보호.** PTE의 protection 필드가 "이 페이지에 접근하려면 CPU가 어느 특권 레벨이어야 하나"를 지정한다. 유저 코드가 커널 페이지에 접근하면 trap.

> 💡 현대 보충: 이 "커널을 모든 주소 공간에 매핑" 설계는 2018년 **Meltdown**(투기적 실행으로 커널 매핑을 읽는 공격) 이후 x86 Linux에서 **KPTI**(유저 모드일 때 커널 매핑 대부분을 떼어 냄)로 수정되었다. 원리는 그대로지만 보안 때문에 대가를 치르게 된 것.

## 5. 페이지 교체 (23.4)

VAX PTE 구성:

```text
| valid 1 | protection 4 | modify(dirty) 1 | OS 예약 5 | PFN 21 |   = 32비트
```

눈치챘나? **reference(use) bit가 없다!** [Ch.22](2026-09-30_C22_swapping_policies.md)의 Clock 같은 LRU 근사를 HW 도움 없이 해야 한다.

또 하나의 걱정: **memory hog** — 메모리를 엄청 쓰는 프로그램이 다른 프로그램을 굶긴다. LRU 같은 **전역(global)** 정책은 프로세스 간 공정성을 보장하지 않는다.

### Segmented FIFO

1. 각 프로세스는 메모리에 둘 수 있는 최대 페이지 수 **RSS**를 가진다.
2. 각 프로세스의 페이지는 **프로세스별 FIFO**에 있다. RSS를 넘으면 first-in 페이지를 쫓아낸다. (HW 지원 불필요!)
3. 쫓겨난 페이지는 바로 사라지지 않고 **전역 second-chance 리스트**로 간다:
   - clean이면 → **clean-page free list** 끝에
   - dirty면 → **dirty-page list** 끝에
4. 다른 프로세스 Q가 프레임이 필요하면 **clean list의 맨 앞**에서 가져간다.
5. 원래 프로세스 P가 그 페이지를 다시 건드리면(아직 재활용 안 됐다면) **리스트에서 되찾는다(reclaim)** — 디스크 I/O 없음!

second-chance 리스트가 클수록 segmented FIFO는 **LRU에 가까워진다**(Turner & Levy, 1981).

### 손 계산: RSS = 2, 전역 clean list가 있을 때

프로세스 P가 페이지 `A, B, C, A, D, B` 순으로 접근, 모두 clean, 다른 프로세스는 아직 clean list를 건드리지 않는다고 하자.

```text
접근  P의 FIFO(RSS=2)   clean list     결과
 A    [A]               []             miss (디스크)
 B    [A,B]             []             miss (디스크)
 C    [B,C]             [A]            miss (디스크), A는 clean list로
 A    [C,A]             [B]            "soft fault": clean list에서 A reclaim (디스크 X), B가 밀려남
 D    [A,D]             [B,C]          miss (디스크), C가 밀려남
 B    [D,B]             [C,A]          soft fault: B reclaim (디스크 X)
```

순수 FIFO(RSS=2, second chance 없음)였다면 6번 전부 디스크 miss. Segmented FIFO는 디스크 4번 + 싼 soft fault 2번. 이 soft fault가 FIFO의 실수를 싸게 만회해 준다.

### Page clustering

512 B 페이지는 스왑 I/O에도 나쁘다(디스크는 큰 전송에 강하다). VMS는 **전역 dirty list에서 페이지를 큰 묶음으로 모아** 한 번에 디스크에 쓴다(쓰고 나면 clean이 됨). 스왑 공간 어디에 놓을지 OS가 자유롭게 정할 수 있으니 묶음 쓰기가 가능하다. 현대 OS도 모두 쓰는 기법이다.

```text
예: HDD 평균 seek+회전 ≈ 10 ms, 전송 100 MB/s 가정
  dirty 페이지 64개를 따로 쓰면: 64 × (10 ms + 512 B / 100 MB/s ≈ 5 µs) ≈ 640 ms
  64개(32 KB)를 한 번에:        10 ms + 32 KB / 100 MB/s ≈ 10.3 ms   → 약 60배
```

> **ASIDE — reference bit 흉내 내기 (Babaoglu & Joy, 1981, Berkeley BSD)**
> 1. 페이지 테이블의 모든 페이지를 **접근 불가**로 표시한다(원래 권한은 PTE의 "OS 예약" 필드에 기억).
> 2. 프로세스가 페이지에 접근하면 **trap** → OS는 "원래 접근 가능한 페이지인가?"를 확인하고, 맞으면 권한을 되돌린다(= use bit를 1로 세팅한 효과).
> 3. 교체 시점에 아직 접근 불가로 남은 페이지 = 최근에 안 쓰인 페이지.
> 핵심은 **오버헤드 조절**: 너무 자주 지우면 trap 폭탄, 너무 드물게 지우면 전부 "쓰였음"이 되어 정보가 없다.
> 이 노트의 C 코드 3번 실험이 정확히 이것을 `mprotect(PROT_NONE)` + 시그널 핸들러로 재현한다.

## 6. 다른 멋진 VM 트릭 (23.5)

> **TIP — 게을러져라 (Be Lazy)**
> 일을 미루면 ① 지금 작업의 지연이 줄고(파일 write를 즉시 "성공"으로 돌려주고 나중에 디스크에 씀), ② **아예 안 해도 되는 경우**가 생긴다(쓰기 전에 파일이 지워지면 쓰기 자체가 불필요).

### Demand zeroing

힙에 페이지를 하나 추가한다고 하자.

- **순진한 방식**: 물리 페이지를 찾아서 **0으로 채우고**(보안상 필수 — 안 그러면 이전 프로세스의 데이터가 보인다!) 페이지 테이블에 매핑. 프로세스가 그 페이지를 안 쓰면 다 헛수고.
- **Demand zeroing**: 페이지 테이블에 엔트리만 넣고 **접근 불가**로 표시. 실제 읽기/쓰기가 일어나면 trap → OS가 PTE의 "OS 예약" 비트를 보고 demand-zero 페이지임을 알아챔 → 그때 물리 페이지 할당, zero, 매핑. **안 쓰면 비용 0.**

### Copy-on-write (COW)

TENEX(1972)까지 거슬러 올라가는 아이디어.

- 한 주소 공간에서 다른 주소 공간으로 페이지를 "복사"해야 할 때, 실제로 복사하지 않고 **양쪽에 같은 물리 페이지를 매핑 + 둘 다 읽기 전용**으로 표시.
- 둘 다 읽기만 하면 끝. **복사 비용 0.**
- 한쪽이 쓰려고 하면 → trap → OS가 COW 페이지임을 확인 → 새 페이지 할당, 내용 복사, 쓰려는 쪽에 매핑(이제 쓰기 가능) → 재개.

COW가 특히 중요한 곳은 UNIX의 **`fork()` + `exec()`**. `fork()`는 주소 공간 전체를 복사해야 하는데, 바로 뒤의 `exec()`가 그걸 거의 다 덮어쓴다. COW fork면 의미(semantics)는 그대로 유지하면서 쓸데없는 복사를 피한다. 공유 라이브러리를 여러 프로세스에 COW로 매핑해 메모리를 아끼는 것도 같은 원리다.

### 새 예제: COW fork가 아끼는 양

부모가 2 GB 주소 공간(4 KB 페이지)을 가지고 `fork()` 직후 자식이 `exec()` 하기 전까지 10개 페이지(스택 등)만 쓴다고 하자.

```text
eager copy : 2 GB / 4 KB = 524,288 페이지 복사 (2 GB memcpy, 메모리 대역폭 10 GB/s면 ≈ 0.2 s)
COW        : 페이지 테이블만 복제 + 쓰기 폴트 10번 × 4 KB 복사 = 40 KB
             (PTE 복제 비용은 남는다 → Linux는 vfork/posix_spawn, 큰 프로세스는 이게 여전히 병목)
```

## 7. 요약 (23.6)

VMS는 지금까지 배운 메커니즘(하이브리드 세그먼트+페이징, 페이지 테이블 스왑, 보호 비트)과 정책(FIFO + second chance, clean 우선, clustering, lazy 기법)이 **한 시스템에서 어떻게 맞물리는지** 보여 준다. 저자들은 Levy & Lipman의 원 논문(1982, 짧고 읽기 쉬움)과 Linux 같은 현대 시스템 공부를 권한다. "오래된 논문의 고전적 아이디어가 현대 OS를 여전히 지배한다."

### 보충: 이 판(v0.91)과 현대 Linux

이 판에는 Linux VM 절이 없다(나중 판에 23장 후반부로 추가됨). 참고용으로 VMS 개념이 현대 Linux에서 어떻게 남아 있는지만 짧게 정리한다.

| VMS 개념 | 현대 Linux의 대응 |
|---|---|
| 세그먼트별 페이지 테이블 | x86-64 4단계(옵션 5단계) 다단계 페이지 테이블 |
| 커널을 모든 주소 공간에 매핑 | 같은 설계, 단 Meltdown 이후 KPTI로 유저 모드에서 대부분 분리 |
| invalid page 0 | `vm.mmap_min_addr` 로 낮은 주소 매핑 금지 |
| segmented FIFO + second chance | active/inactive LRU 리스트(최근 커널은 MGLRU), 리스트 간 이동이 "second chance" |
| RSS 한도 (memory hog 방지) | cgroup memory limit |
| page clustering | swap 클러스터 할당, writeback 묶음 |
| demand zeroing | 익명 메모리 첫 읽기는 공유 **zero page**에 매핑, 첫 쓰기 때 실제 할당 |
| COW | `fork()` COW, 공유 라이브러리 private 매핑 |

## 8. 직접 해보기

이 챕터는 OSTEP 공식 시뮬레이터가 없다(`.tools/ostep-homework`에 VAX 관련 디렉터리 없음). 대신 VMS가 유명하게 만든 세 가지 트릭을 macOS에서 **직접 관찰**한다.

`code/C23_lazy_vm_tricks.c`

1. **Demand zeroing**: 64 MiB 익명 `mmap` → 폴트 수(`ru_minflt`)와 RSS(mach `task_info`) 변화를 단계별로 측정.
2. **COW fork**: 32 MiB를 채운 부모가 `fork()`, 자식이 먼저 읽고 그다음 쓴다. 폴트 수와 시간 비교.
3. **Reference bit 흉내**: 8페이지를 `PROT_NONE`으로 막고, `SIGSEGV`/`SIGBUS` 핸들러에서 "use bit = 1" 기록 + 권한 복구. 주기적으로 다시 막는 것이 "use bit 지우기".

```c
/*
 * C23_lazy_vm_tricks.c
 * OSTEP Ch.23 (VAX/VMS) 에 나온 "게으른" VM 기법 3가지를 macOS에서 직접 관찰한다.
 *
 *  1) Demand zeroing : 큰 익명 mmap은 만들 때 비용 0, 처음 만질 때 페이지 폴트 + 0으로 채워짐
 *  2) Copy-on-write  : fork() 후 자식이 읽기만 하면 복사 없음, 쓰면 그때 페이지별 복사
 *  3) Reference bit 흉내 (Babaoglu & Joy, 1981): 보호 비트(PROT_NONE)로 trap을 받아
 *     "최근에 쓰인 페이지" 를 OS(여기선 시그널 핸들러)가 기록
 *
 * 측정: getrusage(RUSAGE_SELF).ru_minflt (디스크 I/O 없는 페이지 폴트 수)
 *       + mach task_info 의 resident_size (RSS)
 *
 * build: cc -Wall -Wextra -O0 code/C23_lazy_vm_tricks.c -o .work/bin/C23_lazy_vm_tricks
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <signal.h>
#include <unistd.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <sys/wait.h>
#include <time.h>
#include <mach/mach.h>

static double now_us(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1e6 + ts.tv_nsec / 1e3;
}

static long minflt(void)
{
    struct rusage ru;
    getrusage(RUSAGE_SELF, &ru);
    return ru.ru_minflt;
}

static double rss_mib(void)
{
    mach_task_basic_info_data_t info;
    mach_msg_type_number_t cnt = MACH_TASK_BASIC_INFO_COUNT;
    if (task_info(mach_task_self(), MACH_TASK_BASIC_INFO,
                  (task_info_t)&info, &cnt) != KERN_SUCCESS)
        return -1.0;
    return (double)info.resident_size / (1024.0 * 1024.0);
}

/* ---------- 1) demand zeroing ---------- */
static void demo_demand_zero(size_t pg)
{
    const size_t len = 64u << 20;                 /* 64 MiB */
    size_t npages = len / pg;

    printf("== 1. Demand zeroing (64 MiB anonymous mmap, page=%zu B, %zu pages) ==\n",
           pg, npages);
    long f0 = minflt(); double r0 = rss_mib();
    unsigned char *p = mmap(NULL, len, PROT_READ | PROT_WRITE,
                            MAP_PRIVATE | MAP_ANON, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); exit(1); }
    long f1 = minflt(); double r1 = rss_mib();
    printf("  after mmap        : +%5ld faults, RSS %+7.2f MiB  (주소 공간만 생김)\n",
           f1 - f0, r1 - r0);

    p[0] = 1;                                      /* 첫 페이지 한 번 터치 */
    long f2 = minflt(); double r2 = rss_mib();
    printf("  touch 1 page      : +%5ld faults, RSS %+7.2f MiB\n", f2 - f1, r2 - r1);

    unsigned long nonzero = 0;
    for (size_t i = pg; i < len; i += pg)          /* 나머지 페이지 첫 바이트 읽기 */
        nonzero += p[i] != 0;
    long f3 = minflt(); double r3 = rss_mib();
    printf("  read all pages    : +%5ld faults, RSS %+7.2f MiB, nonzero bytes seen = %lu\n",
           f3 - f2, r3 - r2, nonzero);

    for (size_t i = pg; i < len; i += pg)          /* 이제 쓰기 */
        p[i] = 2;
    long f4 = minflt(); double r4 = rss_mib();
    printf("  write all pages   : +%5ld faults, RSS %+7.2f MiB\n\n", f4 - f3, r4 - r3);
    munmap(p, len);
}

/* ---------- 2) copy-on-write fork ---------- */
static void demo_cow(size_t pg)
{
    const size_t len = 32u << 20;                  /* 32 MiB, 미리 다 채워 둠 */
    unsigned char *p = malloc(len);
    if (!p) { perror("malloc"); exit(1); }
    memset(p, 0xAB, len);

    printf("== 2. Copy-on-write fork (parent owns 32 MiB = %zu pages, all touched) ==\n",
           len / pg);
    fflush(stdout);
    pid_t pid = fork();
    if (pid == 0) {
        long f0 = minflt();
        double t0 = now_us();
        unsigned long sum = 0;
        for (size_t i = 0; i < len; i += pg)       /* 자식: 읽기만 */
            sum += p[i];
        long f1 = minflt();
        double t1 = now_us();
        for (size_t i = 0; i < len; i += pg)       /* 자식: 이제 쓰기 */
            p[i] = 0xCD;
        long f2 = minflt();
        double t2 = now_us();
        printf("  child read  all pages : +%5ld faults, %7.0f us (sum=%lu)\n",
               f1 - f0, t1 - t0, sum);
        printf("  child write all pages : +%5ld faults, %7.0f us  <- 페이지마다 private copy\n",
               f2 - f1, t2 - t1);
        fflush(stdout);
        _exit(0);
    }
    waitpid(pid, NULL, 0);
    printf("  parent sees p[0] = 0x%02X (child's write did not leak)\n\n", p[0]);
    free(p);
}

/* ---------- 3) reference bit emulation via protection ---------- */
#define NPG 8
static unsigned char *region;
static size_t g_pg;
static volatile sig_atomic_t referenced[NPG];
static volatile sig_atomic_t traps;

static void on_fault(int sig, siginfo_t *si, void *uc)
{
    (void)sig; (void)uc;
    unsigned char *a = (unsigned char *)si->si_addr;
    if (a < region || a >= region + NPG * g_pg)
        _exit(99);                                 /* 진짜 버그면 그냥 죽는다 */
    size_t idx = (size_t)(a - region) / g_pg;
    referenced[idx] = 1;                           /* "use bit = 1" 기록 */
    traps++;
    /* 원래 권한으로 되돌림 → 같은 페이지 다음 접근은 trap 없이 진행 */
    mprotect(region + idx * g_pg, g_pg, PROT_READ | PROT_WRITE);
}

static void clear_ref_bits(void)
{
    for (int i = 0; i < NPG; i++) referenced[i] = 0;
    mprotect(region, NPG * g_pg, PROT_NONE);       /* 전부 "접근 불가" 로 */
}

static void show_ref_bits(const char *tag)
{
    printf("  %-28s use bits:", tag);
    for (int i = 0; i < NPG; i++) printf(" %d", (int)referenced[i]);
    printf("   (traps so far=%d)\n", (int)traps);
}

static void demo_ref_bits(size_t pg)
{
    g_pg = pg;
    region = mmap(NULL, NPG * pg, PROT_READ | PROT_WRITE,
                  MAP_PRIVATE | MAP_ANON, -1, 0);
    if (region == MAP_FAILED) { perror("mmap"); exit(1); }

    struct sigaction sa;
    memset(&sa, 0, sizeof sa);
    sa.sa_sigaction = on_fault;
    sa.sa_flags = SA_SIGINFO;
    sigemptyset(&sa.sa_mask);
    sigaction(SIGSEGV, &sa, NULL);                 /* macOS는 보호 위반이 SIGBUS로 */
    sigaction(SIGBUS, &sa, NULL);                  /* 오는 경우도 있어 둘 다 등록 */

    printf("== 3. Emulating reference bits with PROT_NONE (8 pages) ==\n");
    clear_ref_bits();
    show_ref_bits("epoch 1 start (all cleared)");
    region[1 * pg] = 1;  region[3 * pg] = 3;  region[3 * pg + 8] = 3;
    (void)*(volatile unsigned char *)&region[6 * pg];
    show_ref_bits("after touching 1,3,3,6");

    clear_ref_bits();                              /* 주기적 clear = clock의 바늘 */
    region[3 * pg] = 4; region[7 * pg] = 7;
    show_ref_bits("epoch 2: touched 3,7");

    printf("  => victim candidates in epoch 2 (use bit 0):");
    for (int i = 0; i < NPG; i++) if (!referenced[i]) printf(" %d", i);
    printf("\n");
    munmap(region, NPG * pg);
}

int main(void)
{
    size_t pg = (size_t)getpagesize();
    demo_demand_zero(pg);
    demo_cow(pg);
    demo_ref_bits(pg);
    return 0;
}
```

실제 출력 (경고 0개, macOS / Apple Silicon arm64, 페이지 16 KB):

```text
== 1. Demand zeroing (64 MiB anonymous mmap, page=16384 B, 4096 pages) ==
  after mmap        : +    0 faults, RSS   +0.00 MiB  (주소 공간만 생김)
  touch 1 page      : +    1 faults, RSS   +0.02 MiB
  read all pages    : + 4095 faults, RSS  +63.98 MiB, nonzero bytes seen = 0
  write all pages   : +    0 faults, RSS   +0.00 MiB

== 2. Copy-on-write fork (parent owns 32 MiB = 2048 pages, all touched) ==
  child read  all pages : + 2048 faults,    1512 us (sum=350208)
  child write all pages : + 2048 faults,    5232 us  <- 페이지마다 private copy
  parent sees p[0] = 0xAB (child's write did not leak)

== 3. Emulating reference bits with PROT_NONE (8 pages) ==
  epoch 1 start (all cleared)  use bits: 0 0 0 0 0 0 0 0   (traps so far=0)
  after touching 1,3,3,6       use bits: 0 1 0 1 0 0 1 0   (traps so far=3)
  epoch 2: touched 3,7         use bits: 0 0 0 1 0 0 0 1   (traps so far=5)
  => victim candidates in epoch 2 (use bit 0): 0 1 2 4 5 6
```

읽는 법:

- **1번 demand zeroing**: `mmap` 직후 폴트 0, RSS 증가 0 — 주소 공간만 생겼다. 첫 페이지를 건드려야 폴트 1번 + 16 KB. 나머지를 **읽기만** 해도 4095번 폴트가 나고 RSS가 64 MiB 늘었다, 그리고 읽은 값은 전부 0이었다(nonzero 0) — "할당 + zero"가 접근 시점에 일어났다는 증거. 이미 매핑된 뒤의 쓰기는 폴트 0.
  - 참고: Linux는 익명 메모리의 **첫 읽기**를 공유 zero page에 매핑하므로 읽기만으로는 RSS가 거의 안 는다. 이 macOS 실행에서는 읽기에도 페이지가 실제로 할당되었다. 같은 "demand zero"라도 OS마다 세부가 다르다.
  - Apple Silicon macOS의 기본 페이지는 **16 KB**다(`getpagesize()`가 16384). VAX의 512 B보다 32배 크다.
- **2번 COW**: 자식의 읽기에서도 2048번 폴트가 났다. XNU는 fork 때 자식 페이지 테이블(pmap)을 비워 두고 첫 접근 시 **공유 페이지를 읽기 전용으로 채워 넣는** 가벼운 폴트를 낸다(복사 없음). 쓰기에서 다시 2048번 폴트 — 이번엔 **페이지마다 실제 복사**가 일어나서 시간이 약 3~4배 더 걸렸다(1512 µs vs 5232 µs; 실행마다 조금씩 다름). 부모는 여전히 `0xAB`를 본다 — 자식의 쓰기가 새지 않았다.
- **3번 reference bit 흉내**: epoch 1에서 1, 3, 3, 6을 건드렸지만 trap은 3번뿐(페이지 3의 두 번째 접근은 이미 권한이 복구돼서 trap 없음 — "use bit는 한 번만 세팅하면 된다"). epoch 2에서 다시 다 막은 뒤 3, 7만 쓰자 victim 후보(use=0)는 0,1,2,4,5,6. 이것이 Babaoglu & Joy의 아이디어 그대로다.
  - 주의: 시그널 핸들러에서 `mprotect`를 부르는 것은 POSIX상 async-signal-safe 목록에 없다. 학습용 데모로는 잘 동작하지만 제품 코드에서는 `userfaultfd`(Linux) 같은 정식 메커니즘을 쓴다.

## 9. 펌웨어 엔지니어의 눈으로

- **Demand zeroing ↔ SSD의 unmapped LBA.** TRIM/Deallocate된 LBA나 한 번도 안 쓴 LBA를 읽으면 FTL은 NAND를 읽지 않고 **0(또는 정해진 패턴)을 돌려준다**(NVMe의 Deallocated 읽기 동작, SATA의 RZAT). 매핑 테이블에 "unmapped" 표시만 있고 실제 NAND 페이지는 없다 — VMS의 "PTE의 OS 예약 비트로 demand-zero 표시"와 같은 구조다.
- **COW ↔ NAND의 out-of-place write.** NAND는 덮어쓰기가 불가능하니 FTL은 모든 쓰기를 새 페이지에 하고 매핑만 바꾼다 — 사실상 **항상 COW**다. 그래서 SSD/파일시스템 스냅샷이 싸다(옛 매핑을 유지만 하면 됨). 공유된 원본 블록을 GC가 함부로 지우면 안 되는 것도 COW의 refcount 문제와 같다.
- **VAX의 "작은 페이지 → 거대 페이지 테이블" ↔ FTL 매핑 테이블 크기.** 4 KB 단위 page-mapping FTL은 1 TB당 2^40 / 2^12 = 2^28 ≈ 2.7억 엔트리 × 4 B ≈ **1 GB DRAM**이 필요하다. VMS가 페이지 테이블을 스왑 가능한 커널 가상 메모리에 둔 것처럼, DRAM이 작은 SSD는 매핑 테이블을 NAND에 두고 일부만 캐시한다(DFTL).
- **Page clustering ↔ 쓰기 coalescing.** dirty list를 모아 큰 쓰기를 내듯, FW는 작은 호스트 쓰기를 write buffer에 모아 NAND page / multi-plane / superblock stripe 단위로 프로그램한다.
- **Reference bit 흉내 ↔ ARMv8의 Access Flag.** ARMv8.0에서 Access Flag(AF)=0인 페이지에 접근하면 **Access flag fault**가 나서 SW가 AF를 세팅한다 — VMS의 보호 비트 트릭이 아키텍처에 공식화된 셈이다. ARMv8.1부터는 HW가 AF/dirty 상태를 직접 갱신하는 옵션(HAFDBS)이 생겼다. 베어메탈/RTOS에서 MMU를 직접 다룰 때 AF를 1로 안 해 두면 첫 접근에 영문 모를 fault가 나는 이유다.
- **Segmented FIFO의 RSS 한도 ↔ 공유 자원의 테넌트별 할당량.** NVMe 멀티 네임스페이스/멀티 큐에서 한 호스트가 write buffer를 독점하지 못하게 큐별 크레딧을 두는 것, AI 가속기에서 여러 컨텍스트가 디바이스 메모리를 나눠 쓸 때 컨텍스트별 한도를 두는 것이 같은 "memory hog" 대책이다.

## 10. 면접 질문

### Q1. fork()에서 copy-on-write는 정확히 어떻게 동작하나?
<details>
<summary>답 보기</summary>

- `fork()` 시 커널은 물리 페이지를 복사하지 않고 **부모의 페이지 테이블(매핑)만 복제**한다. 쓰기 가능한 private 페이지는 **부모·자식 양쪽 모두 읽기 전용**으로 바꾸고, 페이지 refcount를 올린다.
- 어느 쪽이든 쓰면 **protection fault** → 커널이 "원래 쓰기 가능 + COW 페이지"임을 확인 → refcount가 1보다 크면 새 페이지 할당, 내용 복사, 쓰기 가능으로 재매핑 → 명령 재실행. refcount가 1이면 복사 없이 쓰기 권한만 복구.
- 이점: `fork()+exec()` 패턴에서 거의 아무것도 복사하지 않음. 남는 비용은 **페이지 테이블 복제**와 TLB shootdown이라, 큰 프로세스에서는 `vfork`/`posix_spawn`을 쓴다.

</details>

### Q2. OS는 왜 새 페이지를 0으로 채워야 하나? demand zeroing은 왜 이득인가?
<details>
<summary>답 보기</summary>

- **보안**: 물리 프레임은 이전에 다른 프로세스(또는 커널)가 쓰던 것이다. 0으로 안 채우면 비밀번호, 키 같은 데이터가 **프로세스 간에 새어 나간다**.
- **Demand zeroing**: 할당 요청 시엔 PTE만 만들고(접근 불가/특수 표시), **첫 접근 폴트 때** 프레임 할당 + zero + 매핑. `malloc(1GB)` 후 일부만 쓰는 프로그램은 실제로 쓴 페이지만 비용을 치른다.
- Linux는 첫 **읽기**를 공유 zero page로 처리하고 첫 쓰기 때 진짜 페이지를 할당해 더 게으르다.
- 부작용: 메모리 **overcommit** — 약속한 메모리를 나중에 못 줄 수 있어 OOM 가능.

</details>

### Q3. HW에 reference bit가 없다면 어떻게 LRU 근사를 하나?
<details>
<summary>답 보기</summary>

- Babaoglu & Joy 기법: 주기적으로 페이지들을 **invalid/no-access로 표시**(원래 권한은 SW가 따로 기억) → 접근 시 **fault**가 나면 "참조됨"으로 기록하고 권한 복구 → 교체 시 아직 no-access인 페이지가 최근 미사용.
- 트레이드오프: 지우는 주기가 짧으면 fault 오버헤드, 길면 전부 참조됨으로 보여 정보 없음.
- 현대 사례: **ARMv8.0 Access Flag fault**가 이 방식을 아키텍처 차원에서 지원. ARMv8.1 HAFDBS는 HW가 직접 갱신.
- VMS는 아예 다른 길: **segmented FIFO + second-chance 리스트**로 reference bit 없이 LRU에 근접.

</details>

### Q4. 커널을 모든 프로세스 주소 공간에 매핑하는 이유와 위험은?
<details>
<summary>답 보기</summary>

- 이유: 시스템 콜 때 **주소 공간 전환(CR3/TTBR 변경, TLB flush) 없이** 커널 코드 실행, 유저 버퍼를 **직접 포인터로 접근**(copy_from_user), 커널이 "보호된 라이브러리"처럼 동작.
- 보호: PTE의 권한 비트(유저/슈퍼바이저)로 유저 모드 접근 차단.
- 위험: **Meltdown** — 일부 CPU가 권한 검사 전에 투기적으로 커널 데이터를 읽어 캐시 사이드채널로 유출. 대응으로 **KPTI**(유저 모드에선 커널 매핑 최소화) → 시스템 콜마다 페이지 테이블 전환 비용, PCID/ASID로 완화.
- ARM64는 원래 TTBR0(유저)/TTBR1(커널)로 나뉘어 있어 구조가 조금 다르다.

</details>

### Q5. Segmented FIFO는 무엇이고 순수 FIFO·LRU와 비교하면?
<details>
<summary>답 보기</summary>

- 프로세스별 **RSS 한도 + FIFO**로 쫓아내되, 쫓긴 페이지를 바로 버리지 않고 전역 **clean/dirty second-chance 리스트**에 둔다. 재접근하면 디스크 I/O 없이 **reclaim**.
- 순수 FIFO 대비: FIFO의 "중요 페이지 퇴출" 실수를 싼 soft fault로 만회. 리스트가 클수록 LRU에 근접.
- LRU 대비: HW reference bit가 **필요 없고**, RSS 한도 덕에 **memory hog 격리**(전역 LRU는 공정성 없음).
- dirty list는 묶어서 쓰므로 **clustering**과 자연스럽게 결합.

</details>

## 11. 자가 점검 & 숙제

### 퀴즈

**Q1.** VAX에서 P0 세그먼트 하나를 끝까지 다 쓰면 그 페이지 테이블 크기는? (PTE 4 B)
<details>
<summary>정답</summary>

P0 = 2^30 B, 페이지 2^9 B → 2^21 PTE × 4 B = **8 MB**. (선형 전체 32 MB의 1/4)

</details>

**Q2.** 유저 페이지 테이블을 커널 가상 메모리에 두었을 때, TLB miss 한 번에 최악의 경우 메모리 접근이 몇 번 늘어나나?
<details>
<summary>정답</summary>

PTE의 주소가 커널 가상 주소이므로, 먼저 **시스템 페이지 테이블에서 그 주소를 변환**(1회), 그다음 **유저 PTE 읽기**(1회), 마지막으로 **데이터 접근**(1회). PTE 쪽 주소 변환도 TLB에 없으면 데이터 외에 2번의 추가 메모리 접근이 생긴다.

</details>

**Q3.** COW 페이지에 자식이 쓰는데 부모가 이미 종료해서 refcount가 1이라면 커널은 무엇을 해야 하나?
<details>
<summary>정답</summary>

복사할 필요 없이 **PTE를 쓰기 가능으로 바꾸기만** 하면 된다(reuse). 공유자가 없으니 private 복사본이 이미 자기 것이다.

</details>

**Q4.** 이 노트의 macOS 실험에서 64 MiB 영역을 "읽기만" 했는데도 RSS가 늘었다. Linux에서 같은 실험을 하면 어떻게 다를까?
<details>
<summary>정답</summary>

Linux는 익명 메모리의 첫 읽기 폴트를 **공유 zero page**에 읽기 전용으로 매핑하므로, 폴트는 나도 **RSS는 거의 늘지 않는다**. 쓰기 단계에서야 페이지가 할당된다(그 때 또 폴트).

</details>
