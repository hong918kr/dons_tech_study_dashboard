0. 한눈에 보기#

CRUX: HOW TO MAKE A LARGE, FAST, RELIABLE DISK — "How can we make a large, fast, and reliable storage system? What are the key techniques? What are trade-offs between different approaches?" (크고 빠르고 믿을 만한 저장 시스템을 어떻게 만들까? 핵심 기법과 그 trade-off 는?)

  • RAID 는 여러 디스크를 묶어 밖에서는 디스크 하나처럼 보이게 한다(투명성 → 배포가 쉬움). 안에서는 논리 I/O 를 물리 I/O 여러 개로 바꾸는 작은 컴퓨터(마이크로컨트롤러 + 펌웨어 + DRAM + NVRAM)다.
  • 평가 축은 용량 · 신뢰성 · 성능. RAID-0(striping)은 성능·용량 최고·신뢰성 0, RAID-1(mirroring)은 랜덤 성능·신뢰성 좋고 용량 절반, RAID-4/5(parity)는 용량 (N−1)/N 에 디스크 1개 고장 허용, 대신 small write 가 4 I/O.
  • RAID-4 는 parity 디스크가 병목(랜덤 쓰기 R/2, 디스크를 늘려도 그대로), RAID-5 는 parity 를 돌려 놓아 N/4·R 로 늘어난다.
  • 여러 디스크를 "동시에" 바꾸는 쓰기는 중간에 전원이 나가면 어긋난다(consistent-update problem) → NVRAM 쓰기 로그.

2. RAID 의 인터페이스와 내부 (38.1)#

밖에서 RAID 는 블록 배열 이다. 파일시스템이 논리 블록 하나를 읽거나 쓰면, RAID 는 "어느 디스크의 어느 오프셋을 몇 번 건드릴지" 를 계산해 물리 I/O 를 낸다. 미러링이라면 논리 쓰기 1 → 물리 쓰기 2.

하드웨어 RAID 는 별도 상자(또는 카드)로, 안에 마이크로컨트롤러 + 펌웨어 + DRAM(버퍼) + 경우에 따라 NVRAM(안전한 쓰기 버퍼) + parity 계산 전용 로직(XOR 엔진) 이 있다. 책의 표현으로 "RAID 는 매우 특화된 컴퓨터 시스템"이다. SSD 컨트롤러가 NAND 채널 수십 개를 묶는 방식(채널/다이 간 striping, 다이 간 parity)이 거의 그대로 이 구조다.

TIP — TRANSPARENCY ENABLES DEPLOYMENT: 새 기능을 넣을 때 나머지 시스템을 안 바꿔도 되게 만들면 채택이 쉬워진다. RAID 는 SCSI 디스크 자리에 그냥 꽂으면 됐기 때문에 처음부터 성공했다.

3. 고장 모델과 평가 기준 (38.2–38.3)#

  • fail-stop 모델: 디스크는 "모든 블록 정상" 아니면 "통째로 영구 고장" 둘 중 하나. 그리고 고장은 즉시 탐지된다. 조용한 데이터 손상(silent corruption)이나 한 블록만 못 읽는 latent sector error 는 일단 무시한다(→ Ch.44 데이터 무결성).
  • 평가 세 축 (디스크 N 개, 각 B 블록):
    • 용량: 사용자에게 보이는 블록 수. 중복 없으면 N·B, 2중 미러면 N·B/2.
    • 신뢰성: 몇 개의 디스크 고장을 견디나.
    • 성능: 워크로드에 따라 다르다 → 순차/랜덤 두 가지로 단순화.

4. RAID-0: Striping (38.4)#

블록을 디스크에 round-robin 으로 뿌린다. 중복이 없으므로 진짜 "RAID" 는 아니지만, 성능·용량의 상한선 역할을 한다.

4.2 chunk 크기#

  • 작은 chunk: 한 파일이 여러 디스크에 퍼져 파일 내부 병렬성 ↑. 대신 한 요청의 위치결정 시간 = 여러 디스크 중 최댓값 이라 늘어난다.
  • 큰 chunk: 파일 하나가 디스크 하나에 머물러 위치결정은 디스크 하나 수준. 처리량은 여러 동시 요청 에 기대야 한다.
  • 정답은 워크로드에 달렸다. 실제 배열은 64KB 정도를 많이 쓰고, 이 장의 분석은 chunk = 1 블록(4KB)으로 단순화한다.

4.3 성능 지표 S, R 계산#

워크로드 두 가지: 순차(큰 연속 요청, 예 1MB) / 랜덤(작은 요청, 여기저기). 디스크 하나의 순차 대역폭을 S, 랜덤을 R 이라 하자. 책의 예: 평균 seek 7 ms, 평균 회전 3 ms, 전송률 50 MB/s, 순차 요청 10 MB, 랜덤 요청 10 KB.

(아래 C 프로그램은 10KB 를 10/1024 MB 로 계산해 R = 0.958 이 나온다. 단위 선택 차이일 뿐이다.)

4.4 RAID-0 분석#

  • 용량: N·B (완벽)
  • 신뢰성: 0 — 디스크 하나만 죽어도 데이터 손실. 디스크 하나의 연간 고장률이 p 면 배열이 살아 있을 확률은 (1−p)^N.
  • 성능: 단일 요청 지연은 디스크 하나와 같다(그 디스크로 보낼 뿐). 처리량은 순차 N·S, 랜덤 N·R.

5. RAID-1: Mirroring (38.5)#

미러 쌍(0,1)(2,3) 위에 striping — RAID-10(1+0). 반대로 RAID-0 배열 두 개를 미러하면 RAID-01(0+1). 읽기는 두 사본 중 아무거나, 쓰기는 둘 다(병렬로).

5.1 분석 (미러 수준 2)#

  • 용량: N·B/2.
  • 신뢰성: 확실히 1개, 운이 좋으면 N/2 개까지(각 쌍에서 하나씩만 죽으면). 그림에서 Disk 0 과 Disk 2 가 죽어도 무사하다. 실무에선 운에 맡기지 않으므로 "1개".
  • 지연: 읽기 T. 쓰기도 병렬이라 거의 T 지만 두 디스크 중 느린 쪽(seek·회전의 최댓값) 을 기다리므로 평균은 T 보다 약간 크다.
  • 순차 쓰기: 논리 1 블록 → 물리 2 블록 → (N/2)·S.
  • 순차 읽기: 한 사본만 읽으면 되니 N·S 일 것 같지만 (N/2)·S 다. 블록 0..7 을 디스크 0,2,1,3,0,2,1,3 에 나눠 읽게 하면, 디스크 0 은 블록 0, 4 를 읽는다. 사이의 블록 2 자리(자기 사본)를 회전하며 그냥 지나가야 하므로 각 디스크는 절반의 대역폭만 낸다.
  • 랜덤 읽기: 아무 사본이나 고를 수 있으니 모든 디스크 사용 → N·R (미러의 최고 장점).
  • 랜덤 쓰기: 물리 2 번 → (N/2)·R.

5.2 Aside: consistent-update problem#

미러에 쓰기를 내는데, 디스크 0 에는 쓰고 디스크 1 에 내기 직전에 전원이 나가면 두 사본이 다르다. 원하는 건 "둘 다 새 값" 또는 "둘 다 옛 값" 이라는 원자성.

해법: write-ahead log. "이 데이터를 디스크 0,1 에 쓸 것" 을 먼저 기록하고 실행, 크래시 후에는 로그를 재실행(replay). 매 쓰기마다 디스크에 로그를 쓰면 너무 비싸므로 하드웨어 RAID 는 배터리 백업 NVRAM 에 로그한다. 소프트웨어 RAID 는 이게 없어서 크래시 후 전체 resync 를 하거나(mdadm 의 write-intent bitmap 으로 범위를 줄임), 파일시스템 저널과 엮는다(책 참고문헌 DAA05). RAID-5 에서 같은 문제를 write hole 이라 부른다: 데이터는 썼는데 parity 를 못 썼다면, 나중에 다른 디스크가 죽었을 때 틀린 parity 로 엉뚱한 데이터를 복원 한다.

6. RAID-4: Parity 로 공간 아끼기 (38.6)#

6.1 XOR parity#

각 stripe 의 parity = 데이터 블록들의 비트별 XOR. 불변식: 각 비트 행의 1 의 개수는 짝수.

C2 가 사라지면 나머지(0, 0, 1, P=0)를 XOR → 1. 복원도 같은 XOR 이다. 블록 단위로는 4KB × 8 = 32,768 개 비트 위치마다 이것을 한다.

책의 4비트 블록 예제(그림 바로 아래 표)를 그림으로 그리면, parity 계산과 복원이 같은 연산 이라는 게 보인다.

수학적으로는 GF(2) 위의 선형 부호다. 블록들을 벡터 d_1..d_k 로 보면 P = Σd_i 이고, 미지수가 하나(사라진 블록)일 때만 풀린다 → 정확히 1개 고장만 복원. 2개를 견디려면 독립 방정식이 하나 더 필요하다(RAID-6 의 Q = Σ g^i·d_i, GF(2^8) 곱셈 — Reed-Solomon).

6.2 RAID-4 분석#

  • 용량: (N−1)·B.
  • 신뢰성: 1개. 2개면 복구 불가.
  • 순차 읽기: parity 디스크를 뺀 (N−1)·S.
  • 순차 쓰기: full-stripe write — 블록 0,1,2,3 이 한꺼번에 오면 P0 = 0⊕1⊕2⊕3 을 계산해 5개 디스크에 병렬로 쓴다. 읽기가 필요 없으므로 가장 효율적. 유효 대역폭 (N−1)·S (parity 디스크도 일하지만 사용자 데이터는 아님).
  • 랜덤 읽기: (N−1)·R.
  • 랜덤 쓰기: 여기서 문제가 터진다.

6.3 small write: additive vs subtractive#

블록 1 하나만 덮어쓰면 P0 도 바뀌어야 한다. 방법 둘:

  • additive: 같은 stripe 의 나머지 데이터 블록(0, 2, 3)을 읽어 새 블록 1 과 XOR → 새 P0. 쓰기 2번. I/O = (N−2) 읽기 + 2 쓰기.
  • subtractive: 옛 데이터와 옛 parity 만 읽는다.

C_old 와 C_new 가 같은 비트는 parity 가 그대로, 다른 비트는 뒤집는다는 뜻이다. I/O = 2 읽기 + 2 쓰기 = 4, 디스크 수와 무관.

책이 남긴 질문 "언제 additive 가 더 적은 I/O 인가?": additive = N 개(N−2 읽기 + 2 쓰기), subtractive = 4 개. N < 4 이면 additive 가 이득, N = 4 이면 동률, N ≥ 5 면 subtractive. 즉 데이터 디스크 2개(N=3)짜리 배열에서만 additive 가 이긴다. raid.py 는 실제로 "쓸 블록 수 + 1 ≤ 안 쓰는 블록 수" 이면 subtractive, 아니면 additive 를 고른다 — 여러 블록을 쓰는 부분 stripe 쓰기까지 일반화한 같은 판단이다.

6.4 parity 디스크 병목#

블록 4 와 13 을 동시에 쓰면 데이터는 D0, D1 로 나뉘지만 parity P1, P3 는 둘 다 D4 에 있다. 모든 small write 가 parity 디스크에서 read 1 + write 1 을 해야 하므로 직렬화 된다. parity 디스크 하나가 낼 수 있는 랜덤 I/O 가 R 이고 쓰기 하나에 2 I/O 를 쓰니 RAID-4 랜덤 쓰기 처리량은 R/2, 디스크를 아무리 늘려도 그대로다.

지연: 읽기 T. 쓰기는 읽기 2개(병렬) 후 쓰기 2개(병렬)라 약 2T(읽기에서 최댓값 위치결정, 쓰기는 seek 없이 회전만이라 평균보다 조금 짧을 수 있음).

7. RAID-5: Parity 를 돌려 놓기 (38.7)#

parity 위치를 stripe 마다 한 칸씩 왼쪽으로 돌린다. 이 배치(데이터가 parity 바로 오른쪽에서 시작해 감아 도는 것)를 left-symmetric 이라 한다. 데이터를 왼쪽부터 채우되 parity 칸만 건너뛰는 배치가 left-asymmetric(아래 C 출력 참고). left-symmetric 은 순차 읽기 때 연속된 N 개 블록이 항상 N 개의 다른 디스크에 걸쳐서 더 좋다.

분석: 용량·신뢰성·순차 성능·단일 요청 지연은 RAID-4 와 같다. 달라지는 두 가지:

  • 랜덤 읽기: parity 칸도 데이터를 품고 있으므로 모든 디스크 사용 → N·R.
  • 랜덤 쓰기: 쓰기 1 은 D1+D4, 쓰기 10 은 D0+D2 — 병렬. 요청이 충분히 많으면 모든 디스크가 고르게 바쁘다. 총 물리 I/O 처리 능력 N·R 을 쓰기당 4 I/O 로 나눠 N/4 · R. 4 배 손실은 parity RAID 의 근본 비용이다.

RAID-5 가 RAID-4 를 거의 완전히 대체했다. 예외: 항상 큰 쓰기만 하는 시스템(full-stripe write 만 발생 — 예: NetApp WAFL 은 쓰기를 모아 full-stripe 로 내보냄)은 더 단순한 RAID-4 를 쓰기도 한다.

각 칸 유도 한 줄 요약:

  • 순차는 "사용자 데이터를 실어 나르는 디스크 수 × S". 미러 읽기가 N/2 인 건 건너뛴 사본 자리를 회전으로 지나가기 때문.
  • 랜덤은 "전체 물리 I/O 능력 ÷ 논리 I/O 당 물리 I/O 수". RAID-1 쓰기 2개 → N·R/2, RAID-5 쓰기 4개 → N·R/4, RAID-4 는 병목 디스크 하나의 R ÷ 2.

수치 예(N=4, S=47.62, R=0.958; 아래 C 출력): RAID-0 랜덤 쓰기 3.83 MB/s, RAID-1 1.92, RAID-5 0.96, RAID-4 0.48.

결론(책): 성능만 원하면 RAID-0, 랜덤 성능 + 신뢰성 이면 RAID-1(용량 비용), 용량 + 신뢰성 이면 RAID-5(small write 비용), 순차 I/O 만 하면서 용량을 최대화하려 해도 RAID-5.

신뢰성 숫자 감각(새 예제): 디스크 하나의 연간 고장률(AFR) 2%, 디스크 8개. RAID-0 이 1년 버틸 확률 = 0.98^8 ≈ 85%. RAID-5 는 두 번째 디스크가 재구성 중에 죽어야 데이터를 잃는다. 재구성이 20TB ÷ 200MB/s ≈ 28 시간 걸리면, 남은 7개 중 하나가 그 사이 죽을 확률 ≈ 7 × 0.02 × 28/8760 ≈ 0.045%. 작아 보이지만, 재구성 중 남은 디스크 전체(140TB)를 읽다가 URE(10^15 비트당 1)를 만날 기대 횟수는 1.12 × 10^15 비트 ÷ 10^15 ≈ 1.1회 — 그래서 대용량 HDD 에는 RAID-6 를 쓴다.

9. 그 밖의 쟁점 (38.9)#

  • RAID-2/3(비트/바이트 단위 striping + ECC/parity), RAID-6(이중 parity, 2개 고장 허용 — Row-Diagonal Parity 등).
  • hot spare: 고장 즉시 재구성을 시작할 예비 디스크. 고장 중(degraded) 성능과 재구성 중 성능 이 실제 운영에서 중요하다(degraded RAID-5 의 읽기는 사라진 디스크 블록마다 N−1 개를 읽어 XOR).
  • 더 현실적인 고장 모델: latent sector error, 블록 손상 → 체크섬, scrubbing(Ch.44).
  • 소프트웨어 RAID: 싸지만 consistent-update 문제를 NVRAM 없이 풀어야 한다.

11. 펌웨어 엔지니어의 눈으로#

  • SSD 컨트롤러 안의 RAID. NAND 다이 하나가 통째로 죽거나(die failure) 워드라인 단위로 망가지는 경우를 대비해, 엔터프라이즈 SSD FW 는 다이·플레인 간 XOR parity stripe 를 만든다(Samsung RAISE, Micron RAIN 같은 이름). 예: 32 다이 중 31 개에 데이터, 1 개에 parity → 용량 1/32 를 내고 LDPC 로도 못 고친 페이지를 복원한다. 이게 정확히 RAID-5 의 "full-stripe write" 다 — FW 는 쓰기를 모아 stripe 단위로 program 하므로 small-write 문제가 없다(로그 구조 덕분). parity 는 컨트롤러의 XOR 엔진이 SRAM 에서 누적한다.
  • write hole = 전원 손실 시 parity 미완성. stripe 를 다 채우기 전에 전원이 나가면 그 stripe 의 parity 가 없다. FW 는 PLP 캐패시터 시간 안에 부분 parity 를 flush 하거나, 열린(open) stripe 를 복구 시 "parity 없음" 으로 표시하고 다음 GC 때 다시 쓴다. 책의 "NVRAM 에 로그" 해법과 같은 문제를 같은 재료(비휘발 + 순서)로 푼다.
  • 채널/다이 striping = RAID-0. 호스트 128KB 순차 쓰기를 4KB 페이지(또는 16KB 멀티플레인 페이지) 단위로 채널·다이에 round-robin 하는 것이 RAID-0 striping 이고, chunk 크기 trade-off(작으면 병렬성↑, 크면 위치결정 1회)가 "슈퍼 블록/슈퍼 페이지" 크기 결정과 같다.
  • mirroring 은 FW 메타데이터에 쓴다. L2P 체크포인트, 부트 영역, bad block table 같은 치명적 메타데이터는 SLC 모드 블록에 이중 기록(RAID-1)하는 것이 흔하다. 데이터는 parity, 메타데이터는 mirror — 용량과 신뢰성의 trade-off 를 영역별로 다르게 고른 예다.
  • AI 클러스터의 checkpoint 저장. 대규모 학습의 체크포인트(수 TB)를 NVMe-oF 나 분산 파일시스템에 쓸 때는 큰 순차 쓰기라 RAID-5/6 나 erasure coding 이 잘 맞는다(full-stripe). 반대로 작은 랜덤 업데이트가 많은 메타데이터 서버는 미러를 쓴다 — 이 장의 표가 그대로 설계 기준이다.

12. 면접 질문#

Q1. RAID-5 에서 4KB 랜덤 쓰기 하나가 몇 번의 디스크 I/O 를 일으키나? 왜?#

답 보기

4번(읽기 2 + 쓰기 2). parity 를 갱신해야 하는데 subtractive 방식 P_new = (D_old ⊕ D_new) ⊕ P_old 를 쓰면 옛 데이터·옛 parity 를 읽고, 새 데이터·새 parity 를 쓴다. additive(나머지 데이터 전부 읽기)는 N−2 읽기 + 2 쓰기라 N ≥ 5 에서 더 비싸다. 그래서 RAID-5 랜덤 쓰기 처리량은 N·R/4. full-stripe 쓰기는 읽기 0 이므로, 쓰기를 모아 stripe 단위로 내는 로그 구조(WAFL, LFS, SSD FTL)가 parity RAID 와 궁합이 좋다.

Q2. RAID-4 와 RAID-5 의 차이, RAID-4 가 여전히 쓰이는 경우는?#

답 보기

RAID-4 는 parity 가 한 디스크에 고정 되어 모든 small write 가 그 디스크에서 직렬화된다(랜덤 쓰기 R/2, 디스크 수와 무관). RAID-5 는 parity 를 stripe 마다 회전 해 병목을 없애 N·R/4 로 스케일하고, 랜덤 읽기도 N·R(RAID-4 는 N−1). 용량·신뢰성·순차 성능은 같다. RAID-4 는 항상 full-stripe 로만 쓰는 시스템(NetApp WAFL)에서 쓴다 — parity 디스크 병목이 생기지 않고, 디스크 추가 시 parity 재계산이 필요 없는 등 구현이 단순하다.

Q3. RAID write hole 이 무엇이고 어떻게 막나?#

답 보기

여러 디스크를 갱신하는 한 논리 쓰기(데이터 + parity, 또는 미러 두 사본) 도중 크래시가 나면 stripe 가 불일치 한다. 당장은 티가 안 나지만, 나중에 다른 디스크가 죽어 재구성할 때 틀린 parity 로 엉뚱한 데이터를 조용히 복원 한다. 해법: (1) 하드웨어 RAID 의 배터리/캐패시터 백업 NVRAM 쓰기 로그(write-ahead, 크래시 후 replay), (2) 소프트웨어 RAID 의 write-intent bitmap + resync, 또는 journal 장치(md raid5 journal), (3) copy-on-write + 가변 stripe(ZFS RAID-Z 는 덮어쓰기를 안 해서 hole 이 구조적으로 없음), (4) 파일시스템 저널과 협력.

Q4. 8 × 20TB HDD 로 RAID-5 를 구성하는 게 왜 위험한가? 숫자로 설명하라.#

답 보기

한 디스크가 죽으면 재구성을 위해 나머지 7개 전체(140TB = 1.12×10^15 비트)를 읽어야 한다. 소비자급 HDD 의 URE 사양이 10^15 비트당 1 이면 재구성 중 읽기 오류 기대값이 약 1회 → 해당 stripe 복원 불가. 또 재구성 시간(20TB ÷ ~200MB/s ≈ 28시간 이상, 서비스 부하가 있으면 며칠) 동안 두 번째 디스크 고장 위험도 있다. 같은 배치(lot)·같은 사용시간 디스크는 고장이 상관되어 독립 가정보다 위험하다. 그래서 RAID-6/이중 parity, 더 작은 RAID 그룹, 분산 erasure coding(재구성을 여러 노드에 분산)을 쓴다.

Q5. 미러링에서 순차 읽기가 N·S 가 아니라 (N/2)·S 인 이유는? 개선할 방법은?#

답 보기

블록을 사본들에 번갈아 분배하면 각 디스크는 한 블록 건너 한 블록 을 읽게 되고, 건너뛴 블록(자기 사본) 위를 회전하며 그냥 지나가는 시간 동안 유효 대역폭을 내지 못한다 → 디스크당 S/2. 개선: 분배 단위를 큰 덩어리(예: 디스크 0 은 앞 절반 1MB, 디스크 1 은 뒤 절반 1MB)로 바꾸면 각 디스크가 연속으로 읽어 S 에 가까워진다(Linux md raid1/raid10 의 far/offset layout 이 이 아이디어). 랜덤 읽기는 원래 N·R 로 미러가 가장 잘하는 영역이다.

13. 자가 점검 & 숙제#

퀴즈#

퀴즈 1. RAID-0, chunk 2 블록, 디스크 4개. 논리 블록 21 은 어느 디스크 몇 번째 오프셋?

정답

chunk = 21/2 = 10 → disk = 10 % 4 = 2, offset = (10/4)·2 + (21 % 2) = 4 + 1 = 5.

퀴즈 2. 데이터 0110, 1010, 0011 의 XOR parity 는? 두 번째 블록이 사라졌을 때 복원은?

정답

0110 ⊕ 1010 = 1100, ⊕ 0011 = 1111. 복원: 0110 ⊕ 0011 ⊕ 1111 = 1010.

퀴즈 3. 디스크 6개 RAID-5 의 용량 효율과 랜덤 쓰기 처리량(R 단위)은?

정답

용량 5/6 ≈ 83%. 랜덤 쓰기 6/4 · R = 1.5R.

퀴즈 4. RAID-1 이 운 좋으면 몇 개까지 고장을 견디나? 4 디스크(2쌍)에서 고장 2개가 생겼을 때 데이터를 잃을 확률은?

정답

N/2 개. 2개 고장 조합 C(4,2)=6 중 같은 쌍인 경우 2가지 → 1/3.

숙제 (원문 Homework 에서 고른 것)#

  • Q1 (매핑, LS vs LA): -L 5 -5 LS 와 -5 LA 로 같은 시드를 돌려 매핑 차이를 손으로 맞추기 → rotated parity 배치 규칙을 몸에 익히는 문제.
  • Q4 (요청 크기 8k/12k/16k, -W seq): 요청이 stripe 크기와 맞을 때 RAID-4/5 가 읽기 없이 쓰는(full-stripe) 순간을 찾는 문제 → "stripe 정렬 쓰기" 의 근거.
  • Q7 (쓰기 타이밍 스케일링): 디스크 수를 늘릴 때 RAID-4 쓰기만 안 줄어드는 것을 위 결과처럼 확인하고, R/2 공식으로 시간을 예측해 보는 문제.
