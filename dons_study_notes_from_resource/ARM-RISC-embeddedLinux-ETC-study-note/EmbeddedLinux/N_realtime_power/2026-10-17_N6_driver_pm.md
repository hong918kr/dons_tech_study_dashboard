# N6. 드라이버의 PM 구현 — dev_pm_ops, suspend 순서, wakeup source

> **이 노트를 다 읽으면**: `struct dev_pm_ops`의 23개 콜백이 시스템 suspend·hibernate·runtime PM의 어느 순간에 불리는지 실제 로그로 설명할 수 있다 · supplier/consumer 두 드라이버의 suspend 순서를 dpm_list와 device link로 맞출 수 있다 · runtime PM(autosuspend, usage count)과 regmap regcache로 "전원이 꺼져도 설정이 돌아오는" 드라이버를 짤 수 있다 · wakeup source와 wake IRQ로 장치가 시스템을 깨우게(또는 suspend를 막게) 만들 수 있다
> **왜 필요한가**: "resume 뒤에 I2C 센서가 죽는다", "배터리가 하룻밤에 다 닳는다", "버튼을 눌러도 안 깬다" — 양산 직전에 터지는 버그 대부분이 드라이버 PM 코드에서 나오고, 면접관은 이걸로 드라이버 완성도를 가늠한다
> **Don 기준 난이도**: SSD 펌웨어의 power state 진입·복귀(컨텍스트 저장, 클럭 게이팅, wake 이벤트)는 이미 안다 / 새로 배울 것은 "수백 개 드라이버의 순서를 커널이 정하는 규칙"과 runtime PM의 참조 카운트 모델
> **선행 노트**: G2(device model, device link), G3 §12(`DEFINE_SIMPLE_DEV_PM_OPS` 한 쌍), H2 §9(regcache로 suspend/resume), H3(clk/regulator), H4(pinctrl sleep state, gpio-sim), H6(IRQ 컨트롤러), N5(전원 관리 시스템 관점)

## 0. 큰 그림 — 이게 왜 필요한가

### 0.1 펌웨어에서는 이렇게 했다

SSD 펌웨어에서 NVMe의 낮은 power state(PS3/PS4)로 들어갈 때를 떠올려 보자. 호스트가 들어가라고 하거나(Set Features), 일정 시간 일이 없으면 스스로 들어간다(APST — Autonomous Power State Transition). 진입 순서는 펌웨어가 직접 짠다: 진행 중인 명령을 마무리 → NAND 채널을 멈춤 → 컨트롤러 레지스터 컨텍스트를 always-on SRAM에 저장 → 클럭 게이팅 → PLL off. 깨어날 때는 정확히 거꾸로. 그리고 어떤 이벤트(PCIe 링크 활동, 타이머)가 칩을 깨울지 미리 설정해 둔다.

Linux에서도 하는 일은 똑같다. 다른 점은 **그 순서를 한 사람이 짜지 않는다**는 것이다. 장치마다 드라이버가 따로 있고, 각 드라이버는 "내 장치를 재우고 깨우는 법"만 콜백으로 커널에 준다. **순서**는 PM core(`drivers/base/power/`)가 장치 트리 관계와 device link를 보고 정한다. 그래서 드라이버 작성자가 알아야 할 것은 세 가지다.

1. **언제 불리나** — 어떤 콜백이 어느 단계(phase)에서, IRQ가 켜진 상태인지 꺼진 상태인지.
2. **누구 다음에 불리나** — 내가 쓰는 버스·클럭·레귤레이터가 나보다 먼저 잠들면 안 된다.
3. **무엇을 잃나** — 전원이 꺼지면 레지스터가 날아간다. 무엇을 저장하고 무엇을 다시 쓸지.

그림 1 — Linux 드라이버 PM의 두 축. 시스템 sleep은 전체가 함께 자는 것(APST가 아니라 호스트가 시키는 PS 전환에 가깝다), runtime PM은 장치마다 놀면 혼자 자는 것(APST에 가깝다). 둘은 별개의 상태 기계지만 같은 하드웨어를 다루므로 `pm_runtime_force_suspend/resume`으로 잇는다.

- **시스템 sleep** (system suspend / hibernation): 유저가 `/sys/power/state`에 `freeze`(s2idle), `mem`(suspend-to-RAM), `disk`(hibernate)를 쓰면 시작한다. 유저 프로세스를 얼리고(freeze), **모든 장치**의 콜백을 정해진 순서로 부르고, CPU를 idle에 두거나 끈다. 전원·열 관점의 시스템 그림은 N5가 다룬다.
- **runtime PM**: 시스템은 살아 있고, **장치 하나**가 일이 없으면 그 장치만 끈다. 드라이버가 `pm_runtime_get`/`put`으로 "지금 쓴다/다 썼다"를 알리면 PM core가 usage count가 0이 될 때 `runtime_suspend`를 부른다.

### 0.3 이 노트의 실습 — 공급자와 소비자, 두 드라이버

센서 키트로 생각하자. IMU(소비자, consumer)는 I2C 컨트롤러(공급자, supplier)를 통해서만 레지스터에 닿는다. 이 관계를 두 개의 platform 드라이버로 흉내 낸다.

| 모듈 | 역할 | 흉내 내는 실제 부품 |
|---|---|---|
| `n6_bus.ko` | 공급자. `n6_bus_xfer()`로 "버스 전송"을 해 준다. 잠든 상태에서 전송이 오면 `transfer while suspended`를 찍고 `-ESHUTDOWN` | I2C 컨트롤러 + 그 뒤의 센서 칩 레지스터 8개 |
| `n6_imu.ko` | 소비자. regmap(캐시) 위에서 레지스터를 쓰고, runtime PM으로 칩 전원을 끈다. gpio-sim 라인을 wake IRQ로 쓴다 | IMU 드라이버 |
| `n6_board.ko` | "보드 파일". 두 platform 장치를 **등록 순서를 골라** 만들고, wake GPIO를 연결한다 | DT의 노드 두 개 |
| `n6_wkey.ko` | DT 노드로 바인딩. PL061 GPIO 3번을 진짜 wake IRQ로 쓴다 | 전원 버튼 |

실험 환경: VM 호스트 커널 `7.0.0-38-generic`, QEMU 게스트 커널 **`6.18.55-trace`**(`/var/lab/out/Image-trace` — PM_DEBUG, PM_ADVANCED_DEBUG, PM_SLEEP_DEBUG, DYNAMIC_DEBUG, gpio-sim 포함), BusyBox initramfs, `-smp 2 -m 1G`. QEMU는 TCG(에뮬레이션)이고 VM을 여러 작업이 공유해 부하가 높다. **이 노트의 모든 시간 값은 실제 하드웨어 수치가 아니다** — 순서와 상대적인 크기만 본다.

## 1. 실습 판 깔기

### 1.1 공급자 — 가짜 버스 컨트롤러와 그 뒤의 칩

공급자 쪽 API. 소비자는 이 세 함수만 쓴다.

```c
/* n6_bus.h — supplier("bus") API used by the consumer sensor driver */
#ifndef N6_BUS_H
#define N6_BUS_H
#include <linux/device.h>
struct device *n6_bus_get_dev(void);
int n6_bus_xfer(bool write, u8 reg, u8 *val);
void n6_bus_chip_power(bool on);	/* "regulator" of the sensor chip */
ssize_t n6_bus_raw_show(struct device *dev, struct device_attribute *a, char *buf);
#endif
```

"칩"은 공급자 모듈 안의 배열 8바이트다. `n6_bus_xfer()`는 실제 I2C 코어의 `__i2c_check_suspended()`(6.18 `drivers/i2c/i2c-core.h`)를 흉내 내서, 컨트롤러가 시스템 suspend 중이거나 runtime-suspended면 거부한다. 칩 전원을 끄면 레지스터를 `0xEE`로 **오염(poison)** 시키고, 켜면 POR(power-on reset) 값으로 되돌린다. `raw` 속성은 버스를 거치지 않고 배열을 그대로 보여 준다 — 로직 분석기로 칩을 직접 보는 것에 해당하는 뒷문이다.

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_bus_chip.c — fake bus controller + a fake sensor chip behind it */
#include <linux/module.h>
#include <linux/pm_runtime.h>
#include "n6_bus.h"

#define NREG 8
static const u8 chip_por[NREG] = { 0x6c, 0, 0x00, 0x10, 0, 0, 0, 0 };
static u8 chip[NREG] = { 0x6c, 0, 0x00, 0x10, 0, 0, 0, 0 };
static bool chip_on = true;
struct device *n6_bus_dev;	/* set by probe, cleared by remove */
bool n6_bus_sys_suspended;	/* set in .suspend, cleared in .resume */

struct device *n6_bus_get_dev(void) { return n6_bus_dev; }
EXPORT_SYMBOL_GPL(n6_bus_get_dev);

int n6_bus_xfer(bool write, u8 reg, u8 *val)
{
	struct device *d = n6_bus_dev;

	if (!d)
		return -ENODEV;
	if (n6_bus_sys_suspended || pm_runtime_status_suspended(d)) {
		dev_err(d, "transfer while %s (%s reg 0x%02x)\n",
			n6_bus_sys_suspended ? "suspended" : "runtime-suspended",
			write ? "write" : "read", reg);
		return -ESHUTDOWN;	/* same errno as i2c core */
	}
	if (!chip_on)
		return -ENXIO;		/* chip unpowered = NACK */
	if (reg >= NREG)
		return -EINVAL;
	if (write)
		chip[reg] = *val;
	else
		*val = (reg == 1) ? chip[1]++ : chip[reg];	/* 1 = DATA */
	return 0;
}
EXPORT_SYMBOL_GPL(n6_bus_xfer);

void n6_bus_chip_power(bool on)
{
	if (on)
		memcpy(chip, chip_por, NREG);	/* power-on reset values */
	else
		memset(chip, 0xEE, NREG);	/* contents lost (poison) */
	chip_on = on;
	pr_info("n6_bus: chip power %s\n", on ? "ON (POR values)" : "OFF (regs=0xEE)");
}
EXPORT_SYMBOL_GPL(n6_bus_chip_power);

/* backdoor dump, like probing the chip with a logic analyzer */
ssize_t n6_bus_raw_show(struct device *dev, struct device_attribute *a, char *buf)
{
	return sysfs_emit(buf, "%8ph\n", chip);
}
```

공급자 드라이버. 모든 phase의 콜백을 로그만 찍게 채웠다. 매크로 묶음(`SYSTEM_SLEEP_PM_OPS` 등)은 §2에서 푼다.

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_bus_drv.c — supplier platform driver: full dev_pm_ops, logs every phase */
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/pm_runtime.h>
#include "n6_bus.h"

extern struct device *n6_bus_dev;
extern bool n6_bus_sys_suspended;
static DEVICE_ATTR(raw, 0444, n6_bus_raw_show, NULL);

#define LOG(dev) dev_info(dev, "%s\n", __func__)
static int bus_prepare(struct device *d)      { LOG(d); return 0; }
static void bus_complete(struct device *d)    { LOG(d); }
static int bus_suspend(struct device *d)      { LOG(d); n6_bus_sys_suspended = true; return 0; }
static int bus_resume(struct device *d)       { n6_bus_sys_suspended = false; LOG(d); return 0; }
static int bus_suspend_late(struct device *d) { LOG(d); return 0; }
static int bus_resume_early(struct device *d) { LOG(d); return 0; }
static int bus_suspend_noirq(struct device *d){ LOG(d); return 0; }
static int bus_resume_noirq(struct device *d) { LOG(d); return 0; }
static int bus_rt_suspend(struct device *d)   { dev_info(d, "runtime_suspend: bus clock OFF\n"); return 0; }
static int bus_rt_resume(struct device *d)    { dev_info(d, "runtime_resume: bus clock ON\n"); return 0; }

static const struct dev_pm_ops n6_bus_pm = {
	.prepare = pm_sleep_ptr(bus_prepare),
	.complete = pm_sleep_ptr(bus_complete),
	SYSTEM_SLEEP_PM_OPS(bus_suspend, bus_resume)
	LATE_SYSTEM_SLEEP_PM_OPS(bus_suspend_late, bus_resume_early)
	NOIRQ_SYSTEM_SLEEP_PM_OPS(bus_suspend_noirq, bus_resume_noirq)
	RUNTIME_PM_OPS(bus_rt_suspend, bus_rt_resume, NULL)
};

static int n6_bus_probe(struct platform_device *pdev)
{
	struct device *dev = &pdev->dev;
	int ret;

	pm_runtime_set_suspended(dev);		/* clock off until a user comes */
	ret = devm_pm_runtime_enable(dev);
	if (ret)
		return ret;
	ret = device_create_file(dev, &dev_attr_raw);
	if (ret)
		return ret;
	n6_bus_dev = dev;
	dev_info(dev, "probe\n");
	return 0;
}

static void n6_bus_remove(struct platform_device *pdev)
{
	n6_bus_dev = NULL; device_remove_file(&pdev->dev, &dev_attr_raw);
}

static struct platform_driver n6_bus_driver = {
	.probe = n6_bus_probe, .remove = n6_bus_remove,
	.driver = { .name = "n6_bus", .pm = pm_ptr(&n6_bus_pm) },
};
module_platform_driver(n6_bus_driver);
MODULE_LICENSE("GPL"); MODULE_DESCRIPTION("N6 supplier bus");
```

출력에서 볼 것은 아직 없다. 두 가지만 기억하자: `bus_suspend()`에서 `n6_bus_sys_suspended = true`가 되는 순간부터 소비자의 전송은 실패한다. probe에서 `pm_runtime_set_suspended()` + `devm_pm_runtime_enable()`로 "평소에는 꺼져 있고, 누가 쓰면 켜지는" 장치로 시작한다.

### 1.2 보드 파일 — 등록 순서를 고를 수 있게

dpm_list(PM core가 suspend 순서를 정하는 목록)는 **장치를 등록한 순서**로 만들어진다(§3.3). 그래서 등록 순서를 모듈 파라미터 `imu_first`로 바꿀 수 있게 했다. wake GPIO는 `gpiod_lookup_table`로 gpio-sim 뱅크(라벨 `n6_sim`) 0번 라인에 연결한다.

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_board.c — "board file": registers n6_bus + n6_imu, wires the wake GPIO */
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/gpio/machine.h>

static bool imu_first = true;	/* register consumer BEFORE supplier */
module_param(imu_first, bool, 0444);
static struct platform_device *pd_bus, *pd_imu;

static struct gpiod_lookup_table n6_wake_lookup = {
	.dev_id = "n6_imu",
	.table = {	/* gpio-sim bank labelled "n6_sim", line 0 */
		GPIO_LOOKUP("n6_sim", 0, "wake", GPIO_ACTIVE_HIGH),
		{ }
	},
};

static struct platform_device *reg(const char *name)
{
	struct platform_device *p = platform_device_register_simple(name, -1, NULL, 0);

	pr_info("n6_board: registered %s\n", name);
	return p;
}

static int __init n6_board_init(void)
{
	gpiod_add_lookup_table(&n6_wake_lookup);
	if (imu_first) {
		pd_imu = reg("n6_imu");
		pd_bus = reg("n6_bus");
	} else {
		pd_bus = reg("n6_bus");
		pd_imu = reg("n6_imu");
	}
	if (IS_ERR(pd_imu) || IS_ERR(pd_bus))
		return -ENODEV;	/* demo: no partial unwind */
	return 0;
}

static void __exit n6_board_exit(void)
{
	platform_device_unregister(pd_imu);
	platform_device_unregister(pd_bus);
	gpiod_remove_lookup_table(&n6_wake_lookup);
}
module_init(n6_board_init);
module_exit(n6_board_exit);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("N6 board: registers n6_bus and n6_imu");
```

### 1.3 소비자 — regmap, device link, probe

```c
/* n6_imu.h — consumer ("sensor") driver private state */
#include <linux/platform_device.h>
#include <linux/regmap.h>
#include <linux/gpio/consumer.h>

#define IMU_WHOAMI 0x00	/* RO, POR 0x6c */
#define IMU_DATA   0x01	/* volatile sample counter */
#define IMU_CTRL   0x02	/* POR 0x00 */
#define IMU_THRESH 0x03	/* POR 0x10 */
#define IMU_INT_EN 0x04	/* POR 0x00 */

struct n6_imu {
	struct device *dev;
	struct device *bus;		/* supplier device */
```

regmap은 버스 백엔드 대신 `reg_read`/`reg_write` 콜백으로 `n6_bus_xfer()`를 부른다(H2 §2의 "버스 없는 regmap"). `reg_defaults`는 칩의 POR 값과 **정확히 같아야** 한다 — §5에서 왜 그런지 본다. 모듈 파라미터 `link=0`이면 device link 없이 "공급자를 손으로 깨워 붙잡아 두는" 옛날 방식, `link=1`이면 `device_link_add()`다.

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_imu_main.c — consumer: regmap on top of n6_bus + supplier link */
#include <linux/module.h>
#include <linux/pm_runtime.h>
#include "n6_bus.h"
#include "n6_imu.h"

static int link = 1;
module_param(link, int, 0444);	/* 0: no device link (bug), 1: link */

static int imu_reg_read(void *ctx, unsigned int reg, unsigned int *val)
{
	u8 v; int ret = n6_bus_xfer(false, reg, &v);

	*val = v;
	return ret;
}
static int imu_reg_write(void *ctx, unsigned int reg, unsigned int val)
{
	u8 v = val;

	return n6_bus_xfer(true, reg, &v);
}
static bool imu_volatile(struct device *d, unsigned int reg) { return reg == IMU_DATA; }
static bool imu_writeable(struct device *d, unsigned int reg) { return reg >= IMU_CTRL; }
static const struct reg_default imu_defaults[] = {
	{ IMU_WHOAMI, 0x6c }, { IMU_CTRL, 0x00 }, { IMU_THRESH, 0x10 }, { IMU_INT_EN, 0x00 },
};
const struct regmap_config n6_imu_regmap_cfg = {
	.reg_bits = 8, .val_bits = 8, .max_register = 7,
	.reg_read = imu_reg_read, .reg_write = imu_reg_write,
	.volatile_reg = imu_volatile, .writeable_reg = imu_writeable,
	.cache_type = REGCACHE_MAPLE,
	.reg_defaults = imu_defaults, .num_reg_defaults = ARRAY_SIZE(imu_defaults),
};

static void imu_unlink(void *data) { device_link_del(data); }
static void imu_put_bus(void *data) { pm_runtime_put(data); }

int n6_imu_setup_link(struct n6_imu *imu)
{
	int ret;

	if (!link) {	/* old style: hold the supplier awake by hand */
		ret = pm_runtime_resume_and_get(imu->bus);
		return ret ? ret : devm_add_action_or_reset(imu->dev, imu_put_bus, imu->bus);
	}
	imu->link = device_link_add(imu->dev, imu->bus, DL_FLAG_STATELESS |
				    DL_FLAG_PM_RUNTIME | DL_FLAG_RPM_ACTIVE);
	if (!imu->link)
		return -EINVAL;
	return devm_add_action_or_reset(imu->dev, imu_unlink, imu->link);
}
```

`DL_FLAG_STATELESS`는 "링크의 생명주기를 내가 관리한다"(probe/unbind에 따른 자동 관리 없음 — 그래서 `device_link_del()`을 devm 액션으로 걸었다), `DL_FLAG_PM_RUNTIME`은 "소비자가 runtime resume되면 공급자도 먼저 resume", `DL_FLAG_RPM_ACTIVE`는 "링크를 만드는 지금 공급자를 깨워 둔다"(probe 안에서 바로 레지스터를 써야 하니까)이다. 링크 플래그 전체는 G2 §8과 docs.kernel.org의 Device links 문서에 있다.

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_imu_probe.c — consumer probe: link, regmap, chip config, runtime PM */
#include <linux/module.h>
#include <linux/pm_runtime.h>
#include "n6_bus.h"
#include "n6_imu.h"

int n6_imu_probe(struct platform_device *pdev)
{
	struct device *dev = &pdev->dev;
	struct n6_imu *imu;
	int ret;

	imu = devm_kzalloc(dev, sizeof(*imu), GFP_KERNEL);
	if (!imu)
		return -ENOMEM;
	imu->dev = dev;
	imu->bus = n6_bus_get_dev();
	if (!imu->bus)
		return dev_err_probe(dev, -EPROBE_DEFER, "n6_bus not bound\n");
	platform_set_drvdata(pdev, imu);
	ret = n6_imu_setup_link(imu);	/* supplier must be awake from here */
	if (ret)
		return ret;
	imu->map = devm_regmap_init(dev, NULL, imu, &n6_imu_regmap_cfg);
	if (IS_ERR(imu->map))
		return PTR_ERR(imu->map);
	regmap_write(imu->map, IMU_CTRL, 0x35);	/* ODR + enable */
	regmap_write(imu->map, IMU_THRESH, 0x42);
	regmap_write(imu->map, IMU_INT_EN, 0x01);

	ret = n6_imu_setup_wake(imu);	/* gpio-sim line -> IRQ + wakeup */
	if (ret)
		return ret;

	pm_runtime_set_active(dev);	/* chip is powered and configured */
	pm_runtime_set_autosuspend_delay(dev, 500);
	pm_runtime_use_autosuspend(dev);
	ret = devm_pm_runtime_enable(dev);	/* also undoes use_autosuspend */
	if (ret)
		return ret;
	dev_info(dev, "probe ok (link=%s, irq %d)\n", imu->link ? "yes" : "no", imu->irq);
	pm_runtime_mark_last_busy(dev);	/* driver core then pm_request_idle() */
	return 0;
}
```

probe의 runtime PM 순서가 정석이다: 하드웨어를 켜고 설정한 다음 `pm_runtime_set_active()`(PM core에게 "지금 켜져 있다"고 알림) → autosuspend 설정 → `devm_pm_runtime_enable()`. probe가 끝나면 driver core가 `pm_request_idle()`을 부르고(6.18 `drivers/base/dd.c`), usage count가 0이므로 500 ms 뒤 autosuspend된다. `devm_pm_runtime_enable()`은 remove 때 `pm_runtime_disable()`과 `pm_runtime_dont_use_autosuspend()`까지 해 준다.

그림 2 — `dev_pm_ops` 콜백 지도. 가로는 단계(phase), 세로는 전환 종류. 시스템 sleep 콜백 20개 + runtime 3개 = 23개. hibernate는 "메모리 이미지를 만드는 동안 잠깐 멈춤(freeze/thaw)"과 "이미지를 저장한 뒤 진짜 끄기(poweroff)", "부팅 후 이미지에서 복원(restore)"으로 나뉜다.

| 단계 | 언제 | IRQ | 할 일 (전형) |
|---|---|---|---|
| `prepare` | 장치를 건드리기 전, 새 자식이 생기지 않게 막는 단계 | 켜짐 | 대부분 비워 둔다. 양수 반환 = "runtime-suspended면 그대로 둬도 된다"(direct_complete) |
| `suspend` | 본 단계. 유저 공간은 이미 얼었다 | 켜짐 | I/O 멈춤, 칩을 저전력 모드로, wake 설정, 클럭·전원 끄기 |
| `suspend_late` | 모든 장치의 `suspend`가 끝난 뒤. runtime PM이 이 직전에 꺼진다 | 켜짐 | 다른 장치의 `suspend`에서 아직 나를 쓸 수 있을 때, 그 뒤에 할 일 |
| `suspend_noirq` | `suspend_device_irqs()` 뒤. 장치 IRQ 핸들러가 안 불린다 | 꺼짐 | 버스 컨트롤러의 마지막 정리, 인터럽트 컨트롤러 상태 저장 |
| `resume_noirq` → `resume_early` → `resume` → `complete` | 위의 거울 | 꺼짐 → 켜짐 | 복원은 정확히 거꾸로 |

### 2.2 매크로 — 6.x의 관용구

예전 드라이버는 이렇게 썼다.

```c
#ifdef CONFIG_PM_SLEEP
static int foo_suspend(struct device *dev) { ... }
static int foo_resume(struct device *dev) { ... }
#endif
static SIMPLE_DEV_PM_OPS(foo_pm, foo_suspend, foo_resume);
/* 또는 __maybe_unused 를 함수마다 붙이고 SET_SYSTEM_SLEEP_PM_OPS(...) */
```

`#ifdef`는 설정 조합에 따라 컴파일 에러·경고가 숨고, `__maybe_unused`는 함수가 링크에 남는다. 지금은 **항상 컴파일하고, 설정이 꺼져 있으면 포인터를 NULL로 만들어 컴파일러가 죽은 코드로 지우게** 한다. 6.18 소스에서 직접 확인한 정의다(발췌).

```c
/* include/linux/pm.h (v6.18.55) */
#define SYSTEM_SLEEP_PM_OPS(suspend_fn, resume_fn) \
	.suspend = pm_sleep_ptr(suspend_fn), \
	.resume = pm_sleep_ptr(resume_fn), \
	.freeze = pm_sleep_ptr(suspend_fn), \
	.thaw = pm_sleep_ptr(resume_fn), \
	.poweroff = pm_sleep_ptr(suspend_fn), \
	.restore = pm_sleep_ptr(resume_fn),

#define RUNTIME_PM_OPS(suspend_fn, resume_fn, idle_fn) \
	.runtime_suspend = suspend_fn, \
	.runtime_resume = resume_fn, \
	.runtime_idle = idle_fn,

#define DEFINE_SIMPLE_DEV_PM_OPS(name, suspend_fn, resume_fn) \
	_DEFINE_DEV_PM_OPS(name, suspend_fn, resume_fn, NULL, NULL, NULL)

#define pm_ptr(_ptr) PTR_IF(IS_ENABLED(CONFIG_PM), (_ptr))
#define pm_sleep_ptr(_ptr) PTR_IF(IS_ENABLED(CONFIG_PM_SLEEP), (_ptr))

/* include/linux/pm_runtime.h (v6.18.55) */
#define DEFINE_RUNTIME_DEV_PM_OPS(name, suspend_fn, resume_fn, idle_fn) \
	_DEFINE_DEV_PM_OPS(name, pm_runtime_force_suspend, \
			   pm_runtime_force_resume, suspend_fn, \
			   resume_fn, idle_fn)
```

| 매크로 | 채우는 콜백 | 언제 쓰나 |
|---|---|---|
| `DEFINE_SIMPLE_DEV_PM_OPS(n, s, r)` | suspend/resume/freeze/thaw/poweroff/restore = s, r | 시스템 sleep만 (G3 §12, H2 §9) |
| `DEFINE_RUNTIME_DEV_PM_OPS(n, rs, rr, idle)` | runtime 3개 + 시스템 sleep = `pm_runtime_force_suspend/resume` | runtime PM 콜백만 짜고 시스템 sleep은 그걸 재사용 |
| `SYSTEM_SLEEP_PM_OPS(s, r)` | 위 6개 | 직접 `struct dev_pm_ops { ... }`를 쓸 때 조각으로 |
| `LATE_SYSTEM_SLEEP_PM_OPS`, `NOIRQ_SYSTEM_SLEEP_PM_OPS` | `_late/_early`, `_noirq` 6개씩 | 늦은 단계가 필요할 때 |
| `RUNTIME_PM_OPS(rs, rr, idle)` | runtime 3개 (`pm_sleep_ptr` 없음 — `pm_ptr`로 구조체째 지운다) | 조각 |
| `EXPORT_GPL_RUNTIME_DEV_PM_OPS` 등 | 위와 같고 심볼을 export | 여러 모듈(코어 + 버스별 모듈)이 같은 ops를 공유할 때 |
| `pm_ptr(&ops)` / `pm_sleep_ptr(&ops)` | `driver.pm` 자리에 | CONFIG_PM / CONFIG_PM_SLEEP이 꺼지면 NULL |

주의: `DEFINE_RUNTIME_DEV_PM_OPS`의 주석(6.18 `pm_runtime.h`)이 말하듯, 폐기된 `UNIVERSAL_DEV_PM_OPS`(같은 함수를 runtime과 시스템 양쪽에 그대로 꽂음)와 다르다. 시스템 sleep 쪽은 **force 함수가 상태를 보고 필요할 때만** runtime 콜백을 부른다(§4.6).

### 2.3 소비자의 `dev_pm_ops`

이번 실습에서는 단계마다 로그를 찍어야 하므로 매크로 조각으로 직접 채웠다. 실제 드라이버라면 `suspend_late`/`noirq`처럼 할 일이 없는 콜백은 **비워 둔다**.

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_imu_pm.c — consumer dev_pm_ops: runtime PM + regcache, all sleep phases */
#include <linux/pm_runtime.h>
#include "n6_bus.h"
#include "n6_imu.h"

#define LOG(d) dev_info(d, "%s\n", __func__)

int imu_rt_suspend(struct device *dev)
{
	struct n6_imu *imu = dev_get_drvdata(dev);

	regcache_cache_only(imu->map, true);	/* no bus access from now */
	regcache_mark_dirty(imu->map);		/* chip will forget everything */
	n6_bus_chip_power(false);		/* "regulator_disable" */
	dev_info(dev, "runtime_suspend: cache_only, chip OFF\n");
	return 0;
}

int imu_rt_resume(struct device *dev)
{
	struct n6_imu *imu = dev_get_drvdata(dev);
	int ret;

	n6_bus_chip_power(true);		/* chip wakes with POR values */
	regcache_cache_only(imu->map, false);
	ret = regcache_sync(imu->map);		/* rewrite non-default regs */
	dev_info(dev, "runtime_resume: regcache_sync = %d\n", ret);
	return ret;
}

int imu_prepare(struct device *d)       { LOG(d); return 0; }
void imu_complete(struct device *d)     { LOG(d); }
int imu_suspend_late(struct device *d)  { LOG(d); return 0; }
int imu_resume_early(struct device *d)  { LOG(d); return 0; }
int imu_suspend_noirq(struct device *d) { LOG(d); return 0; }
int imu_resume_noirq(struct device *d)  { LOG(d); return 0; }

int imu_suspend(struct device *dev)
{
	struct n6_imu *imu = dev_get_drvdata(dev);
	int ret;

	LOG(dev);
	ret = pm_runtime_resume_and_get(dev);	/* HW access needed below */
	if (ret)
		return ret;
	ret = regmap_write(imu->map, IMU_INT_EN, 0x00);	/* quiesce chip IRQ */
	pm_runtime_put_noidle(dev);
	if (ret) {
		dev_err(dev, "quiesce failed: %d\n", ret);
		return ret;
	}
	n6_imu_arm_wake(imu, true);
	return pm_runtime_force_suspend(dev);	/* -> imu_rt_suspend() */
}
```

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_imu_drv.c — resume side of dev_pm_ops + driver registration */
#include <linux/module.h>
#include <linux/pm_runtime.h>
#include "n6_imu.h"

#define LOG(d) dev_info(d, "%s\n", __func__)

static int imu_resume(struct device *dev)
{
	struct n6_imu *imu = dev_get_drvdata(dev);
	int ret;

	LOG(dev);
	ret = pm_runtime_force_resume(dev);	/* -> imu_rt_resume() if needed */
	n6_imu_arm_wake(imu, false);
	if (ret)
		return ret;
	/* undo the quiesce; goes to the cache only if still runtime-suspended */
	return regmap_write(imu->map, IMU_INT_EN, 0x01);
}

static const struct dev_pm_ops n6_imu_pm = {
	.prepare = pm_sleep_ptr(imu_prepare),
	.complete = pm_sleep_ptr(imu_complete),
	SYSTEM_SLEEP_PM_OPS(imu_suspend, imu_resume)
	LATE_SYSTEM_SLEEP_PM_OPS(imu_suspend_late, imu_resume_early)
	NOIRQ_SYSTEM_SLEEP_PM_OPS(imu_suspend_noirq, imu_resume_noirq)
	RUNTIME_PM_OPS(imu_rt_suspend, imu_rt_resume, NULL)
};

static struct platform_driver n6_imu_driver = {
	.probe = n6_imu_probe,
	.driver = {
		.name = "n6_imu",
		.pm = pm_ptr(&n6_imu_pm),
		.dev_groups = n6_imu_groups,
	},
};
module_platform_driver(n6_imu_driver);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("N6 consumer sensor with full dev_pm_ops");
```

`imu_suspend()`가 핵심이다. 시스템 suspend 전에 칩에 마지막으로 써야 할 것(여기서는 칩 인터럽트 끄기)이 있으면, 장치가 runtime-suspended 상태일 수도 있으므로 **먼저 깨운다**(`pm_runtime_resume_and_get`). 그다음 wake를 설정하고, `pm_runtime_force_suspend()`로 runtime 콜백을 재사용해 전원을 끈다. resume에서는 `pm_runtime_force_resume()` 뒤에 끈 인터럽트를 다시 켠다 — 장치가 아직 runtime-suspended면 그 쓰기는 **캐시에만** 들어가고 다음 runtime resume의 `regcache_sync`가 칩에 쓴다.

### 2.4 콜백은 누가 부르나 — 버스 래퍼

PM core는 드라이버 콜백을 바로 부르지 않을 수도 있다. 우선순위는 `dev->pm_domain` → `dev->type->pm` → `dev->class->pm` → `dev->bus->pm` → `dev->driver->pm`이다(6.18 `drivers/base/power/main.c`의 `device_suspend()` 등). platform 버스는 `.suspend`/`.resume`/`.freeze`... 6개에 `platform_pm_suspend` 같은 래퍼를 두고(`USE_PLATFORM_PM_SLEEP_OPS`), late/noirq는 두지 않는다. 그래서 다음 절 로그에서 suspend는 `calling platform_pm_suspend`로, late는 `calling imu_suspend_late [n6_imu]`로 찍힌다. SoC의 PM domain(genpd)이 붙은 장치는 domain 콜백이 먼저 불리고 그 안에서 드라이버 콜백을 부른다 — 전원 도메인 끄기는 domain이 한다(N5).

출력에서 볼 것:

- **prepare는 정방향**(bus → imu), **suspend·late·noirq는 역방향**(imu → bus), **resume 계열은 정방향**(bus → imu), **complete는 역방향**. PM core는 `dpm_prepare()`에서 dpm_list를 앞에서부터 돌며 준비된 장치를 `dpm_prepared_list`로 옮기고, `dpm_suspend()`는 그 목록을 **뒤에서부터**, resume은 앞에서부터 돈다.
- 소비자 `imu_suspend`가 8.0 ms로 가장 길다: 장치가 runtime-suspended였으므로 깨우고(공급자도 링크 때문에 먼저 `bus clock ON`), `regcache_sync`, INT_EN 끄기, 다시 `runtime_suspend`까지 한 번에 했다. 공급자는 그 뒤에 잠든다 — **링크 덕분에 공급자가 아직 깨어 있을 때** 소비자가 버스를 쓸 수 있었다.
- `enable_irq_wake(22) = -6`(`-ENXIO`): gpio-sim의 irqchip(`irq_sim`)에는 `irq_set_wake`가 없어서 wake 설정이 실패한다. §8에서 다룬다.
- resume 쪽에서 `imu_resume`은 장치를 깨우지 않았다. suspend 직전에 runtime-suspended였고 아무도 쓰지 않으니 `pm_runtime_force_resume()`이 "필요 없음"으로 판단한 것이다. 시스템 resume 직후 쓸데없이 모든 장치를 켜지 않는 것이 배터리 장비에서 중요하다.
- 마지막 줄 근처 `T32`(kworker)의 `bus clock OFF`: `complete` 뒤 runtime PM이 다시 켜지고 공급자의 usage가 0이므로 비동기 idle → suspend가 일어났다.

### 3.2 dpm_list — 순서는 어디서 오나

- 장치는 `device_add()` → `device_pm_add()`에서 **dpm_list 꼬리에** 붙는다. 그래서 기본 순서 = 등록 순서다. 부모는 자식보다 먼저 등록되므로(부모 없이 자식을 만들 수 없다) "자식이 부모보다 먼저 suspend, 부모가 자식보다 먼저 resume"이 자동으로 지켜진다.
- 문제는 **트리 밖의 의존성**이다. IMU의 부모는 `platform`이지 I2C 컨트롤러가 아니다(이번 실습처럼 platform 장치끼리일 때). 실제 I2C 클라이언트는 어댑터의 자식이라 트리로 해결되지만, 클럭·레귤레이터·GPIO·PHY·IOMMU 공급자는 전부 트리 밖이다.
- 해결책이 **device link**다. `device_link_add()`는 `device_reorder_to_tail(consumer)`로 소비자(와 그 자식·소비자들)를 dpm_list 꼬리로 옮긴다(6.18 `drivers/base/core.c`). 그리고 비동기 suspend에서는 `dpm_wait_for_consumers()`/`dpm_wait_for_suppliers()`가 링크를 따라 기다린다.
- DT 시스템에서는 **fw_devlink**가 `clocks`, `*-supply`, `*-gpios`, `interrupts` 같은 phandle을 보고 링크를 자동으로 만든다(G2 §8, G3 §13). 그래서 DT를 제대로 쓰면 드라이버가 직접 `device_link_add()`를 부를 일이 드물다. 직접 부르는 경우는 이번처럼 **DT에 표현되지 않는 관계**(커스텀 API로 다른 드라이버를 쓰는 경우, 소프트웨어로 찾는 동반 장치 등)다.
- deferred probe가 재시도될 때도 `device_pm_move_to_tail()`로 장치를 꼬리로 옮긴다(6.18 `drivers/base/dd.c`, 주석: "the PM code assumes that the order we add things to the list is a good order for suspend but deferred probe makes that very unsafe"). 공급자가 없어서 defer된 장치는 공급자보다 뒤로 가게 된다.

## 4. runtime PM — 참조 카운트로 장치를 끈다

### 4.1 모델

runtime PM은 각 `struct device` 안의 `struct dev_pm_info power`에 상태 기계를 둔다. 핵심 값 세 개:

- `usage_count` — "지금 이 장치를 쓰는 중"인 참조 수. `pm_runtime_get*`가 올리고 `pm_runtime_put*`이 내린다. 0이 되면 idle 검사 → suspend.
- `child_count` — runtime-active인 자식 수. 자식이 깨어 있으면 부모는 못 잔다(`ignore_children`으로 끌 수 있다).
- `runtime_status` — `RPM_ACTIVE`, `RPM_SUSPENDING`, `RPM_SUSPENDED`, `RPM_RESUMING`.

autosuspend를 켜면(`pm_runtime_use_autosuspend`) usage가 0이 되어도 바로 끄지 않고 `last_busy + autosuspend_delay` 시각까지 기다린다. 센서처럼 "짧게 자주" 쓰이는 장치에서 켰다 끄는 비용(전원 램프업, regcache_sync)을 아낀다 — NVMe APST의 idle 시간 임계값과 같은 생각이다.

### 4.2 API 한눈에

| 함수 | usage | 동작 | 언제 |
|---|---|---|---|
| `pm_runtime_resume_and_get(dev)` | 성공할 때만 +1 | 동기 resume | **기본값.** 하드웨어를 만지기 직전 |
| `pm_runtime_get_sync(dev)` | 실패해도 +1 | 동기 resume | 옛 코드. 실패 시 `put_noidle`을 따로 해야 한다 |
| `pm_runtime_get(dev)` | +1 | 비동기 resume 요청 | 원자 컨텍스트에서 "곧 쓸 것" |
| `pm_runtime_get_noresume(dev)` | +1 | 깨우지 않음 | "지금은 잠들지 마"만 |
| `pm_runtime_put_autosuspend(dev)` | -1 | 6.18: `mark_last_busy` + 지연 뒤 suspend | autosuspend 장치의 기본 put |
| `pm_runtime_put(dev)` / `_put_sync(dev)` | -1 | 비동기 / 동기 idle 검사 | autosuspend 안 쓰는 장치 |
| `pm_runtime_put_noidle(dev)` | -1 | 아무것도 안 함 | get_sync 실패 정리, 균형 맞추기 |
| `pm_runtime_mark_last_busy(dev)` | — | autosuspend 타이머 기준 시각 갱신 | 6.17 이전 커널에서는 put 전에 직접 |
| `pm_runtime_set_autosuspend_delay(dev, ms)` + `pm_runtime_use_autosuspend(dev)` | — | autosuspend 설정 | probe |
| `pm_runtime_set_active(dev)` / `_set_suspended(dev)` | — | "지금 실제 상태"를 PM core에 알림 (enable 전에) | probe |
| `devm_pm_runtime_enable(dev)` | — | enable + remove 때 disable, dont_use_autosuspend | probe |
| `pm_runtime_force_suspend/resume(dev)` | — | 시스템 sleep에서 runtime 콜백 재사용 | `.suspend`/`.resume` |
| `pm_runtime_irq_safe(dev)` | — | 콜백을 IRQ off·스핀락 문맥에서 부를 수 있게 (대신 부모가 항상 켜져 있게 된다) | 원자 문맥에서 동기 get이 꼭 필요할 때만 |

6.18에서 확인한 변화 두 가지:

- `pm_runtime_put_autosuspend()`가 이제 **스스로 `pm_runtime_mark_last_busy()`를 부른다**(6.18 `include/linux/pm_runtime.h`: "Update the last access time of a device, drop its usage counter..."). 예전 코드의 `mark_last_busy(); put_autosuspend();` 두 줄은 이제 중복이지만 해롭지 않다. 마지막 접근 시각을 갱신하지 않는 옛 동작이 필요하면 `__pm_runtime_put_autosuspend()`를 쓴다.
- scope 기반 가드가 생겼다: `PM_RUNTIME_ACQUIRE_IF_ENABLED_AUTOSUSPEND(dev, pm)` + `PM_RUNTIME_ACQUIRE_ERR(&pm)`처럼 쓰면 함수가 어느 경로로 나가든 put이 자동으로 된다(`DEFINE_GUARD_COND`, `ACQUIRE()` 기반). §7의 누수 버그를 구조적으로 막는다. 이 노트의 코드는 이전 커널에도 통하도록 명시적 get/put으로 썼다.

### 4.3 예제 5 — autosuspend를 유저 프로그램으로 관찰

무엇을 확인하나: 유저 프로그램이 200 ms 간격으로 센서를 읽는 동안 장치는 켜져 있고, 읽기가 끝나면 autosuspend 지연(500 ms) 뒤 장치와 **공급자까지** 함께 꺼지는지. `runtime_usage`는 CONFIG_PM_ADVANCED_DEBUG에서만 보이는 sysfs 파일이다.

```c
/* rpm_watch.c — read the sensor N times, then watch runtime PM state */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

#define IMU "/sys/devices/platform/n6_imu/"
#define BUS "/sys/devices/platform/n6_bus/"

static void cat1(const char *path, char *out, size_t n)
{
	FILE *f = fopen(path, "r");

	if (!f || !fgets(out, n, f))
		snprintf(out, n, "?");
	out[strcspn(out, "\n")] = 0;
	if (f)
		fclose(f);
}

static double now_ms(void)
{
	static struct timespec t0;
	struct timespec t;

	clock_gettime(CLOCK_MONOTONIC, &t);
	if (!t0.tv_sec)
		t0 = t;
	return (t.tv_sec - t0.tv_sec) * 1e3 + (t.tv_nsec - t0.tv_nsec) / 1e6;
}

static void show(const char *what)
{
	char s[32], u[32], b[32];

	cat1(IMU "power/runtime_status", s, sizeof(s));
	cat1(IMU "power/runtime_usage", u, sizeof(u));
	cat1(BUS "power/runtime_status", b, sizeof(b));
	printf("%7.1f ms %-10s imu=%-9s usage=%s  bus=%s\n", now_ms(), what, s, u, b);
}

int main(int argc, char **argv)
{
	int n = argc > 1 ? atoi(argv[1]) : 5, gap = argc > 2 ? atoi(argv[2]) : 100;
	char v[32];
	show("start");
	for (int i = 0; i < n; i++) {
		cat1(IMU "data", v, sizeof(v));
		printf("%7.1f ms read data=%s\n", now_ms(), v);
		show("after-rd");
		usleep(gap * 1000);
	}
	for (int i = 0; i < 8; i++) {	/* idle: watch autosuspend (500 ms) */
		usleep(100 * 1000);
		show("idle");
	}
	return 0;
}
```

### 4.4 시스템 sleep과 runtime PM을 같이 쓰기

시스템 suspend가 시작되면 PM core는 장치마다 다음을 한다(6.18 `drivers/base/power/main.c`):

- `device_prepare()`: `pm_runtime_get_noresume()`(시스템 전환 중에 runtime suspend가 끼어들지 않게) → `.prepare`.
- `device_suspend()`: `pm_runtime_barrier()`로 진행 중인 runtime 작업을 끝낸다. **이 단계에서는 runtime resume이 아직 된다** — 그래서 `imu_suspend()`가 `pm_runtime_resume_and_get()`을 쓸 수 있었다.
- `device_suspend_late()`: `__pm_runtime_disable()`. **이후로는 runtime PM이 꺼진다.** late/noirq 콜백에서 `pm_runtime_get_sync()`는 장치가 이미 active면 1(아무것도 안 함), suspended면 `-EACCES`로 실패한다 — 깨울 수 없다.
- `device_complete()`: `.complete` → `pm_runtime_put()`(prepare의 get을 돌려줌). 예제 2의 마지막 `bus clock OFF`가 이 put의 결과다.

그래서 흔한 두 함정:

- **이중 suspend**: `.suspend`에서 직접 클럭을 끄는데, 장치가 이미 runtime-suspended라서 클럭이 이미 꺼져 있으면 `clk_disable_unprepare()`가 한 번 더 불려 enable count가 음수가 되고 경고가 뜬다. 해결은 `pm_runtime_force_suspend()`처럼 "이미 suspended면 아무것도 안 한다"는 판단을 넣거나, 한 경로(runtime 콜백)만 실제 하드웨어를 끄게 하는 것이다.
- **direct_complete**: `.prepare`가 양수를 돌려주고 장치가 runtime-suspended면 PM core는 그 장치의 suspend/resume 콜백을 **아예 건너뛴다**. 빠르지만, 자식이나 소비자가 wakeup 경로에 있으면 꺼진다(6.18 `dpm_clear_superiors_direct_complete()`). 그 플래그는 `DPM_FLAG_SMART_PREPARE`, `DPM_FLAG_SMART_SUSPEND`, `DPM_FLAG_MAY_SKIP_RESUME`(`dev_pm_set_driver_flags()`)와 함께 docs.kernel.org의 "Device Power Management Basics"에 정리되어 있다. 예제 7의 dyndbg 출력의 `driver flags: 0`이 이 플래그 값이다.

### 5.1 자원별 정리

| 자원 | 꺼질 때 잃는 것 | suspend 쪽 | resume 쪽 | 노트 |
|---|---|---|---|---|
| 칩 레지스터 (I2C/SPI 센서) | 전원이 끊기면 전부 | `regcache_cache_only(map, true)` + `regcache_mark_dirty(map)` | `regcache_cache_only(map, false)` + `regcache_sync(map)` | H2 §9, 이 노트 §5.2 |
| SoC 주변장치 MMIO | power domain이 꺼지면 전부 | 필요한 레지스터를 구조체에 저장 (또는 regmap-mmio 캐시) | 다시 쓰기, 순서 주의(enable 비트는 마지막) | H1 |
| 클럭 | 상태 자체 | `clk_disable_unprepare()` | `clk_prepare_enable()` + 칩 안정 대기 | H3 |
| 레귤레이터 | 칩 전원 | `regulator_disable()` (전원을 끌 때만) | `regulator_enable()` + 데이터시트의 turn-on 시간 | H3 |
| pinctrl | 패드 설정 (SoC에 따라) | `pinctrl_pm_select_sleep_state(dev)` | `pinctrl_pm_select_default_state(dev)` | H4 §3.5 |
| GPIO 출력 (리셋·enable 핀) | SoC에 따라 패드가 유지되거나 풀린다 | 필요하면 상태 기록, 일부 SoC는 "GPIO hold"/retention 설정 | 다시 구동 | H4 |
| IRQ | 마스크 상태 | wake면 `enable_irq_wake()`, 아니면 PM core가 알아서 끔 | `disable_irq_wake()` | §8 |
| DMA·FIFO·펌웨어 | 진행 중인 전송, 로드한 펌웨어 | 전송을 끝내거나 멈춤 | 다시 큐잉, 필요하면 펌웨어 재로드 | H9, G10 |

pinctrl/clk/regulator를 쓰는 전형적인 runtime 콜백은 다음 모양이다(**가이드 — 이 노트에서 실행하지 않음**, 실습 장치에는 실제 클럭·레귤레이터가 없다).

```c
/* 가이드(실행 안 함): 실제 I2C 센서 드라이버의 runtime 콜백 모양 */
static int imu_runtime_suspend(struct device *dev)
{
	struct imu *s = dev_get_drvdata(dev);

	regcache_cache_only(s->map, true);
	regcache_mark_dirty(s->map);
	clk_disable_unprepare(s->mclk);
	regulator_disable(s->vdd);
	return pinctrl_pm_select_sleep_state(dev);
}

static int imu_runtime_resume(struct device *dev)
{
	struct imu *s = dev_get_drvdata(dev);
	int ret;

	pinctrl_pm_select_default_state(dev);
	ret = regulator_enable(s->vdd);
	if (ret)
		return ret;
	usleep_range(2000, 3000);		/* 데이터시트 turn-on time */
	ret = clk_prepare_enable(s->mclk);
	if (ret)
		goto err_vdd;
	regcache_cache_only(s->map, false);
	ret = regcache_sync(s->map);
	if (ret)
		goto err_clk;
	return 0;
err_clk:
	clk_disable_unprepare(s->mclk);
err_vdd:
	regulator_disable(s->vdd);
	return ret;
}
```

순서가 규칙이다: 끌 때는 "소프트웨어가 하드웨어를 못 건드리게 막기(cache_only) → 클럭 → 전원 → 핀", 켤 때는 정확히 거꾸로, 그리고 **에러 경로에서 켠 것만 되돌린다**.

### 5.2 예제 6 — regcache: 오염된 칩이 캐시로 복원된다

무엇을 확인하나: runtime suspend가 칩 레지스터를 `0xEE`로 오염시킨 뒤, 다음 읽기가 runtime resume을 일으켜 POR 값 위에 `regcache_sync`가 설정을 다시 쓰는지. 칩 내용(`raw`), regmap debugfs(`cache_only`, `cache_dirty`, `registers`), regmap tracepoint를 함께 본다. 부하 때문에 확인 도중 autosuspend가 끼어들지 않도록 지연을 sysfs로 3초로 늘렸다.


### 6.2 고치기

예제 2가 이미 고친 버전이다: 같은 `imu_first=1`이지만 `link=1`에서 `device_link_add(imu, bus, DL_FLAG_STATELESS | DL_FLAG_PM_RUNTIME | DL_FLAG_RPM_ACTIVE)`가 imu를 dpm_list 꼬리로 옮겨 prepare가 `bus → imu`, suspend가 `imu → bus`가 됐다. 덤으로 공급자를 손으로 붙잡을 필요가 없어져서 평소에 공급자가 꺼진다(예제 5).

고치는 법의 우선순위:

1. **DT에 관계를 표현한다** — 공급자가 클럭·레귤레이터·GPIO·인터럽트 컨트롤러면 phandle만 바르게 쓰면 fw_devlink가 링크를 만든다. I2C/SPI 클라이언트는 어댑터의 자식이므로 트리로 해결된다.
2. DT에 표현할 수 없으면 소비자 probe에서 `device_link_add()`. 공급자 드라이버의 bind/unbind에 맞춰 링크도 관리하고 싶으면 STATELESS 대신 managed 링크(`DL_FLAG_AUTOREMOVE_CONSUMER` 등, G2 §8).
3. 버스 컨트롤러 드라이버라면 **늦게 잠들고 일찍 깨기**: 많은 I2C 컨트롤러 드라이버가 실제 끄기를 `suspend_noirq`에서 하고 `resume_noirq`에서 켠다. 그래야 다른 드라이버의 `suspend`/`suspend_late`에서 아직 버스를 쓸 수 있다(PMIC를 noirq 단계 직전에 설정하는 경우 등). i2c 코어는 어댑터가 `i2c_mark_adapter_suspended()`된 뒤의 전송을 `-ESHUTDOWN` + WARN으로 거부한다.

## 7. 버그 2 — usage count 누수

### 7.1 코드 — 버그판과 수정판을 한 파일에

`selftest`는 `fixed` 파라미터에 따라 두 버전 중 하나로 돈다. `inject_fail=1`이면 검사가 `-EIO`로 실패한다.

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_imu_attr.c — sysfs reads that wake the chip; selftest has the leak bug */
#include <linux/module.h>
#include <linux/pm_runtime.h>
#include "n6_imu.h"
bool n6_fixed;
module_param_named(fixed, n6_fixed, bool, 0644);
int n6_inject_fail;
module_param_named(inject_fail, n6_inject_fail, int, 0644);

static ssize_t data_show(struct device *dev, struct device_attribute *a, char *buf)
{
	struct n6_imu *imu = dev_get_drvdata(dev);
	unsigned int v;
	int ret;

	ret = pm_runtime_resume_and_get(dev);	/* usage++ only on success */
	if (ret)
		return ret;
	ret = regmap_read(imu->map, IMU_DATA, &v);	/* volatile: hits the bus */
	pm_runtime_put_autosuspend(dev);	/* mark_last_busy + usage-- (6.18) */
	return ret ? ret : sysfs_emit(buf, "%u\n", v);
}
static DEVICE_ATTR_RO(data);

static int imu_check(struct n6_imu *imu)
{
	unsigned int v;
	int ret = regmap_read(imu->map, IMU_DATA, &v);

	return ret ? ret : (n6_inject_fail ? -EIO : 0);
}

static ssize_t selftest_show(struct device *dev, struct device_attribute *a, char *buf)
{
	struct n6_imu *imu = dev_get_drvdata(dev);
	int ret;

	if (!n6_fixed) {			/* BUGGY version */
		ret = pm_runtime_get_sync(dev);	/* usage++ even on failure */
		if (ret < 0)
			return ret;		/* leak #1 */
		ret = imu_check(imu);
		if (ret)
			return ret;		/* leak #2: no put on error */
		pm_runtime_put_autosuspend(dev);
		return sysfs_emit(buf, "ok\n");
	}
	ret = pm_runtime_resume_and_get(dev);	/* FIXED version */
	if (ret)
		return ret;
	ret = imu_check(imu);
	pm_runtime_put_autosuspend(dev);	/* put on every path */
	return ret ? ret : sysfs_emit(buf, "ok\n");
}
static DEVICE_ATTR_RO(selftest);

static struct attribute *n6_imu_attrs[] = { &dev_attr_data.attr, &dev_attr_selftest.attr, NULL };
static const struct attribute_group n6_imu_group = { .attrs = n6_imu_attrs };
const struct attribute_group *n6_imu_groups[] = { &n6_imu_group, NULL };
```

버그판의 두 누수:

- **leak #1** — `pm_runtime_get_sync()`는 resume이 **실패해도 usage를 올린다**(6.18 주석: "the runtime PM usage counter of @dev remains incremented in all cases, even if it returns an error code"). 에러에서 그냥 return하면 1이 샌다. 고전 수정은 `pm_runtime_put_noidle()`을 붙이는 것, 현대 수정은 `pm_runtime_resume_and_get()`(실패하면 usage를 올리지 않는다).
- **leak #2** — get은 성공했는데 그 뒤의 에러 경로에서 put을 빼먹었다. 이건 API를 바꿔도 안 고쳐진다. **get 이후의 모든 return 앞에 put**이 있어야 한다(goto 정리, 또는 6.18의 `PM_RUNTIME_ACQUIRE*` 가드).

출력에서 볼 것:

- **`cat` 한 번에 +2**: BusyBox `cat`은 먼저 `sendfile()`을 시도하고 실패하면 `read()`로 다시 시도한다(BusyBox 1.37 `libbb/copyfd.c`의 `bb_full_fd_action`, 이 랩의 BusyBox는 `CONFIG_FEATURE_USE_SENDFILE=y`). 그래서 `show()`가 두 번 불렸다. 셸의 `read` 내장 명령은 `read()` 한 번이라 +1. "유저가 한 번 읽었으니 한 번 불린다"는 가정도 버그의 원인이 된다.
- 누수가 생기면 장치가 **영원히 켜져 있고**, 링크로 묶인 공급자도 같이 켜져 있다(`bus=active`). 배터리 장비에서 "밤새 배터리가 사라지는" 버그의 모양이다. `runtime_status`와 `runtime_active_time`이 계속 증가하는 것으로 현장에서 찾는다.
- **드라이버를 다시 올려도 안 사라진다**(`driver reloaded: usage=5`). usage count는 드라이버가 아니라 `struct device` 안에 있고, 장치는 `n6_board`가 만든 것이라 그대로 살아 있다. 장치를 지우거나(보드 모듈 rmmod) 재부팅해야 0이 된다. 재로드 뒤 `bus_usage=2`는 새 링크의 `DL_FLAG_RPM_ACTIVE` 참조가 소비자가 계속 active여서 해제되지 않고 쌓인 것으로 보인다 — 이 노트에서 그 경로를 끝까지 추적하지는 않았다.
- 수정판의 `fixed=Y`: 실패해도 usage가 0으로 돌아가고 autosuspend가 정상 동작한다.

## 8. IRQ와 wakeup

### 8.1 suspend 동안 IRQ는 어떻게 되나

`dpm_suspend_noirq()`의 첫 일이 `suspend_device_irqs()`다(6.18 `drivers/base/power/main.c`). 이때부터 대부분의 장치 IRQ는 **비활성(lazy disable)** 되고, 그 사이 들어온 IRQ는 pending으로 기록되었다가 `resume_device_irqs()`에서 다시 실행된다. 그래서 드라이버는 suspend에서 자기 IRQ를 굳이 끌 필요가 없다 — 단, `.suspend`(IRQ가 아직 켜진 단계)에서 하드웨어를 끈 뒤 IRQ가 오면 핸들러가 꺼진 하드웨어를 건드린다. 그런 경우는 `disable_irq()`로 직접 끄거나 칩의 인터럽트를 먼저 끈다(`imu_suspend`의 INT_EN=0).

| 방법 | 코드 | 결과 | 언제 |
|---|---|---|---|
| 아무것도 안 함 | — | noirq에서 꺼지고, 그 사이 IRQ는 resume 때 재실행 | 대부분의 장치 |
| `disable_irq()` / `enable_irq()` | `.suspend`/`.resume` | 드라이버가 직접 끔. **wake 불가** | `.suspend`에서 하드웨어를 먼저 끄는 경우 |
| `IRQF_NO_SUSPEND` | `request_irq` 플래그 | 끄지 않는다. 핸들러가 suspend 중에도 실행 | 타이머, IPI, 일부 PMIC·전원 버튼 경로. 공유 IRQ면 `IRQF_COND_SUSPEND` 문제 |
| `enable_irq_wake()` / `disable_irq_wake()` | `.suspend`/`.resume` (`device_may_wakeup()` 확인 뒤) | `IRQD_WAKEUP_ARMED` — 그 IRQ가 오면 `pm_system_irq_wakeup()`으로 suspend 중단/깨움 | 버튼, 모뎀 링, 센서 motion detect |
| `dev_pm_set_wake_irq()` / `devm_pm_set_wake_irq()` | probe에서 한 번 | PM core가 suspend 때 자동으로 arm/disarm. `dev_pm_set_dedicated_wake_irq()`는 별도 wake 핀용(runtime suspend에서도 켬) | 현대 드라이버의 권장 방식 |

`enable_irq_wake()`가 성공하려면 그 IRQ의 irqchip이 `irq_set_wake`를 구현하거나 `IRQCHIP_SKIP_SET_WAKE` 플래그를 가져야 한다(6.18 `kernel/irq/manage.c`의 `set_irq_wake_real()` — 둘 다 없으면 `-ENXIO`). gpio-sim의 `irq_sim` irqchip은 둘 다 없어서 예제 2의 `enable_irq_wake(22) = -6`이 나왔다. 실제 SoC GPIO 컨트롤러는 보통 `irq_set_wake`를 구현하고 그 안에서 부모(GIC나 always-on 도메인의 wake 컨트롤러)에 전달한다(PL061의 `pl061_irq_set_wake()`, GIC는 SKIP_SET_WAKE).

### 8.2 wakeup source — "지금 자면 안 된다"를 알리는 객체

wake IRQ가 "잠든 시스템을 깨우는" 것이라면, wakeup source는 "**깨어 있는 동안 이벤트를 처리 중이니 지금 suspend하지 마**"를 커널에 알리는 객체다. Android의 wakelock이 커널로 들어온 형태다.

- `device_init_wakeup(dev, true)` (또는 `devm_device_init_wakeup(dev)`) — `power.can_wakeup = 1`, `power/wakeup = enabled`, 그리고 장치 이름의 `struct wakeup_source`를 만든다.
- `device_may_wakeup(dev)` — 할 수 있고(can_wakeup) 유저가 허락했나(`power/wakeup`). 드라이버는 suspend에서 이것을 보고 wake를 arm한다.
- `pm_stay_awake(dev)` / `pm_relax(dev)` — 이벤트 처리 시작·끝(짝을 맞춘다).
- `pm_wakeup_event(dev, ms)` — "이벤트가 있었고, ms 동안 처리 중으로 쳐라"(타이머로 자동 relax). `pm_wakeup_hard_event(dev)`는 추가로 `pm_system_wakeup()`을 불러 진행 중인 suspend를 중단시킨다.
- 관찰: `/sys/kernel/debug/wakeup_sources`(전체 표), `/sys/devices/.../power/wakeup*`(장치별), `/sys/power/wakeup_count`(전역 카운트), `/sys/power/pm_wakeup_irq`(마지막으로 깨운 IRQ, CONFIG_PM_SLEEP_DEBUG).

중요한 사실 하나: **soft 이벤트(`pm_wakeup_event`)만으로는 `echo freeze > /sys/power/state`가 막히지 않는다.** 6.18 `drivers/base/power/wakeup.c`의 `wakeup_source_report_event()`를 보면 hard일 때만 `pm_system_wakeup()`을 부르고, `pm_wakeup_pending()`은 `events_check_enabled`가 켜졌을 때만 이벤트 카운트를 비교한다. `events_check_enabled`는 유저가 `/sys/power/wakeup_count`에 값을 **써서** 켠다 — 그게 race-free suspend 프로토콜이다(아래 예제 9-b).

### 8.3 소비자의 wake 코드

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_imu_wake.c — wake IRQ: request, mark as wakeup, arm across suspend */
#include <linux/interrupt.h>
#include <linux/device.h>
#include "n6_imu.h"

static bool hard;
module_param(hard, bool, 0644);	/* 1: pm_wakeup_hard_event (aborts suspend) */

static irqreturn_t imu_wake_thread(int irq, void *data)
{
	struct n6_imu *imu = data;

	dev_info(imu->dev, "wake edge -> %s event\n", hard ? "hard" : "soft 3000ms");
	if (hard)
		pm_wakeup_hard_event(imu->dev);	/* also pm_system_wakeup() */
	else
		pm_wakeup_event(imu->dev, 3000);	/* ws stays active 3 s */
	return IRQ_HANDLED;
}

int n6_imu_setup_wake(struct n6_imu *imu)
{
	struct gpio_desc *wake;
	int ret;

	wake = devm_gpiod_get(imu->dev, "wake", GPIOD_IN);
	if (IS_ERR(wake))
		return PTR_ERR(wake);
	imu->irq = gpiod_to_irq(wake);
	if (imu->irq < 0)
		return imu->irq;
	ret = devm_request_threaded_irq(imu->dev, imu->irq, NULL, imu_wake_thread,
					IRQF_ONESHOT | IRQF_TRIGGER_RISING,
					"n6_imu_wake", imu);
	if (ret)
		return ret;
	return devm_device_init_wakeup(imu->dev);	/* can_wakeup + ws object */
}

/* called from .suspend (on=true) and .resume (on=false) */
void n6_imu_arm_wake(struct n6_imu *imu, bool on)
{
	int ret;

	if (on && device_may_wakeup(imu->dev)) {
		ret = enable_irq_wake(imu->irq);
		dev_info(imu->dev, "enable_irq_wake(%d) = %d\n", imu->irq, ret);
		imu->wake_armed = !ret;
	} else if (!on && imu->wake_armed) {
		disable_irq_wake(imu->irq);
		imu->wake_armed = false;
	}
}
```

```text
[   21.609967][  T110] PM: suspend entry (s2idle)
[   21.645799][  T110] n6_imu n6_imu: enable_irq_wake(22) = -6
```

출력에서 볼 것:

- (a) wakeup source가 **active**(active_since 291 ms)인데도 suspend가 그냥 진행됐다. soft 이벤트는 프로토콜 없이 suspend를 막지 못한다.
- (b) `wakeup_count`를 읽어서 그대로 써 넣으면(`events_check_enabled = true`) 그 뒤에 생긴 이벤트가 suspend를 **freeze 단계에서 중단**시킨다(`Freezing user space processes aborted`, `EBUSY`). 유저 공간의 suspend 데몬은 "읽기 → (자기 할 일 확인) → 쓰기 → 성공하면 state에 쓰기"를 반복한다. 쓰기 자체도, 읽은 뒤 이벤트가 있었으면 실패한다.
- (c) 이벤트가 처리 중(3초 타이머)일 때 `wakeup_count`를 **읽으면 블록된다** — 3.3초 기다렸다가 값이 3이 됐다. 데몬은 이 블록 덕분에 "처리 중인 이벤트가 끝날 때까지" 자연스럽게 기다린다.
- (d) hard 이벤트도 **suspend가 시작되기 전에** 온 것은 지워진다(freeze 시작 때 `pm_wakeup_clear(0)`, 6.18 `kernel/power/process.c`). hard 이벤트는 suspend **진행 중**에 와야 의미가 있다 — 그게 다음 예제다.
- (d)의 `wake edge` 줄을 찍은 스레드 `T85`는 threaded IRQ 핸들러(`irq/22-n6_imu_wake`)다.

### 8.5 예제 10 — 진짜로 깨우기: PL061 GPIO + `dev_pm_set_wake_irq()`

QEMU `virt`의 PL061 GPIO 3번은 QEMU 모니터의 `system_powerdown` 명령에 연결된 "전원 버튼"이다(원래 DT에서는 `gpio-keys`가 쓴다). DT에서 `gpio-keys`를 지우고 그 자리에 우리 노드를 넣는다. PL061 irqchip은 `irq_set_wake`를 구현하므로(6.18 `drivers/gpio/gpio-pl061.c`) 여기서는 wake arm이 성공한다.

```dts
/* n6_virt.dts 발췌: QEMU에서 -machine virt,dumpdtb=... 로 뽑은 DT (-smp 2 -m 1G,
   cortex-a57,pmu=on과 같은 인자) 에서 gpio-keys 노드를 이것으로 바꿨다.
   0x8005 = 이 DT에서 pl061@9030000의 phandle */
	n6-wkey {
		compatible = "n6,wkey";
		wake-gpios = <0x8005 0x03 0x00>;
		wakeup-source;
	};
```

```c
// SPDX-License-Identifier: GPL-2.0
/* n6_wkey.c — DT driver: pl061 line 3 as a real system wakeup source */
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/gpio/consumer.h>
#include <linux/interrupt.h>
#include <linux/pm_wakeirq.h>
#include <linux/pm_wakeup.h>
#include <linux/of.h>
#include <linux/property.h>

static irqreturn_t wkey_irq(int irq, void *data)
{
	struct device *dev = data;

	dev_info(dev, "wake key IRQ %d\n", irq);
	pm_wakeup_event(dev, 0);	/* count it on our wakeup source */
	return IRQ_HANDLED;
}

static int n6_wkey_probe(struct platform_device *pdev)
{
	struct device *dev = &pdev->dev;
	struct gpio_desc *g;
	int irq, ret;

	g = devm_gpiod_get(dev, "wake", GPIOD_IN);	/* DT: wake-gpios */
	if (IS_ERR(g))
		return PTR_ERR(g);
	irq = gpiod_to_irq(g);
	if (irq < 0)
		return irq;
	ret = devm_request_irq(dev, irq, wkey_irq, IRQF_TRIGGER_RISING, "n6_wkey", dev);
	if (ret)
		return ret;
	if (!device_property_read_bool(dev, "wakeup-source"))
		return 0;			/* plain key, cannot wake */
	ret = devm_device_init_wakeup(dev);	/* can_wakeup=1, wakeup=enabled */
	if (ret)
		return ret;
	ret = devm_pm_set_wake_irq(dev, irq);	/* PM core arms it: no dev_pm_ops */
	if (ret)
		return ret;
	dev_info(dev, "probe: irq %d, may_wakeup=%d\n", irq, device_may_wakeup(dev));
	return 0;
}

static const struct of_device_id n6_wkey_of[] = {
	{ .compatible = "n6,wkey" }, { }
};
MODULE_DEVICE_TABLE(of, n6_wkey_of);

static struct platform_driver n6_wkey_driver = {
	.probe = n6_wkey_probe,
	.driver = { .name = "n6_wkey", .of_match_table = n6_wkey_of },
};
module_platform_driver(n6_wkey_driver);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("N6 pl061 wake key");
```

이 드라이버에는 **`dev_pm_ops`가 없다.** `devm_pm_set_wake_irq()`로 IRQ를 등록해 두면 PM core가 `dpm_suspend_noirq()` 첫머리(`suspend_device_irqs()` 바로 앞)의 `device_wakeup_arm_wake_irqs()` → `dev_pm_arm_wake_irq()`로 `device_may_wakeup()`을 확인하고 `enable_irq_wake()`를 대신 부른다(6.18 `drivers/base/power/wakeirq.c`). platform 장치에서는 `wakeup-source` DT 속성을 커널이 자동으로 읽어 주지 않으므로 드라이버가 `device_property_read_bool()`로 본다(`gpio-keys` 등 입력 드라이버들의 관례). I2C 클라이언트는 i2c 코어가 DT의 `wakeup-source`를 읽어 `I2C_CLIENT_WAKE`로 넘겨 준다(6.18 `drivers/i2c/i2c-core-of.c`).

드라이버를 쓸 때 다시 만나는 지점:

- I2C/SPI 클라이언트 드라이버(H5, H7): 버스 코어가 `i2c_device_pm` 같은 래퍼를 두고, 어댑터가 부모라 순서는 트리로 해결. 클라이언트는 regmap 캐시 + runtime PM 패턴(이 노트 §5) 그대로.
- IIO(I2): `iio_device_claim_direct()` 안에서 `pm_runtime_resume_and_get()`, 버퍼 모드에서는 `preenable`/`postdisable`에서 get/put. 많은 IIO 드라이버가 `DEFINE_RUNTIME_DEV_PM_OPS` + autosuspend를 쓴다.
- V4L2 센서(I5): `s_stream(1)`에서 `pm_runtime_resume_and_get()`, `s_stream(0)`에서 put. 카메라 센서는 runtime resume에 클럭(MCLK) + 레귤레이터 3개 + 리셋 GPIO 순서가 데이터시트에 정해져 있다.
- 네트워크(I6): `ndo_open`/`ndo_stop`과 runtime PM, WoL(Wake-on-LAN)은 `device_set_wakeup_enable()` + PHY의 wake IRQ.
- PCIe(H11): PCI 코어가 D3hot/D3cold와 PME wake를 대신 처리하고 드라이버는 `dev_pm_ops`만 채운다. `pci_pm_suspend` 같은 버스 래퍼가 예제 7 로그에 보였다.

## 11. Embedded 실무에서 다시 보기

### 11.1 센서 키트의 IMU가 motion으로 시스템을 깨운다

배터리로 도는 로봇 센서 키트가 대기 중일 때 IMU의 motion-detect 인터럽트로 깨어나야 한다. 드라이버가 할 일:

1. DT에 `interrupts`와 `wakeup-source`. probe에서 `device_init_wakeup(dev, device_property_read_bool(dev, "wakeup-source"))`.
2. `.suspend`: `device_may_wakeup(dev)`이면 칩을 저전력 motion-detect 모드로 설정하고(그래서 버스가 아직 살아 있어야 한다 — §6) `enable_irq_wake()`. 아니면 칩 전원 off.
3. `.resume`: `disable_irq_wake()`, 정상 모드 복원.
4. 깨운 직후 이벤트를 유저 공간이 처리할 시간을 주려면 핸들러에서 `pm_wakeup_event(dev, 500)` — 그래야 suspend 데몬(wakeup_count 프로토콜을 쓰는 경우)이 바로 다시 재우지 않는다.

`wakeup-source`가 있는데 SoC GPIO 컨트롤러가 always-on 도메인이 아니면 deep suspend에서 깨지 않는다. 그런 SoC는 별도 wake 컨트롤러(i.MX의 GPC/SNVS, TI의 wkup 도메인 GPIO) 경로를 DT로 지정한다 — 그때 `dev_pm_set_dedicated_wake_irq()`를 쓴다.

### 11.2 "resume 뒤 첫 I2C 읽기가 NACK" 디버깅 순서

1. `pm_print_times`로 순서 확인: 센서 resume이 I2C 어댑터 resume보다 먼저인가? (어댑터 자식이면 그럴 리 없다 — 그렇다면 레귤레이터/클럭 공급자 쪽을 의심)
2. 레귤레이터 enable 뒤 대기 시간: 데이터시트 turn-on time을 지켰나? scope로 VDD 램프와 첫 SCL을 같이 본다(M11 — Don의 강점).
3. regcache: `reg_defaults`가 실제 POR 값인가? `/sys/kernel/debug/regmap/<dev>/registers`와 `i2cget -f`로 칩 실제 값을 비교한다.
4. 핀: resume에서 pinctrl default state로 돌아왔나(`/sys/kernel/debug/pinctrl/`)? sleep state가 SDA를 GPIO로 바꿔 놓고 안 돌렸을 수 있다.

### 11.3 밤새 배터리가 사라진다

1. `cat /sys/kernel/debug/wakeup_sources`에서 `prevent_suspend_time`이 큰 행 — 누가 suspend를 막았나.
2. `/sys/power/suspend_stats` — suspend가 실패하고 있나.
3. 안 잠드는 장치: `grep . /sys/devices/.../power/runtime_status`로 active인 장치를 찾고 `runtime_usage`가 0이 아닌지(예제 8). `power/control`이 `on`으로 남아 있지 않은지(udev 규칙·디버그 흔적).
4. 깨어나는 원인: `pm_wakeup_irq`와 `/proc/interrupts` 증가분.

## 13. 면접에서 이렇게 말한다

**Q.** "Your I2C sensor driver works at boot but fails after resume. Why, and how would you debug it?"

**A.** 원인은 세 부류다. (1) 순서: 센서가 쓰는 공급자(레귤레이터, 클럭, 다른 I2C 장치를 통한 경로)가 먼저 잠들었거나 늦게 깨어났다 — `pm_print_times`로 콜백 순서를 보고 device link/fw_devlink로 고친다. (2) 상태 소실: 전원이 꺼져 레지스터가 POR로 돌아갔는데 복원을 안 했거나, regmap `reg_defaults`가 틀려서 sync가 일부를 건너뛰었다 — debugfs regmap과 칩 실제 값을 비교한다. (3) 타이밍: 레귤레이터 enable 뒤 turn-on 시간을 안 지켜 첫 전송이 NACK — scope로 VDD 램프와 SCL을 같이 본다.

> There are usually three causes. Ordering: a supplier — a regulator, a clock, or the bus itself — suspended before the sensor or resumed after it; I check the callback order with pm_print_times and fix it with a device link or a proper DT phandle so fw_devlink orders it. State loss: the rail went off, the chip came back with power-on defaults, and the driver didn't restore it — or regmap's reg_defaults don't match the real POR values, so regcache_sync silently skipped registers; I compare the regmap debugfs view with what the chip actually returns. Timing: the first transfer happens before the chip's turn-on time after regulator_enable, so it NACKs; I'd put a scope on VDD and SCL together.

**꼬리 질문**: "What does 'Transfer while suspended' mean?" — 어댑터가 `i2c_mark_adapter_suspended()`된 뒤 전송이 왔다는 WARN이고 `-ESHUTDOWN`을 돌려준다. 클라이언트가 어댑터보다 늦게 suspend되는 순서 문제거나, 클라이언트의 IRQ 스레드가 noirq 이후에 돌았다는 뜻이다.

**Q.** "How do you make a device wake the system from suspend?"

**A.** 세 층이다. 하드웨어: 그 IRQ가 suspend 중에도 살아 있는 컨트롤러로 라우팅돼야 하고, irqchip이 `irq_set_wake`를 지원해야 한다. 드라이버: probe에서 `device_init_wakeup()`(DT `wakeup-source`를 보고), 그리고 `dev_pm_set_wake_irq()`로 등록하거나 suspend에서 `device_may_wakeup()`이면 `enable_irq_wake()`. 정책: 유저가 `power/wakeup`으로 켜고 끈다. 확인은 `/sys/power/pm_wakeup_irq`와 wakeup_sources. 실습에서 gpio-sim은 `irq_set_wake`가 없어 `-ENXIO`였고, PL061 라인은 실제로 s2idle을 깨웠다.

> Three layers. Hardware: the interrupt must be routed through a controller that stays powered in the target sleep state, and its irqchip must implement irq_set_wake. Driver: call device_init_wakeup in probe — usually gated on the wakeup-source DT property — and either register the line with dev_pm_set_wake_irq so the PM core arms it, or call enable_irq_wake in suspend when device_may_wakeup is true, and check the return value. Policy: user space decides through the power/wakeup attribute. To verify, I read /sys/power/pm_wakeup_irq after resume and the wakeup_sources table in debugfs.

**Q.** "What's the difference between system suspend callbacks and runtime PM callbacks? How do you avoid duplicating code?"

**A.** 시스템 콜백은 전체 전환 때 PM core가 모든 장치에 정해진 순서로 부르고, runtime 콜백은 장치 하나의 usage count가 0이 될 때 부른다. 보통 하드웨어를 끄고 켜는 코드는 runtime 콜백에만 두고, 시스템 쪽은 `pm_runtime_force_suspend/resume`으로 재사용한다(`DEFINE_RUNTIME_DEV_PM_OPS`). force 함수는 이미 runtime-suspended면 아무것도 안 해서 이중 suspend를 막고, resume 때도 필요할 때만 깨운다.

> System sleep callbacks are invoked for every device in dependency order during a system-wide transition; runtime PM callbacks run for one device when its usage count drops to zero. I put the real power-off and power-on code in the runtime callbacks and reuse them for system sleep through pm_runtime_force_suspend and force_resume — that's what DEFINE_RUNTIME_DEV_PM_OPS does. The force helpers skip devices that are already runtime-suspended, which avoids double-disabling clocks, and on resume they only power the device up if it's needed.

**Q.** "pm_runtime_get_sync vs pm_runtime_resume_and_get?"

**A.** get_sync는 resume이 실패해도 usage를 올려서, 에러 경로에서 `put_noidle`을 안 하면 누수가 된다. resume_and_get은 성공했을 때만 올린다. 누수는 장치를 영원히 켜 두고, 링크로 묶인 공급자까지 켜 둔다. 실습에서 실패 몇 번에 `runtime_usage`가 5가 되고 드라이버를 다시 올려도 남았다 — usage는 `struct device`에 있기 때문이다.

> get_sync increments the usage count even when the resume fails, so an early return without put_noidle leaks a reference; resume_and_get only increments on success. A leak keeps the device — and any supplier linked with DL_FLAG_PM_RUNTIME — powered forever. In my lab a few failed reads left runtime_usage at five, and reloading the driver didn't clear it, because the count lives in struct device, not in the driver.

**Q.** "In which suspend phase would you put the code that turns off an I2C controller, and why?"

**A.** 가능한 늦게 — `suspend_noirq`(또는 late). 다른 드라이버들이 자기 `suspend`/`suspend_late`에서 마지막 설정(PMIC, 센서 wake 모드)을 버스로 써야 하기 때문이다. 대신 noirq에서는 IRQ가 꺼져 있으므로 그 단계의 전송은 polling 모드여야 한다. resume은 반대로 `resume_noirq`에서 일찍 켠다.

> As late as possible — usually suspend_noirq — because other drivers still need the bus in their own suspend and suspend_late callbacks, for example to put a PMIC or a sensor into its wake mode. The trade-off is that interrupts are off by then, so any transfer in the noirq phase must work in polling mode. On the way back I'd bring it up early, in resume_noirq.

**Q.** "What is a wakeup source, and why can't a driver just block suspend by itself?"

**A.** wakeup source는 "이벤트를 처리 중이니 자지 마"를 표시하는 커널 객체다(`pm_stay_awake`/`pm_relax`, `pm_wakeup_event`). 그런데 처리 중 표시만으로는 `echo mem > state`를 막지 못한다 — 유저 공간이 `/sys/power/wakeup_count`를 읽고 다시 쓰는 프로토콜을 써야 그 뒤의 이벤트가 suspend를 중단시킨다. 커널 스스로 중단시키려면 `pm_wakeup_hard_event()`인데, 그것도 suspend가 진행 중일 때 와야 한다. 실습에서 세 경우를 모두 확인했다.

> A wakeup source is a kernel object that says "an event is being processed, don't sleep yet" — pm_stay_awake and pm_relax, or pm_wakeup_event with a timeout. By itself it doesn't stop a plain write to /sys/power/state; the race-free scheme is the wakeup_count handshake, where the suspend daemon reads the count, writes it back, and the kernel aborts if any event happened in between. A driver can force an abort with pm_wakeup_hard_event, but only events that arrive while the transition is in progress count — anything before the freeze phase is cleared.

**Q.** "How do you test a driver's PM code before you have the final hardware?"

**A.** `pm_test`로 단계까지만 돌리고, `rtcwake` 스트레스 루프로 수천 번 반복하며 `suspend_stats`를 본다. `pm_print_times`로 느린 콜백을, `runtime_usage`로 누수를, `power/control=on`으로 "PM 탓인가"를 가른다. 그리고 s2idle만이 아니라 대상 SoC의 deep suspend에서 반드시 돌린다 — 전원 도메인이 진짜로 꺼지는 건 deep뿐이다.

> pm_test to stop at a given phase and roll back, an rtcwake loop running thousands of cycles while I watch suspend_stats, pm_print_times for slow callbacks, runtime_usage for reference leaks, and power/control set to "on" to rule PM in or out. And I always run it in the target SoC's deep state, not just suspend-to-idle, because only deep sleep actually cuts the power domains.

## 14. 직접 해보기

1. (개념) 예제 2의 로그에서 prepare는 왜 정방향이고 suspend는 역방향인가? resume과 complete는? — 정답/힌트: `dpm_prepare()`는 dpm_list를 앞에서부터 돌며 `dpm_prepared_list`로 옮기고, `dpm_suspend()`는 그 목록의 꼬리부터, resume은 머리부터, `dpm_complete()`는 다시 꼬리부터 돈다. 부모·공급자가 앞에 있으므로 "끌 때는 뒤에서, 켤 때는 앞에서".
2. (코드) `n6_imu`를 `DEFINE_RUNTIME_DEV_PM_OPS(n6_imu_pm, imu_rt_suspend, imu_rt_resume, NULL)` 한 줄로 바꾸고 예제 2를 다시 돌려라. 무엇이 빠지고(prepare/late/noirq 로그, INT_EN quiesce, wake arm) 무엇이 같은가? — 정답/힌트: 시스템 suspend는 `pm_runtime_force_suspend`만 불려 장치가 이미 suspended면 아무 로그도 없다. 실제 드라이버 대부분은 이게 정답이고, wake는 `devm_pm_set_wake_irq()`로 옮긴다.
3. (관찰) 예제 7 상태(`imu_first=1 link=0`)에서 `power/async`를 두 장치 모두 `enabled`로 바꾸면 결과가 매번 같은가? — 정답/힌트: async 장치는 관계(부모·링크)만 기다리므로 순서가 비결정적이 된다. 여러 번 돌려 성공·실패가 섞이는지 보라. `echo 1 > /sys/power/pm_async`도 확인.
4. (코드) 6.18의 `PM_RUNTIME_ACQUIRE_IF_ENABLED_AUTOSUSPEND(dev, pm)`와 `PM_RUNTIME_ACQUIRE_ERR(&pm)`로 `selftest_show()`를 다시 써서 put을 한 줄도 쓰지 않고 누수가 없게 하라. — 정답/힌트: `include/linux/pm_runtime.h`의 가드 정의를 읽고, `if (PM_RUNTIME_ACQUIRE_ERR(&pm)) return -ENXIO;` 형태로 쓴다. 예제 8 수정판과 같은 `runtime_usage=0`이 나와야 한다.
5. (관찰) 예제 9-b의 핸드셰이크를 C로 짜라: `wakeup_count` 읽기 → 쓰기 → 성공하면 `freeze` 쓰기, 실패하면 1초 뒤 재시도. 엣지를 계속 넣는 동안 몇 번 재시도하는지 세라. — 정답/힌트: 쓰기 실패는 `EINVAL`, state 쓰기 실패는 `EBUSY`. 읽기가 블록되는 시간도 함께 재 보라.
6. (코드) `n6_wkey`에 `dev_pm_set_dedicated_wake_irq()`를 쓰고 runtime PM을 추가해, runtime-suspended 상태에서도 버튼 IRQ가 `runtime_resume`을 일으키게 하라. — 정답/힌트: dedicated wake IRQ는 runtime suspend 때 PM core가 켜 두고, 오면 `pm_runtime_resume()`을 요청한다(`drivers/base/power/wakeirq.c`).
7. (관찰) `reg_defaults`에서 `IMU_THRESH`의 기본값을 일부러 `0x42`로 틀리게 바꾸고 예제 6을 돌려라. resume 뒤 칩의 reg 3은? — 정답/힌트: sync가 "기본값과 같다"며 건너뛰어 칩에는 POR 값 0x10이 남는다. 캐시는 0x42라고 말하는데 칩은 0x10 — 가장 찾기 어려운 종류의 버그다.

| s2idle (suspend-to-idle, `freeze`) | 가장 얕은 시스템 sleep | 장치 suspend 후 CPU를 idle에 둔다. 모든 아키텍처에서 됨 |
| deep (suspend-to-RAM, `mem`) | 플랫폼 suspend | DRAM self-refresh, SoC 전원 대부분 off. PSCI SYSTEM_SUSPEND |
| hibernation (`disk`) | 메모리 이미지를 저장하고 끄기 | freeze/thaw → poweroff, 부팅 후 restore |
| phase | 단계 | prepare, suspend, late, noirq와 그 거울 |
| dpm_list | 장치 PM 목록 | 등록 순서. suspend는 뒤에서부터 |
| device link | 트리 밖 의존성 | 공급자/소비자, probe·PM 순서와 runtime PM 연동 |
| fw_devlink | 펌웨어(DT/ACPI) 기반 자동 링크 | phandle을 보고 링크 생성 |
| `DL_FLAG_PM_RUNTIME` | 링크 플래그 | 소비자 runtime resume 전에 공급자 resume |
| async suspend | 비동기 장치 suspend | `power/async`. 관계만 기다리며 병렬 |
| runtime PM | 장치 단위 PM | usage count 0 → runtime_suspend |
| usage count | runtime PM 참조 수 | get +1, put -1. sysfs `runtime_usage` |
| autosuspend | 지연된 runtime suspend | `last_busy + autosuspend_delay` |
| `pm_runtime_force_suspend/resume` | 시스템 sleep에서 runtime 콜백 재사용 | 이미 suspended면 건너뜀 |
| direct_complete | 시스템 suspend 건너뛰기 | runtime-suspended 장치의 콜백 생략 |
| regcache | regmap 레지스터 캐시 | cache_only, mark_dirty, sync |
| POR | Power-On Reset 값 | 전원 직후 레지스터 값 = `reg_defaults` |
| wake IRQ | 시스템을 깨우는 IRQ | `enable_irq_wake`, `IRQD_WAKEUP_ARMED` |
| `IRQF_NO_SUSPEND` | 끄지 않는 IRQ | 깨우지는 않는다 |
| wakeup source | 깨어 있음을 표시하는 객체 | `pm_stay_awake`/`pm_relax`, `pm_wakeup_event` |
| wakeup_count 프로토콜 | race-free suspend 절차 | 읽기 → 쓰기 → state |
| `pm_test` | 단계 시험 모드 | freezer/devices/platform/processors/core |
| PM domain (genpd) | 전원 도메인 | 여러 장치의 전원 레일을 묶어 끄는 계층 (N5) |

## 16. 요약 & 체크리스트

드라이버의 PM은 "언제·누구 다음에·무엇을 잃나"의 문제다. `struct dev_pm_ops`는 전환 종류 × 단계의 표이고, 6.x에서는 `SYSTEM_SLEEP_PM_OPS`/`RUNTIME_PM_OPS` 조각과 `pm_ptr`/`pm_sleep_ptr`로 `#ifdef` 없이 쓴다. 순서는 dpm_list(등록 순서)에서 오고, 트리 밖 의존성은 device link(DT면 fw_devlink)로 고친다 — 링크가 없으면 공급자가 먼저 잠들어 `transfer while suspended`가 난다(예제 7). 하드웨어를 끄고 켜는 코드는 runtime 콜백에 한 번만 두고 `pm_runtime_force_*`로 시스템 sleep에 재사용하며, 레지스터는 regmap의 cache_only/mark_dirty/sync로 복원한다(`reg_defaults` = POR). runtime PM은 참조 카운트라 `pm_runtime_resume_and_get`과 빠짐없는 put이 생명이다(예제 8). 장치가 시스템을 깨우려면 wake 가능한 irqchip + `device_init_wakeup` + `dev_pm_set_wake_irq`(또는 `enable_irq_wake`)가 필요하고, "지금 자지 마"는 wakeup source와 유저의 wakeup_count 프로토콜로 표현한다(예제 9, 10).

- [ ] `dev_pm_ops`의 23개 콜백을 전환 × 단계 표로 그릴 수 있다
- [ ] 각 단계에서 IRQ와 runtime PM이 켜져 있는지 말할 수 있다
- [ ] `DEFINE_SIMPLE_DEV_PM_OPS`, `DEFINE_RUNTIME_DEV_PM_OPS`, `pm_sleep_ptr`가 각각 무엇으로 펼쳐지는지 설명할 수 있다
- [ ] dpm_list 순서가 어디서 오고 device link가 그것을 어떻게 바꾸는지 설명할 수 있다
- [ ] `pm_print_times` 로그를 읽고 순서 버그를 찾을 수 있다
- [ ] runtime PM probe 패턴(set_active → autosuspend → devm enable)을 코드로 짤 수 있다
- [ ] `get_sync`와 `resume_and_get`의 차이와 누수 증상을 설명하고 `runtime_usage`로 증명할 수 있다
- [ ] regmap regcache로 runtime suspend/resume을 구현하고 `reg_defaults`의 함정을 설명할 수 있다
- [ ] `disable_irq`, `IRQF_NO_SUSPEND`, `enable_irq_wake`, `dev_pm_set_wake_irq`의 차이를 말할 수 있다
- [ ] wakeup source와 wakeup_count 프로토콜이 suspend를 막는 조건을 설명할 수 있다
- [ ] `pm_test`, `rtcwake` 루프, `suspend_stats`, `pm_wakeup_irq`로 PM 코드를 시험할 수 있다
- [ ] s2idle만으로 테스트가 끝나지 않는 이유(deep에서 전원 도메인 off)를 말할 수 있다
