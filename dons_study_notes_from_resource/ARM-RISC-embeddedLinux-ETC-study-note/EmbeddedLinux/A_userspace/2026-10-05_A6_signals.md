# A6. 시그널 — 프로세스에게 거는 소프트웨어 인터럽트

> **이 노트를 다 읽으면**: 주요 시그널의 기본 동작과 쓰임새를 설명할 수 있다 · `sigaction`·마스크·SA_RESTART·EINTR를 정확히 다룰 수 있다 · async-signal-safe 규칙을 지키는 데몬(signalfd + epoll)을 짤 수 있다 · 커널이 시그널을 배달하는 경로와 D 상태 프로세스가 `kill -9`에 안 죽는 이유를 드라이버 관점에서 말할 수 있다
> **왜 필요한가**: "Ctrl-C를 누르면 무슨 일이?", "핸들러에서 printf 써도 되나?", "kill -9가 안 먹는 프로세스는?"은 Embedded Linux 면접 단골이고, 실무에서는 systemd가 보낸 SIGTERM에 센서 데몬이 깔끔하게 종료되는지가 매일 문제가 된다.
> **Don 기준 난이도**: 인터럽트·pending 비트·마스크·ISR 제약은 이미 몸에 익은 개념 / 그것이 "유저 프로세스" 단위로 어떻게 재해석되는지, 커널의 배달 시점·스레드와의 관계는 새로 배운다
> **선행 노트**: A1, A2, A3, A4 (A4의 epoll은 6절에서 다시 쓴다)

## 0. 큰 그림 — 이게 왜 필요한가

Bare-metal 펌웨어에서 "비동기 이벤트"는 전부 인터럽트였다. UART에 바이트가 오면 IRQ 라인이 올라가고, NVIC의 pending 비트가 켜지고, 마스크가 열려 있으면 벡터 테이블에서 ISR 주소를 찾아 점프한다.

Linux의 유저 프로세스는 하드웨어 IRQ를 직접 받을 수 없다. 대신 커널이 프로세스에게 **"이벤트가 생겼다"는 사실을 비동기로 알려 주는 장치**가 있는데, 그게 **시그널(signal)** 이다. 시그널은 번호(1~64)만 가진 아주 작은 메시지이고, 받는 쪽은 미리 등록한 함수(**handler**)로 반응하거나, 커널이 정한 **기본 동작(default action)** 을 따른다.

센서 키트 장비에서 시그널이 등장하는 장면은 이런 것들이다.

- systemd가 `systemctl stop sensord`를 받으면 데몬에 **SIGTERM**을 보낸다. 데몬은 IMU 전원을 끄고, 버퍼를 flush하고, 종료해야 한다.
- 개발자가 터미널에서 Ctrl-C를 누르면 **SIGINT**.
- 카메라 버퍼를 mmap 했는데 드라이버가 버퍼를 치워 버렸다면 그 주소를 건드리는 순간 **SIGBUS**.
- 데이터 로거가 끊어진 TCP 소켓에 write 하면 **SIGPIPE**로 조용히 죽는다.
- NULL 포인터를 밟으면 **SIGSEGV** → core dump → gdb로 사후 분석.

## 1. 시그널이란 — 하드웨어 IRQ와 어디까지 같은가

### 1.1 정의

**시그널** = 커널이 특정 프로세스(또는 스레드)의 **pending 집합에 번호 하나를 기록**하고, 그 프로세스가 다음에 **커널에서 유저 모드로 돌아갈 때** 그 번호에 해당하는 동작을 실행하게 하는 메커니즘이다.

시그널을 만드는 쪽은 세 가지다.

1. **다른 프로세스**: `kill(pid, sig)`, `sigqueue()`, 셸의 `kill` 명령, systemd.
2. **커널 자신 — 동기(synchronous) 시그널**: 이 스레드가 방금 실행한 명령이 원인. 잘못된 메모리 접근(SIGSEGV), 매핑은 있지만 뒤에 실체가 없는 페이지(SIGBUS), 0으로 나누기(SIGFPE), 정의되지 않은 명령(SIGILL).
3. **커널 자신 — 비동기 이벤트**: 자식 종료(SIGCHLD), 읽는 쪽 없는 pipe에 쓰기(SIGPIPE), 타이머 만료(SIGALRM), 터미널의 Ctrl-C(SIGINT)·끊김(SIGHUP).

### 1.2 IRQ 비유가 맞는 부분

| 하드웨어 인터럽트 | 시그널 | 메모 |
|---|---|---|
| IRQ 번호 | 시그널 번호 (1~64) | 둘 다 "무슨 일인지"만 알려 주는 작은 번호 |
| NVIC pending 비트 | pending 집합의 비트 | 표준 시그널은 **비트 1개**라서 여러 번 와도 1번으로 합쳐진다 — NVIC와 똑같다 |
| PRIMASK, 개별 enable | blocked 마스크 (`sigprocmask`) | 막아 두면 pending으로 남았다가, 풀면 즉시 배달 |
| 벡터 테이블 | `sigaction`으로 등록한 disposition 표 | 시그널마다 기본/무시/handler 셋 중 하나 |
| ISR 안에서 블로킹 함수 금지 | handler 안에서 async-signal-safe 함수만 | 이유도 같다: 끊긴 코드가 락을 쥐고 있을 수 있다 |
| ISR → 메인 루프에 flag | handler → `volatile sig_atomic_t` flag | "ISR은 짧게, 일은 메인에서" 원칙 그대로 |

### 1.3 비유가 깨지는 부분 (면접에서 이걸 말하면 점수가 높다)

| 항목 | 하드웨어 IRQ | 시그널 |
|---|---|---|
| 실행 시점 | 명령 경계에서 즉시 선점 | 그 스레드가 **커널 → 유저로 복귀하는 순간**에만 확인. 커널 안에서 자고 있으면 깨워야 하고, 깨울 수 없는 잠(D 상태)이면 기다린다 |
| 특권 수준 | Handler 모드(특권), 별도 스택(MSP) | **유저 모드**, 기본적으로 **같은 유저 스택**(원하면 `sigaltstack`) |
| 우선순위·중첩 | 우선순위 기반 선점·tail-chaining | 우선순위 개념이 거의 없다. 같은 시그널은 handler 도는 동안 자동 block, 다른 시그널은 중첩 가능 |
| 큐잉 | pending 비트 1개 | 표준은 비트 1개, **real-time 시그널은 큐**(보낸 횟수만큼 배달, 값도 전달) |
| 대상 | 코어 하나 | 프로세스(스레드 그룹) 또는 특정 스레드. 멀티스레드면 "누가 받나"가 문제 (7절) |
| 지연 | 수십 사이클, 결정적 | 스케줄링에 의존, 비결정적. 실측 수백 ns~(9절), 부하 시 ms 단위 |
| 못 막는 것 | NMI, HardFault | **SIGKILL, SIGSTOP** — 잡지도, 막지도, 무시하지도 못한다 |

> 한 문장 요약: 시그널은 "유저 프로세스용 가상 인터럽트"지만, **배달은 커널 복귀 시점에만** 일어나고 **handler는 유저 코드**다. 그래서 실시간 이벤트 전달 수단으로는 부적합하고, 주로 "프로세스 수명 제어(종료·재시작·reload)"와 "치명적 오류 보고"에 쓴다.

## 2. 주요 시그널과 기본 동작

### 2.1 기본 동작 다섯 가지

- **Term**: 프로세스 종료.
- **Core**: 종료 + core dump(메모리 이미지 파일) 생성.
- **Ign**: 무시.
- **Stop**: 정지(TASK_STOPPED, `ps`에서 `T`).
- **Cont**: 정지돼 있으면 재개.

### 2.2 Embedded 실무에서 만나는 시그널

| 시그널 | 번호 | 기본 | 누가/언제 보내나 | 실무 포인트 |
|---|---|---|---|---|
| SIGHUP | 1 | Term | 터미널 끊김 | 데몬 관례: "설정 다시 읽기(reload)" |
| SIGINT | 2 | Term | Ctrl-C | 개발 중 툴 종료. 데몬은 TERM과 같이 처리 |
| SIGQUIT | 3 | Core | Ctrl-\ | 멈춘 프로세스의 core를 얻는 손쉬운 방법 |
| SIGABRT | 6 | Core | `abort()`, `assert` 실패 | glibc가 heap 손상을 감지해도 이것 |
| SIGBUS | 7 | Core | 매핑은 있는데 뒤에 실체 없음 | **mmap한 파일이 잘렸을 때, 디바이스 메모리 접근 오류**, 정렬 위반(일부 아키텍처) |
| SIGKILL | 9 | Term | `kill -9`, OOM killer | 잡기·막기·무시 불가. cleanup 기회 없음 |
| SIGUSR1/2 | 10/12 | Term | 사용자 정의 | "통계 덤프", "로그 레벨 변경" 같은 용도 |
| SIGSEGV | 11 | Core | 잘못된 주소 접근 | NULL 역참조, 스택 오버플로, 쓰기 금지 페이지 |
| SIGPIPE | 13 | Term | 읽는 쪽 없는 pipe/socket에 write | 네트워크 데몬이 **조용히 죽는** 주범 → `SIG_IGN` 또는 `MSG_NOSIGNAL` |
| SIGALRM | 14 | Term | `alarm()`, `setitimer` | 옛 타임아웃 방식. 지금은 timerfd 권장 (A4) |
| SIGTERM | 15 | Term | `kill` 기본, systemd stop | **정상 종료 요청**. 데몬은 반드시 처리 |
| SIGCHLD | 17 | Ign | 자식 종료·정지 | 부모가 `waitpid`로 회수해야 좀비가 안 남는다 (A2) |
| SIGCONT | 18 | Cont | `kill -CONT`, `fg` | 정지된 프로세스 재개 |
| SIGSTOP | 19 | Stop | `kill -STOP` | 잡기 불가. 디버깅용 정지 |
| SIGTSTP | 20 | Stop | Ctrl-Z | 잡을 수 있는 정지 |
| SIGRTMIN~MAX | 34~64 | Term | `sigqueue()` 등 | **큐잉되고 값 전달**, 번호 작은 것부터 배달 |

### 예제 2 — 기본 동작을 직접 확인한다

무엇을 확인하나: 자식 프로세스가 각 시그널을 자기에게 보내고, 부모가 `waitpid` 상태로 Term/Core/Ign/Stop을 판별한다.

```c
/* ex1: 각 시그널의 기본 동작(default action)을 자식 프로세스로 확인 */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/wait.h>
#include <unistd.h>

static void try_sig(int sig)
{
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); exit(1); }
    if (pid == 0) {                  /* 자식: 자기 자신에게 시그널 */
        raise(sig);
        _exit(0);                    /* 시그널이 무시되면 여기로 온다 */
    }
    int st;
    if (waitpid(pid, &st, WUNTRACED) < 0) { perror("waitpid"); exit(1); }
    printf("%-8s(%2d) -> ", sigabbrev_np(sig) ? sigabbrev_np(sig) : "RTMIN", sig);
    if (WIFEXITED(st))
        printf("exit(%d)        : 무시됨(Ign)\n", WEXITSTATUS(st));
    else if (WIFSIGNALED(st))
        printf("killed%s : %s\n", WCOREDUMP(st) ? "+core" : "      ",
               WCOREDUMP(st) ? "Core" : "Term");
    else if (WIFSTOPPED(st)) {
        printf("stopped        : Stop\n");
        kill(pid, SIGKILL);          /* 멈춘 자식 정리 */
        waitpid(pid, &st, 0);
    }
}

int main(void)
{
    int sigs[] = { SIGHUP, SIGINT, SIGQUIT, SIGILL, SIGABRT, SIGBUS, SIGFPE,
                   SIGKILL, SIGUSR1, SIGSEGV, SIGPIPE, SIGALRM, SIGTERM,
                   SIGCHLD, SIGCONT, SIGSTOP, SIGTSTP, SIGURG, SIGWINCH,
                   SIGRTMIN };
    for (size_t i = 0; i < sizeof sigs / sizeof sigs[0]; i++)
        try_sig(sigs[i]);
    return 0;
}
```

### 2.3 SIGBUS vs SIGSEGV — Don에게 특히 중요한 구분

- **SIGSEGV**: 그 주소에 **매핑 자체가 없거나**(`SEGV_MAPERR`), 권한이 없다(`SEGV_ACCERR`). MMU 관점에서 "page table에 없음/권한 위반".
- **SIGBUS**: 매핑은 **있는데** 그 페이지를 채울 실체가 없다. 대표적으로 mmap한 파일이 중간에 truncate 되어 파일 끝 너머 페이지를 건드릴 때(`BUS_ADRERR`), 드라이버의 `.fault`가 `VM_FAULT_SIGBUS`를 돌려줄 때, 메모리 하드웨어 오류(`BUS_MCEERR_AR`). 디바이스 레지스터를 `/dev/mem`이나 UIO로 mmap 해서 접근하다가 버스 에러(외부 abort)가 나는 경우도 아키텍처에 따라 SIGBUS로 온다.

SSD 펌웨어로 치면 SEGV는 "MPU region 밖 접근", SIGBUS는 "region은 열려 있는데 그 뒤 버스 슬레이브가 에러 응답"에 가깝다. 예제 4에서 직접 만든다.

## 3. 시그널 보내기와 받기 — kill, sigaction, SA_RESTART, SA_SIGINFO

### 3.1 보내는 API

| API | 대상 | 특징 |
|---|---|---|
| `kill(pid, sig)` | 프로세스(`pid>0`), 프로세스 그룹(`pid<0`), 모두(`-1`) | 가장 기본. `sig=0`이면 "존재·권한 확인"만 |
| `raise(sig)` | 자기 자신(현재 스레드) | 내부적으로 `tgkill` |
| `pthread_kill(t, sig)` | 같은 프로세스의 특정 스레드 | thread-directed |
| `sigqueue(pid, sig, val)` | 프로세스 | `int`나 포인터 값 하나를 같이 보냄 (RT 시그널과 짝) |
| `tgkill(tgid, tid, sig)` | 특정 스레드 | syscall. 셸에서는 불가 |

### 3.2 `signal()` 대신 `sigaction()`을 쓰는 이유

`signal(sig, handler)`는 오래된 API라 **시스템마다 의미가 다르다**. System V 계열은 handler가 한 번 불리면 SIG_DFL로 되돌리고(재진입 중 같은 시그널 오면 죽음), BSD 계열은 유지 + 시스템콜 자동 재시작이다. glibc의 `signal()`은 BSD 의미지만 이식성 있는 코드는 `sigaction()`만 쓴다. `sigaction`은 다음을 명시적으로 정한다.

```c
struct sigaction sa = {
    .sa_handler = on_term,      /* 또는 .sa_sigaction (SA_SIGINFO일 때) */
    .sa_flags   = SA_RESTART,   /* 아래 3.3 */
};
sigemptyset(&sa.sa_mask);       /* handler 도는 동안 추가로 막을 시그널 */
sigaction(SIGTERM, &sa, NULL);
```

- `sa_mask`: handler 실행 중 **추가로 block**할 시그널. 처리 중인 시그널 자신은 `SA_NODEFER`가 없으면 자동으로 막힌다(ISR이 자기 IRQ를 다시 받지 않는 것과 같다).
- `sa_flags`: `SA_RESTART`, `SA_SIGINFO`, `SA_ONSTACK`(sigaltstack 사용), `SA_NOCLDSTOP`, `SA_NOCLDWAIT`, `SA_RESETHAND`, `SA_NODEFER`.

### 3.3 EINTR와 SA_RESTART — A3의 "robust loop"가 필요한 진짜 이유

blocking syscall(예: `read()`)로 잠들어 있는 동안 시그널이 오면 커널은 그 잠을 깨우고 handler를 돌려야 한다. 그럼 원래의 `read()`는?

- handler에 **SA_RESTART가 없으면**: `read()`는 `-1`, `errno=EINTR`로 돌아온다.
- **SA_RESTART가 있으면**: 커널이 `read()`를 **자동으로 다시 실행**한다. 유저 코드는 끊긴 줄도 모른다.

### 예제 3 — EINTR vs SA_RESTART를 눈으로 보기

무엇을 확인하나: 2초 뒤에 데이터가 오는 pipe를 `read()`로 기다리는 동안 1초 시점에 SIGALRM이 온다. 플래그에 따라 결과가 어떻게 달라지는가.

```c
/* ex2: SA_RESTART 유무에 따라 blocking read()가 EINTR로 깨지는지 확인 */
#define _GNU_SOURCE
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

static struct timespec t0;
static double now(void)
{
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return (t.tv_sec - t0.tv_sec) + (t.tv_nsec - t0.tv_nsec) / 1e9;
}
static void on_alrm(int sig)
{
    (void)sig;
    int saved = errno;               /* 핸들러는 errno를 보존해야 한다 */
    ssize_t r = write(1, "  [handler] SIGALRM\n", 20);   /* write는 async-signal-safe */
    (void)r;
    errno = saved;
}

static void run(int flags, const char *name)
{
    int p[2];
    if (pipe(p) < 0) { perror("pipe"); exit(1); }
    struct sigaction sa = { .sa_handler = on_alrm, .sa_flags = flags };
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIGALRM, &sa, NULL) < 0) { perror("sigaction"); exit(1); }

    if (fork() == 0) {               /* 자식: 2초 뒤에 데이터 쓰기 */
        close(p[0]); sleep(2);
        if (write(p[1], "data", 4) != 4) _exit(1);
        _exit(0);
    }
    close(p[1]);
    clock_gettime(CLOCK_MONOTONIC, &t0);
    alarm(1);                        /* 1초 뒤 SIGALRM */
    char buf[16];
    printf("%s: read() 대기 시작\n", name); fflush(stdout);
    ssize_t n = read(p[0], buf, sizeof buf);
    int e = errno;
    printf("%s: t=%.2fs read()=%zd %s\n\n", name, now(), n,
           n < 0 ? strerrorname_np(e) : "(정상 데이터)");
    close(p[0]);
    sleep(2);                        /* 자식 정리 대기 */
}

int main(void)
{
    run(0, "flags=0         ");
    run(SA_RESTART, "flags=SA_RESTART");
    return 0;
}
```

```text
flags=0         : read() 대기 시작
  [handler] SIGALRM
flags=0         : t=1.01s read()=-1 EINTR

flags=SA_RESTART: read() 대기 시작
  [handler] SIGALRM
flags=SA_RESTART: t=2.01s read()=4 (정상 데이터)
```

출력에서 볼 것: 두 경우 모두 1초에 handler가 돈다. 그런데 `flags=0`이면 `read()`가 1.01초에 **EINTR로 실패**하고, `SA_RESTART`면 재시작되어 2.01초에 데이터 4바이트를 정상으로 받는다.

꼭 기억할 함정 세 가지:

1. **SA_RESTART가 있어도 재시작되지 않는 syscall이 있다**. `poll`, `select`, `epoll_wait`, `nanosleep`/`clock_nanosleep`(남은 시간 반환), 타임아웃을 설정한 소켓 read 등은 handler가 돌면 항상 EINTR다(`man 7 signal`의 "Interruption of system calls" 절). 그래서 이벤트 루프는 **EINTR를 항상 처리**해야 한다.
2. 내가 SA_RESTART를 써도 **라이브러리가 설치한 handler**가 SA_RESTART 없이 깔릴 수 있다. 결론: A3에서 만든 것처럼 `read`/`write` 래퍼는 **항상 `if (errno == EINTR) continue;`** 를 넣는다.
3. 부분 전송: 이미 일부 바이트를 읽거나 쓴 뒤에 시그널이 오면 syscall은 EINTR가 아니라 **그때까지의 바이트 수**를 돌려준다. 그래서 루프가 필요하다.

```c
/* A3에서 만든 robust read — 시그널 때문에 이렇게 생겼다 */
ssize_t read_full(int fd, void *buf, size_t len)
{
    size_t done = 0;
    while (done < len) {
        ssize_t n = read(fd, (char *)buf + done, len - done);
        if (n < 0 && errno == EINTR) continue;   /* 시그널: 다시 */
        if (n < 0) return -1;
        if (n == 0) break;                       /* EOF */
        done += (size_t)n;                       /* 부분 읽기 */
    }
    return (ssize_t)done;
}
```

### 3.4 SA_SIGINFO — "누가, 왜, 어디서"

`SA_SIGINFO`를 켜면 handler 시그니처가 `void h(int sig, siginfo_t *si, void *ucontext)`가 되고, `siginfo_t`로 다음을 알 수 있다.

- `si_code`: 원인. `SI_USER`(kill), `SI_QUEUE`(sigqueue), `SI_KERNEL`, 폴트면 `SEGV_MAPERR`/`SEGV_ACCERR`/`BUS_ADRERR` 등.
- `si_pid`, `si_uid`: 보낸 프로세스 (kill/sigqueue일 때).
- `si_addr`: 폴트 주소 (SIGSEGV/SIGBUS/SIGILL/SIGFPE).
- `si_value`: `sigqueue`로 실려 온 값.
- `si_status`: SIGCHLD일 때 자식의 종료 코드.
- 세 번째 인자 `ucontext_t`: 끊긴 순간의 레지스터 전체 (10절에서 사용).

### 예제 4 — sigqueue 값 받기 + mmap 파일 truncate로 SIGBUS 만들기

무엇을 확인하나: `SA_SIGINFO`로 보낸 프로세스·값을 받고, mmap한 파일을 잘라서 SIGBUS의 `si_code`/`si_addr`를 확인한다.

```c
/* ex3: SA_SIGINFO로 "누가/왜/어디서" 보냈는지 받기 — mmap 파일 truncate 후 SIGBUS */
#define _GNU_SOURCE
#include <fcntl.h>
#include <setjmp.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>

static sigjmp_buf jb;
static volatile sig_atomic_t g_code, g_pid, g_val;
static void *volatile g_addr;

static void h(int sig, siginfo_t *si, void *uctx)
{
    (void)uctx;
    g_code = si->si_code; g_addr = si->si_addr;
    g_pid = si->si_pid;   g_val = si->si_value.sival_int;
    if (sig == SIGBUS) siglongjmp(jb, 1);   /* 폴트 명령으로 돌아가면 무한 반복 */
}

int main(void)
{
    struct sigaction sa = { .sa_sigaction = h, .sa_flags = SA_SIGINFO };
    sigemptyset(&sa.sa_mask);
    sigaction(SIGBUS, &sa, NULL);
    sigaction(SIGUSR1, &sa, NULL);

    /* (1) 다른 프로세스(여기선 자기 자신)가 sigqueue로 값과 함께 보냄 */
    union sigval v = { .sival_int = 42 };
    if (sigqueue(getpid(), SIGUSR1, v) < 0) { perror("sigqueue"); exit(1); }
    printf("SIGUSR1: si_code=%d (SI_QUEUE=%d) si_pid=%d (me=%d) value=%d\n",
           (int)g_code, SI_QUEUE, (int)g_pid, getpid(), (int)g_val);

    /* (2) 파일을 2페이지 mmap 한 뒤 파일을 0바이트로 줄인다 */
    int fd = open("/tmp/A6/bus.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0 || ftruncate(fd, 8192) < 0) { perror("open/ftruncate"); exit(1); }
    char *p = mmap(NULL, 8192, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (p == MAP_FAILED) { perror("mmap"); exit(1); }
    p[0] = 'A';
    printf("mmap ok at %p, p[0]='%c'\n", (void *)p, p[0]);
    if (ftruncate(fd, 0) < 0) { perror("ftruncate"); exit(1); }

    if (sigsetjmp(jb, 1) == 0) {
        volatile char c = p[4096];       /* 파일 끝 너머 페이지 접근 */
        (void)c;
        printf("여기는 오지 않는다\n");
    } else {
        printf("SIGBUS: si_code=%d (BUS_ADRERR=%d) si_addr=%p (p+%ld)\n",
               (int)g_code, BUS_ADRERR, g_addr, (long)((char *)g_addr - p));
    }
    munmap(p, 8192); close(fd);
    return 0;
}
```

```text
SIGUSR1: si_code=-1 (SI_QUEUE=-1) si_pid=33230 (me=33230) value=42
mmap ok at 0xf864b702d000, p[0]='A'
SIGBUS: si_code=2 (BUS_ADRERR=2) si_addr=0xf864b702e000 (p+4096)
```

출력에서 볼 것: SIGUSR1은 `SI_QUEUE`로 왔고 값 42가 실렸다. mmap 주소 범위 안인데도 파일이 0바이트가 된 뒤 두 번째 페이지(`p+4096`)를 읽자 **SIGSEGV가 아니라 SIGBUS**(`BUS_ADRERR`)가 났고 `si_addr`가 정확히 폴트 주소다. PID·주소는 실행마다 다르다.

- handler에서 그냥 return 하면 **폴트 명령을 다시 실행**해서 무한 반복된다. 동기 폴트에서 살아남으려면 `siglongjmp`로 탈출하거나, 로그만 남기고 `_exit`해야 한다. 실무에서는 대부분 "기록 후 종료 + core"가 정답이다.
- 카메라 V4L2 버퍼처럼 **드라이버가 제공하는 mmap**에서도 같은 일이 생긴다. 드라이버의 `vm_operations_struct.fault`가 페이지를 줄 수 없으면 `VM_FAULT_SIGBUS`를 돌려주고, 유저는 SIGBUS를 받는다 (A5, H 모듈의 mmap 드라이버 노트에서 다시 본다).

## 4. 마스크, pending, disposition — 시그널 상태 3종 세트

### 4.1 세 가지 상태

- **disposition** (프로세스 전체 공유): 시그널마다 `SIG_DFL` / `SIG_IGN` / handler 주소. 벡터 테이블.
- **blocked 마스크** (스레드마다): 지금 배달을 미룰 시그널 집합. PRIMASK의 시그널판.
- **pending 집합**: 도착했지만 아직 배달 안 된 시그널. 두 종류가 있다.
  - 스레드 전용 pending (`pthread_kill`, `tgkill`, 동기 폴트) → `/proc/<pid>/status`의 `SigPnd`
  - 프로세스 공유 pending (`kill(pid)`) → `ShdPnd`

배달 조건은 간단하다: **pending AND NOT blocked** 인 시그널이 있으면, 다음 유저 복귀 때 배달된다.

### 예제 5 — /proc/self/status로 마스크·pending을 해독하고, 표준 vs RT 큐잉 비교

무엇을 확인하나: SIGUSR1과 SIGRTMIN을 막은 채 각각 3번씩 보낸 뒤 `/proc/self/status`의 비트를 해독하고, 막기를 풀었을 때 handler가 몇 번 불리는지 센다.

```c
/* ex4: 마스크·펜딩·핸들러 상태를 /proc/self/status로 보고, 표준 vs RT 시그널 큐잉 비교 */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static volatile sig_atomic_t n_usr1, n_rt;
static void h(int sig) { if (sig == SIGUSR1) n_usr1++; else n_rt++; }

static void show(const char *tag)
{
    FILE *f = fopen("/proc/self/status", "r");
    char line[256];
    printf("--- %s\n", tag);
    while (fgets(line, sizeof line, f)) {
        if (strncmp(line, "Sig", 3) && strncmp(line, "ShdPnd", 6)) continue;
        if (!strncmp(line, "SigQ", 4)) { printf("%s", line); continue; }
        unsigned long long m = strtoull(strchr(line, ':') + 1, NULL, 16);
        line[strcspn(line, "\n")] = 0;
        printf("%-24s ->", line);
        for (int s = 1; s <= 64; s++)            /* 비트 (s-1) = 시그널 s */
            if (m & (1ULL << (s - 1)))
                printf(" %s", sigabbrev_np(s) ? sigabbrev_np(s) : "RT");
        printf("\n");
    }
    fclose(f);
}

int main(void)
{
    struct sigaction sa = { .sa_handler = h };
    sigemptyset(&sa.sa_mask);
    sigaction(SIGUSR1, &sa, NULL);
    sigaction(SIGRTMIN, &sa, NULL);
    signal(SIGHUP, SIG_IGN);

    sigset_t blk, old;
    sigemptyset(&blk);
    sigaddset(&blk, SIGUSR1);
    sigaddset(&blk, SIGRTMIN);
    sigprocmask(SIG_BLOCK, &blk, &old);           /* 막아 둔다 */

    for (int i = 0; i < 3; i++) {                  /* 각각 3번씩 보낸다 */
        kill(getpid(), SIGUSR1);
        kill(getpid(), SIGRTMIN);
    }
    show("blocked, 3번씩 보낸 직후");

    sigset_t pend; sigpending(&pend);
    printf("sigpending: USR1=%d RTMIN=%d\n",
           sigismember(&pend, SIGUSR1), sigismember(&pend, SIGRTMIN));

    sigprocmask(SIG_SETMASK, &old, NULL);          /* 풀면 즉시 배달 */
    printf("unblock 후 핸들러 호출 횟수: SIGUSR1=%d SIGRTMIN=%d\n",
           (int)n_usr1, (int)n_rt);
    show("unblock 후");
    return 0;
}
```

- `SigQ: 4/13689` = 현재 큐에 있는 `sigqueue` 항목 수 / 한도(`RLIMIT_SIGPENDING`). USR1 1개 + RTMIN 3개 = 4. USR1은 3번 보냈지만 이미 pending이라 **나머지 2번은 버려졌다**.
- 풀자마자 handler가 USR1은 **1번**, RTMIN은 **3번** 불렸다. 표준 시그널은 NVIC pending 비트처럼 합쳐지고, RT 시그널은 큐잉된다. 그래서 "시그널로 이벤트 개수를 세면 안 된다"(표준 시그널).

### 4.2 sigprocmask vs pthread_sigmask

- `sigprocmask()`는 **싱글 스레드 프로그램용**. 멀티스레드에서는 동작이 정의되지 않았다(POSIX). Linux glibc에서는 호출한 스레드의 마스크만 바꾼다.
- 멀티스레드에서는 `pthread_sigmask()`를 쓴다. 마스크는 **스레드마다** 있고, `pthread_create` 시 **부모 스레드의 마스크를 상속**한다(7절의 핵심).
- `fork()`의 자식은 마스크와 disposition을 상속, pending은 비운다. `exec()`는 마스크·무시(SIG_IGN) 설정을 **유지**하고, handler는 SIG_DFL로 되돌린다(새 프로그램에는 그 handler 코드가 없으니까). 그래서 **시그널을 막아 둔 데몬이 자식을 exec 하면 자식도 SIGTERM이 막힌 채로 시작한다** — 흔한 버그(12절).

## 5. Async-signal-safety — handler 안에서 해도 되는 일

### 5.1 왜 제약이 있나

handler는 프로그램의 **아무 명령 사이에서나** 끼어든다. 메인 코드가 `malloc()` 안에서 힙 락을 쥔 순간 시그널이 와서 handler가 또 `malloc()`을 부르면? 같은 스레드가 자기가 쥔 락을 다시 기다린다 — **self-deadlock**. `printf()`는 stdout 버퍼(+락)를, `syslog()`는 소켓과 락을, `exit()`는 atexit 핸들러와 stdio flush를 건드린다.

ISR에서 RTOS mutex를 잡지 않는 것과 정확히 같은 이유다. 차이는 ISR은 별도 컨텍스트라 "ISR에서는 mutex API 금지"가 명확한 반면, handler는 **같은 스레드 위에** 올라타기 때문에 재귀 진입 문제가 생긴다는 것.

POSIX가 handler에서 불러도 된다고 보장하는 함수 목록이 **async-signal-safe** 목록이다(`man 7 signal-safety`). 대표적으로 `write`, `read`, `_exit`, `kill`, `sigprocmask`, `sem_post`, `clock_gettime`, `open`, `close`, `signal`/`sigaction` 등. **안 되는 것**: `printf` 계열, `malloc`/`free`, `pthread_mutex_lock`, `syslog`, `exit`, 대부분의 C++ 라이브러리.

### 예제 6 — handler에서 "락 잡는 함수"를 부르면 실제로 멈춘다

무엇을 확인하나: 메인 루프와 handler가 같은 로깅 함수(내부에 비재귀 mutex)를 쓴다. glibc의 malloc·stdio가 내부에서 하는 일과 같은 구조다. 100µs마다 SIGALRM을 건다.

```c
/* ex5: 핸들러가 "락을 잡는 함수"를 부르면 생기는 self-deadlock 재현
 * (printf/malloc 내부도 락을 쓴다 — 여기서는 그 구조를 결정적으로 재현) */
#define _GNU_SOURCE
#include <pthread.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <sys/time.h>
#include <unistd.h>

static pthread_mutex_t log_lock = PTHREAD_MUTEX_INITIALIZER;  /* 비재귀 락 */
static char log_buf[4096];
static size_t log_len;

static void log_msg(const char *s)          /* malloc/printf와 같은 구조 */
{
    pthread_mutex_lock(&log_lock);
    size_t n = strlen(s);
    if (log_len + n >= sizeof log_buf) log_len = 0;
    memcpy(log_buf + log_len, s, n);
    log_len += n;
    pthread_mutex_unlock(&log_lock);
}

static volatile sig_atomic_t n_sig;
static void bad_handler(int sig)
{
    (void)sig;
    n_sig++;
    log_msg("tick\n");                      /* async-signal-safe 아님! */
}

int main(void)
{
    struct sigaction sa = { .sa_handler = bad_handler };
    sigemptyset(&sa.sa_mask);
    sigaction(SIGALRM, &sa, NULL);
    struct itimerval it = { { 0, 100 }, { 0, 100 } };    /* 100us마다 */
    setitimer(ITIMER_REAL, &it, NULL);

    for (unsigned long i = 0;; i++) {
        log_msg("main loop working on sensor frame\n");
        if (i % 1000000 == 0) {
            fprintf(stderr, "main alive: iter=%lu signals=%d\n", i, (int)n_sig);
        }
    }
}
```

### 5.2 안전한 패턴 1 — `volatile sig_atomic_t` 플래그

```c
static volatile sig_atomic_t stop;
static void on_term(int s) { (void)s; stop = 1; }   /* 할 일은 이것뿐 */
/* main: while (!stop) { ... } */
```

- `sig_atomic_t`: 시그널에 대해 **한 번에 읽고 쓰는 것이 보장되는** 정수형(찢어진 읽기 없음).
- `volatile`: 컴파일러가 루프 안에서 값을 레지스터에 캐시하지 못하게 한다. ISR 플래그에 `volatile`을 붙이던 것과 같다.
- C11 이후로는 lock-free `atomic_int`도 허용된다. 하지만 `sig_atomic_t`가 가장 이식성 있다.
- 한계: 메인이 `poll()`이나 `read()`에 **잠들어 있으면** 플래그를 확인할 기회가 없다. SA_RESTART면 read가 다시 잠들어 버린다. 이를 해결하는 게 다음 패턴들이다.

### 5.3 안전한 패턴 2 — self-pipe trick

handler는 pipe에 1바이트만 `write`(async-signal-safe)하고, 메인 루프는 그 pipe의 읽기 끝을 다른 fd들과 함께 `poll`한다. 시그널이 "읽을 수 있는 fd 이벤트"로 바뀐다. ISR이 RTOS 큐에 메시지 하나 넣고 끝내는 것과 같다.

### 예제 7 — self-pipe trick

무엇을 확인하나: SIGHUP(reload)과 SIGTERM(종료)을 handler가 pipe에 넣고, poll 루프가 일반 컨텍스트에서 처리한다.

```c
/* ex6: self-pipe trick — 핸들러는 1바이트만 쓰고, 진짜 일은 poll 루프에서 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <poll.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

static int sp[2];                               /* self-pipe */
static volatile sig_atomic_t got_term;          /* 플래그 패턴 */

static void h(int sig)
{
    int saved = errno;
    unsigned char b = (unsigned char)sig;
    if (sig == SIGTERM) got_term = 1;
    if (write(sp[1], &b, 1) < 0) { /* EAGAIN이면 이미 깨울 바이트가 있다 */ }
    errno = saved;
}

int main(void)
{
    if (pipe2(sp, O_NONBLOCK | O_CLOEXEC) < 0) { perror("pipe2"); exit(1); }
    struct sigaction sa = { .sa_handler = h, .sa_flags = SA_RESTART };
    sigemptyset(&sa.sa_mask);
    sigaction(SIGTERM, &sa, NULL);
    sigaction(SIGHUP, &sa, NULL);
    printf("pid=%d, poll 루프 시작 (sensor fd 대신 stdin)\n", getpid());
    fflush(stdout);

    struct pollfd pf[2] = { { .fd = sp[0], .events = POLLIN },
                            { .fd = 0,     .events = POLLIN } };
    while (!got_term) {
        int n = poll(pf, 2, -1);
        if (n < 0 && errno == EINTR) continue;   /* poll은 SA_RESTART와 무관하게 EINTR */
        if (n < 0) { perror("poll"); exit(1); }
        if (pf[0].revents & POLLIN) {
            unsigned char b;
            while (read(sp[0], &b, 1) == 1)      /* 일반 컨텍스트: printf 안전 */
                printf("loop: signal %d 처리 (%s)\n", b,
                       b == SIGHUP ? "설정 reload" : "종료 요청");
        }
        if (pf[1].revents & (POLLIN | POLLHUP)) {
            char buf[64];
            ssize_t r = read(0, buf, sizeof buf);
            if (r <= 0) break;
            printf("loop: stdin %zd bytes\n", r);
        }
        fflush(stdout);
    }
    printf("loop 탈출: got_term=%d → 정리 후 종료\n", (int)got_term);
    return 0;
}
```

## 6. signalfd + epoll — Linux 데몬의 표준 답

### 예제 8 — signalfd + timerfd + epoll 센서 데몬, 그리고 systemd stop

무엇을 확인하나: 200ms 주기 "센서 프레임"(timerfd)을 세는 데몬이 SIGHUP은 reload로, SIGTERM/SIGINT는 graceful shutdown으로 처리한다.

```c
/* ex7: signalfd + timerfd + epoll — 시그널을 "읽을 수 있는 fd"로 받는 데몬 */
#define _GNU_SOURCE
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <string.h>
#include <sys/epoll.h>
#include <sys/signalfd.h>
#include <sys/timerfd.h>
#include <unistd.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

int main(void)
{
    sigset_t m; sigemptyset(&m);
    sigaddset(&m, SIGTERM); sigaddset(&m, SIGINT); sigaddset(&m, SIGHUP);
    if (sigprocmask(SIG_BLOCK, &m, NULL) < 0) DIE("sigprocmask"); /* 필수! */
    int sfd = signalfd(-1, &m, SFD_CLOEXEC | SFD_NONBLOCK);
    if (sfd < 0) DIE("signalfd");

    int tfd = timerfd_create(CLOCK_MONOTONIC, TFD_CLOEXEC);      /* 센서 주기 */
    struct itimerspec its = { { 0, 200000000 }, { 0, 200000000 } };
    if (tfd < 0 || timerfd_settime(tfd, 0, &its, NULL) < 0) DIE("timerfd");

    int ep = epoll_create1(EPOLL_CLOEXEC);
    struct epoll_event e1 = { .events = EPOLLIN, .data.fd = sfd },
                       e2 = { .events = EPOLLIN, .data.fd = tfd };
    if (epoll_ctl(ep, EPOLL_CTL_ADD, sfd, &e1) || epoll_ctl(ep, EPOLL_CTL_ADD, tfd, &e2)) DIE("epoll_ctl");

    FILE *pf = fopen("/tmp/A6/sensord.pid", "w");
    if (!pf) DIE("pidfile");
    fprintf(pf, "%d\n", getpid()); fclose(pf);
    printf("sensord pid=%d start\n", getpid()); fflush(stdout);

    unsigned long frames = 0;
    for (int running = 1; running;) {
        struct epoll_event evs[4];
        int n = epoll_wait(ep, evs, 4, -1);
        if (n < 0) DIE("epoll_wait");
        for (int i = 0; i < n; i++) {
            if (evs[i].data.fd == tfd) {
                uint64_t exp;
                if (read(tfd, &exp, sizeof exp) == sizeof exp) frames += exp;
            } else {
                struct signalfd_siginfo si;
                while (read(sfd, &si, sizeof si) == sizeof si) {
                    printf("signal %s from pid %u (frames=%lu)\n",
                           sigabbrev_np(si.ssi_signo), si.ssi_pid, frames);
                    if (si.ssi_signo != SIGHUP) running = 0;  /* HUP=reload */
                }
            }
        }
        fflush(stdout);
    }
    /* graceful shutdown: 센서 끄기·버퍼 flush·pidfile 삭제 */
    unlink("/tmp/A6/sensord.pid");
    printf("cleanup done, exit 0\n");
    return 0;
}
```

### 6.2 signalfd 사용 규칙

1. **반드시 먼저 block** 한다. 안 막으면 기본 동작(SIGTERM이면 즉사)이 signalfd보다 먼저 일어난다.
2. 멀티스레드면 `pthread_create` **전에** main에서 block 해야 모든 스레드가 상속한다(7절). 한 스레드라도 안 막으면 커널이 그 스레드에 배달해 버린다.
3. 표준 시그널은 signalfd에서도 합쳐진다. `read`는 한 번에 여러 개의 `signalfd_siginfo`(각 128바이트)를 줄 수 있으니 루프로 다 읽는다.
4. **자식 exec 전 마스크 복원**: 막힌 마스크가 exec 후에도 유지되므로, `fork` 후 자식에서 `sigprocmask(SIG_UNBLOCK, ...)` 하거나 `posix_spawnattr_setsigmask`로 지정한다.
5. SIGSEGV 같은 동기 폴트는 block 해도 소용없다(막혀 있으면 커널이 강제로 기본 동작 → 사망). signalfd는 비동기 시그널 전용이다.

## 7. 시그널과 스레드

### 7.1 규칙 네 줄

1. **disposition(handler)은 프로세스 전체 공유**. 어느 스레드에서 `sigaction`해도 전체에 적용.
2. **마스크는 스레드마다**. 새 스레드는 만든 스레드의 마스크를 상속.
3. **process-directed 시그널**(`kill(pid)`)은 그 시그널을 막지 않은 스레드 **아무나 하나**가 받는다. 커널은 먼저 메인 스레드를 시도하고, 막혀 있으면 다른 스레드를 고른다.
4. **thread-directed 시그널**(`pthread_kill`, 그리고 SIGSEGV·SIGBUS·SIGFPE 같은 동기 폴트)은 그 스레드가 받는다. 기본 동작이 Term/Core면 **프로세스 전체**가 죽는다.

### 예제 9 — 누가 받나, 그리고 전용 sigwait 스레드

무엇을 확인하나: [A] 마스크 없이 kill과 pthread_kill이 어느 스레드로 가는지, [B] 모든 스레드가 막고 전용 스레드가 `sigwait`로 받는 패턴. 그리고 "막기 전에 만든 스레드"가 하나 있으면 어떻게 되는지.

```c
/* ex8: 멀티스레드에서 누가 시그널을 받나 + 전용 sigwait 스레드 패턴 */
#define _GNU_SOURCE
#include <pthread.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static volatile sig_atomic_t who;                 /* 핸들러가 돈 스레드 tid */
static void h(int sig) { (void)sig; who = gettid(); }

static void *worker(void *a)
{
    printf("  worker tid=%d (%s)\n", gettid(), (char *)a);
    for (;;) pause();
    return NULL;
}

static void *sig_thread(void *a)
{
    sigset_t *set = a;
    for (;;) {
        int sig;
        if (sigwait(set, &sig) != 0) { perror("sigwait"); exit(1); }
        printf("  sig_thread tid=%d: sigwait -> %s (일반 컨텍스트, printf OK)\n",
               gettid(), sigabbrev_np(sig));
        if (sig == SIGTERM) exit(0);
    }
}

int main(int argc, char **argv __attribute__((unused)))
{
    pthread_t t;
    setvbuf(stdout, NULL, _IOLBF, 0);
    printf("[A] 마스크 없이: main tid=%d\n", gettid());
    signal(SIGUSR1, h);
    pthread_create(&t, NULL, worker, "마스크 없음");
    sleep(1);
    kill(getpid(), SIGUSR1);  sleep(1);           /* process-directed */
    printf("  kill(pid)        → handler ran in tid=%d\n", (int)who);
    pthread_kill(t, SIGUSR1); sleep(1);           /* thread-directed */
    printf("  pthread_kill(t)  → handler ran in tid=%d\n", (int)who);

    if (argc > 1) {                  /* fix: 마스크 없는 옛 스레드 정리 */
        pthread_cancel(t); pthread_join(t, NULL);
    }
    printf("[B] 막고 나서 만든 스레드 + 전용 sigwait 스레드\n");
    static sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, SIGTERM); sigaddset(&set, SIGHUP);
    pthread_sigmask(SIG_BLOCK, &set, NULL);       /* 이후 생성 스레드에 상속 */
    pthread_create(&t, NULL, worker, "SIGTERM/HUP 막힘");
    pthread_create(&t, NULL, sig_thread, &set);
    sleep(1);
    kill(getpid(), SIGHUP);  sleep(1);
    kill(getpid(), SIGTERM); sleep(1);
    return 1;                                      /* 여기 오면 실패 */
}
```

출력에서 볼 것:

- [A]: `kill(pid)`는 main 스레드(tid=pid)가, `pthread_kill(t)`는 지정한 worker가 받았다.

`sigwait`(또는 `sigwaitinfo`, `sigtimedwait`)는 signalfd와 같은 원리(막아 두고 동기적으로 꺼내기)를 "스레드 하나를 바쳐서" 구현한 것이다. 스레드 기반 구조면 sigwait 스레드, 이벤트 루프 구조면 signalfd를 쓴다.

## 8. 코어 덤프 — SIGSEGV/SIGABRT의 사후 분석 (M9 미리보기)

Core 동작 시그널로 죽을 때 커널은 프로세스 메모리 이미지와 레지스터를 ELF 형식 **core 파일**로 쓴다. 조건:

- `RLIMIT_CORE`(셸 `ulimit -c`)가 0이 아니어야 한다. 대부분 배포판·systemd 서비스의 기본은 0 또는 제한적.
- `/proc/sys/kernel/core_pattern`이 파일 위치·이름을 정한다. `%e`(실행 파일 이름), `%p`(pid), `%t`(시각) 같은 지정자를 쓴다. 맨 앞이 파이프 기호면 커널이 core를 **프로그램의 stdin으로 넘긴다**(`systemd-coredump`, Ubuntu의 `apport`가 이 방식). 이 VM은 단순히 `core`이고 `core_uses_pid=1`이라 `core.<pid>`가 현재 디렉터리에 생긴다.
- setuid 프로그램 등은 `fs.suid_dumpable`에 따라 제한된다. 프로세스는 `prctl(PR_SET_DUMPABLE)`로 끌 수도 있다.

## 9. 시그널은 얼마나 비싼가 — 직접 재 보기

### 예제 11 — 송수신 1회 비용

무엇을 확인하나: 자기 자신에게 시그널을 보내고 받는 왕복 비용을 handler / `sigwaitinfo` / signalfd 방식으로 비교한다. 기준은 빈 syscall(`getppid`).

```c
/* ex13: 시그널 한 번 보내고 받는 비용 — 핸들러 vs sigwaitinfo vs signalfd */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <sys/signalfd.h>
#include <time.h>
#include <unistd.h>
#define N 200000

static volatile sig_atomic_t cnt;
static void h(int s) { (void)s; cnt++; }
static double ns(struct timespec a, struct timespec b)
{ return ((b.tv_sec - a.tv_sec) * 1e9 + (b.tv_nsec - a.tv_nsec)) / N; }

int main(void)
{
    struct timespec a, b;
    pid_t me = getpid();
    clock_gettime(CLOCK_MONOTONIC, &a);
    for (int i = 0; i < N; i++) getppid();               /* 기준: 빈 syscall */
    clock_gettime(CLOCK_MONOTONIC, &b);
    printf("getppid() syscall      : %6.0f ns\n", ns(a, b));

    signal(SIGUSR1, h);
    clock_gettime(CLOCK_MONOTONIC, &a);
    for (int i = 0; i < N; i++) kill(me, SIGUSR1);       /* 핸들러 실행 */
    clock_gettime(CLOCK_MONOTONIC, &b);
    printf("kill + handler         : %6.0f ns (cnt=%d)\n", ns(a, b), (int)cnt);

    sigset_t m; sigemptyset(&m); sigaddset(&m, SIGUSR1);
    sigprocmask(SIG_BLOCK, &m, NULL);
    clock_gettime(CLOCK_MONOTONIC, &a);
    for (int i = 0; i < N; i++) { kill(me, SIGUSR1); sigwaitinfo(&m, NULL); }
    clock_gettime(CLOCK_MONOTONIC, &b);
    printf("kill + sigwaitinfo     : %6.0f ns\n", ns(a, b));

    int sfd = signalfd(-1, &m, 0);
    struct signalfd_siginfo si;
    clock_gettime(CLOCK_MONOTONIC, &a);
    for (int i = 0; i < N; i++) {
        kill(me, SIGUSR1);
        if (read(sfd, &si, sizeof si) != sizeof si) return 1;
    }
    clock_gettime(CLOCK_MONOTONIC, &b);
    printf("kill + signalfd read   : %6.0f ns\n", ns(a, b));
    return 0;
}
```

## 10. 커널 안에서는 무슨 일이 일어나나

### 10.1 자료구조

| 구조체·필드 | 무엇 | 메모 |
|---|---|---|
| `task_struct->pending` | 스레드 전용 pending (`struct sigpending`: 비트맵 + `sigqueue` 리스트) | `/proc`의 `SigPnd` |
| `task_struct->signal->shared_pending` | 스레드 그룹 공유 pending | `ShdPnd`. `signal_struct`는 그룹 공유 |
| `task_struct->blocked` | 스레드의 마스크 | `SigBlk` |
| `task_struct->sighand->action[]` | 시그널별 `k_sigaction` (handler, flags, mask) | `SigIgn`/`SigCgt`. `sighand_struct`는 스레드 간 공유 |
| `TIF_SIGPENDING` | thread_info 플래그 | "유저로 돌아가기 전에 시그널 확인하라" 표시 |
| `struct sigqueue` | `siginfo` 한 건 | RT 시그널 큐잉, `SigQ` 카운트 |

### 10.2 보내는 경로 (6.x 기준 이름)

`kill()` → `kill_something_info()` → `kill_pid_info()` → `group_send_sig_info()` → `do_send_sig_info()` → `send_signal_locked()` → `__send_signal_locked()`. 여기서:

1. `prepare_signal()`: SIGCONT/SIGSTOP 계열 정리, 무시될 시그널이면 여기서 버림.
2. `legacy_queue()`: 표준 시그널이 **이미 pending이면 버림** (예제 5의 "3번 보냈는데 1번").
3. `sigqueue` 할당 + 비트 세팅.
4. `complete_signal()`: 받을 스레드 선택(`wants_signal()`), 그리고 **기본 동작이 치명적이면 그룹의 모든 스레드에 SIGKILL을 세팅**(그래서 예제 13에서 SIGTERM이 TASK_KILLABLE 잠을 깨웠다).
5. `signal_wake_up()`: `TIF_SIGPENDING` 세팅 + 대상이 TASK_INTERRUPTIBLE(치명적이면 TASK_WAKEKILL 포함)로 자고 있으면 깨움. 다른 CPU에서 유저 코드를 돌고 있으면 IPI로 커널에 한 번 들어오게 만든다(`kick_process`).

진입 함수 이름은 아키텍처·버전마다 다르다(x86 등 generic entry를 쓰는 아키텍처는 `exit_to_user_mode_loop()` → `arch_do_signal_or_restart()`, arm64는 오랫동안 `do_notify_resume()` → `do_signal()`이었고 generic entry로 옮겨 가는 중이다). 구조 — "TIF 플래그 보고 → `get_signal()` → `handle_signal()` → `setup_rt_frame()`" — 는 같다. arm64 구현은 `arch/arm64/kernel/signal.c`에 있고, syscall 재시작 처리는 `do_signal()`에서 반환값이 `-ERESTARTSYS`/`-ERESTARTNOINTR`/`-ERESTARTNOHAND`/`-ERESTART_RESTARTBLOCK`인지 보고 `x0`를 `orig_x0`로 되돌리고 PC를 4바이트(svc 명령 하나) 뒤로 돌리는 방식이다.

Bare-metal로 번역하면: Cortex-M이 예외 진입 때 하드웨어로 스택에 R0-R3, R12, LR, PC, xPSR을 쌓고 EXC_RETURN으로 돌아오는 것을, **커널이 소프트웨어로 유저 스택에 해 주는 것**이다. 그 "EXC_RETURN"에 해당하는 것이 `rt_sigreturn`이다.

### 예제 12 — 신호 프레임과 rt_sigreturn을 직접 보기

무엇을 확인하나: handler의 `ucontext_t`에서 "끊긴 순간의 PC/SP"를 꺼내고, handler 지역 변수가 그 SP보다 얼마나 아래에 있는지 본다. strace로 `rt_sigreturn`도 확인한다.

```c
/* ex12: 시그널 프레임 들여다보기 — 핸들러는 유저 스택 위에 만든 프레임에서 돈다 */
#define _GNU_SOURCE
#include <dlfcn.h>
#include <signal.h>
#include <stdio.h>
#include <ucontext.h>
#include <unistd.h>

static volatile unsigned long saved_pc, saved_sp, handler_local;

static void h(int sig, siginfo_t *si, void *uc_)
{
    ucontext_t *uc = uc_;
    volatile int here;
    (void)sig; (void)si;
    saved_pc = uc->uc_mcontext.pc;       /* 끊긴 지점의 PC (aarch64) */
    saved_sp = uc->uc_mcontext.sp;       /* 끊긴 지점의 SP */
    handler_local = (unsigned long)&here;
    static const char m[] = "in handler\n";
    if (write(1, m, sizeof m - 1) < 0) _exit(1);
}

int main(void)
{
    struct sigaction sa = { .sa_sigaction = h, .sa_flags = SA_SIGINFO };
    sigemptyset(&sa.sa_mask);
    sigaction(SIGUSR1, &sa, NULL);
    volatile int main_local;
    kill(getpid(), SIGUSR1);
    printf("main local      = %p\n", (void *)&main_local);
    printf("interrupted SP  = 0x%lx\n", saved_sp);
    printf("handler local   = 0x%lx  (SP보다 %lu 바이트 아래)\n",
           handler_local, saved_sp - handler_local);
    Dl_info di;
    if (dladdr((void *)saved_pc, &di) && di.dli_sname)
        printf("interrupted PC  = 0x%lx  (%s+0x%lx in %s)\n", saved_pc, di.dli_sname,
               saved_pc - (unsigned long)di.dli_saddr, di.dli_fname);
    printf("sizeof(ucontext_t)=%zu\n", sizeof(ucontext_t));
    return 0;
}
```

### 예제 13 — 유저 공간만으로 D 상태 만들기: vfork 부모

무엇을 확인하나: `vfork()`의 부모는 자식이 exec/_exit 할 때까지 커널에서 **TASK_KILLABLE**로 잔다. SIGTERM에 handler가 있으면/없으면 어떻게 다른가.

```c
/* ex9: D 상태(uninterruptible) 관찰 — vfork 부모는 TASK_KILLABLE로 잔다 */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

static void on_term(int s) { (void)s; }    /* 핸들러가 있으면 SIGTERM은 "치명적"이 아니다 */

int main(int argc, char **argv __attribute__((unused)))
{
    if (argc > 1) signal(SIGTERM, on_term);
    printf("parent pid=%d\n", getpid());
    fflush(stdout);
    pid_t pid = vfork();          /* 자식이 exec/_exit 할 때까지 부모는 커널에서 대기 */
    if (pid < 0) { perror("vfork"); exit(1); }
    if (pid == 0) {
        sleep(30);                /* 데모용: 원래 vfork 자식은 exec/_exit만 해야 한다 */
        _exit(0);
    }
    printf("parent resumed (child=%d)\n", pid);
    return 0;
}
```

### 예제 14 — 드라이버가 잠드는 방식을 바꿔 보기 (작은 커널 모듈)

무엇을 확인하나: `read()`에서 5초간 잠드는 misc 드라이버. module parameter `mode`로 UNINTERRUPTIBLE / INTERRUPTIBLE / KILLABLE을 바꾸고 `cat /dev/a6sleep`을 `kill -9` 했을 때 몇 초 만에 죽는지 잰다. 드라이버 문법은 G·F 모듈에서 자세히 배우고, 여기서는 "드라이버의 선택이 유저의 kill에 직결된다"만 본다.

```c
// ex10: read()에서 5초 잠드는 misc 드라이버 — 잠드는 방식(mode)에 따라 kill이 먹는지 본다
#include <linux/module.h>
#include <linux/miscdevice.h>
#include <linux/fs.h>
#include <linux/wait.h>
#include <linux/sched.h>

static int mode;              /* 0=UNINTERRUPTIBLE 1=INTERRUPTIBLE 2=KILLABLE */
module_param(mode, int, 0644);
static DECLARE_WAIT_QUEUE_HEAD(wq);
static int never;             /* 아무도 깨우지 않는 조건 → timeout까지 잔다 */

static ssize_t a6_read(struct file *f, char __user *buf, size_t len, loff_t *off)
{
	long ret;

	switch (mode) {
	case 0:
		ret = wait_event_timeout(wq, never, 5 * HZ);            /* D */
		break;
	case 1:
		ret = wait_event_interruptible_timeout(wq, never, 5 * HZ); /* S */
		break;
	default:
		ret = wait_event_killable(wq, never);                   /* D, 단 SIGKILL OK */
		break;
	}
	pr_info("a6sleep: mode=%d read woke, ret=%ld, pending=%d fatal=%d\n",
		mode, ret, signal_pending(current), fatal_signal_pending(current));
	if (ret == -ERESTARTSYS || (mode == 1 && signal_pending(current)))
		return -ERESTARTSYS;  /* 시그널로 깼다 → 커널이 EINTR 또는 restart로 바꿈 */
	return 0;                 /* EOF */
}

static const struct file_operations a6_fops = {
	.owner = THIS_MODULE,
	.read  = a6_read,
};
static struct miscdevice a6_dev = {
	.minor = MISC_DYNAMIC_MINOR, .name = "a6sleep", .fops = &a6_fops, .mode = 0666,
};
module_misc_device(a6_dev);
MODULE_DESCRIPTION("A6 demo: sleep modes vs signals");
MODULE_LICENSE("GPL");
```

## 11. Embedded 실무에서 다시 보기

### 11.1 센서 데몬의 graceful shutdown 체크리스트

SIGTERM을 받은 sensord가 해야 할 일 — 순서가 중요하다.

1. 새 작업 받기 중단 (epoll에서 소켓 제거, 리스닝 소켓 close).
2. 하드웨어를 **안전 상태로**: IMU를 sleep 모드로, 모터 컨트롤러에 CAN으로 정지 명령, 카메라 스트리밍 `VIDIOC_STREAMOFF`.
3. 버퍼 flush: 로그 파일 `fsync`, 마지막 프레임 저장.
4. 리소스 정리: pidfile 삭제, 공유 메모리 `shm_unlink`.
5. `exit(0)`. 전체가 systemd `TimeoutStopSec` 안에 끝나야 한다. 오래 걸릴 수 있으면 `sd_notify("EXTEND_TIMEOUT_USEC=...")`로 연장을 요청하거나 유닛 설정을 늘린다.

이 모든 일을 handler 안에서 하면 안 된다(5절). 예제 8의 signalfd 루프처럼 **루프를 빠져나온 뒤 일반 코드에서** 한다.

### 11.2 SIGPIPE로 조용히 죽는 텔레메트리 업로더

LiDAR 포인트를 TCP로 지상국에 보내는 업로더가 가끔 로그 한 줄 없이 사라진다면 십중팔구 SIGPIPE다. 상대가 연결을 끊은 뒤 `write()`하면 기본 동작 Term으로 즉사한다(셸에서는 exit 141 = 128+13). 고치는 법:

```c
signal(SIGPIPE, SIG_IGN);                 /* 프로세스 전체: write가 -1/EPIPE 반환 */
send(sock, buf, len, MSG_NOSIGNAL);       /* 또는 소켓 호출마다 */
```

그리고 EPIPE를 받으면 재연결 로직으로 간다. systemd 서비스는 기본으로 `IgnoreSIGPIPE=yes`라 서비스로 돌릴 때는 안 죽고, 개발자가 터미널에서 돌릴 때만 죽어서 "재현이 안 되는" 버그가 되기도 한다.

### 11.3 SIGCHLD와 좀비 — 하위 프로세스를 띄우는 매니저

카메라 파이프라인 매니저가 `gst-launch`나 펌웨어 업데이트 스크립트를 fork/exec 한다면 자식이 끝날 때마다 SIGCHLD가 온다. `waitpid()`로 회수하지 않으면 좀비가 쌓인다(A2). signalfd 루프라면 SIGCHLD도 막아서 signalfd에 넣고, 이벤트가 오면 `while (waitpid(-1, &st, WNOHANG) > 0)`으로 **여러 개를 한꺼번에** 회수한다(표준 시그널은 합쳐지므로 SIGCHLD 1번이 자식 여러 개의 종료일 수 있다). 자식 종료 코드가 필요 없다면 `SIGCHLD`를 `SIG_IGN`으로 두면 커널이 자동 회수한다. 최신 대안은 `pidfd_open()`으로 자식마다 fd를 받아 epoll에 넣는 것이다.

### 11.4 SIGBUS로 죽는 카메라 앱

V4L2 버퍼를 mmap 해서 쓰는 앱이, 다른 스레드가 `VIDIOC_REQBUFS(count=0)`로 버퍼를 해제하거나 USB 카메라가 뽑힌 뒤에도 옛 포인터를 읽으면 SIGBUS나 SIGSEGV를 받는다. core의 `si_addr`(gdb `p $_siginfo`)가 mmap 범위 안이면 "매핑 수명 관리 버그"를 의심한다.

## 13. 면접에서 이렇게 말한다

**Q.** What happens when you press Ctrl-C in a terminal running your program?

**A.** 터미널 드라이버(tty line discipline)가 Ctrl-C 문자를 보고 foreground 프로세스 그룹 전체에 SIGINT를 보낸다. 커널은 각 프로세스의 pending에 SIGINT를 세우고 TIF_SIGPENDING을 켠 뒤 잠들어 있으면 깨운다. 프로세스가 유저로 돌아가는 순간 handler가 있으면 신호 프레임을 쌓아 handler를 실행하고, 없으면 기본 동작인 종료가 일어난다.

> The tty line discipline sees the interrupt character and sends SIGINT to the whole foreground process group. The kernel marks it pending, sets TIF_SIGPENDING and wakes the task if it's in an interruptible sleep. On the next return to user space, the kernel either runs the default action, which is terminate, or builds a signal frame on the user stack and jumps to the registered handler, which returns through rt_sigreturn.

**꼬리 질문**: 백그라운드 작업은 왜 Ctrl-C에 안 죽나? → foreground 프로세스 그룹에만 보내기 때문.

**Q.** Can you call printf or malloc inside a signal handler? Why not?

**A.** 안 된다. async-signal-safe가 아니기 때문이다. handler는 메인 코드의 임의 지점에 끼어드는데, 메인이 malloc이나 stdio 안에서 락을 쥔 순간이면 handler가 같은 락을 다시 잡으려다 자기 자신과 교착하거나 내부 자료구조를 깨뜨린다. 그래서 handler에서는 `volatile sig_atomic_t` 플래그를 세우거나 `write()`로 self-pipe에 1바이트 쓰는 정도만 하고, 실제 일은 메인 루프에서 한다. Linux에서는 아예 시그널을 막고 signalfd로 이벤트 루프에서 읽는 게 가장 깔끔하다. 실제로 mutex를 쓰는 로깅 함수를 handler에서 불러 gdb로 `<signal handler called>` 위에서 futex 대기하는 self-deadlock을 재현해 봤다.

> No. They're not async-signal-safe. A handler can interrupt the main flow at any instruction, so if the main code is inside malloc holding the arena lock, the handler's malloc tries to take the same non-recursive lock on the same thread and deadlocks, or corrupts internal state. Handlers should only set a volatile sig_atomic_t flag or write a byte to a self-pipe. On Linux my preference is to block the signals and read them from a signalfd in the epoll loop, so there's no handler at all. It's the same discipline as keeping ISRs short and deferring work to the main loop in firmware.

**Q.** Why can't you catch SIGKILL, and why does `kill -9` sometimes not kill a process?

**A.** SIGKILL과 SIGSTOP은 커널이 프로세스를 확실히 통제하기 위한 수단이라 handler 등록·block·무시가 모두 거부된다. 그런데 SIGKILL도 "pending 비트 + 깨우기"이고, 실제 종료는 그 스레드가 커널을 빠져나오며 `get_signal()`을 지날 때 일어난다. 드라이버나 파일시스템이 TASK_UNINTERRUPTIBLE로 자고 있으면(ps의 D) 시그널로 깨지 않으니 조건이 만족될 때까지 안 죽는다. 그래서 드라이버는 `wait_event_interruptible`이나 최소한 `wait_event_killable`을 써야 한다. 직접 모듈을 만들어 재 보니 uninterruptible은 타임아웃 5초가 끝나서야 죽고, killable은 즉시 죽었다.

> SIGKILL and SIGSTOP are reserved so the kernel can always control a process; sigaction refuses to install handlers or block them. But SIGKILL is still just a pending bit plus a wakeup, and the actual exit happens when the task passes through get_signal on its way back to user space. If a driver puts the task in TASK_UNINTERRUPTIBLE, the D state, the signal can't wake it, so it only dies once the wait condition is met. That's why drivers should use wait_event_interruptible, or at least wait_event_killable, and return -ERESTARTSYS.

**Q.** How are signals delivered in a multithreaded process?

**A.** handler(disposition)는 프로세스 공유, 마스크는 스레드별이다. `kill(pid)`처럼 프로세스로 온 시그널은 막지 않은 스레드 중 하나가 받고, `pthread_kill`이나 SIGSEGV 같은 동기 폴트는 해당 스레드가 받는다. 그래서 패턴은 main 시작 직후 모든 스레드를 만들기 전에 `pthread_sigmask`로 막아 두고, 전용 스레드에서 `sigwait`하거나 signalfd로 읽는 것이다. 막기 전에 만든 스레드가 하나라도 있으면 그쪽으로 배달돼 기본 동작으로 프로세스가 죽는 것을 실험으로 확인했다.

> Dispositions are process-wide, masks are per thread. A process-directed signal goes to any one thread that doesn't block it; thread-directed signals and synchronous faults go to the specific thread. The robust pattern is to block the signals in main before creating any threads, so every thread inherits the mask, and then have one dedicated thread call sigwait, or read a signalfd in the event loop.

**Q.** What is EINTR and how does SA_RESTART relate to it?

**A.** blocking syscall 중에 handler가 실행되면 그 syscall은 중단된다. 드라이버나 커널은 `-ERESTARTSYS`를 돌려주고, handler에 SA_RESTART가 있으면 커널이 PC를 되돌려 syscall을 다시 실행하고, 없으면 유저에게 -1/EINTR를 준다. 다만 poll, select, epoll_wait, nanosleep 같은 것은 SA_RESTART와 무관하게 EINTR를 준다. 그래서 견고한 코드는 항상 EINTR를 재시도하고 부분 읽기·쓰기도 루프로 처리한다.

> If a handler runs while a thread is blocked in a syscall, the kernel side returns -ERESTARTSYS. If the handler was installed with SA_RESTART the kernel rewinds the PC and re-executes the syscall; otherwise user space sees -1 with EINTR. Some calls, like poll, epoll_wait and nanosleep, are never restarted. So robust I/O loops always retry on EINTR and handle short reads and writes.

**Q.** Standard signals vs real-time signals?

**A.** 표준 시그널(1~31)은 pending 비트 하나라서 막혀 있는 동안 여러 번 와도 한 번으로 합쳐지고, 값을 실을 수 없다. RT 시그널(SIGRTMIN~SIGRTMAX)은 보낸 만큼 큐잉되고 `sigqueue`로 정수나 포인터 값을 실을 수 있으며 번호가 낮은 것부터 배달된다. 큐 길이는 `RLIMIT_SIGPENDING`으로 제한된다.

> Standard signals are a single pending bit each, so multiple instances collapse into one and carry no payload. Real-time signals are queued, one entry per send, can carry a value via sigqueue, and are delivered lowest number first. The queue is bounded by RLIMIT_SIGPENDING.

**Q.** How would you implement graceful shutdown for an embedded Linux daemon under systemd?

**A.** systemd는 stop 시 SIGTERM을 보내고 TimeoutStopSec(기본 90초) 후 SIGKILL을 보낸다. 데몬은 시작하자마자 SIGTERM/SIGINT/SIGHUP을 막고 signalfd를 epoll 루프에 넣는다. SIGTERM이 오면 루프를 빠져나와 일반 코드에서 하드웨어를 안전 상태로 두고, 버퍼를 flush 하고, 리소스를 정리한 뒤 exit 0 한다. SIGHUP은 설정 reload로 쓴다. 자식을 띄울 때는 막아 둔 마스크를 풀어 준다.

> systemd sends SIGTERM, waits TimeoutStopSec, then SIGKILL. I block TERM, INT and HUP at startup, add a signalfd to the epoll loop, and on SIGTERM leave the loop, put the hardware in a safe state — stop streaming, park motors — flush and fsync, remove the pidfile and exit zero. HUP triggers a config reload. And before exec'ing children I restore the signal mask, since it's inherited.

**Q.** How does the kernel actually invoke a user-space handler?

**A.** 유저 복귀 직전 TIF_SIGPENDING을 보고 `get_signal()`로 하나를 꺼낸다. handler가 있으면 `setup_rt_frame()`이 유저 스택에 siginfo와 ucontext(레지스터 전체, 이전 마스크, FP 상태)를 저장하고, PC를 handler로, 인자 레지스터를 signo/siginfo/ucontext로, 링크 레지스터를 restorer로 바꿔서 eret 한다. handler가 리턴하면 restorer가 `rt_sigreturn`을 호출하고 커널이 프레임에서 레지스터와 마스크를 복원한다. 하드웨어 예외 진입 때의 스택 프레임과 EXC_RETURN을 소프트웨어로 흉내 내는 것이다.

> On the way back to user space the kernel sees TIF_SIGPENDING, dequeues a signal in get_signal, and if there's a handler, setup_rt_frame pushes siginfo and a ucontext — all registers, the old mask and FP state — onto the user stack, then sets PC to the handler, x0 to x2 to the arguments and the link register to the restorer, and erets. When the handler returns, the restorer calls rt_sigreturn and the kernel restores everything from that frame. It's basically a software version of exception stacking and EXC_RETURN.

## 15. 용어 사전

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| signal | 시그널 | 커널이 프로세스·스레드에게 번호 하나로 알리는 비동기 이벤트 |
| disposition | 처리 방식 | 시그널마다 SIG_DFL·SIG_IGN·handler 중 하나. 프로세스 공유 |
| default action | 기본 동작 | Term, Core, Ign, Stop, Cont |
| pending | 대기 중 | 도착했지만 아직 배달 안 된 상태. SigPnd(스레드)·ShdPnd(공유) |
| blocked mask | 블록 마스크 | 배달을 미룰 시그널 집합. 스레드별. SigBlk |
| process-directed | 프로세스 지정 | `kill(pid)` — 막지 않은 아무 스레드가 받음 |
| thread-directed | 스레드 지정 | `pthread_kill`, 동기 폴트 — 그 스레드가 받음 |
| SA_RESTART | 재시작 플래그 | handler 후 중단된 syscall을 커널이 다시 실행 |
| EINTR | 중단 에러 | syscall이 시그널 때문에 중단되었음을 알리는 errno |
| SA_SIGINFO | 상세정보 플래그 | handler가 `siginfo_t`와 `ucontext`를 받음 |
| async-signal-safe | 시그널 안전 | handler에서 불러도 되는 함수 성질 (`man 7 signal-safety`) |
| sig_atomic_t | 원자 정수형 | 시그널과 메인 사이에서 찢어지지 않고 읽고 쓰는 정수 |
| self-pipe trick | 셀프 파이프 | handler가 pipe에 1바이트를 써서 poll 루프를 깨우는 기법 |
| signalfd | 시그널 fd | 막아 둔 시그널을 read로 꺼내는 fd. epoll에 넣을 수 있음 |
| sigwait | 동기 대기 | 막아 둔 시그널을 스레드가 동기적으로 기다려 꺼냄 |
| real-time signal | 실시간 시그널 | SIGRTMIN~SIGRTMAX. 큐잉되고 값 전달 가능 |
| core dump | 코어 덤프 | 크래시 순간 메모리·레지스터를 ELF 파일로 저장 |
| core_pattern | 코어 경로 규칙 | core 파일 위치·이름 또는 수신 프로그램 지정 |
| TIF_SIGPENDING | 시그널 대기 플래그 | "유저 복귀 전에 시그널 확인" 표시 |
| rt_sigframe | 신호 프레임 | handler 호출을 위해 커널이 유저 스택에 쌓는 구조체 |
| rt_sigreturn | 시그널 복귀 syscall | 프레임에서 레지스터·마스크를 복원 |
| -ERESTARTSYS | 재시작 요청 | 드라이버가 "시그널로 깼다"고 알리는 커널 내부 반환값 |
| TASK_KILLABLE | 죽일 수 있는 D | 치명적 시그널에만 깨는 잠 |
| D state | 깨울 수 없는 잠 | TASK_UNINTERRUPTIBLE(또는 KILLABLE). ps의 D |

## 16. 요약 & 체크리스트

시그널은 커널이 프로세스의 pending 집합에 번호를 세우고, 그 스레드가 커널에서 유저로 돌아가는 순간 기본 동작이나 handler를 실행하게 하는 "유저 프로세스용 가상 인터럽트"다. NVIC처럼 pending·마스크·벡터 테이블 구조를 갖지만, 배달은 커널 복귀 시점에만 일어나고 handler는 같은 유저 스택에서 돈다. 그래서 handler 안에서는 async-signal-safe 함수만 써야 하고, 실무 데몬은 시그널을 막아 두고 signalfd를 epoll 루프에 넣어 일반 코드에서 처리한다. SA_RESTART·EINTR는 드라이버의 `-ERESTARTSYS`에서 시작하며, 드라이버가 TASK_UNINTERRUPTIBLE로 자면 SIGKILL조차 처리되지 않는다. 시그널 왕복은 수백 ns로 비싸므로 데이터 알림이 아니라 수명 제어와 치명적 오류 보고에 쓴다.

- [ ] 시그널과 하드웨어 IRQ의 공통점 3개, 차이점 3개를 설명할 수 있다
- [ ] SIGTERM·SIGKILL·SIGINT·SIGHUP·SIGCHLD·SIGPIPE·SIGSEGV·SIGBUS의 기본 동작과 실무 의미를 말할 수 있다
- [ ] mmap 파일 truncate로 SIGBUS가 나는 이유를 SIGSEGV와 구분해 설명할 수 있다
- [ ] `sigaction`으로 handler를 등록하고 `sa_mask`·SA_RESTART·SA_SIGINFO를 올바르게 쓸 수 있다
- [ ] EINTR가 왜 생기고 어떤 syscall은 SA_RESTART로도 재시작되지 않는지 설명할 수 있다
- [ ] `/proc/<pid>/status`의 SigPnd·ShdPnd·SigBlk·SigIgn·SigCgt를 해독할 수 있다
- [ ] handler에서 printf/malloc이 왜 교착을 만드는지 설명하고 flag·self-pipe 패턴을 짤 수 있다
- [ ] signalfd + epoll로 graceful shutdown 하는 데몬을 짤 수 있다
- [ ] 멀티스레드에서 시그널이 어느 스레드로 가는지, 전용 sigwait 스레드 패턴을 설명할 수 있다
- [ ] core_pattern·ulimit -c를 설정하고 gdb로 core를 읽을 수 있다
- [ ] 커널이 신호 프레임을 쌓고 rt_sigreturn으로 복원하는 과정을 설명할 수 있다
- [ ] D 상태 프로세스가 kill -9에 안 죽는 이유와 드라이버에서 interruptible/killable 대기를 써야 하는 이유를 말할 수 있다
