# A9. 네트워크 소켓 — LiDAR UDP, 원격 툴 TCP, CAN, netlink가 전부 같은 "socket fd"다

> **이 노트를 다 읽으면**: TCP 서버/클라이언트와 UDP 수신기를 직접 짜고 `ss`·`tcpdump`로 상태를 읽을 수 있다 · 스트림 프레이밍과 UDP 손실(SO_RCVBUF, RcvbufErrors)을 측정으로 설명할 수 있다 · SocketCAN·AF_PACKET·netlink(uevent)가 같은 소켓 API라는 것을 코드로 보일 수 있다 · `socket()`에서 `net_device` 드라이버까지 커널 경로를 그릴 수 있다
> **왜 필요한가**: "LiDAR 패킷이 가끔 빠진다", "CAN 모터 명령을 어떻게 보내나", "서버 재시작하면 bind가 실패한다"는 Embedded Linux 현장과 면접의 단골 장면이다
> **Don 기준 난이도**: 바이트 순서·링버퍼·DMA·패킷 개념은 이미 안다 / BSD 소켓 API, TCP 상태 머신, 커널 네트워크 스택(sk_buff, NAPI), netlink는 새로 배운다
> **선행 노트**: A1(fd, VFS), A3(blocking vs non-blocking), A4(epoll), A7(UNIX 소켓)

## 0. 큰 그림 — 이게 왜 필요한가

센서 키트를 Linux SoC(i.MX8, AM62, Jetson Orin)에 올린다고 하자. 데이터가 들어오고 나가는 길을 세어 보면 이렇다.

- LiDAR는 이더넷으로 초당 수천~수만 개의 **UDP** 패킷을 쏜다.
- 원격 진단 툴, ROS 노드, 웹 설정 페이지는 **TCP**로 붙는다.
- 모터 컨트롤러·BMS는 **CAN** 버스에 있다. Linux에서는 이것도 **소켓**(SocketCAN)으로 다룬다.
- `ip link set can0 up` 같은 설정, 장치 hotplug 알림(udev)은 **netlink 소켓**으로 커널과 대화한다.
- 같은 보드 안의 서비스끼리는 **UNIX 도메인 소켓**(A7)을 쓴다.
- 배선 문제를 볼 때는 `tcpdump`가 **AF_PACKET 소켓**으로 이더넷 프레임을 통째로 받는다.

즉 "소켓"은 TCP/IP 전용 API가 아니라, **"커널 안의 어떤 통신 엔드포인트를 fd 하나로 잡는 범용 손잡이"**다. 손잡이 모양(`socket()`, `bind()`, `send()`, `recv()`, `epoll`)은 같고, 첫 인자 address family(`AF_...`)만 바꾸면 반대편이 IP 스택이 되기도, CAN 코어가 되기도, 커널 자신이 되기도 한다.

## 1. 소켓도 fd다

### 1.1 직관

A1에서 fd는 "커널이 들고 있는 핸들 테이블의 인덱스"라고 했다. 소켓도 똑같다. `socket()`이 돌려주는 정수는 `open()`이 돌려주는 정수와 같은 테이블에 들어간다. 그래서 소켓에 `read()`·`write()`·`close()`·`epoll`이 그대로 된다. 차이는 그 fd 뒤의 `struct file`이 디스크 inode가 아니라 `struct socket`을 가리킨다는 것뿐이다.

### 1.2 정의

```c
int socket(int domain, int type, int protocol);
```

- `domain` (address family): `AF_INET`(IPv4), `AF_INET6`, `AF_UNIX`, `AF_PACKET`, `AF_CAN`, `AF_NETLINK` …
- `type`: `SOCK_STREAM`(연결형 바이트 스트림), `SOCK_DGRAM`(메시지 단위), `SOCK_RAW`(프로토콜 헤더까지 직접), `SOCK_SEQPACKET`(연결형 + 메시지 경계)
- `protocol`: 보통 0(기본값). raw 계열에서는 의미가 있다(`CAN_RAW`, `NETLINK_ROUTE`, `htons(ETH_P_ALL)`).

`AF_`와 `PF_`(protocol family)는 Linux에서 같은 값이다. 둘 다 보게 된다.

### 1.3 예제 1 — 여러 family의 소켓을 만들고 /proc에서 보기

무엇을 확인하는가: address family가 달라도 결과는 모두 같은 종류의 fd이고, `/proc/self/fd`에 `socket:[inode]`로 보인다는 것.

```c
// ex1: 소켓도 fd다 — 여러 address family 소켓을 만들고 /proc/self/fd 로 확인
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/stat.h>
#include <netinet/in.h>
#include <linux/if_packet.h>
#include <linux/can.h>
#include <linux/netlink.h>

static int mk(const char *name, int dom, int type, int proto) {
    int fd = socket(dom, type, proto);
    if (fd < 0) { perror(name); return -1; }
    struct stat st;
    if (fstat(fd, &st) < 0) { perror("fstat"); exit(1); }
    char path[64], link[128];
    snprintf(path, sizeof path, "/proc/self/fd/%d", fd);
    ssize_t n = readlink(path, link, sizeof link - 1);
    if (n < 0) { perror("readlink"); exit(1); }
    link[n] = '\0';
    printf("%-22s fd=%d S_ISSOCK=%d -> %s\n", name, fd, S_ISSOCK(st.st_mode), link);
    return fd;
}

int main(void) {
    mk("AF_INET  SOCK_STREAM", AF_INET, SOCK_STREAM, 0);
    mk("AF_INET  SOCK_DGRAM", AF_INET, SOCK_DGRAM, 0);
    mk("AF_INET6 SOCK_STREAM", AF_INET6, SOCK_STREAM, 0);
    mk("AF_UNIX  SOCK_STREAM", AF_UNIX, SOCK_STREAM, 0);
    mk("AF_NETLINK ROUTE", AF_NETLINK, SOCK_RAW, NETLINK_ROUTE);
    mk("AF_CAN   CAN_RAW", AF_CAN, SOCK_RAW, CAN_RAW);
    mk("AF_PACKET SOCK_RAW", AF_PACKET, SOCK_RAW, htons(0x0003));
    return 0;
}
```

```sh
sudo ./ex1 | tail -1
```

출력에서 볼 것: 6개 family 모두 fd 3, 4, 5 …로 순서대로 붙고 `S_ISSOCK`이 1이다. 숫자 `[80298]`은 sockfs라는 가상 파일시스템의 inode 번호다(값은 실행마다 다르다). `AF_PACKET`만 일반 사용자에게 막혀 있다. 이더넷 프레임을 통째로 엿볼 수 있으니 `CAP_NET_RAW` 권한이 필요하다. `AF_CAN` 소켓은 `can_raw` 모듈이 없으면 커널이 자동으로 로드한다(`can-proto-1` alias).

### 1.4 함정

- 소켓 fd도 `fork()`/`exec()`에서 상속된다. 데몬이 자식 프로세스를 띄울 때 리스닝 소켓이 새어 나가지 않게 `SOCK_CLOEXEC`를 type에 OR한다.
- `lseek()`은 소켓에서 `ESPIPE`로 실패한다. 파일처럼 보이지만 위치 개념이 없다.

## 2. TCP — 서버와 클라이언트의 수명주기

### 2.1 직관

TCP는 **"양쪽이 합의한 신뢰성 있는 바이트 파이프"**다. 순서 보장, 재전송, 흐름 제어를 커널이 다 해 준다. 대신 시작(3-way handshake)과 끝(FIN 교환)이 있고, 그 사이 상태를 커널이 상태 머신으로 관리한다. SSD 펌웨어의 NVMe 큐 쌍처럼 "양쪽이 상태를 공유한 채널"이라고 보면 된다.

UDP는 반대로 **"주소를 붙인 메시지를 던지는 것"**이다. 연결도, 재전송도, 순서 보장도 없다. 그래서 단순하고 지연이 작다.

그림 2 — TCP는 서버가 socket → bind → listen → accept, 클라이언트가 socket → connect 순서로 연결을 만든다. UDP는 bind한 소켓에 sendto/recvfrom으로 메시지를 바로 주고받는다.

| 단계 | 서버 쪽 호출 | 클라이언트 쪽 호출 | 커널이 하는 일 |
|---|---|---|---|
| 생성 | `socket()` | `socket()` | `struct socket` + `struct sock` 할당, fd 연결 |
| 주소 지정 | `bind(ip, port)` | 보통 생략 | 포트 예약. 클라이언트는 connect 때 임시(ephemeral) 포트 자동 배정 |
| 대기 | `listen(backlog)` | — | 상태를 LISTEN으로, 완료된 연결을 쌓을 accept 큐 준비 |
| 연결 | `accept()`가 블록 | `connect()`가 블록 | SYN → SYN-ACK → ACK. 완료되면 accept 큐에 새 소켓이 들어감 |
| 데이터 | `read()`/`write()` | `write()`/`read()` | 송신 버퍼 → 세그먼트 → 상대 수신 버퍼 |
| 종료 | `read()`가 0 리턴 → `close()` | `close()` | FIN 교환. 먼저 닫은 쪽이 TIME_WAIT |

### 2.2 예제 2 — TCP echo 서버와 클라이언트

무엇을 확인하는가: 가장 단순한 서버/클라이언트 쌍. 이후 `ss`, `tcpdump`, `strace`로 이 프로그램을 들여다본다.

```c
// ex2-a: 가장 단순한 TCP echo 서버 (한 번에 클라이언트 1개)
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

#define DIE(m) do { perror(m); exit(1); } while (0)

int main(int argc, char **argv) {
    int port = argc > 1 ? atoi(argv[1]) : 5000;
    int ls = socket(AF_INET, SOCK_STREAM, 0);
    if (ls < 0) DIE("socket");
    int one = 1;
    if (setsockopt(ls, SOL_SOCKET, SO_REUSEADDR, &one, sizeof one) < 0) DIE("setsockopt");
    struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(port),
                             .sin_addr.s_addr = htonl(INADDR_ANY) };
    if (bind(ls, (struct sockaddr *)&a, sizeof a) < 0) DIE("bind");
    if (listen(ls, 16) < 0) DIE("listen");
    printf("listening on :%d (fd=%d)\n", port, ls);
    fflush(stdout);
    for (;;) {
        struct sockaddr_in peer; socklen_t pl = sizeof peer;
        int c = accept(ls, (struct sockaddr *)&peer, &pl);
        if (c < 0) DIE("accept");
        printf("accept fd=%d from %s:%d\n", c, inet_ntoa(peer.sin_addr), ntohs(peer.sin_port));
        fflush(stdout);
        char buf[256]; ssize_t n;
        while ((n = read(c, buf, sizeof buf)) > 0)
            if (write(c, buf, n) != n) DIE("write");
        if (n < 0) DIE("read");
        printf("peer closed (read returned 0)\n");
        fflush(stdout);
        close(c);
    }
}
```

```c
// ex2-b: TCP 클라이언트 — connect 후 한 줄 보내고 echo 받기, 잠깐 연결 유지
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

#define DIE(m) do { perror(m); exit(1); } while (0)

int main(int argc, char **argv) {
    const char *msg = argc > 1 ? argv[1] : "hello sensor";
    int hold = argc > 2 ? atoi(argv[2]) : 0;
    int s = socket(AF_INET, SOCK_STREAM, 0);
    if (s < 0) DIE("socket");
    struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(5000) };
    if (inet_pton(AF_INET, "127.0.0.1", &a.sin_addr) != 1) DIE("inet_pton");
    if (connect(s, (struct sockaddr *)&a, sizeof a) < 0) DIE("connect");
    struct sockaddr_in me; socklen_t ml = sizeof me;
    if (getsockname(s, (struct sockaddr *)&me, &ml) < 0) DIE("getsockname");
    printf("connected, my ephemeral port = %d\n", ntohs(me.sin_port));
    size_t len = strlen(msg);
    if (write(s, msg, len) != (ssize_t)len) DIE("write");
    char buf[256];
    ssize_t n = read(s, buf, sizeof buf - 1);
    if (n < 0) DIE("read");
    buf[n] = '\0';
    printf("echo: %s\n", buf);
    sleep(hold);           // 이 동안 ss 로 ESTAB 상태를 본다
    close(s);
    return 0;
}
```

`htons(port)`와 `htonl(INADDR_ANY)`는 3절에서 다룰 바이트 순서 변환이다. `INADDR_ANY`(0.0.0.0)는 "이 장비의 모든 인터페이스에서 받겠다"는 뜻이다. 센서 키트에서 진단 포트를 특정 인터페이스로만 열고 싶으면 그 인터페이스의 IP로 bind한다.

### 2.3 ss와 tcpdump로 연결 들여다보기

같은 VM에서 서버를 띄우고, 패킷 캡처를 켜고, 클라이언트를 2초간 연결 유지시키면서 `ss`(socket statistics)로 상태를 찍었다.

```sh
./tcp_srv > srv.log 2>&1 &
ss -tlnp "sport = :5000"                 # -t TCP, -l listen, -n 숫자, -p 프로세스
sudo tcpdump -i lo -n -c 10 "tcp port 5000" > td.log &
./tcp_cli "hello sensor" 2 &
ss -tnp "( sport = :5000 or dport = :5000 )"
# 클라이언트 종료 후
ss -tan "( sport = :5000 or dport = :5000 )"
```

출력에서 볼 것:

- LISTEN 줄의 `Send-Q 16`은 listen 소켓에서는 **backlog 크기**를 뜻한다(`listen(ls, 16)`). 일반 연결에서는 아직 상대가 ACK하지 않은 송신 바이트 수다.
- 연결 하나에 ESTAB 줄이 **두 개**다. 같은 VM 안이라 클라이언트 쪽 소켓(50362→5000)과 서버 쪽 소켓(5000→50362)이 둘 다 보인다. 서버 쪽은 listen fd 3과 별개인 **새 fd 4**다. `accept()`는 연결마다 새 소켓을 만들어 준다.
- 클라이언트가 먼저 `close()`했으므로 **클라이언트 쪽에 TIME-WAIT**이 남는다(8절에서 다시 본다).

### 2.5 함정

- `listen()`의 backlog는 "동시 연결 수 제한"이 아니다. **handshake가 끝났지만 아직 accept 안 된 연결**의 큐 길이다. 실제 상한은 `net.core.somaxconn`으로 잘린다.
- `connect()`는 TCP에서 handshake 완료까지 블록된다. 상대 장비가 꺼져 있으면 SYN 재전송 때문에 기본 설정에서 2분 넘게 걸릴 수 있다. 센서 키트에서는 non-blocking connect + epoll 타임아웃(7절)이나 `TCP_USER_TIMEOUT`을 쓴다.
- 상대가 닫은 소켓에 `write()`하면 `SIGPIPE`로 프로세스가 죽는다(A6). 서버는 `signal(SIGPIPE, SIG_IGN)` 또는 `send(..., MSG_NOSIGNAL)`을 쓴다.

## 3. 바이트 순서 — htons/htonl은 어디에 쓰나

Don은 엔디언을 이미 안다. 소켓에서 기억할 규칙만 정리한다.

- **네트워크 바이트 순서 = big-endian.** IP 헤더, TCP/UDP 포트, IP 주소는 big-endian으로 선(wire)에 실린다.
- `struct sockaddr_in`의 `sin_port`와 `sin_addr`는 **이미 네트워크 순서로 담는 필드**다. 그래서 `htons(5000)`, `htonl(INADDR_ANY)`를 넣는다. aarch64·x86은 little-endian이므로 실제로 바이트가 뒤집힌다.
- `h`=host, `n`=network, `s`=16비트, `l`=32비트. `ntohs`/`ntohl`은 반대 방향이다. 64비트는 `htobe64()`/`be64toh()`(`<endian.h>`)를 쓴다.
- **내 애플리케이션 프로토콜의 정수 필드**(예제 3의 길이 접두, 예제 4의 seq 번호)도 바이트 순서를 정해 두어야 한다. 관례는 big-endian. 센서 벤더 프로토콜은 little-endian인 경우도 많으니(LiDAR 데이터 패킷이 대표적) 데이터시트를 확인한다.

함정 두 개:

- **netlink 메시지는 host 순서**다(`struct nlmsghdr`). 커널과 같은 장비 안에서만 오가기 때문이다. 습관적으로 `htonl`을 붙이면 깨진다.
- **SocketCAN의 `can_id`도 host 순서** 정수다. CAN 버스 위의 비트 순서는 컨트롤러 하드웨어가 처리한다.

`strace`가 `sin_port=htons(5000)`처럼 보여 주는 것도 메모리에 big-endian으로 들어 있다는 표시다.

### 4.2 예제 3 — 경계가 사라지는 것을 보고, 길이 접두로 고치기

무엇을 확인하는가: 송신 측이 `write()`를 5번 해도 수신 측이 조금 늦게 읽으면 한 번의 `read()`에 다 붙어서 온다. 그리고 `[4바이트 big-endian 길이][payload]` 프레이밍으로 원래 메시지를 복원한다.

```c
// ex3: TCP는 바이트 스트림 — write 경계가 read 경계로 보존되지 않음 + 길이 접두 프레이밍
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <sys/wait.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

static int read_full(int fd, void *p, size_t n) {          // n 바이트를 다 받을 때까지 반복
    size_t got = 0;
    while (got < n) {
        ssize_t r = read(fd, (char *)p + got, n - got);
        if (r < 0) DIE("read");
        if (r == 0) return 0;                                // 상대가 닫음
        got += r;
    }
    return 1;
}
static void send_msg(int fd, const char *s) {               // [4B 길이(big-endian)][payload]
    uint32_t len = strlen(s), be = htonl(len);
    char buf[260]; memcpy(buf, &be, 4); memcpy(buf + 4, s, len);
    if (write(fd, buf, 4 + len) != (ssize_t)(4 + len)) DIE("write");
}
int main(int argc, char **argv) {
    int framed = argc > 1 && !strcmp(argv[1], "framed");
    int ls = socket(AF_INET, SOCK_STREAM, 0), one = 1;
    setsockopt(ls, SOL_SOCKET, SO_REUSEADDR, &one, sizeof one);
    struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(5001),
                             .sin_addr.s_addr = htonl(INADDR_LOOPBACK) };
    if (bind(ls, (void *)&a, sizeof a) < 0 || listen(ls, 1) < 0) DIE("bind/listen");
    if (fork() == 0) {                                       // 자식 = 센서 송신 측
        int s = socket(AF_INET, SOCK_STREAM, 0);
        if (connect(s, (void *)&a, sizeof a) < 0) DIE("connect");
        const char *m[] = { "IMU:1", "IMU:2", "GNSS:fix", "IMU:3", "TEMP:41.5" };
        for (int i = 0; i < 5; i++) {
            if (framed) send_msg(s, m[i]);
            else if (write(s, m[i], strlen(m[i])) < 0) DIE("write");
        }
        close(s); _exit(0);
    }
    int c = accept(ls, NULL, NULL);
    if (c < 0) DIE("accept");
    usleep(100 * 1000);                                      // 수신 측이 조금 늦게 읽는다
    char buf[256];
    if (!framed) {
        ssize_t n;
        while ((n = read(c, buf, sizeof buf - 1)) > 0) { buf[n] = 0; printf("read() -> %2zd bytes: \"%s\"\n", n, buf); }
    } else {
        uint32_t be;
        while (read_full(c, &be, 4)) {
            uint32_t len = ntohl(be);
            if (len >= sizeof buf || !read_full(c, buf, len)) break;
            buf[len] = 0; printf("msg len=%u: \"%s\"\n", len, buf);
        }
    }
    wait(NULL); return 0;
}
```

출력에서 볼 것: 프레이밍 없이 보내면 5개 메시지가 **32바이트 한 덩어리**로 왔다. 수신이 100 ms 늦은 동안 커널 수신 버퍼에 다 쌓였기 때문이다. 반대로 큰 메시지는 여러 `read()`로 쪼개져 올 수도 있다. 그래서 `read_full()`처럼 **원하는 바이트 수를 다 받을 때까지 반복**하는 함수가 필수다.

### 4.3 프레이밍 방식 비교

| 방식 | 예 | 장점 | 단점 |
|---|---|---|---|
| 길이 접두 | 4바이트 길이 + payload (예제 3) | 단순, 바이너리 안전, 미리 버퍼 할당 가능 | 길이 필드가 깨지면 동기 상실 → 상한 검사 필수 |
| 구분자 | 줄바꿈으로 끝나는 텍스트(NMEA, JSON lines) | 사람이 읽기 쉽다, `nc`로 테스트 가능 | payload에 구분자가 나오면 이스케이프 필요 |
| 고정 크기 | 항상 64바이트 레코드 | 파싱이 가장 쉽다 | 낭비, 확장이 어렵다 |
| 상위 프로토콜 | HTTP, MQTT, protobuf + 길이, ROS 2 DDS | 생태계 도구 | 무겁다 |

### 4.4 함정

- 길이 필드를 그대로 믿고 `malloc(len)` 하면 깨진 패킷 하나로 메모리를 다 쓴다. 예제 3처럼 상한(`len >= sizeof buf`)을 검사한다.
- `write()`도 부분 전송될 수 있다(특히 non-blocking 소켓에서 송신 버퍼가 찼을 때). 리턴값이 요청 길이보다 작으면 나머지를 다시 보내야 한다.
- 구조체를 `write(fd, &s, sizeof s)`로 통째로 보내면 패딩·엔디언·컴파일러 차이 때문에 다른 보드에서 깨진다. 필드별로 직렬화한다.

## 5. UDP — 센서·LiDAR 스트림과 패킷 손실

### 5.1 직관

LiDAR는 보통 UDP로 데이터를 쏜다. 예를 들어 Velodyne VLP-16은 1206바이트 데이터 패킷을 초당 약 754개 보낸다(단일 리턴 모드 기준, 장비 매뉴얼 값). 고해상도 LiDAR는 이보다 훨씬 많다. UDP를 쓰는 이유는 명확하다. 늦게 온 포인트 클라우드는 쓸모가 없으니 **재전송보다 최신 데이터**가 중요하다.

### 5.2 예제 4 — LiDAR 흉내 송신기와 느린 수신기

무엇을 확인하는가: 수신기의 패킷당 처리 시간과 `SO_RCVBUF`에 따라 손실이 어떻게 변하는지 측정한다. 패킷 앞 4바이트에 seq 번호를 넣어 빠진 개수를 세고, `SO_RXQ_OVFL` 옵션으로 커널이 센 drop 수도 함께 받는다.

```c
// ex4-a: LiDAR 흉내 UDP 송신기 — burst개씩 몰아서 보내고 gap_us 쉬기를 반복
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <time.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

int main(int argc, char **argv) {
    if (argc < 4) { fprintf(stderr, "usage: %s total burst gap_us\n", argv[0]); return 1; }
    int total = atoi(argv[1]), burst = atoi(argv[2]); long gap = atol(argv[3]);
    int s = socket(AF_INET, SOCK_DGRAM, 0);
    if (s < 0) DIE("socket");
    struct sockaddr_in dst = { .sin_family = AF_INET, .sin_port = htons(6000),
                               .sin_addr.s_addr = htonl(INADDR_LOOPBACK) };
    char pkt[1206];                          // Velodyne VLP-16 데이터 패킷 크기와 같게
    memset(pkt, 0xAB, sizeof pkt);
    struct timespec t; clock_gettime(CLOCK_MONOTONIC, &t);
    for (int seq = 0; seq < total; ) {
        for (int b = 0; b < burst && seq < total; b++, seq++) {
            uint32_t be = htonl(seq);
            memcpy(pkt, &be, 4);
            if (sendto(s, pkt, sizeof pkt, 0, (struct sockaddr *)&dst, sizeof dst) < 0) DIE("sendto");
        }
        t.tv_nsec += gap * 1000;             // 절대 시각 기준으로 다음 burst (drift 방지)
        while (t.tv_nsec >= 1000000000L) { t.tv_nsec -= 1000000000L; t.tv_sec++; }
        clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &t, NULL);
    }
    return 0;
}
```

```c
// ex4-b: UDP 수신기 — 처리 지연(work_us)과 SO_RCVBUF를 바꿔 가며 손실을 센다
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <time.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

static void busy_us(long us) {               // 센서 데이터 처리 시간을 흉내 (sleep 아님)
    struct timespec a, b; clock_gettime(CLOCK_MONOTONIC, &a);
    do clock_gettime(CLOCK_MONOTONIC, &b);
    while ((b.tv_sec - a.tv_sec) * 1000000L + (b.tv_nsec - a.tv_nsec) / 1000 < us);
}
int main(int argc, char **argv) {
    int req = argc > 1 ? atoi(argv[1]) : 0; long work = argc > 2 ? atol(argv[2]) : 0;
    int s = socket(AF_INET, SOCK_DGRAM, 0), one = 1;
    if (s < 0) DIE("socket");
    if (req > 0 && setsockopt(s, SOL_SOCKET, SO_RCVBUFFORCE, &req, sizeof req) < 0) DIE("SO_RCVBUFFORCE");
    setsockopt(s, SOL_SOCKET, SO_RXQ_OVFL, &one, sizeof one);   // 소켓별 drop 카운터를 cmsg로
    struct timeval tv = { .tv_sec = 1 };                          // 1초 조용하면 종료
    setsockopt(s, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof tv);
    struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(6000),
                             .sin_addr.s_addr = htonl(INADDR_LOOPBACK) };
    if (bind(s, (struct sockaddr *)&a, sizeof a) < 0) DIE("bind");
    int eff; socklen_t el = sizeof eff;
    getsockopt(s, SOL_SOCKET, SO_RCVBUF, &eff, &el);
    char buf[2048], cbuf[64]; long got = 0, gaps = 0; int32_t last = -1; uint32_t ovfl = 0;
    for (;;) {
        struct iovec iov = { buf, sizeof buf };
        struct msghdr mh = { .msg_iov = &iov, .msg_iovlen = 1, .msg_control = cbuf, .msg_controllen = sizeof cbuf };
        ssize_t n = recvmsg(s, &mh, 0);
        if (n < 0) break;                                         // 타임아웃 = 스트림 끝
        for (struct cmsghdr *c = CMSG_FIRSTHDR(&mh); c; c = CMSG_NXTHDR(&mh, c))
            if (c->cmsg_level == SOL_SOCKET && c->cmsg_type == SO_RXQ_OVFL) memcpy(&ovfl, CMSG_DATA(c), 4);
        uint32_t be; memcpy(&be, buf, 4); int32_t seq = ntohl(be);
        if (seq != last + 1) gaps += seq - last - 1;
        last = seq; got++;
        busy_us(work);
    }
    printf("rcvbuf_req=%d effective=%d work_us=%ld recv=%ld lost_by_seq=%ld SO_RXQ_OVFL=%u\n",
           req, eff, work, got, gaps, ovfl);
    return 0;
}
```

`SO_RCVBUFFORCE`는 `net.core.rmem_max` 상한을 무시하고 버퍼를 키우는 옵션으로 `CAP_NET_ADMIN`이 필요하다(그래서 버퍼 실험은 `sudo`로 돌렸다). 일반 `SO_RCVBUF`는 `rmem_max`에서 잘린다. VM의 기본값은 이렇다.

```sh
sysctl net.core.rmem_default net.core.rmem_max
```


출력에서 볼 것:

- `skmem:(r…, rb…, d…)`: `r`=현재 수신 큐가 쓰는 메모리, `rb`=수신 버퍼 한도(`sk_rcvbuf`), `d`=이 소켓에서 버려진 패킷 수.
- 두 번째 캡처에서 `r211968`은 정확히 **92 × 2304**다. 1206바이트 payload 하나가 커널 안에서는 sk_buff 헤더·정렬 오버헤드를 포함해 **truesize 2304바이트**를 차지한다. 그래서 기본 버퍼 212992바이트에 1206바이트 패킷은 약 92개만 들어가고, 나머지 358개는 버려졌다(`d358`). **버퍼 크기 ÷ payload 크기로 계산하면 2배 가까이 과대평가한다.** 이 비율(truesize/payload)은 드라이버와 MTU에 따라 다르다.
- `/proc/net/udp`의 `1770`은 포트 6000의 16진수, `0100007F`는 127.0.0.1을 little-endian 정수로 찍은 것이다(3절의 바이트 순서가 여기서도 보인다). 맨 끝 `drops` 열이 같은 358이다.

### 5.6 멀티캐스트 짧게

여러 소비자(인식 노드, 로거, 시각화)가 같은 센서 스트림을 받아야 하면 LiDAR를 멀티캐스트 그룹(예: 239.x.x.x)으로 설정하기도 한다. 수신 측은 `IP_ADD_MEMBERSHIP`으로 그룹에 가입하고, 커널은 IGMP report를 보내 스위치에 알린다. `socat`으로 확인했다.

```sh
ip maddr show dev eth0 | grep -E "inet |239"
echo "LIDAR frame 1" | socat -u - UDP4-DATAGRAM:239.1.1.1:7000,ip-multicast-if=192.168.5.15,ip-multicast-loop=1
```

## 6. 타임스탬프 — 언제 "도착"했나

센서 퓨전(Q3)에서는 "앱이 읽은 시각"이 아니라 **"패킷이 장비에 도착한 시각"**이 필요하다. 앱이 스케줄링 때문에 수 ms 늦게 읽으면 그만큼 오차가 생긴다. 소켓 옵션으로 커널이 기록한 수신 시각을 함께 받을 수 있다.

| 옵션 | 결과 cmsg | 정밀도·출처 |
|---|---|---|
| `SO_TIMESTAMP` | `SCM_TIMESTAMP` (`struct timeval`) | µs, 커널 소프트웨어 |
| `SO_TIMESTAMPNS` | `SCM_TIMESTAMPNS` (`struct timespec`) | ns, 커널 소프트웨어 |
| `SO_TIMESTAMPING` | `SCM_TIMESTAMPING` (timespec 3개) | 플래그로 SW/HW, RX/TX 선택. NIC의 PTP 하드웨어 클럭(PHC) 값까지 |

### 6.1 예제 5 — 커널 수신 시각 vs 앱 읽은 시각

무엇을 확인하는가: 10 ms 간격으로 온 4개 패킷을 60 ms 늦게 몰아서 읽어도 `SO_TIMESTAMPNS`는 각 패킷의 실제 도착 시각을 알려 준다.

```c
// ex5: SO_TIMESTAMPNS — "커널이 패킷을 받은 시각"과 "앱이 read한 시각"은 다르다
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <sys/wait.h>
#define DIE(m) do { perror(m); exit(1); } while (0)
static double ms(struct timespec t, struct timespec b) {
    return (t.tv_sec - b.tv_sec) * 1e3 + (t.tv_nsec - b.tv_nsec) / 1e6;
}
int main(void) {
    int s = socket(AF_INET, SOCK_DGRAM, 0), one = 1;
    if (s < 0) DIE("socket");
    if (setsockopt(s, SOL_SOCKET, SO_TIMESTAMPNS, &one, sizeof one) < 0) DIE("SO_TIMESTAMPNS");
    struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(6001),
                             .sin_addr.s_addr = htonl(INADDR_LOOPBACK) };
    if (bind(s, (struct sockaddr *)&a, sizeof a) < 0) DIE("bind");
    struct timespec base; clock_gettime(CLOCK_REALTIME, &base);
    if (fork() == 0) {                         // 자식: 10 ms 간격으로 4개 송신
        int t = socket(AF_INET, SOCK_DGRAM, 0);
        for (char i = '0'; i < '4'; i++) {
            if (sendto(t, &i, 1, 0, (struct sockaddr *)&a, sizeof a) < 0) DIE("sendto");
            usleep(10000);
        }
        _exit(0);
    }
    usleep(60000);                             // 부모: 일부러 60 ms 늦게 읽기 시작
    for (int k = 0; k < 4; k++) {
        char d, cbuf[64];
        struct iovec iov = { &d, 1 };
        struct msghdr mh = { .msg_iov = &iov, .msg_iovlen = 1, .msg_control = cbuf, .msg_controllen = sizeof cbuf };
        if (recvmsg(s, &mh, 0) < 0) DIE("recvmsg");
        struct timespec now, kts = {0};
        clock_gettime(CLOCK_REALTIME, &now);
        for (struct cmsghdr *c = CMSG_FIRSTHDR(&mh); c; c = CMSG_NXTHDR(&mh, c))
            if (c->cmsg_level == SOL_SOCKET && c->cmsg_type == SCM_TIMESTAMPNS)
                memcpy(&kts, CMSG_DATA(c), sizeof kts);
        printf("pkt %c: kernel rx t=%6.2f ms   app read t=%6.2f ms   (queued %5.2f ms)\n",
               d, ms(kts, base), ms(now, base), ms(now, kts));
    }
    wait(NULL);
    return 0;
}
```

```text
pkt 0: kernel rx t=  0.06 ms   app read t= 64.49 ms   (queued 64.42 ms)
pkt 1: kernel rx t= 10.34 ms   app read t= 64.51 ms   (queued 54.17 ms)
pkt 2: kernel rx t= 20.45 ms   app read t= 64.51 ms   (queued 44.06 ms)
pkt 3: kernel rx t= 32.25 ms   app read t= 64.52 ms   (queued 32.27 ms)
```

출력에서 볼 것: 앱이 읽은 시각은 4개 모두 약 64.5 ms로 같지만, 커널 시각은 0, 10, 20, 32 ms로 실제 송신 간격을 보여 준다. 앱 시각을 타임스탬프로 쓰면 이 경우 최대 64 ms 오차다. `SO_TIMESTAMPNS`는 `CLOCK_REALTIME` 기준이라는 점도 기억한다(NTP/PTP로 시계가 점프하면 같이 움직인다).

VM의 virtio-net은 소프트웨어 타임스탬프만 된다. i.MX8의 ENET/FEC, TI AM62의 CPSW 같은 SoC MAC은 하드웨어 타임스탬프와 PHC(`/dev/ptp0`)를 제공해서 `ptp4l`로 PTP 동기를 할 수 있다. 이런 차이가 Q3(센서 동기화)의 출발점이다.

## 7. non-blocking 소켓과 epoll

A4에서 epoll을 "여러 인터럽트 소스를 한 번에 기다리는 이벤트 그룹"이라고 했다. 소켓은 epoll의 가장 대표적인 사용처다. 센서 게이트웨이 데몬 하나가 LiDAR UDP 소켓, CAN 소켓, 진단 TCP 리스너, 여러 TCP 클라이언트를 **스레드 하나로** 다룰 수 있다.

규칙 세 가지:

- 소켓을 non-blocking으로 만든다(`SOCK_NONBLOCK` 또는 `fcntl(O_NONBLOCK)`). `accept4(..., SOCK_NONBLOCK)`로 받은 연결도 바로 non-blocking이 된다.
- 이벤트가 오면 `EAGAIN`이 나올 때까지 **다 비운다**(listen 소켓은 쌓인 연결을 다 accept, 데이터 소켓은 다 read). edge-triggered(`EPOLLET`)라면 필수다.
- `read()`가 0이면 상대가 FIN을 보낸 것이다. `EPOLLRDHUP`로 반쯤 닫힘을 따로 알 수도 있다.

### 7.1 예제 6 — 스레드 1개로 TCP 클라이언트 3개 처리

```c
// ex6: non-blocking 소켓 + epoll — 스레드 1개로 여러 TCP 클라이언트를 동시에 처리
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <ctype.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <sys/epoll.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

int main(void) {
    int ls = socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK, 0), one = 1;
    if (ls < 0) DIE("socket");
    setsockopt(ls, SOL_SOCKET, SO_REUSEADDR, &one, sizeof one);
    struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(5002),
                             .sin_addr.s_addr = htonl(INADDR_LOOPBACK) };
    if (bind(ls, (struct sockaddr *)&a, sizeof a) < 0 || listen(ls, 64) < 0) DIE("bind/listen");
    int ep = epoll_create1(EPOLL_CLOEXEC);
    struct epoll_event ev = { .events = EPOLLIN, .data.fd = ls };
    if (epoll_ctl(ep, EPOLL_CTL_ADD, ls, &ev) < 0) DIE("epoll_ctl");
    int closed = 0;
    while (closed < 3) {                                  // 데모: 클라이언트 3개가 끝나면 종료
        struct epoll_event evs[16];
        int n = epoll_wait(ep, evs, 16, -1);
        if (n < 0) DIE("epoll_wait");
        for (int i = 0; i < n; i++) {
            int fd = evs[i].data.fd;
            if (fd == ls) {                               // 새 연결: 큐에 쌓인 만큼 모두 accept
                int c;
                while ((c = accept4(ls, NULL, NULL, SOCK_NONBLOCK)) >= 0) {
                    struct epoll_event ce = { .events = EPOLLIN | EPOLLRDHUP, .data.fd = c };
                    epoll_ctl(ep, EPOLL_CTL_ADD, c, &ce);
                    printf("accept  fd=%d\n", c);
                }
                if (errno != EAGAIN) DIE("accept4");
                continue;
            }
            char buf[512]; ssize_t r;
            while ((r = read(fd, buf, sizeof buf)) > 0) {  // EAGAIN 나올 때까지 비운다
                for (ssize_t k = 0; k < r; k++) buf[k] = toupper((unsigned char)buf[k]);
                if (write(fd, buf, r) < 0) perror("write");
                printf("fd=%d  %zd bytes\n", fd, r);
            }
            if (r == 0 || (r < 0 && errno != EAGAIN)) {   // 0 = 상대가 FIN
                printf("close   fd=%d\n", fd);
                epoll_ctl(ep, EPOLL_CTL_DEL, fd, NULL);
                close(fd); closed++;
            }
        }
        fflush(stdout);
    }
    return 0;
}
```

## 8. 자주 쓰는 소켓 옵션

### 8.1 예제 7 — 서버 재시작 시 EADDRINUSE와 SO_REUSEADDR

무엇을 확인하는가: 서버가 먼저 연결을 닫으면 서버 쪽 포트에 TIME_WAIT이 60초 남는다. 이때 같은 포트로 다시 bind하면 실패하고, `SO_REUSEADDR`로 해결된다. 단 **TIME_WAIT 소켓을 만든 쪽(이전 서버)도 옵션을 켰어야** 한다는 것까지 확인한다.

```c
// ex11: 서버를 재시작하면 bind()가 EADDRINUSE — TIME_WAIT과 SO_REUSEADDR
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <sys/wait.h>
#define DIE(m) do { perror(m); exit(1); } while (0)
static struct sockaddr_in A;   // 127.0.0.1:<port> (main에서 채움)

static int try_bind(int reuse) {
    int s = socket(AF_INET, SOCK_STREAM, 0);
    if (s < 0) DIE("socket");
    if (reuse && setsockopt(s, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof reuse) < 0) DIE("setsockopt");
    int r = bind(s, (struct sockaddr *)&A, sizeof A);
    printf("bind(SO_REUSEADDR=%d) -> %s\n", reuse, r == 0 ? "OK" : strerror(errno));
    if (r < 0) { close(s); return -1; }
    return s;
}
int main(int argc, char **argv) {
    A.sin_family = AF_INET; A.sin_port = htons(argc > 2 ? atoi(argv[2]) : 5003); A.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    int ls = try_bind(argc > 1 ? atoi(argv[1]) : 0);  // 첫 서버가 옵션을 켰는가
    if (ls < 0 || listen(ls, 1) < 0) DIE("listen");
    if (fork() == 0) {                                   // 클라이언트: 연결하고 서버가 닫을 때까지 대기
        int c = socket(AF_INET, SOCK_STREAM, 0); char b;
        if (connect(c, (struct sockaddr *)&A, sizeof A) < 0) DIE("connect");
        while (read(c, &b, 1) > 0) {}
        close(c); _exit(0);
    }
    int c = accept(ls, NULL, NULL);
    if (c < 0) DIE("accept");
    close(c);                                            // 서버가 먼저 close → 서버 쪽이 TIME_WAIT
    close(ls);                                           // "서버 프로세스 재시작"을 흉내
    wait(NULL);
    char cmd[96]; fflush(stdout);
    snprintf(cmd, sizeof cmd, "ss -tan 'sport = :%d' | tail -n +2", ntohs(A.sin_port));
    if (system(cmd) < 0) DIE("system");
    int s1 = try_bind(0);                                // 실패할 것
    int s2 = try_bind(1);                                // 성공할 것
    if (s1 >= 0) close(s1);
    if (s2 >= 0) close(s2);
    return 0;
}
```


### 8.2 옵션 정리

| 옵션 | 레벨 | 무엇 | Embedded에서 쓰는 장면 |
|---|---|---|---|
| `SO_REUSEADDR` | `SOL_SOCKET` | TIME_WAIT 포트 재bind 허용 | 모든 TCP 서버. 데몬 재시작 |
| `SO_REUSEPORT` | `SOL_SOCKET` | 여러 소켓이 같은 포트를 동시에 bind, 커널이 분산 | 멀티스레드 UDP 수신 분산 |
| `SO_RCVBUF` / `SO_SNDBUF` | `SOL_SOCKET` | 소켓 버퍼 크기(커널이 2배로 기록) | LiDAR·카메라 UDP 수신 |
| `SO_RCVTIMEO` | `SOL_SOCKET` | 블로킹 recv 타임아웃 | 단순 툴의 타임아웃 |
| `SO_BINDTODEVICE` | `SOL_SOCKET` | 특정 인터페이스로만 송수신 | LiDAR 전용 NIC(eth1)와 업링크 분리 |
| `SO_TIMESTAMPNS` | `SOL_SOCKET` | 수신 시각 cmsg | 센서 타임스탬프 |
| `SO_RXQ_OVFL` | `SOL_SOCKET` | 누적 drop 수 cmsg | 손실 모니터링 |
| `TCP_NODELAY` | `IPPROTO_TCP` | Nagle 알고리즘 끔. 작은 write를 모으지 않고 즉시 전송 | 원격 제어 명령, 작은 요청-응답 |
| `TCP_KEEPIDLE` 등 + `SO_KEEPALIVE` | `IPPROTO_TCP` | 죽은 연결 감지 | 케이블 뽑힘 감지 |
| `IP_ADD_MEMBERSHIP` | `IPPROTO_IP` | 멀티캐스트 그룹 가입 | 멀티캐스트 센서 스트림 |

`SO_BINDTODEVICE`는 이 VM(커널 7.0)에서 일반 사용자로도 설정됐다. 커널 5.7 이전에는 `CAP_NET_RAW`가 필요했다. 오래된 BSP 커널에서 데몬이 root가 아니면 `EPERM`이 날 수 있다.

`TCP_NODELAY`가 왜 필요한가: Nagle 알고리즘은 "아직 ACK 안 된 작은 세그먼트가 있으면 다음 작은 write를 모아서 보낸다". 상대의 delayed ACK와 겹치면 작은 명령 하나가 수십 ms 늦게 나간다. 제어 명령처럼 지연이 중요한 TCP 연결에서는 끈다.

## 9. AF_PACKET — 이더넷 프레임을 통째로

### 9.1 직관

`AF_PACKET`은 IP 스택을 건너뛰고 **드라이버가 올려 준 이더넷 프레임을 그대로** 받거나 보낸다. `tcpdump`, `wireshark`(libpcap)가 바닥에서 쓰는 것이 이것이다. 독자 EtherType을 쓰는 산업용 프로토콜(EtherCAT 마스터 구현 등)이나 PHY 루프백 테스트 툴도 이 소켓으로 짠다. 펌웨어에서 MAC RX 디스크립터의 버퍼를 직접 들여다보던 위치와 가장 가깝다.

### 9.2 예제 8 — ping 프레임 캡처

```c
// ex7: AF_PACKET raw 소켓 — 특정 인터페이스의 Ethernet 프레임을 통째로 받기 (tcpdump의 바닥)
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <arpa/inet.h>
#include <net/if.h>
#include <sys/socket.h>
#include <linux/if_packet.h>
#include <linux/if_ether.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

int main(int argc, char **argv) {
    const char *ifname = argc > 1 ? argv[1] : "lo";
    int cnt = argc > 2 ? atoi(argv[2]) : 6;
    int s = socket(AF_PACKET, SOCK_RAW, htons(ETH_P_ALL));   // 모든 EtherType
    if (s < 0) DIE("socket(AF_PACKET) — root/CAP_NET_RAW 필요");
    struct sockaddr_ll sll = { .sll_family = AF_PACKET, .sll_protocol = htons(ETH_P_ALL),
                               .sll_ifindex = if_nametoindex(ifname) };
    if (sll.sll_ifindex == 0) DIE("if_nametoindex");
    if (bind(s, (struct sockaddr *)&sll, sizeof sll) < 0) DIE("bind");
    printf("capturing on %s (ifindex %d)\n", ifname, sll.sll_ifindex);
    for (int i = 0; i < cnt; i++) {
        unsigned char f[2048];
        struct sockaddr_ll from; socklen_t fl = sizeof from;
        ssize_t n = recvfrom(s, f, sizeof f, 0, (struct sockaddr *)&from, &fl);
        if (n < 0) DIE("recvfrom");
        struct ethhdr *eh = (struct ethhdr *)f;
        unsigned type = ntohs(eh->h_proto);
        printf("%-8s len=%4zd  %02x:%02x:%02x:%02x:%02x:%02x -> %02x:%02x:%02x:%02x:%02x:%02x  type=0x%04x",
               from.sll_pkttype == PACKET_OUTGOING ? "OUT" : "IN", n,
               eh->h_source[0], eh->h_source[1], eh->h_source[2], eh->h_source[3], eh->h_source[4], eh->h_source[5],
               eh->h_dest[0], eh->h_dest[1], eh->h_dest[2], eh->h_dest[3], eh->h_dest[4], eh->h_dest[5], type);
        if (type == ETH_P_IP)                  // IPv4 헤더의 protocol 필드 = offset 14+9
            printf("  IPv4 proto=%u (%s)", f[23], f[23] == 1 ? "ICMP" : f[23] == 6 ? "TCP" : f[23] == 17 ? "UDP" : "?");
        printf("\n");
    }
    return 0;
}
```

## 10. SocketCAN — CAN도 소켓이다

### 10.1 직관

많은 RTOS에서 CAN은 "mailbox에 ID와 데이터를 쓰고 TX 요청 비트를 세우는" 레지스터 API였다. Linux는 CAN 컨트롤러를 **네트워크 인터페이스**(`can0`)로 등록하고 CAN 프레임 하나를 패킷 하나로 다룬다. 그래서 `ip link`로 비트레이트를 설정하고, 소켓으로 송수신하고, `ip -s link`로 에러 카운터를 본다. 이게 SocketCAN이다(Volkswagen 연구소가 기여해 메인라인에 들어갔다. 아래 `modinfo` author 줄에서도 보인다).

### 10.2 예제 9 — vcan0으로 프레임 보내고 필터로 받기

무엇을 확인하는가: TCP/UDP와 똑같은 `socket` → `bind` → `write`/`read` 흐름이고, 커널 안에서 ID 필터링(하드웨어 acceptance filter의 소프트웨어 판)이 된다.

```c
// ex8: SocketCAN — CAN도 같은 socket/bind/write/read API. 필터로 ID 0x100~0x1FF만 받기
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <net/if.h>
#include <sys/socket.h>
#include <linux/can.h>
#include <linux/can/raw.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

static int can_open(const char *ifname) {
    int s = socket(PF_CAN, SOCK_RAW, CAN_RAW);
    if (s < 0) DIE("socket(PF_CAN)");
    struct sockaddr_can addr = { .can_family = AF_CAN, .can_ifindex = if_nametoindex(ifname) };
    if (addr.can_ifindex == 0) DIE("if_nametoindex");
    if (bind(s, (struct sockaddr *)&addr, sizeof addr) < 0) DIE("bind");
    return s;
}
int main(int argc, char **argv) {
    const char *ifn = argc > 1 ? argv[1] : "vcan0";
    int tx = can_open(ifn), rx = can_open(ifn);
    struct can_filter flt = { .can_id = 0x100, .can_mask = 0x700 };   // (id & 0x700) == 0x100
    if (setsockopt(rx, SOL_CAN_RAW, CAN_RAW_FILTER, &flt, sizeof flt) < 0) DIE("CAN_RAW_FILTER");
    canid_t ids[] = { 0x123, 0x321, 0x1A0 };          // 모터 명령, 배터리 상태, 엔코더(가정)
    for (int i = 0; i < 3; i++) {
        struct can_frame f = { .can_id = ids[i], .len = 4 };
        memcpy(f.data, "\x11\x22\x33\x44", 4);
        f.data[3] = i;
        if (write(tx, &f, sizeof f) != sizeof f) DIE("write");     // 16바이트 can_frame 하나 = write 한 번
        printf("TX id=0x%03X len=%d\n", f.can_id, f.len);
    }
    struct timeval tv = { .tv_usec = 200000 };
    setsockopt(rx, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof tv);
    struct can_frame f;
    while (read(rx, &f, sizeof f) == sizeof f) {
        printf("RX id=0x%03X len=%d data=", f.can_id & CAN_SFF_MASK, f.len);
        for (int i = 0; i < f.len; i++) printf("%02X ", f.data[i]);
        printf("\n");
    }
    printf("sizeof(struct can_frame) = %zu\n", sizeof(struct can_frame));
    return 0;
}
```

출력에서 볼 것:

- 0x321은 필터 `(id & 0x700) == 0x100`에 맞지 않아 rx 소켓에 오지 않았다. 필터는 소켓마다 따로 걸린다.
- 같은 프로세스의 다른 소켓(tx)이 보낸 프레임을 rx가 받은 것은 SocketCAN의 **로컬 루프백**(`CAN_RAW_LOOPBACK`, 기본 켜짐) 덕분이다. 실제 버스에서도 같은 장비의 다른 앱이 송신 프레임을 볼 수 있게 해 준다. 보낸 소켓 자신은 기본적으로 자기 프레임을 받지 않는다(`CAN_RAW_RECV_OWN_MSGS` 기본 꺼짐).
- 인터페이스 카운터는 3개 송신, 3개 수신(데이터 4바이트 × 3 = 12바이트)이다. 필터는 소켓 단계라 인터페이스 카운터에는 영향이 없다.
- `struct can_frame`은 16바이트 고정이다(4바이트 ID + 1바이트 길이 + 패딩·예약 3 + 데이터 8). write 한 번 = 프레임 하나, 부분 쓰기가 없다. CAN FD는 `struct canfd_frame`(72바이트) + `CAN_RAW_FD_FRAMES` 옵션을 쓴다.

실물 보드에서는 `can-utils` 패키지의 `candump can0`, `cansend can0 123#11223344`가 같은 소켓 API로 만든 툴이다. `ip -details -statistics link show can0`에서 `berr-counter`, `bus-off` 같은 CAN 에러 상태를 본다.

## 11. AF_NETLINK — 유저 공간이 커널과 대화하는 소켓

### 11.1 직관

`ip`, `ss`, `iw`, `ethtool`(최신), NetworkManager, udev는 `ioctl` 대신 **netlink 소켓**으로 커널에 질문하고 명령한다. netlink는 "상대편이 커널"인 데이터그램 소켓이다. 메시지는 `struct nlmsghdr` 헤더 + 고정 구조체 + TLV(type-length-value) 속성 목록으로 되어 있어, 필드를 추가해도 옛 툴이 깨지지 않는다. 펌웨어로 치면 호스트-디바이스 간 메일박스 프로토콜을 TLV로 확장 가능하게 설계한 것이다.

주요 netlink 프로토콜:

| 프로토콜 | 용도 | 대표 사용자 |
|---|---|---|
| `NETLINK_ROUTE` (rtnetlink) | 링크·주소·라우트·이웃·qdisc 조회/설정 | `ip`, `ss`(일부), NetworkManager |
| `NETLINK_KOBJECT_UEVENT` | 장치 hotplug 이벤트 방송 | systemd-udevd, mdev |
| `NETLINK_GENERIC` (genetlink) | 서브시스템별 확장 채널 | `iw`(nl80211), `ethtool`, `devlink` |
| `NETLINK_SOCK_DIAG` | 소켓 목록·상태 조회 | `ss` |

### 11.2 예제 10 — rtnetlink로 인터페이스 목록 받기

무엇을 확인하는가: `RTM_GETLINK` + `NLM_F_DUMP` 요청 하나로 모든 인터페이스 정보를 받고, TLV 속성을 순회해 이름과 MTU를 꺼낸다.

```c
// ex10: rtnetlink로 인터페이스 목록 받기 — `ip link`가 하는 일의 축소판
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <net/if.h>
#include <net/if_arp.h>
#include <linux/netlink.h>
#include <linux/rtnetlink.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

int main(void) {
    int s = socket(AF_NETLINK, SOCK_RAW | SOCK_CLOEXEC, NETLINK_ROUTE);
    if (s < 0) DIE("socket");
    struct { struct nlmsghdr nh; struct ifinfomsg ifi; } req = {
        .nh = { .nlmsg_len = sizeof req, .nlmsg_type = RTM_GETLINK,
                .nlmsg_flags = NLM_F_REQUEST | NLM_F_DUMP, .nlmsg_seq = 1 },
        .ifi = { .ifi_family = AF_UNSPEC } };
    if (send(s, &req, sizeof req, 0) < 0) DIE("send");
    char buf[32768];
    for (;;) {
        ssize_t n = recv(s, buf, sizeof buf, 0);
        if (n < 0) DIE("recv");
        for (struct nlmsghdr *nh = (void *)buf; NLMSG_OK(nh, n); nh = NLMSG_NEXT(nh, n)) {
            if (nh->nlmsg_type == NLMSG_DONE) return 0;
            if (nh->nlmsg_type == NLMSG_ERROR) { fprintf(stderr, "netlink error\n"); return 1; }
            struct ifinfomsg *ifi = NLMSG_DATA(nh);
            int len = IFLA_PAYLOAD(nh);
            const char *name = "?"; unsigned mtu = 0;
            for (struct rtattr *rta = IFLA_RTA(ifi); RTA_OK(rta, len); rta = RTA_NEXT(rta, len)) {
                if (rta->rta_type == IFLA_IFNAME) name = RTA_DATA(rta);   // TLV 속성을 순회
                if (rta->rta_type == IFLA_MTU) mtu = *(unsigned *)RTA_DATA(rta);
            }
            printf("ifindex=%d %-6s type=%-4u (%s) mtu=%-5u %s\n", ifi->ifi_index, name, ifi->ifi_type,
                   ifi->ifi_type == ARPHRD_ETHER ? "ether" : ifi->ifi_type == ARPHRD_LOOPBACK ? "loop" :
                   ifi->ifi_type == ARPHRD_CAN ? "can" : "other",
                   mtu, (ifi->ifi_flags & IFF_UP) ? "UP" : "DOWN");
        }
    }
}
```

```c
// ex9: NETLINK_KOBJECT_UEVENT — 커널이 방송하는 hotplug 이벤트(udev가 듣는 것)를 직접 듣기
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <linux/netlink.h>
#define DIE(m) do { perror(m); exit(1); } while (0)

int main(int argc, char **argv) {
    int max = argc > 1 ? atoi(argv[1]) : 5;
    int s = socket(AF_NETLINK, SOCK_DGRAM | SOCK_CLOEXEC, NETLINK_KOBJECT_UEVENT);
    if (s < 0) DIE("socket(AF_NETLINK)");
    struct sockaddr_nl sa = { .nl_family = AF_NETLINK, .nl_pid = 0, .nl_groups = 1 }; // group 1 = kernel uevents
    if (bind(s, (struct sockaddr *)&sa, sizeof sa) < 0) DIE("bind");
    struct timeval tv = { .tv_sec = 5 };
    setsockopt(s, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof tv);
    printf("listening for uevents...\n"); fflush(stdout);
    for (int i = 0; i < max; i++) {
        char buf[4096];
        ssize_t n = recv(s, buf, sizeof buf - 1, 0);
        if (n < 0) break;
        buf[n] = '\0';
        // 메시지 = "ACTION@DEVPATH\0KEY=VAL\0KEY=VAL\0..."
        printf("[%zd bytes] %s\n", n, buf);
        for (char *p = buf + strlen(buf) + 1; p < buf + n; p += strlen(p) + 1)
            if (!strncmp(p, "SUBSYSTEM=", 10) || !strncmp(p, "INTERFACE=", 10) ||
                !strncmp(p, "MODALIAS=", 9) || !strncmp(p, "SEQNUM=", 7))
                printf("      %s\n", p);
        fflush(stdout);
    }
    return 0;
}
```

그림 9 — 소켓 계층 → 프로토콜 → net core → net_device 드라이버의 층 구조. 송신은 위에서 아래로 sk_buff에 헤더를 붙이며 내려가고, 수신은 드라이버의 NAPI poll에서 sk_buff가 만들어져 위로 올라온다.

### 13.1 socket() — fd와 struct socket

- `socket()` 시스템 콜 → `__sys_socket()` → `sock_create()` → family별 `net_proto_family.create` 함수(`inet_create`, `packet_create`, `can_create`, `netlink_create`, `unix_create`)가 호출된다. AF_CAN 소켓을 만들 때 `can_raw`가 자동 로드된 것은 여기서 `request_module("can-proto-1")`을 하기 때문이다.
- 결과물은 두 겹이다. `struct socket`(VFS 쪽 얼굴: 타입, 상태, `proto_ops` 포인터)과 `struct sock`(프로토콜 쪽 몸통: 수신 큐 `sk_receive_queue`, `sk_rcvbuf`, `sk_drops`, 대기 큐). TCP라면 `struct sock`은 더 큰 `struct tcp_sock`의 맨 앞에(`inet_connection_sock` → `inet_sock` → `sock` 순으로 겹겹이) 들어 있어서 포인터 캐스팅으로 오간다(C의 구조체 상속 패턴).
- `sock_alloc_file()`이 `struct file`을 만들고 `f_op`를 `socket_file_ops`로 채운다. 그래서 `read()` → `sock_read_iter()` → `sock_recvmsg()` → `sock->ops->recvmsg()`(예: `inet_recvmsg` → `udp_recvmsg`)로 이어진다. A1에서 본 "VFS가 `file_operations`로 분기한다"는 구조가 소켓에도 그대로 적용된다.
- `epoll`은 `socket_file_ops.poll` = `sock_poll()` → 프로토콜의 `poll`(`tcp_poll`, `datagram_poll`)을 부른다. 드라이버의 `.poll` + `poll_wait()`(A4, G4)와 같은 구조다.

### 13.2 송신 경로

`write()` → `sock_sendmsg()` → `inet_sendmsg()` → `udp_sendmsg()`/`tcp_sendmsg()` → 데이터를 `sk_buff`(skb)에 담음 → `ip_output()`이 IP 헤더, 이웃 계층이 이더넷 헤더 → `dev_queue_xmit()` → qdisc(송신 큐 정책) → 드라이버의 `ndo_start_xmit(skb, dev)`. 드라이버는 skb의 데이터를 DMA 매핑해 TX 디스크립터 링에 올리고 doorbell을 친다. 링이 차면 `netif_stop_queue()`로 위층을 멈춘다. Don이 SSD에서 하던 submission queue + doorbell과 같은 그림이다.

### 13.3 수신 경로

NIC가 프레임을 DMA로 RX 링에 쓰고 인터럽트 → 드라이버 ISR이 인터럽트를 끄고 `napi_schedule()` → softirq(NET_RX)에서 드라이버의 NAPI `poll()`이 예산(budget)만큼 디스크립터를 읽어 skb를 만들고 `napi_gro_receive()`/`netif_receive_skb()`로 올림 → `ip_rcv()` → `udp_rcv()` → 소켓 찾기 → 수신 큐에 넣기 전 `sk_rcvbuf` 검사(넘치면 drop, `sk_drops`와 `UDP_MIB_RCVBUFERRORS` 증가 — 5절의 카운터) → `sk_data_ready()`가 `recvmsg()`에서 잠든 태스크나 epoll을 깨움(F3의 wait queue). `AF_PACKET` 소켓은 `netif_receive_skb` 단계에서 등록된 탭(`packet_rcv`)으로 복사본을 받는다. 그래서 tcpdump는 IP 스택이 버리는 패킷도 볼 수 있다.

NAPI는 "인터럽트로 깨운 뒤 폴링으로 몰아서 처리"하는 방식이다. 고속 NIC에서 패킷마다 인터럽트를 받으면 CPU가 인터럽트만 처리하다 끝나는 문제(livelock)를 막는다. 펌웨어에서 인터럽트 coalescing + 폴링 루프로 전환하던 것과 같은 해법이다(F6, F7, I6).

### 13.4 CAN과 netlink는 어디로

- CAN: `can_send()` → `dev_queue_xmit()` → CAN 드라이버 `ndo_start_xmit()`(i.MX8은 `flexcan`, TI AM62는 `m_can`, SPI 외장 컨트롤러는 `mcp251xfd`). 수신은 드라이버가 `can_frame`을 skb에 담아 올리면 CAN 코어의 `can_rcv()`가 소켓별 필터를 돌린다. CAN 드라이버도 결국 `net_device` 드라이버라 I6의 지식이 그대로 쓰인다.
- netlink: 하드웨어로 내려가지 않는다. `netlink_sendmsg()` → 프로토콜별 수신 함수(rtnetlink면 `rtnetlink_rcv()` → `rtnl_dump_ifinfo()` 같은 핸들러) → 응답 skb를 요청한 소켓의 수신 큐에 넣는다. uevent는 `kobject_uevent_env()`가 메시지를 만들어 멀티캐스트로 뿌린다.

### 13.5 드라이버를 쓸 때 다시 만나는 곳

| 유저에서 본 것 | 커널/드라이버에서 다시 만나는 것 | 노트 |

## 14. Embedded 실무에서 다시 보기

### 14.1 LiDAR 수신 스레드

예를 들어 센서 키트라면 LiDAR 수신은 이렇게 짠다.

- LiDAR 전용 NIC(또는 VLAN)에 `SO_BINDTODEVICE`로 묶어 업링크 트래픽과 섞이지 않게 한다.
- `SO_RCVBUF`를 "최대 burst × truesize"로 잡고 `rmem_max`를 같이 올린다(5.5절).
- 수신 스레드는 `recvmmsg()`로 여러 패킷을 한 번에 받아 링버퍼에 넣기만 하고, 포인트 클라우드 변환은 다른 스레드가 한다(5.4절 교훈).
- `SO_TIMESTAMPING`으로 도착 시각을 받고, LiDAR 패킷 안의 GPS/PTP 시각과 비교해 지연을 모니터링한다(Q3).
- 수신 스레드에 RT 우선순위(F1)와 CPU 친화도, NIC IRQ도 같은 클러스터에 고정한다.

### 14.2 CAN 모터 제어 데몬

- 모터 컨트롤러 응답 ID만 받도록 `CAN_RAW_FILTER`를 건다. 수천 fps 버스에서 관심 없는 프레임으로 유저 공간을 깨우지 않는다.
- 에러 프레임을 받으려면 `CAN_RAW_ERR_FILTER`를 켠다. bus-off 같은 상태 변화가 프레임으로 온다.
- CAN 소켓, 타이머(timerfd), 상위 명령 TCP 소켓을 하나의 epoll 루프로 묶는다(A4, 7절).
- 개발 PC에서는 vcan0로 상위 로직을 먼저 검증하고, 보드에서는 인터페이스 이름만 can0로 바꾼다. 이것이 "CAN도 소켓"인 실무적 이점이다.

### 14.3 진단·설정 서버

- TCP 서버는 `SO_REUSEADDR`, `SOCK_CLOEXEC`, `SIGPIPE` 무시, 길이 접두 프레이밍을 기본으로 깐다.
- 장비가 hotplug USB 카메라나 USB-CAN 어댑터를 쓰면 NETLINK uevent(정확히는 libudev monitor)로 연결/해제를 감지해 파이프라인을 재구성한다.
- 링크 업/다운 감지는 `/sys/class/net/eth0/carrier`를 폴링하지 말고 rtnetlink `RTMGRP_LINK` 그룹에 가입해 이벤트로 받는다.

## 15. 흔한 실수와 증상

| 실수 | 증상 | 원인 | 고치는 법 |
|---|---|---|---|

## 16. 면접에서 이렇게 말한다

**Q.** What's the difference between TCP and UDP, and when would you use UDP on an embedded device?

**A.** TCP는 연결 지향 바이트 스트림으로 순서·재전송·흐름 제어를 보장하지만 지연과 head-of-line blocking이 있다. UDP는 메시지 경계가 보존되는 비연결 데이터그램으로 손실·순서 바뀜이 가능하다. LiDAR나 카메라 스트림처럼 늦은 데이터가 쓸모없는 실시간 센서 데이터에는 UDP를, 설정·펌웨어 업데이트·로그처럼 정확성이 중요한 데에는 TCP를 쓴다.

> TCP gives you a reliable, ordered byte stream with retransmission and flow control, at the cost of latency and head-of-line blocking. UDP preserves message boundaries but can lose or reorder datagrams. For real-time sensor streams like LiDAR, a late packet is useless, so UDP with a sequence number in the payload is the right choice. For configuration, firmware updates, or logs, where every byte matters, I'd use TCP.

**꼬리 질문**: "UDP 손실을 어떻게 감지하나?" → 페이로드 seq 번호 + `RcvbufErrors`/`ss -m`의 drops.

**Q.** Our LiDAR driver occasionally drops packets. How do you debug it?

**A.** 층별로 카운터를 본다. `ethtool -S`(NIC RX 링), `ip -s link`(드라이버), `nstat`의 `UdpRcvbufErrors`(소켓 버퍼), `ss -u -m`의 d(어느 소켓). 소켓 단계라면 burst × truesize 기준으로 `SO_RCVBUF`와 `rmem_max`를 올리고, 평균 처리율이 부족하면 수신과 처리를 분리한다. 실측에서 1206바이트 패킷 하나가 커널 메모리 2304바이트를 차지해 기본 버퍼에 92개밖에 안 들어갔다.

> I'd walk the stack bottom-up with counters: ethtool -S for NIC ring drops, ip -s link for driver drops, UdpRcvbufErrors for socket buffer overflow, and ss -u -m to see which socket's drop counter is moving. If it's the socket buffer, I size SO_RCVBUF for the worst burst times the skb truesize, which is roughly twice the payload, and raise rmem_max. If the average processing rate is below the arrival rate, a bigger buffer only delays the loss, so I split receiving from processing and use recvmmsg.

**Q.** Why does TCP need message framing, and how do you implement it?

**A.** TCP는 write 경계를 보존하지 않는다. 여러 write가 한 read로 붙거나 하나가 여러 read로 쪼개진다. 그래서 4바이트 big-endian 길이 접두를 붙이고, 수신 측은 정확한 바이트 수를 다 읽을 때까지 반복하는 `read_full`로 헤더와 payload를 읽는다. 길이 상한 검사도 넣는다.

> TCP is a byte stream, so message boundaries from write calls are not preserved; I've seen five writes arrive in a single 32-byte read. The usual fix is a length prefix in network byte order, and a read-exactly-n-bytes loop on the receiver, with a sanity limit on the length so a corrupted header can't make you allocate gigabytes.

**Q.** What is TIME_WAIT and why do servers set SO_REUSEADDR?

**A.** 먼저 close한 쪽이 지연된 세그먼트가 새 연결에 섞이지 않도록 60초(Linux 고정값) 동안 TIME_WAIT 상태를 유지한다. 서버가 먼저 닫고 재시작하면 그 포트로 bind가 EADDRINUSE로 실패한다. `SO_REUSEADDR`가 이를 허용하는데, Linux에서는 TIME_WAIT를 남긴 이전 소켓도 옵션을 켰어야 해서 항상 켜는 것이 관례다.

> The side that closes first stays in TIME_WAIT for 60 seconds on Linux so that delayed segments from the old connection can't corrupt a new one. If a server restarts while its port has TIME_WAIT entries, bind fails with EADDRINUSE. SO_REUSEADDR allows the bind, and on Linux the old socket must have had it set as well, which is why every server sets it before bind.

**Q.** How does SocketCAN work, and why is it designed as a socket?

**A.** CAN 컨트롤러를 `net_device`(can0)로 등록하고, 프레임 하나를 skb 하나로 다룬다. 앱은 `socket(PF_CAN, SOCK_RAW, CAN_RAW)`, `bind`로 인터페이스 지정, `write`/`read`로 16바이트 `can_frame`을 주고받는다. 소켓 단위 필터, 여러 앱 동시 접근, epoll 통합, `ip`로 비트레이트 설정, qdisc, vcan으로 하드웨어 없이 테스트가 모두 네트워크 스택의 기존 기능으로 해결된다.

> SocketCAN registers the CAN controller as a network device, so each CAN frame travels as an skb. Applications open a PF_CAN raw socket, bind it to can0, and read or write fixed 16-byte can_frame structs. Reusing the network stack gives you per-socket ID filters, multiple concurrent users, epoll integration, configuration through ip and netlink, and virtual interfaces like vcan for testing without hardware. The driver side is a normal net_device driver using alloc_candev and register_candev.

**Q.** How do tools like `ip` or udev talk to the kernel?

**A.** netlink 소켓이다. `ip`는 `NETLINK_ROUTE`에 `RTM_GETLINK` 같은 요청을 보내고 TLV 속성이 담긴 응답을 받는다. udev는 `NETLINK_KOBJECT_UEVENT` 멀티캐스트 그룹에 가입해 커널이 `kobject_uevent()`로 보내는 "add@/devices/..." 메시지를 받아 `/dev` 노드를 만들고 모듈을 로드한다.

> Through netlink sockets. iproute2 sends rtnetlink requests such as RTM_GETLINK with NLM_F_DUMP and parses TLV attributes in the replies, which is extensible and avoids ioctl ABI problems. udev subscribes to the NETLINK_KOBJECT_UEVENT multicast group; the kernel broadcasts messages like add@/devices/... with SUBSYSTEM and MODALIAS keys, and udev uses them to create device nodes and load modules.

**Q.** Walk me through what happens in the kernel when a UDP packet arrives.

**A.** NIC가 DMA로 RX 링에 쓰고 인터럽트 → 드라이버가 NAPI를 스케줄 → softirq에서 poll이 skb를 만들어 `netif_receive_skb` → `ip_rcv` → `udp_rcv` → 포트로 소켓을 찾고 `sk_rcvbuf` 검사 후 수신 큐에 넣음(넘치면 drop + 카운터) → `sk_data_ready`가 대기 중인 recv나 epoll을 깨움 → 앱이 `recvmsg`로 skb 데이터를 복사해 감.

> The NIC DMAs the frame into an RX ring and raises an interrupt; the driver masks it and schedules NAPI. In the NET_RX softirq, the driver's poll function builds skbs and passes them to netif_receive_skb, then ip_rcv and udp_rcv look up the socket by port. Before queuing, the kernel checks the socket's receive buffer limit; if it's full, the packet is dropped and RcvbufErrors is incremented. Otherwise it's queued and sk_data_ready wakes any thread blocked in recvmsg or epoll_wait.

**Q.** How would you get accurate arrival timestamps for sensor packets?

**A.** 앱의 시각은 스케줄링 지연을 포함한다. `SO_TIMESTAMPNS`로 커널 수신 시각을 cmsg로 받고, 더 정확하게는 `SO_TIMESTAMPING`으로 NIC 하드웨어 타임스탬프를 받는다. 이를 위해 NIC가 PHC를 지원해야 하고 `ptp4l`/`phc2sys`로 시스템 시계와 맞춘다. 실험에서 앱 시각은 최대 64 ms 틀렸다.

> Application-side timestamps include scheduling delay; in a quick test, packets that arrived 10 ms apart all looked like they arrived at the same time when read late. I'd enable SO_TIMESTAMPNS for kernel receive timestamps, or SO_TIMESTAMPING for hardware timestamps if the MAC has a PTP hardware clock, and then keep the PHC and system clock aligned with ptp4l and phc2sys.

## 17. 직접 해보기

1. (개념) `listen(fd, 1)`인 서버가 `accept()`를 전혀 안 부르는 상태에서 클라이언트 5개가 `connect()`하면 어떻게 되나? `ss -tn`으로 확인해 보라.
정답/힌트: 처음 몇 개는 handshake가 끝나 ESTAB(accept 큐)에 쌓이고, 큐가 차면 이후 SYN은 응답을 못 받아 재전송한다. 리스너의 Recv-Q가 대기 연결 수다.

2. (코드) 예제 3의 길이 접두 프로토콜에 2바이트 메시지 타입 필드와 CRC32를 추가하고, 일부러 1바이트를 망가뜨린 메시지를 보내 수신 측이 거부하게 만들어라.
정답/힌트: 헤더를 `[len 4][type 2]`, 끝에 CRC 4바이트. zlib의 `crc32()`를 쓰거나 직접 구현한다. 모든 정수는 `htonl`/`htons`.

3. (측정) 예제 4의 `udp_rx`를 `recvmmsg()`로 바꿔 한 번에 32개씩 받게 하고, `work_us=100`에서 손실률이 어떻게 바뀌는지 측정하라.
정답/힌트: syscall 비용이 줄어 100 µs 지점의 2.2% 손실이 줄어든다. 처리 시간 자체가 100 µs를 넘으면 여전히 손실.

4. (관찰) 예제 6 서버를 띄우고 `strace -p <pid> -e trace=epoll_wait,accept4,read,write`로 클라이언트 연결 시 시스템 콜 순서를 관찰하라. `ls -l /proc/<pid>/fd`에서 `anon_inode:[eventpoll]`도 찾아보라.
정답/힌트: `epoll_wait` 리턴 → `accept4` 성공 → `accept4`가 `EAGAIN` → 다시 `epoll_wait`. fd 4가 eventpoll이다.

5. (코드) vcan0에 `CAN_RAW_ERR_FILTER`와 `CAN_RAW_RECV_OWN_MSGS`를 켜고 같은 소켓으로 보낸 프레임이 `MSG_CONFIRM` 플래그와 함께 돌아오는지 `recvmsg()`의 `msg_flags`로 확인하라.
정답/힌트: 자기 프레임은 `msg_flags & MSG_CONFIRM`이 설정되어 온다. 송신 완료 확인 용도로 쓴다.

6. (관찰) 예제 11의 uevent 리스너를 켠 채 `echo change | sudo tee /sys/class/net/eth0/uevent`를 실행해 보라. 어떤 메시지가 오나?
정답/힌트: `change@/devices/.../net/eth0`. sysfs의 `uevent` 파일에 쓰면 커널이 이벤트를 다시 만든다(udev 디버깅·`udevadm trigger`의 원리, G9).

7. (개념) `ss -uanm`에서 `rb212992`인 소켓에 1206바이트 패킷이 몇 개 쌓일 수 있나? 64바이트 패킷이면?
정답/힌트: 1206바이트는 truesize 2304 기준 약 92개. 작은 패킷은 truesize가 payload보다 훨씬 커서(sk_buff 구조 + 최소 버퍼) 바이트 기준 계산보다 훨씬 적게 들어간다. 직접 `udp_tx`의 패킷 크기를 바꿔 `ss -m`의 `r`을 개수로 나눠 확인한다.

## 18. 용어 사전

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| address family | 주소 체계 | `socket()` 첫 인자. 반대편 서브시스템을 고른다(AF_INET, AF_CAN …) |
| ephemeral port | 임시 포트 | 클라이언트가 bind 없이 connect하면 커널이 자동 배정하는 포트 |
| 3-way handshake | 연결 수립 | SYN → SYN-ACK → ACK |
| TIME_WAIT | 종료 후 대기 상태 | 먼저 닫은 쪽이 60초간 포트를 붙잡는 상태 |
| backlog | 대기 큐 길이 | accept를 기다리는 완료 연결 큐의 길이 |
| framing | 메시지 경계 만들기 | 스트림 위에서 길이 접두·구분자로 메시지를 자르는 것 |
| datagram | 메시지 단위 패킷 | UDP·CAN처럼 보낸 단위 그대로 받는 패킷 |
| network byte order | 네트워크 바이트 순서 | big-endian. `htons`/`htonl`로 변환 |
| sk_buff (skb) | 소켓 버퍼 | 커널에서 패킷 하나를 담는 구조체. 헤더 포인터와 데이터 버퍼 |
| truesize | 실제 메모리 사용량 | skb 하나가 소켓 버퍼 한도에서 차지하는 바이트(payload보다 큼) |
| RcvbufErrors | 수신 버퍼 초과 drop | `/proc/net/snmp`의 UDP 카운터 |
| NAPI | 인터럽트 + 폴링 수신 | 인터럽트로 깨운 뒤 softirq에서 budget만큼 몰아 처리 |
| qdisc | 큐잉 규칙 | 송신 큐 정책(fq_codel, pfifo 등). `tc`로 설정 |
| SocketCAN | Linux CAN 서브시스템 | CAN 컨트롤러를 net_device로, 프레임을 소켓으로 다룸 |
| vcan | 가상 CAN | 하드웨어 없이 프레임을 되돌려 주는 테스트용 인터페이스 |
| netlink | 커널-유저 메시지 소켓 | `ip`, udev가 커널과 통신하는 AF_NETLINK 소켓 |
| rtnetlink | 라우팅 netlink | 링크·주소·라우트를 다루는 NETLINK_ROUTE |
| uevent | 장치 이벤트 | 장치 추가·제거 시 커널이 방송하는 "ACTION@DEVPATH" 메시지 |
| PHC | PTP 하드웨어 클럭 | NIC 안의 시계. 하드웨어 타임스탬프의 기준 |
| Nagle 알고리즘 | 작은 세그먼트 모으기 | `TCP_NODELAY`로 끔 |

## 19. 요약 & 체크리스트

소켓은 TCP/IP만을 위한 API가 아니라 커널 안의 통신 엔드포인트를 fd로 잡는 범용 손잡이다. 같은 `socket`/`bind`/`read`/`write`/`epoll`로 UDP(LiDAR), TCP(원격 툴), AF_PACKET(이더넷 프레임), AF_CAN(모터 버스), AF_NETLINK(커널 설정·hotplug), AF_UNIX(로컬 IPC)를 다룬다. TCP는 신뢰성 있는 바이트 스트림이라 애플리케이션 프레이밍이 필요하고, 상태 머신(LISTEN, ESTABLISHED, TIME_WAIT)을 `ss`·`tcpdump`로 읽을 수 있어야 한다. UDP는 메시지 경계를 보존하지만 수신 장비 안에서 소켓 버퍼가 넘치면 조용히 버려진다. 측정해 보면 1206바이트 패킷이 커널 메모리 2304바이트를 차지하고, burst에는 버퍼 크기가, 지속 과부하에는 처리 속도가 답이다. 커널 안에서는 `struct file` → `struct socket` → `struct sock` → 프로토콜 → net core → `net_device` 드라이버로 sk_buff가 오가고, 이 경로가 I6(네트워크 드라이버), G9(uevent), Q3(타임스탬프)로 이어진다.

- [ ] 소켓 fd가 `/proc/<pid>/fd`에서 `socket:[inode]`로 보이는 이유를 VFS 관점에서 설명할 수 있다
- [ ] TCP 서버/클라이언트를 에러 처리 포함해 처음부터 짤 수 있다
- [ ] `ss -tanp` 출력에서 LISTEN·ESTAB·TIME-WAIT과 Recv-Q/Send-Q 의미를 읽을 수 있다
- [ ] tcpdump 출력에서 3-way handshake와 FIN 교환을 찾을 수 있다
- [ ] TCP 프레이밍 문제를 설명하고 길이 접두 + `read_full`을 구현할 수 있다
- [ ] UDP 손실을 seq 번호, `ss -u -m`의 d, `RcvbufErrors`로 측정할 수 있다
- [ ] `SO_RCVBUF`가 2배로 기록되는 것과 truesize를 고려한 버퍼 계산을 설명할 수 있다
- [ ] 버퍼 크기로 해결되는 손실(burst)과 안 되는 손실(지속 과부하)을 구분할 수 있다
- [ ] `SO_REUSEADDR`, `TCP_NODELAY`, `SO_BINDTODEVICE`, `SO_TIMESTAMPNS`의 용도를 말할 수 있다
- [ ] vcan0을 만들고 SocketCAN으로 필터를 건 송수신 코드를 짤 수 있다
- [ ] netlink로 `ip`가 커널과 대화하는 방식과 uevent 메시지 형식을 설명할 수 있다
- [ ] UDP 패킷 수신 시 NIC → NAPI → ip_rcv → udp_rcv → 소켓 큐 경로를 그릴 수 있다
