# K2. BusyBox — 멀티콜 바이너리, init, mdev, 최소 이미지 만들기

## 0. 큰 그림 — 실행 파일 하나가 유저 공간 전부가 된다

SSD 펌웨어 디버그 콘솔을 떠올려 보자. UART로 `rd 0x4000_0000`, `nand_erase 12`, `log dump`를 치면, 펌웨어 안의 **명령 테이블**(`{"rd", cmd_rd}, {"log", cmd_log}, ...`)에서 이름을 찾아 함수 포인터를 호출한다. 명령이 백 개라도 바이너리는 하나다.

BusyBox는 이 구조를 Linux 유저 공간에 그대로 옮긴 것이다. `ls`, `sh`, `mount`, `init`, `mdev`, `udhcpc`, `devmem` … 400개 가까운 명령(BusyBox 용어로 **applet**)이 **실행 파일 하나** `/bin/busybox` 안에 들어 있고, `/bin/ls`, `/sbin/init` 같은 파일은 전부 그 하나를 가리키는 링크다. 커널이 `/sbin/init`을 실행하면 사실 busybox가 실행되고, busybox는 "내가 `init`이라는 이름으로 불렸구나"를 보고 `init_main()`을 호출한다.

그림 1 — 랩 rootfs의 실제 모습. 링크 402개가 실행 파일 하나를 가리킨다. 커널이 띄우는 PID 1(`/sbin/init`)도, 그 init이 띄우는 rcS·데몬·셸도 같은 바이너리다.

왜 이렇게 만들까? 세 가지 이유다.

- **크기**: 명령마다 별도 ELF를 만들면 ELF 헤더, C 런타임 시작 코드, libc 정적 링크분, 공통 유틸(옵션 파싱, 에러 출력)이 400번 반복된다. 하나로 합치면 공통 코드(`libbb`)가 한 번만 들어간다.
- **메모리**: 모든 프로세스가 같은 파일의 코드 페이지를 쓰므로 page cache에 한 벌만 올라간다(A5의 공유 매핑).
- **단순함**: rootfs에 넣을 파일이 "busybox 하나 + 링크 + 설정 파일 몇 개"로 끝난다. initramfs, 복구 이미지, 생산 테스트 이미지에 딱 맞다.

이 노트는 다음 순서로 간다: 멀티콜 디스패치(1절) → Kconfig 설정(2절) → static/dynamic과 libc(3절) → 크기 엔지니어링(4절) → BusyBox init(5절) → mdev(6절) → ash 함정(7절) → 임베디드용 applet(8절) → 최소 이미지와 사이징(9절) → 라이선스와 대안(10절).

실습 환경: Mac의 Lima VM `elinux`(aarch64, 커널 `7.0.0-38-generic`, gcc 15.2)에서 BusyBox 1.37.0을 빌드하고, 랩 커널(`/var/lab/out/Image`, `Image-sub` = 6.18.55)로 QEMU `virt` 보드에서 부팅한다. 랩 소스는 `/var/tmp/K2/src`로 복사해서 썼다.

## 1. 멀티콜 바이너리 — `argv[0]`으로 갈라지는 프로그램

### 1.1 직관 — 실행 파일 "이름"이 첫 번째 인자다

C 프로그램의 `main(int argc, char **argv)`에서 `argv[0]`은 "프로그램을 부른 이름"이다. 보통은 무시하지만, 셸이 `/bin/ls -l`을 실행하면 커널 `execve()`에 `argv = {"/bin/ls", "-l", NULL}`이 넘어간다. `/bin/ls`가 `busybox`를 가리키는 symlink여도 커널은 링크를 따라가 busybox ELF를 로드할 뿐, **`argv[0]`은 호출자가 준 `"/bin/ls"` 그대로** 둔다. 그러니 busybox의 `main()`은 `argv[0]`의 basename(`ls`)만 보면 무엇을 해야 할지 안다.

### 1.2 랩 rootfs에서 직접 보기

랩 rootfs의 링크와, symlink로 실행했을 때 `execve`에 무엇이 넘어가는지 확인한다.

출력에서 볼 것:

- `execve("inst/ls", ["inst/ls", ...])` — 커널은 symlink를 따라 busybox를 실행했지만 `argv[0]`은 `"inst/ls"` 그대로다. busybox는 이걸 보고 `ls`로 동작했다.
- `exec -a cat`(bash 기능: `argv[0]`만 바꿔 실행)만으로 busybox가 `cat`이 된다. 링크 파일 자체는 필요 없다. 이름이 전부다.
- 모르는 이름이면 `applet not found` + 종료 코드 127(셸의 "command not found"와 같은 값).
- 로그인 셸은 관례상 `argv[0]` 앞에 `-`가 붙는다(`-sh`). busybox는 이것을 떼고 `sh`를 찾는다. inittab의 `-/bin/sh`가 바로 이 관례다(5절).
- `--install -s DIR`은 `/proc/self/exe`로 자기 경로를 알아내 DIR에 symlink 402개를 만든다(403 = 링크 402 + busybox 자신).

### 1.3 40줄로 만드는 멀티콜 바이너리

같은 패턴을 C로 재현한다. 정렬된 applet 테이블 + `bsearch`, `busybox <applet>` 형태, 로그인 셸의 `-` 처리, 못 찾으면 127까지 BusyBox와 똑같이 했다.

```c
/* k2_multicall.c - BusyBox-style multi-call binary in ~40 lines */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <libgen.h>

static int hello_main(int argc, char **argv) { (void)argc; (void)argv;
	puts("hello from applet 'hello'"); return 0; }
static int add_main(int argc, char **argv) {
	if (argc != 3) { fprintf(stderr, "usage: add A B\n"); return 1; }
	printf("%ld\n", strtol(argv[1], NULL, 0) + strtol(argv[2], NULL, 0));
	return 0; }
static int upper_main(int argc, char **argv) {
	for (int i = 1; i < argc; i++) {
		for (char *p = argv[i]; *p; p++) putchar(*p >= 'a' && *p <= 'z' ? *p - 32 : *p);
		putchar(i + 1 < argc ? ' ' : '\n'); }
	return 0; }

/* applet table: sorted by name, like BusyBox's applet_names[] + applet_main[] */
static const struct { const char *name; int (*main)(int, char **); } applets[] = {
	{ "add", add_main }, { "hello", hello_main }, { "upper", upper_main },
};
#define N (sizeof(applets) / sizeof(applets[0]))

static int cmp(const void *key, const void *elem) {
	return strcmp(key, *(const char * const *)elem); }

int main(int argc, char **argv)
{
	char *name = basename(argv[0]);          /* "/usr/bin/add" -> "add" */
	if (name[0] == '-') name++;              /* login shells: "-sh" */
	if (strcmp(name, "k2_multicall") == 0) { /* "k2_multicall <applet> ..." */
		if (argc < 2) {
			for (size_t i = 0; i < N; i++) puts(applets[i].name);  /* --list */
			return 0; }
		argv++; argc--; name = argv[0]; }
	const void *a = bsearch(name, applets, N, sizeof(applets[0]), cmp);
	if (!a) { fprintf(stderr, "%s: applet not found\n", name); return 127; }
	return ((const typeof(applets[0]) *)a)->main(argc, argv);
}
```

symlink 두 개(`hello`, `add`)와 hardlink 한 개(`upper`)를 만들어 실행한다.

```sh

ln -sf k2_multicall hello && ln -sf k2_multicall add && ln -f k2_multicall upper
ls -li && ./hello && ./add 40 2 && ./upper busy box && ./k2_multicall add 0x10 1 && ./k2_multicall
cp k2_multicall nope && ./nope; echo "exit=$?"
```

### 1.4 BusyBox 진짜 코드 — 빌드가 만드는 applet 테이블

BusyBox는 각 applet 소스 파일 주석의 `//applet:` 줄(예: `//applet:IF_LS(APPLET_NOEXEC(ls, ls, BB_DIR_BIN, BB_SUID_DROP, ls))`)을 빌드 때 모아 `include/applet_tables.h`를 **생성**한다. 4절의 최소 빌드(applet 19개)에서 만들어진 파일 앞부분이다.

```text
/* This is a generated file, don't edit */
#define NUM_APPLETS 19
#define KNOWN_APPNAME_OFFSETS 0
const char applet_names[] ALIGN1 = ""
"ash" "\0"
"cat" "\0"
"dmesg" "\0"
...  (16줄 생략)
;
#define APPLET_NO_ash 0
...  (생략)
int (*const applet_main[])(int argc, char **argv) = {
ash_main,
cat_main,
dmesg_main,
echo_main,
halt_main,
init_main,
kill_main,
ls_main,
mdev_main,
mkdir_main,
mknod_main,
mount_main,
halt_main,
ps_main,
halt_main,
...
```

포인트 세 가지:

- 이름은 **NUL로 이어 붙인 문자열 하나**(`"ash\0cat\0dmesg\0..."`)에 정렬돼 들어 있다. 포인터 배열보다 작다(64비트에서 포인터 하나가 8바이트). 함수 테이블 `applet_main[]`은 같은 순서다. 내 C 장난감의 struct 배열을 "이름 블롭 + 함수 배열" 두 개로 쪼갠 모양이다.
- `poweroff`(12번)와 `reboot`(14번)가 `halt_main`을 공유한다. 함수 하나가 `applet_name`을 보고 동작을 바꾼다 — 멀티콜 안의 멀티콜이다.
- 디스패치 코드는 `libbb/appletlib.c`의 `main()` → `run_applet_and_exit()` → `find_applet_by_name()`(정렬된 이름 탐색) → `run_applet_no_and_exit()`다. `main()`에는 `if (applet_name[0] == '-') applet_name++;`와 `bb_basename()`이 그대로 있다.

### 1.5 링크를 까는 방법 네 가지

| 방식 | 만드는 법 | 장점 | 단점·주의 |
|---|---|---|---|
| symlink (기본) | `make install` (`CONFIG_INSTALL_APPLET_SYMLINKS=y`) | 눈에 보인다(`ls -l`이 `-> busybox`), 어떤 FS에서도 됨 | 링크마다 inode·디렉터리 엔트리 1개 |
| hardlink | `CONFIG_INSTALL_APPLET_HARDLINKS=y` | inode 하나, 링크 해석 단계 없음 | 같은 파일시스템 안에서만, busybox를 교체하면 링크도 같이 바뀜(이건 장점이기도) |
| 스크립트 래퍼 | `CONFIG_INSTALL_APPLET_SCRIPT_WRAPPERS=y` | 링크를 지원하지 않는 환경 | 실행마다 셸이 한 번 더 뜬다 |
| 링크 없음 | `busybox ls -l`, 또는 부팅 후 `busybox --install -s` | rootfs에 파일 1개 | 스크립트가 `/bin/ls` 같은 경로를 쓰면 실패, `--install`은 `/proc`이 마운트돼 있어야 함 |

`make install`은 `CONFIG_PREFIX`(기본 `./_install`) 아래에 `busybox.links`에 적힌 경로대로 링크를 깐다. 5절에서 쓸 rootfs를 이렇게 만들었다.

```sh
make -C /var/tmp/K2/b_def_static install CONFIG_PREFIX=/var/tmp/K2/rootfs > install.log 2>&1
grep -c -- "->" install.log; ls -l rootfs/sbin/init rootfs/linuxrc rootfs/sbin/devmem; tail -8 install.log | head -4
```

마지막 줄은 "busybox를 setuid root로 만들어야 할 수도 있다"는 경고다. `su`, `passwd`, `ping`(raw socket) 같은 applet이 root 권한을 요구하기 때문인데, 바이너리 하나에 setuid를 걸면 **모든 applet이 setuid**가 된다. 그래서 BusyBox는 `CONFIG_FEATURE_SUID`로 applet별 정책(`BB_SUID_DROP`/`BB_SUID_MAYBE`/`BB_SUID_REQUIRE`)을 두고, 필요 없는 applet은 시작하자마자 권한을 버린다. 대부분 임베디드 보드는 전부 root로 돌기 때문에 신경 안 쓰지만, 일반 사용자 계정이 있는 제품이면 보안 리뷰 항목이다.

### 1.6 함정

- `cp /bin/busybox /bin/myls`처럼 **이름을 바꿔 복사**하면 `myls: applet not found`. 디버깅할 때 바이너리 이름을 바꾸지 말 것.
- `ps`·`top`에 프로세스 이름이 `busybox`가 아니라 applet 이름으로 보인다(`argv[0]`이므로). 반대로 `pkill busybox`는 아무것도 못 죽인다.
- `/proc`이 없는 chroot에서 `busybox --install`이나 `FEATURE_PREFER_APPLETS`(2.3절)는 `/proc/self/exe`를 못 읽어 실패한다.

## 2. Kconfig로 설정하기

### 2.1 커널과 같은 Kconfig — defconfig, allnoconfig, menuconfig

BusyBox는 리눅스 커널의 Kconfig 시스템을 그대로 가져다 쓴다(E2). 명령도 같다.

| 명령 | 하는 일 | 언제 |
|---|---|---|
| `make defconfig` | 거의 모든 applet·기능을 켠다 (이번 빌드에서 `=y` 876개) | 개발용, "일단 다 있는" 셸 |
| `make allnoconfig` | 전부 끈다 (`=y` 0개에서 시작) | 제품용 최소 이미지의 출발점 |
| `make menuconfig` | ncurses 메뉴로 하나씩 켜고 끈다 | 사람이 고를 때 (이 노트에서는 대화형이라 실행하지 않았다) |
| `make oldconfig` | 기존 `.config`에 없는 새 항목만 묻는다 | 버전 업 후, sed로 고친 뒤 |
| `make O=<dir> ...` | 소스 밖 별도 디렉터리에 빌드 | 설정 여러 벌을 동시에 |

실무에서는 `menuconfig`로 고른 뒤 `.config`를 버전 관리에 넣고, 빌드 시스템(Buildroot `BR2_PACKAGE_BUSYBOX_CONFIG`, Yocto의 `defconfig` + config fragment `.cfg`)이 그것을 쓴다(K3, K4). 이 노트에서는 재현 가능하게 **스크립트로 `.config`를 고친다**. 최소 빌드 스크립트다.

```sh
#!/bin/bash
# allnoconfig + ~15 applets, static. $1 = build dir, $2 = extra make args (e.g. CC=musl-gcc)
set -e
S=/var/tmp/K2/src; B=$1; mkdir -p $B
make -C $S O=$B allnoconfig >/dev/null
for o in STATIC BUSYBOX FEATURE_INSTALLER LFS \
         SH_IS_ASH ASH ASH_JOB_CONTROL ASH_ECHO ASH_TEST ASH_PRINTF \
         CAT DMESG ECHO LS MKDIR MKNOD SLEEP UNAME KILL \
         MOUNT UMOUNT PS INIT FEATURE_USE_INITTAB FEATURE_KILL_REMOVED HALT POWEROFF REBOOT \
         MDEV FEATURE_MDEV_CONF FEATURE_MDEV_EXEC FEATURE_MDEV_LOAD_FIRMWARE; do
  sed -i "s/^# CONFIG_$o is not set/CONFIG_$o=y/" $B/.config
done
yes "" | make -C $B oldconfig >/dev/null 2>&1
( time make -C $B -j2 $2 ) > $B/build.log 2>&1
ls -l $B/busybox $B/busybox_unstripped
```

```text
-rwxrwxr-x 1 donh donh 1193592 Oct 17 17:39 /var/tmp/K2/b_min/busybox
-rwxrwxr-x 1 donh donh 1434928 Oct 17 17:39 /var/tmp/K2/b_min/busybox_unstripped
```

`--list`로 확인하면 applet 19개다(`ash cat dmesg echo halt init kill ls mdev mkdir mknod mount poweroff ps reboot sh sleep umount uname`). 설정 줄 수로 보면 defconfig는 `=y` 876 / 꺼짐 155, 이 최소 설정은 `=y` 40 / 꺼짐 991이다.

defconfig에는 두 가지를 껐다: `CONFIG_TC`(VM의 새 커널 헤더와 컴파일 충돌)와 `CONFIG_SHA1_HWACCEL`/`SHA256_HWACCEL`(랩 빌드와 같은 설정). 랩의 `.config`가 정확히 "defconfig + STATIC + 이 셋 끔"이라 내 빌드 결과가 랩 바이너리와 **바이트 단위로 같은 크기(2,242,744)** 가 나왔다.

> 함정: `sed`로 `.config`를 고친 뒤 `oldconfig`를 안 돌리면, 새로 켠 항목에 딸린 하위 항목(예: `ASH`를 켜면 생기는 `ASH_*` 질문)이 정의되지 않은 채 빌드된다. 커널 `.config`와 똑같다.

### 2.2 `FEATURE_*` — applet 안의 옵션들

applet 하나를 켜도 그 안의 기능은 `CONFIG_FEATURE_*`로 더 쪼개진다. defconfig에는 `FEATURE_` 항목이 409개 켜져 있다. 크기·호환성에 영향이 큰 것들이다.

| 옵션 | 켜면 | 끄면 | 판단 |
|---|---|---|---|
| `FEATURE_EDITING` (+`SAVEHISTORY`, `FANCY_PROMPT`) | 셸에서 화살표·히스토리·탭 완성 | 줄 편집 없음 | 시리얼 콘솔에서 사람이 쓰면 켠다 |

### 2.3 NOFORK / NOEXEC / PREFER_APPLETS — 셸이 applet을 부르는 세 가지 방법

셸 스크립트에서 `basename /a/b/c`를 부르면 원래는 `fork()` → 자식에서 `execve("/usr/bin/basename")` → busybox 시작 → `basename_main()`이다. BusyBox는 이 비용을 줄이는 두 단계 최적화가 있다.

- **NOEXEC** applet(`ls`, `seq` 등, 소스 기준 149개): `fork()`는 하지만 자식이 `execve` 없이 바로 `applet_main[]`을 호출한다. 이미 busybox가 메모리에 있으니까.
- **NOFORK** applet(`basename`, `echo`, `true`, `test`, `printf`, `mkdir`, `kill` 등 40개 — 소스의 `//applet:` 줄 중 `APPLET_NOFORK` 개수): `fork`도 안 한다. 셸 프로세스 안에서 함수처럼 호출하고 돌아온다. 그래서 NOFORK applet은 "메모리·fd를 새지 않고, 전역 상태를 바꾸지 않고, 오래 걸리지 않는" 것만 될 수 있다(소스의 `NOFORK_NOEXEC.lst`가 그 기준을 설명한다: interactive, leaks, longterm, hardware 등은 탈락).

이 둘은 `FEATURE_SH_STANDALONE`(셸이 PATH보다 applet을 먼저 찾음) + `FEATURE_SH_NOFORK` + `FEATURE_PREFER_APPLETS`(exec할 때 `/proc/self/exe`로 busybox를 다시 실행)를 켜야 동작한다. defconfig에서는 셋 다 **꺼져 있다**. 켠 빌드와 비교해 `clone`/`execve` 횟수를 `strace -c`로 센다.

```sh
# K2: count fork/exec when ash runs applets 200x, standard vs NOFORK/NOEXEC build
for b in b_def_static b_def_nofork; do
  BB=/var/tmp/K2/$b/busybox
  mkdir -p /var/tmp/K2/nf_$b && ln -sf $BB /var/tmp/K2/nf_$b/basename && ln -sf $BB /var/tmp/K2/nf_$b/seq
  S='i=0; while [ $i -lt 200 ]; do basename /a/b/c >/dev/null; seq 1 >/dev/null; i=$((i+1)); done'
  strace -f -c -e trace=clone,clone3,execve,wait4 -o /var/tmp/K2/nf_$b.txt env PATH=/var/tmp/K2/nf_$b $BB ash -c "$S"
  /usr/bin/time -f "$b: %e s elapsed" env PATH=/var/tmp/K2/nf_$b $BB ash -c "$S"
  grep -E "clone|execve|wait4" /var/tmp/K2/nf_$b.txt | awk -v b=$b '{print "  " b, $NF, "calls=" $(NF-1)}'
done
```

```text
b_def_static: 0.07 s elapsed
  b_def_static wait4 calls=400
  b_def_static clone calls=400
  b_def_static execve calls=402
b_def_nofork: 0.02 s elapsed
  b_def_nofork clone calls=200
  b_def_nofork wait4 calls=200
  b_def_nofork execve calls=2
```

출력에서 볼 것: 기본 빌드는 루프 200회 × 명령 2개 = 400번 fork + 400번 exec(+2는 `env`와 `ash` 자신). NOFORK 빌드는 `basename`(NOFORK)이 fork 0회, `seq`(NOEXEC)가 fork만 200회, exec는 0회다. 시간은 0.07 s → 0.02 s. M2 위 VM에서도 3배이고, QEMU TCG나 저클럭 Cortex-A7 보드에서는 fork+exec 비용이 훨씬 크므로 부팅 스크립트가 무거운 보드에서 의미 있는 최적화다.

## 3. static vs dynamic, glibc vs musl

### 3.1 static으로 빌드하는 이유

initramfs나 복구 이미지에는 `/lib/libc.so.6`과 동적 로더 `/lib/ld-linux-aarch64.so.1`이 없을 때가 많다. 동적 busybox를 넣으면 커널이 init을 실행하는 순간 로더를 못 찾아 **"Kernel panic - not syncing: No working init found"** 류로 끝난다(C7). 그래서 `CONFIG_STATIC=y`가 initramfs의 기본이다. 동적 빌드를 확인한다.

```sh
file b_def_dynamic/busybox; ldd b_def_dynamic/busybox
```

```text
b_def_dynamic/busybox: ELF 64-bit LSB pie executable, ARM aarch64, version 1 (SYSV), dynamically linked, interpreter /lib/ld-linux-aarch64.so.1, BuildID[sha1]=22dd659bfbd43d890fe7c2b9c26f7394c89244ab, for GNU/Linux 3.7.0, stripped
	linux-vdso.so.1 (0x0000e27bdacc8000)
	libm.so.6 => /usr/lib/aarch64-linux-gnu/libm.so.6 (0x0000e27bdaa70000)
	libresolv.so.2 => /usr/lib/aarch64-linux-gnu/libresolv.so.2 (0x0000e27bdaa40000)
	libc.so.6 => /usr/lib/aarch64-linux-gnu/libc.so.6 (0x0000e27bda870000)
	/lib/ld-linux-aarch64.so.1 (0x0000e27bdac80000)
```

동적 busybox 자체는 1.18 MB로 static(2.24 MB)보다 작지만, 이 네 라이브러리를 합치면 2,781,256바이트가 rootfs에 더 필요하다(VM에서 `ls -lL`로 합산). 이미 같은 libc를 쓰는 앱(센서 데몬, Qt UI)이 rootfs에 있다면 동적이 이득이고, busybox만 있는 initramfs라면 static이 이득이다.

### 3.2 glibc static의 경고 — NSS

glibc를 정적으로 링크하면 링커가 이런 경고를 남긴다. BusyBox는 링크 로그를 `busybox_unstripped.out`에 따로 저장하므로 거기서 찾는다.

```sh
grep -i "warning" b_def_static/busybox_unstripped.out | sed "s/.*: warning/warning/" | sort | uniq -c
```

```text
      1     *(.gnu.warning)
      1     /* .gnu.warning sections are handled specially by elf.em.  */
      1 warning: Using 'getaddrinfo' in statically linked applications requires at runtime the shared libraries from the glibc version used for linking
      1 warning: Using 'gethostbyaddr' in statically linked applications requires at runtime the shared libraries from the glibc version used for linking
      1 warning: Using 'gethostbyname' in statically linked applications requires at runtime the shared libraries from the glibc version used for linking
      1 warning: Using 'getservbyname' in statically linked applications requires at runtime the shared libraries from the glibc version used for linking
      1 warning: Using 'getservbyport' in statically linked applications requires at runtime the shared libraries from the glibc version used for linking
      1 warning: the use of `mktemp' is dangerous, better use `mkstemp' or `mkdtemp'
```

뜻: glibc의 이름 조회 함수(DNS `getaddrinfo`, 사용자 `getpwnam` 등)는 **NSS(Name Service Switch)** 로 구현된다. `/etc/nsswitch.conf`를 읽고 `libnss_dns.so`, `libnss_files.so` 같은 플러그인을 **실행 중에 `dlopen`** 한다. 정적 바이너리라도 이 순간엔 공유 라이브러리가 필요하고, 그것도 링크할 때와 같은 glibc 버전이어야 한다. initramfs에 그런 파일이 없으면 `wget http://host/`의 DNS 조회나 `ping hostname`이 조용히 실패한다(IP 주소는 된다).

`getpwnam` 경고가 없는 이유는 BusyBox defconfig가 `CONFIG_USE_BB_PWD_GRP=y`(자체 `/etc/passwd`·`/etc/group` 파서, `libpwdgrp/`)와 `USE_BB_SHADOW`, `USE_BB_CRYPT`를 켜서 glibc NSS를 아예 안 쓰기 때문이다. DNS 쪽은 그런 대체가 없다.

### 3.3 musl로 빌드하기

musl은 NSS가 없고(DNS는 libc 안에서 직접 `/etc/resolv.conf`를 읽는다) 정적 링크를 1급으로 지원하는 작은 libc다(B2). VM에 `musl-gcc` 래퍼가 있다. 단, musl-gcc는 리눅스 커널 헤더(`linux/*.h`)를 포함 경로에 넣지 않아서 처음엔 `init/init.c:134:11: fatal error: linux/vt.h: No such file or directory`로 실패했다. VM의 커널 헤더를 가리키는 디렉터리를 만들어 넘기면 된다.

```sh

  && ln -sfn /usr/include/aarch64-linux-gnu/asm asm && ln -sfn /usr/include/mtd mtd
/Users/donh/.elinux_scratch/K2/build_min.sh /var/tmp/K2/b_min_musl "CC=musl-gcc EXTRA_CFLAGS=-isystem/var/tmp/K2/kh"
file /var/tmp/K2/b_min_musl/busybox
```

### 4.2 링커 map으로 출처 나누기

BusyBox는 `busybox_unstripped.map`(GNU ld `-Map`)을 남긴다. 입력 섹션마다 어느 `.o`/`.a`에서 왔는지 적혀 있으니, 크기를 출처별로 합산한다.

```python
# sum allocated input-section sizes in a GNU ld map file by origin (busybox dir vs libc vs libgcc)
import re, sys, collections
tot = collections.Counter(); sec = None; in_mem = False
for line in open(sys.argv[1], errors="replace"):
    if line.startswith("Linker script and memory map"): in_mem = True; continue
    if not in_mem or line.startswith("/DISCARD/"): continue
    m = re.match(r"^ (\.\S+)\s*$", line)
    if m: sec = m.group(1); continue
    m = re.match(r"^ (\.\S+)?\s+0x([0-9a-f]+)\s+0x([0-9a-f]+)\s+(\S+)", line)
    if not m: continue
    s = m.group(1) or sec; size = int(m.group(3), 16); path = m.group(4)
    if not s or not s.startswith((".text", ".rodata", ".data", ".eh_frame", ".gcc_except", ".tdata", ".init_array", ".fini_array")) or size == 0: continue
    if "libc.a" in path or "/musl/" in path: k = "libc"
    elif "libgcc" in path or "crt" in path: k = "libgcc/crt"
    elif "libm.a" in path or "libresolv" in path: k = "libm/resolv"
    else: k = "busybox:" + path.split("/")[0].split("(")[0].split(".")[0]
    tot[k] += size
bb = sum(v for k, v in tot.items() if k.startswith("busybox:"))
print("busybox_code", bb)
for k, v in tot.most_common():
    if not k.startswith("busybox:"): print(k, v)
for k, v in [kv for kv in tot.most_common() if kv[0].startswith("busybox:")][:6]: print(" ", k, v)
```

### 4.3 크기 줄이는 순서 (효과 큰 것부터)

1. **libc를 고른다** — glibc → musl(또는 uClibc-ng). 최소 빌드에서 3.6배.
2. **applet을 고른다** — allnoconfig에서 시작해 필요한 것만. defconfig 대비 musl에서 4배.
3. **`FEATURE_*`를 끈다** — 셸 편집, 긴 도움말, 유니코드, 긴 옵션.
4. **`-Oz`/`-Os` 유지 + strip** — 기본값이므로 망치지만 않으면 된다.
5. (커널이 지원하면) **압축된 initramfs**로 넣는다 — 9절에서 musl 최소 rootfs가 gzip -9로 330 KB → 166 KB.

크기만이 아니라 **실행 중 메모리**도 따라 준다. 같은 init이 glibc static 빌드에서는 VSZ 3280 KB, musl 최소 빌드에서는 468 KB로 보였다(9절 `ps` 출력).

## 5. BusyBox init — inittab 하나로 도는 작은 슈퍼바이저

C7에서 BusyBox init과 respawn·getty를 처음 봤다. 여기서는 **액션 8종 전부와 시그널 처리**를 한 번에 돌려 보고, init의 생애를 그림으로 정리한다. PID 1의 일반적 책임(좀비 회수, 절대 exit 금지)은 K1·C7 참고.

### 5.1 inittab 문법

한 줄 형식은 `<id>::<action>:<process>`다. SysV init의 `id:runlevels:action:process`와 모양은 같지만 **runlevel 칸은 완전히 무시**된다(BusyBox `init` 도움말에 그렇게 적혀 있다). `id` 칸은 BusyBox에서 "그 프로세스의 제어 터미널(tty)"이다. 비어 있으면 init 자신의 콘솔(`/dev/console`)을 물려준다.

| action | 언제 실행 | init이 기다리나 | 죽으면 | 전형적인 용도 |
|---|---|---|---|---|
| `sysinit` | 부팅 직후 가장 먼저 | 예 (하나씩 끝까지) | 끝 | `/etc/init.d/rcS` |
| `wait` | sysinit 다음 | 예 | 끝 | 순서가 중요한 일회성 작업 |
| `once` | wait 다음 | 아니오 | 끝 | 백그라운드 일회성 작업 |
| `respawn` | once 다음, 계속 | 아니오 | **다시 띄움** | 데몬, `getty` |
| `askfirst` | respawn과 같이 | 아니오 | 다시 띄움 | "Enter를 누르면" 셸 (개발용 콘솔) |
| `ctrlaltdel` | init이 SIGINT를 받으면 | 예 | 끝 | 보통 `/sbin/reboot` |
| `shutdown` | halt/poweroff/reboot/restart 직전 | 예 (줄 순서대로) | 끝 | 데몬 정지, `umount -a -r`, `swapoff -a` |
| `restart` | init이 SIGQUIT을 받으면 | — | init 자리를 `exec`로 차지 | 보통 `/sbin/init` (inittab 새로 적용) |

inittab 파일이 **없으면** init은 기본값을 쓴다(`init/init.c`): sysinit `/etc/init.d/rcS`, 콘솔과 tty2~4에 askfirst 셸, ctrlaltdel `reboot`, shutdown `umount -a -r`와 `swapoff -a`, restart `init`. 커널 커맨드라인에 `single`이 있으면 respawn 셸 하나만 띄운다.

### 5.2 실습 보드의 파일들

센서 키트 보드를 흉내 낸 inittab이다. 모든 액션을 한 번씩 넣었다.

```text
# K2 /etc/inittab   format: <tty>::<action>:<process>
::sysinit:/etc/init.d/rcS
::wait:/bin/echo "K2 wait: init blocks until this exits"
::once:/bin/echo "K2 once: started, init does not wait"
::respawn:/usr/bin/k2_sensord
ttyAMA0::askfirst:-/bin/sh
::ctrlaltdel:/bin/echo "K2 ctrlaltdel: init got SIGINT"
::restart:/sbin/init
::shutdown:/bin/echo "K2 shutdown: stopping services, syncing"
::shutdown:/bin/umount -a -r
```

rcS는 가상 FS를 마운트하고, `/dev`를 비어 있는 tmpfs로 덮은 뒤 mdev로 채우고(6절), syslogd·klogd를 띄운다(8절).

```sh
#!/bin/sh
# K2 rcS: run once by init (sysinit action)
mount -t proc proc /proc
mount -t sysfs sysfs /sys
echo "K2 rcS: /dev before: $(ls /dev)"
mount -t tmpfs -o size=64k,mode=0755 tmpfs /dev
mkdir -p /dev/pts && mount -t devpts devpts /dev/pts
if [ -e /proc/sys/kernel/hotplug ]; then echo /sbin/mdev > /proc/sys/kernel/hotplug
else echo "K2 rcS: no /proc/sys/kernel/hotplug -> using mdev -d (netlink)"; fi
mdev -d                      # initial scan of /sys, then daemon on uevent netlink
echo "K2 rcS: /dev after mdev: $(ls /dev | wc -l) entries"
syslogd -C64 -L              # 64 KiB shm ring buffer (logread). -L: 1.37.0 bug workaround
klogd                        # kernel printk -> syslog
hostname k2-board
echo "K2 rcS: done uptime=$(cut -d' ' -f1 /proc/uptime)"
```

가짜 센서 데몬(3초마다 syslog에 샘플 기록):

```sh
#!/bin/sh
# toy sensor daemon: logs a sample every 3 s
logger -t k2_sensord "started pid=$$"
echo "k2_sensord: started pid=$$"
n=0
while true; do n=$((n + 1)); logger -t k2_sensord "sample $n"; sleep 3; done
```

rootfs = 내 defconfig static busybox의 `make install` + 위 파일들 + `/etc/passwd`·`/etc/group`(`disk:x:6:` 포함) + `null_blk.ko`·`softdog.ko`와 `modules.dep`(랩 `modules-sub`에서 복사). `cpio -H newc`로 묶은 `k2_init.cpio.gz`는 1,850,945바이트. 커널은 모듈과 vermagic이 맞는 `Image-sub`, 인자는 `rdinit=/sbin/init`(initramfs의 `/init` 대신 BusyBox init을 PID 1로).

### 5.3 QEMU에서 전 과정 돌리기

`expect`로 콘솔을 자동 조작한다: Enter(askfirst) → 프로세스 확인 → 데몬 죽이기(respawn) → inittab에 줄 추가 후 SIGHUP → mdev 핫플러그(6절) → 로그(8절) → SIGINT(ctrlaltdel) → SIGQUIT(restart) → `poweroff`.

```text
set timeout 90
spawn qemu-system-aarch64 -machine virt -cpu cortex-a57 -m 512M -nographic -no-reboot -kernel /var/lab/out/Image-sub -initrd /var/tmp/K2/k2_init.cpio.gz -append "console=ttyAMA0 quiet rdinit=/sbin/init"
expect "Please press Enter to activate this console."
sleep 2
send "\r"
expect "# "
send "kill \$(pgrep -f k2_sensord); sleep 2; pgrep -f k2_sensord\r"
expect "# "
...  (같은 send/expect 쌍이 아래 출력의 명령마다 반복된다)
send "kill -QUIT 1\r"
expect "Please press Enter to activate this console."
...
send "poweroff\r"
expect "Power down"
```

(실제 스크립트에는 SIGQUIT 뒤에 `ps` 한 줄이 더 있었는데 정규식 따옴표 실수로 `grep: bad regex`가 나서 출력에서 뺐다.) 부팅부터 첫 셸까지의 출력:

출력에서 볼 것:

- 순서가 표와 같다: rcS(sysinit)가 다 끝난 뒤 `wait` 줄, 그 다음 `once`와 respawn·askfirst가 거의 동시에 시작했다(`Please press Enter`와 `K2 once`가 한 줄에 섞였다 — 기다리지 않으니까).
- `mdev`, `syslogd`, `klogd`는 rcS가 띄웠지만 스스로 데몬화(fork 후 부모 종료)했기 때문에 **고아가 되어 PPID 1**로 입양됐다. respawn 대상은 아니다 — 죽으면 그대로 끝이다. 죽어도 다시 떠야 하는 데몬은 데몬화 옵션 없이(`-n`) inittab respawn에 직접 넣는 게 맞다.
- 셸 `-/bin/sh`의 `argv[0]`이 `-`로 시작한다 — 로그인 셸 표시(1.2절).

respawn과 SIGHUP:

```text
~ # kill $(pgrep -f k2_sensord); sleep 2; pgrep -f k2_sensord
k2_sensord: started pid=83
83
~ # echo '::respawn:/bin/sleep 1000' >> /etc/inittab; kill -HUP 1; sleep 1; pgre
p -l sleep
86 sleep
89 /bin/sleep
```

데몬을 죽이자 init이 PID 83으로 다시 띄웠다. 처음엔 `sleep 1`로 확인했다가 아직 안 떠서 빈 결과가 나왔는데, syslog를 보면 이유가 있다: init은 `process '/usr/bin/k2_sensord' (pid 72) exited. Scheduling for restart.`를 남기고 **약 1초 뒤** 다시 띄운다(아래 logread 출력의 00:47:29 → 00:47:30). init의 메인 루프가 한 바퀴마다 `sleep1()`(소스 주석: "Don't consume all CPU time - sleep a bit")을 하기 때문이고, 계속 죽는 프로세스가 CPU를 태우지 않게 하는 효과가 있다. inittab에 줄을 추가하고 `kill -HUP 1`을 보내자 새 respawn 항목(`/bin/sleep 1000`, PID 89)이 바로 떴다 — 재부팅 없이 inittab 반영.

### 5.4 askfirst, getty, 콘솔

- `askfirst`는 tty에 "Please press Enter to activate this console."을 찍고 Enter를 기다린 뒤 셸을 띄운다. 부팅 로그가 셸 프롬프트와 섞이지 않고, 아무도 시리얼에 안 붙어 있으면 셸 프로세스가 아예 안 생긴다. 개발 보드용이다.
- 제품에서는 보통 `ttyAMA0::respawn:/sbin/getty -L 115200 ttyAMA0 vt100`(로그인 프롬프트, C7 실습) 또는 콘솔 셸을 아예 없앤다(보안, L 모듈).
- tty 칸에 `ttyAMA0`을 적었으므로 init은 `/dev/ttyAMA0`을 열어 셸에 준다. **이 노드는 rcS의 mdev가 만들었다.** mdev가 실패하면 셸이 안 뜬다 — "커널 로그는 다 나왔는데 프롬프트가 안 나온다"의 단골 원인이다. 반대로 tty 칸을 비우면 init이 부팅 때 받은 `/dev/console`을 그대로 쓴다.
- `/dev/console` 자체는 어디서 왔나? `/dev before: console`이 보여 준다. 커널에 내장된 기본 initramfs(`usr/default_cpio_list`)에 `/dev/console` 노드가 들어 있어서, 내 cpio에 `/dev`가 비어 있어도 PID 1이 stdin/stdout/stderr를 열 수 있었다(K1의 장치 노드 절 참고).

## 6. mdev — udev 없이 `/dev` 만들기

### 6.1 세 가지 선택지

| 방식 | 누가 노드를 만드나 | 이름·권한 규칙 | 크기·의존성 | 쓰는 곳 |
|---|---|---|---|---|
| 정적 `/dev` | 이미지 빌드 때 `mknod` | 고정 | 0 | 아주 작은 고정 HW |
| devtmpfs | 커널이 직접 (`devtmpfs_create_node`) | 커널 기본 이름, 권한 0600 위주 | 커널 옵션 하나 | 거의 모든 시스템의 바닥 |
| mdev (BusyBox) | 유저 공간, `mdev.conf` 규칙 | 정규식 규칙, symlink, 스크립트 | busybox 안 | initramfs, 작은 제품 |
| udev (systemd-udevd) | 유저 공간, rule 파일 | 매우 풍부 (속성 매치, persistent 이름) | systemd 의존 | 큰 배포판, L2 |

보통은 devtmpfs + (mdev 또는 udev)를 같이 쓴다. devtmpfs가 노드를 즉시 만들어 부팅을 보장하고, mdev/udev가 그 위에서 권한·이름·symlink를 손본다. 이 실습은 mdev만으로 얼마나 되는지 보려고 **devtmpfs를 일부러 안 쓰고** 빈 tmpfs에서 시작했다. 참고로 커널의 `CONFIG_DEVTMPFS_MOUNT=y`는 커널이 블록 장치 rootfs를 마운트할 때만 `/dev`에 devtmpfs를 자동 마운트한다(`init/do_mounts.c`의 `devtmpfs_mount()`). initramfs에서는 직접 마운트해야 한다.

### 6.2 uevent가 유저 공간에 오는 두 길 — 그리고 한쪽이 닫혀 있다

드라이버가 `device_add()`를 하면 커널은 `kobject_uevent_env()`로 이벤트(`ACTION=add`, `DEVPATH`, `SUBSYSTEM`, `MAJOR`, `MINOR`, `DEVNAME` …)를 만들어 두 군데로 보낸다(`lib/kobject_uevent.c`).

1. **netlink 브로드캐스트** (`NETLINK_KOBJECT_UEVENT`) — 듣는 데몬(udevd, `mdev -d`)이 받는다.
2. **uevent helper** — `/proc/sys/kernel/hotplug`(= `/sys/kernel/uevent_helper`)에 적힌 프로그램을 이벤트마다 `call_usermodehelper`로 실행. 고전적인 `echo /sbin/mdev > /proc/sys/kernel/hotplug`가 이것이다.

BusyBox의 `docs/mdev.txt`와 `mdev --help`는 아직 2번 방식을 먼저 소개한다. 그런데 랩 커널 설정을 보면:

```text
# CONFIG_UEVENT_HELPER is not set
```

그래서 위 rcS 출력에 `no /proc/sys/kernel/hotplug -> using mdev -d (netlink)`가 찍혔고, 셸에서 확인해도 파일이 없다.

```text
~ # ls /proc/sys/kernel/hotplug; ls -l --color=never /dev/console /dev/ttyAMA0 /
dev/null
ls: /proc/sys/kernel/hotplug: No such file or directory
crw-rw----    1 root     root        5,   1 Oct 18 00:44 /dev/console
crw-rw-rw-    1 root     root        1,   3 Oct 18 00:44 /dev/null
crw-rw----    1 root     root      204,  64 Oct 18 00:44 /dev/ttyAMA0
```

arm64 defconfig처럼 최근 설정에서는 uevent helper가 꺼져 있는 경우가 많다(이벤트마다 프로세스를 fork하는 비용, 순서 뒤섞임 문제 때문). 그래서 요즘 BusyBox 시스템은 **`mdev -d`(netlink 데몬 모드, `FEATURE_MDEV_DAEMON`)** 를 쓴다. `mdev -d`는 소켓을 먼저 열고 → `/sys`를 한 번 훑어(= `mdev -s`) 이미 있는 장치 노드를 만들고 → 그 다음에 fork해서 데몬이 된다(`util-linux/mdev.c`의 `daemon_init()` 주석: "Make initial scan after the uevent socket is alive and before we fork away"). 소켓을 먼저 열기 때문에 스캔 도중 생긴 장치도 놓치지 않는다. 위 출력에서 `/dev`가 1개(console) → 140개가 된 것이 그 초기 스캔이고, `null`이 `666`인 것은 아래 `mdev.conf` 규칙 덕이다.

### 6.3 `mdev.conf` 문법

한 줄 형식: `[-][ENV=regex;]<장치 정규식> <user>:<group> <mode> [=경로 또는 >경로 또는 !] [@ 또는 $ 또는 * 명령]`

| 부분 | 뜻 |
|---|---|
| `nullb([0-9]+)` | 장치 이름 정규식. 괄호 그룹은 `%1`, `%2`로 경로에 쓴다. `@major,minor` 또는 `$ENV=regex`로도 매치 가능 |
| `root:disk 640` | 소유자·그룹·권한 (이름은 `/etc/passwd`·`/etc/group`에서 찾는다) |
| `=path` | 노드를 그 이름/디렉터리(끝에 `/`)로 옮긴다 |
| `>path` | 옮기고, 원래 이름으로 symlink도 만든다 |
| `!` | 노드를 만들지 않는다 |
| `@cmd` / `$cmd` / `*cmd` | 만든 뒤 / 지우기 전 / 둘 다 실행. `system()`이라 `/bin/sh` 필요, stdio는 `/dev/null`, 환경 변수 `MDEV`·`ACTION`·`DEVPATH`·`SUBSYSTEM` |
| 줄 앞 `-` | 매치돼도 멈추지 않고 다음 줄도 본다 (기본은 첫 매치에서 멈춤) |

실습 보드의 규칙:

```text
# K2 /etc/mdev.conf  <regex> <user>:<group> <mode> [=path|>path|!] [@|$|*cmd]
null            root:root 666
zero            root:root 666
nullb([0-9]+)   root:disk 640 >k2/sensor_disk%1 */etc/mdev/k2_disk.sh
watchdog[0-9]*  root:root 600
.*              root:root 660
```

`k2_disk.sh`는 mdev가 넘겨주는 환경 변수를 syslog로 남긴다(stdio가 `/dev/null`이므로 `echo`는 안 보인다).

```sh
#!/bin/sh
# run by mdev (* = on add and remove); stdio is /dev/null, so log to syslog
logger -t k2_mdev "ACTION=$ACTION MDEV=$MDEV DEVPATH=$DEVPATH SUBSYSTEM=$SUBSYSTEM"
```

`null_blk`(메모리 없는 가짜 블록 장치 드라이버)를 장치 2개로 로드했다가 내린다. BusyBox `modprobe`가 `/lib/modules/6.18.55-sub/modules.dep`을 읽어 경로를 찾는다.

출력에서 볼 것:

### 6.5 그 밖의 mdev 기능 (이번엔 실행하지 않음)

- **모듈 자동 로드**: `$MODALIAS=.* root:root 660 @modprobe "$MODALIAS"` 한 줄이면 장치가 나타날 때 드라이버 모듈을 로드한다(udev의 기본 동작, G9의 `MODULE_DEVICE_TABLE` → modalias). `mdev --help`에 이 예가 그대로 있다.
- **펌웨어 로딩**: `FEATURE_MDEV_LOAD_FIRMWARE`. 커널이 `SUBSYSTEM=firmware` 이벤트에 `FIRMWARE=<파일명>`을 실어 보내면, mdev가 `/lib/firmware/<파일명>`을 열어 `/sys/$DEVPATH/loading`에 1 → `data`에 내용 → `loading`에 0을 쓴다(`mdev.c`의 `load_firmware()`). 다만 이것은 커널의 **sysfs fallback** 경로이고, 요즘 커널은 `request_firmware()`가 먼저 `/lib/firmware`를 커널 안에서 직접 읽는다. 랩 커널도 `CONFIG_FW_LOADER_USER_HELPER=y`지만 `_FALLBACK`은 꺼져 있어, 보통 드라이버에서는 이 경로가 쓰이지 않는다. 자세한 흐름은 G10.
- **순서 보장**: `/dev/mdev.seq` 파일을 만들어 두면 helper 방식에서 `SEQNUM` 순서대로 처리한다. `mdev -d`는 이벤트를 소켓에서 순서대로 읽으므로 이 문제가 덜하다.

## 7. ash 스크립트 함정 — "내 PC에선 되는데 보드에선 안 돼요"

보드의 `/bin/sh`는 BusyBox **ash**(Almquist shell 계열)다. bash가 아니다. 더 큰 함정은 **같은 ash라도 BusyBox 설정에 따라 문법이 달라진다**는 것이다. 같은 스니펫을 bash와 defconfig ash에 돌렸다.

```sh
# K2: run the same snippets in bash and BusyBox ash
BB=/var/tmp/K2/b_def_static/busybox
t() { printf '%-34s bash: %-22s ash: %s\n' "$1" \
      "$(bash -c "$1" 2>&1 | head -1)" "$($BB ash -c "$1" 2>&1 | head -1)"; }
t 'a=(x y z); echo ${a[1]}'
t 'echo {1..3}'
t '[[ abc == a* ]] && echo match'
t 's=hello; echo ${s//l/L}'
t 's=hello; echo ${s:1:3}'
t 'echo -e "a\tb" | od -c | head -1'
t 'n=0; printf "1\n2\n" | while read x; do n=$((n+1)); done; echo n=$n'
t 'cat <(echo procsub)'
t 'echo $((2**10))'
t 'f() { local v=1; echo v=$v; }; f'
t 'function g { echo kw; }; g'
t 'echo $RANDOM | grep -cE "^[0-9]+$"'
t 'set -o pipefail; false | true; echo rc=$?'
t 'read -t 1 -r x < /dev/null; echo rc=$?'
t 'declare -A m; m[k]=v; echo ${m[k]}'
t 'echo ${BASH_VERSION:-none}'
t 'x=abc; echo ${x^^}'
```

출력에서 볼 것과 규칙:

- **배열, 연관 배열(`declare -A`), 중괄호 확장 `{1..3}`, 대소문자 변환 `${x^^}`은 ash에 없다.** 빌드 옵션과 무관하게 안 된다.
- `[[ ]]`, `${s//a/b}`, `${s:1:3}`, `<(...)`, `function` 키워드는 **BusyBox 빌드 설정에 달렸다.** 개발 보드(defconfig)에서 되던 스크립트가 양산 이미지(최소 설정)에서 `syntax error`로 죽는다. `$RANDOM`은 에러도 없이 빈 문자열이 된다 — 더 위험하다.
- 파이프 안의 `while read`는 bash와 ash 모두 서브셸이라 `n=0`이다(bash `lastpipe` 기본 꺼짐). 흔한 오해.
- `local`은 POSIX가 아니지만 ash·dash·bash 모두 지원한다. `#!/bin/sh` 스크립트의 사실상 표준.

실무 규칙: 보드에서 도는 스크립트는 **`#!/bin/sh` + POSIX 문법**으로 쓰고, 개발 PC에서 `dash -n`이나 `shellcheck -s sh`로 검사한다. bash가 꼭 필요하면 이미지에 bash를 넣고 `#!/bin/bash`라고 명시한다.

```sh
#!/bin/sh

mount -t tmpfs t /dev; /var/tmp/K2/b_def_static/busybox mknod /dev/null c 1 3
BB=/var/tmp/K2/b_def_static/busybox
for flags in "-n" "-n -L"; do
  rm -f /var/tmp/K2/sl.out
  $BB syslogd $flags -O /var/tmp/K2/sl.out & P=$!
  sleep 0.5; $BB logger -t k2 "hello (syslogd $flags)"; sleep 0.5; kill $P; wait $P 2>/dev/null
  echo "== syslogd $flags"; cut -c17- /var/tmp/K2/sl.out
done
```

### 8.2 udhcpc와 default.script

`udhcpc`는 DHCP 프로토콜만 처리하고, **IP 설정은 스크립트에 맡긴다**. 이벤트(`deconfig`, `bound`, `renew`, `leasefail`, `nak`)마다 `/usr/share/udhcpc/default.script <이벤트>`를 실행하고, 받은 값은 환경 변수(`ip`, `subnet`, `router`, `dns`, `lease`, `interface` …)로 준다. BusyBox 소스의 `examples/udhcp/simple.script`를 `simple.script`로 넣고, 앞에 값을 찍는 훅을 두었다.

```sh
#!/bin/sh
# K2 udhcpc hook: udhcpc calls this with $1 = deconfig|bound|renew|leasefail|nak
echo "K2 dhcp-hook: $1 iface=$interface ip=$ip subnet=$subnet router=$router dns=$dns lease=$lease"
exec /usr/share/udhcpc/simple.script "$@"
```

QEMU에 사용자 모드 네트워크(`-netdev user,id=n0 -device virtio-net-device,netdev=n0`)를 붙이면 QEMU 내장 DHCP 서버(10.0.2.2)가 응답한다.

### 8.3 devmem — 유저 공간에서 레지스터 peek/poke

`devmem ADDRESS [WIDTH [VALUE]]`는 `/dev/mem`을 `mmap`해 물리 주소를 읽고 쓴다. Don이 JTAG으로 하던 레지스터 peek을 셸에서 하는 도구다. `out/virt.dts`에서 주소를 찾는다.

```dts
	pl011@9000000 {
		clock-names = "uartclk", "apb_pclk";
		clocks = <0x8000 0x8000>;
		interrupts = <0x00 0x01 0x04>;
		reg = <0x00 0x9000000 0x00 0x1000>;
		compatible = "arm,pl011", "arm,primecell";
	};
```

PrimeCell 주변장치는 블록 끝(오프셋 `0xFE0`~`0xFFC`)에 PeriphID0~3, PCellID0~3 레지스터가 있다. PL011 UART와 PL061 GPIO(`pl061@9030000`)의 ID, 그리고 UART Flag Register(`UARTFR`, 오프셋 `0x18`)를 읽는다.

```text
~ # for o in fe0 fe4 fe8 fec ff0 ff4 ff8 ffc; do printf '%s ' $(devmem 0x09000$o
 32); done; echo
0x00000011 0x00000010 0x00000014 0x00000000 0x0000000D 0x000000F0 0x00000005 0x000000B1 
~ # for o in fe0 fe4 fe8 fec; do printf '%s ' $(devmem 0x09030$o 32); done; echo
; devmem 0x09000018 16
0x00000061 0x00000010 0x00000004 0x00000000 
0x0090
```

출력에서 볼 것: PL011의 PeriphID 하위 바이트 `0x11, 0x10, 0x14, 0x00` → part number `0x011`, designer `0x41`(ARM), PCellID `0x0D, 0xF0, 0x05, 0xB1`은 모든 PrimeCell 공통 값이다. PL061은 part `0x061`. 커널의 AMBA 버스가 장치를 식별할 때 읽는 바로 그 레지스터다(D3, `amba_read_periphid` — 랩 README의 패닉 메시지에도 나오는 함수). `UARTFR=0x0090`은 비트 7(TXFE, 송신 FIFO 빔)과 비트 4(RXFE, 수신 FIFO 빔)가 켜진 상태다.

이게 되는 이유는 랩 커널이 `CONFIG_STRICT_DEVMEM=y`지만 `# CONFIG_IO_STRICT_DEVMEM is not set`이기 때문이다. STRICT_DEVMEM은 일반 RAM 접근을 막고, IO_STRICT_DEVMEM까지 켜면 **드라이버가 이미 잡은 MMIO 영역**(여기선 pl011 드라이버가 잡은 UART)도 막는다. 양산 커널에서는 둘 다 켜는 게 보안상 맞고, 그러면 devmem은 bring-up 전용 커널에서만 쓴다. 쓰기(`devmem ADDR 32 VALUE`)는 드라이버와 경합하므로 bring-up 초기 확인 용도로만 쓴다(H1).

### 8.4 watchdog — 유저 공간 데몬이 개를 쓰다듬는다

`watchdog -T <타임아웃> -t <킥 주기> /dev/watchdog`은 `/dev/watchdog`을 열고 `WDIOC_SETTIMEOUT`으로 타임아웃을 정한 뒤 주기적으로 킥한다. 하드웨어 워치독 대신 커널의 `softdog`(타이머 기반 가짜 워치독, 만료 시 재부팅)으로 실험했다.

```text
~ # modprobe softdog soft_margin=5; watchdog -T 5 -t 1 /dev/watchdog; sleep 1; p
grep -l watchdog
37 watchdogd
111 watchdog
~ # kill -TERM $(pgrep -x watchdog); sleep 7; echo still-alive-after-TERM; dmesg
 | tail -2
still-alive-after-TERM
[    3.482380] softdog: initialized. soft_noboot=0 soft_margin=5 sec soft_panic=0 (nowayout=0)
[    3.482442] softdog:              soft_reboot_cmd=<not set> soft_active_on_boot=0
~ # watchdog -T 5 -t 1 /dev/watchdog; sleep 1; kill -KILL $(pgrep -x watchdog); 
echo killed-at=$(cut -d' ' -f1 /proc/uptime)
[   12.656793] watchdog: watchdog0: watchdog did not stop!
killed-at=12.61
```

`kill -KILL` 후 시간을 따로 쟀다(`loglevel=7`로 다시 부팅, expect가 QEMU 종료까지 측정):

```text
[    4.354221] watchdog: watchdog0: watchdog did not stop!
killed-at=4.31
~ # 
K2 host: qemu exited 6123 ms after kill -KILL
```

출력에서 볼 것:

- `37 watchdogd`는 커널 스레드(워치독 코어의 ping 워커), `111 watchdog`이 BusyBox 데몬이다. 이름이 비슷해 헷갈리기 쉽다.
- **SIGTERM**: BusyBox watchdog은 시그널 핸들러에서 **magic close**(`'V'`를 쓰고 닫기)를 한다. `nowayout=0`이므로 커널이 타이머를 멈춰 7초 뒤에도 살아 있다.
- **SIGKILL**: 핸들러가 못 돈다. fd가 magic close 없이 닫히자 커널이 `watchdog did not stop!`(`drivers/watchdog/watchdog_dev.c`)을 찍고 타이머를 유지했고, 약 5초 + QEMU 종료 시간 후 보드가 리셋됐다(`-no-reboot`라 QEMU가 종료). 데몬이 행(hang)되거나 죽는 상황을 그대로 흉내 낸 것이다. softdog의 `Initiating system reboot` 메시지는 콘솔에 나오기 전에 리셋돼 보이지 않았다.
- 양산에서는 `CONFIG_WATCHDOG_NOWAYOUT=y`로 magic close도 막아 "한 번 켜면 못 끈다"로 만들고, 단순히 "살아 있으면 킥"이 아니라 **앱의 건강 상태를 확인한 뒤 킥**하도록 설계한다(I9, L1의 systemd watchdog 연동).

## 9. 최소 이미지 만들기와 사이징

### 9.1 musl 최소 initramfs를 실제로 부팅

applet 19개짜리 musl busybox(329 KB)로 initramfs를 만들고, inittab에서 정보를 찍은 뒤 끈다.

```sh
#!/bin/bash
# minimal initramfs: allnoconfig+19 applets musl static busybox, BusyBox init, then poweroff
set -e
cd /var/tmp/K2; rm -rf minroot; mkdir -p minroot/{bin,sbin,etc/init.d,proc,sys,dev}
make -C b_min_musl install CONFIG_PREFIX=/var/tmp/K2/minroot CC=musl-gcc EXTRA_CFLAGS=-isystem/var/tmp/K2/kh >/dev/null 2>&1
cat > minroot/etc/inittab <<'X'
::sysinit:/etc/init.d/rcS
::once:/bin/sh -c 'echo K2-MIN applets: $(busybox --list); ps; poweroff'
::shutdown:/bin/umount -a -r
X
cat > minroot/etc/init.d/rcS <<'X'
#!/bin/sh
mount -t proc proc /proc; mount -t sysfs sysfs /sys; mount -t devtmpfs dev /dev
echo "K2-MIN rcS: $(uname -r) up $(cat /proc/uptime)"
X
chmod +x minroot/etc/init.d/rcS
(cd minroot && find . | cpio -o -H newc --quiet | gzip -9) > k2_min.cpio.gz
du -sb minroot | cut -f1; stat -c '%s %n' k2_min.cpio.gz
```

## 10. 라이선스와 대안

### 10.1 GPLv2 — 바이너리를 내보내면 소스도

BusyBox는 **GPLv2(only)** 다(`busybox` 실행 시 "Licensed under GPLv2" 표시). 제품에 넣어 출하하면 그 BusyBox 버전의 **대응 소스 코드(설정 `.config`와 수정 패치 포함)를 제공하거나 서면 제공 약속**을 해야 한다. BusyBox는 GPL 준수 소송으로 유명한 프로젝트라, 법무팀이 SBOM에서 가장 먼저 확인하는 패키지 중 하나다. BusyBox 위에서 도는 내 앱은 별도 프로그램이므로 GPL이 전염되지 않지만, **BusyBox 소스를 고쳐 applet을 추가**하면 그 코드는 GPL이다. 자세한 의무와 SBOM은 K7.

### 10.2 대안

| 대안 | 무엇 | 언제 |
|---|---|---|
| toybox | BSD 계열(0BSD) 라이선스의 멀티콜 바이너리, 같은 `argv[0]` 디스패치 | Android가 기본 명령어 도구로 쓴다 (Android 6 무렵 도입 — 기억에 의존, 확인 필요). GPL을 피하려는 제품 |
| systemd + coreutils/util-linux | 완전한 init·서비스 관리·udev·journald | 큰 Linux(Jetson L4T, Yocto 풀 이미지). L1 |
| 직접 쓴 `/init` 스크립트 또는 C 프로그램 | initramfs 전용 최소 PID 1 | 부팅 시간이 극단적으로 중요할 때 (C7) |
| Buildroot / Yocto | BusyBox를 **패키지로** 빌드·설정·설치 | 실제 제품 이미지. 설정 관리는 K3, K4 |

실무에서 흔한 조합: Buildroot 이미지 = BusyBox(init·셸·도구) + 필요한 패키지, Yocto 이미지 = BusyBox 또는 systemd 중 선택(`INIT_MANAGER`), 그리고 둘 다 **initramfs/복구 이미지는 BusyBox**.

## 11. 커널 안에서는 무슨 일이 일어나나

BusyBox의 각 기능이 커널의 어디로 이어지는지 정리한다.

- **멀티콜 디스패치** — `execve()` → `fs/exec.c`가 경로를 해석하며 symlink를 따라가 실제 inode(busybox)를 연다 → `binfmt_elf`가 ELF를 매핑 → 유저 스택에 `argv`를 **호출자가 준 그대로** 복사한다. 커널은 `argv[0]`을 검사하지 않는다. `/proc/self/exe`는 커널이 기억한 실행 파일(`mm->exe_file`)을 가리키므로, `--install`과 `PREFER_APPLETS`가 링크 이름과 무관하게 busybox 자신을 찾을 수 있다. `comm`(`ps`의 이름)은 `execve`의 파일 이름 basename에서 정해진다(그래서 `ls`로 보인다).
- **init과 시그널** — PID 1은 커널이 기본 시그널 처리를 하지 않는 특별한 프로세스다(C7). Ctrl-Alt-Del 키는 키보드 드라이버 → `ctrl_alt_del()`(`kernel/reboot.c`) → `C_A_D`가 1이면 커널이 바로 재부팅, 0이면 `kill_cad_pid(SIGINT, 1)` → BusyBox init의 ctrlaltdel 액션. BusyBox init은 시작할 때 `reboot(RB_DISABLE_CAD)`로 이 값을 0으로 만들어 두므로 SIGINT를 받는다. `/proc/sys/kernel/ctrl-alt-del`이 이 `C_A_D` 값이다. `poweroff`는 최종적으로 `reboot(LINUX_REBOOT_CMD_POWER_OFF)` 시스템 콜 → `kernel_power_off()` → PSCI SYSTEM_OFF(arm64, C5) → QEMU 종료.
- **mdev** — `device_add()` → `kobject_uevent(KOBJ_ADD)` → `kobject_uevent_env()`가 환경 변수 버퍼를 만들고 `kobject_uevent_net_broadcast()`로 `NETLINK_KOBJECT_UEVENT` 소켓에 브로드캐스트(+ `CONFIG_UEVENT_HELPER`가 켜져 있고 `uevent_helper[0]`이 비어 있지 않으면 `call_usermodehelper`). `mdev -d`는 이 netlink 그룹 1에 bind한 소켓이다. 장치 노드의 major/minor는 드라이버가 `register_chrdev_region`/`alloc_chrdev_region`(G4) 또는 블록 계층에서 받은 값이 `MAJOR=`, `MINOR=`로 실려 온다. 드라이버를 쓸 때 `device_create()`(char) 한 줄이 바로 이 uevent를 만드는 지점이다 — 이걸 빼먹으면 "모듈은 로드됐는데 `/dev`에 노드가 없다".
- **syslogd/klogd** — `/dev/log`는 `AF_UNIX` `SOCK_DGRAM` 소켓. 커널 로그는 printk 링버퍼(`kernel/printk/`)에 쌓이고, klogd는 `syslog(2)`(glibc 이름은 `klogctl`)의 `SYSLOG_ACTION_READ`로 읽는다. `dmesg`는 `/dev/kmsg` 또는 같은 syscall로 버퍼를 통째로 읽는다(M1).
- **devmem** — `/dev/mem`의 `mmap_mem()`(`drivers/char/mem.c`)이 `range_is_allowed()` → `devmem_is_allowed()`로 STRICT_DEVMEM 정책을 검사한 뒤 `remap_pfn_range()`로 물리 페이지를 유저 공간에 매핑한다. 드라이버의 `.mmap` 구현(G5)과 같은 함수다.
- **watchdog** — `/dev/watchdog`은 `drivers/watchdog/watchdog_dev.c`의 misc 장치. `write()` = 킥, `'V'` 쓰기 = 다음 close에서 멈춤 허용, `release()`에서 그게 없으면 `watchdog did not stop!`. 하드웨어 드라이버는 `struct watchdog_ops`의 `.start/.stop/.ping/.set_timeout`만 구현하면 된다(I9).

## 12. Embedded 실무에서 다시 보기

- **센서 키트 복구 이미지**: eMMC rootfs가 깨졌을 때 U-Boot가 띄우는 복구 initramfs. musl static BusyBox + `udhcpc` + `wget`(또는 `tftp`) + `ubiupdatevol`/`dd` + 작은 rcS. 크기가 수백 KB라 SPI NOR 한 구석에 들어간다. DNS 이름으로 서버를 찾는다면 glibc static NSS 함정(3.2절) 때문에 musl을 쓰거나 IP를 직접 쓴다.
- **생산 테스트 이미지**: inittab의 `::once:/usr/bin/factory_test`로 테스트를 돌리고, `i2cget`으로 IMU WHO_AM_I 확인, `devmem`으로 SoC 퓨즈·ID 레지스터 읽기, 결과를 `logread`로 수집해 시리얼로 출력. 테스트가 끝나면 `poweroff`.
- **장치 이름 고정**: USB 카메라 두 대의 `/dev/video*` 순서가 부팅마다 바뀐다. `mdev.conf`에 `$DEVPATH` 매치 규칙(`DEVPATH=.*usb1/1-1.2.*;video[0-9]+ root:video 660 >cam/front`)으로 포트 기준 고정 이름을 만든다(udev 시스템이면 L2의 `ID_PATH` 규칙). 위 규칙 문법은 `mdev --help`의 `[ENV=regex;]` 형식을 따른 것이고, 이 노트에서 실제 USB 장치로 실행하지는 않았다.
- **로그 설계**: 현장 장비에서 `syslogd -C`(RAM 링버퍼)로 평상시 로그를 담고, 오류가 나면 `logread > /data/crash_$(date +%s).log`로 그 순간만 플래시에 저장한다. 플래시 마모와 전원 차단 안전성(J5) 둘 다 잡는 흔한 패턴이다.

## 13. 흔한 실수와 증상

| 실수 | 증상 | 원인 | 고치는 법 |
|---|---|---|---|
| initramfs에 동적 busybox | `Kernel panic ... No working init found` 또는 `Failed to execute /init (error -2)` | 동적 로더·libc가 rootfs에 없음 | `CONFIG_STATIC=y`, 또는 `ldd`로 본 라이브러리 전부 복사 |
| busybox 바이너리 이름을 바꿔 복사 | `xxx: applet not found` | `argv[0]` 디스패치 | 링크로 부르거나 `busybox <applet>` |
| `syslogd`만 쓰고 `-L` 생략 (1.37.0) | `logread`에 "syslogd started"만 | `opts`와 `option_mask32` 불일치 버그 | `syslogd -L ...`, 버전 업 시 재확인 |
| `echo /sbin/mdev > /proc/sys/kernel/hotplug` | `No such file or directory`, 핫플러그 노드가 안 생김 | `CONFIG_UEVENT_HELPER=n` | `mdev -d` 사용 |
| tty 칸에 `ttyAMA0`을 썼는데 `/dev`가 비어 있음 | 부팅 로그는 나오는데 셸 프롬프트 없음 | mdev/devtmpfs가 노드를 안 만듦 | rcS에서 devtmpfs 마운트 또는 `mdev -d`, 빈 tty 칸 사용 |
| 개발용 defconfig로 짠 스크립트를 최소 이미지에서 실행 | `[[: not found`, `bad substitution`, `$RANDOM` 빈 값 | `ASH_BASH_COMPAT` 등 꺼짐 | POSIX sh로 작성, `shellcheck -s sh` |
| rcS에서 데몬화되는 데몬을 띄움 | 데몬이 죽어도 아무도 안 살림 | respawn은 inittab 항목만 감시 | 포그라운드 모드(`-n`)로 inittab `respawn`에 등록 |
| `make install`에 빌드 때 쓴 `CC` 생략 | 이미지 크기가 갑자기 커짐, `file`이 glibc 표시 | install이 기본 gcc로 재빌드 | 같은 변수 전달, 또는 빌드 시스템(K3) 사용 |
| udhcpc만 넣고 default.script 누락 | "lease obtained"인데 IP 없음 | 설정은 스크립트 몫 | `/usr/share/udhcpc/default.script` 설치, 실행 권한 |
| watchdog 데몬을 `kill -9`로 재시작 | 몇 초 뒤 보드 리셋 | magic close 없이 fd 닫힘 | SIGTERM으로 정지, 또는 의도된 동작으로 문서화 |

## 14. 면접에서 이렇게 말한다

**Q.** How can BusyBox provide hundreds of commands in a single binary?

**A.** 실행 파일 하나 안에 applet마다 `xxx_main()` 함수가 있고, 정렬된 이름 테이블과 함수 포인터 테이블이 빌드 때 생성된다. `/bin/ls` 같은 파일은 busybox를 가리키는 링크이고, 커널은 `execve`에서 `argv[0]`을 호출자가 준 그대로 넘기므로 `main()`이 그 basename을 테이블에서 찾아 해당 함수를 호출한다. 공통 코드가 한 번만 들어가서 작고, 코드 페이지를 모든 프로세스가 공유한다.

> BusyBox is a multi-call binary: every applet is just a `foo_main()` function, and the build generates a sorted name table plus a matching function-pointer table. `/bin/ls` is only a symlink to busybox; the kernel passes `argv[0]` through unchanged, so busybox's `main()` takes the basename, looks it up in the table and calls `ls_main()`. You can also run `busybox ls` directly. Shared helpers and the C library are linked once, which is why the whole userland fits in about 1–2 MB, and every process shares the same code pages.

**꼬리 질문**: "symlink와 hardlink 중 뭘 쓰나?" → 기본은 symlink(보이고 FS 무관), hardlink는 inode 하나지만 같은 FS 안에서만. "NOFORK applet이란?" → 셸이 fork 없이 같은 프로세스에서 호출하는 applet, 측정상 fork/exec가 사라진다.

**Q.** Walk me through what BusyBox init does from boot to shutdown.

**A.** `/etc/inittab`을 읽고 액션 종류 순서로 실행한다: sysinit(rcS, 끝까지 대기) → wait → once → respawn·askfirst를 띄우고 감시 루프. 자식이 죽으면 respawn 항목은 1초 정도 뒤 다시 띄운다. SIGHUP이면 inittab을 다시 읽고, SIGINT(Ctrl-Alt-Del)면 ctrlaltdel 액션, SIGUSR1/USR2/TERM이면 shutdown 액션 → 전 프로세스 SIGTERM·SIGKILL → `reboot(2)`, SIGQUIT이면 같은 정리 후 restart 액션을 exec한다. runlevel은 무시한다.

> BusyBox init parses `/etc/inittab` and runs actions by type, not by line order: sysinit entries such as rcS run to completion first, then wait, then once, then it starts respawn and askfirst entries and supervises them, restarting them about a second after they die. Signals drive the rest: SIGHUP rereads inittab, SIGINT from Ctrl-Alt-Del runs ctrlaltdel actions, SIGUSR1, SIGUSR2 and SIGTERM mean halt, poweroff and reboot — shutdown actions run, everything gets SIGTERM then SIGKILL, then it calls `reboot(2)`. SIGQUIT does the same cleanup but execs the restart action instead, so you restart userspace without a kernel reboot. Runlevels are ignored.

**꼬리 질문**: "daemon이 죽었는데 init이 안 살린다, 왜?" → rcS에서 띄워 데몬화(고아 → PID 1 입양)됐기 때문. respawn은 inittab 항목만 감시한다.

**Q.** Without udev, how do device nodes appear under /dev?

**A.** 바닥은 devtmpfs로, 커널이 드라이버 등록 때 직접 노드를 만든다. 규칙(소유자·권한·이름·symlink·스크립트)이 필요하면 BusyBox mdev를 쓴다. 부팅 때 `mdev -s`로 `/sys/dev`를 훑어 기존 장치를 만들고, 핫플러그는 커널 uevent를 받아 처리한다. 예전엔 `/proc/sys/kernel/hotplug`에 mdev를 등록했지만 최근 커널은 `CONFIG_UEVENT_HELPER`가 꺼진 경우가 많아 netlink를 듣는 `mdev -d`를 쓴다. 실제로 랩 커널에서 hotplug 파일이 없어서 `mdev -d`로 null_blk 장치를 `/dev/k2/sensor_disk0` + symlink로 만들었다.

> The baseline is devtmpfs: the kernel itself creates a node when a driver registers a device. When you need policy — owner, mode, a stable name, a symlink, or a script — BusyBox mdev does it from `/etc/mdev.conf` regex rules. At boot `mdev -s` walks `/sys/dev` for devices that already exist; for hotplug, mdev consumes kernel uevents. The old way was registering it as the uevent helper in `/proc/sys/kernel/hotplug`, but many current kernels build without `CONFIG_UEVENT_HELPER`, so you run `mdev -d`, which listens on the uevent netlink socket. On my QEMU board the hotplug file didn't even exist, and `mdev -d` created the null_blk disks with a renamed node, a compatibility symlink and a hook script.

**Q.** Why would you link BusyBox statically, and what are the pitfalls?

**A.** initramfs나 복구 이미지에 공유 라이브러리를 안 넣어도 되고, 다른 앱과 libc 버전이 엮이지 않는다. 함정은 glibc static이 NSS(DNS·사용자 조회)를 위해 실행 중에 공유 라이브러리를 dlopen한다는 점 — 링커 경고가 그걸 말한다. 크기도 glibc가 대부분이다. 최소 빌드 측정에서 glibc static 1.19 MB 중 libc가 약 87%였고, musl로 바꾸니 329 KB가 됐다.

> Static linking means the initramfs or recovery image needs no shared libraries and isn't tied to the libc version of other apps. The catch with glibc is NSS: `getaddrinfo` and friends still `dlopen` NSS modules at run time, which is exactly what the "statically linked applications requires at runtime the shared libraries" warnings mean, so DNS can silently fail. Size is the other issue — in my measurement a 19-applet glibc static build was 1.19 MB and about 87 percent of it was libc; the same config with musl was 329 KB.

**Q.** How do you make a minimal root filesystem as small as possible?

**A.** 먼저 잰다. 이미지 전체에서는 보통 커널이 가장 크다(랩 defconfig 커널 gzip 15 MB vs BusyBox initramfs 0.17~1.2 MB). 유저 공간에서는 libc 선택 → allnoconfig에서 필요한 applet만 → FEATURE 옵션 정리 → `-Os`와 strip → 압축 initramfs 순서로 효과가 크다. 링커 map으로 출처를 나눠 보면 어디를 줄일지 보인다.

> Measure first. In the whole image the kernel usually dominates — in my lab the defconfig kernel was 15 MB gzipped while the BusyBox initramfs was 0.17 to 1.2 MB — so kernel config is the biggest lever. For userspace the order is: pick the libc (musl gave 3.6x), start from allnoconfig and enable only the applets the scripts actually call, trim FEATURE options like line editing and verbose help, keep `-Os` and strip, and ship a compressed initramfs. I attribute bytes with the linker map file so I'm not guessing where the size comes from.

**Q.** Your boot script works on the dev board but fails on the production image with a syntax error. What happened?

**A.** 보드의 `/bin/sh`는 BusyBox ash이고, `[[ ]]`, `${var//a/b}`, `${var:1:3}`, `function` 같은 bash 확장은 `ASH_BASH_COMPAT` 설정에 달려 있다. 개발 이미지는 defconfig라 켜져 있고 양산 이미지는 최소 설정이라 꺼졌을 가능성이 크다. 배열·`{1..3}`은 어느 쪽에서도 안 된다. POSIX sh로 고치고 `shellcheck -s sh`를 CI에 넣는다.

> The board's `/bin/sh` is BusyBox ash, and bash-isms like `[[ ]]`, `${var//a/b}`, substring expansion and the `function` keyword only work if `ASH_BASH_COMPAT` was enabled. Dev images often use defconfig, production uses a trimmed config, so the same script breaks — I reproduced exactly that: `[[: not found` and `bad substitution` on the minimal build, and `$RANDOM` silently empty. Arrays and brace ranges never work in ash. The fix is to write POSIX sh and run `shellcheck -s sh` in CI.

**Q.** How does a userspace watchdog daemon interact with the kernel watchdog driver?

**A.** 데몬이 `/dev/watchdog`을 열면 타이머가 시작되고, `write`나 `WDIOC_KEEPALIVE`로 주기적으로 킥한다. 정상 종료할 땐 `'V'`를 쓰고 닫아(magic close) 타이머를 멈춘다. 데몬이 행이나 SIGKILL로 죽으면 magic close가 없으니 타이머가 만료돼 리셋된다. 실험에서 softdog 5초 설정, SIGTERM은 살아남고 SIGKILL은 약 6초 뒤 리셋됐다. 양산은 NOWAYOUT으로 끌 수 없게 하고, 앱 건강 상태를 확인한 뒤에만 킥한다.

> Opening `/dev/watchdog` arms the timer; the daemon pets it with `write()` or `WDIOC_KEEPALIVE`. On a clean exit it writes the magic character 'V' before closing so the driver may stop the timer. If the daemon hangs or gets SIGKILLed there's no magic close and the board resets. I tested it with softdog and a 5 second timeout: SIGTERM left the system up, SIGKILL logged "watchdog did not stop!" and the VM reset about six seconds later. In production you set NOWAYOUT and only pet after checking the application's health, otherwise the watchdog just proves the daemon is alive, not the system.

## 15. 직접 해보기

1. (개념) `ln /bin/busybox /tmp/sh2`로 hardlink를 만들고 `/tmp/sh2 -c 'echo hi'`를 실행하면 어떻게 되나? `cp`로 복사하면? 이유를 `argv[0]`으로 설명하라.
   정답/힌트: hardlink든 복사든 이름이 `sh2`라 `applet not found`(127). 이름이 `sh`면 된다. inode는 무관하다.
2. (코드) 1.3절 장난감에 `--install DIR` 옵션을 추가해, `/proc/self/exe`를 `readlink`로 읽어 DIR에 applet 이름별 symlink를 만들게 하라.
   정답/힌트: `readlink("/proc/self/exe", buf, sizeof buf - 1)` 후 `symlink(buf, path)`. 이미 있으면 `EEXIST` 처리.
3. (빌드) 4절의 allnoconfig 스크립트에 `FEATURE_EDITING`과 `ASH_BASH_COMPAT`만 추가로 켜서 musl 빌드 크기가 얼마나 늘어나는지 재라. 결과를 표에 한 줄 추가하라.
   정답/힌트: `build_min.sh`의 `for o in` 목록에 두 이름 추가, `stat -c %s`. 늘어난 바이트는 `mapsum.py`의 `busybox:shell`과 `busybox:libbb`에서 보인다.
4. (init) inittab의 `ttyAMA0::askfirst:-/bin/sh`를 `ttyAMA0::respawn:/sbin/getty -L 115200 ttyAMA0 vt100`으로 바꾸고 `/etc/passwd`의 root 비밀번호 칸을 비운 채 로그인해 보라. 셸에서 `exit`하면 무엇이 다시 뜨나?
   정답/힌트: getty가 respawn되어 다시 `login:`. C7 2.2절에 같은 실험 출력이 있다.
5. (mdev) `mdev.conf`에 `$MODALIAS=.* root:root 660 @modprobe "$MODALIAS"` 규칙을 넣고, `null_blk`를 수동 로드하지 않고도 자동 로드되는 장치가 있는지 `logread`로 관찰하라. 왜 null_blk는 자동 로드되지 않나?
   정답/힌트: null_blk는 HW 장치가 없는 가상 드라이버라 MODALIAS를 가진 장치 이벤트가 먼저 오지 않는다. virtio-net 같은 버스 장치가 대상이다(G9).
6. (관찰) 8.1절 버그를 확인하라: rcS의 `syslogd -C64 -L`에서 `-L`을 빼고 부팅해 `logread`를 보고, `strace -f -e trace=read,write`로 syslogd가 메시지를 읽고 버리는 것을 VM 네임스페이스에서 확인하라.
   정답/힌트: `read(0, "<13>...")` 다음에 `write`가 없다. `syslogd.c`의 `syslogd_init()` 반환값과 메인 루프의 `opts & OPT_locallog`를 비교.
7. (사이징) `/lib/modules/6.18.55-sub`에서 `null_blk.ko`·`softdog.ko`만 남기고 VM의 `depmod -b <rootfs> 6.18.55-sub`로 `modules.dep`를 다시 만들어 K2 initramfs 크기를 다시 재라.
   정답/힌트: `modules.alias` 등이 수 KB로 줄어 initramfs가 BusyBox 크기 수준(약 1.2 MB 압축)으로 내려가야 한다.

## 17. 요약 & 체크리스트

BusyBox는 `argv[0]`으로 갈라지는 멀티콜 바이너리 하나로 최소 Linux 유저 공간 전체(init·셸·코어 유틸·mdev·네트워크·로그 도구)를 제공한다. Kconfig로 applet과 기능을 고르고, static/dynamic과 libc 선택이 크기를 좌우한다 — 측정상 최소 빌드에서 glibc가 약 87%를 차지했고 musl로 바꾸면 329 KB가 됐다. BusyBox init은 inittab의 액션 종류 순서(sysinit → wait → once → respawn/askfirst)로 실행하고 시그널(HUP·INT·QUIT·USR1·USR2·TERM)로 재설정·종료한다. mdev는 `mdev.conf` 규칙으로 `/dev`를 만들며, `CONFIG_UEVENT_HELPER`가 꺼진 최근 커널에서는 `mdev -d`가 정답이다. 보드의 셸은 ash이고 bash 확장은 빌드 설정에 따라 달라진다. syslogd 링버퍼·udhcpc·devmem·watchdog은 임베디드에서 매일 쓰는 도구이고, 1.37.0의 syslogd는 `-L` 없이는 메시지를 버린다. 이미지 전체에서는 커널이 BusyBox보다 훨씬 크므로, 줄이기 전에 먼저 잰다.

- [ ] 멀티콜 바이너리가 `argv[0]`으로 applet을 고르는 과정을 `execve` → `main` → 테이블 탐색 순서로 설명할 수 있다
- [ ] 40줄짜리 멀티콜 장난감을 C로 짤 수 있고 symlink·hardlink·`busybox <applet>`의 차이를 말할 수 있다
- [ ] defconfig/allnoconfig/oldconfig/O= 빌드로 원하는 applet만 든 BusyBox를 만들 수 있다
- [ ] NOFORK/NOEXEC가 무엇이고 fork/exec 횟수가 어떻게 줄어드는지 strace로 보여 줄 수 있다
- [ ] glibc static의 NSS 경고가 무슨 뜻인지, musl이 왜 작은지 설명할 수 있다
- [ ] 링커 map으로 바이너리 크기를 출처별로 나눌 수 있다
- [ ] inittab 액션 8종의 실행 순서와 대기 여부를 표 없이 말할 수 있다
- [ ] BusyBox init이 받는 시그널별 동작(HUP·INT·QUIT·USR1·USR2·TERM)을 설명할 수 있다
- [ ] `mdev -d`와 uevent helper의 차이, `CONFIG_UEVENT_HELPER`의 의미를 설명할 수 있다
- [ ] `mdev.conf`로 권한·이름 변경·symlink·스크립트 실행 규칙을 쓸 수 있다
- [ ] ash와 bash의 차이, 빌드 설정에 따라 달라지는 문법을 예로 들 수 있다
- [ ] syslogd `-C` 링버퍼·klogd·logread, udhcpc default.script, devmem, watchdog magic close를 직접 써 봤다고 말할 수 있다
