## 0. 큰 그림 — 이게 왜 필요한가

Don이 bare-metal에서 IMU를 다루던 코드를 떠올려 보자. 대략 이런 덩어리들이 있었다.

1. **설정**: `imu_set_odr(1000)`, `imu_set_range(ACC_8G)` — 레지스터 몇 개를 쓴다.
2. **단발 읽기**: 디버그 콘솔에서 `imu_read_accel(&x, &y, &z)` — 레지스터 6바이트를 읽고 감도(scale)를 곱해 m/s²로 바꾼다.
3. **스트리밍**: DRDY 핀 인터럽트 → ISR에서 타임스탬프 찍고 플래그 → 태스크가 버스트 읽기 → 링버퍼에 (샘플 + 타임스탬프) push → 소비자 태스크가 묶음으로 꺼내 간다.
4. **알림**: "가속도가 임계값을 넘으면(낙하·충격) 알려 줘" — 칩의 wake-up 인터럽트.

Linux의 **IIO(Industrial I/O) 서브시스템**은 이 네 가지를 **모든 센서에 공통인 틀**로 만들어 둔 것이다. 드라이버는 "내 칩에는 이런 채널이 있고, 레지스터는 이렇게 읽는다"만 채우면, IIO core가 나머지를 만든다.

| bare-metal 덩어리 | IIO에서의 이름 | 유저에게 보이는 모습 |
|---|---|---|
| 설정·단발 읽기 | **채널**(`iio_chan_spec`) + `iio_info.read_raw/write_raw` | sysfs 파일: `in_accel_x_raw`, `in_accel_scale`, `sampling_frequency` |
| DRDY ISR + 타임스탬프 | **트리거**(`iio_trigger`) + pollfunc | `trigger/current_trigger`에 이름을 쓴다 |
| 링버퍼 | **버퍼**(kfifo) + scan elements | `/dev/iio:deviceN`을 `read()` — 바이너리 scan 묶음 |
| wake-up/임계값 인터럽트 | **이벤트**(`iio_event_spec`) | 이벤트 fd에서 `struct iio_event_data` 읽기 |

### 0.1 왜 IIO인가 — hwmon, input과 비교

Linux에는 "센서 같은 것"을 받는 서브시스템이 셋 있다. 처음 드라이버를 쓸 때 가장 먼저 정해야 하는 것이 **어디에 붙이나**다(I1 노트의 원칙: 직접 char device를 만들지 말고 맞는 서브시스템에 등록한다).

| | hwmon (I4) | input (I3) | **IIO (이 노트)** |
|---|---|---|---|
| 원래 목적 | 보드 건강 감시: 온도·전압·팬 | 사람의 입력: 키·터치·조이스틱 | 측정 장치: ADC·IMU·기압·조도·자력 |
| 데이터 모양 | 느린 단발 값 (초 단위 폴링) | 이벤트 스트림(`EV_KEY`, `EV_ABS`) | 단발 값 + **고속 연속 샘플 + 타임스탬프** |
| 단위 | 고정 (m°C, mV) | 장치마다 임의 | `raw`·`scale`·`offset`으로 표준 단위 복원 |
| 고속 버퍼 | 없음 | evdev 큐 (사람 속도) | kfifo/DMA 버퍼, 트리거, watermark |
| 타임스탬프 | 없음 | 이벤트마다 있음 (`input_event.time`) | scan마다 s64, 시계 선택 가능 |
| 유저 도구 | `sensors`(lm-sensors) | `evtest`, libinput | `iio_info`·`iio_readdev`(libiio), `iio_generic_buffer` |
| 예 | `lm75`, `ina2xx` (일부는 IIO도) | `gpio-keys`, `goodix` 터치 | `st_lsm6dsx`, `inv_mpu6050`, `bmp280`, `ti-ads1015` |

규칙은 단순하다. **"이 값을 정확한 단위로, 빠르게, 시간과 함께 모아서 계산에 쓸 것인가?"** 그렇다면 IIO다. 로봇의 자세 추정(VIO, EKF)에 들어가는 IMU, 모터 전류를 1 kHz로 재는 ADC, 고도를 잡는 기압계가 모두 여기에 해당한다. 반대로 "보드 온도가 85 °C를 넘으면 팬을 돌려라"는 hwmon/thermal의 일이다. (실제로 `ina2xx`처럼 hwmon 드라이버와 IIO 드라이버가 둘 다 있는 칩도 있다 — 용도가 다르기 때문이다.)

옛날에는 가속도계를 input 서브시스템에 붙여 `EV_ABS` 이벤트로 보내던 드라이버도 있었다(휴대폰 화면 회전용). 지금 새 드라이버를 input에 붙이면 리뷰에서 거절된다. 단위 정보가 없고, 고속 버퍼가 없고, 타임스탬프 시계를 고를 수 없기 때문이다.

### 0.2 이 노트의 실습 환경

실행 환경: Mac의 Lima VM `elinux`(`uname -r` = `7.0.0-38-generic`, aarch64) 안에서 공용 랩의 **서브시스템 커널** `/var/lab/out/Image-sub`(Linux `6.18.55-sub`)를 QEMU `virt`(cortex-a57, `-smp 2`, 512 MB, **KVM 없이 TCG**)로 부팅한다. 이 커널에는 IIO core(`CONFIG_IIO=y`, `CONFIG_IIO_BUFFER=y`, `CONFIG_IIO_TRIGGER=y`, `CONFIG_IIO_CONFIGFS=y`)가 들어 있고, 다음이 모듈로 빌드돼 있다.

| 모듈 | 하는 일 | 이 노트에서 |
|---|---|---|
| `iio_dummy` + `iio_dummy_evgen` | 가상 IIO 장치 (configfs로 생성), 이벤트 생성기 | 2절, 9절 |
| `industrialio-sw-device` / `-sw-trigger` | configfs `/sys/kernel/config/iio/` 틀 | 2절, 5절 |
| `iio-trig-hrtimer`, `iio-trig-sysfs` | 소프트웨어 트리거 | 5절, 6절 |
| `kfifo_buf`, `industrialio-triggered-buffer` | 버퍼와 "트리거로 채우는 버퍼" 도우미 | 4절 |
| `st_lsm6dsx`, `st_lsm6dsx_i2c` | 업스트림 ST IMU 드라이버 | 11절 |

QEMU `virt`에는 I2C 컨트롤러도 IMU도 없다. 그래서 H5·H2에서 한 방법을 그대로 가져온다: **가짜 I2C 어댑터를 직접 쓰고, 그 어댑터가 버스 위의 IMU 칩을 메모리 안에서 흉내 낸다**(`i2_fakebus.ko`). 그 위에 이 노트의 주인공인 IIO 드라이버 `i2_imu.ko`가 진짜 I2C client driver로 붙는다. 가짜 칩은 H2보다 한 걸음 더 나아가 **ODR 타이머(hrtimer)로 스스로 샘플을 만들고, `irq_sim`으로 만든 가상 irqchip을 통해 INT1(data-ready) 인터럽트를 친다**. 그래서 드라이버 입장에서는 진짜 보드와 똑같이 `client->irq`가 있고, 그 IRQ가 ODR마다 울린다.

유저 프로그램은 VM에서 `gcc -static`으로 빌드해 initramfs에 넣는다(게스트는 BusyBox뿐이라 libc가 없다). 커널 소스의 `tools/iio/`에 있는 공식 도구(`lsiio`, `iio_generic_buffer`, `iio_event_monitor`)도 같은 방법으로 빌드했다.

```sh
# build.sh — 소스 조각을 /var/tmp/I2/mod 로 모아 Image-sub(6.18.55-sub) 트리에 대해 빌드
set -e
S=/Users/donh/.elinux_scratch/I2; M=/var/tmp/I2/mod
mkdir -p $M && cd $M
cp $S/i2_regs.h .
cat $S/i2_fakebus.c $S/i2_fakebus_b.c $S/i2_fakebus_c.c > i2_fakebus.c
cat $S/imu1.c $S/imu2.c $S/imu3.c $S/imu4.c $S/imu5.c $S/imu6.c $S/imu7.c > i2_imu.c
echo 'obj-m += i2_fakebus.o i2_imu.o' > Kbuild
make -C /var/lab/out/linux-build-sub M=$M -j2 modules 2>&1 | grep -v "^make"
```

```sh
# bins.sh — 게스트용 정적 바이너리 (게스트엔 libc가 없다)
set -e
S=/Users/donh/.elinux_scratch/I2; B=/var/tmp/I2/bin
mkdir -p $B
for p in "$@"; do gcc -std=gnu11 -Wall -Wextra -O2 -static -I$S $S/$p.c -o $B/$p -lm; done
# 커널 tools/iio 도구도 같은 방식으로 (소스 트리는 읽기 전용, 출력만 /var/tmp/I2/bin)
T=/var/lab/src/linux-6.18.55/tools/iio
for p in lsiio iio_generic_buffer iio_event_monitor; do
  gcc -O2 -static -D_GNU_SOURCE -I/var/lab/src/linux-6.18.55/tools/include/uapi $T/$p.c $T/iio_utils.c -o $B/$p
done
```

```sh
# boot.sh <게스트 스크립트> — Image-sub + IIO 모듈 트리 + 내 모듈/바이너리
set -e
W=/var/tmp/I2; S=/Users/donh/.elinux_scratch/I2; K=6.18.55-sub
MS=/var/lab/out/modules-sub/lib/modules/$K
if [ ! -d $W/base ]; then          # 한 번만: rootfs + IIO 모듈만 추린 /lib/modules
  mkdir -p $W/base && cp -a /var/lab/build/rootfs/. $W/base/
  mkdir -p $W/base/lib/modules/$K/kernel/drivers
  cp $MS/modules.* $W/base/lib/modules/$K/
  cp -a $MS/kernel/drivers/iio $W/base/lib/modules/$K/kernel/drivers/
fi
rm -rf $W/r && cp -a $W/base $W/r
cp $W/mod/*.ko $W/bin/* $W/r/ 2>/dev/null || true
cp $S/$1 $S/common.sh $W/r/
(cd $W/r && find . | cpio -o -H newc --quiet | gzip -1) > $W/i.gz
timeout ${TMO:-180} qemu-system-aarch64 -machine virt -cpu cortex-a57 -smp ${SMP:-2} -m 512M -nographic \
  -kernel /var/lab/out/Image-sub -initrd $W/i.gz \
  -append "console=ttyAMA0 quiet LAB_CMD=sh~/$1"
```

`/lib/modules/6.18.55-sub/`에 랩이 설치해 둔 IIO 모듈 트리와 `modules.dep`을 넣었기 때문에 게스트에서 BusyBox `modprobe iio_dummy`가 의존 모듈(`kfifo_buf`, `industrialio-triggered-buffer`, `industrialio-sw-device` …)까지 알아서 올린다. 게스트 공통 함수는 다음과 같다.

```sh
# common.sh — 게스트 공통
mount -t configfs none /sys/kernel/config 2>/dev/null
C=/sys/kernel/config/iio
dev_of() { for d in /sys/bus/iio/devices/iio:device*; do [ "$(cat $d/name)" = "$1" ] && echo $d; done; }
trig_of() { for d in /sys/bus/iio/devices/trigger*; do [ "$(cat $d/name)" = "$1" ] && echo $d; done; }
imu_up() {	# imu_up [i2_imu 인자] — 가짜 버스 + 드라이버 적재, D=장치 sysfs, N=/dev 노드
	modprobe industrialio-triggered-buffer
	insmod /i2_fakebus.ko $FB && insmod /i2_imu.ko "$@"
	D=$(dev_of i2_imu); N=/dev/${D##*/}
}
show() { for f in "$@"; do printf "%-34s %s\n" $f "$(cat $f 2>&1)"; done; }
enable_all() { for e in $D/scan_elements/*_en; do echo 1 > $e; done; }
```

Mac에서 실행하는 한 줄은 늘 같은 모양이다: `limactl shell elinux -- bash -lc 'sh /Users/donh/.elinux_scratch/I2/boot.sh t4.sh'`. 아래 출력에서 BusyBox `ls`가 넣는 ANSI 색 코드와 마지막 `reboot: Power down` 줄은 지웠다.

## 1. 핵심 객체 — `iio_dev`, `iio_chan_spec`, `iio_info`

### 1.1 직관 — 누가 무엇을 아는가

| 객체 | 한 문장 | bare-metal 대응 | 이 노트의 예 |
|---|---|---|---|
| `struct iio_dev` | **장치 하나**. `/sys/bus/iio/devices/iio:deviceN`과 `/dev/iio:deviceN`의 N | `imu_handle_t` 전역 구조체 | `i2_imu`의 `indio_dev` |
| `iio_priv(indio_dev)` | 드라이버 사설 상태 (같은 메모리 덩어리 뒤쪽) | `static struct imu_state` | `struct i2_imu` (regmap, ODR/FS 인덱스, scan 버퍼) |
| `struct iio_chan_spec[]` | **채널 표**. 무엇을(가속도 X), 어떤 속성으로(raw, scale), 버퍼 몇 번째 칸에(scan_index) | 레지스터 맵 + 단위 표 | 가속도 XYZ, 자이로 XYZ, 온도, 타임스탬프 |
| `struct iio_info` | 콜백 모음: `read_raw`, `write_raw`, `read_avail`, `write_raw_get_fmt` … | `imu_read()`, `imu_set()` 함수 모음 | `i2_info` |
| `struct iio_trigger` | "지금 샘플 하나 잡아라" 신호원 | DRDY ISR, 주기 타이머 | `i2_imu-dev0` (INT1), `i2_hrt` (hrtimer) |
| `struct iio_buffer` (kfifo) | scan 묶음을 쌓는 FIFO, `/dev/iio:deviceN`의 `read()` 대상 | ISR이 채우는 링버퍼 | `buffer/length`, `buffer/watermark` |

핵심: **드라이버는 "표"와 "콜백"을 주고, 파일 이름·권한·파싱·버퍼 관리·poll·타임스탬프 시계 선택은 core가 한다.** Don이 SSD 펌웨어에서 NVMe 명령 테이블을 등록하고 공통 디스패처가 부르게 하던 구조와 같다.

### 1.2 `devm_iio_device_alloc` + `iio_priv` — 한 덩어리 할당

```c
indio_dev = devm_iio_device_alloc(dev, sizeof(struct i2_imu));
st = iio_priv(indio_dev);        /* indio_dev 뒤쪽, 캐시라인 정렬된 위치 */
```

`devm_iio_device_alloc()`은 core 내부 구조(`struct iio_dev_opaque`, 그 안에 공개 `struct iio_dev`) **뒤에 `sizeof_priv`만큼을 이어 붙여** 한 번에 할당한다. `iio_priv()`는 그 뒷부분 주소를 돌려준다. 그래서 콜백에서는 `indio_dev` 하나만 받아도 사설 상태를 바로 찾는다(`container_of`의 반대 방향). `devm_` 접두어는 G3에서 본 대로 **probe가 실패하거나 remove될 때 자동 해제**된다는 뜻이다.

```
 kzalloc 한 덩어리 (주소는 예시)
 +------------------------------+ <- iio_dev_opaque
 |  core 전용 필드 (id, 버퍼 목록, |
 |  이벤트 인터페이스, clock_id …) |
 |  +------------------------+  |
 |  | struct iio_dev (공개)   |  | <- indio_dev  (드라이버가 받는 포인터)
 |  +------------------------+  |
 +------------------------------+
 | 패딩 (IIO_DMA_MINALIGN 정렬)  |
 +------------------------------+ <- iio_priv(indio_dev)
 | struct i2_imu (sizeof_priv)  |
 +------------------------------+
```

priv가 `IIO_DMA_MINALIGN`(arm64에서 보통 128바이트 캐시라인 이상)으로 정렬되는 이유는, SPI 드라이버들이 priv 안의 버퍼를 **DMA 대상**으로 쓰기 때문이다(H9 노트의 캐시라인 공유 문제). 그래서 실제 드라이버들은 priv 끝에 `u8 rx[...] __aligned(IIO_DMA_MINALIGN);` 같은 버퍼를 둔다.

### 1.3 `iio_chan_spec` — 이 표 하나가 ABI를 결정한다

채널 하나는 "측정되는 양 하나"다. 3축 가속도계는 채널 3개(X, Y, Z), 6축 IMU + 온도는 7개, 여기에 소프트웨어 타임스탬프 채널 1개가 붙는다.

| 필드 | 뜻 | `i2_imu` 가속도 X의 값 |
|---|---|---|
| `.type` | 측정량 종류 `enum iio_chan_type` | `IIO_ACCEL` (자이로 `IIO_ANGL_VEL`, 온도 `IIO_TEMP`, 전압 `IIO_VOLTAGE`, 기압 `IIO_PRESSURE`, 조도 `IIO_LIGHT`, 자력 `IIO_MAGN`) |
| `.modified` + `.channel2` | 축 같은 수식어 `enum iio_modifier` | `1`, `IIO_MOD_X` → 이름에 `_x` |
| `.indexed` + `.channel` | 같은 종류가 여러 개일 때 번호 | ADC라면 `in_voltage0_raw`, `in_voltage1_raw` |
| `.differential` + `.channel2` | 차동 입력 쌍 | `in_voltage1-voltage2_raw` (iio_dummy) |
| `.address` | 드라이버 마음대로 쓰는 값 | 그 축의 OUT 레지스터 주소 `0x28` |
| `.info_mask_separate` | 채널마다 따로 있는 속성 | `BIT(IIO_CHAN_INFO_RAW)` |
| `.info_mask_shared_by_type` | 같은 type 채널끼리 공유 | `BIT(IIO_CHAN_INFO_SCALE)` → `in_accel_scale` 하나 |
| `.info_mask_shared_by_dir` | 같은 방향(in/out) 전체 공유 | (dummy의 `in_sampling_frequency`) |
| `.info_mask_shared_by_all` | 장치 전체 공유 | `BIT(IIO_CHAN_INFO_SAMP_FREQ)` → `sampling_frequency` |
| `..._available` 짝 | "가능한 값 목록" 파일을 만들지 | `in_accel_scale_available`, `sampling_frequency_available` |
| `.scan_index` | 버퍼 안 순서 (음수면 버퍼 불가) | `0` |
| `.scan_type` | 버퍼 안 표현: `sign`, `realbits`, `storagebits`, `shift`, `endianness`, `repeat` | `'s', 16, 16, 0, IIO_LE` → `le:s16/16>>0` |
| `.ext_info` | 표준 info_mask 밖의 추가 속성 | `IIO_MOUNT_MATRIX` → `in_mount_matrix` |
| `.event_spec` | 이 채널이 낼 수 있는 이벤트 | (9절) |

파일 이름은 `<방향>_<type>[<번호>][_<수식어>]_<속성>`로 만들어진다. 방향은 입력이면 `in`, 출력(DAC)이면 `out`이다.

### 1.4 `IIO_CHAN_INFO_*` — 숫자 하나를 표준 단위로 되돌리는 세 속성

IIO의 가장 중요한 약속은 이것이다.

```text
processed = (raw + offset) * scale
```

- `raw`: 칩이 준 정수 그대로 (부호 확장만 된 레지스터 값)
- `scale`: LSB 하나가 표준 단위로 얼마인가
- `offset`: raw에 먼저 더할 값 (온도 센서의 "0 LSB = 25 °C" 같은 기준점)

표준 단위는 `Documentation/ABI/testing/sysfs-bus-iio`에 정해져 있다. 센서 키트에서 자주 만나는 것만 추리면 다음과 같다.

| 채널 type | 표준 단위 (processed) | 흔한 칩 |
|---|---|---|
| `IIO_ACCEL` | m/s² | LSM6DSx, BMI270, ICM-42688 |
| `IIO_ANGL_VEL` | rad/s | 같은 IMU의 자이로 |
| `IIO_MAGN` | Gauss | LIS3MDL, AK8963 |
| `IIO_TEMP` | milli °C | IMU 내장 온도, TMP117 |
| `IIO_VOLTAGE` | mV | ADS1015, MCP3208 |
| `IIO_CURRENT` | mA | INA226 (IIO 쪽 드라이버) |
| `IIO_PRESSURE` | kPa | BMP280, LPS22HB |
| `IIO_HUMIDITYRELATIVE` | milli % | BME280, SHT3x |
| `IIO_LIGHT` | lux (`_input`) | VCNL4000, OPT3001 |

단위가 칩마다 다르면 유저 공간 코드가 칩마다 달라진다. IIO는 그걸 막기 위해 드라이버에게 "**raw는 손대지 말고, scale/offset으로 표준 단위를 알려라**"를 요구한다. 그래야 같은 ROS 노드가 LSM6DSO에서도 BMI270에서도 그대로 돈다. 일부 드라이버는 `IIO_CHAN_INFO_PROCESSED`(`_input` 파일)로 이미 계산된 값을 주기도 한다(조도, 걸음 수처럼 raw가 의미 없는 경우).

`info_mask`에 넣을 수 있는 속성은 `enum iio_chan_info_enum`에 30여 개가 있다. IMU·ADC에서 실제로 쓰는 것은 대부분 아래 열 개 안쪽이다.

| 비트 | sysfs 꼬리 | 뜻 |
|---|---|---|
| `IIO_CHAN_INFO_RAW` | `_raw` | 레지스터 값 |
| `IIO_CHAN_INFO_PROCESSED` | `_input` | 이미 단위가 적용된 값 |
| `IIO_CHAN_INFO_SCALE` | `_scale` | LSB당 표준 단위 |
| `IIO_CHAN_INFO_OFFSET` | `_offset` | raw에 더할 값 |
| `IIO_CHAN_INFO_SAMP_FREQ` | `sampling_frequency` | ODR (Hz) |
| `IIO_CHAN_INFO_CALIBBIAS` | `_calibbias` | 칩 내부 오프셋 보정 레지스터 |
| `IIO_CHAN_INFO_CALIBSCALE` | `_calibscale` | 칩 내부 게인 보정 |
| `IIO_CHAN_INFO_OVERSAMPLING_RATIO` | `oversampling_ratio` | 평균 횟수 |
| `IIO_CHAN_INFO_LOW_PASS_FILTER_3DB_FREQUENCY` | `_filter_low_pass_3db_frequency` | 디지털 LPF 대역 |
| `IIO_CHAN_INFO_HARDWAREGAIN` | `_hardwaregain` | PGA 이득 |

### 1.5 반환 형식 `IIO_VAL_*` — 커널에 float이 없어서

커널은 부동소수점을 쓰지 않는다(arm64 커널은 FP/SIMD 레지스터를 일반 코드에서 쓰지 못하게 `-mgeneral-regs-only`로 빌드된다). 그래서 `read_raw`는 정수 두 개(`*val`, `*val2`)와 **"이 두 정수를 어떻게 읽어라"는 형식 코드**를 돌려준다. core의 `iio_format_value()`가 그 코드대로 문자열을 만든다.

| 반환값 | `*val`, `*val2`의 뜻 | 예 → sysfs 문자열 |
|---|---|---|
| `IIO_VAL_INT` | 정수 `val` | `100` → `100` |
| `IIO_VAL_INT_PLUS_MICRO` | `val + val2/10^6` | `0, 1333` → `0.001333` |
| `IIO_VAL_INT_PLUS_NANO` | `val + val2/10^9` | `0, 598205` → `0.000598205` |
| `IIO_VAL_FRACTIONAL` | `val / val2` | `1000, 256` → `3.906250000` |
| `IIO_VAL_FRACTIONAL_LOG2` | `val / 2^val2` | `2500, 12` → `0.610351562` (12비트 ADC, 2.5 V 기준) |
| `IIO_VAL_INT_MULTIPLE` | 정수 여러 개 (`vals[]`) | 행렬·목록 |
| `IIO_VAL_INT_64` | `val`(하위 32) + `val2`(상위 32) | 64비트 카운터 |

쓰기 방향도 같다. 유저가 `echo 0.002392823 > in_accel_scale`을 하면 core가 문자열을 정수 두 개로 파싱해 `write_raw(…, val, val2, mask)`를 부른다. 이때 **소수점 아래를 몇 자리(마이크로? 나노?)로 해석할지**를 드라이버가 `write_raw_get_fmt()`로 알려 줘야 한다. 안 알려 주면 기본값이 마이크로(6자리)라서, 나노 단위 표를 가진 드라이버는 값을 영원히 못 맞춘다 — 3.7절에서 실제로 재현한다.

## 2. 예제 1 — `iio_dummy`를 configfs로 만들어 sysfs ABI 둘러보기

드라이버를 쓰기 전에, 커널에 들어 있는 **교재용 가상 장치** `iio_dummy`(`drivers/iio/dummy/iio_simple_dummy*.c`)로 유저 쪽 모습을 먼저 본다. 이 드라이버는 하드웨어가 없어서 probe가 DT나 I2C가 아니라 **configfs의 `mkdir`**로 불린다. `industrialio-sw-device`가 `/sys/kernel/config/iio/devices/<type>/` 디렉터리를 만들어 두고, 그 아래 `mkdir <이름>`을 하면 해당 sw device 드라이버의 probe가 불린다. 소프트웨어 트리거(hrtimer)도 같은 방식으로 `/sys/kernel/config/iio/triggers/hrtimer/<이름>`을 만든다(G8 노트의 configfs: "유저가 디렉터리를 만들면 커널 객체가 생긴다").

무엇을 확인하나: configfs로 장치와 트리거를 만들고, 채널 파일 이름 규칙과 scan element 타입 문자열을 확인한다.

```sh
# t2.sh (앞부분) — 게스트에서 실행
. /common.sh
modprobe iio_dummy; modprobe iio-trig-hrtimer
echo "### configfs로 장치/트리거 만들기"
mkdir $C/devices/dummy/i2_dummy
mkdir $C/triggers/hrtimer/i2_t100
/lsiio -v
D=$(dev_of i2_dummy); T=$(trig_of i2_t100)
echo "### 단발 읽기"
cd $D
for f in in_voltage0_raw in_voltage0_offset in_voltage0_scale in_voltage1-voltage2_raw in_voltage-voltage_scale in_accel_x_raw in_sampling_frequency current_timestamp_clock; do printf "%-28s %s\n" $f "$(cat $f)"; done
echo "### scan_elements"
for e in scan_elements/*_type; do n=${e%_type}; printf "%-36s idx=%s type=%s en=%s\n" ${n#scan_elements/} $(cat ${n}_index) $(cat $e) $(cat ${n}_en); done
```

출력에서 볼 것:

- `lsiio -v`는 `iio:device0`(장치)와 `trigger0`(트리거)을 따로 센다. **트리거도 IIO 버스 위의 독립 객체**다(`/sys/bus/iio/devices/trigger0`). 장치와 트리거는 나중에 이름으로 짝지어진다.
- `in_voltage0_*`는 indexed 채널(`.channel = 0`), `in_voltage1-voltage2_raw`는 differential 채널, `in_accel_x_raw`는 modified 채널이다. 그림 2의 규칙 그대로다.
- `in_voltage-voltage_scale`: 차동 전압 채널 두 개가 scale 하나를 공유한다(`shared_by_type`). 이름에서 번호가 빠진다.
- processed 전압 = `(73 + 7) × 0.001333 = 0.10664 mV`. 단위는 sysfs-bus-iio ABI에 따라 mV다.
- `in_sampling_frequency`는 `shared_by_dir`라서 `in_` 접두어가 붙고, 값이 `3.000000033`처럼 INT_PLUS_NANO로 나왔다(dummy가 일부러 그렇게 돌려준다).
- `current_timestamp_clock = realtime` — **IIO의 기본 타임스탬프 시계는 `CLOCK_REALTIME`이다**. 로봇에서 이게 왜 문제인지는 10절에서 다룬다.
- scan_elements의 `_type`은 `le:u13/16>>0`(리틀엔디언, 부호 없음, 유효 13비트, 저장 16비트, 시프트 0)처럼 생겼다. 이 문자열을 파싱하는 것이 버퍼 리더의 첫 일이다(4절).
- 모든 `_en`이 0이다. 버퍼 캡처는 "어느 채널을 담을지"를 유저가 고른 다음에 시작한다.

## 3. 내 드라이버 `i2_imu` — 가짜 I2C IMU 위의 IIO 드라이버

### 3.1 가짜 칩의 레지스터 맵

H2 노트의 가짜 IMU(LSM6 계열을 단순화)를 6축 + 온도로 넓혔다. 주소 배치는 실제 LSM6DS3와 거의 같다(WHO_AM_I `0x0f`, CTRL1_XL `0x10`, CTRL2_G `0x11`, CTRL3_C `0x12`, OUT_TEMP `0x20`, 자이로 `0x22`, 가속도 `0x28`). 일부러 그렇게 맞췄기 때문에 11절에서 **업스트림 `st_lsm6dsx` 드라이버까지 이 가짜 칩에 붙는다**.

| 레지스터 | 주소 | 접근 | 이 칩에서의 동작 |
|---|---|---|---|
| INT1_CTRL | 0x0d | RW | bit0 DRDY_XL, bit1 DRDY_G → INT1 핀으로 내보낼지 |
| WHO_AM_I | 0x0f | RO | `0x69` |
| CTRL1_XL | 0x10 | RW | ODR[7:4] (1..7 = 25, 50, 100, 200, 500, 1000, 2000 Hz), FS[3:2] (±2/4/8/16 g) |
| CTRL2_G | 0x11 | RW | ODR[7:4], FS[3:2] (250/500/1000/2000 dps) |
| CTRL3_C | 0x12 | RW | bit0 SW_RESET(쓰면 POR 값으로), bit2 IF_INC(버스트 자동 증가) |
| STATUS | 0x1e | RO | bit0 XLDA, bit1 GDA, bit2 TDA — 새 샘플 있음. OUTZ_H_XL(0x2d)까지 읽으면 지워진다 |
| OUT_TEMP_L/H | 0x20–0x21 | RO | 256 LSB/°C, 0 = 25 °C |
| OUTX_L_G … | 0x22–0x27 | RO | 자이로 X/Y/Z, 16비트 LE |
| OUTX_L_XL … | 0x28–0x2d | RO | 가속도 X/Y/Z, 16비트 LE |

물리량은 이렇게 흉내 낸다: Z축에 1 g(중력), X축에 ±0.1 g 삼각파 진동(64샘플 주기), 자이로 Z에 10 dps 일정 회전, 온도 30.5 °C. full-scale을 바꾸면 raw가 그만큼 작아진다. 모듈 인자 `pattern=1`이면 자이로 X 자리에 16비트 **샘플 일련번호**를 넣는다 — 실제 칩의 self-test/test-pattern 모드처럼, 누락·중복을 세기 위한 장치다. `bus_khz=400/100`이면 전송 하나가 그 버스 클럭에서 걸릴 시간만큼 `xfer()`가 잠든다(6.3절).

### 3.2 `i2_fakebus.c` — 칩 흉내 + 어댑터 + INT1

H5/H2와 다른 점은 셋이다. (1) ODR **hrtimer가 칩 내부 발진기**다 — 레지스터 값을 갱신하고 STATUS 비트를 세운다. (2) `irq_sim`으로 **INT1 핀 하나짜리 irqchip**을 만들고, 샘플이 생길 때 `irq_set_irqchip_state(virq, IRQCHIP_STATE_PENDING, true)`로 인터럽트를 친다(H6 노트의 irq_domain). (3) client를 `i2c_new_client_device()`로 직접 만들면서 `board_info.irq = virq`, `board_info.swnode`(= DT 속성 흉내: `mount-matrix`)를 준다. 드라이버 쪽에서 보면 **DT에 `interrupts`와 `mount-matrix`가 있는 진짜 보드와 똑같다**.

```c
// i2_fakebus.c — 가짜 I2C 어댑터 + 0x6b의 6축 IMU: ODR 타이머가 샘플을 만들고 INT1을 친다
#include <linux/module.h>
#include <linux/i2c.h>
#include <linux/hrtimer.h>
#include <linux/irq_sim.h>
#include <linux/irqdomain.h>
#include <linux/interrupt.h>
#include <linux/property.h>
#include <linux/delay.h>
#include "i2_regs.h"

static const unsigned int odr_hz[] = { 0, 25, 50, 100, 200, 500, 1000, 2000 };
static struct i2c_adapter adap;
static struct i2c_client *client;
static struct irq_domain *sim;
static int virq;
static struct hrtimer tick;
static DEFINE_SPINLOCK(lock);		/* hrtimer(hardirq)와 xfer(프로세스)가 regs 공유 */
static u8 regs[256];
static u16 seq;
static unsigned long n_tick, n_irq, n_xfer, n_rbytes;
static bool pattern;			/* 1 = 자이로 X에 16비트 샘플 번호(테스트 패턴) */
module_param(pattern, bool, 0644);
static unsigned int bus_khz;		/* 0 = 무한대, 100/400 = 그 클럭의 전송 시간만큼 잠든다 */
module_param(bus_khz, uint, 0644);

static void put16(u8 r, s16 v) { regs[r] = v & 0xff; regs[r + 1] = (u16)v >> 8; }

static void por(void)			/* power-on reset 값 */
{
	memset(regs, 0, sizeof(regs));
	regs[I2_WHO_AM_I] = I2_WHOAMI_VAL;
	regs[I2_CTRL3_C] = 0x04;	/* IF_INC */
}

static void make_sample(void)		/* 물리량: 1 g on Z, X 진동(삼각파), 자이로 Z 10 dps, 30.5 °C */
{
	int fsx = 1 << ((regs[I2_CTRL1_XL] & I2_FS_MASK) >> 2);	/* 1,2,4,8 = ±2,4,8,16 g */
	int fsg = 1 << ((regs[I2_CTRL2_G] & I2_FS_MASK) >> 2);	/* 250,500,1000,2000 dps */
	int tri = (seq & 63) < 32 ? (seq & 31) - 16 : 16 - (seq & 31);	/* -16..15 */

	seq++;
	put16(I2_OUT_TEMP_L, 1408);			/* 25 + 5.5 °C */
	put16(I2_OUTX_L_G, pattern ? (s16)seq : 0);
	put16(I2_OUTX_L_G + 2, 0);
	put16(I2_OUTX_L_G + 4, 1143 / fsg);			/* 10 dps / 8.75 mdps */
	put16(I2_OUTX_L_XL, tri * 102 / fsx);			/* ±0.1 g */
	put16(I2_OUTX_L_XL + 2, 0);
	put16(I2_OUTX_L_XL + 4, 16393 / fsx);			/* 1 g / 0.061 mg */
	regs[I2_STATUS] |= 0x07;
}
```

```c
static unsigned int chip_hz(void)	/* 가속도·자이로 중 빠른 ODR로 발진 */
{
	return max(odr_hz[regs[I2_CTRL1_XL] >> 4 & 7], odr_hz[regs[I2_CTRL2_G] >> 4 & 7]);
}

static enum hrtimer_restart tick_fn(struct hrtimer *t)	/* 칩 내부 ODR 발진기 */
{
	unsigned int hz = chip_hz();
	bool fire;

	if (!hz)
		return HRTIMER_NORESTART;
	spin_lock(&lock);
	make_sample();
	n_tick++;
	fire = regs[I2_INT1_CTRL] & 0x03;
	spin_unlock(&lock);
	if (fire && !irq_set_irqchip_state(virq, IRQCHIP_STATE_PENDING, true))
		n_irq++;			/* INT1 펄스 = irq_sim에 pending 세우기 */
	hrtimer_forward_now(t, ns_to_ktime(NSEC_PER_SEC / hz));
	return HRTIMER_RESTART;
}

static void wr(u8 r, u8 v)		/* 쓰기 가능한 레지스터만, 부작용 포함 */
{
	if (r == I2_CTRL3_C && (v & 1)) { por(); return; }	/* SW_RESET: 즉시 완료 */
	if (r != I2_INT1_CTRL && r != I2_CTRL1_XL && r != I2_CTRL2_G && r != I2_CTRL3_C)
		return;
	regs[r] = v;
	if ((r == I2_CTRL1_XL || r == I2_CTRL2_G) && chip_hz())
		hrtimer_start(&tick, ns_to_ktime(NSEC_PER_SEC / chip_hz()),
			      HRTIMER_MODE_REL_HARD);	/* ODR 바뀌면 발진기 재시작 */
}
```

hrtimer 콜백은 **hardirq 문맥**(`HRTIMER_MODE_REL_HARD`)에서 돈다. 그래서 레지스터 파일은 mutex가 아니라 spinlock으로 지키고, 프로세스 문맥인 `xfer()` 쪽은 `spin_lock_irqsave`를 쓴다(F4 노트의 규칙: "IRQ 문맥과 공유하는 데이터는 irqsave"). `hrtimer_forward_now()`는 콜백이 늦게 불려 주기를 여러 번 놓쳤으면 **놓친 주기를 건너뛴다** — 그래서 TCG처럼 느린 환경에서는 칩 자체가 ODR보다 조금 적게 샘플을 만든다(6절에서 `ticks`로 보인다).

```c
static int fb_xfer(struct i2c_adapter *a, struct i2c_msg *msgs, int num)
{
	unsigned long flags;
	unsigned int bits = 2;			/* START + STOP 근사 */
	u8 ptr = 0;
	int i, j;

	n_xfer++;
	for (i = 0; i < num; i++) {
		struct i2c_msg *m = &msgs[i];

		if (m->addr != I2_ADDR)
			return -ENXIO;				/* 주소 NACK */
		spin_lock_irqsave(&lock, flags);
		if (m->flags & I2C_M_RD) {
			for (j = 0; j < m->len; j++, ptr++) {
				m->buf[j] = regs[ptr];
				if (ptr == I2_OUTZ_H_XL)
					regs[I2_STATUS] = 0;	/* 마지막 바이트 읽으면 DA 해제 */
			}
			n_rbytes += m->len;
		} else {
			ptr = m->buf[0];
			for (j = 1; j < m->len; j++)
				wr(ptr++, m->buf[j]);
		}
		spin_unlock_irqrestore(&lock, flags);
		bits += (m->len + 1) * 9;	/* 주소 바이트 + 데이터, 바이트당 ACK 포함 9클럭 */
	}
	if (bus_khz)				/* 진짜 컨트롤러처럼 전송 완료까지 잠든다 */
		usleep_range(bits * 1000 / bus_khz, bits * 1000 / bus_khz + 20);
	return num;
}
```

```c
static u32 fb_func(struct i2c_adapter *a) { return I2C_FUNC_I2C | I2C_FUNC_SMBUS_EMUL; }
static const struct i2c_algorithm fb_algo = { .xfer = fb_xfer, .functionality = fb_func };

static int stats_get(char *buf, const struct kernel_param *kp)
{
	return sysfs_emit(buf, "ticks=%lu irqs=%lu xfers=%lu rbytes=%lu\n",
			  n_tick, n_irq, n_xfer, n_rbytes);
}
static int stats_set(const char *v, const struct kernel_param *kp)
{
	n_tick = n_irq = n_xfer = n_rbytes = 0;
	return 0;
}
static const struct kernel_param_ops stats_ops = { .get = stats_get, .set = stats_set };
module_param_cb(stats, &stats_ops, NULL, 0644);

/* 보드 정보: DT라면 interrupts = <...>; mount-matrix = "..."; 에 해당 */
static const char * const mm[] = { "0", "-1", "0",  "1", "0", "0",  "0", "0", "1" };
static const struct property_entry props[] = {
	PROPERTY_ENTRY_STRING_ARRAY("mount-matrix", mm), { }
};
static const struct software_node imu_node = { .properties = props };

static char *devname = "i2_imu";	/* "lsm6ds3" = 업스트림 st_lsm6dsx를 붙여 보기 */
module_param(devname, charp, 0444);

```

```c
static int __init fb_init(void)
{
	struct i2c_board_info info = { .addr = I2_ADDR };
	int ret;

	por();
	hrtimer_setup(&tick, tick_fn, CLOCK_MONOTONIC, HRTIMER_MODE_REL_HARD);
	sim = irq_domain_create_sim(NULL, 1);		/* INT1 핀 하나짜리 가짜 irqchip */
	if (IS_ERR(sim))
		return PTR_ERR(sim);
	virq = irq_create_mapping(sim, 0);
	adap.owner = THIS_MODULE;
	adap.algo = &fb_algo;
	strscpy(adap.name, "i2-fakebus", sizeof(adap.name));
	ret = i2c_add_adapter(&adap);
	if (ret)
		goto err_sim;
	strscpy(info.type, devname, sizeof(info.type));
	info.irq = strcmp(devname, "i2_imu") ? 0 : virq;	/* 업스트림 실험은 IRQ 없이 */
	info.swnode = &imu_node;
	client = i2c_new_client_device(&adap, &info);	/* = DT 자식 노드가 하는 일 */
	if (IS_ERR(client)) {
		ret = PTR_ERR(client);
		goto err_adap;
	}
	pr_info("i2_fakebus: i2c-%d, IMU 0x%02x, INT1 = virq %d\n", adap.nr, I2_ADDR, virq);
	return 0;
err_adap:
	i2c_del_adapter(&adap);
err_sim:
	irq_domain_remove_sim(sim);
	return ret;
}

static void __exit fb_exit(void)
{
	i2c_unregister_device(client);
	i2c_del_adapter(&adap);
	hrtimer_cancel(&tick);
	irq_dispose_mapping(virq);
	irq_domain_remove_sim(sim);
}
module_init(fb_init);
module_exit(fb_exit);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("I2: fake I2C adapter + 6-axis IMU with data-ready IRQ");
```

### 3.3 `i2_imu.c` — IIO 드라이버 (1/5) 상태와 단위 표

```c
// i2_imu.c — 6축 IMU IIO 드라이버 (1/5: 상태 구조체와 단위 표)
#include <linux/module.h>
#include <linux/i2c.h>
#include <linux/regmap.h>
#include <linux/bitfield.h>
#include <linux/interrupt.h>
#include <linux/iio/iio.h>
#include <linux/iio/sysfs.h>
#include <linux/iio/buffer.h>
#include <linux/iio/trigger.h>
#include <linux/iio/triggered_buffer.h>
#include <linux/iio/trigger_consumer.h>
#include "i2_regs.h"

enum { I2_AX, I2_AY, I2_AZ, I2_GX, I2_GY, I2_GZ, I2_TEMP, I2_TS };	/* scan_index */

struct i2_imu {
	struct regmap *map;
	struct iio_trigger *trig;
	struct iio_mount_matrix orient;
	struct mutex lock;			/* ODR/FS 변경 직렬화 */
	unsigned int odr, fs_xl, fs_g;		/* 표 인덱스 */
	unsigned long n_poll, n_push, n_full, n_stale;	/* 관측용 카운터 */
	struct {
		__le16 ch[7];			/* 활성 채널만 앞에서부터 채운다 */
		aligned_s64 ts;			/* 8바이트 정렬된 타임스탬프 자리 */
	} scan;
};

static bool no_fmt;			/* 1 = write_raw_get_fmt 빼기 (함정 재현) */
module_param(no_fmt, bool, 0444);
static bool check_da;			/* 1 = STATUS.XLDA 확인 후 push */
module_param(check_da, bool, 0444);

static const int odr_avail[] = { 25, 50, 100, 200, 500, 1000, 2000 };	/* ODR 코드 1..7 */
/* IIO 표준 단위: 가속도 m/s², 각속도 rad/s. {정수부, 나노부} = IIO_VAL_INT_PLUS_NANO */
static const int xl_scale[][2] = { {0, 598205}, {0, 1196411}, {0, 2392823}, {0, 4785645} };
static const int g_scale[][2] = { {0, 152716}, {0, 305433}, {0, 610865}, {0, 1221730} };
/* scan_index → 버스트 안 16비트 슬롯 (w[0]=TEMP, w[1..3]=G, w[4..6]=XL) */
static const u8 reg_slot[] = { 4, 5, 6, 1, 2, 3, 0 };
```

단위 표의 숫자는 데이터시트 감도에서 나온다. ±2 g 범위의 감도가 0.061 mg/LSB라면

```text
scale = 0.061e-3 g × 9.80665 (m/s² per g) = 0.000598205 m/s² per LSB  →  {0, 598205} (INT_PLUS_NANO)
±4 g: 0.122 mg → 0.001196411   ±8 g: 0.244 mg → 0.002392823   ±16 g: 0.488 mg → 0.004785645
자이로 250 dps: 8.75 mdps/LSB × π/180 = 0.000152716 rad/s per LSB  →  {0, 152716}
```

마이크로(6자리)로는 0.000598까지밖에 못 적어서 0.03% 오차가 생긴다 — 그래서 IMU 드라이버들은 거의 다 `IIO_VAL_INT_PLUS_NANO`를 쓴다. 업스트림 `st_lsm6dsx`도 `IIO_G_TO_M_S_2(61000)` 같은 매크로로 같은 표를 만든다.

`struct scan`이 이 드라이버의 **버퍼 한 칸(scan) 모양**이다. 16비트 7개(14바이트) 뒤에 `aligned_s64 ts`를 두면 컴파일러가 2바이트 패딩을 넣어 ts를 오프셋 16에 놓고, 전체는 24바이트가 된다. 이것이 4.2절에서 유저가 계산할 배치와 정확히 같아야 한다.

### 3.4 (2/5) 채널 표

static const struct iio_mount_matrix *
i2_get_mount_matrix(const struct iio_dev *indio_dev, const struct iio_chan_spec *ch)
{

}

static const struct iio_chan_spec_ext_info i2_ext_info[] = {
	IIO_MOUNT_MATRIX(IIO_SHARED_BY_DIR, i2_get_mount_matrix),

	I2_CHAN(IIO_ANGL_VEL, IIO_MOD_Y, I2_OUTX_L_G + 2, I2_GY),

		.scan_type = { .sign = 's', .realbits = 16, .storagebits = 16,

- 매크로 하나로 6개 축을 찍어 낸다. 실제 드라이버(`ST_LSM6DSX_CHANNEL_ACC`, `INV_MPU6050_CHAN`)도 같은 패턴이다.
- `.address`에 OUT 레지스터 주소를 넣어 두면 `read_raw`가 채널마다 `switch`할 필요가 없다.

- `IIO_CHAN_SOFT_TIMESTAMP(I2_TS)`는 `type = IIO_TIMESTAMP, channel = -1, scan_type = {'s', 64, 64}` 채널을 만든다 — 버퍼에만 존재하는 "가짜 채널"이다.

### 3.5 (3/5) 단발 읽기와 가능한 값

```c
/* (3/5) 단발 읽기(sysfs)와 "가능한 값" 목록 */
static int i2_read_raw(struct iio_dev *indio_dev, struct iio_chan_spec const *ch,
		       int *val, int *val2, long mask)
{
	struct i2_imu *st = iio_priv(indio_dev);
	__le16 raw;
	int ret;

	switch (mask) {
	case IIO_CHAN_INFO_RAW:
		if (!iio_device_claim_direct(indio_dev))
			return -EBUSY;		/* 버퍼 캡처 중에는 단발 읽기 금지 */
		ret = regmap_bulk_read(st->map, ch->address, &raw, sizeof(raw));
		iio_device_release_direct(indio_dev);
		if (ret)
			return ret;
		*val = (s16)le16_to_cpu(raw);
		return IIO_VAL_INT;
	case IIO_CHAN_INFO_SCALE:
		if (ch->type == IIO_TEMP) {	/* 1000/256 m°C per LSB */
			*val = 1000;
			*val2 = 256;
			return IIO_VAL_FRACTIONAL;
		}
		*val = 0;
		*val2 = ch->type == IIO_ACCEL ? xl_scale[st->fs_xl][1] : g_scale[st->fs_g][1];
		return IIO_VAL_INT_PLUS_NANO;
	case IIO_CHAN_INFO_OFFSET:		/* raw 0 = 25 °C → offset = 25 * 256 */
		*val = 25 * 256;
		return IIO_VAL_INT;
	case IIO_CHAN_INFO_SAMP_FREQ:
		*val = odr_avail[st->odr];
		return IIO_VAL_INT;
	}
	return -EINVAL;
}

static int i2_read_avail(struct iio_dev *indio_dev, struct iio_chan_spec const *ch,
			 const int **vals, int *type, int *length, long mask)
{
	switch (mask) {
	case IIO_CHAN_INFO_SCALE:
		*vals = (const int *)(ch->type == IIO_ACCEL ? xl_scale : g_scale);
		*type = IIO_VAL_INT_PLUS_NANO;
		*length = ARRAY_SIZE(xl_scale) * 2;	/* int 개수 = 쌍 x 2 */
		return IIO_AVAIL_LIST;
	case IIO_CHAN_INFO_SAMP_FREQ:
		*vals = odr_avail;
		*type = IIO_VAL_INT;
		*length = ARRAY_SIZE(odr_avail);
		return IIO_AVAIL_LIST;
	}
	return -EINVAL;
}
```

`iio_device_claim_direct()`는 "지금 버퍼 모드가 아니면 direct 모드를 잡고 true"를 돌려준다(6.18 API. 예전 커널은 `iio_device_claim_direct_mode()`가 int를 돌려줬다). 버퍼 캡처 중에는 칩 레지스터를 트리거 핸들러가 고속으로 읽고 있으므로, 사이에 끼어드는 단발 읽기를 막는다. 막지 않으면 (a) 버스 트래픽이 끼어들어 샘플 타이밍이 흔들리고, (b) STATUS 같은 clear-on-read 레지스터를 엉뚱한 쪽이 지운다.

`read_avail`은 `*_available` 파일의 내용을 준다. `IIO_AVAIL_LIST`면 값 목록, `IIO_AVAIL_RANGE`면 `[min step max]` 세 값이다. INT_PLUS_NANO 목록은 `{정수, 나노}` 쌍을 펼친 int 배열이라 `*length`가 쌍 개수 × 2다.

### 3.6 (4/5) 쓰기 — ODR과 full-scale

```c
/* (4/5) 쓰기: ODR·full-scale 바꾸기 */
static int i2_write_raw(struct iio_dev *indio_dev, struct iio_chan_spec const *ch,
			int val, int val2, long mask)
{
	struct i2_imu *st = iio_priv(indio_dev);
	bool xl = ch->type == IIO_ACCEL;
	const int (*tbl)[2] = xl ? xl_scale : g_scale;
	int i, ret;

	guard(mutex)(&st->lock);
	switch (mask) {
	case IIO_CHAN_INFO_SAMP_FREQ:
		for (i = 0; i < ARRAY_SIZE(odr_avail); i++)
			if (odr_avail[i] == val && !val2)
				break;
		if (i == ARRAY_SIZE(odr_avail))
			return -EINVAL;
		ret = regmap_update_bits(st->map, I2_CTRL2_G, I2_ODR_MASK,
					 FIELD_PREP(I2_ODR_MASK, i + 1));
		ret = ret ?: regmap_update_bits(st->map, I2_CTRL1_XL, I2_ODR_MASK,
						FIELD_PREP(I2_ODR_MASK, i + 1));
		if (!ret)
			st->odr = i;
		return ret;
	case IIO_CHAN_INFO_SCALE:
		if (no_fmt)
			dev_info(&indio_dev->dev, "SCALE write: val=%d val2=%d\n", val, val2);
		for (i = 0; i < ARRAY_SIZE(xl_scale); i++)
			if (val == 0 && val2 == tbl[i][1])
				break;
		if (i == ARRAY_SIZE(xl_scale))
			return -EINVAL;
		if (!iio_device_claim_direct(indio_dev))
			return -EBUSY;		/* 캡처 중 단위가 바뀌면 데이터가 거짓말이 된다 */
		ret = regmap_update_bits(st->map, xl ? I2_CTRL1_XL : I2_CTRL2_G,
					 I2_FS_MASK, FIELD_PREP(I2_FS_MASK, i));
		iio_device_release_direct(indio_dev);
		if (!ret)
			*(xl ? &st->fs_xl : &st->fs_g) = i;
		return ret;
	}
	return -EINVAL;
}

/* sysfs 문자열 "0.000598205"를 몇 자리 소수로 파싱할지 core에 알려 준다 */
static int i2_write_raw_get_fmt(struct iio_dev *indio_dev,
				struct iio_chan_spec const *ch, long mask)
{
	return mask == IIO_CHAN_INFO_SCALE ? IIO_VAL_INT_PLUS_NANO : IIO_VAL_INT;
}
```

- ODR은 버퍼가 돌 때도 바꾸게 했고(많은 드라이버가 허용한다), full-scale은 **버퍼 중 변경 금지**(`-EBUSY`)로 했다. 캡처 중간에 scale이 바뀌면 유저는 한 번 읽어 둔 `in_accel_scale`로 이후 raw를 계속 곱할 것이고, 데이터가 조용히 4배 틀린다.
- `guard(mutex)(&st->lock)`은 6.x 커널의 scope-based cleanup(`linux/cleanup.h`)이다. 함수가 어느 `return`으로 나가든 unlock이 보장된다.
- `no_fmt`일 때만 찍는 `dev_info`는 3.8절 함정 재현용이다.

### 3.7 (5/5) 트리거·버퍼 핸들러와 probe

```c
/* (5/5-a) data-ready 트리거와 버퍼 채우기 (bottom half, 스레드 문맥) */
static int i2_drdy_set_state(struct iio_trigger *trig, bool on)
{
	struct i2_imu *st = iio_trigger_get_drvdata(trig);

	return regmap_write(st->map, I2_INT1_CTRL, on ? 0x01 : 0x00);	/* DRDY → INT1 */
}

static const struct iio_trigger_ops i2_trig_ops = {
	.set_trigger_state = i2_drdy_set_state,
};

static irqreturn_t i2_trigger_handler(int irq, void *p)
{
	struct iio_poll_func *pf = p;
	struct iio_dev *indio_dev = pf->indio_dev;
	struct i2_imu *st = iio_priv(indio_dev);
	struct { u8 status, rsvd; __le16 w[7]; } __packed b;	/* 0x1e..0x2d */
	int i = 0, bit;

	st->n_poll++;
	if (regmap_bulk_read(st->map, I2_STATUS, &b, sizeof(b)))
		goto done;			/* 16바이트를 I2C 트랜잭션 1번에 */
	if (check_da && !(b.status & 0x01)) {
		st->n_stale++;			/* 새 샘플이 아니다: 중복 push 방지 */
		goto done;
	}
	iio_for_each_active_channel(indio_dev, bit) {
		if (bit >= I2_TS)
			break;
		st->scan.ch[i++] = b.w[reg_slot[bit]];	/* LE 그대로: 변환 없음 */
	}
	if (iio_push_to_buffers_with_ts(indio_dev, &st->scan, sizeof(st->scan),
					pf->timestamp))
		st->n_full++;			/* kfifo가 가득: 이 샘플은 버려진다 */
	else
		st->n_push++;
done:
	iio_trigger_notify_done(indio_dev->trig);	/* 다음 트리거를 받을 수 있게 */
	return IRQ_HANDLED;
}

static ssize_t i2_stats_show(struct device *dev, struct device_attribute *a, char *buf)
{
	struct i2_imu *st = iio_priv(dev_to_iio_dev(dev));

	return sysfs_emit(buf, "polls=%lu pushed=%lu full=%lu stale=%lu\n",
			  st->n_poll, st->n_push, st->n_full, st->n_stale);
}
static IIO_DEVICE_ATTR(i2_stats, 0444, i2_stats_show, NULL, 0);
static struct attribute *i2_attrs[] = { &iio_dev_attr_i2_stats.dev_attr.attr, NULL };
static const struct attribute_group i2_group = { .attrs = i2_attrs };

static int i2_reg_access(struct iio_dev *indio_dev, unsigned int reg,
			 unsigned int wval, unsigned int *rval)
{
	struct i2_imu *st = iio_priv(indio_dev);

	return rval ? regmap_read(st->map, reg, rval) : regmap_write(st->map, reg, wval);
}
```

```c
/* (5/5-b) iio_info, regmap, probe */
static struct iio_info i2_info = {
	.read_raw = i2_read_raw,
	.write_raw = i2_write_raw,
	.read_avail = i2_read_avail,
	.write_raw_get_fmt = i2_write_raw_get_fmt,
	.attrs = &i2_group,
	.debugfs_reg_access = i2_reg_access,
};

static bool i2_volatile(struct device *dev, unsigned int reg)
{
	return reg == I2_CTRL3_C || (reg >= I2_STATUS && reg <= I2_OUTZ_H_XL);
}

static const struct regmap_config i2_regmap_cfg = {
	.reg_bits = 8, .val_bits = 8, .max_register = I2_MAX_REG,
	.volatile_reg = i2_volatile, .cache_type = REGCACHE_MAPLE,
};

static int i2_probe(struct i2c_client *client)
{
	struct device *dev = &client->dev;
	struct iio_dev *indio_dev;
	struct i2_imu *st;
	unsigned int id;
	int ret;

	indio_dev = devm_iio_device_alloc(dev, sizeof(*st));	/* iio_dev + priv 한 덩어리 */
	if (!indio_dev)
		return -ENOMEM;
	st = iio_priv(indio_dev);
	ret = devm_mutex_init(dev, &st->lock);
	if (ret)
		return ret;
	st->map = devm_regmap_init_i2c(client, &i2_regmap_cfg);
	if (IS_ERR(st->map))
		return PTR_ERR(st->map);
	ret = regmap_read(st->map, I2_WHO_AM_I, &id);
	if (ret)
		return dev_err_probe(dev, ret, "no response\n");
	if (id != I2_WHOAMI_VAL)
		return dev_err_probe(dev, -ENODEV, "WHO_AM_I 0x%02x\n", id);
	ret = iio_read_mount_matrix(dev, &st->orient);	/* DT/swnode "mount-matrix" */
	if (ret)
		return ret;
	st->odr = 2;					/* 기본 100 Hz, ±2 g, 250 dps */
	ret = regmap_write(st->map, I2_CTRL3_C, 0x04);	/* IF_INC (버스트 자동 증가) */
	ret = ret ?: regmap_write(st->map, I2_CTRL2_G, FIELD_PREP(I2_ODR_MASK, 3));
	ret = ret ?: regmap_write(st->map, I2_CTRL1_XL, FIELD_PREP(I2_ODR_MASK, 3));
	if (ret)
		return ret;
	if (no_fmt)
		i2_info.write_raw_get_fmt = NULL;
```

```c
	indio_dev->name = "i2_imu";
	indio_dev->info = &i2_info;
	indio_dev->channels = i2_channels;
	indio_dev->num_channels = ARRAY_SIZE(i2_channels);
	indio_dev->modes = INDIO_DIRECT_MODE;	/* buffer setup이 TRIGGERED를 더한다 */

	if (client->irq > 0) {			/* INT1이 배선돼 있으면 자체 트리거 */

		iio_trigger_set_drvdata(st->trig, st);

probe의 순서가 곧 "IMU 드라이버 설계" 면접 답의 뼈대다.

1. `devm_iio_device_alloc` → priv.
2. `devm_regmap_init_i2c` — 버스를 regmap 뒤에 숨긴다(H2). volatile 범위는 **STATUS부터 OUT 끝까지 연속**으로 잡았다. 버스트 읽기 범위 안에 캐시되는 레지스터가 하나라도 섞이면 `regmap_bulk_read`가 한 번의 I2C 전송 대신 레지스터별로 쪼개 읽기 때문이다.
3. WHO_AM_I 확인 → 틀리면 `-ENODEV`(`dev_err_probe`로 로그).
4. `iio_read_mount_matrix` — DT/swnode의 `mount-matrix` 속성.
5. 칩 초기 설정(IF_INC, 기본 ODR).
6. 채널·info 연결.
7. IRQ가 있으면 **자체 data-ready 트리거**: `devm_iio_trigger_alloc` → `ops.set_trigger_state`(칩의 INT1 enable) → `devm_request_irq(..., iio_trigger_generic_data_rdy_poll, ...)` → `devm_iio_trigger_register` → `indio_dev->trig = iio_trigger_get(trig)`(기본 트리거로).
8. `devm_iio_triggered_buffer_setup(dev, indio_dev, iio_pollfunc_store_time, i2_trigger_handler, NULL)` — kfifo 버퍼 + pollfunc(top half: 타임스탬프 저장, bottom half: 내 핸들러) 한 방에.
9. `devm_iio_device_register` — 이 순간 sysfs 파일과 `/dev/iio:deviceN`이 생긴다. **반드시 마지막**: 등록 직후부터 유저가 파일을 열 수 있으므로, 그 전에 모든 것이 준비돼 있어야 한다.

트리거 핸들러가 하는 일은 bare-metal DRDY 태스크와 같다: 버스트 한 번(STATUS부터 16바이트 = I2C 트랜잭션 1번), 켜진 채널만 앞에서부터 채우기(`iio_for_each_active_channel`), 타임스탬프를 붙여 push, `iio_trigger_notify_done`. 값은 **LE 바이트 그대로** 넣는다. 채널 `scan_type.endianness = IIO_LE`라고 선언했으므로 변환은 유저 몫이다(4절). `check_da=1`이면 STATUS.XLDA가 꺼져 있을 때(= 새 샘플이 아닐 때) push하지 않는다 — 6.4절에서 쓰는 방어 장치다.

## 4. 버퍼 캡처 — scan, kfifo, `/dev/iio:deviceN`

### 4.1 직관 — DRDY 링버퍼를 커널이 대신 관리한다

sysfs `in_accel_x_raw`를 1 kHz로 읽으면 어떻게 될까? 샘플 하나(7채널)마다 `open/read` 시스템 콜 7번, I2C 트랜잭션 7번, 문자열 변환 7번이 든다. 게다가 **읽은 시각이 곧 샘플 시각**이라 스케줄링 지연이 그대로 타이밍 오차가 된다. 8절에서 실제로 재 보면 샘플당 CPU가 버퍼 방식의 5~18배다.

버퍼 모드는 Don이 bare-metal에서 하던 방식 그대로다: **DRDY 인터럽트가 올 때마다 커널이 칩을 읽어 (값들 + 타임스탬프)를 고정 크기 레코드로 링버퍼에 넣고, 유저는 레코드 여러 개를 `read()` 한 번으로 가져간다.** 이 고정 크기 레코드를 IIO에서는 **scan**(또는 datum)이라 부른다.

유저 쪽 순서는 언제나 같다.

1. 어느 채널을 담을지 고른다: `scan_elements/<채널>_en`에 1.
2. 트리거를 고른다: `trigger/current_trigger`에 트리거 이름(자체 트리거가 있으면 이미 기본값).
3. 버퍼 크기(`buffer/length`, scan 개수)와 깨울 기준(`buffer/watermark`)을 정한다.
4. `buffer/enable`에 1 — 이 순간 core가 scan 배치를 확정하고, 트리거에 pollfunc을 붙이고, 드라이버의 `set_trigger_state(true)`가 칩 INT1을 켠다.
5. `/dev/iio:deviceN`을 `read()`한다. 반환되는 바이트는 항상 scan 크기의 배수다.
6. 끝나면 `buffer/enable`에 0.

### 4.2 scan 배치 규칙 — 유저가 손으로 계산해야 하는 것

`/dev/iio:deviceN`에서 나오는 바이트에는 헤더가 없다. 어떤 채널이 어디에 있는지는 **sysfs `scan_elements/`를 읽어서 유저가 계산**한다. 규칙은 세 줄이다.

1. 켜진(`_en = 1`) 채널만, `_index` 오름차순으로 놓는다.
2. 각 원소는 자기 크기(`storagebits/8`)의 배수 위치에서 시작한다 — 필요하면 앞에 패딩.
3. scan 전체 크기는 가장 큰 원소 크기의 배수로 올린다.

원소 안의 값은 `_type` 문자열이 설명한다: `[be|le]:[s|u]<realbits>/<storagebits>[X<repeat>]>><shift>`. 예를 들어 12비트 ADC가 16비트 칸의 위쪽 12비트에 값을 두면 `be:s12/16>>4` — 빅엔디언으로 16비트를 읽고, 4비트 오른쪽으로 밀고, 하위 12비트를 남긴 뒤 부호 확장한다.

그림 4 — 세 가지 scan 배치. 타임스탬프(s64)는 8의 배수 위치로 밀리고, 그 앞은 패딩(회색)이다. i2_imu 7채널은 14바이트 + 패딩 2 + ts 8 = 24바이트, 가속도만 켜면 6 + 2 + 8 = 16바이트, iio_dummy 3채널도 16바이트.

이 규칙이 커널 안에서는 `iio_compute_scan_bytes()`이고, 드라이버 쪽에서는 `struct { __le16 ch[7]; aligned_s64 ts; }`이 같은 배치를 만든다. 드라이버가 채널 일부만 켜진 경우에도 **앞에서부터 빈틈없이** 채우는 이유가 이것이다(`iio_for_each_active_channel` 루프). 그리고 `iio_push_to_buffers_with_ts()`는 ts를 `scan_bytes / 8 - 1`번째 s64 자리, 즉 **scan의 마지막 8바이트**에 써 넣는다(`include/linux/iio/buffer.h`의 `iio_push_to_buffers_with_timestamp`). 6.18의 `_with_ts` 버전은 버퍼 길이를 함께 받아, 드라이버 버퍼가 `scan_bytes`보다 작으면 `-ENOSPC`로 거절한다 — 예전 API에서 흔하던 "타임스탬프가 스택 너머에 써지는" 버그를 막는 장치다.

### 4.3 예제 5 — 범용 버퍼 리더를 직접 짠다

무엇을 확인하나: sysfs `scan_elements`만 보고 배치를 계산해, 어떤 IIO 장치의 버퍼든 해독하는 리더. 먼저 배치 계산부(헤더)다.

```c
/* i2scan.h — scan_elements/를 읽어 "한 scan(샘플 묶음)"의 바이트 배치를 계산 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <dirent.h>

struct el { char name[64]; int idx, be, sign, real, store, shift, off; };
static struct el els[32];
static int nel, scan_bytes;

static int rd_str(const char *dir, const char *f, char *buf, int n)
{
	char p[512];
	FILE *fp;

	snprintf(p, sizeof(p), "%s/scan_elements/%s", dir, f);
	if (!(fp = fopen(p, "r")) || !fgets(buf, n, fp)) { perror(p); exit(1); }
	fclose(fp);
	return atoi(buf);
}

static int by_idx(const void *a, const void *b)
{
	return ((const struct el *)a)->idx - ((const struct el *)b)->idx;
}
```

```c
static void scan_layout(const char *dir)	/* dir = /sys/bus/iio/devices/iio:deviceN */
{
	char p[512], buf[64], e;
	struct dirent *d;
	DIR *dp;
	int i, maxal = 1;

	snprintf(p, sizeof(p), "%s/scan_elements", dir);
	if (!(dp = opendir(p))) { perror(p); exit(1); }
	while ((d = readdir(dp)) && nel < 32) {
		char *s = strstr(d->d_name, "_en");
		if (!s || s[3] || !rd_str(dir, d->d_name, buf, sizeof(buf)))
			continue;			/* 켜진 채널만 */
		struct el *x = &els[nel++];
		snprintf(x->name, sizeof(x->name), "%.*s", (int)(s - d->d_name), d->d_name);
		snprintf(p, sizeof(p), "%s_index", x->name);
		x->idx = rd_str(dir, p, buf, sizeof(buf));
		snprintf(p, sizeof(p), "%s_type", x->name);
		rd_str(dir, p, buf, sizeof(buf));	/* 예: "le:s16/16>>0" */
		sscanf(buf, "%ce:%c%d/%d>>%d", &e, &e, &x->real, &x->store, &x->shift);
		x->be = buf[0] == 'b';
		x->sign = buf[3] == 's';
	}
	closedir(dp);
	qsort(els, nel, sizeof(els[0]), by_idx);	/* 버퍼 안 순서 = index 오름차순 */
	for (i = 0; i < nel; i++) {		/* 각 원소는 자기 크기로 자연 정렬 */
		int sz = els[i].store / 8;
		scan_bytes = (scan_bytes + sz - 1) / sz * sz;
		els[i].off = scan_bytes;
		scan_bytes += sz;
		if (sz > maxal) maxal = sz;
	}
	scan_bytes = (scan_bytes + maxal - 1) / maxal * maxal;	/* 끝도 최대 정렬로 */
}
```

다음은 읽기·해독부다. `decode()`가 `_type` 문자열의 엔디언·시프트·realbits·부호를 그대로 적용한다.

```c
/* i2read.c — /dev/iio:deviceN 에서 scan N개를 읽어 sysfs 타입 문자열대로 해독 */
#include "i2scan.h"
#include <fcntl.h>
#include <unistd.h>

static int64_t decode(const unsigned char *p, const struct el *x)
{
	uint64_t v = 0;
	int i, n = x->store / 8;

	for (i = 0; i < n; i++)			/* 바이트 순서 처리 */
		v |= (uint64_t)p[x->be ? i : n - 1 - i] << (8 * (n - 1 - i));
	v >>= x->shift;
	if (x->real < 64) {
		v &= (1ULL << x->real) - 1;	/* realbits만 남기고 */
		if (x->sign && (v >> (x->real - 1)) & 1)
			v |= ~0ULL << x->real;	/* 부호 확장 */
	}
	return (int64_t)v;
}

int main(int argc, char **argv)
{
	unsigned char buf[4096];
	char dev[64];
	int fd, i, k, n, want;

	if (argc < 4) { fprintf(stderr, "usage: %s sysdir /dev/iio:deviceN nscans\n", argv[0]); return 1; }
	scan_layout(argv[1]);
	printf("scan_bytes=%d :", scan_bytes);
	for (i = 0; i < nel; i++)
		printf(" %s@%d(%c%d/%d>>%d)", els[i].name, els[i].off, els[i].sign ? 's' : 'u',
		       els[i].real, els[i].store, els[i].shift);
	printf("\n");
	snprintf(dev, sizeof(dev), "%s", argv[2]);
	if ((fd = open(dev, O_RDONLY)) < 0) { perror(dev); return 1; }
	for (want = atoi(argv[3]); want > 0; want -= n) {
		n = read(fd, buf, (want < 32 ? want : 32) * scan_bytes);	/* 블로킹 */
		if (n < 0) { perror("read"); return 1; }
		n /= scan_bytes;
		for (k = 0; k < n; k++) {
			for (i = 0; i < nel; i++)
				printf("%s%lld", i ? " " : "", (long long)decode(buf + k * scan_bytes + els[i].off, &els[i]));
			printf("\n");
		}
	}
	close(fd);
	return 0;
}
```

## 5. 트리거 — "언제 샘플을 잡을까"

### 5.1 트리거의 종류

트리거는 **샘플링 시점을 정하는 독립 객체**다. 장치와 1:1로 묶이지 않는다. 그래서 "ADC 두 개를 같은 타이머로 동시에 샘플링" 같은 구성이 sysfs 설정만으로 된다(하나의 트리거에 `CONFIG_IIO_CONSUMERS_PER_TRIGGER`(랩 커널은 2)개 장치까지 붙는다).

| 트리거 | 누가 발사하나 | 만드는 법 | 쓰는 곳 |
|---|---|---|---|
| 장치 자체 data-ready | 칩의 DRDY/INT 핀 IRQ | 드라이버가 probe에서 `devm_iio_trigger_alloc` + `request_irq` | IMU, 대부분의 ADC — **기본 선택** |
| hrtimer | 커널 hrtimer (hardirq) | configfs `mkdir /sys/kernel/config/iio/triggers/hrtimer/<이름>` 후 `sampling_frequency` | IRQ 핀이 없는 센서, 여러 센서 공통 클럭 |
| sysfs | 유저가 `trigger_now`에 쓰기 | `echo N > /sys/bus/iio/devices/iio_sysfs_trigger/add_trigger` | 테스트, 수동 단발 캡처 |
| 다른 장치의 트리거 | 예: ADC의 변환 완료, STM32 타이머 | 그 장치 드라이버가 등록 | 여러 장치 동기 샘플링 |
| 트리거 없음 (HW FIFO 직접) | 칩 FIFO watermark IRQ | 드라이버가 `devm_iio_kfifo_buffer_setup` | `st_lsm6dsx` 등 FIFO 달린 IMU (7.4절) |

드라이버는 `iio_info.validate_trigger`로 "내 장치는 내 트리거만 받는다"고 제한할 수 있다(칩 FIFO와 묶인 트리거라 외부 타이머로는 의미가 없을 때). `i2_imu`는 제한하지 않았으므로 5.4절에서 hrtimer로 바꿔 끼운다.

### 5.2 data-ready 트리거가 커널 안에서 하는 일

`i2_imu`의 IRQ 핸들러는 IIO가 주는 `iio_trigger_generic_data_rdy_poll`이고, 그 안은 `iio_trigger_poll()` 한 줄이다. 6.18 소스(`drivers/iio/industrialio-trigger.c`)는 이렇게 생겼다.

```c
/* drivers/iio/industrialio-trigger.c:195 (6.18.55, 발췌) */
void iio_trigger_poll(struct iio_trigger *trig)
{
	int i;

	if (!atomic_read(&trig->use_count)) {
		atomic_set(&trig->use_count, CONFIG_IIO_CONSUMERS_PER_TRIGGER);

		for (i = 0; i < CONFIG_IIO_CONSUMERS_PER_TRIGGER; i++) {
			if (trig->subirqs[i].enabled)
				generic_handle_irq(trig->subirq_base + i);
			else
				iio_trigger_notify_done_atomic(trig);
		}
	}
}
```

두 가지가 보인다.

1. **트리거는 그 자체가 작은 irqchip이다.** 붙어 있는 소비자(장치)마다 가상 IRQ(subirq)가 하나씩 있고, 트리거 발사 = 그 subirq들을 `generic_handle_irq`로 울리기다. 각 소비자의 pollfunc은 그 subirq에 `request_threaded_irq(pf->irq, pf->h, pf->thread, ...)`로 걸려 있다(`iio_trigger_attach_poll_func`, 같은 파일 280행). 그래서 pollfunc의 top half(`pf->h`)는 hardirq 문맥, bottom half(`pf->thread`)는 irq 스레드다 — F6 노트의 threaded IRQ 그대로다. 4.4절 `ps`에 보인 `[irq/23-i2_imu_c]`가 바로 그 스레드다(23 = subirq 번호, `i2_imu_consumer0`이 15자로 잘린 이름).
2. **`use_count`가 0이 아니면 아무것도 안 한다.** 모든 소비자가 `iio_trigger_notify_done()`을 불러 카운트를 0으로 되돌리기 전에 다음 트리거가 오면, 그 트리거는 **경고 없이 버려진다**. bottom half(I2C 읽기)가 샘플 주기보다 오래 걸리면 샘플이 빠지는 이유가 이것이다. 6.3절에서 버스 속도를 낮춰 실제로 본다.

`iio_pollfunc_store_time`은 top half로, `pf->timestamp = iio_get_time_ns(indio_dev)` 한 줄을 하고 `IRQ_WAKE_THREAD`를 돌려준다. 즉 **타임스탬프는 hardirq에서, 데이터 읽기는 스레드에서**. 데이터를 읽는 시각이 아니라 인터럽트가 들어온 시각을 기록해야 스케줄링 지연이 타임스탬프에 섞이지 않는다.

`inv_mpu6050`은 한 단계 더 앞에서 찍는다. 칩 IRQ의 hard handler가 `st->it_timestamp = iio_get_time_ns()`를 하고, threaded handler가 칩 상태를 확인한 뒤 `iio_trigger_poll_nested()`로 트리거를 발사한다(`drivers/iio/imu/inv_mpu6050/inv_mpu_trigger.c:230`, `:295`). 칩 IRQ 핸들러 자체가 threaded일 때(I2C로 상태를 읽어야 하므로) 쓰는 패턴이다.

### 5.3 hrtimer 트리거와 sysfs 트리거

hrtimer 트리거(`drivers/iio/trigger/iio-trig-hrtimer.c`)는 `hrtimer_setup(..., CLOCK_MONOTONIC, HRTIMER_MODE_REL_HARD)`로 타이머를 만들고, 콜백에서 `iio_trigger_poll(info->swt.trigger)`(105행)를 부른다. 구조가 data-ready 트리거와 완전히 같고, 방아쇠만 칩 핀 대신 커널 타이머다. 그래서 칩이 실제로 샘플을 만든 시각과 트리거 시각이 **어긋난다**: 칩 ODR이 1000 Hz이고 타이머도 1000 Hz여도 두 발진기는 서로 모르므로, 같은 샘플을 두 번 읽거나 하나를 건너뛸 수 있다(aliasing). 칩에 DRDY 핀이 있으면 그것을 쓰는 것이 원칙이고, hrtimer는 핀이 없을 때의 차선책이다.

sysfs 트리거(`iio-trig-sysfs`)는 유저가 `echo 1 > /sys/bus/iio/devices/triggerN/trigger_now` 할 때마다 한 번 발사한다. 이 랩 커널에 모듈로 있지만 이 노트에서는 실행하지 않았다.

### 5.4 예제 7 — 같은 장치에 트리거를 바꿔 끼우기 (DRDY ↔ hrtimer)

무엇을 확인하나: `current_trigger`에 이름만 쓰면 트리거가 바뀌고, 칩 DRDY와 커널 hrtimer 각각의 샘플률·간격 분포가 어떤지. 측정 도구 `i2rate`는 6.1절에 있다. 칩은 `pattern=1`로 자이로 X에 샘플 번호를 넣는다.

```sh

### 5.5 예제 8 — 자기 트리거를 잡고 있으면 `rmmod`가 안 된다

무엇을 확인하나: probe에서 `indio_dev->trig = iio_trigger_get(trig)`로 자기 트리거를 기본값으로 걸면, 트리거가 모듈 참조를 잡아 `rmmod`가 실패한다.

```

```text

refcnt=1
refcnt=0
rmmod ok
```

출력에서 볼 것: `iio_trigger_get()`은 트리거 device의 참조와 함께 **트리거 owner 모듈(= `i2_imu` 자신)의 참조**를 올린다. 그래서 `refcnt=1`인 채로 `rmmod`가 `EAGAIN`(Resource temporarily unavailable)으로 실패한다. `current_trigger`를 비우면 참조가 풀리고 `rmmod`가 된다. 같은 이유로 처음 측정 스크립트(t8.sh)의 끝에서 `rmmod`/`insmod check_da=1`이 실패해 옛 모듈로 측정이 이어졌다 — 그 부분 결과는 버렸다. 실제 드라이버 개발 루프(`rmmod` → 수정 → `insmod`)에서 처음 만나면 꽤 당황스러운 함정이다.

## 6. 측정 — 샘플률, 타임스탬프 지터, 누락 (TCG 위에서)

> **주의 (모든 측정에 해당)**: QEMU는 KVM 없이 TCG(명령어 번역)로 돌고, 같은 VM에서 다른 노트 작성자 10명이 각자 QEMU를 돌리고 있었다(측정 중 VM load average 1~3). 그래서 절대값(µs 단위 지터, CPU %)은 **실제 i.MX8·Jetson과 전혀 다르다**. 이 절에서 믿을 것은 (1) 경로·메커니즘의 차이가 만드는 **상대적 경향**, (2) 카운터로 센 **누락·중복의 위치**, (3) 버스 시간처럼 **모델이 정한 상한**이다. 각 측정은 한 번(또는 표시한 횟수)만 돌린 것이다.

### 6.1 측정 도구 `i2rate`

무엇을 하는 코드인가: 버퍼를 T초 동안 읽으면서 scan의 타임스탬프 간격(dt) 분포, 실제 샘플률, `read()` 횟수, 칩 샘플 번호(자이로 X 자리)로 센 누락·중복, 리더 프로세스 CPU를 낸다. 통계·시계 도우미는 헤더로 뺐다.

```c
/* i2stat.h — 측정 공통: 시계, 시스템 전체 CPU 사용량(/proc/stat), 통계 */
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <math.h>
#include <sys/resource.h>

static inline double now_s(void)
{
	struct timespec t;
	clock_gettime(CLOCK_MONOTONIC, &t);
	return t.tv_sec + t.tv_nsec / 1e9;
}

static inline void cpu_jiffies(long long *busy, long long *all)	/* 모든 CPU 합 */
{
	long long v[10] = { 0 };
	FILE *f = fopen("/proc/stat", "r");
	int i;

	if (!f || fscanf(f, "cpu %lld %lld %lld %lld %lld %lld %lld %lld", &v[0], &v[1],
			 &v[2], &v[3], &v[4], &v[5], &v[6], &v[7]) != 8) { perror("stat"); exit(1); }
	fclose(f);
	for (*all = 0, i = 0; i < 8; i++)
		*all += v[i];
	*busy = *all - v[3] - v[4];			/* idle, iowait 제외 */
}

static inline int cmp_d(const void *a, const void *b)
{
	double x = *(const double *)a, y = *(const double *)b;
	return (x > y) - (x < y);
}

static inline void dt_stats(double *dt, int n, double period_us)	/* dt[] 단위 us */
{
	double s = 0, ss = 0;
	int i, gaps = 0;

	for (i = 0; i < n; i++) {
		s += dt[i]; ss += dt[i] * dt[i];
		gaps += dt[i] > 1.5 * period_us;
	}
	qsort(dt, n, sizeof(double), cmp_d);
	printf("dt_us mean=%.1f sd=%.1f min=%.1f p50=%.1f p99=%.1f max=%.1f gaps=%d\n",
	       s / n, sqrt(ss / n - (s / n) * (s / n)), dt[0], dt[n / 2],
	       dt[(int)(n * 0.99)], dt[n - 1], gaps);
}
```

```c
/* i2rate.c — 버퍼를 T초 읽어 실제 샘플률·타임스탬프 간격 지터·누락·CPU를 잰다 */
#include "i2scan.h"
#include "i2stat.h"
#include <fcntl.h>
#include <unistd.h>

static double dt[400000];

int main(int argc, char **argv)
{
	static unsigned char buf[64 * 64];
	int fd, i, n, k, nd = 0, reads = 0, ts = -1, sq = -1, sleep_us;
	long long nscan = 0, b0, a0, b1, a1, prev_seq = -1, lost = 0, dup = 0;
	double hz, t_end, t0, first = 0, prev = 0;
	struct rusage ru;

	if (argc < 5) { fprintf(stderr, "usage: %s sysdir dev hz secs [sleep_us] [seq_el]\n", argv[0]); return 1; }
	scan_layout(argv[1]);
	hz = atof(argv[3]);
	sleep_us = argc > 5 ? atoi(argv[5]) : 0;
	for (i = 0; i < nel; i++) {
		if (!strcmp(els[i].name, "in_timestamp")) ts = els[i].off;
		if (argc > 6 && !strcmp(els[i].name, argv[6])) sq = i;
	}
	if (ts < 0 || (fd = open(argv[2], O_RDONLY)) < 0) { perror("ts/open"); return 1; }
	cpu_jiffies(&b0, &a0);
	t0 = now_s(); t_end = t0 + atof(argv[4]);
	while (now_s() < t_end) {
		n = read(fd, buf, sizeof(buf) / scan_bytes * scan_bytes);
		if (n < 0) { perror("read"); return 1; }
		reads++;
		for (k = 0; k < n / scan_bytes; k++, nscan++) {
			unsigned char *s = buf + k * scan_bytes;
			double t = *(int64_t *)(s + ts) / 1e3;		/* ns → us */
			if (nscan == 0) first = t;
			else if (nd < 400000) dt[nd++] = t - prev;
			prev = t;
			if (sq >= 0) {				/* 칩 샘플 번호로 누락 세기 */
				long long v = *(uint16_t *)(s + els[sq].off);
				int d = (int16_t)(v - prev_seq);
				if (prev_seq >= 0) { if (d <= 0) dup++; else lost += d - 1; }
				prev_seq = v;
			}
		}
		if (sleep_us) usleep(sleep_us);			/* 느린 소비자 흉내 */
	}
	cpu_jiffies(&b1, &a1);
	getrusage(RUSAGE_SELF, &ru);
	printf("req=%.0fHz got=%.1fHz scans=%lld reads=%d (%.1f scans/read) lost_seq=%lld dup_seq=%lld\n",
	       hz, (nscan - 1) / ((prev - first) / 1e6), nscan, reads, (double)nscan / reads, lost, dup);
	printf("cpu_sys_busy=%.1f%% reader_cpu_us/scan=%.1f\n", 100.0 * (b1 - b0) / (a1 - a0),
	       (ru.ru_utime.tv_sec * 1e6 + ru.ru_utime.tv_usec + ru.ru_stime.tv_sec * 1e6 +
		ru.ru_stime.tv_usec) / nscan);
	dt_stats(dt, nd, 1e6 / hz);
	return 0;
}
```

- `got`은 첫 scan과 마지막 scan의 **타임스탬프 차이**로 계산한다(유저가 읽은 시각이 아니라).
- `gaps`는 dt가 주기의 1.5배를 넘은 횟수, `lost_seq`는 칩 일련번호가 건너뛴 개수의 합, `dup_seq`는 같은(또는 뒤로 간) 번호가 다시 온 횟수다.
- `reader_cpu_us/scan`은 `getrusage`(스케줄러가 잰 실행 시간)를 scan 수로 나눈 값이다.

그림 5 — 위 출력으로 그린 차트. 왼쪽: 요청한 ODR 대비 실제 받은 샘플률이 모자란 비율. 오른쪽: 타임스탬프 간격의 표준편차(µs). 파랑 = 칩 DRDY 자체 트리거, 주황 = hrtimer 트리거. TCG·공유 VM에서 1회 측정.

출력에서 볼 것:

- **중앙값(p50)은 거의 정확하다**: 100 Hz에서 9987 µs, 1000 Hz에서 1004 µs. 평균 주기는 맞는데, 개별 간격이 흔들린다(sd 285~2045 µs). TCG에서 가상 CPU가 호스트에게 밀리면 IRQ가 한꺼번에 늦게 처리되기 때문이다 — `min=152 µs`(늦게 온 IRQ 직후 다음 IRQ가 바로 처리됨)와 `max=8.7 ms`가 짝을 이룬다. 실제 하드웨어라면 DRDY IRQ 지연은 보통 수~수십 µs 범위다(이 노트에서 재지 않았다).
- 100 Hz에서 sd가 가장 크고 1000 Hz에서 가장 작다. 절대 흔들림(수 ms 단위의 TCG 정지)이 주기와 상관없이 비슷하게 생기므로, 샘플이 촘촘할수록 흔들림이 여러 간격에 나뉘어 sd가 작아진 것으로 보인다. 주기 대비 비율로 보면 100 Hz 13%, 1000 Hz 28%로 오히려 커진다.
- **1000 Hz DRDY에서 `lost_seq=21`, `dup_seq=4`**. 아래 카운터로 어디서 사라졌는지 추적할 수 있다.

1000 Hz DRDY 한 번(5초)의 손실 회계 — 같은 출력 25행의 숫자들이다.

| 단계 | 개수 | 차이의 의미 |
|---|---|---|
| 칩이 만든 샘플 (`ticks`) | 4971 | 이상적이면 약 5000. `hrtimer_forward_now`가 늦은 틱을 건너뛰어 칩 자체가 덜 만듦 + 앞뒤 구간은 INT1이 꺼진 상태 |
| 칩이 친 INT1 (`irqs`) | 4936 | 버퍼 enable 전·disable 후 틱(INT1 꺼짐)은 IRQ를 안 친다 |
| 커널이 처리한 IRQ (`/proc/interrupts` 차이) | 4931 | 5개는 `irq_sim`의 pending 비트에서 합쳐짐 — 엣지 IRQ가 처리되기 전에 다음 엣지가 오면 하나로 보인다 |
| pollfunc 실행 (`polls` 차이 10921 − 6002) | 4919 | 12개는 `iio_trigger_poll`의 `use_count` 검사에서 버려짐 — 이전 샘플의 스레드가 아직 안 끝났다 |
| kfifo에 들어감 (`pushed`) | 4919 | `full=0`: 버퍼 넘침은 없었다 |
| 유저가 읽음 (`scans`) | 4914 | 나머지는 측정 종료 시점에 버퍼에 남아 있었다 |

`dup_seq=4`는 반대 방향 사고다. IRQ 두 개가 늦게 몰려 처리되면, 두 번째 pollfunc이 돌 때 칩에 아직 **새 샘플이 없어서 같은 샘플을 다시 읽는다**. 타임스탬프는 IRQ마다 따로 찍혔으므로, 유저는 "다른 시각의 같은 값"을 받는다. 센서 퓨전에서는 이것이 누락보다 더 나쁘다(가짜 데이터). 6.4절의 `check_da`가 그 방어다.

500 Hz에서는 칩 IRQ 2509 = 처리 2509 = pollfunc 2508(3512 − 1004), 누락 1개다. 여유가 있으면 경로 전체가 거의 손실 없이 돈다.

### 6.3 예제 9 — 버스 속도가 샘플률의 상한을 정한다

무엇을 확인하나: 가짜 버스에 실제 I2C 클럭의 전송 시간을 흉내 내게 하면(`bus_khz`), 샘플 하나를 읽는 시간이 주기보다 길어질 때 무슨 일이 생기나.

먼저 계산이다. `regmap_bulk_read(STATUS, 16바이트)`는 I2C 메시지 2개(쓰기 1바이트 레지스터 주소 + 읽기 16바이트)다. 가짜 버스의 모델은 바이트당 9클럭(8비트 + ACK), 메시지마다 주소 바이트 1개, START/STOP 2클럭이다.

```text
bits = 2 + (1 + 1) x 9 + (16 + 1) x 9 = 173 클럭
400 kHz: 173 / 400e3 = 432 us   → 이론 상한 약 2300 샘플/s
100 kHz: 173 / 100e3 = 1.73 ms  → 이론 상한 약 578 샘플/s
```

```sh
# t11.sh — 게스트 (check_da=1)
. /common.sh
FB=pattern=1 imu_up check_da=1
cd $D; enable_all; echo 4096 > buffer/length
P=/sys/module/i2_fakebus/parameters
for khz in 0 400 100; do
  echo $khz > $P/bus_khz
  for hz in 500 1000; do
    echo $hz > sampling_frequency; echo 0 > $P/stats; s0=$(cat i2_stats)
    echo "### bus_khz=$khz, ODR $hz Hz"
    echo 1 > buffer/enable; /i2rate $D $N $hz 4 0 in_anglvel_x | grep -v cpu; echo 0 > buffer/enable
    echo "chip: $(cat $P/stats) driver: $s0 -> $(cat i2_stats)"
  done
done
```

- 100 kHz: 500 Hz에서 280 Hz, 1000 Hz에서 331 Hz. 1000 Hz 쪽 dt 중앙값이 2994 µs = **정확히 3 주기마다 하나**를 잡았다. 읽기 하나(약 1.9 ms + 깨어나기 지연)가 끝나기 전에 온 IRQ 둘은 버려지고, 세 번째가 잡힌다. `xfers=1334` ≈ `scans=1330`: 버려진 트리거는 버스를 쓰지도 않았다.
- `chip ticks`와 `irqs`는 버스 속도와 상관없이 ODR대로다. **칩은 계속 샘플을 만들고 IRQ를 친다. 버리는 것은 커널 쪽이다.**
- 같은 결론의 실무 버전: IMU를 100 kHz I2C에 달면 6축 1 kHz는 불가능하다. 400 kHz(Fast-mode)나 1 MHz(Fast-mode Plus), 아니면 SPI(10 MHz면 같은 버스트가 약 15 µs)로 간다. 또는 칩 HW FIFO에 모아 두었다가 watermark IRQ 하나에 수십 샘플을 한 번에 읽는다(7.4절) — 트랜잭션 오버헤드가 샘플 수로 나뉜다.

## 7. kfifo 넘침과 watermark

### 7.1 kfifo가 가득 차면 — 새 샘플을 버린다

IIO의 기본 버퍼는 커널 공용 링버퍼 `kfifo` 위에 얹힌 `kfifo_buf`이고, 원소 하나가 scan 하나다. push 경로의 끝은 이렇다.

```c
/* drivers/iio/buffer/kfifo_buf.c:90 (6.18.55) */
static int iio_store_to_kfifo(struct iio_buffer *r,
			      const void *data)
{
	int ret;
	struct iio_kfifo *kf = iio_to_kfifo(r);
	ret = kfifo_in(&kf->kf, data, 1);
	if (ret != 1)
		return -EBUSY;
	return 0;
}
```

가득 찬 kfifo에 넣으면 `kfifo_in`이 0을 돌려주고, 그 scan은 버려진다. **오래된 샘플이 남고 새 샘플이 사라진다.** 덮어쓰기(overwrite-oldest) 링버퍼에 익숙한 Don에게는 반대 정책이다. 결과적으로 유저가 한참 뒤에 깨어나 읽으면 "길이만큼의 오래된 샘플 + 큰 구멍"을 받는다. 그래서 IIO 버퍼에서는 **타임스탬프나 일련번호로 구멍을 검사하는 것이 소비자의 의무**다. `iio_push_to_buffers*()`가 `-EBUSY`를 돌려주므로 드라이버가 셀 수는 있다(`i2_imu`의 `full` 카운터). 다만 유저에게 알리는 표준 ABI는 없다.

### 7.2 예제 11 — 느린 소비자: length 64 vs 1024

### 7.3 watermark — 몇 개 모이면 깨울까

```c
/* drivers/iio/industrialio-buffer.c:171 (6.18.55, 발췌) iio_buffer_read() */
	if (filp->f_flags & O_NONBLOCK)
		to_wait = 0;
	else
		to_wait = min_t(size_t, n / datum_size, rb->watermark);
```

블로킹 `read()`는 "요청한 개수"와 "watermark" 중 작은 것만큼 쌓일 때까지 잠든다. `poll()`도 watermark를 기준으로 `POLLIN`을 낸다. watermark를 올리면 **깨어나는 횟수(문맥 전환·시스템 콜)가 그만큼 줄어든다**. 대가는 지연이다: watermark 64 @ 1 kHz면 첫 샘플은 최대 64 ms 늦게 유저에게 간다. 제어 루프(자세 제어)는 낮게, 로깅·오프라인 퓨전은 높게 잡는다.

```sh
# t8.sh 중간 — 게스트

for wm in 1 64; do
  echo "### 1000 Hz, watermark=$wm"
  echo $wm > buffer/watermark
  echo 1 > buffer/enable; /i2rate $D $N 1000 5 0 in_anglvel_x; echo 0 > buffer/enable
done
echo 1 > buffer/watermark; echo 500 > sampling_frequency
echo "### 500 Hz 버퍼(watermark 1 / 32)"
for wm in 1 32; do echo $wm > buffer/watermark; echo 1 > buffer/enable; /i2rate $D $N 500 5 | head -2; echo 0 > buffer/enable; done
```

### 7.4 HW FIFO + watermark (st_lsm6dsx 방식) vs 샘플마다 트리거

지금까지의 `i2_imu`는 **샘플 하나 = IRQ 하나 = I2C 트랜잭션 하나**다. 1 kHz × 6축이면 IRQ 1000번/s, 스레드 깨우기 1000번/s다. 요즘 IMU(LSM6DSO, ICM-42688, BMI270)는 칩 안에 수 KB짜리 FIFO가 있고, "N개 쌓이면 INT"를 칠 수 있다. 업스트림 `st_lsm6dsx`는 그것을 이렇게 쓴다.

| | 샘플마다 트리거 (`i2_imu`, `inv_mpu6050`의 기본 구조) | HW FIFO watermark (`st_lsm6dsx`) |
|---|---|---|
| IRQ 빈도 | ODR (1 kHz면 1000/s) | ODR / watermark (예: 32개면 31/s) |
| I2C 트랜잭션 | 샘플당 1번 | IRQ당 1번에 수백 바이트 (`regmap_noinc_read`로 FIFO 레지스터 반복 읽기) |
| IIO 구조 | `devm_iio_triggered_buffer_setup` + 트리거 | `devm_iio_kfifo_buffer_setup` — **트리거 없음**, threaded IRQ가 직접 push (`st_lsm6dsx_buffer.c:806`, `st_lsm6dsx_core.c:2584`) |
| 타임스탬프 | IRQ 시각 하나 = 샘플 하나 | 배치 안의 샘플마다 시각을 **추정**해야 한다: 칩 HW 타임스탬프(`ts_gain`) 또는 IRQ 시각 + ODR로 보간 |
| 누락 위험 | 스레드가 주기보다 늦으면 트리거 버림 | 칩 FIFO가 넘치기 전까지(수십 ms) 여유 |
| 지연 | 1샘플 | watermark 샘플 |
| core의 연결 고리 | — | `iio_info.hwfifo_set_watermark`: 유저가 `buffer/watermark`를 쓰면 드라이버가 칩 FIFO 임계값도 맞춘다 (`st_lsm6dsx_set_watermark`, `core.c:2035`) |

`st_lsm6dsx_read_fifo()`(`st_lsm6dsx_buffer.c:377`)는 FIFO 바이트 수를 읽고, 패턴(어느 센서 샘플이 어떤 순서로 들어 있는지)을 따라 가속도·자이로·외부 센서 scan으로 나눈 뒤, 칩 타임스탬프 블록에서 꺼낸 시각에 `ts_gain`을 곱하고 `ts_ref`를 더해 `iio_push_to_buffers_with_timestamp()`를 부른다(같은 파일 483–517행). `inv_mpu6050`은 트리거 구조를 유지하되 pollfunc 안에서 칩 FIFO를 통째로 읽고(`inv_mpu_ring.c:43`), `inv_sensors_timestamp_pop()`으로 IRQ 시각과 ODR에서 샘플별 시각을 보간한다(같은 파일 118행). 두 드라이버 모두 **"IRQ 하나에 여러 샘플, 시각은 보간"**이 핵심이다. 고속 IMU 드라이버를 새로 쓴다면 이 구조가 정답에 가깝다. `i2_imu`의 가짜 칩은 FIFO가 없어서 이 경로는 코드 읽기로만 다뤘다.

## 8. 예제 12 — CPU 비용: sysfs 폴링 vs 버퍼 read

무엇을 확인하나: 같은 7채널을 500 Hz로 얻을 때, 유저 프로세스가 sysfs `*_raw` 파일 7개를 폴링하는 경우와 버퍼를 읽는 경우의 샘플당 CPU. 폴링 도구는 이렇다.

	if (argc < 4) { fprintf(stderr, "usage: %s sysdir hz(0=max) secs\n", argv[0]); return 1; }
	for (i = 0; i < 7; i++) {
		snprintf(p, sizeof(p), "%s/in_%s_raw", argv[1], ch[i]);
		if ((fd[i] = open(p, O_RDONLY)) < 0) { perror(p); return 1; }
	}
	hz = atof(argv[2]);
	cpu_jiffies(&b0, &a0);
	t0 = next = now_s(); t_end = t0 + atof(argv[3]);
	while (now_s() < t_end) {
		for (i = 0; i < 7; i++) {		/* 채널마다 syscall 1번 + I2C 트랜잭션 1번 */
			int n = pread(fd[i], buf, sizeof(buf) - 1, 0);
			if (n < 0) { perror("pread"); return 1; }
			buf[n] = 0;
			sum += atoi(buf);
		}
		sets++;
		if (hz > 0) {				/* 목표 주기까지 잠들기 */
			struct timespec ts;
			next += 1.0 / hz;
			ts.tv_sec = (time_t)next;
			ts.tv_nsec = (long)((next - ts.tv_sec) * 1e9);
			clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &ts, NULL);
		}
	}
	cpu_jiffies(&b1, &a1);
	struct rusage ru;
	getrusage(RUSAGE_SELF, &ru);
	printf("req=%.0fHz got=%.1f sets/s (7 ch each) cpu_sys_busy=%.1f%% reader_cpu_us/set=%.1f (sum %d)\n",
	       hz, sets / (now_s() - t0), 100.0 * (b1 - b0) / (a1 - a0),
	       (ru.ru_utime.tv_sec * 1e6 + ru.ru_utime.tv_usec + ru.ru_stime.tv_sec * 1e6 +
		ru.ru_stime.tv_usec) / sets, sum & 1);
	return 0;
}

## 9. 이벤트 — 임계값을 넘으면 알려 줘

### 9.1 구조

이벤트는 "값의 스트림"이 아니라 "**조건이 일어났다는 사실**"이다. IMU의 wake-up(움직임 감지), free-fall, tap, ADC의 과전압 같은 칩 내장 비교기가 대표적이다. 칩이 비교를 하므로 CPU는 자고 있어도 된다.

드라이버는 채널에 `iio_event_spec`을 붙인다.

```c
/* drivers/iio/dummy/iio_simple_dummy.c:54 (6.18.55) */
static const struct iio_event_spec iio_dummy_event = {
	.type = IIO_EV_TYPE_THRESH,
	.dir = IIO_EV_DIR_RISING,
	.mask_separate = BIT(IIO_EV_INFO_VALUE) | BIT(IIO_EV_INFO_ENABLE),
};
```

그러면 core가 `events/in_voltage0_thresh_rising_value`, `events/in_voltage0_thresh_rising_en` 파일을 만들고, 그 파일 읽기·쓰기가 `iio_info.read_event_value / write_event_value / read_event_config / write_event_config` 콜백으로 간다. 칩 IRQ가 오면 드라이버가 `iio_push_event(indio_dev, code, timestamp)`를 부른다. `code`는 64비트 하나에 채널 type·번호·수식어·이벤트 종류·방향을 압축한 값이다(`IIO_UNMOD_EVENT_CODE()`, `IIO_MOD_EVENT_CODE()` 매크로).

| 비트 (uapi `linux/iio/events.h`) | 추출 매크로 | 뜻 |
|---|---|---|
| 63..56 | `IIO_EVENT_CODE_EXTRACT_TYPE` | `enum iio_event_type`: THRESH=0, MAG=1, ROC=2, … CHANGE=5 |
| 55 | `IIO_EVENT_CODE_EXTRACT_DIFF` | 차동 채널인가 |
| 54..48 | `IIO_EVENT_CODE_EXTRACT_DIR` | EITHER=0, RISING=1, FALLING=2, NONE=3 |
| 47..40 | `IIO_EVENT_CODE_EXTRACT_MODIFIER` | `IIO_MOD_X` 등 |
| 39..32 | `IIO_EVENT_CODE_EXTRACT_CHAN_TYPE` | `enum iio_chan_type`: VOLTAGE=0, ACCEL=3, … STEPS=20 |
| 31..16 | `IIO_EVENT_CODE_EXTRACT_CHAN2` | 차동의 두 번째 채널 |
| 15..0 | `IIO_EVENT_CODE_EXTRACT_CHAN` | 채널 번호 |

유저는 `/dev/iio:deviceN`을 열고 `ioctl(fd, IIO_GET_EVENT_FD_IOCTL, &efd)`로 **별도의 이벤트 fd**를 받는다(anon inode). 그 fd에서 `struct iio_event_data { __u64 id; __s64 timestamp; }`를 `read()`한다. 같은 장치 노드가 버퍼(read)와 이벤트(ioctl로 얻는 다른 fd)를 둘 다 담당하는 셈이다. 이벤트 fd는 장치당 한 명만 열 수 있다(두 번째 ioctl은 `EBUSY`).

### 9.2 예제 13 — 이벤트 fd로 임계값 이벤트 받기

무엇을 확인하나: `iio_dummy`의 이벤트 생성기(`iio_evgen`의 `poke_ev0`에 쓰면 가짜 IRQ)를 이용해, 이벤트 fd를 얻고 코드를 해독한다.

```c
/* i2ev.c — IIO 이벤트 fd를 얻어(ioctl) 임계값 이벤트를 읽고 코드를 해독 */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <poll.h>
#include <sys/ioctl.h>
#include <linux/iio/events.h>
#include <linux/iio/types.h>

int main(int argc, char **argv)
{
	struct iio_event_data ev;
	int fd, efd, i, max;

	if (argc < 3) { fprintf(stderr, "usage: %s /dev/iio:deviceN max_events\n", argv[0]); return 1; }
	if ((fd = open(argv[1], O_RDONLY)) < 0) { perror("open"); return 1; }
	if (ioctl(fd, IIO_GET_EVENT_FD_IOCTL, &efd) < 0) { perror("ioctl"); return 1; }
	close(fd);					/* 이벤트는 efd 하나로 충분 */
	printf("event fd=%d\n", efd);
	max = atoi(argv[2]);
	for (i = 0; i < max; i++) {
		struct pollfd p = { .fd = efd, .events = POLLIN };
		if (poll(&p, 1, 3000) <= 0) { printf("timeout\n"); break; }
		if (read(efd, &ev, sizeof(ev)) != sizeof(ev)) { perror("read"); return 1; }
		printf("ts=%lld id=0x%016llx chan_type=%d chan=%d ev_type=%d dir=%d diff=%d\n",
		       (long long)ev.timestamp, (unsigned long long)ev.id,
		       (int)IIO_EVENT_CODE_EXTRACT_CHAN_TYPE(ev.id),
		       (int)IIO_EVENT_CODE_EXTRACT_CHAN(ev.id),
		       (int)IIO_EVENT_CODE_EXTRACT_TYPE(ev.id),
		       (int)IIO_EVENT_CODE_EXTRACT_DIR(ev.id),
		       (int)IIO_EVENT_CODE_EXTRACT_DIFF(ev.id));
	}
	close(efd);
	return 0;
}

IIO core는 `_en` 값을 드라이버의 `write_event_config`로 전달만 하고, `iio_push_event()`에서 걸러 주지 않는다(core가 확인하는 것은 "이벤트 fd를 누가 열고 있나"뿐이다). 진짜 드라이버라면 `write_event_config(false)`에서 **칩의 인터럽트 enable 비트를 끄는 것**으로 이 약속을 지킨다. `iio_dummy`는 교재용이라 그걸 안 한다. 드라이버를 리뷰할 때 확인할 항목이다.
- 같은 스크립트를 처음 돌렸을 때(같은 명령, 바로 연달아 poke 0 → 3 → 0)는 이렇게 나왔다:

```text
event fd=4
ts=1791760579963312064 id=0x0001000000000000 chan_type=0 chan=0 ev_type=0 dir=1 diff=0
ts=1791760579965578736 id=0x0001000000000000 chan_type=0 chan=0 ev_type=0 dir=1 diff=0
timeout
```

steps 이벤트가 사라지고 voltage가 두 번 왔다. `iio_dummy_evgen`은 "어떤 이벤트인가"를 **공유 레지스터 하나**(`regs->reg_data`)에 써 두고 IRQ를 친다. 드라이버의 threaded 핸들러가 그 레지스터를 읽기 전에 다음 poke가 값을 덮어쓰면, 앞의 이벤트 종류가 사라진다. 두 번째 실행에서는 타이밍이 맞아 셋 다 왔다. 실제 칩의 "인터럽트 원인 레지스터를 나중에 읽는" 설계에서도 똑같이 생기는 경쟁이다 — 그래서 칩들은 **래치(latched) 인터럽트 + clear-on-read 소스 레지스터**를 둔다(`st_lsm6dsx_init_device`가 LIR 비트를 켜는 이유, `st_lsm6dsx_core.c` 2355행 근처).

## 10. 타임스탬프 — 어떤 시계로, 어디서 찍나

### 10.1 `current_timestamp_clock` — 기본값이 realtime이다

모든 IIO 타임스탬프는 `iio_get_time_ns(indio_dev)`를 거친다.

```c
/* drivers/iio/industrialio-core.c:320 (6.18.55, 발췌) */
s64 iio_get_time_ns(const struct iio_dev *indio_dev)
{
	struct timespec64 tp;

	switch (iio_device_get_clock(indio_dev)) {
	case CLOCK_REALTIME:
		return ktime_get_real_ns();
	case CLOCK_MONOTONIC:
		return ktime_get_ns();
	...
	case CLOCK_BOOTTIME:
		return ktime_get_boottime_ns();
	case CLOCK_TAI:
		return ktime_get_clocktai_ns();
```

장치마다 `current_timestamp_clock` 파일로 고른다(realtime, monotonic, monotonic_raw, realtime_coarse, monotonic_coarse, boottime, tai). **기본값은 `realtime`**이다(2절 출력).

무엇을 확인하나: 버퍼 타임스탬프가 정말 그 시계의 값인지, 바꾸면 바뀌는지.

```c
/* i2clk.c — 버퍼 타임스탬프가 어느 시계 기준인지: 마지막 8바이트(ts)를 세 시계와 비교 */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <time.h>

static double clk(clockid_t c)
{
	struct timespec t;
	clock_gettime(c, &t);
	return t.tv_sec + t.tv_nsec / 1e9;
}

int main(int argc, char **argv)
{
	unsigned char buf[64];
	int64_t ts;
	int fd, sb;

	if (argc < 3) { fprintf(stderr, "usage: %s dev scan_bytes\n", argv[0]); return 1; }
	sb = atoi(argv[2]);
	if ((fd = open(argv[1], O_RDONLY)) < 0 || read(fd, buf, sb) != sb) { perror("read"); return 1; }
	memcpy(&ts, buf + sb - 8, 8);			/* ts는 scan의 마지막 8바이트 */
	printf("sample ts      = %.6f s\n", ts / 1e9);
	printf("CLOCK_REALTIME = %.6f\nCLOCK_MONOTONIC= %.6f\nCLOCK_BOOTTIME = %.6f\n",
	       clk(CLOCK_REALTIME), clk(CLOCK_MONOTONIC), clk(CLOCK_BOOTTIME));
	close(fd);
	return 0;
}
```

echo 1 > buffer/enable; /i2clk $N 24; echo 0 > buffer/enable

출력에서 볼 것: 첫 번째 샘플의 ts(1791761306.953 s)는 `CLOCK_REALTIME`(벽시계, 2026년 10월)과 몇 ms 차이다. `monotonic`으로 바꾸자 ts가 0.960 s — 부팅 후 경과 시간 — 가 됐고, `CLOCK_MONOTONIC`과 0.6 ms 차이다(그만큼 전에 찍힌 샘플). 이 게스트는 suspend가 없으니 monotonic과 boottime이 같다.

로봇에서 realtime이 왜 위험한가: NTP·PTP·GNSS가 시스템 시계를 맞추는 순간 `CLOCK_REALTIME`은 **뒤로 가거나 점프**한다. IMU 타임스탬프가 뒤로 가면 EKF는 적분을 거꾸로 한다. 그래서 센서 퓨전 스택은 거의 언제나 `CLOCK_MONOTONIC`(또는 suspend를 넘어 이어져야 하면 `CLOCK_BOOTTIME`)을 쓴다. 카메라(V4L2 버퍼 타임스탬프는 monotonic, I5), CAN(SocketCAN 수신 시각), LiDAR 패킷 수신 시각과 **같은 시계**로 맞춰야 서로 비교할 수 있다 — Q3(멀티 센서 동기화) 노트의 출발점이다. 부팅 스크립트나 udev 규칙에서 `echo monotonic > current_timestamp_clock`을 하는 것이 실무 관례다. 여러 머신 사이 시각을 맞추는 일(PTP의 `CLOCK_TAI`, `phc2sys`)은 Q3에서 다룬다.

### 10.2 어디서 찍나 — 오차의 출처

| 찍는 위치 | 오차 | 예 |
|---|---|---|
| 유저가 `read()`로 받은 시각 | 버퍼 대기 + 스케줄링 지연 (ms 단위, watermark에 비례) | sysfs 폴링, 순진한 앱 |
| irq 스레드(bottom half)에서 `iio_get_time_ns()` | 스레드 깨우기 지연 (RT 아닌 커널에서 수십 µs~ms) | 피해야 할 패턴 |
| **hardirq에서** (`iio_pollfunc_store_time`, 칩 IRQ의 hard handler) | IRQ 지연만 (수 µs 수준) | `i2_imu`, `inv_mpu6050` |
| 칩 내부 HW 타임스탬프 → 시스템 시계로 환산 | 칩 발진기 드리프트, 환산 오차 (보정 필요) | `st_lsm6dsx`(`ts_gain`, `ts_ref`) |
| 외부 HW 트리거로 샘플링 시점 자체를 정함 + PPS/PTP | 거의 0 (설계 문제) | 카메라-IMU 하드웨어 동기 (Q3) |

FIFO 배치에서는 "IRQ 시각 = 마지막 샘플 시각"으로 보고 ODR 간격으로 앞 샘플들의 시각을 거꾸로 채운다. ODR 발진기가 1% 틀리면 64샘플 배치의 첫 샘플은 0.64 주기만큼 틀린다. 그래서 `inv_sensors_timestamp`는 IRQ 간격을 관찰해 실제 칩 주기를 추정하고 보간에 반영한다(`drivers/iio/common/inv_sensors/inv_sensors_timestamp.c`). 이것이 "타임스탬프 지터 측정 툴"(S4 프로젝트, Q7)이 필요한 이유다. 6절의 `i2rate`가 그 출발점이다.

## 12. 커널 안에서는 무슨 일이 일어나나

유저의 동작 하나하나가 어디로 가는지 정리한다. 함수 이름은 6.18 기준이다.

| 유저 동작 | 커널 경로 | 드라이버가 만나는 곳 |
|---|---|---|

## 13. Embedded 실무에서 다시 보기

### 13.1 센서 키트 bring-up — DT에 IMU 넣기 (실행하지 않은 예시)

예를 들어 센서 키트 보드(i.MX8M Plus 같은 SoC)의 I2C3에 LSM6DSO가 붙고, INT1이 GPIO1_IO12에 연결됐다면 DT 노드는 대략 이렇다. 이 노트의 `i2_fakebus`가 `board_info.irq`, `swnode`로 흉내 낸 것이 정확히 이 속성들이다. (이 DTS는 바인딩 문서 `Documentation/devicetree/bindings/iio/imu/st,lsm6dsx.yaml`의 형식을 따른 예시이고, 랩에서 부팅해 보지 않았다.)

```dts
&i2c3 {
	clock-frequency = <400000>;          /* 6.3절: 100 kHz면 1 kHz 6축 불가 */
	imu@6a {
		compatible = "st,lsm6dso";
		reg = <0x6a>;
		interrupt-parent = <&gpio1>;
		interrupts = <12 IRQ_TYPE_LEVEL_HIGH>;
		vdd-supply = <&reg_3v3>;
		vddio-supply = <&reg_1v8>;
		mount-matrix = "0", "-1", "0",
			       "1",  "0", "0",
			       "0",  "0", "1";
	};
};
```

부팅 후 확인 순서(11.1절 출력과 같은 것을 본다): `dmesg | grep lsm6` → `/sys/bus/iio/devices/*/name` → `in_accel_z_raw × in_accel_scale ≈ 9.8` → `cat /proc/interrupts`에서 버퍼 enable 후 IRQ가 ODR만큼 느는지 → `iio_generic_buffer`나 6절 같은 도구로 샘플률·간격 확인.

### 13.2 유저 공간 쪽 — libiio, ROS

실제 제품에서 버퍼 리더를 매번 손으로 짜지는 않는다. Analog Devices의 **libiio**가 이 노트 4절의 일(scan_elements 파싱, 배치 계산, 엔디언·시프트 변환)을 라이브러리로 해 주고, `iio_info`, `iio_attr`, `iio_readdev` 같은 명령과 네트워크 데몬 `iiod`(원격 장치를 로컬처럼)도 준다(이 랩에는 설치돼 있지 않아 실행하지 않았다). ROS 2라면 IMU 드라이버 노드가 `/dev/iio:deviceN`을 읽어 `sensor_msgs/Imu`로 내보내는데, 그때 (1) 타임스탬프 시계를 monotonic으로, (2) mount matrix를 적용해 기체 좌표로, (3) 단위를 m/s²·rad/s로 — IIO가 준 정보를 그대로 쓰면 세 가지가 다 해결된다.

### 13.3 "가끔 IMU 데이터가 튄다" 디버깅

현장 증상 → 이 노트에서 본 원인으로 좁히기.

1. 타임스탬프 간격 분포를 본다(6절 `i2rate` 같은 도구). 간격이 주기의 2배, 3배로 뛰면 **누락**이다 → `/proc/interrupts`의 IRQ 수, 드라이버 통계, 버스 클럭(6.3절), irq 스레드 우선순위를 확인.
2. 같은 값이 다른 타임스탬프로 두 번 오면 **중복** → 드라이버가 DRDY status/FIFO count를 확인하는지(6.4절).
3. 간격은 정상인데 시각이 점프하면 **시계** → `current_timestamp_clock`이 realtime인지(10.1절).
4. 오래된 데이터가 한 무더기 오고 구멍이 나면 **kfifo 넘침** → `buffer/length`와 소비자 정지 시간(7.2절).
5. X, Y, Z가 서로 다른 샘플에서 온 것 같으면 **sysfs 폴링** → 버퍼로 바꾼다(8절).

### 13.4 IRQ 스레드 우선순위

PREEMPT_RT가 아닌 커널에서도 irq 스레드는 SCHED_FIFO 우선순위 50으로 돈다. 그래서 일반 프로세스보다 먼저 돈다. 그러나 다른 irq 스레드(네트워크, 스토리지)와는 동급이다. 1 kHz IMU가 다른 장치의 IRQ 폭주에 밀리면 6.2절의 "트리거 버림"이 실제 보드에서도 생긴다. 대책은 `chrt -f -p 60 <irq 스레드 pid>`로 IMU 스레드를 올리거나, IRQ affinity로 CPU를 나누거나, 칩 HW FIFO를 써서 IRQ 빈도를 낮추는 것이다(7.4절). 이 노트에서는 측정하지 않았다 — F1(스케줄링 클래스)·F6(IRQ affinity)와 함께 실험해 볼 과제다.

## 15. 면접에서 이렇게 말한다

**Q.** "Design a Linux driver for a 6-axis IMU on I2C with a data-ready interrupt. Walk me through it."

**A.** I2C client driver로 시작해 regmap을 만들고, WHO_AM_I 확인·리셋·기본 ODR 설정을 한다. IIO 장치 하나에 가속도·자이로 XYZ, 온도, 소프트 타임스탬프 채널을 둔다. raw는 separate, scale은 shared_by_type, ODR은 shared_by_all로 두고 available 목록을 준다. INT1이 있으면 자체 data-ready 트리거를 등록하고, triggered buffer의 top half에서 타임스탬프를 찍고 bottom half에서 버스트 한 번으로 읽어 push한다. 버퍼 중에는 단발 읽기와 FS 변경을 막는다. 1 kHz 이상이면 칩 HW FIFO와 watermark IRQ로 배치 읽기를 하고 샘플 시각은 보간한다. mount matrix는 DT에서 읽어 노출한다. 데이터 회전은 유저가 한다.

> I'd write it as an I2C client driver with regmap, check WHO_AM_I, reset and set a default ODR in probe. Then register one IIO device with accel XYZ, gyro XYZ, temperature and a soft timestamp channel — raw per channel, scale shared by type, sampling frequency shared by all, each with an available list. If INT1 is wired I register the device's own data-ready trigger and a triggered buffer: the top half captures the timestamp in hard IRQ context, the threaded bottom half does one burst read and pushes the scan with the timestamp. I block one-shot reads and full-scale changes while the buffer runs. For 1 kHz and above I'd move to the chip's hardware FIFO with a watermark interrupt, read batches, and interpolate per-sample timestamps. The mount matrix comes from DT and is exposed, not applied.

**꼬리 질문**: "왜 input이나 hwmon이 아니라 IIO인가?" → 표준 단위(raw/scale/offset), 고속 버퍼와 타임스탬프, 트리거로 샘플링 시점 제어 — 셋 다 다른 서브시스템에는 없다(0.1절).

**Q.** "Where do you take the timestamp, and with which clock?"

**A.** hardirq에서 찍는다. 스레드나 유저 공간에서 찍으면 스케줄링 지연이 섞인다. FIFO 배치라면 IRQ 시각과 ODR로 샘플별 시각을 보간하거나 칩의 HW 타임스탬프를 시스템 시계로 환산한다. 시계는 IIO 기본값인 realtime이 아니라 monotonic(또는 boottime)으로 바꾼다. NTP·PTP가 realtime을 점프시키기 때문이고, 카메라·CAN 타임스탬프와 같은 시계여야 융합할 수 있기 때문이다.

> In hard IRQ context — `iio_pollfunc_store_time` or the driver's own hard handler — so scheduling latency isn't baked in. With a hardware FIFO I interpolate per-sample times from the IRQ time and the ODR, or convert the chip's own timestamp counter. And I switch `current_timestamp_clock` from the default realtime to monotonic, because realtime can jump when NTP or PTP steps the clock, and every sensor in the fusion stack has to share one timebase.

**Q.** "Your IMU runs at 1 kHz but the application sees 880 Hz with gaps. How do you debug it?"

**A.** 어디서 사라지는지 단계별로 센다: 칩이 IRQ를 몇 번 쳤나(`/proc/interrupts`), pollfunc이 몇 번 돌았나, push 실패(kfifo 넘침)가 있나, 유저가 몇 개 읽었나. IRQ 수 > pollfunc 수라면 트리거가 바쁜 동안 버려진 것이다. bottom half가 주기보다 오래 걸린다는 뜻이니 버스 클럭과 전송 크기로 읽기 시간을 계산한다(400 kHz에서 16바이트 버스트 약 0.43 ms). push 실패라면 버퍼 길이나 소비자 쪽 문제다. 해결은 버스 속도 올리기, HW FIFO 배치 읽기, irq 스레드 우선순위 순으로 본다.

> I'd account for every sample stage by stage: interrupts in /proc/interrupts, trigger handler runs, push failures, and scans read. If IRQs exceed handler runs, triggers were dropped because the previous bottom half hadn't called notify_done — the read takes longer than the period. I'd compute the bus time: a 16-byte burst at 400 kHz is about 430 µs before any scheduling overhead. If pushes fail, it's buffer length or a slow consumer. Fixes: faster bus or SPI, the chip FIFO with batched reads, then IRQ thread priority.

**Q.** "What is a trigger in IIO, and why is it separate from the device?"

**A.** 트리거는 "지금 샘플을 잡아라"는 신호원이고, IIO 버스 위의 독립 객체다. 장치와 분리돼 있어서 같은 하드웨어 타이머 하나로 ADC 여러 개를 동시에 샘플링하거나, DRDY 핀이 없는 센서에 hrtimer를 붙일 수 있다. 내부적으로 트리거는 소비자마다 subirq를 가진 작은 irqchip이고, pollfunc이 그 subirq에 threaded IRQ로 걸린다.

> A trigger is the source of "capture a sample now", registered as its own object on the IIO bus. Decoupling it lets one timer drive several ADCs in lockstep, or lets a sensor without a DRDY pin run from an hrtimer. Internally a trigger is a tiny irqchip with one sub-IRQ per consumer, and each consumer's poll function is a threaded handler on that sub-IRQ.

**Q.** "How does userspace know the layout of the data it reads from /dev/iio:deviceN?"

**A.** 헤더가 없다. `scan_elements/`의 `_en`, `_index`, `_type`을 읽고, 켜진 채널을 index 순으로, 각자 크기에 맞춰 정렬해 놓는다. 타임스탬프 같은 8바이트 원소는 8의 배수 위치에 오고 전체 크기도 8의 배수로 올린다. `_type` 문자열 `le:s12/16>>4`가 엔디언, 부호, 유효 비트, 저장 비트, 시프트를 알려 준다.

> There's no header. Userspace reads `scan_elements`: which channels are enabled, their index, and their type string. Enabled channels are laid out in index order, each naturally aligned to its storage size, so the 64-bit timestamp lands on an 8-byte boundary and the scan is padded to a multiple of 8. A type like `le:s12/16>>4` gives endianness, signedness, valid bits, storage bits and shift.

**Q.** "What happens when the IIO buffer is full?"

**A.** kfifo 버퍼는 새 샘플을 버리고 오래된 것을 남긴다. 드라이버의 push가 `-EBUSY`를 받는다. 유저는 나중에 깨어나 오래된 샘플 한 무더기와 구멍을 받으므로, 타임스탬프나 일련번호로 구멍을 검사해야 한다. 길이는 ODR × 소비자의 최악 정지 시간으로 잡는다.

> The kfifo buffer drops the new sample and keeps the old ones; the driver's push returns -EBUSY. The reader later gets a block of stale samples followed by a gap, so consumers must check timestamps or sequence numbers. I size the buffer as ODR times the worst-case consumer stall, with margin — at 1 kHz that's hundreds of scans, only tens of kilobytes.

**Q.** "Why is sysfs polling a bad idea for a high-rate sensor?"

**A.** 샘플 하나에 채널 수만큼 시스템 콜과 버스 트랜잭션이 들고, 채널끼리 같은 순간이라는 보장이 없고, 타임스탬프가 없다. 내 측정(QEMU)에서 7채널 500 Hz 기준 리더 CPU가 버퍼 방식보다 5~18배 컸다.

> Every sample costs one syscall and one bus transaction per channel, the channels aren't captured at the same instant, and there's no timestamp. In my QEMU measurement, 7 channels at 500 Hz cost the reader about 400 µs per sample via sysfs versus about 20–80 µs through the buffer depending on the watermark.

**Q.** "How does a driver report thresholds or motion events?"

**A.** 채널에 `iio_event_spec`(종류·방향·value/enable 속성)을 달고, 칩 이벤트 IRQ에서 `iio_push_event()`로 64비트 이벤트 코드와 타임스탬프를 보낸다. 유저는 `IIO_GET_EVENT_FD_IOCTL`로 이벤트 fd를 받아 읽는다. enable 속성은 드라이버가 칩 인터럽트 enable로 지켜야 한다 — core는 걸러 주지 않는다.

> Attach an `iio_event_spec` to the channel — type, direction, and value/enable attributes — and in the chip's event IRQ call `iio_push_event()` with a 64-bit code and a timestamp. Userspace gets a separate event fd through `IIO_GET_EVENT_FD_IOCTL`. The driver must honour the enable attribute by programming the chip's interrupt enable; the core doesn't filter events for you.

## 16. 직접 해보기

1. **개념**: 채널이 `{type=IIO_VOLTAGE, indexed=1, channel=3, info_mask_separate=RAW, info_mask_shared_by_type=SCALE, scan_type=be:u12/16>>4}`일 때 sysfs 파일 이름 3개와, 버퍼에서 바이트 `0xAB 0xC0`이 무슨 값이 되는지 써라.
   정답/힌트: `in_voltage3_raw`, `in_voltage_scale`, `scan_elements/in_voltage3_type` 등. `0xABC0 >> 4 = 0xABC = 2748`.
2. **배치 계산**: `i2_imu`에서 가속도 X와 온도와 타임스탬프만 켜면 scan 크기는? `i2read`로 확인하라.
   정답/힌트: ax@0, T@2, 패딩 4, ts@8 → 16바이트.
3. **코드 과제**: `i2_imu`에 `IIO_CHAN_INFO_LOW_PASS_FILTER_3DB_FREQUENCY`(ODR/2 고정, 읽기 전용)를 추가하고, 파일 이름이 무엇이 되는지 예측한 뒤 확인하라.
   정답/힌트: shared_by_all이면 `filter_low_pass_3db_frequency`, shared_by_type이면 `in_accel_filter_low_pass_3db_frequency`.
4. **코드 과제**: `i2ev`를 고쳐 `IIO_EVENT_CODE_EXTRACT_MODIFIER`도 출력하고, `iio_dummy`의 `in_activity_running_thresh_rising` 이벤트를 받아 보라(`poke_ev0`에 1, 단 `in_activity_running_input`이 `_value`보다 커야 한다 — `iio_simple_dummy_events.c` 191행).
   정답/힌트: modifier 값은 `IIO_MOD_RUNNING`.
5. **관찰**: 1 kHz 캡처 중 `/proc/interrupts`와 `ps`의 `irq/NN-i2_imu_c` 스레드를 보고, `chrt -p <pid>`로 스케줄링 정책·우선순위를 확인하라(BusyBox에 `chrt`가 없으면 `/proc/<pid>/sched`나 `stat`의 policy 필드).
   정답/힌트: SCHED_FIFO 50이 기본이다.
6. **측정 과제**: `i2_fakebus`에 HW FIFO(예: 32 샘플)와 FIFO watermark IRQ를 추가하고, 드라이버를 `st_lsm6dsx`처럼 트리거 없는 kfifo 버퍼로 바꿔 6.3절의 `bus_khz=100`, 1000 Hz를 다시 재라. 이론적으로 몇 Hz까지 가능한가?
   정답/힌트: 32샘플 × 12바이트 버스트 하나 ≈ (2 + 9×2 + 9×385) / 100 kHz ≈ 35 ms에 32샘플 → 약 900 샘플/s. 트랜잭션 오버헤드가 나뉘므로 상한이 크게 오른다.
7. **ftrace 과제**: H5 노트의 `i2c:i2c_write`/`i2c_read` tracepoint와 `irq:irq_handler_entry`를 함께 켜서, IRQ 하나 → I2C 메시지 2개가 같은 간격으로 반복되는지 보라(디버그 커널이 필요하면 Image-dbg용으로 모듈을 다시 빌드).
   정답/힌트: `echo 1 > /sys/kernel/tracing/events/i2c/enable`.

## 18. 요약 & 체크리스트

IIO는 측정 장치를 위한 서브시스템이다. 드라이버는 **채널 표**(`iio_chan_spec`)와 **콜백**(`iio_info`)을 주고, core가 sysfs 이름(`in_accel_x_raw`, `in_accel_scale`)과 단위 규약(`(raw + offset) × scale`)을 만든다. 고속 데이터는 **트리거**(칩 DRDY IRQ, hrtimer)가 샘플링 시점을 정하고, **pollfunc**이 hardirq에서 타임스탬프를 찍은 뒤 스레드에서 버스트로 읽어 **kfifo**에 scan을 넣는다. 유저는 `scan_elements`로 배치를 계산해 `/dev/iio:deviceN`을 읽는다. 이 노트에서는 가짜 I2C IMU(`i2_fakebus`: ODR hrtimer + irq_sim INT1) 위에 regmap 기반 IIO 드라이버 `i2_imu`를 짜서 QEMU에서 돌렸고, 같은 가짜 칩에 업스트림 `st_lsm6dsx`까지 붙여 같은 값을 확인했다. 측정(TCG)에서는 트리거 중 버려지는 샘플, irq_sim의 엣지 합침, 드문 중복 샘플, 버스 속도가 정하는 상한(100 kHz에서 1 kHz 불가), kfifo 넘침이 새 샘플을 버리는 동작, watermark가 깨우기 비용을 1/W로 줄이는 효과, sysfs 폴링이 버퍼보다 샘플당 5~18배 비싼 것을 숫자로 봤다. 실무 결론은 넷이다: 버퍼로 읽고, 타임스탬프는 hardirq·monotonic, 버퍼 길이와 버스 속도는 계산해서 정하고, 고속이면 칩 HW FIFO 배치 읽기로 간다.

- [ ] IMU·ADC를 hwmon·input이 아니라 IIO에 붙이는 이유 세 가지를 말할 수 있다
- [ ] `iio_chan_spec`의 type·modified·info_mask가 sysfs 파일 이름이 되는 규칙을 설명할 수 있다
- [ ] raw·scale·offset으로 m/s², rad/s, m°C를 복원하고, 데이터시트 감도에서 INT_PLUS_NANO scale 표를 만들 수 있다
- [ ] `read_raw`/`write_raw`/`read_avail`/`write_raw_get_fmt`를 짜고, get_fmt를 빼면 생기는 버그를 설명할 수 있다
- [ ] data-ready 트리거 + triggered buffer + `iio_push_to_buffers_with_ts`를 갖춘 probe를 화이트보드에 쓸 수 있다
- [ ] scan 배치(index 순, 자연 정렬, 8바이트 타임스탬프)를 손으로 계산하고 `_type` 문자열을 해독하는 리더를 짤 수 있다
- [ ] `iio_trigger_poll`의 `use_count` 때문에 트리거가 버려지는 조건을 설명하고, 버스 시간으로 상한을 계산할 수 있다
- [ ] kfifo 넘침이 새 샘플을 버린다는 것과 버퍼 길이·watermark를 정하는 법을 설명할 수 있다
- [ ] 트리거 기반 구조와 HW FIFO watermark 구조(`st_lsm6dsx`)의 장단점을 비교할 수 있다
- [ ] 타임스탬프를 hardirq에서 찍는 이유와 `current_timestamp_clock`을 monotonic으로 바꾸는 이유를 말할 수 있다
- [ ] 이벤트 fd를 얻어 이벤트 코드를 해독하고, enable 속성을 드라이버가 지켜야 한다는 점을 설명할 수 있다
- [ ] 샘플률·지터·누락·중복을 재는 도구를 만들고, 결과를 TCG의 한계와 함께 해석할 수 있다
