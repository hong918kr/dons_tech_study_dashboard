# C6. tickless 커널 — 할 일이 없으면 tick을 끄고, 다음 마감에 한 번만 깬다

> **이 노트를 다 읽으면**: 1 kHz tick이 배터리를 왜 먹는지 숫자로 설명한다 · FreeRTOS `vPortSuppressTicksAndSleep()`(port.c)를 한 줄씩 따라가며 reload 계산·24비트 한계·멈춘 시간 보정·조기 기상을 설명한다 · SysTick 대신 저전력 타이머(LPTIM/RTC)로 tick을 만드는 `configUSE_TICKLESS_IDLE=2` 구현을 직접 짠다 · Zephyr의 기본 tickless(`sys_clock_set_timeout()`)와 FreeRTOS를 같은 보드에서 깨어남 횟수로 비교한다
> **왜 필요한가**: "배터리로 6개월 가야 한다", "대기 전류가 데이터시트보다 10배 높다", "tickless를 켰더니 시계가 하루에 몇 초씩 틀린다" — 배터리 장비 펌웨어 면접과 실무에서 바로 나오는 장면이다
> **Don 기준 난이도**: 타이머 레지스터·인터럽트·WFI는 이미 안다 / tick을 멈췄다 다시 켤 때 시간을 어떻게 메우는지, 커널이 "잘 수 있다"를 어떻게 판단하는지가 새로 배울 부분
> **선행 노트**: A7(tick 비용 측정 — Zephyr tickless + slicing off = 0%), C5(tick과 시간 관리), B3(PRIMASK · BASEPRI), EL N2(Linux의 `nohz` — 참조만)

## 0. 큰 그림 — 이게 왜 필요한가

### 0.1 tick은 "1초에 1000번 울리는 알람시계"다

C5에서 본 tick 인터럽트는 1 kHz면 1 ms마다 들어온다. 태스크가 모두 막혀(block) 있어도 들어온다. 커널은 tick마다 깨어나서 "지연 리스트 맨 앞의 태스크가 깰 시각인가?"를 확인하고, 아니면 다시 잔다. 대부분의 tick은 **"아직 아니다"를 확인하려고 CPU를 깨우는 일**이다.

배터리 장비에서 이게 문제가 되는 이유는 두 가지다.

1. **깨어날 때마다 전력이 든다.** MCU의 깊은 수면(예: STM32의 STOP 모드)은 수 µA, 동작 중은 수 mA다. 1000번 깨면 그때마다 클럭을 다시 켜고(PLL·레귤레이터 안정화), 몇 µs 동안 mA를 쓰고, 다시 잠든다. "깨어 있는 시간"이 짧아도 횟수가 많으면 평균 전류가 수면 전류의 몇 배가 된다.
2. **깊은 수면에서는 SysTick 자체가 멈춘다.** SysTick은 코어 클럭으로 돈다. 코어 클럭을 끄는 STOP 모드에 들어가면 tick이 안 온다. 즉 "tick을 유지하면서 깊이 자기"는 원래 불가능하다. 1 kHz tick을 유지하려면 얕은 수면(WFI만, 클럭은 살아 있음)만 쓸 수 있다.

**tickless idle**은 이 문제를 이렇게 푼다: "할 일이 없을 때, 다음에 깨어야 할 시각(가장 빠른 타임아웃)을 계산해서, 그때 한 번만 울리는 one-shot 타이머를 걸고 잔다. 깨어나면 그동안 지나간 tick 수를 한꺼번에 더한다."

### 0.2 Don의 경험과 연결 — SSD의 power state와 같은 문제

NVMe SSD 펌웨어에는 APST(Autonomous Power State Transition)와 PCIe L1.2 같은 저전력 상태가 있다. "호스트 명령이 일정 시간 안 오면 더 깊은 상태로 내려가고, 깨울 이벤트가 오면 exit latency를 내고 올라온다." 펌웨어는 **언제 내려갈지(진입 조건), 무엇이 깨울지(wake source), 올라왔을 때 무엇을 보정할지(타이머·카운터 복원)**를 정한다.

tickless는 그 문제의 RTOS판이다.

| SSD 펌웨어 | RTOS tickless |
|---|---|
| idle 타이머가 만료되면 PS3/PS4로 | 다음 타임아웃까지 `configEXPECTED_IDLE_TIME_BEFORE_SLEEP` tick 이상 남으면 잔다 |
| 호스트 doorbell · PERST · 타이머가 wake source | one-shot 타이머 · 외부 인터럽트가 wake source |
| 복귀 후 타임스탬프 카운터 보정 | 복귀 후 `vTaskStepTick()`으로 tick 카운트 보정 |
| exit latency를 SLA에서 뺀다 | wake latency를 마감 계산에서 뺀다 (§9) |

SSD 실행부(executive)에도 주기 tick이 없거나 아주 느렸을 것이다. 시간은 자유 실행 하드웨어 카운터를 읽고, 타임아웃은 "다음 마감 시각"과 비교한다. A7에서 말했듯이 **tickless는 실행부 개발자가 원래 하던 방식을 커널이 대신 해 주는 것**이다.

### 0.3 세 가지 "잠자는 방식" — 용어 정리

| 방식 | tick | 잠은? | 깨는 횟수 (1 kHz, 거의 idle) | 대표 |
|---|---|---|---|---|
| 주기 tick, idle은 루프만 | 항상 | 안 잔다 | 1000/s, CPU 100% 동작 | FreeRTOS 기본 설정 |
| 주기 tick + idle에서 WFI ("sleep on idle") | 항상 | tick 사이에 얕게 | 1000/s | idle hook에 `__WFI()` |
| tickless idle | idle일 때만 끈다 | 다음 타임아웃까지 | 실제 이벤트 수만큼 | FreeRTOS `configUSE_TICKLESS_IDLE` |
| 완전 tickless 커널 | 원래 주기 tick이 없다 | 다음 타임아웃까지 | 실제 이벤트 수만큼 | Zephyr `CONFIG_TICKLESS_KERNEL` (기본) |

FreeRTOS의 tickless는 **idle일 때만** tick을 멈춘다. 태스크가 돌고 있으면 tick은 평소처럼 1 ms마다 온다. Zephyr는 커널 설계 자체가 "다음 타임아웃이 있을 때만 타이머를 건다"라서, 바쁜 스레드 하나만 돌 때도 타이머 인터럽트가 0번일 수 있다(A7 예제 8에서 측정: tickless + slicing off = tick 비용 0%).

Linux의 같은 개념(`CONFIG_NO_HZ_IDLE`, `nohz_full`)은 EL N2에서 다뤘다. 여기서는 **MCU에서 달라지는 점** — 24비트 SysTick 한계, 깊은 수면에서 SysTick이 멈추는 문제, 저전력 타이머로 시간을 이어 붙이는 법 — 만 쓴다.

### 실습 환경 한 줄

QEMU `mps2-an385`(Cortex-M3 @ 25 MHz) + FreeRTOS V11.3.2(ARM_CM3 포트) / 같은 보드의 Zephyr v4.4.2. 모든 타이밍은 `ICOUNT=1`(명령 1개 = 32 ns 가상 시간, 실행마다 같은 숫자)이다. **QEMU icount 기준이라 실제 칩과 절대값은 다르다**(캐시·플래시 wait state·버스·클럭 기동 시간을 모델링하지 않는다). 특히 QEMU에는 "깊은 수면"과 "전류"가 없다 — WFI는 "다음 타이머 이벤트까지 가상 시계를 건너뛴다"로만 구현된다. 그래서 이 노트는 전력 대신 **깨어난 횟수**와 **깨어 있던 시간 비율**을 잰다. 이 둘이 실제 칩에서 평균 전류를 정하는 두 변수다.

## 1. tickless의 원리 — "다음 마감까지 자고, 깨서 시간을 메운다"

### 1.1 직관 — 알람을 1분마다 맞추지 말고, 약속 시각에 한 번만 맞춘다

1 kHz tick은 "1 ms마다 울리는 알람을 켜 두고, 울릴 때마다 시계를 보고 약속 시각인지 확인한다"이다. tickless는 "가장 빠른 약속이 37 ms 뒤면 37 ms짜리 알람 하나를 맞추고 잔다"이다. 다만 두 가지가 더 필요하다.

- **일찍 깰 수 있다.** 37 ms 알람을 맞췄는데 12 ms에 UART 인터럽트가 와서 깨면, "지금이 몇 tick인가"를 알아내서 12만 더해야 한다(37이 아니라).
- **알람을 바꾸는 동안 시계가 흐른다.** 타이머를 멈추고 새 값을 쓰는 몇십 사이클 동안 흐른 시간도 어딘가에 더해야 한다. 이걸 대충 하면 시계가 조금씩 틀어진다(drift, §5).

### 1.2 정의 — 세 단계

tickless 구현은 어느 RTOS든 세 단계다.

1. **얼마나 잘 수 있나 계산** — "다음 깨울 시각 − 지금". FreeRTOS는 `xNextTaskUnblockTime − xTickCount`(`prvGetExpectedIdleTime()`, tasks.c), Zephyr는 타임아웃 리스트 맨 앞(`next_timeout()`, kernel/timeout.c).
2. **그 시각에 one-shot 타이머를 걸고 WFI** — 하드웨어 한계(SysTick 24비트)를 넘으면 잘라서 여러 번 잔다.
3. **깨어나서 지난 시간을 tick 단위로 되돌려 준다** — FreeRTOS `vTaskStepTick(n)`, Zephyr `sys_clock_announce(n)`.

### 1.3 SSD 비유로 다시

SSD 실행부에서 "GC를 50 ms 뒤에 돌려야 하고, 그 전에 호스트 명령이 오면 먼저 처리한다"를 짤 때, 50 ms 타이머 하나를 걸고 WFI로 잔 뒤 깨면 "타이머가 깨웠나, doorbell이 깨웠나"를 보고 남은 시간을 다시 계산했을 것이다. 1.2의 세 단계가 정확히 그것이다. 다른 점은 RTOS에서는 이걸 **커널의 tick 카운터와 맞물려서** 해야 한다는 것뿐이다 — 태스크들이 `vTaskDelay(37)`처럼 tick 단위로 시간을 쓰기 때문이다.

## 2. FreeRTOS의 tickless 설정 손잡이

### 2.1 설정 항목 한눈에 (V11.3.2 소스에서 확인)

| 항목 | 기본값 | 뜻 | 정의 위치 |
|---|---|---|---|
| `configUSE_TICKLESS_IDLE` | 0 | 0 = 끔, 1 = 포트가 주는 SysTick 구현, 2 이상 = 내가 만든 구현 | `include/FreeRTOS.h` |
| `configEXPECTED_IDLE_TIME_BEFORE_SLEEP` | 2 | 이만큼(tick) 이상 잘 수 있을 때만 잔다. 2 미만이면 `#error` | `include/FreeRTOS.h` |
| `configPRE_SUPPRESS_TICKS_AND_SLEEP_PROCESSING(x)` | 빈 매크로 | 스케줄러를 멈춘 뒤, 자기 직전. `x = 0`으로 만들면 이번엔 안 잔다 | tasks.c `prvIdleTask` |
| `configPRE_SLEEP_PROCESSING(x)` | 빈 매크로 | WFI 직전(인터럽트 마스크 상태). 클럭 낮추기 · 주변장치 끄기. `x = 0`이면 포트의 WFI를 건너뛴다(직접 WFI/STOP 진입했다는 뜻) | port.c |
| `configPOST_SLEEP_PROCESSING(x)` | 빈 매크로 | WFI 직후. 클럭 복구 | port.c |
| `portSUPPRESS_TICKS_AND_SLEEP(x)` | `vPortSuppressTicksAndSleep(x)` | 실제로 재우는 함수. mode 2면 내가 정의한다 | `portmacro.h` |
| `vPortSetupTimerInterrupt()` | weak 함수 | tick 타이머 초기화. 덮어쓰면 SysTick 대신 다른 타이머로 tick을 만든다 | port.c |
| `configSYSTICK_CLOCK_HZ` | `configCPU_CLOCK_HZ` | SysTick이 코어 클럭이 아닌 외부 클럭(STCLK)으로 돌 때 | port.c |

`configUSE_TICKLESS_IDLE`의 값 구분이 재미있다. tasks.c의 idle 태스크는 `#if ( configUSE_TICKLESS_IDLE != 0 )`으로 tickless 경로를 켜고, port.c는 `#if ( configUSE_TICKLESS_IDLE == 1 )`일 때만 자기 `vPortSuppressTicksAndSleep()`을 컴파일한다. 소스 주석 그대로 옮기면: "user defined low power mode implementations require configUSE_TICKLESS_IDLE to be set to a value other than 1". 그래서 **2 = 커널의 tickless 경로는 쓰되 재우는 함수는 내가 준다**는 뜻이 된다(§7).

`eSleepModeStatus`(task.h)는 세 값이다.

| 값 | 뜻 | 반환 조건 (`eTaskConfirmSleepModeStatus()`, tasks.c) |
|---|---|---|
| `eAbortSleep` | 자면 안 된다 | 스케줄러가 멈춘 사이에 태스크가 ready가 됨(`xPendingReadyList`), yield가 밀림, tick이 밀림(`xPendedTicks != 0`) |
| `eStandardSleep` | 다음 타임아웃까지 자도 된다 | 기본값 |
| `eNoTasksWaitingTimeout` | 타임아웃을 기다리는 태스크가 하나도 없다 — 외부 인터럽트만 기다린다 | 모든 앱 태스크가 suspended 리스트에 있음(`portMAX_DELAY`로 막힌 태스크도 여기 들어간다, `INCLUDE_vTaskSuspend == 1`일 때) |

### 2.2 이 노트의 실험용 설정 파일

랩 템플릿 `FreeRTOSConfig.h`를 그대로 포함하고 tickless 손잡이만 얹는다. `xPortSysTickHandler`를 `SysTick_Handler`로 바꾸는 템플릿의 매크로는 풀어서, SysTick 인터럽트 횟수를 세는 래퍼를 끼운다.

무엇을 확인하는 코드인지: 측정용 훅(SysTick 횟수, WFI 횟수, 잠든 사이클, 매 수면의 계획/실제/보정 tick)을 FreeRTOS 설정 매크로에 연결한다.

```c
/* C6 FreeRTOSConfig.h — lab template + tickless knobs (override with EXTRA_CFLAGS) */
#ifndef C6_CONFIG_H
#define C6_CONFIG_H
#include "/var/rtoslab/templates/freertos-mps2/FreeRTOSConfig.h"
#undef  xPortSysTickHandler              /* SysTick_Handler = counting wrapper in c6_common.c */

#define configUSE_TICKLESS_IDLE 0        /* 0 = off, 1 = port.c SysTick version, 2 = user version */
#endif
#include <stdint.h>
void c6_pre_sleep(uint32_t *x);
void c6_post_sleep(uint32_t x);

#define configPOST_SLEEP_PROCESSING(x)  c6_post_sleep(x)
void c6_step(uint32_t n);
#define traceINCREASE_TICK_COUNT(x)     c6_step(x)      /* called by vTaskStepTick() */

void c6_suppress_ticks_and_sleep(uint32_t xExpectedIdleTime);
#define portSUPPRESS_TICKS_AND_SLEEP(x) c6_suppress_ticks_and_sleep(x)

```

`traceINCREASE_TICK_COUNT(x)`는 `vTaskStepTick()` 안에서만 불리는 trace 매크로다(tasks.c). 이걸로 "깨어나서 몇 tick을 한꺼번에 더했나"를 기록한다.

```c
/* c6.h — counters shared by the C6 FreeRTOS experiments */
#ifndef C6_H
#define C6_H
#include <stdint.h>
#include "board.h"
#define CYC() REG32(0x40028018u)                 /* FPGAIO COUNTER: 25 MHz free-running */
extern volatile uint32_t n_systick, n_lpirq, n_wfi, sleep_cyc;   /* n_lpirq: lp_tick.c */
typedef struct { uint32_t expected, slept_cyc, stepped; } sleep_log_t;
#define LOG_N 16
extern sleep_log_t slog[LOG_N];
extern volatile uint32_t n_log;                  /* sleeps recorded since last reset */
static inline void spin_us(uint32_t us) { uint32_t t = CYC(); while (CYC() - t < us * 25u) { } }
#endif
```

```c
/* c6_common.c — SysTick counter, sleep accounting, plain "WFI in idle hook" */
#include "FreeRTOS.h"
#include "task.h"
#include "c6.h"
volatile uint32_t n_systick, n_lpirq, n_wfi, sleep_cyc;
static uint32_t t_sleep;
sleep_log_t slog[LOG_N];
volatile uint32_t n_log;

extern void xPortSysTickHandler(void);
void SysTick_Handler(void) { n_systick++; xPortSysTickHandler(); }

/* called by port.c right before / after its WFI (interrupts masked by cpsid i) */
void c6_pre_sleep(uint32_t *x)
{
    n_wfi++;
    if (n_log < LOG_N) slog[n_log].expected = *x;
    t_sleep = CYC();
}
void c6_post_sleep(uint32_t x)
{
    (void)x;
    uint32_t d = CYC() - t_sleep;
    sleep_cyc += d;
    if (n_log < LOG_N) slog[n_log].slept_cyc = d;
}
void c6_step(uint32_t n) { if (n_log < LOG_N) slog[n_log++].stepped = n; }

#if (configUSE_IDLE_HOOK == 1) && (configUSE_TICKLESS_IDLE == 0)
void vApplicationIdleHook(void)          /* "sleep on idle" without tickless */
{
    __asm volatile("cpsid i" ::: "memory");
    n_wfi++;
    uint32_t t = CYC();
    __asm volatile("dsb\n wfi\n isb" ::: "memory");
    sleep_cyc += CYC() - t;
    __asm volatile("cpsie i" ::: "memory");  /* the waking IRQ runs here */
}
#endif
```

시간은 MPS2의 FPGAIO COUNTER(0x40028018, 리셋부터 25 MHz로 증가)로 잰다. SysTick과 독립이라 SysTick을 멈췄다 켜도 영향을 받지 않는 "벽시계"다. `vApplicationIdleHook()`의 WFI도 `cpsid i` 안에서 한다 — 그래야 깨운 인터럽트의 ISR 시간이 "잠든 시간"에 섞이지 않는다(PRIMASK가 1이어도 WFI는 깨어난다, §4.3).

## 3. 예제 1 — 1초 동안 몇 번 깨나: tick 켬 vs tickless

### 3.1 작업 부하 — "거의 idle"인 센서 노드

예를 들어 배터리로 도는 드론 원격 텔레메트리 노드나 센서 허브라면, 대부분의 시간은 기다림이다. 10 Hz로 센서를 읽고(500 µs 작업), 4 Hz로 텔레메트리를 보낸다(200 µs 작업). CPU가 일하는 시간은 1초에 5.8 ms, 0.58%다.

무엇을 확인하는 코드인지: 같은 부하를 ① tick + idle 루프, ② tick + idle hook WFI, ③ tickless(mode 1)로 돌려서, 1초 동안의 tick 인터럽트 수 · WFI 진입 수 · 깨어 있던 시간 비율을 잰다.

```c
/* ex1 — mostly-idle workload: SysTick IRQs, WFI entries, awake fraction over 1 s */
#include <stdio.h>
#include "FreeRTOS.h"
#include "task.h"
#include "c6.h"

static void sensor(void *p)              /* 10 Hz sample: 500 us of work every 100 ms */
{
    (void)p;
    TickType_t last = xTaskGetTickCount();
    for (;;) { spin_us(500); vTaskDelayUntil(&last, pdMS_TO_TICKS(100)); }
}

static void telem(void *p)               /* 4 Hz telemetry: 200 us every 250 ms */
{
    (void)p;
    for (;;) { spin_us(200); vTaskDelay(pdMS_TO_TICKS(250)); }
}

static void report(void *p)
{
    (void)p;
    vTaskDelay(pdMS_TO_TICKS(200));                       /* warm-up */
    taskENTER_CRITICAL();
    n_systick = n_lpirq = n_wfi = sleep_cyc = 0;
    uint32_t c0 = CYC();
    TickType_t k0 = xTaskGetTickCount();
    taskEXIT_CRITICAL();

    vTaskDelay(pdMS_TO_TICKS(1000));                      /* measurement window */

    taskENTER_CRITICAL();
    uint32_t dc = CYC() - c0, st = n_systick + n_lpirq, w = n_wfi, sl = sleep_cyc;
    TickType_t dk = xTaskGetTickCount() - k0;
    taskEXIT_CRITICAL();
    uint32_t awake_bp = (uint32_t)((uint64_t)(dc - sl) * 10000u / dc);
    printf("tickless=%d idle_hook=%d | tick_irq=%4lu wfi=%4lu | awake=%3lu.%02lu%% "
           "| kernel_ticks=%lu wall=%lu us\n",
           configUSE_TICKLESS_IDLE, configUSE_IDLE_HOOK, (unsigned long)st, (unsigned long)w,
           (unsigned long)(awake_bp / 100), (unsigned long)(awake_bp % 100),
           (unsigned long)dk, (unsigned long)(dc / 25u));
    board_exit(0);
}

int main(void)
{
    xTaskCreate(sensor, "sensor", 256, NULL, 3, NULL);
    xTaskCreate(telem, "telem", 256, NULL, 2, NULL);
    xTaskCreate(report, "report", 512, NULL, 4, NULL);
    vTaskStartScheduler();
    return 0;
}
```

출력에서 볼 것:

- **깨어나는 횟수: 1000 → 12.** tickless에서는 1초 동안 SysTick 인터럽트가 12번만 들어왔다. 12 = 센서 10번 + 텔레메트리 4번 − 겹친 2번(텔레메트리의 500 ms·1000 ms 기상이 센서와 같은 tick에 걸린다).
- **깨어 있는 시간: 100% → 0.84% → 0.61%.** 일 자체가 0.58%다. ②와 ③의 차이 0.23%p(1초에 2.3 ms)는 tick으로 988번 더 깬 비용이다 — 한 번에 약 2.3 µs(약 58사이클: 예외 진입, `xTaskIncrementTick()`, 복귀, 다시 WFI).
- ②와 ③의 "깨어 있는 시간" 차이는 작아 보이지만, **실제 칩의 전류는 횟수에 더 민감하다.** 깨어날 때마다 클럭·레귤레이터가 안정화되는 시간이 있고(QEMU엔 없다), ②는 tick을 지키느라 깊은 수면(STOP)을 쓸 수 없다. ③은 한 번 자면 평균 약 83 ms를 잔다 — STOP 모드로 들어갈 가치가 있는 길이다.
- 마지막 숫자 `wall=999974 us`를 기억해 두자. 커널은 1000 tick(1,000,000 µs)이 지났다고 하는데 벽시계는 999,974 µs다. **tickless가 26 µs만큼 시계를 앞서가게 했다.** 이 drift의 원인을 §5에서 끝까지 추적한다.

### 3.2 계산으로 확인 — 깨는 횟수가 평균 전류를 정한다

실제 칩에서의 평균 전류는 대략 `I_avg ≈ I_sleep + (깨는 횟수/s × 깨어날 때마다 쓰는 전하) + 동작 전류 × 동작 비율`이다. 동작 비율(0.58%)은 일의 양이라 줄일 수 없다. tickless가 줄이는 것은 가운데 항이다 — 1000/s → 12/s. 숫자(µA, µC)는 칩마다 크게 다르므로 이 노트에서는 지어내지 않는다. 데이터시트의 "wakeup time from Stop"과 동작 전류로 직접 넣어 계산하라(§12 연습 3).

## 4. port.c 해부 — `vPortSuppressTicksAndSleep()`를 한 줄씩

### 4.1 idle 태스크에서 port.c까지

먼저 누가 이 함수를 부르는지 보자. tasks.c의 `prvIdleTask()` 루프 끝부분이다(V11.3.2, 주석 줄임).

```c
#if ( configUSE_TICKLESS_IDLE != 0 )
{
    TickType_t xExpectedIdleTime;
    xExpectedIdleTime = prvGetExpectedIdleTime();          /* 1차: 스케줄러 안 멈추고 대충 */

    if( xExpectedIdleTime >= ( TickType_t ) configEXPECTED_IDLE_TIME_BEFORE_SLEEP )
    {
        vTaskSuspendAll();
        {
            configASSERT( xNextTaskUnblockTime >= xTickCount );
            xExpectedIdleTime = prvGetExpectedIdleTime();  /* 2차: 이제 믿을 수 있는 값 */
            configPRE_SUPPRESS_TICKS_AND_SLEEP_PROCESSING( xExpectedIdleTime );

            if( xExpectedIdleTime >= ( TickType_t ) configEXPECTED_IDLE_TIME_BEFORE_SLEEP )
            {
                traceLOW_POWER_IDLE_BEGIN();
                portSUPPRESS_TICKS_AND_SLEEP( xExpectedIdleTime );
                traceLOW_POWER_IDLE_END();
            }
        }
        ( void ) xTaskResumeAll();
    }
}
#endif
```

두 번 계산하는 이유: 첫 계산은 스케줄러가 돌고 있는 상태라 그 사이에 값이 바뀔 수 있다. 하지만 idle 루프마다 `vTaskSuspendAll()`/`xTaskResumeAll()`을 하면 비싸므로, 가망이 있을 때만 스케줄러를 멈추고 다시 잰다.

`prvGetExpectedIdleTime()`은 다음 세 경우에 0을 돌려준다(= 자지 마라).

- 지금 도는 태스크가 idle 우선순위보다 높다(`pxCurrentTCB->uxPriority > tskIDLE_PRIORITY`) — idle hook이 아닌 곳에서 불렸을 때.
- **idle 우선순위에 ready 태스크가 또 있다** — time slicing으로 다음 tick에 그 태스크로 넘어가야 하기 때문이다(§9.5 함정).
- `configUSE_PREEMPTION == 0`이라 더 높은 ready 태스크가 있는데 idle이 돌고 있다.

그 밖에는 `xNextTaskUnblockTime − xTickCount`를 돌려준다. `xNextTaskUnblockTime`은 지연 리스트 맨 앞 태스크의 깰 시각이다(C5). 아무도 타임아웃을 기다리지 않으면 `portMAX_DELAY`라 아주 큰 값이 나온다.

### 4.2 시작할 때 정하는 상수 세 개

`vPortSetupTimerInterrupt()`(port.c, weak)가 스케줄러 시작 때 계산한다.

```c
#if ( configUSE_TICKLESS_IDLE == 1 )
{
    ulTimerCountsForOneTick = ( configSYSTICK_CLOCK_HZ / configTICK_RATE_HZ );
    xMaximumPossibleSuppressedTicks = portMAX_24_BIT_NUMBER / ulTimerCountsForOneTick;
    ulStoppedTimerCompensation = portMISSED_COUNTS_FACTOR / ( configCPU_CLOCK_HZ / configSYSTICK_CLOCK_HZ );
}
#endif
```

| 상수 | 이 보드 값 | 뜻 |
|---|---|---|
| `ulTimerCountsForOneTick` | 25,000,000 / 1000 = **25000** | tick 하나 = SysTick 카운트 몇 개 |
| `xMaximumPossibleSuppressedTicks` | 0xFFFFFF / 25000 = **671** | 한 번에 건너뛸 수 있는 최대 tick. `portMAX_24_BIT_NUMBER` = 0xffffff |
| `ulStoppedTimerCompensation` | 94 / 1 = **94** | SysTick을 멈춘 동안 흘렀다고 "가정"하는 카운트. `portMISSED_COUNTS_FACTOR` = 94UL, 소스 주석이 "A fiddle factor"라고 부른다 |

SysTick의 LOAD 레지스터는 24비트다(Armv7-M 아키텍처의 SysTick 정의). 그래서 25 MHz에서 한 번 잘 수 있는 최대 시간은 2^24 / 25 MHz = 0.671초다. **이 한계는 tick rate와 무관하다** — tick을 100 Hz로 줄여도 67 tick × 10 ms = 670 ms다. 코어가 빠를수록 더 짧아진다(§7.1의 계산: 480 MHz면 34 ms).

### 4.3 본문 — 단계별로

V11.3.2 port.c의 실제 코드를 순서대로 자르고(주석은 줄이고 한국어 설명을 붙였다), 각 단계가 왜 필요한지 쓴다.

**단계 ① 상한 자르기**

```c
if( xExpectedIdleTime > xMaximumPossibleSuppressedTicks )
{
    xExpectedIdleTime = xMaximumPossibleSuppressedTicks;
}
```

2000 tick을 자고 싶어도 671에서 자른다. 671 tick 뒤에 깨면 idle 루프가 다시 돌아서 남은 1329 tick을 다시 계산한다(예제 2에서 확인).

**단계 ② `cpsid i` — BASEPRI가 아니라 PRIMASK로 막는다**

```c
__asm volatile ( "cpsid i" ::: "memory" );
__asm volatile ( "dsb" );
__asm volatile ( "isb" );
```

소스 주석: "Enter a critical section but don't use the taskENTER_CRITICAL() method as that will mask interrupts that should exit sleep mode." 여기가 Cortex-M의 미묘한 점이다(B3).

- `taskENTER_CRITICAL()`은 BASEPRI를 `configMAX_SYSCALL_INTERRUPT_PRIORITY`로 올린다. Armv7-M에서 WFI가 깨어나는 조건은 "PRIMASK를 무시했을 때 선점할 수 있는 우선순위의 인터럽트가 pending"이다. **BASEPRI로 막힌 인터럽트는 WFI를 깨우지 못한다.** 그러면 SysTick(가장 낮은 우선순위)도 못 깨운다 — 영원히 잔다.
- PRIMASK(`cpsid i`)는 핸들러 **실행**만 막고 WFI 기상은 막지 않는다. 그래서 "깨어나긴 하되, ISR은 아직 돌리지 말고 내 보정 코드부터 실행"하는 상태가 된다. 이게 tickless의 핵심 트릭이다 — 깬 직후 SysTick이 몇을 가리키는지 ISR보다 먼저 읽어야 하기 때문이다.

Zephyr의 `arch_cpu_idle()`도 같은 이유로 `cpsid i` 후 BASEPRI를 0으로 내리고 WFI를 한다(§8.4의 역어셈블).

**단계 ③ 마지막 확인 — `eTaskConfirmSleepModeStatus()`**

```c
if( eTaskConfirmSleepModeStatus() == eAbortSleep )
{
    __asm volatile ( "cpsie i" ::: "memory" );
}
else
{   /* ... 아래 단계들 ... */
```

스케줄러를 멈춘 뒤(`vTaskSuspendAll`) ~ `cpsid i` 사이에 ISR이 세마포어를 줘서 태스크가 ready가 됐을 수 있다. 그 태스크는 스케줄러가 멈춰 있어서 `xPendingReadyList`에 들어가 있다. 이걸 확인하지 않고 자면 "할 일이 생겼는데 671 ms 동안 잔다". 인터럽트를 막은 뒤에 확인하므로 이제는 경쟁 조건이 없다.

**단계 ④ SysTick 멈추고, 이번 tick의 남은 몫 읽기**

```c
portNVIC_SYSTICK_CTRL_REG = ( portNVIC_SYSTICK_CLK_BIT_CONFIG | portNVIC_SYSTICK_INT_BIT );
ulSysTickDecrementsLeft = portNVIC_SYSTICK_CURRENT_VALUE_REG;
if( ulSysTickDecrementsLeft == 0 )
{
    ulSysTickDecrementsLeft = ulTimerCountsForOneTick;
}
```

CTRL에 ENABLE 비트를 빼고 쓰면 카운터가 멈춘다(**멈춤 구간 ① 시작**). VAL은 "다음 tick까지 남은 카운트"다. VAL == 0이면 남은 게 0이 아니라 한 tick 전체다 — SysTick은 1→0으로 내려갈 때 인터럽트를 요청하고, 0 다음에는 LOAD를 다시 싣기 때문이다.

**단계 ⑤ 새 reload 계산**

```c
ulReloadValue = ulSysTickDecrementsLeft + ( ulTimerCountsForOneTick * ( xExpectedIdleTime - 1UL ) );

if( ( portNVIC_INT_CTRL_REG & portNVIC_PEND_SYSTICK_SET_BIT ) != 0 )
{
    portNVIC_INT_CTRL_REG = portNVIC_PEND_SYSTICK_CLEAR_BIT;
    ulReloadValue -= ulTimerCountsForOneTick;
}
if( ulReloadValue > ulStoppedTimerCompensation )
{
    ulReloadValue -= ulStoppedTimerCompensation;
}
```

- 지금 tick의 남은 몫 + 나머지 (N−1) tick 전체. `−1`인 이유는 "지금은 첫 tick의 중간"이기 때문이다. 예: N = 671, 남은 몫 = 24300이면 24300 + 25000 × 670 = 16,774,300 (< 0xFFFFFF = 16,777,215 — 그래서 671이 상한이다).
- `cpsid i` 직전에 SysTick이 이미 0을 지나 인터럽트가 pending이면(ICSR.PENDSTSET), 그 tick은 "이미 시작된 둘째 tick"이므로 pending을 지우고 한 tick을 뺀다. 소스 주석: "The expected idle time is always at least two ticks" — 이 빼기가 있어서 `configEXPECTED_IDLE_TIME_BEFORE_SLEEP`이 2 미만이면 `#error`다.
- **보정 94를 뺀다.** 멈춤 구간 ①·② 동안 SysTick이 못 센 시간만큼 미리 짧게 잡는 것이다. 이 숫자가 실제 멈춘 시간과 다르면 drift가 생긴다(§5).

**단계 ⑥ 적재하고 재시작**

```c
portNVIC_SYSTICK_LOAD_REG = ulReloadValue;
portNVIC_SYSTICK_CURRENT_VALUE_REG = 0UL;
portNVIC_SYSTICK_CTRL_REG |= portNVIC_SYSTICK_ENABLE_BIT;
```

VAL에 아무 값이나 쓰면 VAL이 0이 되고 COUNTFLAG가 지워진다. 다음 클럭에 LOAD를 싣고 세기 시작한다(**멈춤 구간 ① 끝**).

**단계 ⑦ 잔다**

```c
xModifiableIdleTime = xExpectedIdleTime;
configPRE_SLEEP_PROCESSING( xModifiableIdleTime );
if( xModifiableIdleTime > 0 )
{
    __asm volatile ( "dsb" ::: "memory" );
    __asm volatile ( "wfi" );
    __asm volatile ( "isb" );
}
configPOST_SLEEP_PROCESSING( xExpectedIdleTime );
```

`configPRE_SLEEP_PROCESSING`이 값을 0으로 바꾸면 포트의 WFI를 건너뛴다 — 훅 안에서 직접 STOP 모드에 들어갔다는 뜻이다(예: STM32 HAL의 `HAL_PWR_EnterSTOPMode()`가 안에서 WFI를 한다). 원래 값은 복사본으로 보존한다. `dsb`는 메모리 쓰기를 다 끝내고 자기 위해, `isb`는 깬 뒤 파이프라인을 새로 채우기 위해서다.

**단계 ⑧ 깨어난 인터럽트를 잠깐 돌린다**

```c
__asm volatile ( "cpsie i" ::: "memory" );
__asm volatile ( "dsb" );
__asm volatile ( "isb" );
__asm volatile ( "cpsid i" ::: "memory" );
__asm volatile ( "dsb" );
__asm volatile ( "isb" );
```

여기서 인터럽트를 한 번 열어서 **깨운 ISR(예: UART, TIMER0)을 바로 실행**한다. 그 ISR이 세마포어를 주면 태스크는 `xPendingReadyList`로 간다(스케줄러는 아직 멈춰 있다). 그다음 다시 닫는다 — 이제 SysTick을 또 멈추고 보정할 차례인데, 그 사이에 ISR이 끼어들면 멈춘 시간이 늘어나 오차가 커지기 때문이다.

깨운 게 SysTick 자신이었다면? SysTick 핸들러도 여기서 돈다. 그런데 스케줄러가 멈춰 있으므로 `xTaskIncrementTick()`은 tick을 세지 않고 `xPendedTicks++`만 한다. 이 밀린 tick은 나중에 `xTaskResumeAll()`이 처리한다.

**단계 ⑨ 다시 멈추고, 누가 깨웠는지 판별**

```c
portNVIC_SYSTICK_CTRL_REG = ( portNVIC_SYSTICK_CLK_BIT_CONFIG | portNVIC_SYSTICK_INT_BIT );
if( ( portNVIC_SYSTICK_CTRL_REG & portNVIC_SYSTICK_COUNT_FLAG_BIT ) != 0 )
```

CTRL을 **읽지 않고 쓰기만** 해서 멈춘다(**멈춤 구간 ② 시작**). CTRL의 COUNTFLAG(비트 16)는 **읽으면 지워지는(clear-on-read)** 비트라, 멈추려고 read-modify-write를 하면 판별 근거가 사라진다. 그다음 줄에서 한 번만 읽어 COUNTFLAG를 본다.

- COUNTFLAG = 1 → SysTick이 0까지 내려갔다 = **계획대로 N tick을 다 잤다**(또는 다른 IRQ로 깨어난 뒤 보정하기 전에 마침 다 됐다).
- COUNTFLAG = 0 → **다른 인터럽트가 일찍 깨웠다.**

**단계 ⑩-a 계획대로 깬 경우**

```c
ulCalculatedLoadValue = ( ulTimerCountsForOneTick - 1UL ) - ( ulReloadValue - portNVIC_SYSTICK_CURRENT_VALUE_REG );
if( ( ulCalculatedLoadValue <= ulStoppedTimerCompensation ) || ( ulCalculatedLoadValue > ulTimerCountsForOneTick ) )
{
    ulCalculatedLoadValue = ( ulTimerCountsForOneTick - 1UL );
}
portNVIC_SYSTICK_LOAD_REG = ulCalculatedLoadValue;
ulCompleteTickPeriods = xExpectedIdleTime - 1UL;
```

0을 지난 뒤 SysTick은 다시 큰 reload 값부터 세고 있다. `ulReloadValue − VAL`이 "0을 지나고 흐른 카운트"이므로, 새 tick의 남은 몫은 `(25000 − 1) − 그 값`이다. 너무 작거나 이상하면(POST 훅이 너무 오래 걸렸을 때) 그냥 한 tick 전체로 둔다.
더할 tick은 **N − 1**이다. 나머지 1은 단계 ⑧에서 pending된 SysTick 인터럽트(또는 `xPendedTicks`)가 더한다. 예제 2의 `stepped=670`(expected 671)이 이것이다.

**단계 ⑩-b 다른 인터럽트가 일찍 깨운 경우**

```c
ulSysTickDecrementsLeft = portNVIC_SYSTICK_CURRENT_VALUE_REG;
ulCompletedSysTickDecrements = ( xExpectedIdleTime * ulTimerCountsForOneTick ) - ulSysTickDecrementsLeft;
ulCompleteTickPeriods = ulCompletedSysTickDecrements / ulTimerCountsForOneTick;
portNVIC_SYSTICK_LOAD_REG = ( ( ulCompleteTickPeriods + 1UL ) * ulTimerCountsForOneTick ) - ulCompletedSysTickDecrements;
```

남은 카운트(VAL)로부터 "계획한 N tick 중 몇 카운트가 지났나"를 구하고, 완전한 tick 수만큼만 더한다. 나머지 조각(지금 tick에서 남은 부분)은 LOAD에 넣어서 다음 tick 경계가 원래 격자에 맞게 한다.
여기서 미묘한 점: 계산은 "N × 25000"을 기준으로 하지만 실제로 적재한 값은 "남은 몫 + 25000 × (N−1) − 94"였다. 그 차이는 첫 tick의 부분 몫과 보정 94인데, 이것들이 일찍 깬 경우의 계산에 그대로 섞인다. 측정에서 조기 기상의 drift가 계획대로 깬 경우와 조금 다른 이유다(§5).

**단계 ⑪ 평소 tick으로 복귀**

```c
portNVIC_SYSTICK_CURRENT_VALUE_REG = 0UL;
portNVIC_SYSTICK_CTRL_REG = portNVIC_SYSTICK_CLK_BIT | portNVIC_SYSTICK_INT_BIT | portNVIC_SYSTICK_ENABLE_BIT;
#if ( portNVIC_SYSTICK_CLK_BIT_CONFIG == portNVIC_SYSTICK_CLK_BIT )
{
    portNVIC_SYSTICK_LOAD_REG = ulTimerCountsForOneTick - 1UL;
}
#else
    /* (외부 클럭 SysTick일 때의 처리 — 생략) */
#endif
vTaskStepTick( ulCompleteTickPeriods );
__asm volatile ( "cpsie i" ::: "memory" );
```

### 4.4 `vTaskStepTick()` — 그냥 더하기가 아니다

```c
void vTaskStepTick( TickType_t xTicksToJump )
{
    TickType_t xUpdatedTickCount;
    xUpdatedTickCount = xTickCount + xTicksToJump;
    configASSERT( xUpdatedTickCount <= xNextTaskUnblockTime );

    if( xUpdatedTickCount == xNextTaskUnblockTime )
    {
        configASSERT( uxSchedulerSuspended != ( UBaseType_t ) 0U );
        configASSERT( xTicksToJump != ( TickType_t ) 0 );
        taskENTER_CRITICAL();
        {
            xPendedTicks++;
        }
        taskEXIT_CRITICAL();
        xTicksToJump--;
    }
    xTickCount += xTicksToJump;
    traceINCREASE_TICK_COUNT( xTicksToJump );
}
```

- `xTickCount`를 직접 더하므로 건너뛴 tick마다 tick hook(`vApplicationTickHook`)은 **불리지 않는다**(소스 주석: "Note this does not call the tick hook function for each stepped tick" — 원문은 not을 강조 표시했다). tick hook으로 시간을 세는 코드는 tickless에서 틀린다(§9).
- 더한 결과가 정확히 다음 깰 시각이면, 마지막 1 tick은 직접 더하지 않고 `xPendedTicks`로 미룬다. 그래야 `xTaskResumeAll()`이 그 tick을 **진짜 tick처럼** `xTaskIncrementTick()`으로 처리하면서 지연 리스트에서 태스크를 깨운다. 그냥 더해 버리면 "깰 시각은 지났는데 아무도 리스트를 안 봤다"가 된다.
- 넘어서면 `configASSERT`가 터진다. mode 2를 직접 짤 때 가장 먼저 밟는 지뢰다 — 늦게 깨서 계산이 N+1이 나오면 N으로 잘라야 한다(§7.3).

### 4.5 예제 2 — 한 번에 몇 tick까지 잘 수 있나 (24비트 한계 검증)

무엇을 확인하는 코드인지: 태스크 하나가 `vTaskDelay(2 s)`로 막혔을 때 커널이 몇 번 나눠 자는지, 매 수면의 계획(expected) · 실제 잔 시간 · 보정 tick(stepped)을 기록한다. tick rate를 1000 / 100 / 10000 Hz로 바꿔 본다.

```c
/* ex2 — how long can one SysTick-based tickless sleep be? (24-bit LOAD limit) */
#include <stdio.h>
#include "FreeRTOS.h"
#include "task.h"
#include "c6.h"

static void probe(void *p)
{
    (void)p;
    vTaskDelay(2);                                     /* settle */
    taskENTER_CRITICAL(); n_log = 0; n_systick = n_lpirq = 0; taskEXIT_CRITICAL();
    uint32_t c0 = CYC();
    TickType_t k0 = xTaskGetTickCount();
    vTaskDelay(pdMS_TO_TICKS(2000));                   /* one long block: 2 s */
    uint32_t wall_us = (CYC() - c0) / 25u, st = n_systick + n_lpirq, nl = n_log;
    TickType_t dk = xTaskGetTickCount() - k0;

#if configUSE_TICKLESS_IDLE == 1
    printf("SysTick tickless: tick=%u Hz counts/tick=%u -> max_suppress=0xFFFFFF/%u=%u ticks\n",
           (unsigned)configTICK_RATE_HZ, (unsigned)(configCPU_CLOCK_HZ / configTICK_RATE_HZ),
           (unsigned)(configCPU_CLOCK_HZ / configTICK_RATE_HZ),
           (unsigned)(0xFFFFFFu / (configCPU_CLOCK_HZ / configTICK_RATE_HZ)));
#else
    printf("LP-timer tickless (mode 2): 32-bit @ 1.5625 MHz, clamp 0x7FFFFFFF/1562=%u ticks\n",
           (unsigned)(0x7FFFFFFFu / (configCPU_CLOCK_HZ / 16u / configTICK_RATE_HZ)));
#endif
    for (uint32_t i = 0; i < nl && i < LOG_N; i++)
        printf("  sleep %lu: expected=%5lu ticks  slept=%7lu us  stepped=%5lu\n",
               (unsigned long)i, (unsigned long)slog[i].expected,
               (unsigned long)(slog[i].slept_cyc / 25u), (unsigned long)slog[i].stepped);
    printf("  sleeps=%lu tick_irq=%lu  kernel=%lu ticks  wall=%lu us\n",
           (unsigned long)nl, (unsigned long)st, (unsigned long)dk,
           (unsigned long)wall_us);
    board_exit(0);
}

int main(void)
{
    xTaskCreate(probe, "probe", 512, NULL, 2, NULL);
    vTaskStartScheduler();
    return 0;
}
```

## 5. 시간 정확도 — tickless는 시계를 틀어지게 한다

### 5.1 직관 — 시계를 멈췄다 다시 켤 때마다 몇 초씩

벽시계의 건전지를 뺐다 끼울 때마다 "대충 3초 걸렸으니 3초 앞으로 돌리자"고 하면, 실제로 2초 걸렸을 때마다 시계는 1초씩 빨라진다. port.c의 94카운트 보정이 바로 그 "대충 3초"다. 하루에 수만 번 자는 장비라면 작은 오차가 쌓인다.

drift가 생기는 출처는 세 가지다.

1. **멈춘 시간 보정이 틀림** — mode 1에서 SysTick을 멈춘 두 구간의 실제 길이 ≠ 94카운트(§4.6에서 QEMU는 39카운트).
2. **타이머를 다시 쓰는 동안 못 센 시간** — 카운터를 읽고 새 값을 쓰기까지의 몇 명령. Zephyr처럼 SysTick을 멈추지 않아도, 읽기와 쓰기 사이를 세지 않으면 생긴다(§8.6).
3. **두 클럭 사이의 비율 오차** — 저전력 타이머가 32.768 kHz인데 tick이 1 kHz면 32.768카운트/tick이라 정수가 아니다. 반올림하면 매 tick 오차가 쌓인다(§7.1).

### 5.2 예제 4 — 5초 동안 수천 번 자고 깨면 얼마나 틀어지나

무엇을 확인하는 코드인지: 태스크가 `vTaskDelay(DLY)`를 5초 동안 반복한다(= 매번 tickless로 잔다). 또는 긴 지연 중에 TIMER0 인터럽트가 `T0_US`마다 일찍 깨운다(ISR은 횟수만 센다). 끝에서 커널 시간(tick × 1000 µs)과 FPGAIO 벽시계를 비교한다.

```c
/* ex3 — does tickless keep time? kernel ticks vs FPGAIO wall clock over 5 s */
#include <stdio.h>
#include "FreeRTOS.h"
#include "task.h"
#include "c6.h"
#ifndef DLY
#define DLY 7            /* ticks per vTaskDelay() */
#endif
#ifndef T0_US
#define T0_US 0          /* >0: TIMER0 IRQ every T0_US us wakes the CPU early */
#endif
static volatile uint32_t n_t0;

void TIMER0_IRQHandler(void) { TIMER_INTCLR(TIMER0_BASE) = 1; n_t0++; }

static void probe(void *p)
{
    (void)p;
    if (T0_US) {
        TIMER_RELOAD(TIMER0_BASE) = T0_US * 25u - 1u;
        TIMER_VALUE(TIMER0_BASE)  = T0_US * 25u - 1u;
        TIMER_CTRL(TIMER0_BASE)   = 1u | 8u;          /* enable + IRQ enable */
        NVIC_IPR(8) = 0x40;                           /* below configMAX_SYSCALL (0x20) */
        NVIC_ISER0  = 1u << 8;
    }
    vTaskDelay(2);
    taskENTER_CRITICAL();
    n_systick = n_lpirq = n_wfi = 0; n_t0 = 0;
    uint32_t c0 = CYC();
    TickType_t k0 = xTaskGetTickCount();
    taskEXIT_CRITICAL();

    uint32_t loops = 0;
    while (xTaskGetTickCount() - k0 < pdMS_TO_TICKS(5000)) { vTaskDelay(DLY); loops++; }

    taskENTER_CRITICAL();
    uint32_t wall = (CYC() - c0) / 25u, st = n_systick + n_lpirq, w = n_wfi, t0 = n_t0;
    uint32_t kern = (xTaskGetTickCount() - k0) * (1000000u / configTICK_RATE_HZ);
    taskEXIT_CRITICAL();
    int32_t drift = (int32_t)(kern - wall);
    printf("tickless=%d DLY=%2d T0=%4u us | loops=%4lu wfi=%4lu tick_irq=%4lu t0_irq=%4lu | "
           "kernel=%lu wall=%lu drift=%+ld us (%+ld ppm)\n",
           configUSE_TICKLESS_IDLE, DLY, (unsigned)T0_US, (unsigned long)loops,
           (unsigned long)w, (unsigned long)st, (unsigned long)t0, (unsigned long)kern,
           (unsigned long)wall, (long)drift, (long)((int64_t)drift * 1000000 / (int64_t)wall));
    board_exit(0);
}

int main(void)
{
    xTaskCreate(probe, "probe", 512, NULL, 2, NULL);
    vTaskStartScheduler();
    return 0;
}
```

출력에서 볼 것:

- **tick을 켜 두면(tickless=0) drift가 정확히 0이다.** SysTick이 한 번도 멈추지 않기 때문이다. 같은 조건에서 TIMER0이 3650번 인터럽트를 걸어도 0이다.
- **tickless(mode 1)는 sleep 한 번마다 커널 시계가 앞서 간다.** 5400/2500 = 1545/715 = 216/100 = **2.16 µs/회**. 지연 길이와 상관없이 "자고 깬 횟수"에 비례한다. §4.6의 예측(94 − 39 = 55카운트 = 2.2 µs)과 맞는다.
- 그래서 **짧게 자주 잘수록 나쁘다.** 2 tick씩 자면 1081 ppm(하루 93초), 50 tick씩 자면 43 ppm(하루 3.7초).
- **조기 기상(TIMER0)은 회당 2.32 µs**로 조금 더 크다(8450/3645 = 1173/506). 단계 ⑩-b의 계산 경로가 다르고, 단계 ⑧에서 ISR을 실행하는 동안의 시간 처리도 다르기 때문이다. 1.37 ms마다 깨면 1692 ppm — 하루 146초다.
- `t0_irq=3643`(tick 켬은 3650): 커널 시계가 빨라서 커널 기준 5초가 벽시계로는 4.99초에 끝났다. 그 사이에 TIMER0이 덜 울렸다.

> 이 숫자는 **QEMU icount의 명령 타이밍** 기준이다. 실제 칩에서는 멈춤 구간의 49명령이 다른 사이클 수를 쓰므로 drift의 크기는 물론 **부호도 바뀔 수 있다**(실제 구간이 94카운트보다 길면 커널이 느려진다). 결론은 숫자가 아니라 구조다: "고정 보정 상수 방식은 칩·클럭·컴파일러마다 오차가 다르고, 수면 횟수에 비례해 쌓인다."

### 5.4 실무에서 drift가 문제가 되는 때와 아닌 때

- **문제 아님**: "약 100 ms마다 센서 읽기" 같은 상대 시간. 0.1% 틀려도 아무도 모른다.
- **문제**: 커널 tick으로 **벽시계(달력 시간)**를 유지할 때. 1000 ppm이면 하루 86초다. 로그 타임스탬프가 GPS·서버 시간과 어긋난다. → 벽시계는 RTC(32.768 kHz 크리스털, 수 ppm~수십 ppm)에서 읽고, 커널 tick은 상대 시간용으로만 쓴다.
- **문제**: 여러 노드의 동기(TDMA 무선 슬롯, 센서 융합 타임스탬프). → 동기는 하드웨어 타임스탬프나 RTC 기준으로 하고, 주기적으로 외부 기준(GPS PPS 등)과 맞춘다.
- 측정 방법은 이 예제 그대로다: **tick과 독립인 자유 실행 카운터**(MPS2 FPGAIO, 실칩이면 RTC나 자유 실행 32비트 타이머, DWT CYCCNT는 코어 클럭이 멈추는 수면에서 같이 멈출 수 있어 부적합)로 "커널 시간 − 벽시계"를 오래 잰다.

## 6. 언제 안 자나, 언제 더 깊이 자도 되나

### 6.1 예제 5 — `configEXPECTED_IDLE_TIME_BEFORE_SLEEP`: 짧은 틈은 안 잔다

무엇을 확인하는 코드인지: 태스크가 100 µs 일하고 `vTaskDelay(DLY)`를 1초 동안 반복할 때, 문턱값(THRESH)과 지연(DLY)에 따라 실제로 tickless 수면에 들어가는지 본다.

```c
/* ex5 — configEXPECTED_IDLE_TIME_BEFORE_SLEEP: which idle gaps are worth a tickless sleep? */
#include <stdio.h>
#include "FreeRTOS.h"
#include "task.h"
#include "c6.h"

static void worker(void *p)
{
    (void)p;
    vTaskDelay(2);
    taskENTER_CRITICAL(); n_wfi = n_systick = sleep_cyc = 0; taskEXIT_CRITICAL();
    uint32_t c0 = CYC();
    TickType_t k0 = xTaskGetTickCount();
    while (xTaskGetTickCount() - k0 < 1000) { spin_us(100); vTaskDelay(DLY); }
    uint32_t dc = CYC() - c0, w = n_wfi, st = n_systick, sl = sleep_cyc;
    printf("THRESH=%2d DLY=%d | tick_irq=%4lu wfi=%4lu  in WFI=%3lu%%\n",
           configEXPECTED_IDLE_TIME_BEFORE_SLEEP, DLY, (unsigned long)st,
           (unsigned long)w, (unsigned long)((uint64_t)sl * 100u / dc));
    board_exit(0);
}

int main(void)
{
    xTaskCreate(worker, "worker", 512, NULL, 2, NULL);
    vTaskStartScheduler();
    return 0;
}
```

출력에서 볼 것:

- **`vTaskDelay(1)`은 tickless로 자지 않는다** — 그리고 이 설정(idle hook 없음)에서는 WFI도 안 해서 **CPU가 0% 잔다**(idle 루프만 돈다). 예상 idle이 1 tick이라 문턱 2를 못 넘는다. tickless를 켰다고 안심하면 안 되는 첫 함정이다. 짧은 틈에서도 자려면 idle hook에 WFI를 같이 넣는다(§9.6).
- 문턱 이상이면 지연 1회당 sleep 1회다(DLY=2 → 500회, DLY=4 → 250회).
- 문턱을 5로 올리면 DLY=2, 4는 아예 안 잔다. 문턱은 "깊은 수면의 진입+복귀 비용을 회수하려면 최소 몇 tick 자야 하나"로 정한다. 예를 들어 STOP 진입·복귀에 수십 µs와 클럭 재설정이 들면 2 ms 수면은 손해일 수 있다 — 데이터시트의 wakeup time으로 계산해서 정한다.

### 6.2 예제 6 — 모든 태스크가 무한 대기: `eNoTasksWaitingTimeout`

무엇을 확인하는 코드인지: 유일한 앱 태스크가 `xSemaphoreTake(sem, portMAX_DELAY)`로 막히고, 1초마다 TIMER0 ISR이 세마포어를 준다("버튼 누름"). 타임아웃을 기다리는 태스크가 하나도 없을 때 커널이 몇 번 깨는지 본다.

```c
/* ex4 — every task blocks forever: eTaskConfirmSleepModeStatus() = eNoTasksWaitingTimeout */
#include <stdio.h>
#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"
#include "c6.h"
static SemaphoreHandle_t sem;
static volatile uint32_t n_t0;

void TIMER0_IRQHandler(void)                          /* "button press" once per second */
{
    TIMER_INTCLR(TIMER0_BASE) = 1;
    n_t0++;
    BaseType_t hp = pdFALSE;
    xSemaphoreGiveFromISR(sem, &hp);
    portYIELD_FROM_ISR(hp);
}

static void waiter(void *p)
{
    (void)p;
    TIMER_RELOAD(TIMER0_BASE) = 25000000u - 1u;       /* 1 s */
    TIMER_VALUE(TIMER0_BASE)  = 25000000u - 1u;
    TIMER_CTRL(TIMER0_BASE)   = 1u | 8u;
    NVIC_IPR(8) = 0x40;
    NVIC_ISER0  = 1u << 8;
    taskENTER_CRITICAL(); n_log = n_wfi = n_systick = n_lpirq = 0; taskEXIT_CRITICAL();
    uint32_t c0 = CYC();
    for (int i = 0; i < 3; i++) xSemaphoreTake(sem, portMAX_DELAY);   /* no timeout at all */
    uint32_t wall = (CYC() - c0) / 25u, w = n_wfi, st = n_systick + n_lpirq, nl = n_log;
    printf("tickless=%d | 3 events in %lu us | wfi=%lu tick_irq=%lu t0_irq=%lu\n",
           configUSE_TICKLESS_IDLE, (unsigned long)wall, (unsigned long)w,
           (unsigned long)st, (unsigned long)n_t0);
    for (uint32_t i = 0; i < nl && i < 6; i++)
        printf("  sleep %lu: expected=%lu slept=%lu us\n", (unsigned long)i,
               (unsigned long)slog[i].expected, (unsigned long)(slog[i].slept_cyc / 25u));
    board_exit(0);
}

int main(void)
{
    sem = xSemaphoreCreateBinary();
    xTaskCreate(waiter, "waiter", 512, NULL, 2, NULL);
    vTaskStartScheduler();
    return 0;
}
```

## 7. 저전력 타이머로 tick 만들기 — `configUSE_TICKLESS_IDLE = 2`

### 7.1 왜 SysTick으로는 부족한가 — 세 가지 이유

1. **깊은 수면에서 멈춘다.** STM32의 STOP 모드처럼 코어 클럭(HCLK)을 끄는 모드에서는 SysTick도 멈춘다. mode 1 구현은 "WFI 동안 SysTick이 계속 돈다"를 가정하므로, STOP에 들어가면 깨울 수도 없고 시간도 잴 수 없다.
2. **24비트라 짧다.** 코어가 빠를수록 더 짧다(아래 계산).
3. **보정 상수에 의존한다**(§5).

그래서 실제 배터리 장비는 깊은 수면에서도 도는 **저전력 타이머**를 쓴다.

- **LPTIM** (예: STM32L4/U5 계열): LSE(32.768 kHz 크리스털)나 LSI로 돌고 STOP 모드에서도 동작한다. 흔히 16비트 카운터 + compare 레지스터, compare match로 깨운다.
- **RTC wakeup timer / RTC 카운터**: 역시 32.768 kHz 도메인, 가장 깊은 모드에서도 산다. nRF52의 RTC는 24비트 카운터 + compare 채널을 가진 32.768 kHz 타이머다(Zephyr의 nRF용 system timer가 이것을 쓴다).
- 공통 패턴: **멈추지 않는 카운터 = 시간 기준**, **compare(또는 one-shot) = 깨우기**. tick 경계는 카운터 값에서 계산한다.

**예제 7 — 수면 상한과 클럭 비율 계산.** 무엇을 확인하는 코드인지: 24비트 SysTick의 한 번 수면 상한을 코어 클럭별로, 16비트 32.768 kHz LPTIM의 해상도와 상한을, 그리고 32.768 kHz로 tick을 만들 때 정수로 반올림하면 생기는 오차를 계산한다.

```python
# limits.py — max tickless sleep per timer, and the tick-ratio error of a 32.768 kHz LPTIM
SYSTICK_MAX = 0xFFFFFF                      # 24-bit SysTick LOAD
print("SysTick (24-bit) @ core clock, configTICK_RATE_HZ=1000:")
for mhz in (25, 64, 168, 480):
    cpt = mhz * 1_000_000 // 1000           # ulTimerCountsForOneTick
    n = SYSTICK_MAX // cpt                  # xMaximumPossibleSuppressedTicks
    print(f"  {mhz:4d} MHz: counts/tick={cpt:7d}  max={n:4d} ticks = {n:4d} ms")

print("16-bit LPTIM @ 32768 Hz (prescaler 1/1, 1/8, 1/32):")
for div in (1, 8, 32):
    f = 32768 / div
    print(f"  /{div:<2d}: resolution={1e6 / f:7.1f} us  max one-shot={65535 / f:8.3f} s")

print("tick rate vs 32768 Hz: counts per tick and the error if you round it")
for hz in (1000, 1024, 100, 128):
    exact = 32768 / hz
    r = round(exact)
    err_ppm = (r - exact) / exact * 1e6
    print(f"  {hz:5d} Hz: exact={exact:8.3f}  rounded={r:4d}  period error={err_ppm:+8.1f} ppm"
          f" -> kernel clock {-err_ppm * 86400 / 1e6 + 0.0:+7.2f} s/day")
```

출력에서 볼 것:

- **480 MHz Cortex-M7(STM32H7급 드론 FC)이면 SysTick tickless는 한 번에 34 ms밖에 못 잔다.** 1초 무한 대기에 30번 깬다. 빠른 칩일수록 저전력 타이머가 필요하다.
- 32.768 kHz 16비트 LPTIM은 분주 없이 30.5 µs 해상도에 최대 2초, /32면 1 ms 해상도에 64초. 해상도와 최대 수면 길이를 맞바꾼다.
- **1 kHz tick + 32.768 kHz 클럭 = 32.768카운트/tick.** 33으로 반올림하면 tick이 0.71% 길어져 커널 시계가 하루 612초 늦는다. 그래서 (a) tick rate를 1024 Hz나 128 Hz처럼 32768의 약수로 하거나, (b) 정수 반올림 대신 **절대 카운트에서 tick 경계를 계산**한다(아래 구현이 (b)).

### 7.2 설계 — mode 2에서 내가 해야 할 일

`configUSE_TICKLESS_IDLE = 2`로 두면 tasks.c의 tickless 경로(그림 2의 파랑)는 그대로 쓰고, 주황 부분을 내가 채운다.

| 할 일 | FreeRTOS 연결점 | 이 구현 |
|---|---|---|
| tick 타이머 시작 | `vPortSetupTimerInterrupt()` 덮어쓰기(port.c에서 weak) | DT2를 자유 실행으로, DT1을 다음 tick 경계 one-shot으로 |
| 평소 tick | tick ISR에서 `xTaskIncrementTick()` + 필요하면 PendSV | `DUALTIMER_IRQHandler`: 카운터에서 "지금까지 지났어야 할 tick 수"를 계산해 모자란 만큼 증가 |
| 수면 | `portSUPPRESS_TICKS_AND_SLEEP(x)` 정의 | `c6_suppress_ticks_and_sleep()` |
| 수면 확인 | `eTaskConfirmSleepModeStatus()` | `eNoTasksWaitingTimeout`이면 깨우기 타이머를 끈다 |
| 시간 보정 | `vTaskStepTick(n)` | n = (카운터로 계산한 tick) − (이미 알린 tick), N으로 상한 |

핵심 아이디어는 **"tick 경계 k는 카운트 ceil(k × LP_HZ / TICK_HZ)에 있다"**다. 매번 "몇 카운트 남았나"를 누적하지 않고, 절대 카운트로부터 계산하므로 1562.5카운트/tick처럼 나누어떨어지지 않아도, 몇 번을 자고 깨도 오차가 쌓이지 않는다. Zephyr의 tickless 드라이버들도 같은 생각이다(`announced_cycles`, §8.3).

### 7.3 구현

무엇을 확인하는 코드인지: SysTick을 한 번도 켜지 않고, DUALTIMER만으로 FreeRTOS tick과 tickless 수면을 구현한다.

```c
/* lp_tick.c — configUSE_TICKLESS_IDLE=2: tick from a "low-power timer" (CMSDK DUALTIMER as a
 * stand-in for LPTIM/RTC); SysTick never runs. DT2 = always-on timebase, DT1 = one-shot wake-up */
#include "FreeRTOS.h"
#include "task.h"
#include "c6.h"
#define DT(o)   REG32(0x40002000u + (o))
#define LP_HZ   (configCPU_CLOCK_HZ / 16u)            /* prescale /16 = 1.5625 MHz */
#define CTL_32P16 ((1u << 1) | (1u << 2))             /* 32-bit counter, prescale /16 */
#define CTL_EN  (1u << 7)
#define DT1_CTL (1u | CTL_32P16 | (1u << 5))         /* one-shot + IRQ enable */
#define LP_MAX_TICKS (0x7FFFFFFFu / (LP_HZ / configTICK_RATE_HZ))   /* ~1.37 M ticks */
static uint64_t announced;                            /* ticks given to the kernel */

static uint64_t lp_now(void)          /* DT2 extended to 64 bit; call with IRQs masked */
{
    static uint32_t last; static uint64_t hi;
    uint32_t c = 0xFFFFFFFFu - DT(0x24);              /* DT2 counts down */
    if (c < last) hi += 1ull << 32;                   /* wraps every 45.8 min */
    last = c; return hi | c;
}
static uint64_t due_ticks(void) { return lp_now() * configTICK_RATE_HZ / LP_HZ; }
static void arm_at_tick(uint64_t k)                   /* one-shot at tick boundary k */
{
    uint64_t at = (k * LP_HZ + configTICK_RATE_HZ - 1) / configTICK_RATE_HZ;
    int64_t d = (int64_t)(at - lp_now());
    DT(0x08) = DT1_CTL;                               /* stop, reload, restart */
    DT(0x00) = d > 1 ? (uint32_t)d : 1u;
    DT(0x08) = DT1_CTL | CTL_EN;
}
void vPortSetupTimerInterrupt(void)                   /* overrides port.c's weak SysTick setup */
{
    DT(0x28) = CTL_32P16;                             /* DT2: free-running, no IRQ */
    DT(0x20) = 0xFFFFFFFFu;
    DT(0x28) = CTL_32P16 | CTL_EN;
    NVIC_IPR(10) = configKERNEL_INTERRUPT_PRIORITY;   /* same level as SysTick would be */
    NVIC_ISER0 = 1u << 10;
    arm_at_tick(1);
}
void DUALTIMER_IRQHandler(void)
{
    DT(0x0C) = 1;                                     /* clear DT1 interrupt */
    n_lpirq++;
    UBaseType_t m = portSET_INTERRUPT_MASK_FROM_ISR();
    BaseType_t sw = pdFALSE;
    for (uint64_t due = due_ticks(); announced < due; announced++)
        sw |= xTaskIncrementTick();                   /* catch up if we were late */
    arm_at_tick(announced + 1);
    portCLEAR_INTERRUPT_MASK_FROM_ISR(m);
    portYIELD_FROM_ISR(sw);
}
void c6_suppress_ticks_and_sleep(uint32_t xExpectedIdleTime)
{
    __asm volatile("cpsid i" ::: "memory");
    eSleepModeStatus st = eTaskConfirmSleepModeStatus();
    if (st == eAbortSleep) { __asm volatile("cpsie i" ::: "memory"); return; }
    if (xExpectedIdleTime > LP_MAX_TICKS) xExpectedIdleTime = LP_MAX_TICKS;
    if (st == eNoTasksWaitingTimeout) DT(0x08) = DT1_CTL;      /* no timeout: no wake timer */
    else arm_at_tick(announced + xExpectedIdleTime);
    uint32_t x = xExpectedIdleTime;
    configPRE_SLEEP_PROCESSING(x);                    /* real chip: enter STOP here */
    __asm volatile("dsb\n wfi\n isb" ::: "memory");
    configPOST_SLEEP_PROCESSING(x);
    uint64_t step = due_ticks() - announced;          /* time came from the never-stopped DT2 */
    if (step > xExpectedIdleTime) step = xExpectedIdleTime;
    vTaskStepTick((TickType_t)step);
    announced += step;
    DT(0x0C) = 1; REG32(0xE000E280u) = 1u << 10;      /* drop a stale DT1 IRQ (NVIC ICPR) */
    arm_at_tick(announced + 1);
    __asm volatile("cpsie i" ::: "memory");
}
```

한 줄씩 짚을 곳:

- `lp_now()` — DT2는 아래로 세므로 `0xFFFFFFFF − VALUE`로 뒤집고, 45.8분(2^32 / 1.5625 MHz)마다 한 바퀴 도는 것을 64비트로 늘린다. 항상 인터럽트가 막힌 상태(ISR 안 또는 `cpsid i` 안)에서만 불리므로 `last`/`hi` 갱신이 경쟁하지 않는다. wrap을 놓치지 않으려면 45.8분 안에 한 번은 불려야 하는데, 수면 상한(`LP_MAX_TICKS` ≈ 1.37 M tick ≈ 22.9분)이 그걸 보장한다.
- `arm_at_tick(k)` — 목표 카운트까지의 차이를 DT1에 넣는다. 이미 지났으면(차이 ≤ 1) 1을 넣어 바로 인터럽트가 나게 한다. CMSDK DUALTIMER는 one-shot이 끝난 뒤 LOAD만 써서는 다시 돌지 않아서(첫 시도에서 QEMU가 "Timer with delta zero, disabling"을 출력하고 멈췄다) 끄고-쓰고-켜는 순서로 한다. 실칩 LPTIM이면 compare 레지스터 하나만 쓰면 된다(대신 "CMP 쓰기 완료" 플래그를 기다려야 하는 칩이 많다 — 데이터시트 확인).
- `DUALTIMER_IRQHandler` — `xTaskIncrementTick()`을 **모자란 만큼 반복**한다. ISR이 늦게 돌아도(다른 ISR이 길었다든가) tick을 잃지 않는다. 우선순위는 SysTick이 원래 쓰던 `configKERNEL_INTERRUPT_PRIORITY`(가장 낮음)로 둔다 — tick ISR이 커널 API를 쓰기 때문이다(B3).
- `c6_suppress_ticks_and_sleep()` — port.c와 같은 뼈대(`cpsid i` → 확인 → 타이머 → PRE → WFI → POST → step → `cpsie i`)지만 **카운터를 멈추지 않으므로 보정 상수가 없다.** 깬 뒤 `due_ticks() − announced`가 정확히 지난 tick 수다. N보다 크면(보정하기 전에 경계를 하나 더 넘었으면) N으로 자른다 — `vTaskStepTick()`의 `configASSERT(xUpdatedTickCount <= xNextTaskUnblockTime)`을 지키기 위해서다. 남은 tick은 곧바로 울리는 DT1 ISR이 채운다.
- 깬 직후 DT1의 pending 인터럽트를 NVIC ICPR(0xE000E280)로 지운다. 계획대로 깬 경우 그 인터럽트의 몫은 방금 `vTaskStepTick()`이 처리했으므로, ISR이 또 돌면 다음 경계 재설정만 한 번 더 하게 된다(해롭진 않지만 쓸데없는 기상).

## 8. Zephyr — 처음부터 tickless인 커널

### 8.1 설정 — 기본값이 이미 tickless

| Kconfig | 이 보드 값 | 뜻 (v4.4.2 `kernel/Kconfig`, `drivers/timer/Kconfig.cortex_m_systick`) |
|---|---|---|
| `CONFIG_TICKLESS_KERNEL` | y | `default y if TICKLESS_CAPABLE`. Cortex-M SysTick 드라이버는 tickless 가능으로 선언돼 있다 |
| `CONFIG_SYS_CLOCK_TICKS_PER_SEC` | 100 | `default 100 if QEMU_TARGET` / `default 10000 if TICKLESS_KERNEL` / 그 밖 100. **실칩에서 tickless면 기본 10 kHz**다 — tick은 "시간 해상도"일 뿐 인터럽트 주기가 아니기 때문이다 |
| `CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC` | 25000000 | SysTick 클럭 |
| `CONFIG_CORTEX_M_SYSTICK` | y | system timer 드라이버 = `drivers/timer/cortex_m_systick.c` |
| `CONFIG_TIMESLICING` / `CONFIG_TIMESLICE_SIZE` | y / 20 | 같은 우선순위 스레드의 슬라이스 타이머(§9.5) |
| `CONFIG_PM` | n | 켜면 idle에서 `pm_system_suspend()`가 SoC 전력 상태를 고른다(P2) |

(값은 이 노트 빌드의 `build/zephyr/.config`에서 확인했다.)

FreeRTOS와의 결정적 차이: FreeRTOS는 "주기 tick이 기본이고 idle일 때만 멈춘다", Zephyr는 "**타임아웃 리스트의 맨 앞이 바뀔 때마다** 타이머를 그 시각에 다시 건다"이다. 그래서 Zephyr에서는 바쁜 스레드가 돌 때도 tick 인터럽트가 없다(A7 예제 8: slicing off면 0%).

### 8.2 커널 → 드라이버 경로

- 스레드가 `k_msleep(7)` → `z_add_timeout()`(kernel/timeout.c)가 타임아웃 리스트에 넣고, 맨 앞이 바뀌었으면 `sys_clock_set_timeout(next_timeout(...), false)`를 부른다.
- 타이머 인터럽트 → `sys_clock_isr()`(cortex_m_systick.c)가 지난 사이클을 tick으로 바꿔 `sys_clock_announce(dticks)` → 만료된 타임아웃 처리 → 다음 맨 앞으로 `sys_clock_set_timeout()` 재호출.
- 실행할 스레드가 없으면 idle 스레드(`kernel/idle.c`의 `idle()`)가 `arch_irq_lock()` 후 `k_cpu_idle()` → `arch_cpu_idle()`(arch/arm/core/cortex_m/cpu_idle.c) = WFI. `CONFIG_PM`이면 그 전에 `pm_system_suspend(z_get_next_timeout_expiry())`가 깊은 상태를 시도하고, 그때만 `sys_clock_set_timeout(ticks − exit_latency, true)`처럼 **idle = true**로 부른다(subsys/pm/pm.c).

즉 Zephyr의 "tickless idle"은 별도 함수가 아니다. **언제나 다음 타임아웃에 타이머가 걸려 있으므로, idle은 그냥 WFI를 하면 된다.** FreeRTOS의 `vPortSuppressTicksAndSleep()`이 하던 일 — 남은 시간 계산과 재설정 — 은 타임아웃이 바뀔 때마다 이미 끝나 있다.

### 8.3 `sys_clock_set_timeout()` 해부 (cortex_m_systick.c, v4.4.2)

먼저 상수.

```c
#define COUNTER_MAX 0x00ffffff
#define TIMER_STOPPED 0xff000000
#define CYC_PER_TICK (CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC/CONFIG_SYS_CLOCK_TICKS_PER_SEC)
#define _MAX_TICKS (int)((k_ticks_t)(COUNTER_MAX / CYC_PER_TICK) - 1)
#define MAX_TICKS ((_MAX_TICKS > 0) ? _MAX_TICKS : 1)
#define MAX_CYCLES (MAX_TICKS * CYC_PER_TICK)
#define MIN_DELAY MAX(1024U, ((uint32_t)CYC_PER_TICK/16U))
```

- 같은 24비트 한계: 100 Hz면 `MAX_TICKS` = 16777215/250000 − 1 = 66, 1000 Hz면 670. 둘 다 약 0.67초.
- `MIN_DELAY`: 너무 가까운 시각을 걸면 LOAD를 쓰는 사이에 지나가 버린다. 최소 1024사이클 또는 tick의 1/16. 소스 주석은 이 값이 "인터럽트가 막혀 있을 수 있는 최대 시간보다 커야 한다"고 말한다 — LOAD 한 바퀴보다 오래 인터럽트를 막으면 wrap을 놓치기 때문이다.

본문의 tickless 부분(줄임).

```c
	if (IS_ENABLED(CONFIG_TICKLESS_KERNEL) && idle && ticks == K_TICKS_FOREVER) {
		SysTick->CTRL &= ~SysTick_CTRL_ENABLE_Msk;
		last_load = TIMER_STOPPED;
		return;
	}
	/* ... (LPM companion 타이머 경로 생략) ... */
	ticks = (ticks == K_TICKS_FOREVER) ? MAX_TICKS : ticks;
	ticks = CLAMP(ticks - 1, 0, (int32_t)MAX_TICKS);

	k_spinlock_key_t key = k_spin_lock(&lock);
	uint32_t pending = elapsed();
	val1 = SysTick->VAL;
	cycle_count += pending;
	overflow_cyc = 0U;
	uint32_t unannounced = cycle_count - announced_cycles;
	/* ... */
		delay = ticks * CYC_PER_TICK;
		delay += unannounced;
		delay = DIV_ROUND_UP(delay, CYC_PER_TICK) * CYC_PER_TICK;
		delay -= unannounced;
		delay = MAX(delay, MIN_DELAY);
		if (delay > MAX_CYCLES) {
			last_load = MAX_CYCLES;
		} else {
			last_load = delay;
		}
	val2 = SysTick->VAL;
	SysTick->LOAD = last_load - 1;
	SysTick->VAL = 0; /* resets timer to last_load */
	if (val1 < val2) {
		cycle_count += (val1 + (last_load_ - val2));
	} else {
		cycle_count += (val1 - val2);
	}
	k_spin_unlock(&lock, key);
```

단계별로:

1. **idle이고 영원히 기다린다면 SysTick을 끈다.** 단, `idle == true`는 PM 경로에서만 온다. PM이 없는 이 보드에서는 이 줄이 실행되지 않는다(예제 9에서 "타임아웃 없는 idle"도 0.67초마다 깨는 이유).
2. 영원(`K_TICKS_FOREVER`)은 `MAX_TICKS`로 바꾼다 — 24비트를 넘지 않게, 그리고 `cycle_count`(32비트 누적 사이클)가 wrap을 놓치지 않게 주기적으로 깨기 위해서다.
3. **SysTick을 멈추지 않는다.** 대신 `elapsed()`로 지금까지 센 사이클을 `cycle_count`에 더하고, LOAD를 새로 쓴 뒤 VAL = 0으로 다시 시작한다. 읽기(val1)와 다시 시작 사이에 흐른 사이클(val1 − val2)도 더한다.
4. 지연을 **"아직 알리지 않은 사이클(unannounced)"을 포함해서 tick 경계로 올림**한다. 그래서 인터럽트는 늘 tick 격자 위에서 난다. `sys_clock_isr()`는 `dticks = (cycle_count − announced_cycles) / CYC_PER_TICK`만큼만 알리고 나머지는 다음으로 넘긴다 — §7의 "절대 카운트 기준" 아이디어와 같다.

FreeRTOS mode 1과 비교하면: FreeRTOS는 "멈추고, 고정 보정 94를 빼고, 다시 켠다", Zephyr는 "멈추지 않고, 읽은 값의 차이로 직접 더한다". Zephyr 방식이 원리상 더 정확하지만, **"읽은 순간"과 "다시 시작한 순간" 사이의 몇 명령은 여전히 아무도 세지 않는다**(§8.6에서 측정).

### 8.4 idle은 정말 WFI 하나인가 — 역어셈블

무엇을 확인하는 코드인지: Zephyr 빌드의 `arch_cpu_idle()`이 무엇을 하는지 기계어로 본다.

```sh
limactl shell elinux -- bash -lc 'arm-none-eabi-objdump -d --no-show-raw-insn /var/tmp/rtos/C6/z1_tl100/zephyr/zephyr.elf | awk "/<arch_cpu_idle>:/,/^$/"'
```

```text
00002660 <arch_cpu_idle>:
    2660:	push	{r3, lr}
    2662:	bl	2604 <sys_trace_idle>
    2666:	cpsid	i
    2668:	movs	r3, #0
    266a:	msr	BASEPRI, r3
    266e:	isb	sy
    2672:	dsb	sy
    2676:	wfi
    2678:	bl	260c <sys_trace_idle_exit>
    267c:	cpsie	i
    267e:	isb	sy
    2682:	pop	{r3, pc}
```

출력에서 볼 것:

- idle 스레드는 `arch_irq_lock()`(= BASEPRI 올림) 상태로 들어온다. 그대로 WFI를 하면 **BASEPRI에 막힌 인터럽트는 WFI를 깨우지 못한다**(§4.3 단계 ②와 같은 이유). 그래서 `cpsid i`로 PRIMASK를 먼저 세우고(실행은 막고) BASEPRI를 0으로 내린다(기상은 허용). 소스 주석: "configuring BASEPRI to the lowest priority to ensure wake-up will cause interrupts to be serviced".
- `wfi` 뒤 `cpsie i`에서 깨운 ISR이 실행된다. FreeRTOS port.c의 단계 ⑧과 같은 패턴이다.
- `sys_trace_idle` / `sys_trace_idle_exit`는 `CONFIG_TRACING=y`라서 들어간 호출이다. 다음 예제가 이 훅으로 idle 진입을 센다.

### 8.5 예제 8 — 같은 부하를 Zephyr로: 몇 번 깨나

무엇을 확인하는 코드인지: 예제 1과 같은 부하(10 Hz × 500 µs, 4 Hz × 200 µs)를 Zephyr 스레드로 돌리고, `CONFIG_TRACING_USER`의 훅으로 ISR 진입 수와 idle(WFI) 진입 수, 깨어 있던 비율을 잰다.

```text
CONFIG_PRINTK=y
CONFIG_TRACING=y
CONFIG_TRACING_USER=y
```

```c
/* z1 — same mostly-idle workload on Zephyr: timer ISRs, idle (WFI) entries, awake % */
#include <zephyr/kernel.h>
#include <zephyr/sys/printk.h>
#define CYC() (*(volatile uint32_t *)0x40028018u)          /* FPGAIO 25 MHz counter */
static volatile uint32_t n_isr, n_idle, sleep_cyc, t_idle, in_idle;

void sys_trace_idle_user(void) { n_idle++; t_idle = CYC(); in_idle = 1; }   /* before WFI */
void sys_trace_isr_enter_user(void)                                          /* after wake */
{
    n_isr++;
    if (in_idle) { sleep_cyc += CYC() - t_idle; in_idle = 0; }
}
static void spin_us(uint32_t us) { uint32_t t = CYC(); while (CYC() - t < us * 25u) { } }

static void sensor(void *a, void *b, void *c)              /* 10 Hz: 500 us work */
{
    int64_t next = k_uptime_get();
    for (;;) { spin_us(500); next += 100; k_sleep(K_TIMEOUT_ABS_MS(next)); }
}
static void telem(void *a, void *b, void *c)               /* 4 Hz: 200 us work */
{
    for (;;) { spin_us(200); k_msleep(250); }
}
K_THREAD_DEFINE(t_s, 1024, sensor, NULL, NULL, NULL, 3, 0, 0);
K_THREAD_DEFINE(t_t, 1024, telem, NULL, NULL, NULL, 4, 0, 0);

int main(void)                                              /* main = prio 0 */
{
    k_msleep(200);
    unsigned int key = irq_lock();
    n_isr = n_idle = sleep_cyc = 0;
    uint32_t c0 = CYC();
    int64_t k0 = k_uptime_ticks();
    irq_unlock(key);
    k_msleep(1000);
    key = irq_lock();
    uint32_t dc = CYC() - c0, i = n_isr, w = n_idle, sl = sleep_cyc;
    int64_t dk = k_uptime_ticks() - k0;
    irq_unlock(key);
    uint32_t bp = (uint32_t)((uint64_t)(dc - sl) * 10000u / dc);
    printk("zephyr %-8s %5d Hz slice=%d | timer_isr=%4u idle(wfi)=%4u | awake=%u.%02u%% "
           "| ticks=%u wall=%u us\n",
           IS_ENABLED(CONFIG_TICKLESS_KERNEL) ? "tickless" : "periodic",
           CONFIG_SYS_CLOCK_TICKS_PER_SEC, IS_ENABLED(CONFIG_TIMESLICING), i, w,
           bp / 100, bp % 100, (uint32_t)dk, dc / 25u);
    register uint32_t r0 __asm__("r0") = 0x18, r1 __asm__("r1") = 0x20026;
    __asm volatile("bkpt 0xab" : : "r"(r0), "r"(r1) : "memory");
    return 0;
}
```

- FreeRTOS는 12번이었다. 차이 3번은 Zephyr의 상대 지연 규칙 때문이다: `k_msleep(1000)`이 `ticks=1001`로 끝났듯이 **상대 타임아웃은 1 tick을 더한다**(최소한 요청한 시간 이상 자도록 보장). 그래서 텔레메트리 주기가 251 tick(100 Hz면 26 tick = 260 ms)이 되어 센서(절대 시각 100 ms 격자)와 한 번도 겹치지 않는다. 10 + 4 + 측정 끝 1 = 15.

### 8.6 예제 9 — Zephyr tickless의 시간 정확도와 "타임아웃 없는 idle"

무엇을 확인하는 코드인지: (1) `k_msleep(DLY)`를 5초 동안 반복한 뒤 커널 시간(`k_uptime_ticks()`)과 FPGAIO 벽시계의 차이, (2) 아무 스레드도 타임아웃을 기다리지 않을 때(TIMER0 ISR이 3초 뒤 세마포어를 줄 때까지) 몇 번 깨는지.

```c
/* z2 — Zephyr tickless: (1) time accuracy over many sleeps, (2) idle with no timeout */
#include <zephyr/kernel.h>
#include <zephyr/irq.h>
#include <zephyr/sys/printk.h>
#define CYC()  (*(volatile uint32_t *)0x40028018u)
#define T0(o)  (*(volatile uint32_t *)(0x40000000u + (o)))   /* CMSDK TIMER0, IRQ 8 */
static volatile uint32_t n_isr, n_idle;
static K_SEM_DEFINE(sem, 0, 1);

void sys_trace_idle_user(void) { n_idle++; }
void sys_trace_isr_enter_user(void) { n_isr++; }
static void t0_isr(const void *arg) { T0(0xC) = 1; T0(0x0) = 0; k_sem_give(&sem); }

static void drift(int dly)
{
    k_msleep(1);
    uint32_t c0 = CYC(), loops = 0;
    int64_t k0 = k_uptime_ticks();
    n_isr = n_idle = 0;
    while (k_uptime_ticks() - k0 < 5 * CONFIG_SYS_CLOCK_TICKS_PER_SEC) { k_msleep(dly); loops++; }
    int64_t us_k = k_ticks_to_us_floor64(k_uptime_ticks() - k0);
    uint32_t wall = (CYC() - c0) / 25u;
    printk("  DLY=%2d ms loops=%4u isr=%4u idle=%4u kernel=%u wall=%u drift=%+d us\n",
           dly, loops, n_isr, n_idle, (uint32_t)us_k, wall, (int)((uint32_t)us_k - wall));
}

int main(void)
{
    printk("zephyr %s %d Hz\n", IS_ENABLED(CONFIG_TICKLESS_KERNEL) ? "tickless" : "periodic",
           CONFIG_SYS_CLOCK_TICKS_PER_SEC);
    drift(2); drift(7); drift(50);

    IRQ_CONNECT(8, 2, t0_isr, NULL, 0);                /* one-shot-ish: 3 s from now */
    irq_enable(8);
    n_isr = n_idle = 0;
    uint32_t c0 = CYC();
    T0(0x8) = 3u * 25000000u; T0(0x4) = 3u * 25000000u; T0(0x0) = 1u | 8u;
    k_sem_take(&sem, K_FOREVER);                        /* nothing else has a timeout */
    printk("  no-timeout idle: %u us, isr=%u (incl. 1 TIMER0) idle=%u\n",
           (CYC() - c0) / 25u, n_isr, n_idle);
    register uint32_t r0 __asm__("r0") = 0x18, r1 __asm__("r1") = 0x20026;
    __asm volatile("bkpt 0xab" : : "r"(r0), "r"(r1) : "memory");
    return 0;
}
```

출력에서 볼 것:

- **Zephyr tickless는 sleep 한 번마다 커널 시계가 약 2.4 µs 늦어진다**: 623/250 = 2.49, 4018/1667 = 2.41, 1509/625 = 2.41, 242/99 = 2.44 µs. FreeRTOS mode 1과 크기는 비슷하고 **부호가 반대**다(FreeRTOS는 보정을 너무 많이 해서 빠르고, Zephyr는 못 센 시간이 있어서 느리다). 주기 tick은 −1 µs(측정 해상도)라 정확하다.
- 100 Hz에서는 `k_msleep(2)`와 `k_msleep(7)`이 똑같이 250번 돈다. 둘 다 1 tick으로 올림 + 1 tick = 20 ms다. tick rate가 낮으면 짧은 지연이 크게 부풀려진다.
- **타임아웃이 하나도 없어도 3초에 SysTick이 4번 깼다**(isr 5 − TIMER0 1). 약 0.67초마다다 — `K_TICKS_FOREVER` → `MAX_TICKS`. FreeRTOS mode 1의 671 ms와 같은 24비트 한계다. PM이 켜진 실칩에서는 idle = true 경로로 SysTick을 아예 끄고(§8.3 단계 1) 저전력 타이머(LPM companion, 다음 절)에 맡긴다.
- 주기 tick은 같은 3초에 3000번 깼다.

drift 원인을 좁히려고, 재설정이 한 loop에 몇 번 일어나는지 셌다.

무엇을 확인하는 코드인지: 링커의 `--wrap`으로 kernel/timeout.c → `sys_clock_set_timeout()` 호출을 가로채 횟수를 세고, drift를 호출 1회당으로 나눈다.

```c
/* z3 — how often does the tickless kernel reprogram SysTick, and what does each cost in drift? */
#include <zephyr/kernel.h>
#include <zephyr/drivers/timer/system_timer.h>
#include <zephyr/sys/printk.h>
#define CYC() (*(volatile uint32_t *)0x40028018u)
static volatile uint32_t n_set;

void __real_sys_clock_set_timeout(int32_t ticks, bool idle);
void __wrap_sys_clock_set_timeout(int32_t ticks, bool idle)
{
    n_set++;
    __real_sys_clock_set_timeout(ticks, idle);
}

int main(void)
{
    k_msleep(1);
    uint32_t c0 = CYC();
    int64_t k0 = k_uptime_ticks();
    n_set = 0;
    for (int i = 0; i < 625; i++) k_msleep(7);
    uint32_t calls = n_set;
    int64_t us_k = k_ticks_to_us_floor64(k_uptime_ticks() - k0);
    uint32_t wall = (CYC() - c0) / 25u;
    int drift_ns = (int)(((int64_t)us_k - wall) * 1000);
    printk("625 x k_msleep(7) @ %d Hz: set_timeout calls=%u (%u.%02u per loop)\n",
           CONFIG_SYS_CLOCK_TICKS_PER_SEC, calls, calls / 625, (calls * 100 / 625) % 100);
    printk("  kernel=%u us wall=%u us drift=%d us = %d ns per loop = %d ns per call\n",
           (uint32_t)us_k, wall, drift_ns / 1000, drift_ns / 625, drift_ns / (int)calls);
    register uint32_t r0 __asm__("r0") = 0x18, r1 __asm__("r1") = 0x20026;
    __asm volatile("bkpt 0xab" : : "r"(r0), "r"(r1) : "memory");
    return 0;
}
```

- 역어셈블로 보면(위 빌드의 `sys_clock_set_timeout` + `elapsed`), `elapsed()` 안에서 VAL을 마지막으로 읽은 뒤 `val1 = SysTick->VAL`까지 약 16명령, `val2` 읽기부터 `VAL = 0` 쓰기까지 3명령이 어느 쪽 계산에도 들어가지 않는다. 그 합(약 20명령)이 측정된 손실(26명령분)과 같은 크기다. **원인 후보로는 이게 가장 그럴듯하지만, 실칩에서 같은 크기로 나타나는지는 확인 못 함**(실칩은 같은 명령이 더 많은 사이클을 쓰므로 손실이 더 클 수도 있다).
- 실무 결론은 FreeRTOS와 같다: **tickless 커널의 uptime으로 달력 시간을 유지하지 말라.** 오차는 "깬 횟수 × 회당 몇 µs"이고, 회당 값은 커널·포트·칩마다 다르다.

### 8.7 Zephyr에서 저전력 타이머를 쓰는 법 (개념)

- 많은 SoC는 SysTick 대신 **저전력 타이머 자체를 system timer 드라이버**로 쓴다: nRF는 RTC(`drivers/timer/nrf_rtc_timer.c`), STM32는 LPTIM(`drivers/timer/stm32_lptim_timer.c`). 이 경우 `sys_clock_set_timeout()`이 처음부터 32.768 kHz 카운터의 compare를 건다 — §7과 같은 구조다.
- v4.4.2의 cortex_m_systick.c에는 **"LPM companion"** 옵션(`CONFIG_SYSTEM_TIMER_LPM_COMPANION_*`)이 있다. 평소에는 SysTick을 쓰다가 idle = true로 깊이 잘 때만 `z_sys_clock_lpm_enter(timeout_us)`로 보조 저전력 타이머를 걸고, 깬 뒤 그 타이머로 잰 시간만큼 `cycle_count`를 보정한다(§8.3에서 생략한 부분). SysTick이 수면 중 리셋되는 SoC를 위한 `CONFIG_SYSTEM_TIMER_RESET_BY_LPM`도 있다.
- 어느 쪽이든 "언제 깊이 잘지"는 PM 정책(`pm_system_suspend()`가 각 상태의 `min-residency-us`, `exit-latency-us`를 보고 고름)의 일이다 — P2에서 다룬다.

### 8.9 FreeRTOS vs Zephyr 한눈에

| 항목 | FreeRTOS (V11.3.2, ARM_CM3) | Zephyr (v4.4.2, cortex_m_systick) |
|---|---|---|
| 기본값 | 꺼짐(`configUSE_TICKLESS_IDLE 0`) | 켜짐(`CONFIG_TICKLESS_KERNEL=y`) |
| tick을 끄는 때 | idle 태스크가 돌 때만 | 항상 — 다음 타임아웃에만 타이머 |
| 바쁜 태스크 하나일 때 tick | 1 kHz 그대로 | 0 (slicing off일 때, A7) |
| 결정 지점 | `prvGetExpectedIdleTime()` + 문턱 | `next_timeout()` (timeout.c) |
| 하드웨어 재설정 | `vPortSuppressTicksAndSleep()` | `sys_clock_set_timeout()` |
| 시간 보정 | SysTick 멈춤 + 고정 94카운트 + `vTaskStepTick()` | 멈추지 않음, `cycle_count` 누적 + `sys_clock_announce()` |
| 한 번 최대 수면 (25 MHz) | 671 tick = 671 ms | `MAX_TICKS` ≈ 0.67 s |
| 측정 drift (QEMU) | +2.16~2.32 µs/sleep | −2.4 µs/sleep (재설정 3회) |
| 측정 기상 (예제 1 부하) | 12/s | 15/s (상대 지연 +1 tick) |
| 저전력 타이머 | mode 2로 직접 구현 | SoC system timer 드라이버 또는 LPM companion |
| 깊은 수면 정책 | `configPRE_SLEEP_PROCESSING`에 직접 | `CONFIG_PM` + DT 전력 상태 |

## 9. 함정 — tickless를 켠 뒤에 생기는 일

### 9.1 drift — 타이머를 멈추고 다시 켤 때마다

§5·§8.6에서 잰 대로, 회당 µs 단위 오차가 수면 횟수에 비례해 쌓인다. 대처: 달력 시간은 RTC에서 읽는다 · mode 2처럼 멈추지 않는 카운터를 시간 기준으로 쓴다 · tickless를 켜고 끈 두 빌드로 장시간 drift를 재서 문서화한다.

### 9.2 wake latency — 깨어나는 데 걸리는 시간

얕은 WFI의 기상은 몇 사이클이지만, STOP 같은 깊은 모드는 레귤레이터·클럭 기동 때문에 µs~수십 µs가 걸리고, PLL을 다시 잠그면 더 걸린다(값은 칩 데이터시트의 "wakeup time from Stop" 표를 본다 — 칩·모드·전압 범위마다 다르다). 결과:

- **타임아웃 기상이 늦어진다.** tick 경계에 맞춰 깨도 태스크는 exit latency만큼 늦게 돈다. 해결: 그만큼 일찍 깨운다(Zephyr PM은 `ticks − exit_latency_ticks`로 건다, pm.c).
- **외부 인터럽트 응답이 늦어진다.** 드론 IMU data-ready(1 kHz 이상)에 수십 µs 기상 지연이 붙으면 제어 루프 지터가 된다. 해결: 그런 장치는 깊은 수면을 금지하고(PM 정책의 "constraint", P2) 얕은 WFI만 쓴다.

### 9.3 디버거가 끊긴다

깊은 수면에서 코어 클럭·디버그 도메인이 꺼지면 SWD/JTAG 연결이 끊기거나 breakpoint가 안 걸린다. STM32라면 DBGMCU_CR의 DBG_SLEEP/DBG_STOP/DBG_STANDBY 비트로 "수면 중에도 디버그 클럭 유지"를 켤 수 있다 — **켜면 전류 측정이 틀어지므로** 전력 측정 빌드에서는 끈다. 증상이 "tickless를 켜면 디버거가 Target not responding"이라면 이것부터 의심한다. (QEMU의 gdb stub은 이 영향이 없다 — 예제 3이 잘 돈 이유.)

### 9.4 tick에 기대는 코드와 주변장치

- **tick hook으로 시간을 세는 코드**: `vTaskStepTick()`은 건너뛴 tick마다 hook을 부르지 않는다(§4.4). tick hook에서 소프트웨어 타이머·LED 깜빡임·watchdog 카운트를 하면 tickless에서 멈춘다.
- **`xTaskGetTickCount()` 폴링 루프**: `while (xTaskGetTickCount() - t0 < 10) {}`는 바쁜 대기라 idle이 안 돌아 tickless와 무관하지만, 반대로 `vTaskDelay(1)`을 끼운 폴링은 1 tick이라 문턱(2)을 못 넘어 **아예 안 잔다**(예제 5).
- **클럭이 꺼지는 주변장치**: 깊은 수면에서 UART 수신(baud 클럭), PWM, ADC가 멈춘다. 저전력 UART(LPUART)나 wake-up 가능한 핀(EXTI)으로 바꾸거나, 그 장치가 동작 중이면 수면 깊이를 제한한다(`configPRE_SLEEP_PROCESSING`에서 판단, Zephyr는 `pm_policy_state_lock_get()`).
- **HAL의 SysTick 의존**: 벤더 HAL은 `HAL_Delay()`·타임아웃을 SysTick 1 ms 인터럽트로 세는 경우가 많다(STM32 HAL의 `HAL_IncTick()`). RTOS tick을 SysTick에서 LPTIM으로 옮기면 HAL용 시간 기준을 따로 정해야 한다.

### 9.5 tickless + time slicing

- **FreeRTOS**: idle 우선순위에 ready 태스크가 하나 더 있으면 `prvGetExpectedIdleTime()`이 0을 돌려준다(§4.1) — "다음 tick에 그 태스크로 바꿔야 하니까". idle 우선순위에 백그라운드 태스크를 두면 **tickless가 영영 안 걸린다.** 해결: 백그라운드 일은 idle hook으로 옮기거나 우선순위를 1 이상으로 올리고 블로킹하게 짠다.
- **Zephyr**: 같은 우선순위의 바쁜 스레드가 있으면 슬라이스 타이머(`CONFIG_TIMESLICE_SIZE`, 기본 20 ms)가 타임아웃으로 걸린다 — A7 예제 8에서 tickless + slicing on은 200 ms에 10번 깼다. 배터리 장비는 `CONFIG_TIMESLICING=n` 또는 우선순위를 나눠서 슬라이스가 필요 없게 짠다.

### 9.6 "tickless를 켰는데 전류가 그대로"

체크 순서: (1) 정말 idle이 도나(바쁜 대기·로그 출력 태스크) (2) 예상 idle이 문턱을 넘나(1 tick 지연) (3) idle 우선순위에 다른 태스크가 있나 (4) `configPRE_SLEEP_PROCESSING`에서 실제로 깊은 모드에 들어가나(기본은 그냥 WFI = 얕은 수면) (5) 깨우는 인터럽트가 너무 자주 오나(예: 디버그 UART RX 노이즈, 1 kHz 센서 IRQ) (6) 주변장치 클럭이 켜져 있나. 측정은 이 노트처럼 **깨는 횟수**부터 센다 — 전류계 없이도 대부분 원인이 보인다.

## 11. 실무에서 다시 보기

### 11.1 드론 비행 제어기 — 비행 중엔 끄고, 지상 대기에선 켠다

예를 들어 STM32H7급 드론 FC라면, 비행 중에는 IMU 1~8 kHz와 rate loop가 쉬지 않으므로 idle이 거의 없고 tickless의 이득도 없다. 오히려 깊은 수면의 기상 지연이 IMU data-ready 응답에 붙으면 위험하다. 반면 **배터리 연결 후 이륙 전 대기, 착륙 후 대기, 원격 조종기·GNSS 트래커 같은 보조 MCU**는 대부분 idle이라 tickless + 저전력 타이머가 대기 전류를 정한다. 설계 문장: "armed 상태에서는 PM constraint로 깊은 수면 금지, disarmed에서는 tickless + STOP 허용". 그리고 480 MHz 코어의 SysTick tickless는 한 번에 34 ms밖에 못 자므로(§7.1), 대기 모드에서는 LPTIM/RTC로 tick을 옮긴다.

### 11.2 센서 허브 MCU — 타임스탬프는 tick이 아니라 하드웨어 카운터로

Linux SoC 옆의 센서 허브가 IMU 샘플에 타임스탬프를 찍는다면, tickless의 drift(§5, §8.6: 회당 µs, 짧게 자주 자면 1000 ppm 수준)를 타임스탬프에 쓰면 안 된다. 타임스탬프는 멈추지 않는 하드웨어 카운터(자유 실행 32비트 타이머 또는 RTC 서브초)에서 읽고, Linux 쪽과는 그 카운터로 동기화한다. 커널 tick은 "다음 샘플까지 자기" 같은 상대 시간에만 쓴다.

### 11.3 로봇 관절 모터 컨트롤러 — tickless가 거의 무의미한 경우

FOC 전류 루프 20 kHz는 타이머 ISR로 돌고 CPU가 쉴 틈이 거의 없다. 이런 MCU에서는 tickless를 켜도 깨는 횟수는 20 kHz ISR이 정한다. 이득이 없고, 대신 tick 비용(A7: tick당 1.5~4.5 µs)을 줄이려면 tick rate를 낮추는 쪽이 맞다. "모든 RTOS 제품에 tickless를 켜라"가 아니라 **"idle 비율이 높고 배터리인 제품"**의 기능이다.

### 11.4 SSD 펌웨어 — 같은 문제의 다른 이름

Don이 했던 APST/L1.2 진입 로직은 tickless + PM 정책과 구조가 같다: idle 시간 예측(호스트 명령 간격) → 진입 문턱(`configEXPECTED_IDLE_TIME_BEFORE_SLEEP`에 해당) → wake source → 복귀 후 타임스탬프 보정. 면접에서 "tickless를 써 봤나?"라는 질문에 "RTOS의 tickless는 안 써 봤지만, SSD에서 자율 전력 상태 전이를 구현하면서 진입 문턱, exit latency 예산, 복귀 후 시간 보정 문제를 다뤘다"로 연결할 수 있다.

## 13. 면접에서 이렇게 말한다

**Q.** What is tickless idle and why does it matter?

**A.** 할 일이 없을 때 주기 tick을 멈추고, 다음 타임아웃 시각에 one-shot 타이머를 걸고 자는 것이다. 깨어나면 지난 tick 수를 한꺼번에 더한다. 1 kHz tick은 idle에서도 1초에 1000번 깨우고, 깊은 수면에서는 SysTick이 멈춰 tick을 유지할 수도 없다. 내 측정(같은 부하, QEMU)에서 1초 기상 횟수가 1000 → 12로 줄었다.

> Tickless idle stops the periodic tick when nothing is runnable, programs a one-shot timer for the next timeout, sleeps, and on wake-up adds the elapsed ticks in one step. A 1 kHz tick wakes the CPU a thousand times a second even when idle, and in deep sleep the SysTick clock stops anyway. In my measurement on the same workload, wake-ups went from 1000 per second to 12.

**꼬리 질문**: "그럼 tick rate를 낮추면 되지 않나?" → 해상도를 잃고, 여전히 주기적으로 깬다. tickless는 해상도를 유지하면서 깨는 횟수만 줄인다.

**Q.** Walk me through what FreeRTOS does in vPortSuppressTicksAndSleep on Cortex-M.

**A.** 한 번 최대 tick을 24비트 한계(25 MHz면 671)로 자르고, `cpsid i`로 인터럽트 실행만 막는다(BASEPRI를 쓰면 WFI가 안 깬다). `eTaskConfirmSleepModeStatus()`로 그 사이 깨어난 태스크가 없는지 확인하고, SysTick을 멈춰 남은 몫을 읽고, "남은 몫 + (N−1) tick − 보정 상수"를 LOAD에 넣고 재시작해 WFI. 깨면 다시 멈추고 COUNTFLAG로 "타임아웃이었나 다른 IRQ였나"를 가려서 지난 완전한 tick 수를 계산하고, 남은 조각을 LOAD에 넣어 tick 격자를 맞춘 뒤 `vTaskStepTick()`.

> It clamps the idle time to what fits in the 24-bit SysTick, masks interrupts with PRIMASK rather than BASEPRI so that WFI can still wake up, and confirms with eTaskConfirmSleepModeStatus that nothing became ready. Then it stops SysTick, computes a reload of the remaining fraction plus N minus one tick periods minus a fixed compensation, restarts it and executes WFI. After waking it stops SysTick again, uses COUNTFLAG to tell a timeout from an early wake, computes the whole ticks that elapsed, reloads the leftover fraction to stay on the tick grid, and calls vTaskStepTick.

**Q.** Why does tickless mode cause clock drift, and how big is it?

**A.** 타이머를 멈췄다 켜는 구간을 고정 상수로 보정하거나(FreeRTOS 94카운트), 읽기와 재시작 사이를 세지 않기 때문이다(Zephyr). 오차는 수면 횟수에 비례한다. QEMU에서 FreeRTOS는 수면당 +2.2 µs, Zephyr는 −2.4 µs였다 — 2 ms마다 자면 약 1000 ppm, 하루 90초 수준이다. 그래서 달력 시간은 RTC에서 읽고, 시간 기준은 멈추지 않는 카운터로 잡는다.

> Because the timer is stopped and restarted with a fixed compensation, or because the few cycles between reading and restarting the counter are not counted. The error scales with the number of sleeps. On QEMU I measured plus 2.2 microseconds per sleep for FreeRTOS and minus 2.4 for Zephyr, which is about 1000 ppm if you sleep every two milliseconds. So I keep calendar time in the RTC and use a never-stopped counter as the timebase.

**Q.** Your MCU uses STOP mode. Can you still use the built-in FreeRTOS tickless implementation?

**A.** 아니다. STOP에서는 코어 클럭이 꺼져 SysTick이 멈추므로 깨우지도, 시간을 재지도 못한다. `configUSE_TICKLESS_IDLE = 2`로 두고, LPTIM이나 RTC 같은 저전력 도메인 타이머로 `portSUPPRESS_TICKS_AND_SLEEP`을 직접 구현한다. 보통 tick 자체도 그 타이머로 만들고(`vPortSetupTimerInterrupt()` 덮어쓰기), 멈추지 않는 카운터 값에서 tick 경계를 계산해서 보정 상수 없이 drift를 없앤다. 이 방식으로 구현해서 drift 0과, 타임아웃 없는 대기에서 이벤트 수만큼만 깨는 것을 확인했다.

> No. In STOP the core clock is gated, so SysTick stops and can neither wake the core nor measure the sleep. I set configUSE_TICKLESS_IDLE to 2 and implement portSUPPRESS_TICKS_AND_SLEEP on a low-power timer such as LPTIM or the RTC, usually generating the tick from it as well by overriding vPortSetupTimerInterrupt. Tick boundaries are computed from the free-running counter, so there is no compensation constant and no drift. I built one like that and measured zero drift and exactly one wake-up per external event when no task had a timeout.

**Q.** How is Zephyr's tickless different from FreeRTOS's?

**A.** FreeRTOS는 주기 tick이 기본이고 idle일 때만 멈춘다. Zephyr는 커널이 원래 이벤트 기반이라 타임아웃 리스트 맨 앞이 바뀔 때마다 `sys_clock_set_timeout()`으로 다음 시각에만 타이머를 건다. 그래서 바쁜 스레드가 돌 때도 tick 인터럽트가 없고, idle은 그냥 WFI다. SysTick은 멈추지 않고 사이클을 누적하며, tick rate는 해상도일 뿐이라 실칩 기본이 10 kHz다.

> FreeRTOS keeps a periodic tick and suppresses it only in the idle task. Zephyr is event-driven: whenever the head of the timeout list changes, sys_clock_set_timeout programs the next expiry, so even a busy thread sees no tick interrupts and idle is just WFI. The SysTick keeps running and cycles are accumulated, and the tick rate is only a resolution, which is why the default on real hardware with tickless is 10 kHz.

**Q.** We enabled tickless but the standby current did not change. How do you debug it?

**A.** 전류계 전에 깨는 횟수부터 센다 — tick ISR, idle 진입, WFI 횟수를 카운터로. 흔한 원인은 idle 우선순위의 백그라운드 태스크(예상 idle 0), 1 tick 지연 폴링(문턱 미달), 기본 구현이 얕은 WFI만 한다는 점(PRE_SLEEP 훅에서 STOP에 안 들어감), 잦은 외부 인터럽트, 꺼지지 않은 주변장치 클럭이다. 하나씩 고치며 횟수가 이벤트 수에 가까워지는지 본다.

> Before the current meter, I count wake-ups: tick interrupts, idle entries and WFI entries. Typical causes are a background task at idle priority, which makes the expected idle time zero, one-tick delay polling that never reaches the sleep threshold, the default implementation only doing a shallow WFI because the pre-sleep hook never enters STOP, a noisy interrupt source, and peripheral clocks left on. I fix them one by one until the wake-up count matches the real event rate.

**Q.** What is configEXPECTED_IDLE_TIME_BEFORE_SLEEP for, and how would you choose it?

**A.** 이 tick 수 이상 잘 수 있을 때만 tickless에 들어간다(기본 2, 2 미만은 컴파일 에러 — 포트가 첫 tick을 이미 진행 중인 tick으로 빼는 계산 때문이다). 깊은 수면의 진입·복귀 시간과 에너지를 회수할 수 있는 최소 수면 길이로 정한다. 측정해 보면 문턱 아래의 틈은 아예 WFI도 안 하므로, 짧은 틈이 많은 시스템은 idle hook에 얕은 WFI를 같이 둔다.

> It is the minimum number of idle ticks before the kernel enters tickless sleep. The default is two and anything below two is a compile error, because the port treats the first tick as already in progress. I choose it so that the sleep is long enough to pay back the entry and exit time and energy of the low-power mode. Gaps shorter than the threshold do not even execute WFI, so on systems with many short gaps I also put a plain WFI in the idle hook.

## 14. 직접 해보기

1. **개념** — Cortex-M 코어 클럭이 64 MHz이고 `configTICK_RATE_HZ = 1000`일 때 `ulTimerCountsForOneTick`, `xMaximumPossibleSuppressedTicks`를 구하라. 같은 칩에서 `configSYSTICK_CLOCK_HZ = 8000000`(외부 STCLK)으로 바꾸면?
   정답/힌트: 64000, 0xFFFFFF/64000 = 262. 외부 8 MHz면 8000카운트/tick, 2097 tick(2.1초)까지 — 대신 `ulStoppedTimerCompensation = 94/(64/8) = 11`로 줄어든다(port.c 공식).
2. **개념** — `taskENTER_CRITICAL()`로 tickless를 감싸면 왜 영원히 잘 수 있나? 어느 인터럽트도 깨울 수 없는 조건을 Armv7-M의 WFI 기상 규칙으로 설명하라.
   정답/힌트: BASEPRI가 `configMAX_SYSCALL_INTERRUPT_PRIORITY`면 그보다 낮은(숫자 큰) 인터럽트 — SysTick 포함 — 는 pending이어도 "선점할 수 있는 우선순위"가 아니라 WFI를 깨우지 못한다. PRIMASK는 기상 판정에서 무시된다.
3. **계산** — 데이터시트에서 칩 하나(예: STM32L4)의 STOP 2 전류, Run 전류, STOP 2 기상 시간을 찾아, 예제 1의 기상 횟수(1000/s vs 12/s)와 깨어 있는 비율로 평균 전류를 비교하라.
   정답/힌트: `I = I_stop × (1 − d) + I_run × d + n × I_run × t_wake`. n을 1000 → 12로 바꿨을 때 어느 항이 지배적인지 본다. 숫자는 반드시 데이터시트 값으로.
4. **코드** — 예제 4(`ex3.c`)를 mode 1로, `T0_US`를 500·1370·5000·20000으로 바꿔 돌리고 "조기 기상 1회당 drift"가 일정한지 확인하라. 일정하지 않다면 단계 ⑩-b의 어느 항 때문인가?
   정답/힌트: drift ÷ wfi를 표로. 기상 간격이 1 tick보다 짧으면 sleep에 못 들어가는 경우(문턱)가 섞인다 — wfi 횟수부터 확인.
5. **코드** — `lp_tick.c`의 분주를 /256(97656.25 Hz)으로 바꾸고(`LP_HZ`를 `configCPU_CLOCK_HZ / 256u`로, 제어 비트 2→3) 예제 4·6을 다시 돌려라. drift가 여전히 0인가? 해상도는 몇 µs가 되나?
   정답/힌트: 25 MHz/256는 정수가 아니라 `LP_HZ` 정수 나눗셈에서 오차가 생긴다 — 정수가 안 되는 클럭은 분자·분모를 따로 두고 계산해야 한다(이게 32.768 kHz 실칩의 상황). 해상도 10.24 µs.
6. **측정** — Zephyr z1 앱에 같은 우선순위의 바쁜 스레드 두 개를 추가하고 `CONFIG_TIMESLICING` y/n으로 1초 기상 횟수를 비교하라.
   정답/힌트: 슬라이스 20 ms면 1초에 약 50번 더 깬다(A7 예제 8의 200 ms에 10번과 같은 비율). FreeRTOS에서 같은 실험(idle 우선순위가 아닌 같은 우선순위 두 개)과도 비교해 보라 — FreeRTOS는 태스크가 돌 때 원래 tick이 1 kHz다.
7. **설계** — 드론 FC의 "disarmed 대기"에서만 tickless + STOP을 허용하고 "armed"에서는 금지하려면 FreeRTOS와 Zephyr에서 각각 어디에 무엇을 넣겠나?
   정답/힌트: FreeRTOS는 `configPRE_SUPPRESS_TICKS_AND_SLEEP_PROCESSING(x)`에서 armed면 `x = 0`(아예 안 잠) 또는 `configPRE_SLEEP_PROCESSING`에서 STOP 대신 WFI만. Zephyr는 armed 진입 시 `pm_policy_state_lock_get()`으로 깊은 상태 잠금(P2).

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| tick | 커널 시간 단위 | 주기 인터럽트로 세거나(주기 tick), 카운터에서 계산한다(tickless) |
| tickless idle | idle일 때 tick 억제 | FreeRTOS `configUSE_TICKLESS_IDLE` |
| tickless kernel | 주기 tick이 없는 커널 | Zephyr `CONFIG_TICKLESS_KERNEL`, 다음 타임아웃에만 타이머 |
| one-shot 타이머 | 한 번만 울리는 타이머 | 다음 깰 시각에 건다 |
| WFI | Wait For Interrupt | 인터럽트가 pending될 때까지 코어 정지. PRIMASK는 기상을 막지 않고 BASEPRI는 막는다 |
| PRIMASK / BASEPRI | Cortex-M 인터럽트 마스크 | PRIMASK = 전부(실행만), BASEPRI = 우선순위 이하 (B3) |
| SysTick | Cortex-M 내장 24비트 타이머 | 코어 클럭으로 돌아 깊은 수면에서 멈춘다 |
| COUNTFLAG | SysTick CTRL 비트 16 | 0을 지나면 1, 읽으면 지워진다(clear-on-read) |
| `xMaximumPossibleSuppressedTicks` | 한 번에 건너뛸 최대 tick | 0xFFFFFF / 카운트per tick (25 MHz, 1 kHz → 671) |
| `ulStoppedTimerCompensation` | 멈춤 보정 | `portMISSED_COUNTS_FACTOR`(94) / 클럭비, 고정 상수 |
| `vTaskStepTick()` | tick 보정 함수 | 건너뛴 tick을 더하고, 정확히 깰 시각이면 1을 `xPendedTicks`로 |
| `eTaskConfirmSleepModeStatus()` | 잘지 최종 확인 | eAbortSleep / eStandardSleep / eNoTasksWaitingTimeout |
| `configEXPECTED_IDLE_TIME_BEFORE_SLEEP` | 수면 문턱 | 이 tick 이상 잘 수 있을 때만 (기본 2) |
| `sys_clock_set_timeout()` | Zephyr 타이머 재설정 | 다음 타임아웃을 tick 경계로 올려 SysTick LOAD에 |
| `sys_clock_announce()` | Zephyr 시간 알림 | 지난 tick을 커널에 알리고 만료 처리 |
| LPTIM | Low-Power Timer | 32.768 kHz 등 저전력 클럭으로 STOP에서도 동작 |
| RTC | Real-Time Clock | 가장 깊은 모드에서도 사는 시계·깨우기 타이머 |
| LSE | Low-Speed External | 32.768 kHz 크리스털 클럭 |
| drift | 시계 어긋남 | 커널 시간 − 실제 시간, ppm으로 표시 |
| ppm | parts per million | 1000 ppm = 0.1% = 하루 86.4초 |
| wake latency / exit latency | 기상 지연 | 수면 → 코드 실행까지 걸리는 시간 |
| STOP 모드 | 깊은 수면(STM32 용어) | 코어 클럭 정지, RAM 유지, µA급 |

## 16. 요약 & 체크리스트

1 kHz tick은 할 일이 없어도 1초에 1000번 CPU를 깨우고, 깊은 수면에서는 SysTick이 멈춰서 유지할 수도 없다. tickless는 "다음 타임아웃까지 one-shot으로 자고, 깨서 지난 tick을 한꺼번에 더한다". FreeRTOS(`configUSE_TICKLESS_IDLE=1`)는 idle 태스크에서 `prvGetExpectedIdleTime()` → `vTaskSuspendAll()` → port.c `vPortSuppressTicksAndSleep()`으로 SysTick을 멈추고 긴 LOAD를 걸어 WFI한 뒤, COUNTFLAG로 깬 이유를 가려 `vTaskStepTick()`으로 보정한다. 같은 부하에서 기상은 1000 → 12/s로 줄었지만, 24비트 한계로 한 번에 671 ms까지만 자고(480 MHz면 34 ms), 고정 보정 상수(94) 때문에 수면당 +2.2 µs씩 시계가 앞섰다(QEMU). 저전력 타이머 기반 mode 2(이 노트의 DUALTIMER 구현)는 멈추지 않는 카운터에서 tick 경계를 계산해서 drift 0, 2초 한 번에 수면, 무한 대기에서 이벤트 수만큼만 기상을 보였다. Zephyr는 원래 tickless라 타임아웃이 바뀔 때마다 `sys_clock_set_timeout()`으로 다음 시각만 걸고 idle은 WFI 하나다 — 기상 15/s, 수면당 −2.4 µs(재설정 3회 × 0.82 µs). 함정은 drift, 기상 지연, 디버거, tick에 기대는 코드·주변장치, time slicing이다.

- [ ] 1 kHz tick이 배터리에 왜 나쁜지 "횟수"와 "깊은 수면에서 SysTick 정지" 두 가지로 설명한다
- [ ] `configUSE_TICKLESS_IDLE` 0 / 1 / 2의 차이와, 2가 왜 "내 구현"인지 소스로 말한다
- [ ] 25 MHz · 1 kHz에서 671 tick 한계를 계산하고, 480 MHz에서는 몇 ms인지 안다
- [ ] port.c가 `taskENTER_CRITICAL()` 대신 `cpsid i`를 쓰는 이유(WFI 기상 규칙)를 설명한다
- [ ] COUNTFLAG를 읽지 않고 SysTick을 멈추는 이유(clear-on-read)를 안다
- [ ] 계획대로 깬 경우 `N − 1`, 일찍 깬 경우 완전한 tick 수만 더하는 이유를 그림으로 그린다
- [ ] `vTaskStepTick()`이 마지막 tick을 `xPendedTicks`로 미루는 이유와 tick hook이 안 불리는 것을 안다
- [ ] tickless drift의 출처 세 가지(멈춤 보정, 못 센 재설정 구간, 클럭 비율)를 말하고 측정법을 안다
- [ ] `eNoTasksWaitingTimeout`을 mode 1이 활용하지 않는다는 것과 mode 2에서 어떻게 쓰는지 안다
- [ ] LPTIM/RTC로 tick을 만드는 설계(멈추지 않는 카운터 + compare, 절대 카운트로 경계 계산)를 설명한다
- [ ] Zephyr `sys_clock_set_timeout()`의 MAX_TICKS · MIN_DELAY · tick 경계 올림을 설명한다
- [ ] "tickless 켰는데 전류 그대로"를 기상 횟수부터 디버깅하는 순서를 말한다
