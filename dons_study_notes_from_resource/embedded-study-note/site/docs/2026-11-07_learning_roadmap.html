학습 로드맵 추천 (2026-11-07)

68트랙 · 2,121개 아이템을 전부 푸는 게 목표가 아니다. 아이템 하나가 약 45분이니 전부 풀면 1,600시간이다. 이 로드맵은 공통 코어 → 목표 직무 갈래 하나 → 면접 마무리 순서로, 반년 안에 "면접에서 직접 짜고 설명할 수 있는" 범위를 고른다.

기준: 펌웨어 · 실리콘 검증 · AI 가속기/로봇 칩 쪽 면접 (Rivian, Apple, NVIDIA, Anduril, Tesla …). C · NAND/FTL · NVMe는 이미 강점이라 반복하지 않고, 약한 쪽(C++, 아키텍처, RTOS 깊이, 칩 검증)에 시간을 쓴다.

속도 가정: 하루 3개(≈ 2시간 15분) × 주 5일 = 주 15개. 레슨 작성도 이 순서대로 진행하면, 다음에 풀 레슨이 항상 준비돼 있다.

Advanced는 기본 경로에 넣지 않았다. 갈래 트랙의 Advanced는 포트폴리오로 쓸 것만 2–3개 골라서 푼다.

1. 코어 I — 언어와 하드웨어 감각 (약 7주)#

지금 위치에서 바로 이어지는 단계. Mid로 올라가는 C/DS/CPP와, 아직 손대지 않은 하드웨어 기초 트랙의 Basic을 번갈아 푼다. 같은 트랙만 연속으로 풀면 지루해지고 기억도 덜 남는다.

주하루 3개 조합 (예)이유
1–2C-M + ARCH-B + DS-MC-M의 UB · 정렬 · 메모리 맵이 ARCH-B의 캐시 · 버스와 바로 연결된다
3–4CPP-M + ARM-B + ALGO-BCPP-M의 템플릿 · constexpr 결과를 ARM-B에서 어셈블리로 확인
5–7남은 C-M/DS-M/CPP-M + TOOL-BTOOL-B(링커 · gdb · 맵 파일)는 다음 단계 BM의 준비물
  • ALGO-B는 코딩 테스트용이다. 전화 면접 일정이 잡히면 앞당기고, 아니면 하루 1개로 줄여도 된다.
  • ARCH-B가 이 단계의 핵심이다. 칩/검증 쪽으로 가려면 캐시 · 파이프라인 · 버스를 그림으로 설명할 수 있어야 한다.

2. 코어 II — 펌웨어 본체 (약 8주)#

임베디드 면접의 "직접 짜 봐"가 대부분 여기서 나온다.

순서트랙 · 레벨포인트
1BM-B → BM-Mreset handler · 메모리 맵 · 클럭 · GPIO/UART/타이머/NVIC를 레지스터로 직접. 이후 모든 트랙의 기반
2COMM-B → COMM-MUART/SPI/I2C 비트 수준 · CRC · 프레이밍(SLIP/COBS) · 명령 파서. RF 통합 경험과 바로 연결
3RTOS-B → RTOS-M스케줄러 · 우선순위 역전 · 큐. 면접 단골
4OS-B · MEM-B가상 메모리 · 페이지 테이블 · DRAM 기본. 리눅스/칩 갈래의 준비
5TEST-B단위 테스트 · HIL 기본. 검증 직무라면 필수

BM과 COMM은 같이 푸는 게 좋다. BM에서 만든 startup 위에 COMM의 드라이버를 올리면 하나의 작은 펌웨어가 된다.

3. 갈래 — 목표 직무 하나 고르기#

코어 II가 끝날 즈음 지원 중인 회사에 맞춰 하나만 고른다. 갈래끼리 겹치는 트랙(MEM, SOCX, LPERF 등)은 두 번째 갈래로 넘어갈 때 다시 풀지 않는다.

A. 펌웨어 · 실리콘 검증 (추천 1순위) — 136개, 약 9주#

Rivian Silicon & Sensing, Apple/NVIDIA silicon validation 같은 역할. NVMe/SSD 경력이 가장 직접적으로 살아나는 갈래.

순서트랙 · 레벨
1PCIE-B/M — LTSSM · config space · NVMe 큐. 이미 아는 걸 코드로 증명
2SIV-B/M — 테스트 플랜 · 레지스터 스윕 · 실패 분류
3HWLAB-B/M — 보드 브링업 · 오실로스코프/로직 분석기 판독
4MEM-M · TEST-M — 메모리 컨트롤러 · 캐시 일관성 · 커버리지 · 신뢰성
5ELX-B · LPERF-B · SOCX-B — 리눅스 위에서 검증하는 환경, 인터커넥트 기초

B. AI 가속기 · 칩 — 148개, 약 10주#

NVIDIA, AI 칩 스타트업의 펌웨어/아키텍처 역할. 가장 양이 많고 ARCH Mid/Advanced가 필요하다.

순서트랙 · 레벨
1ARCH-M/A — 캐시 일관성 · 메모리 순서 · 성능 모델
2AIPERF-B/M · EML-B/M — roofline · 양자화 · int8 GEMM
3NPU-B/M — systolic array · DMA 스케줄링 · 컴파일러 인터페이스
4SOCX-B/M · RISCV-B · RTLDV-B — 칩 안쪽을 읽을 수 있을 만큼
5GPGPU-B — GPU 쪽 질문 대비

C. 로봇 · 방산 · 자율 시스템 — 122개, 약 8주#

Anduril, Tesla Optimus, 드론 회사. 제어 · 센서 · 실시간성 질문이 중심.

순서트랙 · 레벨
1RCTL-B/M — PID · 칼만 · 상태 추정
2SENS-B/M · DSP-B/M — 센서 융합 · 고정소수점 필터
3RTOS-A — 응답 시간 분석 · 지터 (실시간 보장을 숫자로)
4DRONE-B · AUTON-B · AERO-B — 도메인 어휘와 대표 문제
5ROS-B · RUST-B — 요즘 공고에 자주 붙는 스택

D. 임베디드 리눅스 · 플랫폼 · 데이터센터 — 95개, 약 6–7주#

BSP, BMC, SmartNIC, 서버 플랫폼 역할. EmbeddedLinux 노트(A–S)를 이미 끝냈으니 가장 빨리 끝난다.

순서트랙 · 레벨
1ELX-B/M — 디바이스 트리 · 드라이버 · 부팅 (기존 노트와 연결)
2PLAT-B/M — 펌웨어 업데이트 · 전원 · 부팅 체인
3LPERF-M · NET-B — perf/eBPF, 네트워크 스택
4VIRT-B · BMC-B — 서버 쪽 역할이라면

4. 마무리 — 시스템 설계와 포트폴리오 (약 3주)#

  • SYSD-B/M: 설계 면접 형식으로만 푼다. 구현이 겹치는 아이템은 이미 갈래에서 짠 결과물을 가져와 설명만 한다 (중복 검토 문서 참고).
  • CAP 전체: 갈래에서 만든 것 2–3개를 하나의 포트폴리오 저장소로 묶고, 면접용 설명 스크립트를 쓴다.

면접 일정이 잡히면#

로드맵보다 면접이 우선이다. 일정이 잡히면 2–3주 동안 아래처럼 바꾼다.

  1. 그 회사 갈래의 Basic만 앞으로 당긴다 (Mid는 면접 뒤로).
  2. ALGO-B · C-M을 하루 1개씩 유지한다 (코딩 라운드 대비).
  3. 해당 트랙 레슨의 면접 Q&A 섹션만 따로 훑는 날을 하루 둔다.

예: Rivian 온사이트 → 갈래 A의 PCIE-B · SIV-B · HWLAB-B를 먼저, C-M의 비트 연산 아이템을 매일 1개.

진행 관리#

  • 허브의 문제 브라우저에서 트랙 · 레벨 필터로 이번 주 범위만 띄운다. 레슨의 "완료 표시"는 이 브라우저에 저장된다.
  • 커리큘럼 맵에서 초록 네모가 늘어나는 게 진행도다. 단계가 끝날 때마다 이 문서의 표에 ✅를 붙인다.
  • 레슨이 없는 아이템(회색 네모)은 이 로드맵 순서대로 레슨을 만들어 달라고 하면 된다.
