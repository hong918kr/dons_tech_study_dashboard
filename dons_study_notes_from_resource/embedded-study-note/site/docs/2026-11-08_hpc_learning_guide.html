HPC 학습 가이드 (2026-11-08)

HPC(High Performance Computing, 고성능 컴퓨팅)는 "같은 하드웨어에서 더 빠르게, 더 많은 코어로 더 크게"를 숫자로 증명하는 분야다. AI 학습 클러스터, 과학 시뮬레이션, 칩 검증 팜이 모두 같은 원리 위에서 돈다.

이번에 HPC · 병렬 컴퓨팅 트랙(HPC, 30개)을 새로 만들었다. 기존 트랙에 흩어져 있던 roofline · SIMD · GEMM · GPU · all-reduce · AI 병렬화 아이템과 합쳐 8개 층으로 묶었다. 새 트랙은 OpenMP(공유 메모리)와 MPI(분산 메모리)로 stencil · SpMV · N-body · FFT 같은 대표 문제를 직접 병렬화하는 쪽을 맡는다.

준비물: brew install libomp open-mpi 한 번이면 HPC 트랙 전체가 Mac에서 된다. OpenMP는 clang -Xpreprocessor -fopenmp -I$(brew --prefix libomp)/include -L$(brew --prefix libomp)/lib -lomp, MPI는 mpicc x.c && mpirun -np 4 ./a.out (노트북 한 대에서 프로세스 4개로 분산 메모리를 흉내 낸다).

쓰는 법

  • 층을 위에서부터 내려간다. 층마다 면접 체크를 말로 설명할 수 있으면 다음 층으로 간다.
  • ⭐ 표시 20개가 핵심 경로다. 시간이 없으면 ⭐만 순서대로 푼다.
  • 🆕 표시는 이 가이드를 만들며 새로 추가한 아이템이다 (30개).
  • 아이템 ID를 누르면 트랙 표의 그 줄로 간다. 레슨이 써졌는지(학습가능/준비중)는 그 표에서 실시간으로 보인다.
  • env가 linux면 Lima VM elinux, qemu면 QEMU, gpu면 NVIDIA GPU가 필요하다. 나머지는 Mac에서 바로 된다.

1. 측정과 성능 모델#

HPC의 모든 답은 "그래서 몇 배 빨라졌고, 왜 거기서 멈췄나"다. 숫자를 믿을 수 있게 재는 법과, 한계를 미리 계산하는 모델부터 익힌다.

아이템레벨 · env제목확인할 것 (아이템 목표)
HPC-B01 ⭐ 🆕Basic · mac성능 측정 하네스: 반복·워밍업·통계와 GFLOP/s·GB/sHPC 실험의 기본기인 '믿을 수 있는 숫자'를 만드는 측정 하네스를 갖춘다.
HPC-B02 ⭐ 🆕Basic · macStrong vs Weak Scaling: Amdahl·Gustafson 실측과 Karp-Flatt스레드 수를 늘릴 때의 확장성을 두 가지 방식으로 측정하고 직렬 비율을 역추정한다.
ARCH-A11 ⭐Adv · mac성능 모델: Amdahl과 Roofline연산 강도와 메모리 대역폭으로 커널 성능 상한을 추정한다
MEM-B11Basic · mac메모리 대역폭 측정: STREAM Copy/Scale/Add/Triad지속 대역폭과 이론 피크의 차이, 스레드 수의 영향을 측정한다.
AIPERF-B04Basic · macRoofline 대역폭 천장 정하기: STREAM 결과 해석측정한 지속 대역폭을 roofline 천장과 LLM 토큰 속도 상한으로 바꾸는 법을 익힌다
AIPERF-B06Basic · macRoofline 모델 구축과 커널 배치피크 연산과 대역폭으로 roofline을 그리고 커널의 위치로 병목을 판정한다
AIPERF-M07Mid · mac계층적 Roofline: L1/L2/DRAM캐시 계층별 대역폭 천장을 그려 타일링 최적화의 효과를 해석한다
HPC-M11 🆕Mid · mac병렬 프로그램 프로파일링: 타임라인 계측과 불균형 지표PMU 없이도 병렬 프로그램의 병목(불균형·동기화·통신)을 숫자로 찾는다.

면접 체크 — 말로 설명할 수 있으면 통과

  • ☐ strong scaling과 weak scaling의 차이, 각각 Amdahl·Gustafson 중 무엇과 맞나
  • ☐ 8코어에서 speedup이 5배면 직렬 비율은 대략 얼마인가 (Karp-Flatt)
  • ☐ roofline의 두 천장과 연산 강도(FLOP/byte)로 커널이 메모리/연산 바운드인지 판정하기
  • ☐ 벤치마크에서 워밍업·반복·중앙값이 필요한 이유, 컴파일러가 루프를 지우는 문제

병렬화 전에 코어 하나를 제대로 쓰는 단계다. 코어 하나가 느리면 코어 100개도 느리다.

면접 체크 — 말로 설명할 수 있으면 통과

  • ☐ 행렬곱에서 ijk와 ikj의 속도 차이를 캐시 라인으로 설명
  • ☐ 타일 크기는 어떻게 정하나 (L1/L2 용량, 세 타일이 동시에 들어가야 함)
  • ☐ AoS vs SoA — 어느 쪽이 벡터화에 유리하고 왜
  • ☐ 컴파일러가 루프를 벡터화하지 못하는 대표 이유 (aliasing, 루프 의존성, 분기)

3. 공유 메모리 병렬 — OpenMP#

노드 하나 안의 여러 코어를 쓰는 표준 방법이다. 레이스와 false sharing은 동시성 가이드에서 먼저 익혀 두면 좋다.

아이템레벨 · env제목확인할 것 (아이템 목표)

HPC-B04 ⭐ 🆕Basic · macOpenMP 스케줄링: static·dynamic·guided와 부하 불균형반복마다 비용이 다른 루프에서 스케줄 정책과 chunk 크기가 성능에 주는 영향을 설명한다.
HPC-B05 ⭐ 🆕Basic · macWork-Span 모델: 병렬 reduction·prefix sum과 Brent 정리병렬 알고리즘을 work·span·병렬도로 분석하고 실제 속도 향상의 상한을 예측한다.
HPC-B07 🆕Basic · mac병렬 reduction의 비결정성: 스레드 수와 결과가 바뀌는 이유부동소수점 덧셈의 비결합성이 병렬 결과의 재현성을 깨는 원리와 해결책을 안다.
HPC-M02 🆕Mid · mac이기종 코어 스케줄링: Apple Silicon P/E 코어와 부하 분산성능이 다른 코어가 섞인 머신에서 정적 분할이 깨지는 이유와 대응을 측정으로 보인다.
OS-A05Adv · macwork-stealing 스레드 풀: Chase-Lev deque로드 밸런싱을 위한 작업 훔치기 스케줄러와 lock-free deque의 메모리 오더링을 구현한다(false sharing 측정은 see:MEM)
MEM-M09Mid · macNUMA: 지역성, first-touch, 원격 접근 비용NUMA 시스템에서 메모리 배치가 지연·대역폭에 주는 영향을 모델링한다.

면접 체크 — 말로 설명할 수 있으면 통과

  • ☐ #pragma omp parallel for reduction(+:s)가 내부적으로 하는 일
  • ☐ static vs dynamic 스케줄은 언제 어느 쪽이 이기나
  • ☐ work W, span S일 때 P코어 시간의 상한 (Brent 정리)
  • ☐ 병렬 합 결과가 스레드 수마다 마지막 자리까지 달라지는 이유와 해결책
  • ☐ P코어/E코어가 섞인 머신에서 static 분할이 느린 이유

4. 대표 커널 — HPC 문제 은행#

HPC 면접과 과제는 거의 이 커널들의 변형이다. 각 커널이 메모리 바운드인지, 연산 바운드인지, 불규칙한지를 먼저 말할 수 있어야 한다.
