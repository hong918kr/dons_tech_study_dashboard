LA 캡처 타이밍 컴플라이언스: SPI·UART vs 데이터시트

Mid⏱ 80분env: mac#logic-analyzer#timing#spi#uart#compliance#see:COMMupdated 2026-11-08
목표 디코드를 넘어 캡처에서 타이밍 파라미터를 측정하고 데이터시트 한계와 비교한다.
과제 COMM-A10 디코더 위에 SPI tCSS/tCSH/tSU/tH·SCLK 주파수·duty와 UART 실제 baud(비트 폭 히스토그램)·inter-byte gap 측정을 추가해 데이터시트 min/max 표(JSON)와 비교한 위반 리포트를 내고, 샘플링 주기에 의한 측정 불확도(±1/fs)를 pass/fail 판정에 반영한다(see:COMM-A10).
내 상태

학습 목표#

  • 디코드가 끝난 LA 캡처에서 데이터시트 타이밍 파라미터를 직접 잰다: SPI tCSS / tCSH / tCSD / tSU / tH / tCH / tCL, SCLK 평균 주파수와 duty, UART 비트 폭 히스토그램 → 실제 baud, inter-byte gap.
  • 각 측정값에 샘플링 불확도 U 를 붙인다: 에지 하나는 [0, Ts) 늦게 보이므로 간격은 ±Ts, 채널이 다르면 + skew, 긴 간격은 + 타임베이스 ppm, span 평균은 ±Ts/N.
  • 데이터시트 min/max 표(JSON)와 비교해 PASS / FAIL / UNRESOLVED 가드밴드 판정을 내리고, 순진한(naive) 비교가 거짓 PASS 를 내는 비율을 실험으로 보인다.
  • "평균을 내면 정밀해진다"가 언제 참이고(span 기반 주파수, 비동기 샘플링) 언제 거짓인지(정수비 샘플링의 duty, min 스펙) 설명한다.
  • 보드 두 장의 캡처로 하드웨어/펌웨어 엔지니어가 바로 움직일 수 있는 한 줄 위반 리포트와 원인 힌트(공통 클럭 비율 → 크리스털)를 만든다.

1. 문제#

LA 로 "디코드가 잘 된다"는 것은 타이밍이 스펙 안이라는 증거가 아니다 — Rivian/NVIDIA/Apple 보드 검증 면접은 "그 setup time 을 LA 로 몇 ns 정밀도로 쟀고, 그래서 PASS 라고 말할 수 있나?"를 묻는다.

상황: EVT2 센서 허브 보드. MCU U1 이 SPI ADC U7(가상 부품, mode 0)을 읽고, UART TX 로 BLE 모듈 U9 에 AT 명령을 보낸다 (115200 8N1). 펌웨어 클럭 설계는 HSE 24 MHz → PCLK 76.8 MHz → SPI ÷8 = 9.6 MHz, UART BRR=667 → 115142 baud (−0.05%). 보드 A 는 "BLE 가 가끔 응답 없음", "ADC 값이 가끔 튐" 이 보고됐고, 보드 B 는 수정본이다. LA 캡처(.sr)와 데이터시트 표(evt2_limits.json)가 주어진다.

데이터시트 숫자는 이 계열 부품의 대표값 — 데이터시트/스펙 확인 필요. 테스트는 이 레슨의 JSON 과 자기 일관적이다.

Part A — 디코더 위에 타이밍 측정#

.sr 로더(HWLAB-B07 축약)와 SPI mode 0 / UART 8N1 디코더(COMM-A10 식 디코더를 축약)는 주어진다. 작성할 것:

  • spi_measure(cap) — CS_N 창마다 tCSS, tCSH, tCH, tCL, MOSI 변화마다 tSU, tH, 프레임 사이 tCSD (ns 목록), span 평균 fSCLK (MHz), duty (%).
  • uart_measure(cap) — run 폭 히스토그램 → T0 → 프레임 디코드 → 프레임 안 에지 span 으로 Tbit → baud, baud_err (%), gap (공칭 문자 시간 단위).

정답 기준은 샘플링하지 않은 같은 파형(G.ideal(wave))이다: 100 MS/s 캡처의 모든 인스턴스가 진짜 값과 Ts 이내여야 한다.

Part B — 불확도와 가드밴드 판정#

  • meas_uncertainty(name, m, ts_ps, la) — 파라미터 종류별 U (같은 채널 / 다른 채널 / span 평균 / duty / baud / gap).
  • guard_verdict(vmin, vmax, u, lim) — PASS/FAIL/UNRESOLVED. u=0 이면 순진한 비교.
  • compliance(meas, params, ts_ps, la) — 데이터시트 표 순서로 행을 만든다. 인스턴스가 없으면 NO DATA.
  • 실험: (1) 진짜 tCSS 17 / 23 ns vs min 20 ns 를 100~1000 MS/s 무작위 위상 100회 — 순진한 비교의 오판률 vs 가드밴드 (2) span 평균 주파수 vs 한 주기 (3) 정수비(coherent) 샘플링의 duty 편향 (4) UART +1.5% 를 1 MS/s 와 10 MS/s 로.

Part C — EVT2 보드 위반 리포트#

board_report(label, spi_cap, uart_cap, spec) → (overall, lines, oneline). 보드 A(100 MS/s SPI + 10 MS/s UART)는 FAIL 과 원인 힌트, 보드 B 100 MS/s 는 UNRESOLVED + 재캡처 제안, 보드 B 500 MS/s 는 PASS 여야 한다. MOSI 가 한 번도 안 바뀌는 캡처는 tSU/tH 가 NO DATA → PASS 가 아니다.

2. Problem (English)#

Timing compliance from logic-analyzer captures.

A capture is {"names", "tr": {ch: [(t_ps, level), ...]}, "ts_ps"} (first entry = initial level). A datasheet table gives min/max limits (evt2_limits.json). Using only the Python 3 standard library:

  1. spi_measure(cap) (mode 0): per CS_N-low window measure tCSS (CS_N fall → first SCLK rise), tCSH (last SCLK rise → CS_N rise), tCH/tCL, and for every in-window MOSI change tSU (→ next rise) and tH (previous rise →); tCSD between frames; mean SCLK frequency from Σ(n_i−1)/Σ(last_rise−first_rise) and duty mean(tCH)/T.
  2. uart_measure(cap): estimate the bit time from a run-width histogram, decode 8N1 frames, refine Tbit = Σ span / Σ n_bits over in-frame edges, report baud error vs 115200 and inter-byte idle gaps in character times.
  3. Each sampled edge is late by [0, Ts). Attach an uncertainty U (±Ts per interval, + channel skew if two channels,
  • timebase ppm, F·Ts/Σcycles for span averages) and return PASS only if the whole interval [v−U, v+U] meets the limit, FAIL only if it is entirely outside, else UNRESOLVED.
  1. Produce a one-line actionable report per board.

Example: EVT2-A FAIL: fSCLK=10.407+-0.048MHz, tCSH=0.000+-11.001ns, baud_err=8.281+-0.155%, gap=2.074+-0.003char | ...

4. 힌트#

힌트 1 — CS_N 창과 bisect

cs_windows(cap) 가 [(fall, rise)] 를 준다. SCLK rising 시각 리스트 rises 에서 rises[bisect_left(rises, lo):bisect_right(rises, hi)] 가 창 안의 rising 이다. hi 와 같은 샘플의 rising 도 넣는다 — 순서를 모르니 tCSH = 0 ± U 가 정직한 값이다. MOSI 변화 t 마다 j = bisect_left(r, t): r[j] - t 가 tSU, t - r[j-1] 이 tH.

힌트 2 — 주파수는 주기 하나가 아니라 span 으로

한 주기 측정은 ±Ts (100 MS/s 에서 104 ns 주기는 100 또는 110 ns 로만 보인다). 프레임 안 첫 rising ~ 마지막 rising 의 span 도 ±Ts 지만 23주기로 나누면 ±0.43 ns. 프레임 F 개면 T = Σspan / Σ(n−1), 오차 한계 F·Ts / Σ(n−1).

힌트 3 — UART 히스토그램은 출발점, 정밀값은 span

1비트 클러스터 = 가장 짧은 run 근처(w < 1.5·min)의 중앙값 → T_init. 모든 run 을 n = round(w/T_init) 로 묶어 히스토그램. stop+idle 이 섞인 run 은 비정수 폭이라 T0 를 조금 끌고 간다. 그래서 디코드 후 프레임 안(start falling ~ stop 중앙 전) 에지의 span 만 써서 Tbit = Σspan/Σn 으로 다시 맞춘다 (두 번 반복).

힌트 4 — 가드밴드 판정의 비대칭

min 한계: vmin + u < min 이면 FAIL (진짜도 반드시 미달), vmin − u < min 이면 UNRESOLVED. max 한계는 거울상. duty 처럼 둘 다 있으면 두 쪽 모두 보고 FAIL 이 UNRESOLVED 보다 우선. u = 0 을 넣으면 그대로 순진한 비교가 된다 — 같은 함수로 비교할 수 있다.

힌트 5 — 원인 힌트는 비율 두 개로

r_spi = fSCLK/설계값, r_uart = baud/설계값. 둘 다 1% 넘게 틀렸고 서로 0.3% 안이면 같은 클럭 트리가 틀린 것이다. HSE_VALUE × r 을 표준 크리스털 목록과 비교한다.

ideal(샘플링 없음) 측정과 캡처 측정 (solution 출력):

읽는 법:

  • tSU 최악값 21 ns 는 첫 비트다. 나머지 비트는 MOSI 가 falling 뒤 3 ns 에 바뀌어 setup 이 T·0.52 − 3 ≈ 51 ns 인데, 첫 비트는 CS_N ↓ + 5 ns 에 세팅되고 첫 rising 은 tCSS = 26 ns 뒤 → 21 ns. 실제 보드에서도 "첫 비트 setup 은 tCSS 가 결정한다"가 흔하다.
  • 100 MS/s 의 tCH 는 50 또는 60 ns 로만 나온다 (진짜 49.5~50.6). 각 인스턴스 오차는 테스트로 확인한 대로 모두 < Ts.
  • tSU/tH 는 커버리지가 있다: 0x00 같은 바이트는 MOSI 가 안 바뀌어 측정 인스턴스가 없다. 그래서 검증용 펌웨어는 0x55/0xAA·walking-1 패턴을 보낸다 (Part C 의 NO DATA 테스트).

UART baud 를 왜 이렇게 재나. run 폭 하나의 오차는 ±Ts — 10 MS/s 에서 1비트(8 µs)의 ±1.25%. 그러나 한 프레임 안의 에지는 모두 같은 비트 격자 위에 있으므로 start ↓ 부터 마지막 프레임 안 에지까지의 span 은 오차 ±Ts 하나로 n 비트를 덮는다. 프레임 사이 idle 은 격자를 끊으므로(gap 은 임의 길이) span 은 프레임 안에서만 잇는다. 실제 출력:

보드 A 의 실제 baud 는 124 740 (+8.28%). 같은 캡처를 공칭 115200 으로 디코드하면 쓰레기 — U9 이 받는 것이 바로 이것이다. 8N1 수신기는 start ↓ 에서 맞춘 뒤 stop 중앙(9.5 비트)까지 동기 없이 가므로 누적 어긋남 9.5·e 가 반 비트를 넘으면 깨진다: 양쪽 오차의 합 |e| < 0.5/9.5 ≈ 5.3% 가 이론 한계이고, 수신기 16× 오버샘플링의 샘플 불확도와 느린 에지를 빼면 실제 여유는 그보다 작다. 그래서 흔한 설계 규칙이 "각 측 ±2%" 다 (이 레슨 JSON 의 한계, 대표값). gap 은 다음 start − (start + 10·Tbit) 를 공칭 문자 시간(86.8 µs)으로 나눈 값.

Part B — 불확도 U 는 어디서 오나#

샘플러 하나가 모든 채널을 같은 시각에 찍는 timing-mode LA 에서 에지 t 는 t_obs = t + δ, δ ∈ [0, Ts) (HWLAB-B07). 그러면:

이 표에 없는 항목도 말할 수 있어야 한다: ① LA 임계값 vs 데이터시트 기준 레벨 — 데이터시트 타이밍은 보통 VIH/VIL 또는 50% 교차 기준인데 LA 는 비교기 하나의 임계값에서 잰다. 에지가 느리면 (예: tr 5 ns) 기준 레벨 차이만큼 각 에지가 수 ns 이동한다 → 스코프로 그 에지의 crossing 을 IEEE-181 방식으로 재야 한다 (HWLAB-B04). ② 프로브 위치 — 입력 타이밍은 수신 부품(U7) 핀에서 잰다. ③ 합성 LA 는 skew 0 이지만 예산에는 사양값 1 ns 를 넣었다 (보수적).

최악값에도 U 를 그대로 쓸 수 있는 이유. 인스턴스마다 |m_i − x_i| ≤ U 이면 |min m_i − min x_i| ≤ U (min 은 각 좌표 오차의 최대를 넘지 않는다). 그래서 "측정 최악값 ± U 안에 진짜 최악값" — 테스트 truth inside [worst +- U] 가 모든 파라미터에서 확인한다.

실험 1 — 순진한 비교는 얼마나 자주 틀리나 (진짜 tCSS 17 ns = 위반, 23 ns = 통과, 한계 ≥ 20 ns, 위상 무작위 100회, 실제 출력):

  • 100 MS/s 에서 진짜 17 ns(위반)를 순진한 비교는 절반을 PASS 라고 했다 (측정값이 10 또는 20 ns 로 양자화, 20 ≥ 20). 가드밴드는 한 번도 틀리지 않았다 — 대신 "모른다"고 했다.
  • 23 ns 는 마진이 3 ns 라 U = Ts + 1 ns 가 3 ns 보다 작아지는 1 GS/s 에서야 전부 결정된다. 500 MS/s(U=3)는 98% 가 경계에 걸렸다. 필요한 샘플링률은 마진이 정한다 (연습 2: 반드시 결정하려면 Ts < M/2 − skew).

실험 2 — 주파수는 span 으로. 보드 A 100 MS/s:

한 주기로 보면 11.1 MHz (+6.8%) 같은 엉뚱한 값이 나오지만 span 평균은 10.407 ± 0.048 MHz (진짜 10.400) — 10 MHz 한계를 확정적으로 넘는다. 단, 평균이 스펙 안이어도 개별 사이클이 짧을 수 있다(지터, 클럭 게이팅, spread spectrum). 그 경우는 tCH/tCL (사이클별, ±Ts)이 잡는다.

실험 3 — 평균이 거짓말할 때 (coherent sampling). duty 48%, 지터 0, 한 프레임 96 클럭, 위상 8개:

10 MHz 와 100 MS/s 는 정수비라 모든 에지가 샘플 격자에 대해 같은 위상에 놓인다 → 96번 평균해도 같은 오차를 96번 더할 뿐(+2 % 또는 −8 %). 9.6 MHz 는 주기가 10.417 샘플이라 위상이 12 사이클마다 격자를 한 바퀴 돌며 오차가 상쇄(dither)된다. 그래서 U 는 평균 개수로 나누지 않는다 — 비동기라는 보장이 없으면 최악 한계 Ts 를 그대로 쓴다. 통계적 정밀도(σ = Ts/√6 per 간격, /√N)는 "샘플 클럭과 신호가 무관하다"는 가정에서만 성립한다.

실험 4 — UART 는 샘플링률로만 좋아진다.

U_Tb = F·Ts/Σn ≈ Ts/(프레임당 평균 비트 수) — 프레임을 더 많이 잡아도 최악 한계는 그대로다(프레임마다 ±Ts 가 더해지고 비트 수도 같은 비율로 늘어난다). 1 MS/s 의 ±1.3% 는 ±2% 판정에 쓸 수 없다. 10 MS/s 면 ±0.14%.

8. 면접 Q&A#

Q1. 100 MS/s LA 로 잰 tSU 가 20 ns 이고 스펙이 min 10 ns 입니다. PASS 인가요?

각 에지가 [0, Ts) 늦게 보이므로 간격은 ±10 ns, 다른 채널이니 skew 1 ns 를 더해 U = 11 ns. 진짜는 [9, 31] ns → 한계 10 ns 에 걸쳐 UNRESOLVED. 이 레슨의 보드 B 가 정확히 그렇고, 500 MS/s 재캡처에서 20 ± 3 → PASS. 꼬리질문: "그럼 100 MS/s 로 증명할 수 있는 최소 마진은?" → 반드시 결정하려면 Ts < M/2 − skew → M > 22 ns. "U 에 Ts 가 두 번 들어가는 이유는?" → 측정이 진짜에서 최대 U 만큼 벗어나 있고, 판정도 측정에서 U 만큼 떨어져야 하므로 (연습 2).

Q2. SCLK 주파수를 LA 로 0.5% 이내로 재는 방법은? 100 MS/s 에서 10 MHz 는 10 샘플뿐인데요.

한 주기가 아니라 프레임 안 첫 rising ~ 마지막 rising 의 span 을 사이클 수로 나눈다. span 오차도 ±Ts 하나라 23 사이클이면 ±0.43 ns/주기 ≈ ±0.44% (100 ns 주기). 여러 프레임은 Σspan/Σ사이클 (최악 F·Ts/Σ사이클). 주파수 카운터의 "게이트 시간"을 늘리는 것과 같은 원리. 꼬리질문: "평균 주파수가 스펙 안이면 끝인가?" → 아니다. fSCLK max 는 사실상 사이클별 최소 주기·tCH/tCL 요구다. 지터·spread spectrum·클럭 스트레칭은 평균으로 안 보인다 → 사이클별 tCH/tCL(±Ts)을 같이 판정한다.

Q3. 측정을 1000번 반복해 평균내면 ±Ts 가 ±Ts/√1000 이 되지 않나요?

샘플 클럭과 신호가 비동기이고 위상이 고르게 퍼질 때만이다. 그때 한 간격의 양자화 오차는 (−Ts, Ts) 삼각 분포(σ = Ts/√6)라 평균은 √N 으로 줄어든다. 하지만 10 MHz 를 100 MS/s 로 잡으면 위상이 고정되어 같은 오차를 N 번 더한다 — 실험 3 의 duty 가 50.00 / 40.00 으로 박혔다. 게다가 min/max 스펙은 평균이 아니라 최악 인스턴스에 대한 것이라 평균 자체가 답이 아니다. 꼬리질문: "그럼 일부러 dither 를 만들 수 있나?" → LA 샘플링률을 신호와 정수비가 아니게 고르거나(예: 97 MS/s), 여러 캡처를 비동기로 반복. 그래도 컴플라이언스 보고에는 최악 한계를 쓰고 통계값은 참고로.

Q4. UART 실제 baud 를 LA 로 어떻게 재고, 왜 프레임을 많이 잡아도 정밀도가 안 좋아지나요?

run 폭 히스토그램으로 1비트 클러스터를 찾고(거친 T0), 디코드 후 각 프레임 안 에지 span 을 비트 수로 나눠 Tbit = Σspan/Σn. 프레임 사이 idle 은 임의 길이라 비트 격자가 끊기므로 span 은 프레임 안(최대 ~9비트)에서만 가능하다. 최악 한계는 프레임마다 ±Ts, 비트 수도 프레임 수에 비례 → F·Ts/Σn ≈ Ts/9 로 F 와 무관. 정밀도를 올리려면 fs 를 올린다 (1 MS/s ±1.3% → 10 MS/s ±0.14%). 꼬리질문: "0x55 를 연속으로 보내면?" → 모든 비트에 에지가 있어 히스토그램이 깨끗하고, gap 없이 연속(DMA)이면 프레임 경계에서도 격자가 이어져 span 을 여러 프레임에 걸칠 수 있다 — LIN sync byte 와 오토보드(autobaud)에 0x55 를 쓰는 이유와 같다.

Q5. SPI 클럭과 UART 가 둘 다 약 8% 빠릅니다. 무엇을 의심하나요?

두 주변장치가 같은 비율로 틀렸으면 공통 원인 — 클럭 트리. 이 레슨에서는 ×1.0841 / ×1.0834 (측정 불확도 안에서 같음) → HSE 24 MHz × 1.0837 = 26.01 MHz → 26 MHz 크리스털이 실장됐는데 펌웨어는 HSE_VALUE=24 MHz. 확인: MCO 핀으로 HSE/SYSCLK 를 내보내 카운터로 재거나, 크리스털 마킹/BOM 확인. RF 보드에서 26 MHz TCXO 가 흔해 대체 부품으로 섞이기 쉽다. 꼬리질문: "+8% UART 인데 왜 '가끔' 응답했나?" → 이 데이터에서는 공칭 디코드가 전부 깨진다. 실제 현장에서 '가끔'이라면 오차가 수신 한계(이론 ±5.3%, 실제 그 이하) 근처라는 신호이고, 온도로 RC 발진기(HSI)가 움직이는 경우를 먼저 의심한다.

Q6. tCSH 위반을 펌웨어 엔지니어에게 어떻게 설명하나요?

"마지막 SCLK rising 뒤 CS_N 이 0 ± 11 ns 에 올라간다, U7 은 30 ns 이상을 요구 — 측정 불확도를 넣어도 위반이 증명된다." 원인 후보: TXE(송신 버퍼 비었음)만 보고 CS 를 올림 — TXE 는 마지막 바이트가 시프트 레지스터로 옮겨진 순간이지 전송 완료가 아니다. 수정: BSY=0(또는 STM32H7 의 EOT, RXNE 로 마지막 수신 바이트 확인) 후 CS_N ↑, 하드웨어 NSS 의 경우 NSS 지연 설정. 꼬리질문: "100 MS/s 로 증명이 되는 이유는?" → 마진이 커서다: 진짜 4 ns vs 한계 30 ns, 측정 0 + 11 = 11 < 30. 위반이 크면 저가 LA 로도 FAIL 은 증명할 수 있다. PASS 를 증명하는 것이 더 비싸다.

Q7. LA 로 잰 타이밍과 데이터시트 타이밍이 정의상 다를 수 있는 지점은?

① 기준 레벨: 데이터시트는 VIH/VIL 또는 50% VDD 교차, LA 는 비교기 임계값 하나. 느린 에지(수 ns)에서는 수 ns 차이 → 에지가 느리면 스코프로 (HWLAB-B04 crossing). ② 측정 위치: 수신 핀 기준 — MCU 쪽에서 재면 트레이스 지연(FR-4 에서 대략 6~7 ps/mm)과 반사가 빠진다. ③ 기준 에지 정의(tCSH 가 rising 기준인지 falling 기준인지). ④ 부하 조건(데이터시트 CL 30 pF 등) vs 실제 보드 + 프로브 부하. 꼬리질문: "LA 프로브가 신호를 바꾸나?" → 입력 용량 수 pF 와 리드 인덕턴스. 고속 에지에서는 링잉을 만들어 LA 에 이중 에지로 보일 수 있다 (HWLAB-B05).

10. 핵심 정리#

  • 샘플된 에지는 [0, Ts) 늦다 → 간격 ±Ts, 다른 채널 + skew, 긴 간격 + ppm. 최악값에도 같은 U.
  • 판정은 3값: [v−U, v+U] 가 한계 안 = PASS, 밖 = FAIL, 걸침 = UNRESOLVED. 순진한 비교는 100 MS/s 에서 진짜 위반(17 vs 20 ns)을 50% PASS 로 냈다.
  • 필요 샘플링률은 마진이 정한다: 반드시 결정하려면 Ts < M/2 − skew. FAIL 증명은 싸고 PASS 증명은 비싸다.
  • 주파수·baud 는 span 으로 (±Ts/N). duty·간격의 평균은 비동기일 때만 줄고, 정수비 샘플링은 편향을 그대로 남긴다.
  • UART: 히스토그램 → T0 → 프레임 안 span → Tbit. 정밀도는 fs 로만 오른다 (Ts/9). 공칭 디코드 = 수신기가 보는 것.
  • tSU/tH 는 데이터가 바뀐 비트에서만 잴 수 있다 → 인스턴스 수와 NO DATA 를 보고, 토글 패턴으로 커버리지 확보.
  • 여러 주변장치가 같은 비율로 틀리면 클럭 트리: HSE_VALUE × 비율 → 실장 크리스털.
  • LA 임계값 ≠ 데이터시트 기준 레벨. 마진이 Ts 급이거나 에지가 느리면 스코프(HWLAB-B04).
