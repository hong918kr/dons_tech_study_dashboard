BER Bathtub과 Q-scale 외삽

Mid⏱ 85분env: mac#ber#bathtub#q-scale#extrapolation#see:SIVupdated 2026-11-08
목표 짧은 측정으로 낮은 BER에서의 eye 개방을 외삽하고 그 한계를 안다.
과제 샘플링 위상을 UI 전체에 sweep하며 BER을 계측(오류 카운트는 see:SIV-M06 PRBS checker 재사용)해 bathtub을 만들고, 1e-6까지만 측정한 데이터를 Q-scale 선형 피팅으로 1e-12 eye opening까지 외삽해 M10 dual-Dirac 예측·장시간 직접 측정과 비교하며 측정 시간·신뢰도 trade-off를 표로 정리한다.
내 상태

학습 목표#

  • BERT(bit error ratio tester)가 샘플링 위상을 UI 전체에 걸쳐 옮기며 BER을 재는 bathtub 곡선을 직접 만든다. PRBS7 checker(정렬 → 잠금 → 오류 카운트)로 센 오류 수가 "에지 지터가 샘플링 위상을 넘은 횟수"와 정확히 같다는 것을 보이고, 해석식 BER(x) = ρT·[P(J&gt;x) + P(J&gt;1−x)] 로 검증한다.
  • 1e-6 깊이까지만 잰 bathtub을 Q-scale(Q = √2·erfc⁻¹(2·BER/ρ))로 펴서 가중 최소제곱 직선을 맞추고, 1e-12 eye opening(EO)과 그 표준오차, dual-Dirac 성분(RJ, DJδδ, TJ)을 외삽한다.
  • 외삽이 비틀리는 지점을 수치로 안다: 정규화 ρ 관례(7.034 vs 6.840), 피팅 창에 DJ 영역을 넣는 실수, 정현 PJ처럼 dual-Dirac이 아닌 DJ, 측정 깊이, 그리고 드문 큰 지터(low-probability DJ) — 짧은 측정이 절대 못 보는 꼬리.
  • 측정 시간·신뢰수준 trade-off(0 오류로 1e-12를 95 % 신뢰로 말하려면 3.0e12 비트 = 10 Gb/s에서 300 s)를 표로 말하고, "외톨이 오류(outlier) 검사 + 마스크 위상 장시간 측정"으로 외삽을 검증하는 판정 흐름을 만든다.

1. 문제#

SerDes 링크 검증에서 "1e-12에서 eye가 몇 UI 열려 있나?"는 매일 묻는 질문이고, 그 답은 거의 항상 외삽이다 — Rivian/NVIDIA/Apple 실리콘·보드 검증 면접은 "그 1e-12 숫자를 몇 분 측정으로 어떻게 냈고, 그 외삽은 언제 거짓말하나?"를 꼭 묻는다.

BERT는 패턴 발생기(PG)가 PRBS를 보내고, 오류 검출기(ED)가 받은 비트를 샘플링 위상 x에서 판정해 기대 패턴과 비교한다. x를 UI 왼쪽 끝에서 오른쪽 끝까지 옮기며 위상마다 BER을 찍으면 욕조 모양 곡선이 나온다. 벽은 지터 때문에 생긴다: 왼쪽 벽은 비트 시작 에지가 늦게 와서(J &gt; x) 이전 비트를 읽는 오류, 오른쪽 벽은 다음 에지가 일찍 와서(J &lt; x − 1) 다음 비트를 읽는 오류다. 오류는 전이(transition)가 있는 비트 경계에서만 생기므로 전이 밀도 ρT(PRBS7 = 64/127)가 곱해진다.

BER(x) = ρT · [ P(J &gt; x) + P(J &lt; x − 1) ] = ρT · [ P(J &gt; x) + P(J &gt; 1 − x) ] (J가 0 대칭일 때)

이 레슨이 다른 레슨에서 빌려 오는 것 (전부 이 디렉터리 안에 축약해서 넣었다 — 다른 레슨을 import 하지 않는다):

  • SIV-M06 PRBS checker → prbs7() + prbs7_align() + prbs7_errors() (잠금 checker, 오류 증식 없음). 자기동기 checker의 오류 증식은 연습 1.
  • HWLAB-M10 dual-Dirac → tie_dual_dirac(): scope TIE 1e5 에지의 꼬리를 Q-scale로 피팅하는 축약판. TJ = DJδδ + 2·Q·RJ.
  • 지터 모델: dual-Dirac DJ + 가우시안 RJ, 정현 PJ + RJ, 그리고 "확률 p로 ±s가 더해지는" 드문 큰 지터. 모두 주입한 정답이 있다.

"장시간 직접 측정"을 어떻게 했는지 정직하게 적는다. 1e-12를 직접 세려면 1e13 비트 정도가 필요한데 순수 Python으로는 불가능하다(이 레슨의 에지 카운터는 에지 하나에 약 0.3 µs → 1e13 비트면 약 18일). 그래서 비교 기준을 둘로 나눴다:

Part A — PRBS7 checker, 비트 단위 시뮬레이션 == 에지 카운트, 해석 bathtub#

  1. prbs7_align(rx): 받은 비트열이 PRBS7 주기(127)의 어느 위치 a에 맞는지 64비트 창으로 찾는다. 창 안에 오류가 있으면 다음 창으로(= BERT의 sync). prbs7_errors(rx, a): 로컬 기준 패턴과 비교해 오류 수.
  2. bathtub_counts(jitters, P): 에지 지터 목록만으로 위상 k/P마다 오류 수 = #(j &gt; x) + #(j &lt; x − 1). 히스토그램 + 누적합으로 위상 수와 무관하게 O(에지 수).
  3. simulate_link()(주어짐)로 16 384비트를 비트 단위로 보내 13개 위상에서 checker로 센 오류가 2의 결과와 한 개도 다르지 않음을 확인한다.
  4. tail_prob(model, x) = P(J &gt; x)를 dual-Dirac, 정현 PJ(아크사인 ⊛ 가우시안, 수치 적분), rare 혼합에 대해 구현하고, 1e7비트 Monte Carlo bathtub과 Poisson 4.5σ 이내로 맞춘다.

Part B — Q-scale 피팅과 외삽, 그리고 외삽이 비틀리는 곳#

  1. q_of_ber(ber, ρ)(이분법 erfc⁻¹), qscale_fit(): 한쪽 꼬리에서 BER ≤ 1e-3, 오류 ≥ 5인 점만 골라 Q = m·x + c 를 Poisson 역분산 가중으로 피팅. σ = 1/|m|, μ = −c/m.
  2. extrapolate(): Q_t = Q(1e-12)까지 두 직선을 연장 → EO, 델타 방법 표준오차, RJ = (σL+σR)/2, DJδδ = 1 − (μR − μL), TJ = 1 − EO.
  3. 주입 정답과 비교: DD(DJδδ 0.20, RJ 0.020 UI) 1e7비트에서 EO 오차, ρ = 1로 잘못 정규화했을 때 RJ/DJ 분해가 얼마나 틀어지는지, TIE 1e5 에지(M10 방식)와 BERT 외삽의 불확도 차이, 정현 PJ에서 DJδδ &lt; DJpp, 피팅 창을 DJ 영역(BER 0.1)까지 넓혔을 때의 오차.

Part C — VALBRD-B U7 리타이머 lane0 / lane3 판정#

bert_sweep.csv(gen_bert.py가 만든 BERT export): lane마다 255위상 × 1e7비트 sweep + 마스크 위상(0.30, 0.70 UI) 2.5e7비트 장시간 측정. 스펙(spec.json): 1e-12에서 EO ≥ 0.40 UI(자체 대표값). find_outliers()로 "피팅이 오류 0.01개 미만을 예상하는 위상에서 난 오류"를 찾고, judge_lane()이 ① 마스크 장시간 오류 → FAIL ② 외톨이 오류 → INCONCLUSIVE ③ EO − 2·se ≥ 스펙 → PASS 순으로 판정한다. lane3에는 확률 1e-6으로 ±0.20 UI가 더해지는 드문 큰 지터를 심어 두었다 — 외삽만 보면 PASS(0.528 UI), 정답은 0.227 UI.

2. Problem (English)#

Build a BER bathtub from a BERT phase sweep and extrapolate the 1e-12 eye opening on the Q-scale.

Units are UI (10 Gb/s → 1 UI = 100 ps). Python 3 standard library only.

  1. PRBS7 (x^7 + x^6 + 1, b[t] = b[t-7] ^ b[t-6]) checker: prbs7_align(rx, nverify=64) returns the offset a such that rx[t] == PRBS7[(t+a) % 127] over an error-free 64-bit window (slide the window if needed, None if never); prbs7_errors(rx, a) counts mismatches against the local reference.
  2. bathtub_counts(jitters, P): given the TIE of every data transition (UI, positive = late), return the error count at sampling phases k/P, k = 1..P-1: #(j > x) + #(j < x-1), in O(len(jitters) + P). It must equal, exactly, the error count a bit-level simulation + PRBS checker produces with the same jitter draws.
  3. tail_prob(model, x) = P(J > x) for dual-Dirac + Gaussian, sinusoidal PJ + Gaussian, and a rare-event mixture.
  4. qscale_fit(points, side, rho, ber_max, min_err): weighted least squares of Q = sqrt(2)*erfcinv(2*BER/rho) versus phase on one side of the eye using only tail points (BER <= ber_max, errors >= min_err), weights n_err * (phi(Q)/Qbar(Q))^2. extrapolate(fitL, fitR, ber, rho) -> eye opening at ber, its standard error, RJ, DJ(δδ), TJ.
  5. Given a BERT export for two lanes (sweep to 1e-6 depth + long dwell at mask phases), decide PASS / INCONCLUSIVE / FAIL against EO(1e-12) >= 0.40 UI, flagging errors that the fitted tails say should not exist.

Example: dual-Dirac DJ = 0.20 UI, RJ = 0.020 UI, PRBS7, 1e7 bits per phase → fit gives RJ ≈ 0.020, DJ(δδ) ≈ 0.20, EO(1e-12) ≈ 0.526 UI (analytic truth 0.5264). A lane with a 1e-6-probability ±0.20 UI jitter event still extrapolates to ≈ 0.53 UI, while its true EO(1e-12) is 0.227 UI.

4. 힌트#

힌트 1 — 정렬(lock)은 127가지 위치만 보면 된다

PRBS7은 주기 127이다. PRBS7_PERIOD[(t + a) % 127] 의 a를 0..126 중에서 찾으면 된다. 창 64비트가 전부 맞으면 오탐 확률은 2⁻⁶⁴ 수준. 창 안에 오류가 하나라도 있으면 어떤 a도 안 맞으니 창을 옮긴다. 실제 하드웨어 checker(SIV-M06)는 받은 비트로 LFSR 상태를 채우고 32번 연속 예측이 맞으면 LOCKED로 넘어간다 — 같은 일을 스트리밍으로 하는 것.

힌트 2 — "오류 = 에지가 샘플링 위상을 넘은 사건"

비트 k를 위상 x에서 읽는다. 왼쪽 경계(전이가 있을 때)의 지터 j_k가 x보다 크면 아직 이전 비트다 → 오류. 오른쪽 경계의 j_{k+1}이 x − 1보다 작으면 이미 다음 비트다 → 오류. 지터가 ±0.5 UI 안이면 두 사건이 한 비트에 겹치지 않는다. 그러니 checker 없이도 #(j > x) + #(j < x − 1) 이 정확한 오류 수다.

힌트 3 — 모든 위상을 한 번에: floor(j·P) 히스토그램

b = floor(j·P)로 칸에 넣으면 j &gt; k/P ⟺ b ≥ k, j &lt; k/P − 1 ⟺ b ≤ k − P − 1 (경계에 정확히 걸릴 확률 0). b는 −P..P 범위이니 인덱스 b + P. 뒤에서부터 누적합 ge[i] = Σ hist[i:] 을 만들면 late = ge[k+P], early = total − ge[k].

힌트 4 — Q-scale 변환과 가중치

Q = −Φ⁻¹(BER/ρ) 를 tail(Q) = BER/ρ 의 이분법으로. 가우시안 꼬리면 Q는 x에 대해 직선이다. 점마다 신뢰도가 다르다: 오류 n개의 상대오차는 1/√n이고, δQ = δBER / (ρ·φ(Q)) = Q̄(Q)/(φ(Q)·√n) ≈ 1/(Q·√n). 그래서 가중치 w = n·(φ(Q)/Q̄(Q))². 오류 0개 점은 Q = ∞ — 절대 넣지 않는다.

힌트 5 — 외삽 표준오차 (델타 방법)

가중 최소제곱의 공분산은 (XᵀWX)⁻¹: D = S·Sxx − Sx², Var m = S/D, Var c = Sxx/D, Cov = −Sx/D. x(Q_t) = (Q_t − c)/m 이므로 ∂x/∂c = −1/m, ∂x/∂m = −x/m → Var x = (x²·Var m + Var c + 2x·Cov)/m². 두 꼬리는 서로 다른 데이터라 EO의 분산은 합.

힌트 6 — 외톨이 오류

피팅 직선으로 그 위상의 기대 오류 = n·ρ·Q̄(m·x + c). 이게 0.01개보다 작은데 오류가 났다면, 그 오류는 피팅한 가우시안 꼬리에서 나올 수 없다 — 다른 메커니즘이 꼬리를 차지하고 있다는 신호다.

5. 풀이#

Part A — checker가 센 오류 = 에지가 넘은 횟수#

실제 출력 (solution.py):

정렬은 eye 중앙(x = 0.5, 오류 0)에서 한 번 하고, 그 기준을 유지한 채 위상을 옮긴다(BERT가 실제로 하는 방식 — 가장자리 위상에서는 BER이 25 %라 거기서 sync를 잡을 수 없다). 그다음 13개 위상의 checker 결과가 에지 카운트와 한 개도 다르지 않다. 이 동치 덕분에 1e7비트 bathtub을 비트 단위로 돌리지 않고 에지 지터만 세서 만들 수 있다(5e6 에지 ≈ 1.5 s).

Part B — Q-scale: 가우시안 꼬리를 직선으로 편다#

dual-Dirac 한쪽 꼬리는 BER_L(x) = ρT·½·Q̄((x − μL)/σ). 그러므로 ρ = ρT/2로 정규화한 Q = Q̄⁻¹(BER/ρ) = (x − μL)/σ — 기울기 1/σ(RJ), Q = 0 절편이 Dirac 위치 μ인 직선이다. 1e-12까지 연장하는 건 이 직선 위에서 Q_t까지 가는 것뿐이다.

③ TIE 기반 dual-Dirac(HWLAB-M10 방식)과의 비교. 스코프 TIE 1e5 에지의 꼬리는 ρT = 1인 bathtub과 같은 모양이라 같은 코드로 피팅된다. 결과 EO 0.5274 ± 0.0055 — 맞지만 se가 BERT 외삽의 5.5배다. 1e5 에지의 CDF는 ~5e-5까지만 내려가서 외삽 거리가 길다. 실무 차이도 있다: 스코프 TIE에는 스코프 자체의 잡음·타임베이스 지터가 섞이고, 기준 클럭(golden PLL, HWLAB-M09)의 정의에 따라 저주파 지터가 빠지거나 남는다. 8. 면접 Q&A#

Q1. bathtub 곡선이 뭐고, 왜 BER이 전이 밀도에 비례하나요?

샘플링 위상을 UI 안에서 옮기며 잰 BER(x). 왼쪽 벽은 비트 시작 에지가 x보다 늦게 오는 확률, 오른쪽 벽은 다음 에지가 x보다 일찍 오는 확률이다. 에지가 없으면(같은 비트 연속) 늦을 에지도 없으니 오류가 없다 → BER = ρT·[P(J&gt;x) + P(J&gt;1−x)]. 가운데의 평평한 바닥 폭이 eye opening, 1 − EO가 그 BER에서의 TJ다. 꼬리질문: "PRBS7과 PRBS31의 bathtub이 같은 지터에서 다른 이유?" → ρT는 둘 다 ≈ 0.5지만, 긴 run length(31은 최대 31개 연속)가 채널 ISI → 패턴 의존 지터(DDJ)를 키운다. 같은 칩·채널이라도 PRBS31 eye가 더 닫히는 게 정상이고, 스펙이 요구하는 패턴으로 재야 한다.

Q2. Q-scale은 무엇이고 왜 직선이 되나요? 기울기와 절편은 무슨 뜻이죠?

BER을 Q = √2·erfc⁻¹(2·BER/ρ)로 바꾼 축. 꼬리가 가우시안 ρ·Q̄((x−μ)/σ)이면 Q = (x − μ)/σ — 직선이다. 기울기의 역수가 RJ(σ), Q = 0 절편이 그 꼬리를 만드는 Dirac 위치(μ). 양쪽 μ 간격으로 DJδδ = 1 − (μR − μL). 1e-12까지 외삽 = 직선을 Q_t까지 연장. 꼬리질문: "어떤 점을 피팅에 쓰나?" → 가우시안이 지배하는 꼬리(대략 BER ≤ 1e-3)이면서 오류가 충분한 점(≥ 5~10개). 벽 근처를 넣으면 DJ 모양이 섞여 PJ 예에서 오차가 −0.006 → −0.057 UI로 10배 커졌다.

Q3. 1e-12를 직접 측정하려면 얼마나 걸리나요?

오류 0개로 "BER &lt; 1e-12"를 95 % 신뢰로 말하려면 N = −ln(0.05)/1e-12 = 3.0e12 비트 → 10 Gb/s 300 s, 25 Gb/s 120 s. 오류 1개를 허용하면 4.74e12, 2개면 6.30e12. 1e-15면 10 Gb/s에서 3.5일. bathtub 64위상 전부를 1e-12까지 직접 재면 5.3 시간. 꼬리질문: "그럼 외삽은 왜 믿나?" → RJ가 가우시안이고 DJ가 유계(bounded)라는 모델 가정 + 측정 깊이까지의 데이터가 직선 위에 있다는 확인. 믿는 범위를 넓히려면 마스크 위상에서만 장시간 측정한다(점 1~2개 × 5분).

Q4. dual-Dirac의 DJδδ가 실제 DJ pk-pk보다 작은 이유는?

dual-Dirac은 "꼬리를 가장 잘 설명하는 두 Dirac + 가우시안"이다. 정현 PJ(아크사인)처럼 확률이 양 끝에 몰리지만 연속인 분포를 두 점으로 근사하면, 가우시안과 합성된 꼬리를 맞추는 Dirac 간격이 pp보다 안쪽으로 온다. 이 레슨: PJ 0.20 UIpp → DJδδ 0.167, 대신 RJ가 0.022로 부풀어 차이를 흡수한다. 꼬리질문: "그러면 TJ도 틀린가?" → TJ(BER)는 측정 깊이 근처에선 데이터가 고정하므로 상대적으로 강건하다(EO 오차 −0.006 UI). RJ/DJ 분해 숫자는 방법(스펙트럼, 꼬리 피팅, ρ 관례)에 따라 달라지므로 장비 간 비교는 TJ@BER로 한다.

Q5. Q-scale 외삽이 틀리는 대표적인 경우와, 그걸 어떻게 잡나요?

측정 깊이 아래에서 꼬리 메커니즘이 바뀌는 경우: 전원 버스트·부하 스텝이 PLL을 흔드는 드문 사건, 가끔만 정렬되는 크로스토크, CDR이 놓치는 저주파 wander, 비가우시안 잡음. 이 레슨 lane3(확률 1e-6, ±0.20 UI): 피팅 EO 0.528 vs 정답 0.227. 잡는 법: ① 피팅이 오류를 거의 예상하지 않는 위상의 외톨이 오류 검사, ② 마스크 위상 장시간 측정, ③ Q-scale 그래프에서 꺾임(knee) 확인, ④ 같은 lane 반복·다른 lane 비교(lane0 0.574 대비). 꼬리질문: "외톨이 오류가 없으면 안전한가?" → 아니다. 1e7비트에서 기대 개수가 ~1개 수준이면 0개일 확률이 크다(Poisson e⁻¹ ≈ 37 %). 없음은 증거가 아니다 — 마스크 위상 장시간 측정이 최종.

Q6. TJ = DJ + 14.069·RJ의 14.069는 어디서 왔나요? 이 레슨의 6.84와 왜 다르죠?

14.069 = 2 × 7.034, 7.034 = Q̄⁻¹(1e-12) — 꼬리 확률 자체가 1e-12인 점(ρ = 1 관례, Fibre Channel MJSQ 등). 비트당 BER로 읽으면 전이 밀도 ρT(≈ 0.5)와 dual-Dirac 한쪽 가중치 ½이 곱해져 Q̄⁻¹(1e-12/0.252) = 6.84. RJ 0.02 UI에서 TJ 차이 0.0078 UI. 꼬리질문: "리포트에는 무엇을 쓰나?" → 스펙이 정한 관례. 스펙이 TJ = DJ + 14.069·RJ로 정의하면 그걸로, 장비가 내부적으로 ρT를 넣는지 확인해서 "어느 Q로 계산했는지"를 적는다. 관례가 다른 두 숫자를 비교하면 1 ps 가까이 차이 날 수 있다.

Q7. 스코프 TIE로 낸 TJ와 BERT bathtub에서 낸 TJ가 다릅니다. 어느 쪽이 맞나요?

둘은 보는 것이 다르다. 스코프 TIE는 기준 클럭(이상 클럭 또는 golden PLL, HWLAB-M09) 대비 에지 시각이고, 스코프 자체 잡음·타임베이스 지터가 RJ에 더해진다. 표본도 1e5~1e6 에지라 꼬리가 얕다(이 레슨: se 0.0055 vs BERT 0.0010). BERT는 실제 수신 경로(CDR)가 따라가지 못한 지터만 오류로 센다. 저주파 지터는 CDR이 추적해 BERT에선 사라지고, 스코프에선 golden PLL 대역폭에 따라 남거나 빠진다. 꼬리질문: "스코프 쪽 RJ가 항상 더 크면?" → 스코프 노이즈 플로어(TIE floor)를 제곱합으로 빼는 보정(RJ_dut² ≈ RJ_meas² − RJ_scope²), 프로브·케이블 대역폭 확인. 그리고 스펙이 어느 측정 방법(어떤 CDR 대역폭)을 정의하는지 맞춘다.

Q8. PRBS checker가 오류를 과대 계수할 수 있나요?

자기동기(self-synchronizing) checker는 예측 비트를 받은 비트로 만든다: pred = rx[t−7] ⊕ rx[t−6]. 오류 1개는 자기 자리 + 6, 7비트 뒤 예측에서 다시 걸려 3번 세어진다(탭 2개 다항식). 연습 1: 4개 주입 → 12. 그런데 6비트 간격 두 오류는 서로 상쇄돼 6이 아니라 4로 세어진다 — 계수 배율이 패턴 의존이라 단순히 3으로 나누면 안 된다. 잠금(locked) checker는 로컬 LFSR로 기대 비트를 만들어 1번만 센다. 꼬리질문: "그럼 자기동기를 왜 쓰나?" → 시작·재동기가 자동이다. 실무 checker는 HUNT(자기동기로 lock) → LOCKED(로컬 생성) 두 모드로 동작하고, 오류율이 높으면 sync loss로 다시 HUNT (SIV-M06).

9. 추가 연습#

연습 1 — 자기동기 checker의 오류 증식#

selfsync_errors(rx): 예측 = rx[t−7] ⊕ rx[t−6]. 서로 떨어진 단일 오류 4개를 넣은 2000비트 PRBS7에서 잠금 checker는 4, 자기동기는 12. 6비트 간격 오류 두 개는 몇으로 세어지나?

답 보기

실제 출력: locked=4 selfsync=12, 6비트 간격 두 오류는 selfsync=4. t = 500, 506에 오류가 있으면 t = 506의 예측 rx[499] ⊕ rx[500]이 틀리고(오류 500의 영향) 받은 rx[506]도 틀려서 두 오류가 상쇄 → 그 자리는 "맞음". 남는 건 500(자기), 507(500+7), 512(506+6), 513(506+7) 4개. 그래서 자기동기 카운트를 3으로 나누는 보정은 오류가 드물고 흩어져 있을 때만 근사로 맞는다. BER 측정에는 잠금 모드를 쓴다.

연습 2 — ρ를 자유 변수로 피팅#

fit_rho(points, side, bmax): log 격자 41점에서 가중 χ²가 최소인 ρ. ① DD, 창 BER ≤ 5e-2 → ρ가 ρT/2의 10 % 이내 ② DD, 창 ≤ 1e-3 → χ²가 ρT/2와 1에서 거의 같음(식별 불가) ③ PJ, 창 ≤ 5e-2 → ρ_eff ≠ ρT/2, 그리고 고정 ρ보다 EO 오차가 3배 이상 작다.

답 보기

실제 출력: DD 넓은 창 best ρ = 0.2597 (ρT/2 = 0.2520), 꼬리 창 χ² 7.23 vs 6.04 — 깊은 꼬리만으로는 Q̄⁻¹(BER/ρ)의 ρ 의존이 기울기·절편에 흡수돼 구별이 안 된다. ρ를 정하려면 꼬리가 시작되는 어깨(BER 1e-2 근처)가 필요하다. PJ: ρ_L = ρ_R = 0.1324 — 아크사인 분포의 "효과적인 Dirac 가중치"는 ½이 아니다. 같은 넓은 창에서 EO 오차가 고정 ρ −0.0335 → 맞춘 ρ −0.0066 UI. 넓은 창을 쓰려면 ρ도 같이 맞춰야 한다는 것이 Stephens식 Q-scale 방법의 요점이다.

연습 3 — Poisson 신뢰도#

bits_for_cl_k(ber, cl, k)(오류 k개 허용 시 필요한 비트), poisson_bounds(k, n)(정확 양측 구간). 95 % 배수 0/1/2개 = 2.996 / 4.744 / 6.296을 재현하고, lane3 마스크(6 err / 5e7 비트)와 lane0(0 / 5e7)의 구간을 구한다.

답 보기

P(X ≤ k | λ) = 1 − CL을 이분법으로 → 2.996 / 4.744 / 6.296 (χ²(2k+2) 분위수의 절반과 같다). lane3: BER ∈ [4.40e-8, 2.61e-7] — 하한이 1e-12보다 4자릿수 이상 위라 FAIL이 통계적으로 확정. lane0: 상한 7.38e-8(양측 97.5 % 단측 = −ln 0.025 / n = 3.689/n) — "PASS"를 말하기엔 4~5자릿수 부족. 오류가 나는 건 짧은 측정으로도 증명되지만, 안 나는 건 오래 재야만 증명된다.

연습 4 — RJ 예산#

rj_budget(eo_min, djdd, ber): EO = 1 − DJδδ − 2·Q·RJ ≥ eo_min → RJ_max. EO ≥ 0.40 UI, DJδδ 0.18에서 RJ_max는 몇 UI, 10G/25G에서 몇 ps?

답 보기

RJ_max = (1 − 0.40 − 0.18)/(2 × 6.8397) = 0.0307 UI = 3.07 ps @10G, 1.23 ps @25G. 같은 UI 예산이라도 라인 레이트가 올라가면 ps 예산이 비례해서 줄어든다 — 25G 이상에서 refclk·PLL 위상잡음(HWLAB-M08)이 갑자기 중요해지는 이유. ρ = 1 관례(Q = 7.034)로 계산하면 0.0299 UI로 약 3 % 더 빡빡하다.

10. 핵심 정리#

  • bathtub: BER(x) = ρT·[P(J&gt;x) + P(J&gt;1−x)]. 오류는 에지가 샘플링 위상을 넘은 사건 — checker 카운트와 에지 카운트가 정확히 같다.
  • Q-scale: Q = √2·erfc⁻¹(2·BER/ρ). 가우시안 꼬리면 직선, 기울기 1/RJ, 절편 = Dirac 위치. EO(BER) = 두 직선을 Q_t까지 연장한 간격, TJ = 1 − EO = DJδδ + 2·Q_t·RJ.
  • Q(1e-12) = 7.034는 ρ = 1 관례(14.069 = 2×7.034). 비트 BER + ρT + Dirac ½ → 6.84. 관례를 리포트에 적는다.
  • 피팅은 꼬리 창(BER ≤ 1e-3, 오류 ≥ 5)만, Poisson 역분산 가중, 오류 0 점 제외. se는 델타 방법, 판정은 EO − 2·se.
  • RJ/DJ 분해는 방법 의존(ρ=1: DJδδ −15 %), EO/TJ@BER가 물리량. DJδδ ≤ DJpp (PJ 0.20pp → 0.167).
  • 1e-12 직접: 0 오류 95 % → 3.0e12 비트 = 10G 300 s. 1e-6 깊이 sweep 64점은 64 ms.
  • 외삽은 "꼬리 메커니즘이 깊이 아래에서 안 바뀐다"는 가정. 드문 큰 지터(lane3: 확률 1e-6)는 외삽 EO 0.528 → 정답 0.227.
  • 잡는 법: eye 안쪽 외톨이 오류 검사 → 마스크 위상 장시간 측정. 오류 0은 아무것도 증명하지 않고, 오류 1개는 많은 것을 증명한다.
