Constrained-Random 테스트와 Scoreboard

Advanced⏱ 120분env: mac#constrained-random#scoreboard#reference-modelupdated 2026-11-08
목표 랜덤 시퀀스 + 골든 참조 모델 비교로 사람이 생각 못 한 코너를 찾는다
과제 레지스터 쓰기/DMA 요청/인터럽트 이벤트를 제약 조건 하에 랜덤 생성하는 generator, 같은 입력을 받는 골든 모델, DUT 모델 출력을 비교하는 scoreboard를 구현; DUT 모델에 미묘한 버그(특정 순서에서만 status 갱신 누락)를 넣고 시드 재현성으로 디버그한다.
내 상태

학습 목표#

  • 레지스터 쓰기 · DMA 시작 · 인터럽트 이벤트를 가중치 + 합법성 제약 아래 랜덤으로 뽑는 generator를 만들고, 그 generator가 왜 DUT가 아니라 모델 상태를 봐야 재현성이 생기는지 설명한다.
  • DUT와 코드를 공유하지 않는 골든 참조 모델과, 첫 불일치에서 시드·step·기대값·실제값·직전 trace를 남기는 scoreboard를 구현한다.
  • directed 테스트가 놓치는 "좁은 순서" 결함을 constrained-random으로 찾고, sequences-to-detect를 고정 시드 표로 측정해 가중치·제약·관찰 방식이 검출 속도를 어떻게 바꾸는지 숫자로 말한다.
  • 실패 시퀀스를 시드로 재현하고 ddmin + 타이밍 보존 치환으로 5 op 근처까지 자동 축소한 뒤, 스펙 단정(assertion)으로 DUT 버그와 모델 버그를 가른다.
  • 이 방법이 못 찾는 것(공통 원인 오독, 값 하나짜리 코너, 과잉 제약, 관찰 부족에 의한 masking)을 실측값으로 제시한다.

1. 문제#

사람이 쓴 directed 테스트는 사람이 생각한 순서만 검사한다 — 실리콘 검증 면접에서 "랜덤 테스트를 어떻게 설계하고, 실패하면 어떻게 줄여서 디버그 팀에 넘기나"를 묻는 이유가 이것이고, Rivian/NVIDIA 같은 팀의 first-silicon 회귀가 실제로 이렇게 돈다.

SIV-B11(trigger-check-clear)과 SIV-M02/M03은 "DMA 한 번 → 완료 확인 → W1C" 순서를 검사한다. 맞는 테스트지만, 칩이 죽는 건 대개 순서가 겹칠 때다. 예: 드라이버가 INT_STS의 다른 비트를 W1C로 지우는 바로 그 cycle에 DMA 완료가 들어오면, 상태 레지스터의 next-state 로직에서 HW set 경로가 write 경로에 눌려 DONE이 사라진다. 소프트웨어 입장에서는 인터럽트가 영원히 안 오는 hang이다. 이런 순서는 테스트 작성자의 머리에 없으므로 directed로는 잘 안 나온다.

해법은 세 조각이다 (UVM의 sequence/predictor/scoreboard와 같은 역할 분담인데, 여기서는 C로 직접 만든다):

Part A — Generator · 골든 모델 · scoreboard#

  • model_cycle: 스펙을 절대 시각(done_at)으로 구현. BUSY 판정은 cycle 시작 시점 값, 읽기도 cycle 시작 시점 값, set 승 (TODO A1). DUT는 cnt 다운카운터로 다르게 구현돼 있다 — 코드를 공유하면 공통 원인 버그가 숨는다.
  • gen_next: 합법 제약 (BUSY 채널 START 금지, W1C는 pending 비트의 부분집합만, BUSY 채널의 LEN 금지, reserved 비트 0)을 지키며 가중치로 뽑는다. 제약 위반 비율(illegal_pct), 다음 cycle에 끝나는 DMA를 W1C로 겨누는 aware_pct, 과잉 제약(no_w1c_busy)을 프로파일로 둔다 (TODO A2).
  • sb_run: 같은 op를 DUT/모델에 넣고 OBS_EVERY(매 op 전체 비교) · OBS_READ(시퀀스의 RD 값만) · OBS_END(끝에서만)로 비교, 첫 불일치에서 멈춰 리포트와 직전 8 op trace를 채운다 (TODO A3).

Part B — 좁은 순서 결함과 측정#

  • directed 7개(정상 흐름 + 에러 경로)는 최강 관찰(OBS_EVERY)에서도 RACE·MASKED·LATE를 놓쳐야 한다 (CHECK). 쉬운 W1C_ALL과 BUSY 중 START는 directed가 잡는다.
  • seqs_to_detect로 시드 16~32개에 걸친 sequences-to-detect 평균/중앙값/최악을 측정. 프로파일(uniform / tuned / aware / over-constrained / illegal)별로 표를 만든다 (TODO B1).
  • 한계를 CHECK로 못박는다: 값 코너(BUG_MAGIC) 0건, 공통 원인(DUT·모델 둘 다 clear-wins) 불일치 0건, 관찰을 줄이면 masking.

Part C — 시드 재현, 자동 축소, 판정, 리포트#

  • 같은 시드는 같은 step에서 같은 리포트를 낸다 (strcmp CHECK).
  • ddmin(complement-only) → shrink_full(ddmin + IDLE 치환 + IDLE 병합 + 창 제거): 시퀀스를 합법·같은 시그니처를 유지하며 줄인다 (TODO C1, C1-b).
  • spec_check(스펙 단정 5개) → classify: 축소된 시퀀스를 DUT 쪽/모델 쪽으로 각각 돌려 누가 스펙을 어겼는지로 DUT_BUG / MODEL_BUG / SPEC_MISREAD? / INCONCLUSIVE (TODO C2, C3).
  • 야간 회귀 시나리오: 결함별 첫 실패 → 축소 → 판정 → 디버그 팀에 바로 넘길 한 줄 (format_report, TODO C4).

2. Problem (English)#

Design a constrained-random verification harness for a small DMA / interrupt-status block (C11, host model).

The block has 2 DMA channels and a W1C status register INT_STS (DONE0, DONE1, EVT, ERR), with a mask register and an IRQ line. A bus operation takes one cycle; a DMA started with LEN finishes LEN cycles later, independently of the bus. If a hardware set and a W1C clear hit the same bit in the same cycle, set wins.

Implement:

  1. A golden reference model model_cycle (independent of the DUT implementation) and a constrained generator gen_next(model, rng, profile, op) that only emits legal ops (no START on a busy channel, W1C only of currently pending bits, LEN only while the channel is idle), weighted per profile. The generator must read the model state only.
  2. A scoreboard sb_run(seq, n, bugs, model_bugs, mode, report) comparing DUT and model, stopping at the first mismatch and reporting seed, step, cycle, register, expected, actual and the last 8 operations.
  3. A campaign function seqs_to_detect and a report of sequences-to-detect across fixed seeds. Show that directed tests miss a bug which only fires when a W1C of one bit coincides with a DMA completion of another, and quantify how weights and constraints change the detection rate.
  4. Failure handling: deterministic seed replay, a ddmin-based sequence shrinker that preserves legality and the failure signature, and a classifier that uses independent spec assertions to distinguish a DUT bug from a model bug.

Report format: FAIL sb seed=0x… step=… cycle=… reg=INT_STS off=0x008 exp=0x… act=0x… diff=0x… bits=[…] class=… sa=… | trace(last N): … | shrunk=<len> ops

Checked tests must be deterministic (fixed seeds, no wall-clock); planted defects must be caught with the right location, the correct model must pass, and at least one test must demonstrate what the method cannot find.

4. 힌트#

힌트 1 — 모델을 DUT와 다르게 쓰기

DUT는 카운터를 줄여 0이 되면 끝. 모델은 done_at = now + len을 저장하고 done_at == now일 때 끝. 쓰기 효과는 cycle 시작 시점의 BUSY로 판단해야 "같은 cycle에 끝나는 채널에 START"가 스펙대로 ERR가 된다.

힌트 2 — 합법 제약은 가중치를 0으로 만드는 것

intent별 가중치 배열을 복사한 뒤, 지금 불가능한 것을 0으로 만들고 추첨한다: EN=0이거나 idle 채널이 없으면 START=0, pending이 없으면 W1C=0. 가중치 합이 0이 되지 않도록 항상 가능한 intent(IDLE/EVT/RD)를 남겨 둔다.

힌트 3 — scoreboard는 첫 불일치에서 멈춘다

첫 불일치 뒤의 비교는 의미가 없다 — DUT와 모델의 상태가 이미 갈라졌기 때문이다. trace는 불일치 op를 포함해 마지막 8개를 복사한다 (시퀀스가 배열이니 step-7..step).

힌트 4 — ddmin의 함정은 시간이다

op를 지우면 뒤 op들이 앞당겨지므로 "완료 cycle과 겹침"이 사라진다. 그래서 ddmin은 시간을 메우던 op를 못 치운다. IDLE(1)로 치환해 시간을 유지하면서 op의 의미를 없앤 뒤, 인접 IDLE을 합치고, 그다음에 다시 지운다. 또 후보 검사에서 "합법인가"를 먼저 본다.

힌트 5 — 스펙 단정은 모델이 아니라 관찰값으로

"BUSY가 내려간 채널은 DONE이 1이어야 한다"처럼 op와 전후 관찰값만으로 쓴다. 그래야 모델과 독립이고, 모델 쪽 trace에도 똑같이 적용해서 누가 어겼는지 볼 수 있다.

5. 풀이#

Part A — 왜 이렇게 나눴나#

Generator가 모델을 봐야 하는 이유. gen_next가 다음 op를 고르려면 "지금 pending이 뭔지", "채널이 BUSY인지"를 알아야 한다. 이걸 DUT에서 읽으면 결함이 자극을 바꾼다 — DUT가 틀렸을 때 시퀀스 자체가 달라지므로 시드 재현이 깨지고, 불일치의 원인과 결과가 섞인다. 모델 그림자(shadow) 상태로 만들면 시퀀스는 시드와 프로파일만의 함수가 된다. 그래서 시퀀스를 먼저 다 만들고(seq_generate) 그다음에 DUT와 모델에 넣는다. 첫 번째 시퀀스 재현(run_seed 2회)이 그대로 CHECK다.

합법 제약 vs 스펙. 두 층을 구분한다:

층예어기면
스펙(하드웨어 동작)BUSY 중 START → ERR, W1C는 set 승DUT 버그
합법 제약(자극 규칙)"BUSY 중에는 START 안 함" (constrained)버그 아님, 단지 그 영역을 안 쳐봄

constrained 모드는 드라이버가 스펙대로 쓰는 범위(conformance)를 집중 공략하고, illegal_pct는 에러 경로 강건성을 친다. 나중 표에서 보듯 둘은 찾는 결함이 다르다.

골든 모델은 왜 DUT와 코드를 공유하지 않나. DUT와 같은 함수를 쓰면 같은 오해도 복사된다 (Part B의 공통 원인 실험). 모델은 일부러 다른 표현(절대 cycle 타임스탬프)으로 작성했다. model_cycle의 핵심 네 줄:

set-승 수식이 (sts & ~clr) | set인 것이 이 레슨 전체의 기준점이다. 결함 BUG_CLEARW의 (sts | set) & ~clr과의 차이는 같은 cycle에 같은 비트일 때만 드러난다.

Scoreboard — 관찰 방식 세 가지. pre-silicon에서는 내부 신호를 다 볼 수 있지만, post-silicon에서 볼 수 있는 건 버스 읽기로 얻는 값뿐이고 그 읽기는 타이밍을 바꾼다. 그래서 OBS_EVERY(이상적 — 시뮬/에뮬), OBS_READ(시퀀스에 RD가 있을 때만 — 실리콘에 가깝다), OBS_END(끝에서 한 번 — 스트레스 테스트의 흔한 형태)를 분리해 측정한다.

리포트는 왜 그 필드들인지 있다: seed로 재현하고, step·cycle로 어디서 터졌는지, reg·exp·act·diff·bits로 무엇이 틀렸는지, 직전 8 op로 어떤 순서 끝에 왔는지.

  • 모델 인식 조준(aware): "다음 cycle에 DONE1이 끝나고 EVT가 pending이면 W1C를 겨눈다" — 평균 1.6. 커버리지 기반 생성의 원리와 같다. 단, 이미 결함을 아니까 겨눈 것이고, 야간 회귀에서는 tuned 정도가 정직한 추정이다.
  • 가중치의 함정: tuned는 race가 빨라지는 대신 len_max=4라 LEN=8 코너를 영영 못 친다 (0건). 제약은 무엇을 빠르게 만들면서 무엇을 영구히 잠근다.
  • 과잉 제약: no_w1c_busy("BUSY 중 W1C 금지")는 작성자 눈에 안전한 규칙이지만, race를 0건으로 만든다. 제약을 볼 때 "이 제약이 어떤 버그 영역을 지우는가"를 물어야 한다.
  • illegal: restart는 constrained 프로파일 전부 0건, illegal15만 찾는다. 합법 시퀀스는 에러 경로를 안 탄다.

통계: 시퀀스당 검출 확률이 p면 처음 검출까지의 시퀀스 수 평균 1/p (기하 분포). 표의 uniform 21.2는 시퀀스당 p≈4.7% 근처. 0건일 때 p의 상한은 "2000개 0건 → 95% 신뢰로 p < 3/2000"(SIV-M06/M09의 rule of three와 같다).

8. 면접 Q&A#

Q1. Constrained-random 환경의 세 구성요소와 왜 나누는지 설명해 보세요.

Generator(제약 + 가중치로 자극), Reference model(스펙을 독립 구현해 기대값 생성), Scoreboard(DUT와 비교, 첫 불일치 보고). 나누는 이유: 자극과 판정이 분리되어야 시드만으로 재현할 수 있고, 모델을 바꾸거나 DUT를 바꿔도 비교부가 그대로다. Generator가 DUT가 아니라 모델 상태를 봐야 하는 게 핵심이다. 꼬리질문 "모델이 RTL과 다른 사람이 썼으면 충분한가?" → 코드는 분리돼도 같은 스펙 해석이면 공통 원인 버그가 남는다. 그래서 스펙 assertion, 교차 리뷰, 이전 칩 회귀가 별도로 필요하다.

Q2. 랜덤 테스트가 실패했습니다. 다음에 뭘 하나요?

① 시드로 재현 ② 첫 불일치 step까지 자르기 ③ 축소(ddmin 류) — 합법성과 실패 시그니처를 지키면서 ④ 모델 버그인지 DUT 버그인지 판정(스펙 단정, 이전 revision, 독립 모델) ⑤ 최소 재현을 directed 테스트로 고정해 회귀에 넣기. 대부분의 시간을 쓰는 건 ③④다. 꼬리질문 "ddmin이 왜 안 줄어드나요?" → 타이밍 의존성. op를 지우면 뒤가 앞당겨져 조건이 깨진다. NOP로 치환해 시간을 유지하고, 의존 쌍(START와 그 clear)은 창으로 같이 뺀다.

Q3. Scoreboard 불일치가 났는데 DUT가 맞을 수도 있나요? 어떻게 구분하죠?

그렇다 — 이 레슨의 MB_CLEAR_WINS가 그 경우다. 구분 방법: 스펙 단정을 모델과 독립적으로 써서 DUT/모델 각각의 관찰값에 적용한다(classify). DUT만 위반 → DUT 버그, 모델만 위반 → 모델 버그, 둘 다 → 스펙 해석 회의, 둘 다 통과 → 단정이 커버 못 한 영역(이 레슨의 late)이라 사람이 본다. 꼬리질문 "단정도 사람이 쓰는데?" → 맞다, 단정 층도 틀릴 수 있다. 다만 모델과 다른 형태(cycle-accurate 구현 vs 불변식)로 쓰므로 같은 실수를 할 확률이 낮아진다. 그래서 2중화 이상의 판단이 필요한 건 스펙 담당자에게 간다.

Q4. 시퀀스 수를 얼마나 돌려야 충분한가요? "언제 끝났다"고 하죠?

버그당 p(시퀀스당 검출 확률)를 알면 95% 신뢰에 ln(0.05)/ln(1-p)≈3/p 시퀀스가 필요하다. 하지만 p를 모르는 게 정상이므로, 시드 수 대신 기능 커버리지 수렴(SIV-M13)을 본다: 특히 cross 항목(이 레슨이라면 "완료 cycle × 버스 op 종류" — 연습 5)이 채워졌는지. 0건 2000 시퀀스면 "p < 약 3/2000"(95%)까지만 말할 수 있고, 안 친 영역은 아무 말도 못 한다. 꼬리질문 "커버리지 100%면 끝인가요?" → 커버리지 모델이 표현한 공간만 끝난 것이다. over-constr 표에서 race가 0건이어도 그 프로파일의 W1C 커버리지 bin은 뭔가 찰 수 있다 (cross로 "완료 cycle에 W1C" bin을 직접 정의해야 잡힌다).

Q5. 포스트실리콘에서 이 방법의 한계는 무엇입니까? 프리실리콘과 어떻게 다르죠?

① 관찰: 내부 신호를 못 보고 레지스터 읽기로만 본다 — 읽기 자체가 타이밍을 바꾸고, 표에서 보듯 OBS_END/OBS_READ로 가면 검출이 15~50배 느려진다. ② 타이밍 제어: 소프트웨어로는 정확한 cycle을 겨눌 수 없다. 여기처럼 "완료 cycle에 W1C"를 cycle 단위로 맞추는 건 시뮬레이터 세계의 얘기고, 실리콘에서는 지연 값을 sweep하고 반복 횟수를 늘리며 (shmoo처럼 시간 축도 랜덤화 대상), 짧은 DMA·타이트한 폴링 루프로 충돌 확률을 올린다. ③ 재현성: 인터럽트 타이밍·DVFS·메모리 레이턴시 때문에 같은 시드가 같은 인터리빙을 보장 못 한다. ④ 대신 장점: 실행 속도가 RTL 시뮬레이션과 비교가 안 되게 빨라 사이클 수로 압도할 수 있다. 꼬리질문 "실패 시 내부 상태는 어떻게 얻나요?" → on-chip 트레이스(ETM/ELA 류), 레지스터 스냅숏, 실패 즉시 멈춰 JTAG로 덤프, 그리고 재현 후 에뮬레이터로 옮겨 내부 신호 보기.

Q6. 가중치를 어떻게 정하나요? 더 세게 편향하면 항상 좋은가요?

아니다. 표에서 tuned는 race를 21.2 → 3.1로 줄였지만 len_max=4 때문에 late(LEN=8) 코너를 0건으로 만들었다. 가중치는 탐색의 초점이고, 제약은 영역 절단이다. 그래서 프로파일을 여러 개 두고 회귀를 돌린다(uniform 등 넓은 것 + tuned + illegal), 그리고 커버리지 hole을 보며 가중치를 조정한다(coverage-directed). 모델 인식(aware)은 더 강력하지만 "무엇을 겨눌지 알아야" 한다 — 새 버그 탐색에는 한계가 있고, 알려진 위험 패턴(SET/CLEAR 충돌, FIFO full, 경계 LEN)을 표적으로 쓴다. 꼬리질문 "시퀀스 길이는요?" → 측정표처럼 총 op 수는 비슷했다. 길이는 리셋 비용(리셋이 비싸면 길게), 축소 쉬움(짧게), 상태 깊이(긴 시퀀스만 도달하는 상태)로 정한다.

Q7. W1C 레지스터에서 HW set과 소프트웨어 clear가 동시에 오면 어떻게 동작해야 하고, 어떻게 검증하나요?

스펙이 정할 문제고 흔한 답은 set 승 — 이벤트를 절대 잃지 않기 위해서다 (clear가 이기면 그 사이에 들어온 이벤트가 영구 소실). 검증은 "완료 cycle에 W1C를 겹치는" 시퀀스를 의도적으로 만들어야 한다: directed로 정확한 cycle을 겨누거나(가능한 환경이면), 랜덤에서 그 교차 커버리지(cross) bin을 재서 hole이 있는지 본다. 이 레슨의 두 결함 — set 누락(RACE), clear 승(CLEARW) — 이 정확히 이 지점이다. 꼬리질문 "소프트웨어가 안전하게 W1C하려면?" → 읽은 값의 비트만 다시 써서 지운다(SIV-M09/C-M02의 RMW 회피). 그 이상의 동시성 보호는 하드웨어 set-승 구조가 책임진다.

9. 추가 연습#

practice.c는 채널 하나짜리 mini 모델로 코드를 다시 짠다 (본문 DUT를 다시 include 하지 않는다).

연습 1 — 온라인 trace ring

시퀀스가 미리 저장되지 않는 실리콘 스트레스 루프에서는 실패 시점까지의 op를 고리 버퍼에 남겨야 한다. ring_push/ring_dump를 구현해 wrap 후에도 오래된 것부터 N개, 전체 시작 인덱스를 돌려준다.

답: b[total % N] = op; total++; / dump는 n = min(total, N), first_idx = total - n, out[i] = b[(first_idx + i) % N].

연습 2 — 탐지 시퀀스 수 통계

시퀀스당 검출 확률 p일 때 평균 시퀀스 수(1/p)와 신뢰도 cl에 필요한 시퀀스 수(ln(1-cl)/ln(1-p)의 올림)를 구현. p=0.05, cl=0.95면 59 — 실무 감각으로 "3/p"와 맞는지 확인.

답: p=0.05 → ln(0.05)/ln(0.95) = 58.4 → 59개, 3/p=60과 비슷. 작은 p로 갈수록 3/p에 수렴.

연습 3 — 가중치 ↔ 실측 hit rate

mini generator의 가중치를 바꿔 시퀀스당 p를 측정하고, 시드를 바꿔 측정한 평균 시퀀스 수가 1/p와 ±25% 안에 드는지 확인 (표본 400 trial; 공차는 기하분포 표준편차≈평균을 표본 수의 제곱근으로 나눈 값의 약 5배로 잡은 것 — 시드가 고정이므로 flaky 없이 결정적으로 통과).

답: practice.c의 measure_p/measure_mean_seqs. 측정값: pu=0.1377, pt=0.2663, mean_t=3.62 vs 1/pt=3.75.

연습 4 — 필드 축소 (LEN과 필러 같이 줄이기)

ddmin은 값을 안 건드린다. EVT, START(5), NOP×4, W1C(EVT)처럼 LEN과 필러가 결합돼 있으면 "LEN을 1 줄이고 NOP 하나 지우기"를 같이 해야 시간이 맞는다. shrink_len_pair로 EVT, START(1), W1C(EVT)까지 줄인다.

답: START를 찾아 v>1이면 그 뒤 첫 NOP를 지우고 v-1로 만든 후보가 여전히 실패하면 수용, 아니면 종료. 본문의 shrink_full에 같은 아이디어를 값 변형 단계로 추가할 수 있다.

연습 5 — done-cycle cross coverage (완료 cycle에 어떤 버스 op가 있었나)

SIV-M13의 cross 개념을 축소판으로: 완료 cycle에 버스 op가 nop / W1C(EVT만) / W1C(그 외) / 기타 중 무엇이었는지 bin을 센다. W1C 가중치가 0이면 W1C bin은 영원히 hole, 가중치를 주면 채워진다 — 측정은 no_w1c: w1c_evt=0, tuned: w1c_evt=789.

답: cov_seq. 이 cross를 처음부터 재고 있었다면 over-constrained 프로파일의 hole을 바로 봤을 것이다.

10. 핵심 정리#

  • Constrained-random = Generator(시드·가중치·제약) + 독립 골든 모델 + Scoreboard(첫 불일치 + 재현 정보). Generator는 모델 상태를 본다 — DUT를 보면 재현이 깨진다.
  • directed는 작성자의 순서만 친다. "완료 cycle에 W1C" 같은 겹침 결함은 측정에서 directed 0건, uniform 평균 21.2 시퀀스, 가중치 조정 3.1, 모델 인식 1.6.
  • 가중치는 초점, 제약은 절단 — 빠르게 하면서 영역을 지운다 (tuned가 LEN=8 코너를 0건으로, 과잉 제약이 race를 0건으로). 프로파일 여러 개 + 커버리지 cross로 보완.
  • Scoreboard mismatch는 "둘이 다르다"일 뿐이다. 스펙 단정으로 DUT 버그 / 모델 버그 / 스펙 오독을 가른다. 공통 원인은 불일치가 없어 단정·리뷰가 아니면 안 잡힌다.
  • 실패 처리 순서: 시드 재현 → 첫 불일치까지 자르기 → 합법·시그니처 유지 축소 → 판정 → 최소 재현을 directed 회귀로 고정.
  • ddmin만으론 부족하다: 시간 의존 시퀀스는 op를 IDLE로 치환해 시간을 유지해야 줄어든다 (측정 9.8 → 5.5 ops). 축소 후보는 "아무 실패"가 아니라 "같은 실패"여야 한다.
  • 못 찾는 것을 말할 수 있어야 한다: 값 하나짜리 코너, 공통 원인, 과잉 제약, 관찰 부족에 의한 masking(OBS_END 15배 느림).
  • 포스트실리콘에서는 정확한 cycle을 못 겨누고 내부 신호를 못 보므로, 지연 sweep·반복·관찰 지점 설계로 메운다. 0건은 "p < 약 3/N" 이상을 말하지 않는다.
