Stage 4 · LPERF · Linux Performance & Observability

리눅스 성능 · 관측

아이템 29Basic 10Mid 12Advanced 7학습가능 1

리눅스 성능 분석은 '느리다'는 증상을 CPU·메모리·I/O·스케줄러·락 중 어디서 시간이 새는지 증거로 귀속하는 기술로, 임베디드 리눅스 제품과 데이터센터 서버 면접 모두에서 perf·eBPF·flame graph 활용 능력을 직접 묻는다. 이 트랙은 Brendan Gregg의 Systems Performance / BPF Performance Tools 방법론(USE, on/off-CPU, 드릴다운)을 따라 지표의 출처부터 PMU top-down, bpftrace/libbpf 도구 작성, 회귀 감지와 상시 프로파일링까지 직접 구현하며 익힌다.

트랙 목표

  • USE 방법론과 /proc·PSI 지표로 병목 후보를 빠르게 좁힌다
  • perf stat/record와 perf_event_open으로 카운터·샘플링 프로파일을 정확히 수집하고 해석한다
  • on-CPU/off-CPU flame graph와 top-down 분해로 병목을 함수·마이크로아키텍처 수준까지 귀속한다
  • bpftrace·libbpf로 스케줄러·I/O·락·메모리 지연을 측정하는 도구를 직접 작성한다
  • cgroup 자원 제한·OS 노이즈가 꼬리 지연에 미치는 영향을 재현하고 정량화한다
  • CI 회귀 감지와 fleet 상시 프로파일링을 설계해 성능을 지속적으로 지킨다

LPERF-M08Midlibbpf CO-RE 도구 작성: ring buffer와 skeleton

LPERF-M11Mid메모리 압박 관측: reclaim·PSI·OOM in cgroup v2

LPERF-M12MidCPU 스로틀링과 꼬리 지연: cpu.max·nr_throttled
cgroup v2 cpu.max(예: 50ms/100ms)를 건 멀티스레드 요청 처리기에 버스트 부하를 넣어 cpu.stat의 nr_throttled·throttled_usec와 요청 지연 p50/p99를 함께 측정하고, 스레드 수·period 길이·cpu.max.burst 변화가 스로틀링과 꼬리 지연에 주는 영향을 표로 정리한다.		외부환경필요linux

벤치를 wall time과 perf stat -e instructions:u(또는 cachegrind Ir)로 동시에 측정하는 CI 스크립트를 만들어 지표별 변동 계수를 비교하고, 0.5%/2% 회귀를 주입한 커밋에서 기준 빌드와의 folded 스택 차이를 빨강/파랑 차등 flame graph(difffolded)로 생성해 회귀 함수를 지목한다(통계 검정은 see:AIPERF-A06, bisect는 see:TOOL-M08, fleet 회귀는 see:INFRA-A06).		외부환경필요linux
LPERF-A06AdvancedContinuous profiling 설계: fleet 상시 프로파일러
저빈도(19Hz) 샘플링 에이전트(perf 또는 libbpf profile)가 주기적으로 build-id 포함 folded 스택을 업로드하고, 서버가 오프라인 심볼화·버전/서비스별 집계·기간 비교 쿼리를 제공하는 구조(GWP·Parca·Pyroscope 참고)를 설계하고, 에이전트와 집계 서버의 최소 구현으로 오버헤드·저장량(샘플/일)을 계산해 검증한다.		외부환경필요linux
LPERF-A07Advanced종합: 꼬리 지연 미스터리 사후 분석
요청 처리 서버에 락 경합, 주기적 fsync, cgroup CPU 스로틀링, 메모리 압박에 의한 reclaim 중 3가지를 무작위로 숨기는 주입 스크립트를 만들고, USE 점검 → on/off-CPU flame graph → runqlat·biolatency·PSI 순으로 원인을 찾아 p99 개선 전후 수치와 함께 1페이지 포스트모템(타임라인·증거·조치)을 작성한다.		외부환경필요linux
