# 스터디 노트 작성 규격 — `notes/` (초보자용, 아주 자세히)

## 0. 목표와 독자

이 노트를 다 읽으면 **같은 폴더의 연습 문제 10개(`01_*` ~ `10_*`)와 원본 Verkada 스크리닝 문제를
스스로 풀 수 있어야** 한다. 그게 유일한 성공 기준이다.

**독자 설정 (중요, 반드시 이 가정으로 쓴다)**

- 임베디드 펌웨어 경험은 있지만 **동시성(pthread, mutex, condvar, atomic)은 거의 처음**이다.
- **코딩 테스트형 자료구조**(해시맵 직접 구현, 힙, 이진 탐색, prefix sum)를 손으로 짜본 적이 거의 없다.
- **Embedded Linux / POSIX 사용자 공간**(fd, syscall, /dev, poll)이 약하다.
- 그래서 "당연히 알겠지"를 **한 번도 가정하지 않는다.** 용어가 처음 나오면 그 자리에서 정의한다.
- 다만 바보 취급은 하지 않는다. C 문법 자체(if/for/함수)는 안다고 봐도 된다.

## 1. 파일

## 3. 다이어그램 (이 노트의 핵심 요구사항)

노트마다 **최소 2개**의 그림이 있어야 한다. 두 가지 방법을 쓴다.

### (a) ASCII 다이어그램 — 코드 펜스 안

```
시간 →   스레드 A              스레드 B
  1     load r0 <- 5
  2                           load r0 <- 5
  3     store counter <- 6
  4                           store counter <- 6   ← 증가가 하나 사라짐
```

### (b) SVG — ```` ```svg ```` 펜스 안 (원문 그대로 들어간다)

규칙:
- **자체 완결**이어야 한다. 외부 이미지·폰트·스크립트 금지.
- 색은 **하드코딩하지 말고** 아래 클래스를 쓴다 (다크모드에서도 읽히게 되어 있다):
  - `class="box"` 테두리 상자, `class="fill-soft"` 강조 상자
  - `class="accent"` 강조 선, `class="muted"` 보조 선, `class="dash"` 점선
  - 글자는 `<text>` 그대로 (자동으로 본문 색), 작은 설명은 `class="lbl"`
- `viewBox`를 반드시 넣고 `width`/`height`는 생략하거나 100% (반응형).
- 글자 크기는 12~14 정도. 너무 빽빽하게 넣지 말 것.

예시:

```svg
<svg viewBox="0 0 520 140" role="img" aria-label="생산자-소비자">
  <rect class="box" x="10" y="30" width="120" height="50" rx="8"/>
  <text x="70" y="60" text-anchor="middle">생산자</text>
  <rect class="fill-soft" x="200" y="30" width="120" height="50" rx="8"/>
  <text x="260" y="60" text-anchor="middle">큐</text>
  <rect class="box" x="390" y="30" width="120" height="50" rx="8"/>
  <text x="450" y="60" text-anchor="middle">소비자</text>
  <line class="accent" x1="130" y1="55" x2="198" y2="55" marker-end=""/>
  <line class="accent" x1="320" y1="55" x2="388" y2="55"/>
  <text class="lbl" x="164" y="45" text-anchor="middle">push</text>
  <text class="lbl" x="354" y="45" text-anchor="middle">pop</text>
</svg>
```

화살표가 필요하면 `<polygon>`으로 삼각형을 직접 그린다(marker는 쓰지 말 것 — 일부 뷰어에서 색이 깨진다).

## 4. 코드 규칙

- 언어는 **C11 + pthread**. 연습 문제와 같은 환경(`cc -std=c11 -O2 -Wall -Wextra -pthread`).
- 노트에 넣는 코드는 **직접 컴파일해 보고** 넣는다. 돌려본 출력이 있으면 함께 싣는다.
- 길어야 40줄. 넘어가면 쪼개서 단계별로.
- 연습 문제의 모범답안에서 인용할 때는 **파일명을 밝힌다**
  (예: `03_event_tailer_shutdown/event_queue_solution.c`).

## 5. 톤과 언어

- **한국어**, 설명체(~다). 존댓말 금지. 기술 용어는 영어 그대로(mutex, condition variable, atomic).
- 문장은 짧게. 한 문단은 3~5줄.
- 비유를 적극적으로 쓰되, 비유 뒤에 **정확한 정의**를 반드시 붙인다.
- 영어 문장이 필요한 곳(면접에서 말할 것)은 영어로 따로 적는다.
